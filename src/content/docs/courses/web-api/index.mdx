O **Guia de Web APIs** estuda as interfaces nativas que o navegador disponibiliza para que o JavaScript interaja com a página, a rede, o armazenamento e os recursos do sistema operacional.

O [Guia de ECMAScript](../ecmascript/) ensina a sintaxe e a lógica da linguagem. Este guia explica o **ambiente de execução do navegador**. Uma aplicação web moderna nasce do encontro entre os dois: ECMAScript fornece a sintaxe, objetos e Promises; as Web APIs fornecem `window`, `document`, `fetch`, `localStorage`, `WebSocket`, eventos e sensores do dispositivo.

<Aside type="tip" title="Modelo Mental">
A linguagem JavaScript define *como* escrever a lógica; o navegador define *quais recursos do sistema* essa lógica pode acessar.
</Aside>

## Os Três Sentidos da Palavra API

O termo **API** (*Application Programming Interface*) é amplamente utilizado no desenvolvimento de software, mas pode se referir a três níveis de abstração completamente distintos. Desfazer essa ambiguidade cedo evita a confusão mais comum de quem estuda o desenvolvimento web:

1. **API da Linguagem (Standard Library do ECMAScript)**: São os tipos, objetos e métodos utilitários padronizados pela especificação da linguagem JavaScript. Exemplos incluem a API de manipulação de strings (`String.prototype.includes()`, `slice()`), de arrays (`map()`, `filter()`, `reduce()`), e utilitários como `Math`, `JSON` e `Promise`. Essas funções rodam de forma idêntica em qualquer ambiente (navegador, Node.js, Deno ou Bun) porque pertencem ao próprio JavaScript.
2. **Web API (Interface do Navegador / Host)**: São as interfaces que o **navegador** expõe para permitir que o JavaScript acesse a página, a tela, a persistência e o hardware (`document`, `window`, `localStorage`, `fetch()`, `WebSocket`, `navigator.geolocation`). Elas não pertencem ao padrão ECMAScript, mas sim às especificações da W3C e WHATWG implementadas pelo navegador.
3. **API Web (Serviço Remoto HTTP)**: São os serviços de **back-end** acessíveis através da rede por requisições HTTP. Arquiteturas como [REST](http/rest/) e [GraphQL](http/graphql/) definem como o servidor organiza suas rotas e payloads; elas não são métodos que você executa no JavaScript, mas contratos de comunicação que você consome via `fetch()`.

A tabela separa o papel de cada conceito no desenvolvimento de uma aplicação web:

| Camada | O que é, tecnicamente | Você chama diretamente no código? | Exemplo |
| --- | --- | --- | --- |
| **API da Linguagem** | Métodos embutidos da especificação ECMAScript | Sim, manipula variáveis e memória | `'devlab'.toUpperCase()`, `[1, 2].map()` |
| **Web API do Navegador** | Interfaces nativas fornecidas pelo navegador | Sim, interage com a página e recursos | `fetch()`, `document.getElementById()`, `localStorage` |
| **API Web (Serviço HTTP)** | Serviço remoto hospedado em um servidor | Não; você envia texto/JSON via `fetch()` | [REST](http/rest/), [GraphQL](http/graphql/), rotas de API |
| **Políticas e Ferramentas** | Regras de segurança e clientes externos | Acompanham a requisição ou substituem chamadas | [CORS](http/cors/), [SSR](browser/ssr/), Clientes HTTP |

O critério prático é direto: se você manipula dados na memória sem depender do navegador, é uma **API da linguagem**; se você usa um identificador global para tocar na tela, no disco local ou na rede do dispositivo, é uma **Web API**; se você está conversando com um servidor remoto que processa regras de negócio, é uma **API Web**.

O diagrama abaixo ilustra como as três camadas se conectam durante o ciclo de vida de uma única requisição:

<Mermaid title="Conexão entre API da linguagem, Web API do navegador, rede e API Web no servidor">
{`
flowchart TD
  subgraph JS["1. API da Linguagem (ECMAScript)"]
    A1["Manipulação de dados:<br/>JSON.stringify(), Array.map()"]
    A2["Lógica assíncrona:<br/>Promises, async/await"]
  end

  subgraph Browser["2. Web API do Navegador"]
    B["fetch(url, options)<br/>Interface nativa do navegador"]
  end

  subgraph Network["3. Rede & Políticas"]

  end

  subgraph Server["4. API Web (Servidor / Back-end)"]
    D["Serviço REST / GraphQL<br/>Endpoints e Banco de Dados"]
  end

  A1 --> A2
  A2 -->|"Chama"| B
  B -->|"Aplica CORS e transmite"| C

O CORS é o caso mais ilustrativo dessa fronteira: a regra de segurança é verificada e aplicada pelo **navegador** (Web API), mas a autorização vem em cabeçalhos HTTP emitidos exclusivamente pelo **servidor** (API Web).

A estrutura deste guia reflete essa divisão: as **APIs do Navegador** reúnem o que você invoca no código (`fetch`, `WebSocket`, `EventSource`, `localStorage`, DOM), enquanto os **Fundamentos de Rede** e **Segurança** abordam os padrões e arquiteturas que operam na comunicação e no servidor (`REST`, `GraphQL`, `SSR` e `CORS`).

## Roteiro Sugerido de Estudos

Se esta é a sua primeira passagem pelo guia, comece por [O que uma Aplicação Front-end Faz?](common-features/): a página liga cada funcionalidade recorrente de uma aplicação vanilla à Web API que a resolve, e serve de índice por problema para tudo o que vem depois.

A ordem abaixo parte do que sustenta todo o resto, o carregamento da página e o DOM, e avança para rede, armazenamento e recursos do dispositivo:

<Steps>
1. **Fundamentos do Ambiente**: Comece por [Ciclo de Vida da Página](browser/lifecycle/) e [Objetos do Navegador](browser/objects/) para entender quando o código é executado e quais objetos globais existem.
2. **DOM e Interatividade**: Domine a [Manipulação do DOM](dom/manipulation/), [Eventos](dom/events/), [Elementos Dinâmicos](dom/dynamic-elements/), [Formulários e Validação](dom/forms/) e [Rolagem e Posicionamento](dom/scroll/).
3. **Armazenamento de Dados**: Estude [Local Storage](storage/local-storage/) e [Cookies](storage/cookies/) para gerenciar estados e sessões no cliente.
4. **Rede e Comunicação**: Consuma dados assíncronos com a [Fetch API](http/fetch/), receba eventos em streaming com [Server-Sent Events](http/sse/), comunique-se em tempo real com a [WebSockets API](http/websockets/), entenda [CORS e Segurança](http/cors/), [REST API](http/rest/), [GraphQL](http/graphql/) e renderização no servidor com [Server-Side Rendering (SSR)](browser/ssr/).
5. **Segurança no Front-end**: Entenda os vetores de ataque em [OWASP e Segurança no Cliente](security/client-side/) e aplique defesas contra XSS, CSRF e armazenamento inseguro.
6. **Recursos do Dispositivo e Desempenho**: Experimente [Geolocation](browser/modern-apis/geolocation/), [Notifications](browser/modern-apis/notification/), [Vibration](browser/modern-apis/vibration/), [Observadores](browser/observers/) e [Web Workers](browser/workers/) para tarefas pesadas, e feche com [WebAssembly](browser/webassembly/) quando nem outra thread resolver.
</Steps>

Além das etapas essenciais deste roteiro, o guia inclui uma cobertura completa de interfaces modernas e recursos especializados, como a [History API](browser/history/) para navegação SPA sem recarregar a tela, a [Dialog API](browser/modern-apis/dialog/) para caixas de diálogo e modais acessíveis, a [Canvas API](browser/modern-apis/canvas/) para renderização gráfica 2D, a [Web Speech API](browser/modern-apis/web-speech/) para síntese e reconhecimento de voz, além de utilitários como [Área de Transferência (Clipboard)](browser/modern-apis/clipboard/), [Arrastar e Soltar (Drag and Drop)](browser/modern-apis/drag-and-drop/) e [Tela Cheia (Fullscreen)](browser/modern-apis/fullscreen/).

## Decisões Frequentes de Arquitetura

A tabela funciona como índice por problema: localize a necessidade na primeira coluna e siga para a API indicada. A terceira coluna traz o cuidado que costuma ser descoberto tarde demais em cada caso:

| Problema / Necessidade | API Indicada | Cuidados Principais |
| --- | --- | --- |
| Executar código após carregamento do HTML | `DOMContentLoaded`, `defer`, `type="module"` | Garantir que a árvore DOM já foi construída antes da consulta. |
| Alterar conteúdo, atributos e estilos | `document.querySelector`, `classList` | Verificar se o elemento consultado existe antes da manipulação. |
| Reagir a cliques, teclas e formulários | `addEventListener` | Tratar `preventDefault()` e vazamento de memória em listeners. |
| Navegação SPA sem recarregar a página | `history.pushState()`, `popstate` | Configurar o servidor para fallback de rotas (404/index.html). |
| Guardar preferências locais do usuário | `localStorage` | Serializar com `JSON.stringify()` e limitar dados não sensíveis. |
| Comunicação em tempo real full-duplex | `WebSocket` (`wss://`) | Gerenciar reconexões automáticas e serialização de mensagens. |
| Requisitar dados de um servidor HTTP | `fetch()` | `fetch()` não rejeita Promises para erros HTTP 404/500 (checar `res.ok`). |
| Notificar o usuário fora da aba | `Notification` | Requer protocolo `https://` e permissão prévia do usuário. |
| Feedback tátil em dispositivos móveis | `navigator.vibrate()` | Requer ação/gesto prévio do usuário e suporte do hardware. |
| Tratar cálculos pesados sem travar a UI | `Web Worker` | Código roda em thread separada; comunicação via `postMessage()`. |
| Executar algoritmo numérico intensivo ou biblioteca em C/Rust | `WebAssembly` | O módulo não acessa o DOM; só troca números com o JavaScript. |
