A **Clipboard API** permite copiar e ler texto da área de transferência pelo navegador. Como a área
de transferência pertence ao sistema operacional e pode conter dados sensíveis, o acesso é
deliberadamente restrito.

## Objetivo

Usar `navigator.clipboard.writeText()` e `navigator.clipboard.readText()` com tratamento de erro,
entendendo por que contexto seguro, foco da página e gesto explícito do usuário são requisitos
centrais.

## Modelo da API

A interface principal fica em `navigator.clipboard`. Suas operações são assíncronas porque passam por
políticas de segurança e podem depender de permissão.

| Recurso | Papel |
| --- | --- |
| `navigator.clipboard` | Entrada para leitura e escrita no clipboard |
| `writeText(texto)` | Copia texto para a área de transferência |
| `readText()` | Lê texto da área de transferência quando permitido |
| `try/catch` | Trata bloqueio por permissão, contexto ou navegador |
| Gesto do usuário | Clique ou ação clara que justifica o acesso |

<Aside type="caution" title="Privacidade">
Não tente ler o clipboard automaticamente ao carregar a página. O usuário precisa entender por que a
aplicação quer acessar esse dado.
</Aside>

## Cuidados práticos

Em ambientes de aula, o preview em iframe pode bloquear operações que funcionam quando o arquivo é
aberto em uma aba própria.

| Situação | Cuidado |
| --- | --- |
| Copiar botão de convite | Use `writeText()` após clique |
| Colar conteúdo externo | Explique a finalidade antes de chamar `readText()` |
| Ambiente sem suporte | Mostre uma mensagem alternativa |
| Erro de permissão | Capture a exceção e não trate como falha do usuário |

## Executando

<Steps>
1. Abra o exemplo `clipboard.html` pelo link do preview.
2. Clique no botão de copiar.
3. Cole em outro campo para confirmar o texto copiado.
4. Teste a leitura e observe se o navegador pede permissão ou bloqueia a chamada.
</Steps>

## Exercício

1. Adicione um campo para o usuário escolher o texto copiado.
2. Mostre uma mensagem de sucesso apenas depois que `writeText()` resolver.
3. Crie uma mensagem específica para erro de permissão.

<details>
  <summary>Possível resposta</summary>

  A ação principal deve ficar dentro de um listener de clique com `async/await`. Depois de
  `await navigator.clipboard.writeText(input.value)`, a interface pode mostrar sucesso. No `catch`,
  o texto deve explicar que o navegador bloqueou o acesso.
</details>
