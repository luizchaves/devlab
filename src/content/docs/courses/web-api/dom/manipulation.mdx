O **Document Object Model (DOM)** é uma interface de programação que representa um documento HTML estruturado como uma árvore de objetos. Através do DOM, o JavaScript consegue acessar, modificar, criar ou remover dinamicamente qualquer elemento, estilo ou atributo da página em tempo de execução.

Materiais: [slides do tópico](../../../../slides/courses/web-api/dom/manipulation/) e [mapa mental](../../../../mindmaps/courses/web-api/dom/manipulation/).

## Objetivo

Compreender o DOM como a árvore de objetos que o navegador constrói a partir do HTML, e alterá-la com as APIs modernas de consulta e edição. Ao final do tópico, o leitor deve ser capaz de:

- Situar nós de elemento, de texto e de atributo dentro da árvore do documento.
- Reconhecer a hierarquia de interfaces e o polimorfismo dos nós do DOM (EventTarget, Node, Element, HTMLElement, HTMLInputElement).
- Selecionar elementos com `querySelector()` e `querySelectorAll()`, diferenciando `NodeList` de `HTMLCollection`.
- Escolher entre `textContent`, `innerText` e `innerHTML` conforme o risco de injeção e o custo de renderização.
- Manipular classes e estilos com `classList` e `style`, preferindo a classe ao estilo inline.
- Ler e escrever atributos com `getAttribute()`, `setAttribute()` e `dataset`, e ler o valor de campos de formulário.

## A Árvore DOM

Quando o navegador carrega um arquivo HTML, o motor de renderização analisa a marcação e constrói uma representação hierárquica na memória. Cada tag, texto e atributo torna-se um **nó** (*Node*) na árvore DOM.

O HTML a seguir é pequeno, mas já contém a estrutura essencial que o navegador precisa transformar em objetos: documento, elemento raiz, cabeçalho, corpo, elementos visíveis, texto e atributos.

```html title="HTML de entrada para a árvore DOM"
<!doctype html>
<html>
  <head>
    <title>DevLab</title>
  </head>
  <body>
    <h1>Manipulação do DOM</h1>
    <p class="descricao">
      Leia a documentação no <a href="https://developer.mozilla.org">MDN</a>.
    </p>
  </body>
</html>
```

A representação a seguir mostra como esse HTML vira uma árvore em memória. O JavaScript não edita o texto do arquivo original diretamente: ele altera esses objetos, e o navegador reflete as mudanças na tela.

Existem diferentes tipos de nós no DOM:

- **`Document`**: O nó raiz de todo o documento HTML.
- **`Element`**: Representa qualquer tag HTML (`<div>`, `<p>`, `<a>`).
- **`Text`**: O conteúdo de texto dentro ou entre as tags.
- **`Attr`**: Os atributos associados aos elementos (ex: `href`, `class`).

## Hierarquia de Interfaces e Polimorfismo no DOM

No DOM, os elementos não são estruturas isoladas: eles formam uma cadeia de herança orientada a objetos padronizada pelas especificações do W3C e WHATWG (Web IDL). Esse modelo exemplifica o conceito de **polimorfismo por herança**: um mesmo elemento pode ser visto e manipulado sob diferentes interfaces, onde cada camada acrescenta métodos e propriedades especializados.

Considere como exemplo um elemento `<input>`. Esse objeto herda cumulativamente de seis camadas principais na cadeia de protótipos:

1. **`Object`**: A raiz de todos os objetos em JavaScript. Fornece métodos utilitários fundamentais da linguagem (`toString()`, `valueOf()`, `hasOwnProperty()`, `isPrototypeOf()`).
2. **`EventTarget`**: Interface raiz de eventos. Permite que o objeto receba, registre e dispare eventos (`addEventListener()`, `removeEventListener()`, `dispatchEvent()`).
3. **`Node`**: Interface genérica para qualquer nó da árvore. Fornece propriedades estruturais e métodos de navegação hierárquica (`parentNode`, `childNodes`, `firstChild`, `appendChild()`, `removeChild()`, `cloneNode()`, `textContent`).
4. **`Element`**: Especialização para nós que representam elementos de marcação (HTML, SVG ou XML). Introduz suporte a tags, classes CSS, seletores e atributos (`tagName`, `id`, `className`, `classList`, `getAttribute()`, `setAttribute()`, `querySelector()`, `innerHTML`, `getBoundingClientRect()`).
5. **`HTMLElement`**: Especialização para elementos pertencentes à linguagem HTML. Acrescenta suporte a estilos inline, atributos `data-*`, acessibilidade, foco e renderização (`style`, `dataset`, `hidden`, `tabIndex`, `focus()`, `blur()`, `click()`).
6. **`HTMLInputElement`**: Implementação concreta do elemento de formulário `<input>`. Disponibiliza propriedades de controle de entrada, validação e manipulação de texto digitado (`type`, `value`, `checked`, `placeholder`, `disabled`, `select()`, `setSelectionRange()`, `checkValidity()`).

Todas essas capacidades coexistem na mesma instância. O código a seguir demonstra o acesso a propriedades de cada nível da hierarquia e comprova essa relação com o operador `instanceof`:

```js title="Inspeção de interfaces e polimorfismo no elemento input"
const input = document.querySelector('input');

// 1. Camada EventTarget: escuta de eventos do usuário
input.addEventListener('input', (event) => {
  console.log('Texto digitado:', event.target.value);
});

// 2. Camada Node: navegação estrutural na árvore
console.log(input.parentNode);
console.log(input.nodeType); // 1 (Node.ELEMENT_NODE)

// 3. Camada Element: atributos gerais e classes CSS
input.setAttribute('aria-label', 'Campo de busca');
input.classList.add('campo-ativo');

// 4. Camada HTMLElement: estilo visual e controle de foco
input.style.borderColor = '#2563eb';
input.focus();

// 5. Camada HTMLInputElement: propriedades específicas de formulários
input.value = 'usuario@exemplo.com';
input.select();

// Verificação de herança e polimorfismo com instanceof
console.log(input instanceof HTMLInputElement); // true
console.log(input instanceof HTMLElement);      // true
console.log(input instanceof Element);          // true
console.log(input instanceof Node);             // true
console.log(input instanceof EventTarget);      // true
console.log(input instanceof Object);           // true
```

Compreender o polimorfismo no DOM ajuda a evitar erros de tipo e chamadas inválidas: métodos visuais como `focus()` existem apenas a partir de `HTMLElement`, e propriedades de digitação como `value` pertencem a classes específicas como `HTMLInputElement` e `HTMLTextAreaElement`, não existindo em uma `<div>` genérica.

## Seleção de Elementos

Antes de alterar qualquer elemento da página, é necessário obtê-lo através dos métodos de consulta do objeto `document`.

### Métodos Modernos de Seleção (`querySelector`)

Os métodos `querySelector` e `querySelectorAll` utilizam a mesma sintaxe de seletores CSS:

```js title="Seleção por seletores CSS"
// Retorna o PRIMEIRO elemento que corresponde ao seletor CSS
const titulo = document.querySelector('h1');
const botaoSalvar = document.querySelector('#btn-salvar');
const primeiroItem = document.querySelector('.lista-itens .item');

// Retorna uma NodeList com TODOS os elementos correspondentes
const todosOsCards = document.querySelectorAll('.card');

// Iterando sobre uma NodeList com forEach
todosOsCards.forEach(card => {
  console.log(card);
});
```

### Métodos Tradicionais de Seleção

Antes dos seletores CSS, cada critério de busca tinha um método próprio. Eles continuam disponíveis e ainda aparecem em código existente:

```js title="Seleção por ID ou Classe"
// Seleção direta por ID (alta performance)
const campoNome = document.getElementById('nome');

// Seleção por classe (retorna HTMLCollection viva)
const itens = document.getElementsByClassName('item');
```

<Aside type="tip" title="NodeList vs HTMLCollection">
`querySelectorAll` retorna uma `NodeList` estática que aceita métodos de array como `.forEach()`. Métodos legados como `getElementsByClassName` retornam uma `HTMLCollection` viva que é atualizada automaticamente quando o DOM muda, mas não possui o método `.forEach()`.
</Aside>

## Conteúdo de Elementos

A manipulação do conteúdo interno de nós do DOM envolve decisões entre segurança de dados, legibilidade do código e desempenho de renderização.

### Propriedades de Leitura e Escrita

Existem três propriedades fundamentais para ler ou alterar o conteúdo de um elemento HTML:

```js title="Leitura e escrita de conteúdo"
const elemento = document.querySelector('#mensagem');

// 1. textContent: Obtém ou define o texto puro (preserva espaços, ignora tags HTML)
elemento.textContent = "Novo texto de mensagem";

// 2. innerText: Obtém o texto visível renderizado (respeita estilos CSS como display: none)
console.log(elemento.innerText);

// 3. innerHTML: Interpreta e renderiza tags HTML contidas na string
elemento.innerHTML = "<strong>Texto em negrito</strong> com <em>ênfase</em>";
```

A propriedade `textContent` é a escolha padrão e recomendada para qualquer atualização de texto, pois trata qualquer conteúdo estritamente como caracteres literais, sem acionar o analisador sintático de HTML.

### Quando o Uso de `innerHTML` é Seguro e Quando Evitar

A decisão de utilizar `innerHTML` depende da **origem dos dados** (*source of truth*) e da **forma de inserção**:

- **Seguro (dados confiáveis em memória)**: criar um nó isolado (`document.createElement()`) e preencher sua estrutura interna via *template literals* a partir de dados estáticos ou controlados no próprio código.
- **Inseguro (dados não confiáveis)**: interpolar entradas de formulários (`<input>`), URLs ou retornos de APIs externas diretamente no `innerHTML`, gerando risco de **Cross-Site Scripting (XSS)**.
- **Inadequado (concatenação no DOM)**: usar `element.innerHTML += ...` no documento ativo, pois força o navegador a destruir e recriar toda a subárvore, perdendo eventos já registrados.

O exemplo a seguir contrasta o uso de *template literals* em nó isolado com a alternativa defensiva:

```js title="Template literals em memória versus criação defensiva"
// 1. Template literal em nó isolado (seguro para dados estáticos/controlados)
const tr = document.createElement('tr');
tr.innerHTML = `<td>${item.ip}</td><td>${item.mascara}</td>`;

// 2. Criação defensiva com textContent (essencial para dados de formulário ou API)
const tr = document.createElement('tr');
const td = document.createElement('td');
td.textContent = inputUsuario; // Imune a injeção de tags ou scripts
tr.append(td);
```

A tabela a seguir resume as recomendações de cada abordagem:

| Abordagem | Tratamento de Tags | Risco de Injeção (XSS) | Quando Utilizar |
| :--- | :--- | :--- | :--- |
| `textContent` | Trata tudo como texto literal | Zero | Atualizar textos, rótulos e valores dinâmicos de inputs/APIs. |
| `innerHTML` em nó na memória | Interpreta tags do template | Seguro para dados estáticos; Alto para dados de usuários | Montar pequenas estruturas de UI controladas antes do append. |
| `innerHTML +=` no documento | Destrói e recria os filhos | Alto se envolver variáveis externas | Evitar sempre; use `append()`, `appendChild()` ou `DocumentFragment`. |

Atenção especial deve ser mantida ao manipular dados externos:

<Aside type="danger" title="Atenção com Segurança (XSS)">
Nunca atribua entradas não confiáveis do usuário diretamente ao `innerHTML`. Isso expõe sua aplicação a ataques de **Cross-Site Scripting (XSS)**. Para inserir texto vindo de formulários ou APIs externas, utilize sempre `textContent`.
</Aside>

O uso inseguro de `innerHTML` para exibir variáveis externas é um dos descuidos mais recorrentes em código gerado por ferramentas de IA:

<Aside type="caution" title="Dica de IA: Troque `innerHTML` por `textContent` no código gerado">
Pedidos como "mostre o nome do usuário na tela" costumam voltar com `element.innerHTML = data.name`.
Enquanto o dado vem de um campo controlado, nada acontece; assim que ele vem de uma API ou de outro
usuário, a marcação é interpretada e a página passa a executar script de terceiros.

**Prompt:** *"Aponte cada atribuição a `innerHTML` neste arquivo que recebe dado externo, troque por
`textContent` onde não houver marcação intencional e mostre um valor de entrada que explora cada uma
das que sobrarem."*
</Aside>

## Alteração de Estilos e Classes

A melhor prática para alterar o visual de um elemento é manipular suas classes CSS através da propriedade `classList`.

Quando uma classe é adicionada ou removida, o JavaScript altera a árvore DOM, mas o visual final é recalculado em conjunto com outra estrutura mantida pelo navegador: o **CSS Object Model (CSSOM)**. O DOM guarda os elementos e atributos; o CSSOM guarda as regras CSS aplicáveis; a renderização combina os dois para decidir cor, tamanho, posição e visibilidade.

Essa separação explica a recomendação prática desta seção: use `classList` para trocar estados visuais já descritos no CSS, e deixe `element.style` para valores realmente dinâmicos, como uma posição calculada em pixels.

### A propriedade `classList`

O objeto `classList` fornece métodos convenientes para alterar o estado visual sem sobrescrever outras classes:

```js title="Manipulando classes com classList"
const card = document.querySelector('.card');

// Adiciona uma ou mais classes
card.classList.add('destaque', 'sombra');

// Remove uma classe
card.classList.remove('sombra');

// Alterna a classe (adiciona se não existir, remove se existir)
card.classList.toggle('ativo');

// Verifica se possui determinada classe (retorna booleano)
if (card.classList.contains('destaque')) {
  console.log('O card está em destaque!');
}
```

### Estilos Inline (`style`)

Caso seja necessário aplicar estilos dinâmicos diretos (ex: posições calculadas em pixels):

```js title="Alterando propriedades de estilo inline"
const caixa = document.querySelector('.caixa');

// Propriedades CSS em camelCase (background-color vira backgroundColor)
caixa.style.backgroundColor = '#2563eb';
caixa.style.fontSize = '1.2rem';
caixa.style.marginTop = '20px';

// Aplicação de múltiplos estilos em bloco com cssText
caixa.style.cssText = 'color: white; padding: 16px; border-radius: 8px;';
```

## Manipulação de Atributos

É possível ler, definir ou remover atributos HTML de qualquer elemento através da interface de atributos:

```js title="Manipulação de atributos nativos e data-attributes"
const link = document.querySelector('a#link-externo');

// Ler o valor de um atributo
const destino = link.getAttribute('href');

// Definir um novo valor para o atributo
link.setAttribute('href', 'https://developer.mozilla.org');
link.setAttribute('target', '_blank');

// Remover um atributo
link.removeAttribute('title');

// Atributos customizados (dataset / data-*)
// HTML: <div id="produto" data-id="105" data-categoria="livros"></div>
const produto = document.querySelector('#produto');
console.log(produto.dataset.id);        // "105"
console.log(produto.dataset.categoria); // "livros"

produto.dataset.emEstoque = "true";     // Define data-em-estoque="true"
```

## Propriedades de Formulários

Elementos de entrada de formulários (`<input>`, `<select>`, `<textarea>`) possuem propriedades dedicadas para capturar dados digitados pelo usuário:

```js title="Leitura de campos de formulário"
const campoEmail = document.querySelector('#email');
const campoAceito = document.querySelector('#termos');

// Lê o valor atual digitado no input
console.log(campoEmail.value);

// Define um novo valor para o input
campoEmail.value = 'usuario@exemplo.com';

// Verifica se um checkbox ou radio button está marcado
if (campoAceito.checked) {
  console.log('Termos aceitos pelo usuário');
}
```

## Quando usar, e quando não usar?

As APIs de manipulação se sobrepõem bastante, e quase toda alteração pode ser escrita de três formas
diferentes. A escolha errada raramente quebra a página; ela cobra depois, em desempenho, em
acessibilidade ou em segurança.

A tabela contrapõe cada situação à alternativa que costuma aparecer no lugar certo apenas por hábito:

| Situação | Escolha | Em vez de |
| --- | --- | --- |
| Exibir texto vindo de uma API ou de um campo | `textContent` | `innerHTML`, que interpreta marcação e abre espaço para XSS |
| Ler o texto como o usuário o enxerga, sem partes ocultas | `innerText` | `textContent`, que devolve também o que está com `display: none` |
| Aplicar um conjunto de estilos ligado a um estado | `classList.toggle()` | `element.style`, que espalha valores fixos pelo JavaScript |
| Guardar um identificador junto do elemento | `dataset` | Atributo inventado, que não é válido em HTML |
| Selecionar vários elementos e percorrê-los | `querySelectorAll()` | `getElementsByClassName()`, cuja coleção viva muda durante o laço |

A última linha é a que mais surpreende. `getElementsByClassName()` devolve uma coleção viva: remover a
classe de um elemento durante o laço encurta a própria lista que está sendo percorrida, e metade dos
elementos escapa do processamento.

## Exercício

Os itens a seguir exercitam seleção, alteração de conteúdo e a escolha entre `textContent` e `innerHTML`:

1. Qual a diferença conceitual e de segurança entre utilizar `element.textContent` e `element.innerHTML`?
2. Como alternar a classe `ativo` em um elemento com ID `#menu` ao clicar nele?
3. Dado o HTML `<button id="btn" data-user-id="42">Perfil</button>`, como ler o ID do usuário via JavaScript?

<details>
  <summary>Possível resposta</summary>

  1. `textContent` trata todo o valor atribuído como texto puro, neutralizando qualquer tag HTML e evitando falhas de segurança XSS. O `innerHTML` interpreta e compila strings como marcação HTML, o que permite injeção de scripts maliciosos se a string contiver dados do usuário.

  2. Código para alternar a classe:
     ```js title="Alternância de classe no menu"
     const menu = document.querySelector('#menu');
     menu.classList.toggle('ativo');
     ```

  3. Acessando via propriedade `dataset`:
     ```js title="Atributo desabilitado no botão"
     const botao = document.querySelector('#btn');
     const userId = botao.dataset.userId; // "42"
     ```
</details>

## Desafio

Crie uma função `destacarLinksExternos()` que selecione todos os links `<a>` da página e adicione a classe CSS `link-externo` e o atributo `target="_blank"` apenas naqueles cujo atributo `href` comece com `"http"`.

<details>
  <summary>Possível resposta</summary>

  ```js title="Destaque para links externos"
  function destacarLinksExternos() {
    // Seleciona apenas links que começam com http
    const linksExternos = document.querySelectorAll('a[href^="http"]');

    linksExternos.forEach(link => {
      link.classList.add('link-externo');
      link.setAttribute('target', '_blank');
      link.setAttribute('rel', 'noopener noreferrer');
    });
  }

  destacarLinksExternos();
  ```
</details>
