A **Drag and Drop API** permite criar interações de arrastar e soltar. Ela aparece em kanbans,
uploads, reordenação de listas e interfaces em que o gesto espacial ajuda mais do que um formulário.

## Objetivo

Compreender o encadeamento de eventos que sustenta o arrastar e soltar nativo, e o papel do `DataTransfer` como transporte de dados entre origem e destino. Ao final do tópico, o leitor deve ser capaz de:

- Habilitar uma origem de arrasto com `draggable="true"` e registrar o dado em `dragstart`.
- Explicar por que o destino só aceita o item quando `dragover` cancela o comportamento padrão.
- Ler o dado transportado no evento `drop` e concluir a ação de negócio.
- Limpar o estado visual em `dragend`, mesmo quando o gesto é abandonado.
- Escolher entre a API nativa, eventos de ponteiro e um `<input type="file">` conforme o gesto e o público.

## O ciclo de um arrasto

Arrastar e soltar não é um evento, é uma sequência deles, disparados em dois elementos diferentes. A
origem informa o que está sendo levado; o destino precisa declarar que aceita receber, e só então
recebe.

O ponto que quebra quase toda primeira implementação está no meio dessa sequência: por padrão, uma
área da página **não** aceita nada solto sobre ela. O destino só passa a aceitar quando o código
cancela o comportamento padrão do evento `dragover`.

<Mermaid title="Sequência de eventos entre a origem e o destino de um arrasto">
{`
sequenceDiagram
  participant O as Origem
  participant D as Destino
  O->>O: dragstart<br/>grava o dado no DataTransfer
  O->>D: dragover (repetido)
  D->>D: preventDefault()<br/>declara que aceita
  O->>D: drop<br/>lê o dado e conclui a ação
  D->>O: dragend<br/>limpa o estado visual
`}
</Mermaid>

O trecho abaixo é a versão mínima dessa sequência. Repare que o `preventDefault()` da linha 6 não é
uma correção de bug: ele é a declaração de que aquela área é um destino válido.

```js title="Origem e destino mínimos"
source.addEventListener('dragstart', (event) => {
  event.dataTransfer.setData('text/plain', source.id);
});

target.addEventListener('dragover', (event) => {
  event.preventDefault();
});

target.addEventListener('drop', (event) => {
  event.preventDefault();
  const id = event.dataTransfer.getData('text/plain');
  target.append(document.getElementById(id));
});
```

O dado trafega como texto identificado por um tipo MIME. Em geral não se transporta o elemento em si,
e sim o identificador dele, como na linha 2, deixando para o destino a decisão do que fazer com essa
informação.

## Modelo da API

O fluxo depende de eventos encadeados. O destino só aceita o item quando o código cancela o
comportamento padrão em `dragover`.

| Evento ou objeto | Papel |
| --- | --- |
| `draggable="true"` | Habilita o elemento como origem de arrasto |
| `dragstart` | Define o que está sendo arrastado |
| `dragover` | Permite que uma área receba o item |
| `drop` | Executa a ação final quando o item é solto |
| `DataTransfer` | Transporta texto, IDs, arquivos ou outros dados |
| `dragend` | Permite limpar estado visual depois do gesto |

<Aside type="caution" title="O detalhe que mais quebra">
Sem `event.preventDefault()` no `dragover` do destino, o navegador não dispara o `drop` como você
espera. Esse detalhe é pequeno, mas faz parte do contrato da API.
</Aside>

## Cuidados práticos

Drag and drop é útil, mas não deve ser a única forma de executar uma ação importante.

| Situação | Cuidado |
| --- | --- |
| Reordenar lista | Ofereça alternativa por teclado ou botões |
| Upload de arquivos | Valide tipo e tamanho também no servidor |
| Mover item entre colunas | Atualize o estado de dados, não só o DOM visual |
| Interface mobile | Teste suporte e considere Pointer Events |

## Quando usar, e quando não usar?

O arrastar e soltar nativo é um gesto de mouse. Ele não tem equivalente por teclado, funciona mal em
telas de toque e depende de precisão motora, o que o torna uma escolha ruim como caminho único para
qualquer ação.

A tabela relaciona cada necessidade à interface adequada:

| Situação | Escolha | Em vez de |
| --- | --- | --- |
| Receber arquivos vindos da área de trabalho | API nativa, lendo `dataTransfer.files` | Apenas o seletor de arquivos, que ignora o gesto natural |
| Reordenar itens de uma lista curta | API nativa **com** botões de subir e descer | Só o arrasto, que exclui quem navega por teclado |
| Mover cartões entre colunas em telas de toque | Eventos de ponteiro (*Pointer Events*) | A API nativa, cujo suporte em toque é irregular |
| Ação crítica, como excluir ou enviar | Botão comum | Arrasto para uma área de descarte, difícil de desfazer |
| Upload simples de um arquivo | `<input type="file">` | Toda a sequência de eventos, para o mesmo resultado |

A segunda linha é a regra prática do tópico: o arrasto pode ser o caminho rápido, nunca o único. Toda
ação alcançável por arrasto precisa de um equivalente acionável por teclado.

## Perguntas de revisão

Teste seus conhecimentos sobre o fluxo de eventos de arrastar e soltar e a transferência de dados no navegador:

### Sequência de eventos

As questões a seguir avaliam o ciclo de vida dos eventos de arrasto e a preparação da zona de soltura:

1. **Por que uma área da página não aceita um item solto sobre ela sem código adicional?**

<details>
  <summary>Possível resposta</summary>

  Porque o comportamento padrão do navegador é recusar. O destino só passa a aceitar quando cancela
  esse padrão com `preventDefault()` em `dragover`.
</details>

2. **Em qual evento o dado transportado deve ser gravado?**

<details>
  <summary>Possível resposta</summary>

  Em `dragstart`, com `event.dataTransfer.setData(tipo, valor)`.
</details>

3. **Qual a função do atributo `draggable="true"`?**

<details>
  <summary>Possível resposta</summary>

  Marcar o elemento como origem de arrasto, o que faz o navegador disparar `dragstart` sobre ele.
</details>

4. **Para que serve o evento `dragend`, já que o `drop` conclui a ação?**

<details>
  <summary>Possível resposta</summary>

  Para limpar o estado visual da origem, inclusive quando o gesto é abandonado fora de um destino
  válido e o `drop` nunca acontece.
</details>

### Dados e alternativas

As questões a seguir avaliam o objeto DataTransfer, recebimento de arquivos e acessibilidade:

5. **Por que se costuma transportar o identificador do elemento e não o elemento em si?**

<details>
  <summary>Possível resposta</summary>

  Porque o `DataTransfer` trafega strings por tipo MIME. Com o identificador, o destino localiza o
  elemento e decide o que fazer com ele.
</details>

6. **Como receber arquivos arrastados da área de trabalho?**

<details>
  <summary>Possível resposta</summary>

  Lendo `event.dataTransfer.files` no evento `drop`, que traz uma `FileList` equivalente à de um
  `<input type="file">`.
</details>

7. **Por que o arrasto não pode ser o único caminho para uma ação?**

<details>
  <summary>Possível resposta</summary>

  Porque não existe equivalente por teclado, o que exclui parte dos usuários. A ação precisa de um
  botão ou menu correspondente.
</details>

8. **Quando os *Pointer Events* são preferíveis à API nativa?**

<details>
  <summary>Possível resposta</summary>

  Em interfaces de toque, onde o suporte da API nativa é irregular e o controle direto do ponteiro
  dá um gesto mais previsível.
</details>
