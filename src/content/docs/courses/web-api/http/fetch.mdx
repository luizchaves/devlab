A **Fetch API** é a interface padrão nativa do navegador (e disponível no Node.js a partir da versão 18) para realizar requisições HTTP assíncronas pela rede. Ela substituiu a antiga e verbosa API `XMLHttpRequest`, fornecendo uma abstração limpa baseada em **Promises**.

## Objetivo

Compreender o consumo de Web APIs e serviços REST no front-end, dominando os métodos HTTP, o envio e recebimento de cargas JSON, o tratamento correto de erros de resposta (`response.ok`), a configuração de CORS e o cancelamento de requisições com `AbortController`.

---

## Natureza Assíncrona e Event Loop

A comunicação com servidores remotos via rede é uma operação de entrada e saída (*I/O*) não bloqueante. O método `fetch()` não trava a execução da página nem paralisa a interface do usuário enquanto aguarda os dados do servidor.

Em vez disso, ele delega a tarefa de rede para o navegador e retorna uma **Promise**. Quando a resposta do servidor chega, o navegador envia o resultado para a fila de *microtasks* do Event Loop, permitindo que a aplicação trate os dados sem causar congelamento (*freezing*) na tela. Por isso, a sintaxe padrão recomendada em todo o guia é o uso de `async/await` com blocos `try/catch`.

---

## A Função `fetch` e a Classe `Response`

A função `fetch()` aceita uma URL de destino e um objeto opcional de opções de configuração. Ela retorna uma Promise que resolve em um objeto do tipo `Response`:

```js
fetch(url, options)
```

<Mermaid title="Fluxo de Execução do fetch e Parse do JSON">
{`
flowchart TD
  Req["fetch(url, options)"] -- "Requisição Assíncrona" --> Net["Servidor Remoto / API"]
  Net -- "Retorna Objeto Response" --> Res["const res = await fetch(...)"]
  Res --> Check{res.ok === true?}
  Check -- "Sim" --> Parse["await res.json()"]
  Check -- "Não (404, 500)" --> Err["throw new Error(res.status)"]
  Parse --> Data["Dados JS prontos para uso"]
`}
</Mermaid>

## Operações CRUD com `fetch`

### 1. Leitura de Dados (GET)

A requisição do tipo GET é o padrão do `fetch` caso nenhum segundo parâmetro seja fornecido:

```js title="GET - Consultando uma API"
async function buscarUsuarios() {
  try {
    const resposta = await fetch('https://jsonplaceholder.typicode.com/users');

    // VERIFICAÇÃO CRÍTICA: fetch NÃO lança exceções em status 404 ou 500!
    if (!resposta.ok) {
      throw new Error(`Erro HTTP! Status: ${resposta.status}`);
    }

    const usuarios = await resposta.json();
    console.log(usuarios);
  } catch (erro) {
    console.error('Falha na requisição de rede:', erro);
  }
}

buscarUsuarios();
```

<Aside type="caution" title="Armadilha Crítica do fetch">
Uma Promise retornada pelo `fetch()` **NÃO é rejeitada** em caso de erro HTTP como `404 Not Found` ou `500 Internal Server Error`. A Promise só é rejeitada se houver uma falha real de rede (ex: perda de conexão ou endereço inexistente). Sempre verifique a propriedade `resposta.ok`!
</Aside>

### 2. Envio de Dados (POST)

Para enviar dados em formato JSON para uma API, três configurações no objeto de opções são obrigatórias:
1. `method: 'POST'`
2. `headers: { 'Content-Type': 'application/json' }`
3. `body: JSON.stringify(dados)`

```js title="POST - Criando um recurso"
async function criarUsuario(novoUsuario) {
  const opcoes = {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json'
    },
    body: JSON.stringify(novoUsuario)
  };

  const resposta = await fetch('https://jsonplaceholder.typicode.com/users', opcoes);

  if (!resposta.ok) {
    throw new Error(`Erro ao criar usuário: ${resposta.status}`);
  }

  const usuarioCriado = await resposta.json();
  return usuarioCriado;
}
```

### 3. Atualização (PUT e PATCH) e Remoção (DELETE)

```js title="PUT, PATCH e DELETE"
// PUT - Atualização completa do recurso
await fetch('https://api.com/users/1', {
  method: 'PUT',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ nome: 'Ana Silva', email: 'ana@email.com' })
});

// DELETE - Remoção do recurso
const resDelete = await fetch('https://api.com/users/1', {
  method: 'DELETE'
});

// Respostas 204 No Content não possuem corpo — não chame .json() nelas!
if (resDelete.status === 204) {
  console.log('Recurso excluído com sucesso!');
}
```

## Montando Query Strings com `URLSearchParams`

Evite concatenar strings manualmente para passar parâmetros na URL. Utilize o utilitário nativo `URLSearchParams`:

```js title="Construção segura de query parameters"
const parametros = new URLSearchParams({
  page: 1,
  limit: 10,
  busca: 'desenvolvimento web'
});

const url = `https://api.com/produtos?${parametros.toString()}`;
// Resultado: https://api.com/produtos?page=1&limit=10&busca=desenvolvimento+web

const resposta = await fetch(url);
```

## Entendendo o CORS (Cross-Origin Resource Sharing)

O **CORS** é um mecanismo de segurança implementado pelos navegadores que restringe requisições HTTP feitas via scripts para um domínio (origem) diferente daquele que serviu a página atual.

<Mermaid title="Fluxo de Verificação do CORS pelo Navegador">
{`
flowchart TD
  App["Aplicação Web (meusite.com)"] -- "fetch('https://api.com/dados')" --> Browser["Navegador"]
  Browser -- "Requisição HTTP (com Origin: meusite.com)" --> API["Servidor API (api.com)"]
  API -- "Resposta com Access-Control-Allow-Origin" --> Browser
  Browser -- "Valida se meusite.com foi permitido" --> Decision{Permitido?}
  Decision -- "Sim" --> Deliver["Entrega dados ao JS"]
  Decision -- "Não" --> Block["Bloqueia no JS (CORS Error)"]
`}
</Mermaid>

Se a API remota não retornar o cabeçalho `Access-Control-Allow-Origin` autorizando a origem do seu site, o navegador **bloqueará o acesso à resposta** por motivos de segurança.

## Cancelando Requisições com `AbortController`

Em busca dinâmica ou navegação rápida, requisições antigas que ainda estão em andamento devem ser canceladas para evitar *race conditions* ou desperdício de banda. Isso é feito com a API `AbortController`:

```js title="Cancelando requisições com AbortController"
const controller = new AbortController();
const signal = controller.signal;

async function buscarDadosComTimeout() {
  try {
    // Cancela automaticamente após 5 segundos
    const timer = setTimeout(() => controller.abort(), 5000);

    const resposta = await fetch('https://api.com/dados-demorados', { signal });
    clearTimeout(timer);

    const dados = await resposta.json();
    return dados;
  } catch (erro) {
    if (erro.name === 'AbortError') {
      console.warn('A requisição foi cancelada por ter excedido o tempo limite!');
    } else {
      console.error('Outro erro de rede:', erro);
    }
  }
}
```

## Exercício

1. Por que uma requisição `fetch()` que retorna o código de status HTTP `404 Not Found` **não** cai no bloco `catch` de um `try/catch`?
2. Quais são os três cabeçalhos/propriedades fundamentais necessários para enviar dados em formato JSON utilizando o método `POST` no `fetch`?
3. O que é e para que serve o `AbortController`?

<details>
  <summary>Possível resposta</summary>

  1. Porque a Fetch API considera como "rejeição" apenas falhas físicas de rede (sem conexão, falha de DNS ou erro de CORS). Respostas HTTP válidas retornadas pelo servidor (mesmo com erros 4xx ou 5xx) resolvem a Promise normalmente.

  2. As três propriedades são:
     - `method: 'POST'`
     - `headers: { 'Content-Type': 'application/json' }`
     - `body: JSON.stringify(dados)`

  3. O `AbortController` é uma API nativa que permite abortar/cancelar uma ou mais requisições HTTP em andamento, sendo usada para timeouts ou para cancelar buscas anteriores quando o usuário digita um novo termo.
</details>

## Desafio

Escreva uma função `buscarComRetry(url, tentativas)` que tente realizar um `fetch(url)` até o número máximo de tentativas especificado. Se a resposta não for `.ok`, a função deve aguardar 1 segundo e tentar novamente antes de lançar o erro final.

<details>
  <summary>Possível resposta</summary>

  ```js
  async function buscarComRetry(url, tentativas = 3) {
    for (let i = 1; i <= tentativas; i++) {
      try {
        console.log(`Tentativa ${i} de ${tentativas}...`);
        const res = await fetch(url);
        if (res.ok) {
          return await res.json();
        }
      } catch (erro) {
        if (i === tentativas) throw erro;
      }
      // Aguarda 1 segundo antes da próxima tentativa
      await new Promise(resolve => setTimeout(resolve, 1000));
    }
    throw new Error(`Falha após ${tentativas} tentativas.`);
  }
  ```
</details>

   <details>
     <summary>Possível resposta</summary>

   <details>
     <summary>Possível resposta</summary>
