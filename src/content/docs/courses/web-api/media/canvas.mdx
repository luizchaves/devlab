A **Canvas API** fornece uma área de desenho em bitmap. O HTML cria a superfície com `<canvas>`, e o
JavaScript desenha pixels usando um contexto, como `2d`.

## Objetivo

Compreender o `<canvas>` como uma superfície de pixels, desenhada por comandos, em contraste com os elementos da árvore DOM. Ao final do tópico, o leitor deve ser capaz de:

- Explicar a diferença entre desenho imperativo em bitmap e elementos HTML retidos no DOM.
- Obter o contexto 2D e desenhar formas, caminhos e texto com `fillRect()`, `arc()` e `fillText()`.
- Localizar um ponto no sistema de coordenadas do canvas, com origem no canto superior esquerdo.
- Redesenhar a cena a cada quadro com `requestAnimationFrame()`.
- Escolher entre canvas, SVG e elementos HTML conforme a necessidade de acessibilidade, interatividade e volume de elementos.

## Pixels em vez de elementos

Todo o resto deste guia trata de elementos: nós que o navegador guarda, redesenha quando mudam e
entrega ao leitor de tela. O `<canvas>` funciona pelo princípio oposto. Ele é um retângulo de pixels,
e cada comando de desenho pinta esses pixels de uma vez, sem deixar registro do que foi desenhado.

A consequência prática aparece logo no primeiro exercício de animação: para mover um círculo, não
existe "o círculo" para alterar. É preciso limpar a área e desenhar tudo de novo na posição nova.

O trecho abaixo é o menor programa de canvas possível. Ele obtém o contexto de desenho na linha 2 e
pinta um único retângulo azul de 120 por 80 pixels a partir do ponto `(10, 10)`:

```js title="Desenho mínimo no contexto 2D"
const canvas = document.querySelector('#board');
const ctx = canvas.getContext('2d');

ctx.fillStyle = '#2563eb';
ctx.fillRect(10, 10, 120, 80);
```

Repare que `fillRect()` não devolve nada. Não há objeto retângulo para guardar em uma variável, e é
essa ausência que separa o canvas de tudo que foi visto em manipulação do DOM.

## Modelo da API

Canvas não cria botões, parágrafos ou elementos clicáveis por desenho. Depois que uma linha é
desenhada, ela vira pixel; se o estado mudar, o programa precisa redesenhar.

| Recurso | Papel |
| --- | --- |
| `<canvas width height>` | Define a resolução interna do bitmap |
| `canvas.getContext('2d')` | Retorna a API de desenho 2D |
| `fillRect()` e `strokeRect()` | Desenham retângulos preenchidos ou contornados |
| `beginPath()`, `moveTo()`, `lineTo()` | Constroem caminhos e linhas |
| `arc()` | Desenha círculos e arcos |
| `fillText()` | Desenha texto como pixels |
| `requestAnimationFrame()` | Agenda animações sincronizadas com o navegador |

<Aside type="caution" title="Canvas não é DOM">
Um círculo desenhado no canvas não é um elemento selecionável por `querySelector`. Para detectar
cliques, você calcula coordenadas do mouse e compara com a geometria que seu código desenhou.
</Aside>

## Cuidados práticos

O tamanho visual do canvas em CSS pode ser diferente da resolução do bitmap. Quando isso acontece, o
desenho pode ficar esticado ou borrado.

| Situação | Cuidado |
| --- | --- |
| Canvas responsivo | Ajuste `width` e `height` internos, não apenas CSS |
| Tela de alta densidade | Considere `devicePixelRatio` para evitar desenho borrado |
| Animação | Limpe e redesenhe a cena a cada quadro |
| Acessibilidade | Forneça texto alternativo fora do canvas quando houver informação importante |

## Quando usar, e quando não usar?

Canvas é a ferramenta certa para muitos elementos que mudam a cada quadro, e a errada para poucos
elementos que precisam ser lidos, clicados ou encontrados por busca.

A tabela contrapõe as três formas de desenhar na web pelo que cada uma entrega ao usuário:

| Situação | Escolha | Por quê |
| --- | --- | --- |
| Animação com centenas de partículas ou um jogo 2D | Canvas | O DOM não sustenta centenas de nós mudando a cada quadro |
| Gráfico estático que precisa de rótulo acessível | SVG | Cada forma é um elemento, com texto selecionável e `aria-label` |
| Ícone ou ilustração que escala com o zoom | SVG | Vetor não perde definição; canvas é bitmap |
| Filtro ou recorte de imagem no navegador | Canvas | Acesso direto aos pixels por `getImageData()` |
| Interface com botões e campos | Elementos HTML | Foco, teclado e leitor de tela vêm de graça |
| Visualização 3D | WebGL (`getContext('webgl2')`) | O contexto 2D não tem projeção nem iluminação |

A terceira e a quinta linhas são as que mais custam quando ignoradas. O que é desenhado no canvas não
existe para o leitor de tela nem para a busca da página, então interface desenhada em pixels precisa
de um equivalente textual ao lado.

## Perguntas de revisão

Teste seus conhecimentos sobre renderização 2D em bitmap, resolução e animação com o elemento Canvas:

### Modelo de desenho

As questões a seguir avaliam o funcionamento do contexto de renderização, coordenadas e resolução:

1. **Por que não é possível "mover" uma forma já desenhada no canvas?**

<details>
  <summary>Possível resposta</summary>

  Porque o canvas guarda apenas os pixels resultantes, não a forma. Para mover, limpa-se a área com
  `clearRect()` e desenha-se novamente na posição nova.
</details>

2. **O que `canvas.getContext('2d')` devolve, e o que acontece se o mesmo contexto for pedido duas vezes?**

<details>
  <summary>Possível resposta</summary>

  Devolve o objeto com a API de desenho 2D. Pedir de novo devolve o mesmo objeto, não um novo contexto.
</details>

3. **Qual a diferença entre os atributos `width`/`height` da tag e as dimensões definidas por CSS?**

<details>
  <summary>Possível resposta</summary>

  Os atributos definem a resolução interna do bitmap; o CSS apenas estica ou encolhe o resultado na
  tela. Definir só o CSS produz desenho borrado.
</details>

4. **Onde fica a origem do sistema de coordenadas do canvas?**

<details>
  <summary>Possível resposta</summary>

  No canto superior esquerdo, com `x` crescendo para a direita e `y` crescendo para baixo.
</details>

### Animação e escolha da ferramenta

As questões a seguir avaliam o ciclo de renderização e as diferenças entre Canvas e SVG:

5. **Por que `requestAnimationFrame()` é preferível a `setInterval()` para animar?**

<details>
  <summary>Possível resposta</summary>

  Porque ele sincroniza com o ciclo de pintura do navegador e é suspenso quando a aba fica oculta,
  o que economiza CPU e bateria.
</details>

6. **Quando um gráfico deve ser feito em SVG e não em canvas?**

<details>
  <summary>Possível resposta</summary>

  Quando os elementos são poucos e precisam ser acessíveis, clicáveis individualmente, selecionáveis
  como texto ou escaláveis sem perda.
</details>

7. **Qual o problema de construir uma interface inteira dentro de um canvas?**

<details>
  <summary>Possível resposta</summary>

  Nada do que é desenhado existe para o leitor de tela, para a navegação por teclado ou para a busca
  da página; tudo isso teria de ser reimplementado à mão.
</details>

8. **O que muda ao trocar `getContext('2d')` por `getContext('webgl2')`?**

<details>
  <summary>Possível resposta</summary>

  A API de desenho passa a ser a do WebGL, com projeção 3D e execução na GPU; os métodos do contexto
  2D, como `fillRect()`, deixam de existir.
</details>
