O **Supabase Client** (`@supabase/supabase-js`) é o SDK JavaScript que conecta uma aplicação aos serviços do Supabase. Ele não é um serviço separado, mas a porta de entrada para Database API, Auth, Storage, Realtime e funções.

## Objetivo

Compreender o Supabase Client como camada de integração, não como lugar de regra de negócio, para organizar o front-end sem espalhar chamadas à plataforma por todos os componentes. Ao final do tópico, o leitor deve ser capaz de:

- Inicializar o cliente com URL e chave pública do projeto.
- Identificar quais serviços são acessados pelo mesmo objeto `supabase`.
- Tratar respostas `{ data, error }` sem engolir falhas.
- Separar camada de serviço, componente de interface e política de acesso.
- Reconhecer quando o SDK não deve ser usado por depender de segredo.

## Modelo Mental

O SDK compõe requisições, anexa tokens de sessão, abre canais em tempo real e padroniza retornos. A segurança, porém, continua nos serviços: RLS no banco, regras no Storage e configuração do Auth.

<Mermaid title="Supabase Client como porta de entrada para os serviços">
{`

O melhor uso do SDK é ficar atrás de módulos pequenos. A tela pede `createInvestment`, `login` ou `uploadAvatar`; o módulo decide qual chamada do Supabase executa.

## Recursos Principais

O mesmo cliente cobre várias áreas da plataforma. A tabela abaixo mostra o que cada família de métodos representa:

| Família | Exemplo | Papel |
| --- | --- | --- |
| **Database** | `from('investments').select()` | Consultar e alterar tabelas pela Database API. |
| **Auth** | `auth.signInWithPassword()` | Criar sessão, renovar token e observar login/logout. |
| **Storage** | `storage.from('avatars').upload()` | Enviar, ler e remover objetos de buckets. |
| **Realtime** | `channel('portfolio').subscribe()` | Receber eventos por WebSocket. |
| **Functions** | `functions.invoke('charge')` | Chamar código serverless da plataforma. |

## Pequenos Trechos

O cliente começa com URL e chave pública. Em Vite, variáveis com `VITE_` entram no bundle, então só valores públicos pertencem aqui:

```js title="Inicialização do Supabase Client"
import { createClient } from '@supabase/supabase-js';

export const supabase = createClient(
  import.meta.env.VITE_SUPABASE_URL,
  import.meta.env.VITE_SUPABASE_ANON_KEY
);
```

Uma consulta simples deve tratar `error` como falha real, não como mensagem de console:

```js title="Leitura com tratamento explícito"
export async function listInvestments() {
  const { data, error } = await supabase
    .from('investments')
    .select('id,name,amount')
    .order('created_at', { ascending: false });

  if (error) {
    throw new Error(error.message);
  }

  return data;
}
```

Uma função de login pertence a um módulo de sessão, não ao componente do formulário:

```js title="Função de sessão"
export async function login(email, password) {
  const { data, error } = await supabase.auth.signInWithPassword({ email, password });

  if (error) {
    throw new Error('E-mail ou senha inválidos.');
  }

  return data.user;
}
```

<Aside type="caution" title="Dica de IA: Não espalhe `supabase.from()` pela interface">
  Código gerado costuma chamar o SDK direto dentro de cada botão e componente. Isso deixa a troca
  de plataforma cara e mistura erro de rede com regra de tela.

  **Prompt:** *"Refatore estas chamadas `supabase.from('investments')` para um módulo `investmentService`, mantendo os componentes dependentes apenas de funções como `listInvestments` e `saveInvestment`."*
</Aside>

## Aplicações

O SDK é uma boa escolha quando o front-end é o cliente principal dos serviços do Supabase. Ele reduz código repetido, integra sessão com chamadas ao banco e permite usar Realtime sem montar WebSocket manualmente.

| Aplicação | Como o SDK ajuda | Cuidado |
| --- | --- | --- |
| CRUD autenticado | Anexa sessão e expõe API fluente. | RLS continua obrigatória. |
| Upload de avatar | Usa Storage com o mesmo projeto e sessão. | Caminho e política precisam impedir sobrescrita cruzada. |
| Interface em tempo real | Abre canais e gerencia eventos. | Ainda precisa de leitura inicial e reconciliação. |
| Chamada administrativa | **Não usar no front-end** | Chave `service_role` exige servidor ou função. |

## Quando Usar, e Quando Não Usar?

Use o Supabase Client para operações públicas ou autenticadas que respeitam as políticas da plataforma. Não use no navegador para tarefas administrativas, integrações pagas ou qualquer fluxo que dependa de segredo.

| Cenário | Escolha | Por quê |
| --- | --- | --- |
| Front-end com login e CRUD | **Supabase Client** | O SDK coordena sessão e chamadas aos serviços. |
| Script de teste ou documentação de contrato | **HTTP direto** | A requisição explícita ensina melhor o protocolo. |
| Webhook ou cobrança | **Edge Function** | O segredo precisa ficar no servidor. |
| API própria com domínio extenso | **Back-end próprio** | A camada de aplicação centraliza regras e testes. |

## Exercício

Por que um módulo de serviço melhora a manutenção quando a aplicação usa Supabase Client?

<details>
  <summary>Possível resposta</summary>

  Porque concentra chamadas ao SDK em um lugar. Os componentes usam funções de domínio, e mudanças de filtro, tratamento de erro ou plataforma não se espalham pela interface.
</details>

## Desafio

Defina três módulos para uma aplicação Supabase: `sessionService`, `investmentService` e `avatarService`. Liste quais métodos do SDK cada um poderia usar.

<details>
  <summary>Possível resposta</summary>

  `sessionService` usa `supabase.auth`, `investmentService` usa `supabase.from('investments')` e `avatarService` usa `supabase.storage.from('avatars')`. Cada módulo devolve funções de domínio em vez de expor o cliente inteiro.
</details>

## Perguntas de revisão

1. **O Supabase Client substitui RLS?**
   <details>
     <summary>Possível resposta</summary>
     Não. Ele apenas faz chamadas. A autorização continua nas políticas do banco e dos serviços.
   </details>

2. **Por que a chave `service_role` não pode ser usada pelo Supabase Client no navegador?**
   <details>
     <summary>Possível resposta</summary>
     Porque ela ignora RLS e qualquer valor no bundle pode ser lido pelo usuário. Ela pertence a servidor ou função.
   </details>
