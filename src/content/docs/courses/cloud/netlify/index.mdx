O **Netlify** é uma plataforma para publicar sites e aplicações web com uma experiência muito centrada no repositório Git. Ele combina build, deploy atômico, CDN global, previews, roteamento versionado, formulários gerenciados, funções serverless, funções de borda e recursos de dados para aplicações web modernas.

## Objetivo

Compreender o Netlify como plataforma de entrega e automação para projetos front-end, distinguindo os produtos que pertencem ao fluxo de publicação, os que pertencem à execução de código e os que evitam criar infraestrutura própria. Ao final do tópico, o leitor deve ser capaz de:

- Explicar por que deploy atômico reduz risco em produção.
- Relacionar Deploys, CDN, redirects, headers e previews.
- Diferenciar Functions, Edge Functions e Forms.
- Reconhecer os casos em que Netlify precisa ser combinado com BaaS, banco ou API própria.
- Comparar Netlify com Vercel, Firebase Hosting, Supabase e Cloudflare Pages.

## Mapa da Plataforma

O Netlify pode ser lido em três camadas: publicação do site, execução de lógica curta e serviços prontos para tarefas comuns. Essa separação evita tratar a plataforma como se fosse apenas "um lugar para subir HTML".

<Mermaid title="Produtos centrais do Netlify">
{`

  Deploys --> Forms["Forms<br/>submissões gerenciadas"]

O ponto forte do Netlify é deixar muita coisa versionada junto do projeto. Build, diretório publicado, redirects, headers e configuração de functions podem viver no repositório, passar por revisão e acompanhar cada deploy preview.

## Produtos e Recursos

A plataforma é mais fácil de escolher quando cada produto é associado a uma responsabilidade concreta.

| Produto | O que resolve | Recursos importantes | Aplicações típicas |
| --- | --- | --- | --- |
| **Deploys** | Publicação de versões completas do site. | Build por Git, deploy preview, branch deploy, deploy atômico, rollback. | Documentação, front-end de SaaS, landing pages, sites Astro, React, Vue ou Svelte. |
| **CDN** | Entrega global de assets. | Cache de arquivos estáticos, URLs versionadas, invalidação por deploy, distribuição global. | Sites com muitos assets, documentação pública, aplicações que precisam carregar rápido. |
| **Redirects e Headers** | Controle de rotas e respostas HTTP. | `_redirects`, `netlify.toml`, rewrites, proxy, headers de segurança e cache. | SPA com fallback, migração de URLs, proxy para API, política de segurança. |
| **Functions** | Código serverless sob demanda. | Rotas HTTP, variáveis privadas, webhooks, integrações com APIs externas. | Pagamentos, envio de e-mail, endpoint de contato, assinatura de requests. |
| **Edge Functions** | Lógica executada antes da resposta chegar à origem. | Personalização, autenticação leve, roteamento por contexto, baixa latência. | Experiências por região, testes A/B, proteção de conteúdo, redirects dinâmicos. |
| **Forms** | Captura de submissões sem back-end próprio. | Detecção por HTML, painel de submissões, notificações, proteção anti-spam. | Contato, newsletter, inscrição de evento, pesquisa simples. |
| **Dados e Storage** | Persistência complementar ao front-end. | Blobs, Netlify Database, cache e integração com bancos externos. | Conteúdo gerado por usuário, pequenos arquivos, protótipos e integrações. |

<Aside type="tip" title="Netlify é plataforma de entrega, não substituto universal de back-end">
  Netlify brilha quando o front-end é o centro da aplicação. Para regras de negócio extensas, transações ricas, controle fino de permissões ou consultas complexas, combine Netlify com Supabase, Firebase, Neon, Turso, PlanetScale, uma API Express ou outro serviço de dados.
</Aside>

## Quando Usar?

O Netlify é uma boa escolha quando a aplicação nasce como site, documentação, front-end estático ou front-end com poucas rotas dinâmicas. Ele também é útil quando o time valoriza previews automáticos por pull request e configuração reproduzível no repositório.

| Cenário | Use Netlify quando | Evite ou complemente quando |
| --- | --- | --- |
| Site institucional ou documentação | O conteúdo é gerado no build e precisa de CDN. | O conteúdo depende de sessão e consulta complexa a cada request. |
| Aplicação front-end com BaaS | Supabase, Firebase ou outro serviço cuidam de dados e auth. | A maior parte da regra de negócio precisa rodar no servidor. |
| Formulário simples | A submissão só precisa ser recebida, notificada e revisada. | O formulário exige fluxo transacional ou validação de domínio pesada. |
| Integração com API privada | Uma Function curta protege tokens e normaliza resposta. | A integração exige filas, retries longos, workers ou auditoria detalhada. |
| Personalização por request | Edge Function decide redirect, headers ou variante. | A lógica depende de bibliotecas Node.js pesadas ou acesso complexo a banco. |

## Configuração Típica

Em muitos projetos, o `netlify.toml` concentra a configuração essencial: comando de build, pasta publicada, redirects, headers e diretório de functions.

```toml
[build]
  command = "pnpm build"
  publish = "dist"

[functions]
  directory = "netlify/functions"

[[redirects]]
  from = "/app/*"
  to = "/app/index.html"
  status = 200

[[headers]]
  for = "/*"
  [headers.values]
    X-Frame-Options = "DENY"
    X-Content-Type-Options = "nosniff"
```

Esse arquivo não é obrigatório para todo projeto, mas ele torna a infraestrutura revisável. Em sala, isso ajuda a discutir deploy como código, não como sequência de cliques no painel.

## Executando

Estude o Netlify começando pela camada de publicação e só depois avance para execução de código.

<Steps>
1. Publique um site estático e confirme o diretório de saída do framework.
2. Adicione `netlify.toml` com build, publish e redirects.
3. Abra um deploy preview de branch e compare com produção.
4. Crie uma Function para proteger um segredo de API externa.
5. Substitua um endpoint simples por Netlify Forms quando o domínio permitir.
6. Avalie se uma Edge Function melhora roteamento, personalização ou autenticação leve.
</Steps>

## Perguntas de revisão

1. **Qual é a diferença entre Functions e Forms?**
   <details>
     <summary>Possível resposta</summary>
     Functions executam código serverless escrito pelo projeto. Forms captura submissões de HTML e entrega um fluxo gerenciado pela plataforma, sem endpoint próprio para o caso simples.
   </details>

2. **Por que redirects versionados são importantes?**
   <details>
     <summary>Possível resposta</summary>
     Porque as regras de rota acompanham o código, passam por revisão e podem ser reproduzidas em previews, produção e rollback.
   </details>

3. **Quando Netlify deve ser combinado com um BaaS?**
   <details>
     <summary>Possível resposta</summary>
     Quando a aplicação precisa de banco, autenticação, regras de autorização, arquivos ou consultas que vão além da publicação do front-end e de funções curtas.
   </details>
