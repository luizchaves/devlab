O **Amplify Hosting** publica aplicações web e front-ends com integração ao Git, builds automáticos, branches, domínios customizados e recursos para aplicações estáticas ou full-stack. Ele é a porta de entrada mais comum para usar Amplify em projetos web.

## Objetivo

Compreender Amplify Hosting como camada de publicação dentro do ecossistema AWS. Ao final do tópico, o leitor deve ser capaz de:

- Explicar o ciclo de build e deploy.
- Diferenciar hosting estático e aplicação full-stack.
- Planejar branches, previews e variáveis.
- Reconhecer quando a integração AWS é vantagem.
- Comparar Amplify Hosting com Vercel, Netlify e Cloudflare Pages.

## Ciclo de Deploy

O fluxo começa no repositório. Amplify executa build, publica a saída e conecta domínios e ambientes pelo console.

<Mermaid title="Deploy com Amplify Hosting">
{`
flowchart TD
  Git["Repositório Git"] --> Build["Build"]
  Build --> Branch["Branch ou preview"]
  Branch --> Hosting["Amplify Hosting"]
  Hosting --> Domain["Domínio e HTTPS"]
  Hosting --> User["Usuário"]
`}
</Mermaid>

Quando o app usa Auth, Data, Storage ou Functions do Amplify, o hosting vira parte de uma aplicação full-stack, não apenas o lugar onde os arquivos estáticos ficam.

## Recursos

Amplify Hosting fica mais interessante quando publicação e backend gerenciado fazem parte do mesmo fluxo.

| Recurso | O que resolve | Atenção |
| --- | --- | --- |
| **Build por Git** | Publica a partir de commits e branches. | Verifique comando, saída e versão do runtime. |
| **Branch deployments** | Separa preview, staging e produção. | Cada branch pode precisar de variáveis próprias. |
| **Domínios customizados** | Conecta domínio e HTTPS. | DNS e certificados entram na operação. |
| **SSR e full-stack** | Hospeda frameworks que precisam de servidor. | Entenda o que roda no cliente e no servidor. |
| **Integração com backend** | Conecta recursos Amplify ao app. | Permissões e custo passam a envolver AWS. |

## Variáveis e Ambientes

Como em qualquer hosting moderno, variáveis públicas podem ir para o bundle, enquanto segredos pertencem ao runtime de servidor ou functions.

```txt title="Classificação de variáveis no Hosting"
PUBLIC_API_URL: pode aparecer no front-end
AMPLIFY_AUTH_REGION: configuração pública do app
PAYMENT_SECRET: somente servidor ou Function
DATABASE_ADMIN_TOKEN: nunca no bundle
```

O prefixo e a forma exata dependem do framework, mas o princípio não muda: tudo que chega ao navegador deve ser tratado como público.

<Aside type="caution" title="Dica de IA: Peça separação entre build e runtime">
  Assistentes podem listar variáveis sem dizer se são avaliadas durante o build ou durante a execução. Em Amplify, essa diferença decide se o valor pode virar JavaScript público.

  **Prompt:** *"Classifique estas variáveis de Amplify Hosting entre build, runtime de servidor e segredo; explique quais podem aparecer no navegador e quais devem ficar em Function."*
</Aside>

## Critérios de Uso

Use Amplify Hosting quando a publicação do front-end deve estar próxima dos recursos AWS do app.

| Cenário | Encaixa bem? | Motivo |
| --- | --- | --- |
| App React ou Next.js com Auth e Data Amplify | **Sim** | Hosting e backend ficam no mesmo fluxo. |
| Organização já padronizada em AWS | **Sim** | Governança e contas existentes ajudam. |
| Site estático isolado | **Talvez** | Vercel, Netlify, Cloudflare Pages ou GitHub Pages podem ser mais simples. |
| Projeto didático sem AWS | **Talvez não** | O ecossistema pode adicionar complexidade cedo. |

## Executando

Estude Hosting como primeira peça do Amplify.

<Steps>
1. Identifique framework, comando de build e pasta de saída.
2. Configure branch principal e branch de preview.
3. Classifique variáveis públicas e privadas.
4. Conecte domínio customizado somente depois do preview funcionar.
5. Revise logs de build e diferenças entre ambientes.
</Steps>

## Exercício

Por que um site estático simples talvez não precise de Amplify Hosting?

<details>
  <summary>Possível resposta</summary>

  Porque, se não há necessidade de integração AWS, auth, dados ou backend Amplify, plataformas mais simples como GitHub Pages, Netlify, Vercel ou Cloudflare Pages podem resolver com menos complexidade.
</details>

## Desafio

Planeje o deploy de um front-end do InvestApp em Amplify Hosting com Supabase como dados. Liste quais variáveis seriam públicas e quais exigiriam Function.

<details>
  <summary>Possível resposta</summary>

  URL e chave anônima do Supabase podem ser públicas se RLS estiver correta. Service role, token de pagamento e segredo de e-mail exigem Function ou API de servidor.
</details>

## Perguntas de revisão

1. **Quando Amplify Hosting fica mais interessante do que hosting estático simples?**
   <details>
     <summary>Possível resposta</summary>
     Quando o app também usa recursos Amplify ou AWS, como Auth, Data, Storage e Functions.
   </details>

2. **Por que branch deployment exige atenção a variáveis?**
   <details>
     <summary>Possível resposta</summary>
     Porque preview e produção podem usar chaves, domínios e recursos diferentes.
   </details>
