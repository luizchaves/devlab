O **AWS Amplify** é a porta de entrada da AWS para aplicações web e mobile full-stack. Ele reúne hospedagem, autenticação, dados, storage e funções com uma experiência mais guiada do que montar cada serviço AWS isoladamente.

## Objetivo

Compreender o Amplify como camada de produtividade sobre serviços AWS, distinguindo o que ele simplifica e quais compromissos continuam existindo. Ao final do tópico, o leitor deve ser capaz de:

- Explicar o papel do Amplify Hosting.
- Relacionar Auth, Data, Storage e Functions dentro de uma aplicação.
- Reconhecer quando a integração com AWS é vantagem.
- Identificar quando a complexidade de cloud provider completo pesa demais.
- Comparar Amplify com Firebase, Supabase, Vercel e Netlify.

## Mapa da Plataforma

Amplify deve ser lido como uma experiência de desenvolvimento, não como um único serviço isolado. Por trás dele existem recursos AWS, mas o desenvolvedor interage por uma camada mais próxima do projeto.

<Mermaid title="Camadas do AWS Amplify">
{`
flowchart TD
  App["Aplicação web ou mobile"] --> Hosting["Hosting<br/>build e deploy"]
  App --> Auth["Auth<br/>identidade"]
  App --> Data["Data<br/>modelos e API"]
  App --> Storage["Storage<br/>arquivos"]
  App --> Functions["Functions<br/>lógica de servidor"]
  Auth --> AWS["Serviços AWS"]
  Data --> AWS
  Storage --> AWS
  Functions --> AWS
`}
</Mermaid>

A vantagem é começar rápido em uma nuvem grande. O custo é que, ao crescer, o time precisa entender conceitos de permissão, ambientes, cobrança e observabilidade do próprio ecossistema AWS.

## Produtos e Recursos

Os recursos principais cobrem as mesmas perguntas de qualquer aplicação: onde publicar, como autenticar, onde guardar dados e onde executar segredo.

| Produto | O que resolve | Aplicações típicas | Atenção |
| --- | --- | --- | --- |
| **Amplify Hosting** | Build e deploy de front-end e aplicações full-stack. | React, Next.js, Vue, Angular, Astro e sites estáticos. | Configure ambientes e variáveis com cuidado. |
| **Auth** | Cadastro, login e identidade. | Login por e-mail, social login, sessão de usuário. | Regras de acesso continuam sendo parte do desenho de dados. |
| **Data** | API e modelos de dados integrados ao app. | CRUD de entidades de produto, protótipos e apps mobile. | Entenda o formato de modelagem antes de acoplar o domínio. |
| **Storage** | Arquivos associados à aplicação. | Avatares, anexos, imagens e uploads de usuário. | Permissão por usuário precisa ser desenhada. |
| **Functions** | Lógica de servidor e integrações. | Webhooks, tarefas com segredo, validações externas. | Não substitui arquitetura cuidadosa em domínio extenso. |

## Critérios de Uso

Amplify faz sentido quando o projeto quer entrar no ecossistema AWS sem começar por IAM, CloudFormation, API Gateway, Lambda e serviços separados logo no primeiro dia.

| Cenário | Amplify encaixa bem? | Motivo |
| --- | --- | --- |
| Aplicação web ou mobile com login e dados | **Sim** | A plataforma integra hosting, auth, dados e storage. |
| Time que já usa AWS | **Sim** | Integração com contas, governança e serviços existentes ajuda. |
| Prova de conceito full-stack | **Sim** | O caminho inicial é mais curto que montar serviços manualmente. |
| Curso introdutório sem foco em AWS | **Talvez** | A produtividade inicial pode esconder conceitos importantes. |
| Projeto que precisa de portabilidade máxima | **Cuidado** | O acoplamento ao ecossistema AWS tende a crescer. |

<Aside type="caution" title="Dica de IA: Peça a fronteira entre Amplify e AWS">
  Assistentes podem gerar instruções que misturam Amplify com configuração manual de serviços AWS sem explicar quem é responsável por cada parte. Isso cria tutoriais que funcionam uma vez e ficam difíceis de manter.

  **Prompt:** *"Explique, neste plano de deploy com Amplify, quais recursos são configurados pelo Amplify e quais exigem configuração AWS separada; destaque riscos de permissão, custo e ambiente."*
</Aside>

## Comparação Com BaaS e Hosting

Amplify se sobrepõe parcialmente a Firebase, Supabase, Vercel e Netlify, mas parte de uma premissa diferente: integração com um provedor amplo.

| Comparação | Amplify tende a ganhar quando | Outra opção tende a ganhar quando |
| --- | --- | --- |
| **Amplify x Firebase** | O time já usa AWS ou quer compor serviços AWS. | O app precisa de SDK mobile maduro e ecossistema Firebase. |
| **Amplify x Supabase** | A prioridade é integração AWS. | A prioridade é PostgreSQL, SQL e RLS. |
| **Amplify x Vercel** | O app precisa de auth, dados e storage no mesmo fluxo AWS. | O foco é front-end, Next.js e deploy preview. |
| **Amplify x Netlify** | A aplicação precisa de stack full-stack AWS. | O projeto é site/JAMstack com forms, redirects e functions curtas. |

## Executando

Estude Amplify como composição de serviços, sempre anotando o que ficaria preso ao ecossistema AWS.

<Steps>
1. Comece pelo Hosting e publique uma aplicação simples.
2. Adicione autenticação e descreva o ciclo de sessão.
3. Modele uma entidade pequena em Data.
4. Separe arquivos públicos e privados em Storage.
5. Use Function apenas para lógica que exige segredo ou servidor.
6. Revise custo, permissões, ambientes e plano de saída.
</Steps>

## Exercício

Por que Amplify pode ser mais simples no início e mais complexo quando o projeto cresce?

<details>
  <summary>Possível resposta</summary>

  Porque ele oferece uma entrada guiada para recursos AWS, reduzindo configuração inicial. Quando o projeto cresce, aparecem os mesmos temas de uma nuvem grande: permissões, cobrança, ambientes, observabilidade, integrações e governança.
</details>

## Desafio

Compare Amplify e Supabase para o InvestApp. Indique qual escolheria se o requisito principal fosse SQL e qual escolheria se a instituição já operasse toda a infraestrutura na AWS.

<details>
  <summary>Possível resposta</summary>

  Se SQL, relatórios e RLS forem centrais, Supabase tende a ser a escolha mais direta. Se a instituição já usa AWS, tem políticas internas, contas, auditoria e serviços integrados, Amplify pode ser mais adequado como entrada para esse ecossistema.
</details>

## Perguntas de revisão

1. **O que o Amplify simplifica para um projeto web?**
   <details>
     <summary>Possível resposta</summary>
     Ele simplifica o acesso inicial a hosting, autenticação, dados, storage e funções integrados ao ecossistema AWS.
   </details>

2. **Qual risco aparece ao adotar Amplify sem entender AWS?**
   <details>
     <summary>Possível resposta</summary>
     O time pode depender de permissões, ambientes e serviços que não consegue diagnosticar quando algo falha ou quando a cobrança cresce.
   </details>

3. **Quando Supabase pode ser uma escolha mais simples?**
   <details>
     <summary>Possível resposta</summary>
     Quando o domínio é naturalmente relacional, o time conhece SQL e as regras de acesso cabem bem em políticas de RLS.
   </details>
