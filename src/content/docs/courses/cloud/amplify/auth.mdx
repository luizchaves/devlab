O **Amplify Auth** adiciona autenticação a aplicações web e mobile usando recursos AWS por baixo, especialmente Amazon Cognito. Ele cobre cadastro, login, sessão, provedores sociais, grupos e integração com regras de acesso em Data e Storage.

## Objetivo

Compreender Auth como identidade gerenciada dentro do Amplify. Ao final do tópico, o leitor deve ser capaz de:

- Diferenciar autenticação e autorização.
- Explicar o papel de usuários, grupos e provedores.
- Relacionar Auth com Data e Storage.
- Planejar ciclos de cadastro, login e recuperação de senha.
- Reconhecer quando personalização exige cuidado com Cognito e AWS.

## Fluxo de Identidade

Auth resolve quem é o usuário. A autorização, ou seja, o que ele pode acessar, aparece quando Data e Storage usam essa identidade para aplicar regras.

<Mermaid title="Auth conectando identidade a dados">
{`
flowchart TD
  User["Usuário"] --> Auth["Amplify Auth"]
  Auth --> Token["Sessão e tokens"]
  Token --> Data["Amplify Data<br/>regras por usuário ou grupo"]
  Token --> Storage["Amplify Storage<br/>arquivos protegidos"]
`}
</Mermaid>

O erro clássico é tratar login como segurança completa. Login identifica; regras de acesso protegem recursos.

## Recursos

Auth oferece os fluxos comuns de identidade que quase toda aplicação precisa cedo.

| Recurso | O que resolve | Aplicação típica |
| --- | --- | --- |
| **Cadastro e login** | Cria usuário e sessão. | Área autenticada de app. |
| **Recuperação de senha** | Fluxo de redefinição. | Produto público com conta própria. |
| **Provedores sociais** | Login por contas externas. | Reduzir atrito de entrada. |
| **Grupos** | Classificação de usuários. | Admin, professor, aluno, suporte. |
| **Integração com Data e Storage** | Autorização por identidade. | Dados e arquivos por dono ou grupo. |

## Exemplo de Regra Mental

Em Amplify, a regra de autorização costuma ser expressa junto do recurso. O trecho abaixo é conceitual e mostra a intenção de dono dos dados.

```txt title="Regra conceitual de dono"
Portfolio: {
  owner: 'authenticated user',
  operations: ['create', 'read', 'update', 'delete'],
}
```

O formato real depende da versão e do recurso, mas a ideia não muda: Auth fornece identidade, e o recurso aplica a política.

<Aside type="caution" title="Dica de IA: Peça regras de acesso, não só tela de login">
  Assistentes geram formulário de login com facilidade e esquecem a política que protege dados depois da autenticação.

  **Prompt:** *"Além do fluxo de login com Amplify Auth, escreva as regras de autorização para que cada usuário acesse apenas as próprias carteiras e explique como testar acesso cruzado."*
</Aside>

## Critérios de Uso

Use Auth quando o projeto quer identidade gerenciada dentro de uma aplicação Amplify ou AWS.

| Cenário | Encaixa bem? | Motivo |
| --- | --- | --- |
| App Amplify com Data e Storage | **Sim** | Identidade alimenta regras de acesso. |
| Login social ou por e-mail | **Sim** | Fluxos comuns já vêm organizados. |
| Organização com Cognito existente | **Sim, com cuidado** | Pode reutilizar infraestrutura, mas exige entendimento. |
| App simples com auth em Supabase | **Talvez não** | Misturar dois provedores de auth aumenta complexidade. |

## Executando

Projete Auth começando pelos papéis do domínio.

<Steps>
1. Liste tipos de usuário e permissões.
2. Defina fluxos de cadastro, login e recuperação.
3. Escolha se haverá provedores sociais.
4. Ligue identidade às regras de Data e Storage.
5. Teste acesso cruzado entre usuários e grupos.
</Steps>

## Exercício

Por que autenticação sem autorização ainda pode vazar dados?

<details>
  <summary>Possível resposta</summary>

  Porque saber quem é o usuário não define automaticamente quais registros e arquivos ele pode acessar. Essa decisão precisa de regras em Data, Storage ou API.
</details>

## Desafio

Modele três grupos para um app educacional no Amplify: aluno, professor e admin. Indique um recurso permitido para cada grupo.

<details>
  <summary>Possível resposta</summary>

  Aluno lê o próprio progresso. Professor lê turmas que ministra. Admin gerencia usuários e configurações globais.
</details>

## Perguntas de revisão

1. **Qual é a diferença entre Auth e autorização?**
   <details>
     <summary>Possível resposta</summary>
     Auth identifica o usuário. Autorização decide quais dados, arquivos e ações aquele usuário pode acessar.
   </details>

2. **Por que grupos podem simplificar regras?**
   <details>
     <summary>Possível resposta</summary>
     Porque permitem expressar permissões por papel, como admin ou professor, em vez de regra individual para cada usuário.
   </details>
