Nesta etapa, o InvestApp ganha interface conectada ao Supabase. O módulo `storage.js` esconde o SDK atrás de funções de domínio, preservando o restante da aplicação caso a persistência mude depois.

<ProjectLinks path="examples/courses/cloud/supabase-client/invest-app" devcontainer={false} />

## Objetivo

Conectar o front-end do InvestApp ao Supabase com o SDK oficial, mantendo o acesso aos dados isolado em uma camada de serviço. Ao final do tópico, o leitor deve ser capaz de:

- Inicializar `@supabase/supabase-js` com variáveis `VITE_`.
- Implementar `create`, `read`, `update` e `remove` sobre a tabela `investments`.
- Tratar respostas `{ data, error }` de forma consistente.
- Explicar por que a chave `service_role` nunca entra no front-end.
- Comparar a ergonomia do SDK com as chamadas HTTP da etapa anterior.

As variáveis expostas ao Vite identificam o projeto e a chave pública. O conteúdo abaixo é escrito manualmente porque o componente de código não publica dotfiles:

```ini title=".env.example"
VITE_APP_SUPABASE_URL=https://seu-projeto.supabase.co
VITE_APP_SUPABASE_KEY=sua_chave_anon
```

## Executando

Rode a etapa como uma aplicação Vite:

<Steps>
1. Instale as dependências dentro de `examples/courses/cloud/supabase-client/invest-app`.
2. Preencha as variáveis `VITE_APP_SUPABASE_URL` e `VITE_APP_SUPABASE_KEY`.

## Exercício

Por que `storage.js` devolve funções genéricas como `create(resource, data)` em vez de chamar o SDK diretamente no componente?

<details>
  <summary>Possível resposta</summary>

  Para isolar a persistência. A interface fala com uma camada de domínio simples, e a troca de Supabase por Firebase ou API própria afeta menos arquivos.
</details>

## Desafio

Adicione paginação ao `read`, recebendo `page` e `perPage`, e explique como isso muda o custo da tela quando a tabela cresce.

<details>
  <summary>Possível resposta</summary>

  A função pode usar `.range(from, to)` e, se precisar do total, `.select('*', { count: 'exact' })`. Isso evita trazer a tabela inteira quando a carteira tem muitos registros.
</details>

## Perguntas de revisão

1. **Qual arquivo concentra o acesso ao Supabase nesta etapa?**
   <details>
     <summary>Possível resposta</summary>
     `js/services/storage.js`.
   </details>

2. **Por que `VITE_APP_SUPABASE_KEY` ainda exige RLS?**
   <details>
     <summary>Possível resposta</summary>
     Porque variáveis `VITE_` entram no JavaScript publicado. A chave é pública, então a proteção precisa estar nas políticas.
   </details>
