Nesta etapa, o InvestApp troca o modelo relacional do Supabase pelo modelo de documentos do Firestore. A interface continua parecida, mas o módulo de serviço muda: não há tabela, `id` não é campo do documento e algumas consultas exigem modelagem diferente.

## Objetivo

Reimplementar a persistência do InvestApp com Cloud Firestore, comparando o custo mental de coleções e documentos com a etapa anterior em Supabase. Ao final do tópico, o leitor deve ser capaz de:

- Inicializar o Firebase a partir de variáveis de ambiente.
- Criar, listar, atualizar e remover documentos da coleção `investments`.
- Explicar por que o `id` do documento precisa ser reunido aos dados lidos.
- Identificar consultas que o Firestore aceita, exige índice ou não resolve.
- Comparar modelagem por tela e modelagem relacional.

<Aside type="caution" title="Dica de IA: Peça a modelagem antes da consulta">
  O Firestore não é SQL em JSON. Assistentes sugerem `like`, junções e filtros arbitrários porque parecem naturais para quem veio de tabela, mas essas consultas não existem ou exigem índice específico.

</Aside>

## Executando

Rode esta etapa como alternativa à etapa de Supabase Client:

<Steps>

## Exercício

Por que a função de leitura devolve `id: doc.id` junto dos campos de `doc.data()`?

<details>
  <summary>Possível resposta</summary>

  Porque o identificador do documento fica no caminho do Firestore, não dentro do objeto de dados. A interface precisa dele para atualizar ou remover o documento depois.
</details>

## Desafio

Adapte a modelagem para que cada usuário leia apenas os próprios investimentos. Compare duas opções: coleção global com campo `user_id` e subcoleção `users/{uid}/investments`.

<details>
  <summary>Possível resposta</summary>

  A coleção global facilita relatórios administrativos, mas exige regras que comparem `resource.data.user_id`. A subcoleção aproxima o caminho da regra, com `users/{uid}/investments/{id}`, e simplifica acesso por dono, mas muda consultas globais.
</details>

## Perguntas de revisão

1. **Qual é a unidade persistida no Firestore?**
   <details>
     <summary>Possível resposta</summary>
     O documento, organizado dentro de uma coleção.
   </details>

2. **Por que esta etapa é alternativa à etapa de Supabase Client?**
   <details>
     <summary>Possível resposta</summary>
     Porque as duas implementam persistência cloud para o mesmo domínio. Elas existem lado a lado para comparar modelos, não para serem usadas juntas no CRUD inicial.
   </details>
