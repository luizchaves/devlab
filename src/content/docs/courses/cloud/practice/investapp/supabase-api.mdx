Nesta etapa, o InvestApp deixa de precisar de uma rota Express para o CRUD inicial. A tabela `investments` é criada no Supabase, o PostgREST publica a API automaticamente e as requisições HTTP mostram o contrato sem esconder nada atrás de SDK.

<ProjectLinks path="examples/courses/cloud/supabase-api" devcontainer={false} />

## Objetivo

Construir a primeira persistência cloud do InvestApp com Supabase API, entendendo como tabela, RLS, filtros e cabeçalhos HTTP substituem a rota escrita à mão. Ao final do tópico, o leitor deve ser capaz de:

- Criar a tabela `investments` usada pelo domínio do InvestApp.
- Habilitar uma política RLS de estudo e reconhecer por que ela não serve para produção.
- Executar `POST`, `GET`, `PATCH` e `DELETE` diretamente contra o PostgREST.
- Interpretar filtros como `eq` e `gt` na URL.
- Preparar a passagem para o SDK cliente da próxima etapa.

## Executando

Os passos abaixo reproduzem a etapa sem front-end:

<Steps>
1. Crie o projeto no Supabase e execute o SQL de criação da tabela `investments`.
2. Habilite RLS e aplique a política de estudo.
3. Preencha `SUPABASE_URL` e `SUPABASE_KEY` em um `.env` local.
4. Execute as requisições `.http` ou os scripts `.sh`.
5. Confira no painel do Supabase se cada operação alterou apenas o registro esperado.
</Steps>

## Exercício

Explique por que esta etapa usa HTTP puro antes de instalar `@supabase/supabase-js`.

<details>
  <summary>Possível resposta</summary>

  Porque HTTP puro torna visíveis URL, método, cabeçalhos, corpo, status e filtros. Depois que o contrato fica claro, o SDK pode melhorar ergonomia sem esconder a arquitetura.
</details>

## Desafio

Troque a política permissiva de estudo por uma política que exige usuário autenticado e coluna `user_id`. Liste quais requisições desta etapa deixam de funcionar sem login.

<details>
  <summary>Possível resposta</summary>

  A tabela precisa de `user_id uuid default auth.uid()`. A política compara `auth.uid() = user_id`. Requisições com apenas a anon key deixam de criar, listar, atualizar e remover linhas, porque falta o JWT de usuário.
</details>

## Perguntas de revisão

1. **O que o PostgREST gera a partir da tabela `investments`?**
   <details>
     <summary>Possível resposta</summary>
     Uma API REST para consultar e modificar a tabela, respeitando permissões e políticas do PostgreSQL.
   </details>

2. **Por que a anon key não é uma senha secreta?**
   <details>
     <summary>Possível resposta</summary>
     Porque ela pode ir ao navegador. A proteção real dos dados vem das políticas RLS.
   </details>
