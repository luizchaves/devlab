Bootstrap é uma biblioteca front-end para criar interfaces Web com HTML, CSS e
JavaScript prontos para uso. Em vez de escrever todos os estilos do zero, o
desenvolvedor aplica classes como `container`, `row`, `col`, `btn`,
`text-center`, `d-flex` e `mt-3` para montar layouts, botões, formulários,
navegações e outros componentes comuns.

Ele não substitui HTML nem CSS. Bootstrap é uma camada pronta em cima deles:
o HTML continua descrevendo a estrutura da página e o CSS continua definindo a
aparência. A diferença é que muitas decisões visuais já vêm organizadas em classes,
componentes e padrões responsivos.

## Objetivo

Entender o que o Bootstrap resolve, como ele entra em uma página, quais partes da
biblioteca aparecem com mais frequência e quando faz sentido usá-lo em um projeto.
Ao final, você deve conseguir ler uma página com Bootstrap sem tratar cada classe
como um código misterioso.

## Versão Atual

Nesta aula, vamos usar **Bootstrap 5.3.8** como versão de referência. Escolher uma
versão específica deixa os exemplos mais previsíveis, porque todos usam a mesma
documentação, os mesmos arquivos de CSS e o mesmo JavaScript.

<Aside type="note" title="Versão usada nos exemplos">
  Use a mesma versão de CSS e JavaScript do Bootstrap na página. Misturar, por
  exemplo, CSS 5.3.8 com JavaScript 5.3.1 pode gerar diferenças sutis em
  componentes interativos.
</Aside>

Referências: [página de versões do Bootstrap](https://getbootstrap.com/docs/versions/),
[download oficial](https://getbootstrap.com/docs/5.3/getting-started/download/) e
[pacote bootstrap no npm](https://www.npmjs.com/package/bootstrap).

## O Que o Bootstrap Resolve?

Em um projeto sem biblioteca visual, o desenvolvedor precisa definir muitas regras
recorrentes: espaçamento, largura máxima do conteúdo, grid responsivo, aparência de
botões, campos de formulário, navegação, cards, tabelas, alertas e estados de foco.
Bootstrap entrega boa parte desse vocabulário pronto.

<Aside type="tip" title="CSS e JavaScript têm papéis diferentes">
  O CSS do Bootstrap já resolve estilos, grid, espaçamento, cores e aparência dos
  componentes. O JavaScript é necessário para componentes interativos, como modal,
  dropdown, collapse, offcanvas, tooltip e toast.

  Em muitos casos, isso reduz ou até elimina a necessidade de escrever CSS próprio
  para uma tela simples. Mesmo assim, nada impede criar uma folha CSS do projeto
  para ajustar detalhes que ficam fora do Bootstrap, como identidade visual,
  espaçamentos específicos, variações de componentes e regras próprias da aplicação.
</Aside>

## Modelo Mental

Bootstrap fica mais fácil quando é visto em camadas. Primeiro existe uma base de
estilo para normalizar elementos HTML. Depois vêm classes utilitárias, sistema de
layout, componentes prontos e plugins JavaScript.

| Camada | Exemplos | Ideia principal |
| ------ | -------- | --------------- |
| Base | [Reboot](https://getbootstrap.com/docs/5.3/content/reboot/), [tipografia](https://getbootstrap.com/docs/5.3/content/typography/), [tabelas](https://getbootstrap.com/docs/5.3/content/tables/) | Ajustar estilos padrão do navegador e dar uma base visual consistente |
| Layout | [`container`](https://getbootstrap.com/docs/5.3/layout/containers/), [`row` e `col`](https://getbootstrap.com/docs/5.3/layout/grid/), [breakpoints](https://getbootstrap.com/docs/5.3/layout/breakpoints/) | Distribuir conteúdo em colunas e adaptar a tela a diferentes larguras |
| Utilitários | [`p-3`](https://getbootstrap.com/docs/5.3/utilities/spacing/), [`mt-4`](https://getbootstrap.com/docs/5.3/utilities/spacing/), [`d-flex`](https://getbootstrap.com/docs/5.3/utilities/display/), [`text-center`](https://getbootstrap.com/docs/5.3/utilities/text/) | Aplicar uma regra pequena e direta sem criar uma classe nova |
| Helpers | [`text-bg-primary`](https://getbootstrap.com/docs/5.3/helpers/color-background/), [`clearfix`](https://getbootstrap.com/docs/5.3/helpers/clearfix/), [`ratio`](https://getbootstrap.com/docs/5.3/helpers/ratio/) | Resolver padrões específicos que combinam mais de uma regra ou melhoram casos comuns |
| Componentes | [`btn`](https://getbootstrap.com/docs/5.3/components/buttons/), [`card`](https://getbootstrap.com/docs/5.3/components/card/), [`navbar`](https://getbootstrap.com/docs/5.3/components/navbar/), [`alert`](https://getbootstrap.com/docs/5.3/components/alerts/), [`modal`](https://getbootstrap.com/docs/5.3/components/modal/) | Reutilizar padrões de interface já documentados |
| JavaScript | [Dropdown](https://getbootstrap.com/docs/5.3/components/dropdowns/), [modal](https://getbootstrap.com/docs/5.3/components/modal/), [collapse](https://getbootstrap.com/docs/5.3/components/collapse/), [toast](https://getbootstrap.com/docs/5.3/components/toasts/) | Adicionar comportamento a componentes que precisam de interação |

## Base Visual

Antes dos componentes e utilitários, o Bootstrap aplica uma base chamada
[Reboot](https://getbootstrap.com/docs/5.3/content/reboot/). Ela ajusta padrões do
navegador para deixar texto, links, títulos, listas, tabelas e formulários mais
previsíveis entre diferentes navegadores.

Reboot não significa que todos os elementos ficam com aparência de componente. Ele
é uma base discreta: melhora consistência, usa `box-sizing: border-box`, remove a
margem padrão do `body`, define tipografia base e ajusta detalhes de elementos HTML.

### Nomes de Cores

Bootstrap usa nomes semânticos para cores. Em vez de decorar o valor exato de azul,
verde ou vermelho, o mais importante é entender a intenção: ação principal,
informação secundária, sucesso, alerta, erro e assim por diante.

| Nome | Ideia comum | Exemplos de classe |
| ---- | ----------- | ------------------ |
| `primary` | Ação ou destaque principal | `btn-primary`, `text-primary`, `text-bg-primary` |
| `secondary` | Informação ou ação secundária | `btn-secondary`, `text-secondary`, `text-bg-secondary` |
| `success` | Sucesso, confirmação ou estado positivo | `btn-success`, `text-success`, `text-bg-success` |
| `danger` | Erro, remoção ou ação destrutiva | `btn-danger`, `text-danger`, `text-bg-danger` |
| `warning` | Atenção ou estado que exige cuidado | `btn-warning`, `text-warning`, `text-bg-warning` |
| `info` | Informação complementar | `btn-info`, `text-info`, `text-bg-info` |
| `light` | Superfície clara ou contraste suave | `btn-light`, `bg-light`, `text-bg-light` |
| `dark` | Superfície escura ou contraste forte | `btn-dark`, `bg-dark`, `text-bg-dark` |

<Aside type="tip" title="Cores são semânticas">
  `primary` não deve ser entendido apenas como "azul". Em um projeto customizado,
  a cor principal pode mudar, mas a intenção da classe continua sendo indicar o
  destaque principal da interface.
</Aside>

## Classes Utilitárias

Utilitários são classes pequenas e focadas. Em CSS puro, você poderia criar uma
classe própria para cada ajuste visual. Com Bootstrap, muitos ajustes comuns já
existem.

| Grupo | Classes | Efeito comum |
| ----- | ------- | ------------ |
| [Espaçamento](https://getbootstrap.com/docs/5.3/utilities/spacing/) | `m-0`, `mt-3`, `mb-4`, `p-3`, `px-4` | Controlam `margin` e `padding` |
| [Texto](https://getbootstrap.com/docs/5.3/utilities/text/) | `text-start`, `text-center`, `fw-bold`, `fs-4` | Alinhamento, peso e tamanho de texto |
| [Cor](https://getbootstrap.com/docs/5.3/utilities/colors/) | `text-primary`, `bg-light`, `text-bg-success` | Cor de texto, fundo ou combinação acessível |
| [Display](https://getbootstrap.com/docs/5.3/utilities/display/) | `d-none`, `d-block`, `d-flex`, `d-grid` | Alteram o tipo de layout do elemento |
| [Flexbox](https://getbootstrap.com/docs/5.3/utilities/flex/) | `justify-content-between`, `align-items-center`, `gap-2` | Organizam itens dentro de um contêiner flexível |
| [Responsivo](https://getbootstrap.com/docs/5.3/layout/breakpoints/) | `d-md-flex`, `text-lg-start`, `mt-sm-4` | Aplicam regras apenas a partir de um breakpoint |

No exemplo a seguir, observe como as classes utilitárias resolvem espaçamento,
alinhamento, tamanho de texto, cor secundária e botão sem escrever uma folha CSS
própria.

</Aside>

| Componente | Uso comum | Precisa de JavaScript? |
| ---------- | --------- | ---------------------- |
| Button | Ações e links destacados | Não |
| Card | Agrupar conteúdo relacionado | Não |
| Navbar | Navegação principal | Apenas para collapse/dropdown |
| Alert | Mensagens de estado | Só para fechar dinamicamente |
| Modal | Janela sobre a página | Sim |
| Dropdown | Menu suspenso | Sim |

## Grid e Responsividade

O grid do Bootstrap divide a largura disponível em 12 colunas. A combinação mais
comum é `container`, `row` e `col`: o contêiner centraliza e limita a largura, a
linha agrupa colunas, e as colunas definem como o espaço será dividido.

<HtmlPreview
  path="examples/css/frameworks/bootstrap/responsive-grid/index.html"
  height="18rem"
/>

<SourceCode
  path="examples/css/frameworks/bootstrap/responsive-grid/index.html"
  title="Grid responsivo"
  lines="13-33"
  showLineNumbers
  mark={[
    'class="container py-4"',
    'class="row g-3"',
    'class="row g-3 mb-3"',
    'class="col-8"',
    'class="col-4"',
    'class="col-12 col-md-8"',
    'class="col-12 col-md-4"',
  ]}
/>

No exemplo, a primeira linha usa `col-8` e `col-4`, então a divisão 8/4 vale para
qualquer largura. A segunda linha começa com largura inteira em telas pequenas
(`col-12`) e só muda a partir do breakpoint `md`: a primeira coluna passa a ocupar
8 partes e a segunda 4.

| Breakpoint | Infixo | Largura mínima |
| ---------- | ------ | -------------- |
| Extra small | nenhum | &lt;576px |
| Small | `sm` | 576px |
| Medium | `md` | 768px |
| Large | `lg` | 992px |
| Extra large | `xl` | 1200px |
| Extra extra large | `xxl` | 1400px |

<Aside type="tip" title="Pense mobile first">
  Classes sem breakpoint valem para todos os tamanhos. Classes com `sm`, `md`,
  `lg`, `xl` ou `xxl` passam a valer a partir daquela largura. Por isso,
  `col-12 col-md-6` significa: largura inteira primeiro, metade da linha em telas
  médias ou maiores.
</Aside>

## Quando Usar

Bootstrap é útil quando a prioridade é montar telas consistentes com velocidade,
especialmente em sistemas administrativos, protótipos, páginas institucionais,
dashboards simples e projetos em que a equipe prefere seguir um padrão já pronto.

Ele pode ser menos adequado quando o projeto exige uma identidade visual muito
específica, animações complexas, componentes altamente customizados ou quando a
equipe quer controlar cada detalhe do CSS. Mesmo nesses casos, Bootstrap ainda pode
servir como referência de organização, nomes de classes e documentação.

## Exemplos e Templates

Além da documentação de componentes, Bootstrap mantém uma página de
[exemplos oficiais](https://getbootstrap.com/docs/5.3/examples/) com starters,
snippets e layouts completos. Ela é útil para observar como as classes aparecem em
interfaces reais: cabeçalhos, sidebars, páginas de preço, checkout, dashboards,
navbars e formulários de login.

Esses exemplos podem servir como ponto de partida para um projeto ou como
referência de composição. A ideia não é copiar a tela inteira sem entender, mas
identificar padrões: como o grid foi montado, quais componentes foram combinados,
onde aparecem utilitários de espaçamento e quando foi necessário adicionar CSS
próprio.

Também existem galerias de templates construídos com Bootstrap, como
[BootstrapMade](https://bootstrapmade.com/) e
[Start Bootstrap](https://startbootstrap.com/themes). Elas ajudam a buscar
inspiração visual e repertório de layout, especialmente para portfolios, páginas
institucionais, dashboards e landing pages.

<Aside type="caution" title="Template não substitui projeto">
  Antes de usar um template, verifique licença, dependências e versão do Bootstrap.
  Em aula, use templates principalmente como referência: extraia ideias de layout,
  navegação e componentes, mas adapte o código ao objetivo do projeto.
</Aside>

<Aside type="tip" title="IA como apoio para criar telas">
  Ferramentas de IA também podem ajudar a construir uma página ou um elemento de
  interface com Bootstrap. Para ter bons resultados, descreva o objetivo da tela,
  o público, o conteúdo obrigatório, os componentes esperados, a versão do
  Bootstrap, restrições de layout e o formato de entrega. Depois, revise o HTML
  gerado, teste responsividade, confira acessibilidade e adapte nomes, textos e
  estilos ao projeto.

  Um prompt útil costuma ser específico:

## Cuidados Comuns

| Cuidado | Por que importa |
| ------- | --------------- |
| Não decorar sem entender | Copiar classes sem saber o efeito dificulta manutenção |
| Conferir a versão | Exemplos antigos podem usar classes ou comportamentos diferentes |
| Ler a estrutura do componente | Alguns componentes dependem de uma ordem específica de tags |
| Incluir o JavaScript quando necessário | Modal, dropdown e collapse não funcionam só com CSS |
| Verificar licença de templates | Nem todo template pode ser usado livremente em qualquer contexto |
| Evitar customização espalhada | Muitos ajustes soltos podem quebrar a consistência visual |

## Perguntas de revisão

**1. Qual problema o Bootstrap resolve em relação ao CSS escrito do zero?**

<details>
  <summary>Possível resposta</summary>

  Bootstrap entrega uma base pronta para layout, espaçamento, componentes,
  responsividade e estados visuais comuns. Isso acelera a criação de telas e reduz
  decisões repetidas, como aparência de botões, formulários, cards e grids.
</details>

**2. Por que Bootstrap não substitui HTML e CSS?**

<details>
  <summary>Possível resposta</summary>

  Porque Bootstrap é construído sobre HTML, CSS e JavaScript. O HTML continua
  definindo a estrutura e o significado do conteúdo, enquanto o CSS continua
  controlando a apresentação. Bootstrap apenas fornece classes, componentes e
  padrões prontos.
</details>

**3. Quando basta carregar apenas o CSS do Bootstrap?**

<details>
  <summary>Possível resposta</summary>

  Quando a página usa apenas estilos, utilitários, grid e componentes sem
  comportamento interativo, como botões, cards, tabelas e formulários simples.
  Componentes como modal, dropdown e collapse precisam do JavaScript do Bootstrap.
</details>

**4. O que o Reboot aplica automaticamente ao carregar o CSS do Bootstrap?**

<details>
  <summary>Possível resposta</summary>

  Reboot ajusta padrões do navegador para deixar a base visual mais consistente:
  tipografia, margem do `body`, `box-sizing`, links, títulos, listas, tabelas,
  formulários e outros elementos HTML.
</details>

**5. Por que tabelas usam classes como `table` e `table-striped`?**

<details>
  <summary>Possível resposta</summary>

  Porque os estilos visuais de tabela no Bootstrap são opt-in. A classe `table`
  aplica a base visual da tabela, e variações como `table-striped` e `table-hover`
  adicionam comportamentos visuais específicos.
</details>

**6. O que significa `primary` em classes como `btn-primary`?**

<details>
  <summary>Possível resposta</summary>

  `primary` indica a cor ou ação principal da interface. Não deve ser entendido
  apenas como "azul", porque a cor pode mudar em um tema customizado; a intenção
  semântica continua sendo destaque principal.
</details>

**7. Quais componentes precisam do JavaScript do Bootstrap?**

<details>
  <summary>Possível resposta</summary>

  Componentes que abrem, fecham ou reagem à interação do usuário, como modal,
  dropdown, collapse, offcanvas, tooltip e toast, precisam do JavaScript do
  Bootstrap.
</details>

**8. O que significa `col-12 col-md-6`?**

<details>
  <summary>Possível resposta</summary>

  Significa que a coluna ocupa 12 partes da linha em telas pequenas, ou seja,
  largura inteira. A partir do breakpoint `md`, ela passa a ocupar 6 das 12 partes,
  ou seja, metade da linha.
</details>

**9. Qual a diferença entre uma classe utilitária e uma classe de componente?**

<details>
  <summary>Possível resposta</summary>

  Uma classe utilitária aplica uma regra pequena e direta, como margem, padding,
  alinhamento ou display. Uma classe de componente faz parte de um padrão de
  interface maior, como `btn`, `card`, `navbar`, `alert` ou `modal`.
</details>

**10. Como exemplos e templates podem ajudar sem substituir o entendimento do código?**

<details>
  <summary>Possível resposta</summary>

  Eles servem como referência de composição, organização visual e combinação de
  componentes. O ideal é observar padrões, adaptar ao objetivo do projeto e revisar
  versão, licença, acessibilidade e responsividade antes de reaproveitar qualquer
  trecho.
</details>

**11. Por que é importante conferir a versão dos exemplos usados em aula?**

<details>
  <summary>Possível resposta</summary>

  Porque classes, componentes, APIs e comportamentos podem mudar entre versões. Usar
  CSS, JavaScript e documentação da mesma versão reduz inconsistências e facilita a
  reprodução dos exemplos.
</details>
