CSS (*Cascading Style Sheets*) é a linguagem usada para estilizar e organizar visualmente documentos HTML. Enquanto o HTML define a **estrutura e a semântica** do conteúdo, o CSS cuida da **apresentação**: cores, fontes, espaçamentos, bordas e alinhamentos.

---

## Objetivo

Compreender a estrutura de uma regra CSS, diferenciar os métodos de inclusão de estilos em uma página HTML e dominar as regras de **cascata, especificidade e herança** que determinam qual declaração é aplicada pelo navegador quando ocorrem conflitos.

---

## Por Que o CSS Importa?

No início da Web, a aparência era misturada diretamente no HTML com tags obsoletas como `<font>` e `<center>`. O CSS introduziu o princípio da **separação de responsabilidades**:

- **HTML**: Descreve *o que* o conteúdo é (títulos, parágrafos, listas, botões).
- **CSS**: Define *como* o conteúdo deve ser apresentado visualmente.

<Aside type="note" title="Manutenibilidade">
  A separação permite que uma única alteração em um arquivo `.css` externo modifique o visual de centenas de páginas de um portal inteiro sem alterar uma única linha de HTML.
</Aside>

---

No começo da Web, era comum misturar estrutura e aparência no HTML com tags como
`<center>` e `<font>`. Esses elementos hoje são obsoletos: o HTML deve descrever o
conteúdo, enquanto o CSS deve cuidar da apresentação.

```html title="HTML antigo" del={1-3}
<center>
  <font color="blue" size="6">Bem-vindos</font>
</center>
```

```html title="HTML com significado" ins={1}
<h1>Bem-vindos</h1>
```

```css title="CSS para aparência" ins={1-4}
h1 {
  color: blue;
  text-align: center;
}
```

<Aside type="tip" title="Separe responsabilidade">
  Use HTML para dizer o que cada conteúdo é. Use CSS para definir como esse conteúdo
  deve aparecer. Para observar claramente essa separação, você pode desabilitar os
  estilos CSS da página usando extensões como a
  [Web Developer](https://chrome.google.com/webstore/detail/web-developer/bfbameneiokkgbdmiekhjnmfkcnldffj).
</Aside>

Referências: [`<center>` no MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/center)
e [`<font>` no MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/font).

## Anatomia de uma Regra CSS

Uma regra CSS é composta por um **seletor** e um **bloco de declarações** delimitado por chaves `{}`. Cada declaração é um par `propriedade: valor;`.

```css
/* Exemplo de regra CSS */
h1 {
  color: #1d4ed8;
  font-size: 2rem;
  text-align: center;
}
```

A tabela a seguir detalha a função de cada componente da anatomia de uma regra CSS:

| Componente | Função | Exemplo |
| :--- | :--- | :--- |
| **Seletor** | Indica quais elementos HTML receberão o estilo | `h1` |
| **Bloco de Declarações** | Conjunto de instruções entre `{}` | `{ color: ...; }` |
| **Propriedade** | Aspecto visual a ser modificado | `font-size` |
| **Valor** | A configuração atribuída à propriedade | `2rem` |
| **Ponto e vírgula `;`** | Separa declarações (obrigatório entre regras) | `;` |

---

CSS tem poucas peças de sintaxe, mas elas aparecem combinadas em muitos lugares:
propriedades, seletores, valores, funções, variáveis e regras iniciadas com `@`.

## Formas de Inclusão do CSS

CSS pode ser escrito diretamente no elemento, dentro do próprio HTML ou em um arquivo
separado. Os três formatos são úteis para entender a linguagem, mas projetos reais
normalmente usam arquivo externo.

| Forma       | Onde fica                               | Quando faz sentido                                  |
| ----------- | --------------------------------------- | --------------------------------------------------- |
| Inline      | Atributo `style` no elemento             | Testes rápidos ou valores calculados por JavaScript |
| Interno     | Tag `<style>` dentro do `<head>`         | Exemplos pequenos e páginas isoladas                |
| Externo     | Arquivo `.css` carregado por `<link>`    | Projetos reais, reaproveitamento e manutenção       |

### CSS inline

O atributo `style` recebe declarações CSS diretamente no elemento. Uma
**declaração** é um par `propriedade: valor`: em `font-size: 20px`, a propriedade é
`font-size` e o valor é `20px`.

<Mermaid title="Anatomia de uma Declaração Inline em Atributo Style">
{`
flowchart TD
  subgraph Element["Elemento HTML: <p style='font-size: 20px;'>"]
    subgraph Decl["Declaração"]
      P["Propriedade: font-size"] --> V["Valor: 20px"]
    end
  end
`}
</Mermaid>

Como o estilo está no próprio elemento, não há seletor: a declaração vale apenas
para aquele elemento.

| Parte       | Papel no CSS                                                   |
| ----------- | -------------------------------------------------------------- |
| Declaração  | Par `propriedade: valor`                                       |
| Propriedade | Nome do aspecto visual que será alterado                       |
| Valor       | Valor aplicado à propriedade                                   |
| `:`         | Separa propriedade e valor                                     |
| `;`         | Encerra uma declaração; é obrigatório quando há mais de uma     |

O exemplo a seguir mostra declarações aplicadas diretamente nos elementos e o
resultado visual produzido por elas.

  No DevTools, selecione um elemento na aba **Elements** e observe o painel

  CSS inline espalha aparência pelo HTML e dificulta reutilização. Use para testes,

</Aside>

### CSS interno

A tag `<style>` fica no `<head>` e afeta a página atual. Dentro dela, uma regra CSS
junta um **seletor** e um bloco de **declarações**: o seletor escolhe os elementos,
e cada declaração muda uma propriedade visual.

<Mermaid title="Anatomia de uma Regra CSS">
{`
flowchart TD
  subgraph Rule["Regra CSS: p { color: #1d4ed8; }"]
    direction LR
    S["Seletor: p"] --> D["Bloco de Declarações"]
    subgraph D["Bloco de Declarações"]
      P["Propriedade: color"] --> V["Valor: #1d4ed8"]
    end
  end
`}
</Mermaid>

Nesta forma, aparecem peças que não existem no CSS inline:

| Parte        | Papel no CSS                                                    |
| ------------ | --------------------------------------------------------------- |
| Seletor      | Define quais elementos recebem as declarações                   |
| Bloco        | Agrupa declarações entre `{` e `}`                              |

O exemplo a seguir mostra regras CSS dentro da tag `<style>` e como elas afetam os
elementos da mesma página.

<Aside type="note" title="Prós e contras do CSS interno">
  CSS interno é prático para protótipos e páginas pequenas, porque mantém o
  exemplo completo em um único arquivo HTML. Em projetos maiores, ele dificulta o
  reaproveitamento entre páginas, aumenta o tamanho do HTML e pode deixar a
  manutenção mais trabalhosa. Quando o estilo precisa ser compartilhado, prefira CSS
  externo.
</Aside>

</Aside>


## Cascata, Especificidade e Herança

Quando duas ou mais regras CSS competem pela mesma propriedade em um elemento, o navegador resolve o conflito utilizando três critérios principais:

### 1. Especificidade
A especificidade é uma pontuação calculada pelo seletor usado:

```txt
Inline style (1,0,0,0)  >  ID (0,1,0,0)  >  Classe/Atributo/Pseudo-classe (0,0,1,0)  >  Elemento (0,0,0,1)
```

- `style="..."`: Peso mais alto.
- `#header`: 1 ID (sobrepõe qualquer número de classes).
- `.btn.primary`: 2 Classes.
- `h1`: 1 Elemento.

<Aside type="caution" title="Uso de !important">
  A instrução `!important` sobrepõe qualquer regra de especificidade. Evite abusar de `!important`, pois ele quebra o fluxo natural da cascata e dificulta futuras alterações.
</Aside>

### 2. Ordem no Código
Se duas regras possuírem a **mesma especificidade**, a regra definida **mais abaixo** no arquivo CSS prevalecerá.

```css
p { color: blue; }
p { color: red; } /* Vence por ter sido declarada por último */
```

### 3. Herança
Algumas propriedades CSS são herdadas automaticamente pelos elementos filhos (como `color`, `font-family` e `line-height`), enquanto outras (como `margin`, `padding` e `border`) não são herdadas.

---

### Exemplo completo

A palavra "cascading" no nome CSS importa. Várias regras podem atingir o mesmo
elemento, e o navegador precisa decidir qual valor usar para cada propriedade.

De forma prática, observe no código quais trechos disputam a mesma propriedade. Em
herança e valor inicial, o ponto principal é o que acontece quando não existe uma
declaração direta no próprio elemento.

| Fator          | Ideia central                                                             | No exemplo                                                                 |
| -------------- | ------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| Ordem          | Se duas regras equivalentes competem, a última no arquivo vence           | Em `<p class="aviso destaque">`, `.aviso` define `color: #2563eb` e `.destaque` define `color: #b45309`. Como as duas classes têm a mesma especificidade, vence `#b45309`, pois `.destaque` aparece depois no CSS |
| Importância    | Uma declaração com `!important` ganha prioridade sobre declarações normais | Em `<p class="prioridade" style="color: #dc2626;">`, o inline tenta usar `#dc2626`, mas `.prioridade` define `color: #be123c !important`. Vence `#be123c`, porque a declaração importante supera a declaração normal |
| Especificidade | ID vence classe, classe vence elemento                                    | Em `<p id="mensagem" class="aviso">`, `p` define `#334155`, `.aviso` define `#2563eb` e `#mensagem` define `#047857`. Vence `#047857`, porque o seletor de ID é mais específico |
| Inline         | O atributo `style` costuma vencer regras do arquivo CSS                   | Em `<p id="urgente" class="aviso" style="color: #dc2626;">`, `#urgente` define `#7c3aed`, mas o inline define `#dc2626`. Vence `#dc2626`, porque o atributo `style` tem prioridade maior que seletores normais |
| Herança        | Algumas propriedades, como `color` e `font-family`, passam para filhos    | `body` define `font-family: Arial, sans-serif`. Como os `<p>` não definem outra `font-family`, eles herdam esse valor do elemento pai |
| Valor inicial  | Quando nada é definido, o navegador usa o valor inicial da propriedade    | Nenhuma regra define `font-weight` para os parágrafos. Por isso, eles usam o valor inicial `normal` |

<Aside type="tip" title="Use o DevTools para investigar conflitos">
  Quando duas regras definem a mesma propriedade, o painel **Styles** do DevTools
  mostra quais declarações foram aplicadas e quais foram descartadas. Essa é uma
  forma prática de enxergar a cascata, a especificidade, a ordem e o efeito de
  `!important` no elemento selecionado.
</Aside>

<Aside type="caution" title="Evite !important como padrão">
  `!important` existe para casos excepcionais, mas não deve virar padrão. Quando ele
  é usado sem necessidade, o código fica mais difícil de sobrescrever e a cascata
  perde previsibilidade.
</Aside>

<Aside type="tip" title="Prefira classes para estilizar componentes">
  IDs são úteis para fragmentos de URL e JavaScript, mas classes costumam ser mais
  flexíveis para CSS. Evite resolver conflitos aumentando especificidade sem motivo.
</Aside>

<Aside type="note" title="Contêineres genéricos: <div> e <span>">
  `<div>` (bloco) e `<span>` (inline) são contêineres genéricos sem estilo visual
  próprio ou valor semântico específico. Eles são muito usados com classes para
  agrupar elementos. Ao aplicar propriedades herdáveis (como `color` e `font-family`)
  em um `<div>`, todos os elementos e `<span>` filhos herdam esses estilos
  automaticamente, a menos que uma regra mais específica os sobrescreva.
</Aside>

no MDN.

## Resumo e Boas Práticas

- Prefira sempre **CSS Externo** vinculado por `<link rel="stylesheet">`.
- Mantenha seletores simples baseados em **classes** (`.card`, `.btn`) em vez de IDs ou seletores ultralonge encadeados.
- Compreenda a pontuação de especificidade para evitar resolver conflitos com `!important`.

   veja as abas `Styles` e `Computed`.

</Steps>

<Aside type="tip" title="Formatação no VS Code">

## Exercício

Use a página pessoal criada na aula de HTML e acrescente CSS externo:

1. Crie a pasta `css/` e o arquivo `css/style.css`;
2. Carregue o arquivo com `<link rel="stylesheet" href="css/style.css" />`;
3. Defina cores, fonte, largura máxima e espaçamento geral;
4. Transforme o menu em uma lista horizontal;
5. Crie ao menos duas classes reutilizáveis, como `.card` e `.destaque`;
6. Use `:hover` em links ou botões;
7. Crie uma `@media` query para telas maiores ou impressão;
8. Inspecione uma regra no DevTools e identifique propriedade, valor e seletor.

## Desafio

Crie variáveis em `:root` para cor principal, cor de fundo, cor do texto e espaço
padrão. Em seguida, implemente um tema escuro alterando os valores dessas variáveis
dentro de uma media query `@media (prefers-color-scheme: dark)` ou de uma classe `.dark`.


## Perguntas de revisão

**1. Qual é a responsabilidade do CSS em uma página?**

<details>
  <summary>Possível resposta</summary>

  CSS descreve a apresentação visual do documento: cores, fontes, espaçamentos,
  bordas, layout, responsividade e outros aspectos de renderização.
</details>

**2. Qual é a diferença entre CSS inline, interno e externo?**

<details>
  <summary>Possível resposta</summary>

  Inline fica no atributo `style` de um elemento. Interno fica na tag `<style>` da
  página. Externo fica em um arquivo `.css` carregado com `<link>`, que é a opção
  mais comum para projetos.
</details>

**3. O que um seletor faz?**

<details>
  <summary>Possível resposta</summary>

  Um seletor escolhe quais elementos do HTML receberão as declarações de uma regra
  CSS.
</details>

**4. Por que uma regra pode vencer outra?**

<details>
  <summary>Possível resposta</summary>

  Porque a cascata considera fatores como origem, importância, especificidade,
  ordem de leitura e herança. De forma prática, ID costuma vencer classe, classe
  costuma vencer elemento, e regras equivalentes obedecem à última declaração.
</details>
