Compreender as fases de modelagem de dados, dominar os elementos constitutivos do Modelo Entidade-Relacionamento (entidades, atributos, relacionamentos e cardinalidades) e aplicar as regras formais de conversão do DER para o modelo de tabelas relacionais.

## Fases do Projeto de Banco de Dados

Projetar um banco de dados eficiente exige um processo estruturado que previne erros arquiteturais caros no futuro. O projeto divide-se em três etapas sucessivas:

<Mermaid title="Fases do projeto de banco de dados">
{`
flowchart TD
    A[1. Análise de Requisitos] -->|Levantamento do Negócio| B[2. Modelagem Conceitual MER / DER]
    B -->|Mapeamento Relacional| C[3. Modelagem Lógica Tabelas / Chaves]
    C -->|Implementação em SGBD| D[4. Modelagem Física Scripts SQL DDL]
`}
</Mermaid>

1. **Modelagem Conceitual**: Abstração de alto nível, independente de SGBD ou tecnologia. Captura as entidades do mundo real e suas interações (MER/DER).
2. **Modelagem Lógica**: Adaptação do modelo conceitual para o paradigma do SGBD escolhido (ex: Modelo Relacional composto por tabelas, colunas e chaves).
3. **Modelagem Física**: Codificação em linguagem SQL (DDL) especificando os tipos de dados concretos, índices, partições e configurações do servidor.

## Modelo Entidade-Relacionamento (MER)

Introduzido por Peter Chen em 1976, o **Modelo Entidade-Relacionamento (MER)** descreve o mundo real em termos de objetos de interesse e de suas associações.

### 1. Entidades

Uma **Entidade** representa um conjunto de objetos do mundo real sobre os quais a aplicação precisa armazenar informações (ex: `Cliente`, `Produto`, `Pedido`).

- **Entidade Forte**: Existe independentemente de outras entidades (ex: `Cliente`).
- **Entidade Fraca**: Sua existência depende diretamente de outra entidade pai (ex: `Dependente` de um `Funcionario`).

### 2. Atributos

São as propriedades que caracterizam uma entidade:

- **Atributo Simples (Atômico)**: Não pode ser dividido em partes menores (ex: `CPF`, `Preço`).
- **Atributo Composto**: Formado pela junção de múltiplos componentes (ex: `Endereço` composto por `Rua`, `Número`, `CEP`).
- **Atributo Multivalorado**: Pode conter múltiplos valores para um único registro (ex: `Telefones`).
- **Atributo Chave (Identificador)**: Valor único que distingue univocamente cada elemento da entidade (ex: `ID_Cliente` ou `CPF`).

## Relacionamentos e Cardinalidade

Um **Relacionamento** é uma associação entre duas ou mais entidades. A **Cardinalidade** define quantas instâncias de uma entidade podem estar associadas a instâncias de outra entidade.

### Mapeamento das Cardinalidades

As três cardinalidades fundamentais no modelo relacional são:

#### Um para Um (`1:1`)
Cada registro da Entidade A associa-se a no máximo um registro da Entidade B.
- *Exemplo*: `Usuario` e `PerfilConfiguracao`.

#### Um para Muitos (`1:N`)
Um registro da Entidade A pode relacionar-se com vários registros da Entidade B, mas um registro da Entidade B associa-se a apenas um da Entidade A.
- *Exemplo*: `Cliente` realiza vários `Pedidos`, mas um `Pedido` pertence a apenas um `Cliente`.

#### Muitos para Muitos (`N:M`)
Vários registros da Entidade A associam-se a vários registros da Entidade B.
- *Exemplo*: `Aluno` cursa várias `Disciplinas`, e uma `Disciplina` possui vários `Alunos`.

<Aside type="caution" title="Relacionamento N:M no Modelo Relacional">
  Bancos de dados relacionais **não conseguem** implementar relacionamentos `N:M` diretamente entre duas tabelas. É obrigatório criar uma **Tabela Associativa** (ou tabela de junção) contendo as Chaves Estrangeiras de ambas as entidades.
</Aside>

## Regras de Mapeamento DER para Modelo Lógico (Tabelas)

Para converter um modelo DER em tabelas relacionais, siga quatro regras universais:

### Regra 1: Mapeamento de Entidades
Cada entidade virará uma tabela. O atributo chave vira a **Chave Primária (Primary Key - PK)**.

### Regra 2: Mapeamento de Relacionamentos `1:N`
A Chave Primária do lado `1` (pai) é inserida como **Chave Estrangeira (Foreign Key - FK)** na tabela do lado `N` (filho).

### Regra 3: Mapeamento de Relacionamentos `N:M`
Cria-se uma **nova tabela associativa**. A chave primária dessa nova tabela será a junção (*chave composta*) das duas chaves estrangeiras que apontam para as tabelas originais.

### Regra 4: Mapeamento de Relacionamentos `1:1`
A Chave Estrangeira pode ficar em qualquer um dos dois lados, preferencialmente na tabela que possui participação obrigatória.

## Exemplo Completo de Mapeamento

Considere a regra de negócio: *"Um Professor pode ministrar várias Turmas, mas uma Turma tem apenas um Professor (1:N). Uma Turma possui vários Alunos e um Aluno pode estar em várias Turmas (N:M)."*

O mapeamento para o modelo de tabelas relacionais fica assim:

```sql title="modelo-logico.sql"
-- Entidade Professor (Lado 1 do relacionamento 1:N)
CREATE TABLE Professor (
    id INT PRIMARY KEY AUTOINCREMENT,
    nome VARCHAR(100) NOT NULL
);

-- Entidade Turma (Lado N do relacionamento 1:N)
CREATE TABLE Turma (
    id INT PRIMARY KEY AUTOINCREMENT,
    codigo VARCHAR(20) NOT NULL,
    professor_id INT NOT NULL,
    FOREIGN KEY (professor_id) REFERENCES Professor(id)
);

-- Entidade Aluno
CREATE TABLE Aluno (
    id INT PRIMARY KEY AUTOINCREMENT,
    nome VARCHAR(100) NOT NULL
);

-- Tabela Associativa para o relacionamento N:M entre Turma e Aluno
CREATE TABLE Turma_Aluno (
    turma_id INT NOT NULL,
    aluno_id INT NOT NULL,
    data_matricula DATE NOT NULL,
    PRIMARY KEY (turma_id, aluno_id),
    FOREIGN KEY (turma_id) REFERENCES Turma(id) ON DELETE CASCADE,
    FOREIGN KEY (aluno_id) REFERENCES Aluno(id) ON DELETE CASCADE
);
```

## Exercício

Considere uma biblioteca onde um `Leitor` pode pegar emprestado vários `Livros`, e um `Livro` pode ser emprestado a vários `Leitores` ao longo do tempo.

1. Qual é a cardinalidade conceitual entre `Leitor` e `Livro`?
2. Projete o modelo de tabelas em SQL (incluindo a tabela associativa `Emprestimo`) contendo a data do empréstimo e a data de devolução.

<details>
  <summary>Possível resposta</summary>

  1. **Cardinalidade**: `N:M` (Muitos para Muitos).

  2. **Modelo em SQL**:
     ```sql
     CREATE TABLE Leitor (
         id INT PRIMARY KEY AUTOINCREMENT,
         nome VARCHAR(100) NOT NULL
     );

     CREATE TABLE Livro (
         id INT PRIMARY KEY AUTOINCREMENT,
         titulo VARCHAR(200) NOT NULL
     );

     CREATE TABLE Emprestimo (
         leitor_id INT NOT NULL,
         livro_id INT NOT NULL,
         data_emprestimo DATE NOT NULL,
         data_devolucao DATE,
         PRIMARY KEY (leitor_id, livro_id, data_emprestimo),
         FOREIGN KEY (leitor_id) REFERENCES Leitor(id),
         FOREIGN KEY (livro_id) REFERENCES Livro(id)
     );
     ```
</details>

## Perguntas de revisão

1. **Quais são as 3 etapas de um projeto de banco de dados?**
   <details><summary>Possível resposta</summary>Modelagem Conceitual (MER/DER), Modelagem Lógica (Tabelas/Chaves) e Modelagem Física (SQL DDL/SGBD).</details>

2. **O que é uma Entidade Fraca?**
   <details><summary>Possível resposta</summary>É uma entidade cuja existência depende diretamente da presença de uma entidade pai forte.</details>

3. **O que distingue uma Chave Primária (PK) de uma Chave Estrangeira (FK)?**
   <details><summary>Possível resposta</summary>A PK identifica unicamente cada linha de uma própria tabela. A FK é um atributo em uma tabela que faz referência à PK de outra tabela.</details>

4. **Por que não é possível criar um relacionamento N:M direto com apenas 2 tabelas num banco relacional?**
   <details><summary>Possível resposta</summary>Porque causaria repetição de dados e violação de atomicidade das células da tabela. Exige-se uma tabela associativa intermediária.</details>

5. **O que é uma Chave Composta?**
   <details><summary>Possível resposta</summary>É uma chave primária formada pela união de duas ou mais colunas para identificar unicamente uma linha.</details>

6. **Onde deve ser colocada a Chave Estrangeira num relacionamento 1:N?**
   <details><summary>Possível resposta</summary>No lado "N" (muitos) do relacionamento.</details>

7. **Qual é a notação gráfica mais utilizada para modelagem conceitual de dados?**
   <details><summary>Possível resposta</summary>O Diagrama Entidade-Relacionamento (DER).</details>

8. **O que são atributos multivalorados? Give an example.**
   <details><summary>Possível resposta</summary>São atributos que podem ter mais de um valor para a mesma entidade, como o atributo `Telefones` em um cadastro de cliente.</details>
