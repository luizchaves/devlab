O termo **Big Data** define cenários onde o volume, a velocidade e a variedade dos dados excedem a capacidade de armazenamento e processamento de um único servidor convencional. Para resolver esse desafio, surgiram arquiteturas de computação distribuída baseadas em clusters: o **Apache Spark** (padrão global para processamento em memória, pipelines ETL e machine learning) e o **Trino** (motor de consultas SQL interativas e massivamente paralelas).

---

## Objetivo

Compreender os fundamentos da computação distribuída para Big Data, a arquitetura mestre-trabalhadores (*Coordinator-Workers*) e os casos de uso de Apache Spark e Trino. Ao final deste tópico, o leitor será capaz de:

- Descrever os princípios dos 5 Vs do Big Data (Volume, Velocidade, Variedade, Veracidade e Valor).
- Mapear as categorias funcionais do ecossistema de Big Data (processamento, armazenamento, streaming, data warehouse, NoSQL, orquestração e BI).
- Explicar a arquitetura do Apache Spark baseada em DAG (*Directed Acyclic Graph*), RDDs (*Resilient Distributed Datasets*) e DataFrames.
- Compreender o motor de consultas federadas e distribuídas do Trino (antigo PrestoSQL).
- Avaliar quando utilizar o Spark para transformações pesadas em lote versus o Trino para consultas SQL interativas ad-hoc.

## Os 5 Vs do Big Data e a Mudança de Paradigma

O processamento de Big Data rompe com o modelo de bancos tradicionais centralizados onde os dados são movidos até a CPU. Em sistemas distribuídos modernos, o princípio fundamental é **levar a computação até onde os dados residem**:

    BD --> V4["4. Veracidade: Qualidade e consistência dos dados"]

## O Ecossistema de Big Data por Função

O termo Big Data não se refere a uma ferramenta isolada, mas a um ecossistema abrangente de tecnologias especializadas. Para projetar uma arquitetura de dados moderna, engenheiros organizam essas ferramentas de acordo com a função exercida em cada etapa do ciclo de vida dos dados:

| Categoria Funcional | Principais Tecnologias e Ferramentas | Papel e Função no Ecossistema |
| :--- | :--- | :--- |
| **Processamento Distribuído** | [Apache Spark](https://spark.apache.org/), [Apache Hadoop (MapReduce)](https://hadoop.apache.org/), [Apache Flink](https://flink.apache.org/) | Computação massivamente paralela em lote (*batch*) ou em tempo real (*stream*). |
| **Armazenamento Distribuído** | [Hadoop HDFS](https://hadoop.apache.org/docs/current/hadoop-project-dist/hadoop-hdfs/HdfsUserGuide.html), [Amazon S3](https://aws.amazon.com/s3/), [Google Cloud Storage](https://cloud.google.com/storage), [Azure Data Lake Storage (ADLS)](https://azure.microsoft.com/products/storage/data-lake-storage/) | Armazenamento de alta durabilidade e baixo custo para petabytes de dados brutos e refinados. |
| **Data Warehouse Moderno** | [Google BigQuery](https://cloud.google.com/bigquery), [Snowflake](https://www.snowflake.com/), [Amazon Redshift](https://aws.amazon.com/redshift/), [Azure Synapse](https://azure.microsoft.com/products/synapse-analytics/) | Armazenamento colunar corporativo voltado para consultas analíticas SQL de alta velocidade. |
| **Streaming e Mensageria** | [Apache Kafka](https://kafka.apache.org/), [Apache Pulsar](https://pulsar.apache.org/), [Amazon Kinesis](https://aws.amazon.com/kinesis/) | Ingestão contínua, enfileiramento resiliente e transporte de eventos em tempo real com pub/sub. |
| **Processamento de Stream** | [Apache Flink](https://flink.apache.org/), [Spark Structured Streaming](https://spark.apache.org/streaming/), [Kafka Streams](https://kafka.apache.org/documentation/streams/) | Transformação de eventos em tempo real com janelas temporais (*sliding/tumbling windows*). |
| **Bancos NoSQL em Escala** | [Apache Cassandra](https://cassandra.apache.org/), [MongoDB](https://www.mongodb.com/), [Apache HBase](https://hbase.apache.org/), [Amazon DynamoDB](https://aws.amazon.com/dynamodb/) | Persistência operacional com particionamento horizontal e altíssimo *throughput* de I/O. |
| **ETL/ELT e Orquestração** | [Apache Airflow](https://airflow.apache.org/), [dbt (data build tool)](https://www.getdbt.com/), [Apache NiFi](https://nifi.apache.org/), [AWS Glue](https://aws.amazon.com/glue/) | Agendamento, orquestração de fluxos DAG e transformação declarativa de dados. |
| **Motores de Consulta SQL** | [Trino](https://trino.io/), [Presto](https://prestodb.io/), [Apache Hive](https://hive.apache.org/), [Spark SQL](https://spark.apache.org/sql/) | Execução de consultas SQL federadas e interativas sobre múltiplos silos de dados sem movimentação física. |
| **Data Lake e Formatos de Tabela** | [Apache Iceberg](https://iceberg.apache.org/), [Delta Lake](https://delta.io/), [Apache Hudi](https://hudi.apache.org/) | Camada de metadados transacionais (ACID, *time travel* e particionamento dinâmico) sobre Object Storage. |
| **BI e Visualização** | [Power BI](https://powerbi.microsoft.com/), [Tableau](https://www.tableau.com/), [Looker](https://cloud.google.com/looker), [Apache Superset](https://superset.apache.org/) | Dashboards executivos, exploração analítica de indicadores e relatórios visuais. |
| **Cloud Big Data Gerenciado** | [AWS EMR](https://aws.amazon.com/emr/), [Databricks](https://www.databricks.com/), [Google Cloud Dataproc](https://cloud.google.com/dataproc), [Azure HDInsight](https://azure.microsoft.com/products/hdinsight/) | Plataformas que automatizam provisionamento, autoescala e gerenciamento de clusters Spark/Hadoop. |

## Apache Spark: Processamento em Memória Unificado

O **Apache Spark** substituiu o modelo clássico do MapReduce/Hadoop processando dados diretamente na memória RAM dos nós do cluster, atingindo velocidades até 100 vezes superiores:

<Mermaid title="Arquitetura de Cluster do Apache Spark (Driver e Executors)">
{`
flowchart TD
    Driver["Driver Program (SparkSession)"] -->|"Cria Plano de Execução (DAG)"| CM["Cluster Manager (YARN / K8s / Standalone)"]
    
    CM --> Worker1["Worker Node 1"]
    CM --> Worker2["Worker Node 2"]
    
    subgraph W1 ["Executors Node 1"]
        Worker1 --> E1["Executor 1 (Tasks em RAM)"]
        Worker1 --> E2["Executor 2 (Tasks em RAM)"]
    end

    subgraph W2 ["Executors Node 2"]
        Worker2 --> E3["Executor 3 (Tasks em RAM)"]
        Worker2 --> E4["Executor 4 (Tasks em RAM)"]
    end
`}
</Mermaid>

Os componentes centrais do Spark incluem:

1. **Spark SQL e DataFrames**: Abstração tabular com otimizador de consultas avançado (*Catalyst Optimizer*) que gera planos de execução altamente eficientes.
2. **Avaliação Preguiçosa (*Lazy Evaluation*)**: Transformações (`map`, `filter`, `groupBy`) não são executadas imediatamente; o Spark constrói um grafo acíclico dirigido (*DAG*) e só processa os dados quando uma ação (`count`, `collect`, `write`) é solicitada.
3. **Structured Streaming**: Processamento unificado de fluxos contínuos de eventos e dados em lote sob a mesma API.
4. **MLlib**: Biblioteca integrada de algoritmos de aprendizado de máquina distribuídos.

## Trino (PrestoSQL): Motor de Consultas SQL Massivamente Paralelo (MPP)

Enquanto o Spark é uma plataforma de processamento e transformação de dados, o **Trino** é um motor puramente analítico de consultas SQL rápidas:

- **Arquitetura MPP (*Massively Parallel Processing*)**: Um nó coordenador (*Coordinator*) recebe a query SQL, divide o plano em múltiplos fragmentos e os distribui entre dezenas ou centenas de nós trabalhadores (*Workers*).
- **Consultas Federadas (*Query Federation*)**: O Trino conecta-se simultaneamente a diferentes bancos através de conectores: você pode executar uma única query SQL que realiza um `JOIN` entre uma tabela no PostgreSQL, um balde no Amazon S3 e uma coleção no MongoDB.
- **Zero Armazenamento Próprio**: O Trino não armazena dados em disco: ele apenas processa os dados em memória enquanto lê das fontes conectadas.

## Comparativo: Apache Spark vs. Trino

A tabela abaixo sintetiza os papéis complementares das duas tecnologias:

| Característica | Apache Spark | Trino (Presto) |
| :--- | :--- | :--- |
| **Foco Principal** | Transformação em lote (ETL), streaming e machine learning | Consultas SQL interativas ad-hoc e dashboards de BI |
| **Execução de Queries** | Baseada em estágios (*Stages*) com tolerância a falhas intermediária | Pipeline contínuo em memória (*Streaming Execution*) |
| **Linguagens Suportadas** | Python (PySpark), Scala, Java, R, SQL | SQL ANSI padronizado |
| **Tolerância a Falhas** | Recomputa partições perdidas via DAG em caso de falha de nó | Queries falham se um nó cair (otimizado para velocidade) |
| **Latência Típica** | Segundos a minutos (foco em vazão massiva) | Milissegundos a poucos segundos (foco em interatividade) |

1. O que é a avaliação preguiçosa (*Lazy Evaluation*) no Apache Spark e qual a sua principal vantagem?
2. Por que o Trino é chamado de motor de consultas federadas?

<details>
  <summary>Possível resposta</summary>

  1. É o modelo onde o Spark apenas registra o plano de transformações sem executá-lo de imediato, acumulando as etapas para que o otimizador *Catalyst* possa reordenar filtros e projeções da forma mais eficiente antes da execução física.

  2. Porque ele permite consultar e combinar dados de múltiplas fontes heterogêneas (S3, PostgreSQL, Kafka, Hive, MySQL) em uma única consulta SQL, sem a necessidade de migrar todos os dados para um repositório central prévio.

## Desafio

Uma empresa de logística possui 500 milhões de eventos de telemetria de frotas por dia gravados em arquivos Parquet no S3 e um banco relacional MySQL com os dados cadastrais dos motoristas. Explique como utilizar o Spark e o Trino em conjunto para atender engenharia de dados e análise de negócios.

<details>
  <summary>Possível resposta</summary>

  O Apache Spark executa os pipelines noturnos de engenharia de dados (ETL), lendo os dados brutos de telemetria, limpando inconsistências, calculando agregações pesadas e gerando tabelas refinadas em Parquet/Iceberg. O Trino é disponibilizado para a equipe de analistas de negócios e dashboards de BI (Power BI/Tableau) para executar consultas SQL interativas em tempo real cruzando as tabelas analíticas no S3 diretamente com o cadastro no MySQL via federação de dados.
</details>

## Perguntas de revisão

1. **O que é o Driver Program no Apache Spark?**
   <details><summary>Possível resposta</summary>É o processo central que executa a função principal da aplicação, cria o `SparkSession`, divide o código em tarefas e orquestra a distribuição dessas tarefas entre os executores no cluster.</details>

2. **Por que o Trino atinge tempos de resposta mais rápidos que o Spark para consultas de BI?**
   <details><summary>Possível resposta</summary>Porque o Trino mantém os nós do cluster sempre ativos e executa o processamento em pipeline contínuo de memória sem gravar checkpoints intermediários em disco.</details>

3. **Qual a função do Catalyst Optimizer no Spark SQL?**
   <details><summary>Possível resposta</summary>É o otimizador extensível que converte consultas relacionais em árvores de expressões, aplicando otimizações lógicas (como empurrar predicados `WHERE` para a fonte) e gerando código Java em tempo de execução para acelerar o processamento.</details>
