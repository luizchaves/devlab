A operação de bancos chave-valor serverless difere da infraestrutura tradicional: você não gerencia instâncias ou clusters com IPs fixos, mas cria tabelas sob demanda com provisionamento elástico. Neste tópico, você aprenderá a provisionar tabelas no **Amazon DynamoDB**, executar o **DynamoDB Local** via Docker e integrar o **Upstash Redis** em aplicações *Serverless* e *Edge* via API HTTP.

---

## Objetivo

Aprender a criar e configurar tabelas no DynamoDB e bancos Upstash Redis, utilizando ferramentas de linha de comando, emuladores locais e SDKs sem estado (*Stateless*). Ao final do tópico, o leitor deve ser capaz de:

- Criar tabelas no Amazon DynamoDB definindo chaves primárias (*Partition Key* e *Sort Key*) e modo de capacidade sob demanda (*PAY_PER_REQUEST*).
- Executar o DynamoDB Local com Docker para desenvolvimento e testes integrados offline.
- Conectar uma aplicação Node.js utilizando o cliente oficial `@aws-sdk/client-dynamodb` e `@aws-sdk/lib-dynamodb`.
- Provisionar um banco Upstash Redis e obter credenciais de acesso via REST HTTP.
- Executar operações de leitura e gravação no Upstash com o pacote `@upstash/redis` em funções de borda (*Edge Functions*).

---

## Passo a Passo: Provisionamento do DynamoDB

<Steps>
1. **Criar tabela sob demanda via AWS CLI:**

   Crie a tabela `invest-portfolio` definindo a chave primária composta `PK` (String) e `SK` (String):

   ```bash
   aws dynamodb create-table \
     --table-name "invest-portfolio" \
     --attribute-definitions \
         AttributeName=PK,AttributeType=S \
         AttributeName=SK,AttributeType=S \
     --key-schema \
         AttributeName=PK,KeyType=HASH \
         AttributeName=SK,KeyType=RANGE \
     --billing-mode PAY_PER_REQUEST
   ```

2. **Executar o DynamoDB Local via Docker para testes:**

   Para desenvolver sem gastar cotas na nuvem:

   ```bash
   docker run -d -p 8000:8000 --name dynamodb-local amazon/dynamodb-local
   ```

3. **Conectar e gravar via AWS SDK v3 em Node.js:**

   Utilize o `DynamoDBDocumentClient` para serializar objetos JavaScript nativos:

   ```typescript
   import { DynamoDBClient } from '@aws-sdk/client-dynamodb';
   import { DynamoDBDocumentClient, PutCommand, GetCommand } from '@aws-sdk/lib-dynamodb';

   const client = new DynamoDBClient({
     region: 'us-east-1',
     // endpoint: 'http://localhost:8000' // Descomente para testes locais
   });

   const docClient = DynamoDBDocumentClient.from(client);

   // Inserir item
   await docClient.send(new PutCommand({
     TableName: 'invest-portfolio',
     Item: {
       PK: 'USER#ana_silva',
       SK: 'ASSET#PETR4',
       quantidade: 200,
       precoMedio: 37.80,
       atualizadoEm: new Date().toISOString(),
     }
   }));
   ```
</Steps>

## Passo a Passo: Upstash Redis via HTTP

<Steps>
1. **Obter credenciais no Upstash Console:**

   Crie um banco no painel do Upstash e copie as variáveis `UPSTASH_REDIS_REST_URL` e `UPSTASH_REDIS_REST_TOKEN`.

2. **Instalar o cliente leve em seu projeto:**

   ```bash
   pnpm add @upstash/redis
   ```

3. **Executar comandos no backend ou Edge Worker:**

   ```typescript
   import { Redis } from '@upstash/redis';

   const redis = new Redis({
     url: process.env.UPSTASH_REDIS_REST_URL!,
     token: process.env.UPSTASH_REDIS_REST_TOKEN!,
   });

   // Gravar valor com expiração de 60 segundos
   await redis.set('sessao:user_123', { role: 'admin', ip: '192.168.1.1' }, { ex: 60 });

   // Incrementar contador atômico de acessos
   const totalAcessos = await redis.incr('metricas:visitas_hoje');
   ```
</Steps>

## Desafio

Crie um endpoint de API em TypeScript (`GET /usuarios/:id/saldo`) que:
- Consulte primeiro o cache no **Upstash Redis** (`GET cache:user:<id>`).
- Se houver *Cache Hit*, retorne o saldo imediatamente com latência inferior a 10ms.
- Se houver *Cache Miss*, busque o item no **DynamoDB**, grave o resultado no Upstash com TTL de 5 minutos (`SET ... EX 300`) e responda a requisição.

## Perguntas de revisão

<details>
<summary>1. O que é o DynamoDB Document Client (lib-dynamodb) e por que ele é indispensável?</summary>
O cliente base do DynamoDB exige tipagem explícita em formato JSON com delimitadores de tipo (ex: `{"nome": {"S": "Ana"}, "idade": {"N": "28"}}`). O `DynamoDBDocumentClient` abstrai essa complexidade, permitindo enviar e receber objetos JavaScript puros de forma transparente.
</details>

<details>
<summary>2. Como o NoSQL Workbench auxilia no design de tabelas do DynamoDB?</summary>
O *NoSQL Workbench for DynamoDB* é uma ferramenta visual oficial da AWS para modelagem de dados, simulação de padrões de acesso (*Data Modeling*), visualização de índices secundários e geração automática de código para SDKs.
</details>
