Este tópico coloca o SQLite para rodar de três formas: pelo binário `sqlite3` no terminal, pelo módulo `node:sqlite` dentro de um programa Node.js e por uma imagem Docker mínima, para quem quer isolar a ferramenta. As três abrem o mesmo arquivo, e a sessão de terminal desta página foi executada contra o banco do projeto `invest-db`.

## Objetivo

Instalar e operar o SQLite nas três formas que um projeto web usa, e dominar o cliente de terminal o suficiente para inspecionar qualquer banco sem escrever código. Ao final do tópico, o leitor deve ser capaz de:

- Instalar o binário `sqlite3` ou usá-lo pela imagem Docker do projeto.
- Abrir um banco pelo `node:sqlite` sem instalar dependência.
- Criar um banco em arquivo a partir dos `.sql` do projeto.
- Inspecionar tabelas e esquemas com os comandos de ponto do cliente.
- Trocar o modo de saída e importar ou exportar dados no terminal.

## Três Formas de Instalar

O SQLite já está presente na maioria dos sistemas, e o Node.js 22 o traz embutido. A tabela abaixo mostra quando cada forma é a mais conveniente:

| Forma | Como obter | Quando usar |
| --- | --- | --- |
| **Binário `sqlite3`** | `brew install sqlite` no macOS, `apt install sqlite3` no Debian e Ubuntu, instalador no Windows | Inspecionar e consultar bancos no terminal |
| **`node:sqlite`** | Já vem no Node.js 22 | Dentro da aplicação e dos scripts, sem `npm install` |
| **Imagem Docker** | `docker compose run sqlite` na pasta do projeto | Ambiente isolado, sem instalar nada na máquina |

Confirme a versão instalada antes de seguir, porque `STRICT` (3.37) e `RIGHT JOIN` (3.39) dependem dela:

```bash title="Terminal"
sqlite3 --version
```

```txt title="Output" frame="terminal"
3.51.0 2025-06-12 13:14:41 f0ca7bba1c5e232e5d279fad6338121ab55af0c8c68c84cdfb18ba5114dcaapl (64-bit)
```

## Criando o Banco a Partir dos Arquivos

O cliente lê SQL da entrada padrão, então os arquivos do projeto `invest-db` criam um banco em arquivo com dois comandos. O primeiro cria as tabelas, o segundo as preenche:

```bash title="Terminal"
sqlite3 invest.db < schema.sql
sqlite3 invest.db < seed.sql
```

O arquivo `invest.db` passa a existir com as três tabelas do blog. Os comandos de ponto do cliente inspecionam o resultado sem SQL:

```bash title="Terminal"
sqlite3 invest.db ".tables"
```

```txt title="Output" frame="terminal"
Post     Product  User
```

```bash title="Terminal"
sqlite3 invest.db ".schema Post"
```

```txt title="Output" frame="terminal"
CREATE TABLE Post (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  title     TEXT    NOT NULL,
  content   TEXT,
  category  TEXT,
  views     INTEGER DEFAULT 0,
  published BOOLEAN DEFAULT 0,
  authorId  INTEGER NOT NULL,
  FOREIGN KEY (authorId) REFERENCES User(id) ON DELETE CASCADE
);
```

Os comandos de ponto mais usados no dia a dia são poucos:

| Comando | O que faz |
| --- | --- |
| `.tables` | Lista as tabelas e visões do banco. |
| `.schema [tabela]` | Mostra o `CREATE` de tudo, ou só da tabela informada. |
| `.mode box` | Saída em tabela desenhada; `.mode csv` e `.mode json` também existem. |
| `.headers on` | Inclui o nome das colunas na saída. |
| `.read arquivo.sql` | Executa um arquivo SQL na sessão atual. |
| `.dump` | Exporta o banco inteiro como SQL. |
| `.quit` | Encerra a sessão. |

Para quem prefere uma interface, o arquivo `.db` abre em qualquer um dos clientes abaixo, e vale saber que o arquivo não pode ser aberto para escrita por dois deles ao mesmo tempo:

| Cliente | Tipo | Como obter | Quando preferir |
| --- | --- | --- | --- |
| [DB Browser for SQLite](https://sqlitebrowser.org/) | Aplicação de área de trabalho | Instalador; ou a imagem [`linuxserver/sqlitebrowser`](https://hub.docker.com/r/linuxserver/sqlitebrowser) no navegador | Editar dados e esquema com formulários, importar CSV |
| [DBeaver](https://dbeaver.io/) | Aplicação de área de trabalho, multiplataforma | Instalador | Mesma ferramenta para SQLite e para os servidores |
| [SQLite Viewer](https://marketplace.visualstudio.com/items?itemName=qwtel.sqlite-viewer) | Extensão do VS Code | Instalar a extensão | Abrir o `.db` do projeto com um clique, só leitura |
| [SQLite](https://marketplace.visualstudio.com/items?itemName=alexcvzz.vscode-sqlite) | Extensão do VS Code | Instalar a extensão | Executar consultas no editor e ver o resultado em aba |
| [Adminer](https://www.adminer.org/) | Web | Imagem `adminer`, com o arquivo montado no contêiner | Inspeção rápida quando o Adminer já está no ar para outro motor |

## A Saída em Modo Tabela

Por padrão o cliente separa colunas com `|`, o que é ótimo para scripts e ruim para ler. O modo `box` desenha a tabela, e pode ser passado como opção na linha de comando:

```bash title="Terminal"
sqlite3 -box invest.db "SELECT id, name FROM User;"
```

```txt title="Output" frame="terminal"
┌────┬─────────────┐
│ id │    name     │
├────┼─────────────┤
│ 1  │ Ana Silva   │
│ 2  │ Bruno Costa │
│ 3  │ Carla Souza │
│ 4  │ Diego Lima  │
└────┴─────────────┘
```

Para uma sessão interativa, abra o banco sem consulta e digite os comandos no prompt `sqlite>`. O `.mode box` e o `.headers on` valem até o fim da sessão.

## Pelo Node.js, Sem Instalar Nada

O `node:sqlite` é o caminho que os projetos deste portal usam, e é o que o `run.mjs` do `invest-db` faz. A classe `DatabaseSync` abre um arquivo ou um banco em memória, e `exec` executa SQL sem retorno:

<SourceCode path="examples/courses/database/invest-db/run.mjs" region="run-file" mark={[23, 30, 31]} />

A linha 23 abre um banco em memória, que existe só enquanto o processo vive; trocar `':memory:'` por `'invest.db'` grava em arquivo. As linhas 30 e 31 carregam o esquema e os dados a partir dos mesmos arquivos que o cliente de terminal lê, o que garante que as duas formas de acesso vejam o mesmo banco.

<Aside type="caution" title="Dica de IA: Confira se a sugestão é `node:sqlite` ou uma dependência">
  Ao pedir "use SQLite no Node", assistentes ainda sugerem `sqlite3` ou `better-sqlite3` do npm, que exigem compilação nativa e às vezes falham na instalação. No Node.js 22 o módulo `node:sqlite` já vem embutido, e é o que o Guia de Express.js usa na trilha de persistência.

  **Prompt:** *"Reescreva este acesso ao SQLite com o módulo embutido `node:sqlite` (`DatabaseSync`, `prepare`, `all`, `run`), sem dependência do npm, e aponte o que muda em relação ao `better-sqlite3`."*
</Aside>

## Executando

Os passos abaixo criam o banco em arquivo e o inspecionam das três formas:

<Steps>
1. Na pasta `examples/courses/database/invest-db/`, crie e preencha o banco:

   ```bash title="Terminal"
   sqlite3 invest.db < schema.sql && sqlite3 invest.db < seed.sql
   ```
2. Abra uma sessão interativa, ligue o modo tabela e consulte:

   ```bash title="Terminal"
   sqlite3 invest.db
   ```

   ```txt title="Terminal" frame="terminal"
   sqlite> .mode box
   sqlite> SELECT COUNT(*) AS posts FROM Post;
   ┌───────┐
   │ posts │
   ├───────┤
   │ 6     │
   └───────┘
   sqlite> .quit
   ```
3. Pelo Node.js, sem instalar nada, leia o mesmo arquivo:

   ```bash title="Terminal"
   node -e "const { DatabaseSync } = require('node:sqlite'); console.log(new DatabaseSync('invest.db').prepare('SELECT COUNT(*) AS posts FROM Post').get())"
   ```

   ```txt title="Output" frame="terminal"
   [Object: null prototype] { posts: 6 }
   ```
4. Pela imagem Docker, com a pasta `data/` montada, o mesmo binário roda isolado:

   ```bash title="Terminal"
   docker compose run --rm sqlite sqlite3 invest.db ".tables"
   ```
</Steps>

## Exercício

Responda com base nos comandos desta página:

1. Qual comando mostra a instrução `CREATE TABLE` de uma tabela existente, e por que ele é útil ao herdar um banco?
2. Qual é a diferença entre abrir `':memory:'` e abrir `'invest.db'` no `node:sqlite`?
3. Por que o `.mode csv` interessa mesmo para quem só usa o cliente de terminal para consultar?

<details>
  <summary>Possível resposta</summary>

  1. O `.schema tabela`. Ele recupera o esquema exato do arquivo, o que dispensa procurar o SQL original e revela restrições que a documentação do projeto talvez não mencione.

  2. O banco em memória existe só durante o processo e desaparece ao fim; o arquivo persiste entre execuções e pode ser aberto por outros programas, inclusive o cliente de terminal.

  3. Porque combinado com redirecionamento (`sqlite3 -csv banco.db "SELECT …" > dados.csv`) ele transforma qualquer consulta em um arquivo que planilhas e outras ferramentas abrem.
</details>

## Desafio

O `run.mjs` do projeto imprime cada resultado em uma tabela de texto que ele mesmo desenha. Reescreva o script para delegar a formatação ao cliente de terminal: em vez de executar as instruções pelo `node:sqlite`, ele gera o SQL e invoca `sqlite3 -box` por `child_process`, com o esquema e os dados carregados antes.

Compare as duas abordagens: o que se ganha e o que se perde ao depender do binário instalado em vez do módulo embutido? E o que acontece com os arquivos marcados como `-- standalone`?

<details>
  <summary>Possível resposta</summary>

  A versão com `child_process` ganha a formatação do cliente (`box`, `csv`, `json` de graça) e perde a portabilidade: passa a exigir o binário instalado e na versão certa, o que quebra em máquinas sem ele e em CI. Também perde o controle fino por instrução, porque o cliente executa o arquivo inteiro e para no primeiro erro, a menos que se use `.bail off`; o `run.mjs` original imprime o erro e continua, o que a documentação precisa.

  Os arquivos `-- standalone` exigem que o script decida, por arquivo, se prefixa ou não o esquema, exatamente como faz hoje; a diferença é que o prefixo vira um `.read schema.sql` enviado ao cliente antes do arquivo. A conclusão prática é a que o projeto adotou: o módulo embutido é a base, e o cliente de terminal é a ferramenta de inspeção.
</details>

## Perguntas de revisão

### Instalação

1. **Por que um projeto Node.js 22 não precisa instalar nada para usar SQLite?**
   <details><summary>Possível resposta</summary>Porque o módulo `node:sqlite` vem embutido no runtime, com a biblioteca SQLite compilada dentro dele.</details>

2. **O que a imagem Docker do projeto acrescenta ao binário?**
   <details><summary>Possível resposta</summary>Isolamento: o binário roda no contêiner, com a pasta `data/` montada para que os bancos apareçam na máquina, sem instalar o SQLite localmente.</details>

3. **Por que a versão do SQLite importa?**
   <details><summary>Possível resposta</summary>Porque recursos como tabelas `STRICT` (3.37) e `RIGHT JOIN` (3.39) não existem em versões antigas, ainda comuns em sistemas instalados.</details>

### Cliente

4. **Como criar um banco em arquivo a partir de um `.sql`?**
   <details><summary>Possível resposta</summary>Redirecionando o arquivo para o cliente: `sqlite3 banco.db < arquivo.sql`. O arquivo do banco é criado se não existir.</details>

5. **O que `.tables` e `.schema` mostram?**
   <details><summary>Possível resposta</summary>`.tables` lista tabelas e visões; `.schema` mostra as instruções `CREATE` que as definem, de todas ou de uma tabela específica.</details>

6. **Como obter a saída de uma consulta em formato de tabela desenhada?**
   <details><summary>Possível resposta</summary>Com `.mode box` na sessão, ou com a opção `-box` na linha de comando.</details>
