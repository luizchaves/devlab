Quando o volume de dados ultrapassa a capacidade de processamento de um único servidor ou máquina de análise local e atinge a escala de centenas de terabytes ou petabytes (*Big Data*), as organizações migram para serviços de **Data Lakehouse Gerenciado em Nuvem**. Plataformas como **Databricks**, **Amazon Athena**, **Google BigQuery Studio** e **Microsoft Fabric** fornecem computação distribuída elástica, catálogos universais de governança e formatos abertos sem a sobrecarga de gerenciar infraestrutura de clusters.

---

## Objetivo

Compreender a arquitetura, o modelo operacional e os diferenciais técnicos das principais plataformas de Data Lakehouse em nuvem gerenciada. Ao final deste tópico, o leitor será capaz de:

- Explicar como plataformas serverless (Amazon Athena) e de computação elástica distribuída (Databricks) consultam diretamente o Object Storage.
- Comparar o papel de catálogos centrais de metadados como AWS Glue e Unity Catalog na governança de dados.
- Avaliar a arquitetura *Medallion* (camadas Bronze, Prata e Ouro) para saneamento e enriquecimento progressivo de dados.
- Escolher a solução de Lakehouse em nuvem adequada a partir de requisitos de custo, latência e ecossistema de fornecedor.

## Arquitetura Medallion: Bronze, Prata e Ouro

A arquitetura padrão da indústria para estruturar dados dentro de um Lakehouse corporativo organiza o fluxo em três camadas de qualidade progressiva:

<Mermaid title="Fluxo de refinamento de dados na Arquitetura Medallion">
{`
flowchart TD
    subgraph Ingestion ["Ingestão de Fontes"]
        direction TB
        F1["APIs REST"] ~~~ F2["Bancos OLTP (CDC)"] ~~~ F3["Logs / IoT"]
    end

    subgraph Bronze ["1. Camada Bronze (Raw)"]
        direction TB
        B1["Dados Brutos / Imutáveis<br/>JSON, CSV, Parquet"]
    end

    subgraph Silver ["2. Camada Prata (Cleansed)"]
        direction TB
        S1["Dados Filtrados e Padronizados<br/>Delta Lake / Apache Iceberg"]
    end

    subgraph Gold ["3. Camada Ouro (Curated)"]
        direction TB
        G1["Agregações de Negócio / BI<br/>Tabelas Fato e Dimensão"]
    end

    Ingestion --> Bronze --> Silver --> Gold
`}
</Mermaid>

Cada camada desempenha um papel bem delimitado:

### 1. Camada Bronze (Dados Brutos)
Armazena os dados brutos exatamente como foram extraídos das fontes originais, preservando o histórico de eventos no estado original sem transformações destrutivas.

### 2. Camada Prata (Dados Higienizados)
Aplica validações de esquema, remoção de duplicidades, tipagem estrita de colunas e enriquecimento básico. Os dados passam a ser gravados em formatos de tabela aberta (Delta Lake ou Iceberg) com suporte a ACID.

### 3. Camada Ouro (Dados de Negócio)
Consolida tabelas prontas para consumo por ferramentas de *Business Intelligence* (Power BI, Tableau, Looker) e modelos de inteligência artificial, contendo métricas sumarizadas, tabelas dimensão e KPIs de desempenho.

## Comparativo de Plataformas de Lakehouse em Nuvem

Os principais provedores de nuvem oferecem abordagens complementares para processamento de Lakehouse:

| Dimensão | Amazon Athena (AWS) | Databricks Lakehouse | Google BigQuery Studio / Dataplex | Microsoft Fabric (OneLake) |
| :--- | :--- | :--- | :--- | :--- |
| **Motor Central** | Trino / Presto (*Serverless*) | Apache Spark otimizado (Photon Engine) | BigQuery Engine distribuído (Dremel) | Apache Spark / T-SQL Polaris |
| **Formato Padrão** | Apache Iceberg, Parquet, ORC | Delta Lake (compatível com Iceberg via UniForm) | Apache Iceberg / BigQuery Managed | Delta Lake (OneLake) |
| **Catálogo de Metadados** | AWS Glue Data Catalog | Unity Catalog | Google Cloud Dataplex Catalog | Microsoft Purview / Fabric |
| **Modelo de Cobrança** | Por terabyte escaneado (US$ 5/TB) ou capacidade | Unidades de computação DBU + infraestrutura VM | Por terabyte escaneado ou slots de computação | Unidades de capacidade Fabric (F-SKU) |
| **Melhor Caso de Uso** | Consultas ad-hoc rápidas e pipelines serverless sem cluster. | Processamento massivo de ETL, machine learning e governança unificada. | Análise integrada em escala de petabytes no ecossistema Google. | Ambientes corporativos integrados ao ecossistema Microsoft e Office. |

## Catálogos Universais e Governança

O grande divisor de águas entre um Data Lake comum e um Lakehouse gerenciado é o **Catálogo de Metadados**:

- **AWS Glue Data Catalog**: Mapeia esquemas, partições e estatísticas de arquivos no S3, permitindo que Athena, Redshift Spectrum e EMR compartilhem as mesmas definições de tabela.
- **Databricks Unity Catalog**: Fornece governança de dados unificada com controle de acesso granular em nível de linha e coluna (*Row/Column-level Security*), mascaramento de dados sensíveis (LGPD) e linhagem ponta a ponta (*Data Lineage*).

## Desafio

Desenhe a arquitetura de um pipeline corporativo que ingere transações bancárias de bancos relacionais via *Change Data Capture (CDC)*, grava no Amazon S3 na camada Bronze, refina em tabelas Apache Iceberg via Athena e disponibiliza visões analíticas na camada Ouro.

<details>
  <summary>Possível resposta</summary>

  O banco OLTP emite eventos de alteração via ferramenta CDC (como Debezium ou AWS DMS) gravando arquivos Parquet contínuos em um bucket S3 (`s3://banco-lakehouse/bronze/`). Um processo agendado no Athena executa queries de consolidação gravando os dados limpos em tabelas Apache Iceberg registradas no AWS Glue (`s3://banco-lakehouse/silver/transactions/`). Por fim, visões agregadas diárias e mensais são geradas na camada Ouro (`s3://banco-lakehouse/gold/kpis/`), consumidas diretamente por dashboards executivos via SQL.
</details>

## Perguntas de revisão

1. **O que significa o formato Delta Lake UniForm no Databricks?**
   <details><summary>Possível resposta</summary>É o recurso de compatibilidade universal (*Universal Format*) que gera metadados para Apache Iceberg e Apache Hudi automaticamente a partir de uma tabela Delta Lake, permitindo que motores externos leiam a tabela sem duplicação de dados.</details>

2. **Como o Amazon Athena cobra pelas consultas executadas?**
   <details><summary>Possível resposta</summary>Por padrão, cobra por quantidade de terabytes de dados lidos do S3 (aproximadamente US$ 5,00 por TB escaneado). O uso de formatos colunares (Parquet) e compressão reduz drasticamente o volume lido e o custo.</details>

3. **O que é linhagem de dados (Data Lineage)?**
   <details><summary>Possível resposta</summary>É o rastreamento automático do ciclo de vida do dado, mostrando de quais tabelas e fontes originais uma métrica ou relatório final foi derivado e quais transformações sofreu no caminho.</details>
