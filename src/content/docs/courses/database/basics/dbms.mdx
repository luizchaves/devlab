## Instalação e Operação com Docker

A forma mais prática e limpa de rodar motores de banco de dados em ambiente de desenvolvimento é utilizar contêineres Docker.

### MySQL Server

O MySQL é um dos bancos de dados relacionais mais populares do mundo, utilizando a porta padrão **3306**.

#### Execução rápida via Docker CLI

O comando a seguir inicia um contêiner MySQL de forma desanexada (`-d`), definindo a senha do usuário root:

```bash title="Terminal"
docker run -d \
  --name mysql \
  -e MYSQL_ROOT_PASSWORD=secret \
  -p 3306:3306 \
  mysql:8.3
```

Para conectar interativamente no terminal interativo do MySQL dentro do contêiner:

```bash title="Terminal"
docker exec -it mysql mysql -u root -p
```

```txt title="Output"
Enter password: 
Welcome to the MySQL monitor.  Commands end with ; or \g.
Your MySQL connection id is 8
Server version: 8.3.0 MySQL Community Server - GPL

mysql> SHOW DATABASES;
mysql> quit
Bye
```

#### Persistência com Volume

Para garantir que os dados não sejam perdidos ao remover o contêiner, associe um volume do Docker:

```bash title="Terminal"
docker volume create mysql-data

docker run -d \
  --name mysql \
  -e MYSQL_ROOT_PASSWORD=secret \
  -v mysql-data:/var/lib/mysql \
  mysql:8.3
```

#### Orquestração com Docker Compose

Em projetos reais, é comum rodar o banco junto com uma ferramenta gráfica de administração (como o Adminer). Veja o arquivo de orquestração a seguir:

<SourceCode path="examples/database/servers/mysql-server/docker-compose.yml" />

Crie o arquivo de variáveis de ambiente `.env` a partir do modelo abaixo:

```ini title=".env.example"

MYSQL_DATABASE=example
MYSQL_USER=devuser
MYSQL_PASSWORD=secret
```

Suba o ambiente completo e verifique os serviços ativos com os seguintes comandos:

```bash title="Terminal"

docker compose ps
```

### PostgreSQL Server

O PostgreSQL é um SGBD relacional objeto-relacional avançado, de código aberto, focado em conformidade com padrões e extensibilidade. Utiliza a porta padrão **5432**.

#### Execução via Docker CLI

Suba uma instância do PostgreSQL 16 configurando um volume para dados:

```bash title="Terminal"
docker run -d \
  --name postgres \
  -e POSTGRES_PASSWORD=secret \
  -v pgdata:/var/lib/postgresql/data \
  -p 5432:5432 \
  postgres:16.2
```

Para conectar no terminal interativo `psql`:

```bash title="Terminal"
docker exec -it postgres psql -U postgres
```

#### Comandos Úteis do `psql`

A tabela abaixo resume os principais comandos utilitários (*dot-commands*) do terminal interativo `psql`:

| Comando | Descrição Didática |
| :--- | :--- |
| `\h` ou `help` | Exibe a ajuda geral e sintaxe de comandos SQL. |
| `\l` | Lista todos os bancos de dados criados no servidor. |
| `\c <banco>` | Conecta ao banco de dados especificado. |
| `\d` | Lista todas as tabelas e visões do banco atual. |
| `\d <table>` | Exibe a estrutura de colunas e tipos da tabela informada. |
| `\du` | Lista todos os usuários e papéis (*roles*) cadastrados. |
| `\q` | Sai do terminal `psql`. |

### SQLite

O SQLite é uma biblioteca em linguagem C que implementa um mecanismo de banco de dados SQL autônomo, sem servidor e sem necessidade de configuração.

#### Dockerfile para SQLite

O exemplo abaixo demonstra como empacotar uma imagem leve de SQLite:

#### Comandos do `sqlite3` CLI

Principais utilitários no terminal do SQLite:

- `.databases`: Lista os arquivos de bancos de dados anexados.
- `.tables`: Lista o nome de todas as tabelas.
- `.schema <table>`: Exibe a instrução `CREATE TABLE` usada para criar a tabela.
- `.dump`: Exporta todo o banco em formato de script SQL.
- `.quit`: Encerra o interpretador do SQLite.

### MongoDB Server (NoSQL)

O MongoDB é um banco de dados Não-Relacional orientado a documentos JSON/BSON, que opera na porta **27017**.

#### Docker Compose para MongoDB e Mongo Express

Abaixo está o comando para subir o MongoDB em contêiner com suporte a autenticação:

```bash title="Terminal"
docker run -d \
  --name mongo \
  -e MONGO_ROOT_USERNAME=root \
  -e MONGO_ROOT_PASSWORD=secret \
  -v mongodata:/data/db \
  -p 27017:27017 \
  mongo:7.0
```

Conecte-se ao Shell do MongoDB (`mongosh`):

```bash title="Terminal"
docker exec -it mongo mongosh -u root -p secret
```

```javascript title="Shell do MongoDB (mongosh)"
// Alternar ou criar banco de dados
use monitor_db

// Inserir um documento na coleção 'hosts'
db.hosts.insertOne({
  name: 'Google DNS',
  address: '8.8.8.8'
});

// Consultar documentos da coleção
db.hosts.find()
```

## Gestão de Usuários e Permissões

Por questões de segurança, aplicações em produção nunca devem utilizar o usuário superadministrador (`root` ou `postgres`). É essencial criar usuários dedicados com privilégios limitados.

A tabela a seguir compara o ciclo de vida de controle de acesso nos três principais SGBDs com suporte a usuários:

<Aside type="tip" title="Aplicando Alterações no MySQL">
  No MySQL, após executar comandos de privilégios manuais, execute `FLUSH PRIVILEGES;` para recalcular as tabelas de acesso na memória do servidor.
</Aside>

## Tabela Comparativa de Tipos de Dados

Cada motor possui sua especificação de tipos de dados. A tabela abaixo compara os equivalentes mais comuns entre MySQL, PostgreSQL e SQLite:

| Categoria | Tipo Abstrato | MySQL | PostgreSQL | SQLite |
| :--- | :--- | :--- | :--- | :--- |
| **Texto** | String curta | `VARCHAR(n)` | `VARCHAR(n)` ou `TEXT` | `TEXT` |
| **Texto** | Texto longo | `TEXT`, `LONGTEXT` | `TEXT` | `TEXT` |
| **Inteiro** | Chave Auto-Incremento | `INT AUTO_INCREMENT` | `SERIAL` ou `BIGSERIAL` | `INTEGER PRIMARY KEY` |
| **Decimal** | Valor Financeiro | `DECIMAL(10,2)` | `NUMERIC(10,2)` | `REAL` ou `NUMERIC` |
| **Data/Hora** | Data e Horário | `DATETIME` / `TIMESTAMP` | `TIMESTAMP` | `TEXT` (ISO8601) / `INTEGER` |
| **Booleano** | Verdadeiro / Falso | `TINYINT(1)` / `BOOLEAN` | `BOOLEAN` | `INTEGER` (0 ou 1) |
| **Binário** | Arquivos / BLOB | `LONGBLOB` | `BYTEA` | `BLOB` |

## Backup e Restauração

Garantir rotinas de cópia de segurança é premissa básica de administração de SGBD:

<Tabs>
  <TabItem label="MySQL">
    ```bash title="Terminal (Backup e Restore)"
    # Exportar banco completo em SQL
    docker exec mysql mysqldump -u root -p monitor_db > backup.sql

    # Restaurar script SQL
    docker exec -i mysql mysql -u root -p monitor_db < backup.sql
    ```
  </TabItem>
  <TabItem label="PostgreSQL">
    ```bash title="Terminal (Backup e Restore)"
    # Exportar usando pg_dump
    docker exec postgres pg_dump -U postgres monitor_db > backup.sql

    # Restaurar usando psql
    docker exec -i postgres psql -U postgres monitor_db < backup.sql
    ```
  </TabItem>
  <TabItem label="SQLite">
    ```bash title="Terminal (Backup e Restore)"
    # Gerar cópia física ou dump SQL
    sqlite3 banco.db .dump > backup.sql

    # Restaurar
    sqlite3 banco_restaurado.db < backup.sql
    ```
  </TabItem>
</Tabs>

## Exercício

1. Crie um arquivo `docker-compose.yml` que suba uma instância do PostgreSQL e uma instância do Adminer.
2. Escreva o comando SQL para criar um usuário `gestor` no PostgreSQL com acesso apenas de leitura (`SELECT`) em todas as tabelas do esquema público.

<details>
  <summary>Possível resposta</summary>

  1. **Docker Compose**:
     ```yaml
     version: '3.8'
     services:
       db:
         image: postgres:16
         environment:
           POSTGRES_PASSWORD: secret
       adminer:
         image: adminer
         ports:
           - "8080:8080"
     ```

  2. **Comando SQL**:
     ```sql
     CREATE USER gestor WITH PASSWORD 'senha123';

     GRANT USAGE ON SCHEMA public TO gestor;
     GRANT SELECT ON ALL TABLES IN SCHEMA public TO gestor;
     ```
</details>

## Perguntas de revisão

1. **Qual a diferença fundamental entre a arquitetura do MySQL/Postgres e a do SQLite?**
   <details><summary>Possível resposta</summary>MySQL e Postgres utilizam arquitetura Cliente-Servidor com processos independentes escutando em portas de rede. O SQLite é embutido (*file-based*), rodando no próprio processo da aplicação.</details>

2. **Qual é a porta de rede padrão do MySQL, PostgreSQL e MongoDB?**
   <details><summary>Possível resposta</summary>MySQL: 3306. PostgreSQL: 5432. MongoDB: 27017.</details>

3. **Para que serve a instrução `FLUSH PRIVILEGES;` no MySQL?**
   <details><summary>Possível resposta</summary>Recarrega as permissões de acesso da tabela de concedimentos na memória RAM do servidor MySQL imediatamente.</details>

4. **Como o SQLite lida nativamente com o tipo de dado Booleano?**
   <details><summary>Possível resposta</summary>O SQLite armazena booleanos como inteiros, usando 0 para falso e 1 para verdadeiro.</details>

5. **Qual utilitário de linha de comando é usado para fazer backup de um banco PostgreSQL?**
   <details><summary>Possível resposta</summary>O utilitário `pg_dump` (ou `pg_dumpall` para todos os bancos do cluster).</details>

6. **No PostgreSQL, o que faz a coluna com o tipo de dado `SERIAL`?**
   <details><summary>Possível resposta</summary>Cria um inteiro com incremento automático vinculado a uma sequência (*sequence*).</details>

7. **Qual é o comando do MongoDB Shell para listar as coleções do banco atual?**
   <details><summary>Possível resposta</summary>`show collections` ou `db.getCollectionNames()`.`</details>

8. **Por que é recomendável usar volumes do Docker ao executar contêineres de SGBD?**
   <details><summary>Possível resposta</summary>Para garantir a persistência dos dados gravados no banco mesmo quando o contêiner for destruído ou atualizado.</details>
