O provisionamento de bancos de dados relacionais gerenciados na nuvem envolve a definição de motores (PostgreSQL ou MySQL), classes de computação, armazenamento e configurações de rede privada (*Virtual Private Cloud - VPC*). Neste tópico, você aprenderá a criar instâncias no **Amazon RDS** e clusters no **Amazon Aurora**, liberar portas com *Security Groups* e conectar clientes com criptografia TLS.

---

## Objetivo

Aprender a provisionar instâncias relacionais gerenciadas na nuvem pública, isolar o acesso em redes virtuais privadas e conectar clientes e SDKs utilizando endpoints de cluster e certificados TLS. Ao final do tópico, o leitor deve ser capaz de:

- Provisionar uma instância no Amazon RDS ou cluster no Amazon Aurora via AWS Console e AWS CLI.
- Configurar *DB Subnet Groups* e regras de entrada em *Security Groups* para portas padrão (5432 para PostgreSQL e 3306 para MySQL).
- Diferenciar o *Cluster Endpoint* (escrita e leitura) do *Reader Endpoint* (balanceamento entre réplicas) no Aurora.
- Estabelecer conexões seguras exigindo certificados de Autoridade Certificadora (*CA*) e TLS.
- Conectar utilitários de linha de comando (`psql`, `mysql`) e ferramentas visuais como DBeaver ao banco na nuvem.

## Passo a Passo de Provisionamento

<Steps>
1. **Definir o Security Group de Acesso:**

   Crie um grupo de segurança na VPC autorizando a porta 5432 (PostgreSQL) apenas para o IP da sua aplicação ou faixa CIDR interna:

   ```bash
   aws ec2 create-security-group \
     --group-name "db-access-sg" \
     --description "Acesso restrito ao banco relacional" \
     --vpc-id "vpc-0a1b2c3d4e5f6"
   ```

2. **Provisionar um cluster Amazon Aurora PostgreSQL via AWS CLI:**

   Execute o comando de criação do cluster definindo o motor e as credenciais mestras:

   ```bash
   aws rds create-db-cluster \
     --db-cluster-identifier "invest-db-cluster" \
     --engine "aurora-postgresql" \
     --engine-version "16.2" \
     --master-username "dbadmin" \
     --master-user-password "SuaSenhaForte123!" \
     --vpc-security-group-ids "sg-0123456789abcdef0" \
     --backup-retention-period 7
   ```

3. **Adicionar a instância primária de computação:**

   Crie a instância que atuará como nó de escrita no cluster criado:

   ```bash
   aws rds create-db-instance \
     --db-instance-identifier "invest-db-instance-1" \
     --db-cluster-identifier "invest-db-cluster" \
     --db-instance-class "db.t4g.medium" \
     --engine "aurora-postgresql"
   ```

4. **Obter os Endpoints de Conexão:**

   Consulte os endereços DNS gerados para escrita e leitura:

   ```bash
   aws rds describe-db-clusters \
     --db-cluster-identifier "invest-db-cluster" \
     --query "DBClusters[0].[Endpoint,ReaderEndpoint]"
   ```
</Steps>

## Conexão Segura com TLS/SSL

Em bancos de dados na nuvem, conexões sem criptografia são vulneráveis a interceptações em trânsito. A AWS disponibiliza o pacote de certificados raiz globais para validar a identidade do servidor:

```bash
# Conectar via psql exigindo verificação de certificado TLS
psql "host=invest-db-cluster.cluster-xyz.us-east-1.rds.amazonaws.com \
      port=5432 \
      dbname=postgres \
      user=dbadmin \
      sslmode=verify-full \
      sslrootcert=global-bundle.pem"
```

Em aplicações Node.js utilizando `pg` ou Prisma:

```typescript
// Configuração de conexão no Node.js com SSL obrigatório
import { Pool } from 'pg';
import fs from 'node:fs';

export const pool = new Pool({
  host: process.env.DATABASE_HOST, // Cluster Endpoint
  port: 5432,
  user: process.env.DATABASE_USER,
  password: process.env.DATABASE_PASSWORD,
  database: 'invest_db',
  ssl: {
    rejectUnauthorized: true,
    ca: fs.readFileSync('./certs/global-bundle.pem').toString(),
  },
});
```

## Perguntas de revisão

<details>
<summary>1. O que é um DB Subnet Group no Amazon RDS?</summary>
Um *DB Subnet Group* é uma coleção de sub-redes privadas de uma VPC que engloba no mínimo duas Zonas de Disponibilidade distintas. Ele define em quais zonas físicas o RDS pode provisionar instâncias de computação e manter instâncias de reserva (*standby*) para alta disponibilidade.
</details>

<details>
<summary>2. Como os grupos de parâmetros (DB Parameter Groups) controlam o comportamento do motor?</summary>
Os *Parameter Groups* atuam como o arquivo de configuração (`postgresql.conf` ou `my.cnf`) do banco na nuvem. Eles permitem ajustar parâmetros globais como `max_connections`, `shared_buffers`, fuso horário e extensões sem acesso direto ao sistema operacional da máquina virtual.
</details>
