Até aqui os dados viviam num array — some tudo quando o servidor reinicia. Um banco
de dados relacional resolve isso e, de quebra, garante consistência.

Usaremos **SQLite**: um banco relacional completo em um único arquivo, sem servidor
para instalar.

## Tabelas, colunas e linhas

Um recurso da API costuma virar uma tabela. Cada campo vira uma coluna, cada registro
vira uma linha.

```sql title="schema.sql" showLineNumbers {2,5}
CREATE TABLE User (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  name      TEXT    NOT NULL,
  email     TEXT    NOT NULL UNIQUE,
  createdAt DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

- `PRIMARY KEY` identifica cada linha de forma única.
- `NOT NULL` impede o campo vazio.
- `UNIQUE` impede duplicidade — é o banco garantindo a regra, não a aplicação.

## Relacionamentos

Um usuário tem vários posts. A chave estrangeira mora no lado "muitos":

```sql title="schema.sql" {6-7}
CREATE TABLE Post (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  title     TEXT    NOT NULL,
  content   TEXT,
  published BOOLEAN DEFAULT 0,
  authorId  INTEGER NOT NULL,
  FOREIGN KEY (authorId) REFERENCES User(id) ON DELETE CASCADE
);
```

`ON DELETE CASCADE` remove os posts quando o autor é removido, evitando registros
órfãos.

## As quatro operações

```sql title="crud.sql"
-- CREATE
INSERT INTO User (name, email) VALUES ('Ana', 'ana@example.com');

-- READ
SELECT * FROM User;
SELECT id, name FROM User WHERE id = 1;

-- UPDATE
UPDATE User SET name = 'Ana Silva' WHERE id = 1;

-- DELETE
DELETE FROM User WHERE id = 1;
```

:::caution[`WHERE` não é opcional]
`UPDATE User SET name = 'X';` sem `WHERE` altera **todas** as linhas. O mesmo vale
para `DELETE`.
:::

## Filtrar, ordenar e paginar

São exatamente as operações que a API expõe via query string:

```sql title="consultas.sql"
SELECT * FROM User WHERE name LIKE 'A%';

SELECT * FROM User ORDER BY name ASC;

SELECT * FROM User LIMIT 10 OFFSET 20;
```

## JOIN

Traz dados de duas tabelas em uma consulta:

```sql title="join.sql" {4}
SELECT User.name, Post.title
FROM Post
INNER JOIN User ON Post.authorId = User.id
WHERE Post.published = 1;
```

- `INNER JOIN` traz apenas linhas com correspondência nos dois lados.
- `LEFT JOIN` traz todas as linhas da esquerda, mesmo sem correspondência.

## Agregações

```sql title="agregacoes.sql"
SELECT COUNT(*) AS total FROM User;

SELECT authorId, COUNT(*) AS posts
FROM Post
GROUP BY authorId;
```

## E a partir daqui?

Escrever SQL na mão dentro do controller funciona, mas expõe a aplicação a erros de
digitação e a SQL injection. Na próxima aula usamos o **Prisma**, que gera consultas
seguras a partir de um schema declarativo — sem que você deixe de saber o que ele
está executando.

categoria. Escreva as consultas para: listar produtos com o nome da categoria,
contar produtos por categoria e remover uma categoria sem deixar produtos órfãos.
