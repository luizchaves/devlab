Este tópico apresenta os fundamentos da linguagem **SQL** (Structured Query Language). Você aprenderá a criar e alterar a estrutura de tabelas usando comandos **DDL** (*Data Definition Language*), aplicar restrições de integridade relacional e manipular os dados com os comandos **DML** (*Data Manipulation Language*) do CRUD.

---

## Objetivo

Dominar a sintaxe dos comandos que definem a estrutura de um banco e manipulam seus dados, a partir de um esquema de blog executado de verdade no SQLite, para que cada instrução tenha uma saída conferível. Ao final do tópico, o leitor deve ser capaz de:

- Diferenciar os subconjuntos da SQL (DDL, DML, DQL, DCL e TCL) pela finalidade de cada um.
- Criar tabelas com `CREATE TABLE`, aplicando `PRIMARY KEY`, `NOT NULL`, `UNIQUE`, `DEFAULT` e `CHECK`.
- Relacionar tabelas por chave estrangeira e prever o efeito de `ON DELETE CASCADE`.
- Executar as quatro operações do CRUD com `INSERT`, `SELECT`, `UPDATE` e `DELETE`.
- Filtrar, ordenar e paginar resultados com `WHERE`, `ORDER BY`, `LIMIT` e `OFFSET`.

---

## Subdivisões da Linguagem SQL

A linguagem SQL é dividida em subconjuntos especializados de acordo com a finalidade de cada comando:

| Subconjunto | Sigla | Comandos Principais | Descrição Didática |
| :--- | :--- | :--- | :--- |
| **Data Definition Language** | DDL | `CREATE`, `ALTER`, `DROP` | Define e modifica a estrutura das tabelas e esquemas. |
| **Data Manipulation Language** | DML | `INSERT`, `UPDATE`, `DELETE` | Insere, altera e remove dados dentro das tabelas. |
| **Data Query Language** | DQL | `SELECT` | Consulta e recupera dados armazenados. |
| **Data Control Language** | DCL | `GRANT`, `REVOKE` | Administra permissões de acesso dos usuários. |
| **Transaction Control Language** | TCL | `COMMIT`, `ROLLBACK` | Gerencia a confirmação e cancelamento de transações. |

Este tópico cobre DDL, DML e DQL. O controle de acesso tem o [tópico próprio de DCL](../dcl/) e aparece em [Administração](../../basics/administration/), e as transações têm o [tópico próprio](../transactions/).

### Restrições de Integridade Relacional

As restrições (*constraints*) garantem a validade dos dados no próprio SGBD, antes de qualquer validação na aplicação:

- `PRIMARY KEY`: Identifica unicamente cada linha de forma exclusiva.
- `NOT NULL`: Impede que a coluna receba valores nulos ou vazios.
- `UNIQUE`: Garante que não existam dois registros com o mesmo valor (ex: e-mail duplicado).
- `DEFAULT`: Atribui um valor padrão automático caso nenhum seja informado na inserção.
- `CHECK`: Valida se o valor atende a uma condição (ex: `age >= 18`).

As quatro operações fundamentais do CRUD são mapeadas diretamente para comandos SQL. A inserção nomeia as colunas que recebem valor e deixa o `id` e o `createdAt` para os padrões da tabela:

<SourceCode path="examples/courses/database/invest-db/crud.sql" region="create" />

```txt title="Output"
-- 1 linha(s) afetada(s)
```

A leitura tem duas formas: todas as colunas de todas as linhas com `SELECT *`, ou colunas escolhidas e uma linha filtrada por `WHERE`:

<SourceCode path="examples/courses/database/invest-db/crud.sql" region="read" />

```txt title="Output"
id | name        | email             | createdAt
---+-------------+-------------------+--------------------
1  | Ana Silva   | ana@example.com   | 2026-01-10 09:00:00
2  | Bruno Costa | bruno@example.com | 2026-02-15 14:30:00
3  | Carla Souza | carla@example.com | 2026-03-20 08:45:00
4  | Diego Lima  | diego@example.com | 2026-04-05 17:10:00
5  | Eva Rocha   | eva@example.com   | 2026-05-01 10:00:00
id | name
---+----------
1  | Ana Silva
```

A atualização e a exclusão seguem o mesmo padrão: o `WHERE` escolhe as linhas, e a consulta em seguida confere o efeito:

<SourceCode path="examples/courses/database/invest-db/crud.sql" region="update" />

```txt title="Output"
-- 1 linha(s) afetada(s)
id | name
---+----------------
1  | Ana Maria Silva
```

<SourceCode path="examples/courses/database/invest-db/crud.sql" region="delete" />

```txt title="Output"
-- 1 linha(s) afetada(s)
total
-----
4
```

<Aside type="caution" title="Cuidado: A Cláusula WHERE não é opcional">
  Executar `UPDATE User SET name = 'X';` ou `DELETE FROM User;` sem a cláusula `WHERE` alterará ou apagará **todas as linhas** da tabela sem confirmação prévia!
</Aside>

<Aside type="caution" title="Dica de IA: Peça o SELECT que conta antes do UPDATE ou DELETE">
  Assistentes entregam o `UPDATE` ou o `DELETE` pronto e correto para o exemplo pedido, mas o `WHERE` que está certo para dez linhas de teste pode atingir milhares em produção, e o comando não pede confirmação. O hábito que protege é rodar primeiro o `SELECT COUNT(*)` com o mesmo `WHERE`.

  **Prompt:** *"Antes do `DELETE`, escreva o `SELECT COUNT(*)` com exatamente a mesma cláusula `WHERE`, e mostre como executar os dois dentro de uma transação para reverter se a contagem for maior do que o esperado."*
</Aside>

## Operadores de Filtragem no `WHERE`

Para realizar buscas precisas, a cláusula `WHERE` aceita operadores de padrão (`LIKE`), de conjunto (`IN`), de intervalo (`BETWEEN`), de nulidade (`IS NULL`) e os conectivos lógicos `AND` e `OR`. O arquivo abaixo exercita um de cada:

<SourceCode path="examples/courses/database/invest-db/filters.sql" />

```txt title="Output"
id | name
---+----------
1  | Ana Silva
id | name
---+------------
1  | Ana Silva
3  | Carla Souza
id | title              | views
---+--------------------+------
2  | Junções explicadas | 80
4  | Receita de pão     | 45
id | title
---+-----------------------
3  | Rascunho sobre índices
id | title
---+------------------
4  | Receita de pão
5  | Viagem ao litoral
```

Repare na segunda consulta: o `IN (1, 3, 5)` devolveu só dois usuários, porque não existe `id = 5` no `seed.sql`. Um filtro que pede valores inexistentes não é erro, é conjunto vazio.

## Ordenação e Paginação

Em APIs RESTful, é essencial ordenar e paginar grandes volumes de dados antes de enviá-los ao cliente. O `ORDER BY` define a ordem, o `LIMIT` a quantidade e o `OFFSET` quantas linhas pular:

<SourceCode path="examples/courses/database/invest-db/ordering.sql" />

```txt title="Output"
id | name
---+------------
1  | Ana Silva
2  | Bruno Costa
3  | Carla Souza
4  | Diego Lima
id | title              | views
---+--------------------+------
2  | Junções explicadas | 80
4  | Receita de pão     | 45
```

A segunda consulta ordena os seis posts por audiência e devolve a "segunda página" de dois: pulou os dois mais vistos (200 e 120) e trouxe os dois seguintes. O custo dessa forma de paginar em tabelas grandes é tratado em [Desempenho](../performance/).

## Exercício

Considere a criação de um sistema de inventário de produtos, no mesmo estilo do blog do projeto:

1. Escreva o comando DDL para criar a tabela `Product` com colunas `id`, `name` (obrigatório), `price` (decimal positivo), e `categoryId` (chave estrangeira).
2. Escreva o comando DML para atualizar o preço em 10% de todos os produtos da categoria 2.

<details>
  <summary>Possível resposta</summary>

  1. **Comando DDL**:
     ```sql
     CREATE TABLE Product (
       id INTEGER PRIMARY KEY AUTOINCREMENT,
       name TEXT NOT NULL,
       price DECIMAL(10,2) CHECK (price >= 0),
       categoryId INTEGER NOT NULL,
       FOREIGN KEY (categoryId) REFERENCES Category(id)
     );
     ```

  2. **Comando DML**:
     ```sql title="Atualização de preço por categoria"
     UPDATE Product
     SET price = price * 1.10
     WHERE categoryId = 2;
     ```
</details>

## Desafio

O `seed.sql` do projeto insere os dados em uma ordem fixa: usuários antes dos posts, porque a chave estrangeira exige que o autor exista. Escreva um arquivo `challenge.sql` que tente violar cada uma das restrições do esquema, uma por instrução: um e-mail duplicado, um post sem título, um post cujo `authorId` não existe e um `DELETE` de usuário que arraste os posts pelo `ON DELETE CASCADE`.

Execute com `node run.mjs challenge.sql` e explique, para cada instrução, se o erro impresso veio da restrição que você esperava. Depois responda: por que o script imprime o erro e continua, em vez de parar no primeiro?

<details>
  <summary>Possível resposta</summary>

  As três primeiras instruções falham com mensagens distintas do SQLite: `UNIQUE constraint failed: User.email`, `NOT NULL constraint failed: Post.title` e `FOREIGN KEY constraint failed`. A quarta não falha: o `DELETE FROM User WHERE id = 1` remove a usuária e os três posts dela, o que um `SELECT COUNT(*) FROM Post` em seguida confirma ao devolver 3 em vez de 6. Vale notar que a chave estrangeira só é aplicada porque o `run.mjs` liga `PRAGMA foreign_keys = ON`: por padrão, o SQLite aceita o post órfão em silêncio.

  O script continua porque a página precisa mostrar erros de propósito. Em uma aplicação, o comportamento é o oposto: o erro interrompe, e a transação em que a instrução estava é desfeita, como o tópico de [Transações](../transactions/) mostra.
</details>

## Perguntas de revisão

### Estrutura

1. **Quais são os 5 subconjuntos da linguagem SQL?**
   <details><summary>Possível resposta</summary>DDL (Data Definition), DML (Data Manipulation), DQL (Data Query), DCL (Data Control) e TCL (Transaction Control).</details>

2. **Qual é a diferença entre os comandos `DROP` e `DELETE`?**
   <details><summary>Possível resposta</summary>`DROP` (DDL) remove a própria tabela e sua estrutura do banco. `DELETE` (DML) apaga apenas as linhas de dados mantendo a estrutura da tabela intacta.</details>

3. **O que garante a restrição `UNIQUE` em uma coluna?**
   <details><summary>Possível resposta</summary>Garante que nenhum valor seja duplicado naquela coluna entre as linhas da tabela.</details>

4. **Para que serve o operador `LIKE` em uma consulta SQL?**
   <details><summary>Possível resposta</summary>Para realizar buscas textuais por padrões flexíveis utilizando os caracteres curinga `%` e `_`.</details>

### Dados

5. **Como funciona a paginação usando `LIMIT` e `OFFSET`?**
   <details><summary>Possível resposta</summary>`LIMIT` define a quantidade de registros a retornar e `OFFSET` indica quantos registros devem ser pulados do início.</details>

6. **O que acontece ao apagar um registro pai com a opção `ON DELETE CASCADE` configurada na chave estrangeira?**
   <details><summary>Possível resposta</summary>Todos os registros filhos vinculados àquele pai na tabela dependente serão automaticamente excluídos.</details>

7. **Qual é o operador SQL usado para verificar se um campo não possui valor atribuído?**
   <details><summary>Possível resposta</summary>O operador `IS NULL` (ou `IS NOT NULL`).</details>

8. **Qual comando DDL é utilizado para adicionar uma nova coluna em uma tabela existente?**
   <details><summary>Possível resposta</summary>O comando `ALTER TABLE nome_tabela ADD COLUMN nome_coluna tipo;`.</details>
