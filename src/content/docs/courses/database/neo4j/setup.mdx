Configurar o **Neo4j** para desenvolvimento envolve inicializar a edição comunitária em contêiner Docker com portas abertas para a interface web de exploração visual e para o protocolo binário Bolt.

## Objetivo

Aprender a subir o servidor Neo4j localmente com Docker Compose, autenticar-se na interface interativa Neo4j Browser e executar comandos administrativos através do utilitário `cypher-shell`. Ao final do tópico, o leitor deve ser capaz de:

- Iniciar o Neo4j Community através de um arquivo `docker-compose.yml`.
- Configurar autenticação inicial através da variável `NEO4J_AUTH`.
- Utilizar a interface gráfica Neo4j Browser na porta HTTP `7474`.
- Executar scripts Cypher no terminal com `cypher-shell`.

## Executando

<Steps>
1. **Criar o arquivo `.env`:**

   Copie as variáveis de ambiente padrão para a pasta do servidor:

   ```bash
   cp examples/courses/database/servers/neo4j-server/.env.example examples/courses/database/servers/neo4j-server/.env
   ```

2. **Iniciar o contêiner:**

   Suba o serviço Neo4j com Docker Compose:

   ```bash
   docker compose -f examples/courses/database/servers/neo4j-server/docker-compose.yml up -d
   ```

3. **Conectar pelo terminal com `cypher-shell`:**

   Execute o comando abaixo para abrir a sessão de linha de comando:

   ```bash
   docker exec -it neo4j cypher-shell -u neo4j -p neo4jpassword123
   ```

   O prompt interativo confirma a conexão:

   ```text
   Connected to: Neo4j/5.18.0
   neo4j@neo4j> RETURN "Neo4j Online!" AS status;
   +-----------------+
   | status          |
   +-----------------+
   | "Neo4j Online!" |
   +-----------------+
   1 row available after 2 ms
   ```

4. **Acessar a interface visual Neo4j Browser:**

   Abra o navegador no endereço `http://localhost:7474`.
   - **Database**: `neo4j`
   - **Authentication type**: `Username / Password`
   - **Username**: `neo4j`
   - **Password**: `neo4jpassword123`

   O Neo4j Browser renderiza os nós como círculos coloridos e os relacionamentos como setas interativas que podem ser arrastadas e expandidas com cliques.
</Steps>

## Cadeia de Conexão (Bolt Protocol)

Para conectar drivers de aplicação (como `neo4j-driver` em Node.js ou Python):

```text
bolt://localhost:7687
```

- **Protocolo**: `bolt://` (ou `neo4j://` para clusters gerenciados como o Neo4j AuraDB).
- **Porta**: `7687` (transporte binário de baixa latência).

## Exercício

Com o `cypher-shell` aberto, execute as operações básicas:

1. Crie um nó com o rótulo `:TestNode` e a propriedade `name: 'Servidor Local'`.
2. Consulte o nó criado e exiba suas propriedades.
3. Apague o nó de teste.

<details>
  <summary>Possível resposta</summary>

  ```cypher
  CREATE (t:TestNode {name: 'Servidor Local'}) RETURN t;
  MATCH (t:TestNode {name: 'Servidor Local'}) RETURN t.name;
  MATCH (t:TestNode {name: 'Servidor Local'}) DELETE t;
  ```
</details>

## Desafio

Por que apagar um nó que possui relacionamentos ativos gera um erro de integridade (`Cannot delete node because it still has relationships`), e qual modificador do comando `DELETE` resolve essa situação de uma única vez?

<details>
  <summary>Possível resposta</summary>

  O Neo4j impede que relacionamentos fiquem "órfãos" (sem nós nas extremidades de origem ou destino).

  Para remover o nó e todos os relacionamentos conectados a ele de forma atômica, utiliza-se a cláusula `DETACH DELETE`:

  ```cypher
  MATCH (n:User {name: 'Lucas'})
  DETACH DELETE n;
  ```
</details>
