A linguagem **Cypher** é a interface declarativa do Neo4j. Ela expressa consultas através de padrões visuais em arte ASCII: parênteses `()` representam **nós**, colchetes `[]` representam **relacionamentos** e setas `-->` indicam a direção da conexão.

## Objetivo

Dominar a sintaxe da linguagem Cypher para criar, consultar e analisar dados conectados no domínio de investimentos do `invest-db`, implementando sistemas de recomendação social e cálculo de caminhos mínimos. Ao final do tópico, o leitor deve ser capaz de:

- Criar restrições de unicidade e índices para garantir integridade e acelerar pontos de entrada.
- Inserir nós e relacionamentos com propriedades utilizando a cláusula `CREATE`.
- Consultar dados conectados combinando `MATCH`, `WHERE` e `RETURN`.
- Escrever consultas de recomendação colaborativa e caminhos mínimos com `shortestPath()`.

## Sintaxe Visual do Cypher

A tabela abaixo compara as cláusulas essenciais do Cypher com seus equivalentes relacionais:

| Cláusula Cypher | Cláusula SQL Equivalente | Função no Grafo |
| :--- | :--- | :--- |
| `CREATE (n:Label {prop: 'val'})` | `INSERT INTO ...` | Cria um novo nó ou relacionamento com propriedades. |
| `MATCH (a)-[:REL]->(b)` | `SELECT ... FROM ... JOIN` | Busca padrões de nós e relacionamentos interconectados. |
| `WHERE a.prop > 100` | `WHERE ...` | Aplica filtros lógicos aos nós ou propriedades do padrão. |
| `RETURN a.name, b.title` | `SELECT ...` | Projeta os campos, nós ou caminhos que devem ser devolvidos. |
| `SET n.amount = 500` | `UPDATE ... SET` | Adiciona ou altera propriedades de nós e relacionamentos existentes. |
| `DELETE n` / `DETACH DELETE n` | `DELETE FROM ...` | Remove nós e seus respectivos relacionamentos conectados. |

## Consultas Fundamentais

### 1. Filtrando por Vizinhança Direta

Para listar todos os ativos em que o usuário `"Lucas Chaves"` investe:

```cypher
MATCH (u:User {name: 'Lucas Chaves'})-[r:INVESTS_IN]->(a:Asset)
RETURN a.code AS Ativo, r.amount AS ValorInvestido;
```

### 2. Motor de Recomendação Social ("Quem você segue investe em quê?")

Identifica ativos investidos por amigos que o próprio usuário ainda não possui na carteira:

```cypher
MATCH (eu:User {name: 'Lucas Chaves'})-[:FOLLOWS]->(amigo:User)-[:INVESTS_IN]->(ativo:Asset)
WHERE NOT (eu)-[:INVESTS_IN]->(ativo)
RETURN DISTINCT amigo.name AS Amigo, ativo.name AS Sugestao;
```

### 3. Menor Caminho entre Duas Pessoas (*Degrees of Separation*)

Calcula a rota mais curta de conexões sociais entre duas pessoas distantes:

```cypher
MATCH p = shortestPath((u1:User {name: 'Lucas Chaves'})-[:FOLLOWS*]-(u3:User {name: 'Carlos Souza'}))
RETURN [n IN nodes(p) | n.name] AS CaminhoSocial, length(p) AS GrausDeSeparacao;
```

## Exercício

Com base no grafo de investimentos criado:

1. Escreva uma consulta Cypher que retorne o valor total investido somando todos os usuários por categoria de ativo.
2. Escreva uma consulta que descubra se existe algum ativo sem nenhum investidor conectado.

<details>
  <summary>Possível resposta</summary>

  1. Soma total por categoria:
     ```cypher
     MATCH (:User)-[r:INVESTS_IN]->(a:Asset)-[:IN_CATEGORY]->(c:Category)
     RETURN c.name AS Categoria, sum(r.amount) AS TotalInvestido
     ORDER BY TotalInvestido DESC;
     ```

  2. Ativos sem investidores (nós desconectados do relacionamento `INVESTS_IN`):
     ```cypher
     MATCH (a:Asset)
     WHERE NOT ()-[:INVESTS_IN]->(a)
     RETURN a.name AS AtivoSemInvestidores;
     ```
</details>

## Desafio

Em uma rede financeira, transferências suspeitas ocorrem quando o dinheiro circula em **ciclos fechados** (o usuário A transfere para B, B para C e C transfere de volta para A).

Como expressar uma consulta em Cypher para detectar qualquer ciclo de transferências financeiras de até 4 saltos de distância?

<details>
  <summary>Possível resposta</summary>

  Utiliza-se a correspondência de caminhos de comprimento variável com nós de início e fim idênticos:

  ```cypher
  MATCH p = (u:User)-[:TRANSFERRED_TO*2..4]->(u)
  RETURN [n IN nodes(p) | n.name] AS CicloSuspeito, length(p) AS Saltos;
  ```

  Essa consulta simples em Cypher substitui dezenas de linhas de SQL recursivo complexo e custoso.
</details>

## Perguntas de revisão

1. **Como criar uma restrição para impedir e-mails duplicados no Neo4j?**
   <details><summary>Possível resposta</summary>Com o comando `CREATE CONSTRAINT FOR (u:User) REQUIRE u.email IS UNIQUE;`.</details>

2. **Qual é a função do operador `OPTIONAL MATCH`?**
   <details><summary>Possível resposta</summary>É o equivalente ao `LEFT JOIN` do SQL: tenta casar o padrão no grafo e, caso não encontre relacionamentos, devolve `null` nos campos correspondentes sem descartar a linha.</details>

3. **O que representa a sintaxe `-[:FOLLOWS*1..3]->`?**
   <details><summary>Possível resposta</summary>Representa um caminho de comprimento variável, percorrendo relacionamentos do tipo `FOLLOWS` de 1 até 3 saltos de profundidade.</details>
