Configurar o **MinIO** para desenvolvimento local envolve subir o servidor como contêiner Docker com persistência em volume, acessar o painel administrativo web (*MinIO Console*) e utilizar o utilitário de linha de comando **MinIO Client (`mc`)** para criar baldes e definir políticas de acesso.

---

## Objetivo

Aprender a provisionar o servidor MinIO localmente com Docker Compose, autenticar no Console Web e configurar aliases no utilitário de terminal `mc`. Ao final do tópico, o leitor deve ser capaz de:

- Subir o contêiner MinIO através do arquivo `docker-compose.yml`.
- Configurar credenciais de administrador seguras via arquivo `.env`.
- Acessar e operar o MinIO Web Console no navegador (`http://localhost:9001`).
- Configurar e executar comandos de gerenciamento com o utilitário `mc`.
- Criar *buckets* e validar a conectividade da API S3 na porta 9000.

---

## Arquivos de Configuração

O diretório `examples/courses/database/servers/minio-server/` disponibiliza o ambiente de desenvolvimento completo com a imagem oficial do MinIO:

As variáveis de credenciais ficam isoladas no arquivo `.env`:

```ini title=".env.example"

MINIO_ROOT_PASSWORD=miniopassword123
```

## Executando

<Steps>
1. **Criar o arquivo de variáveis de ambiente:**

   Copie o modelo de variáveis para criar o arquivo `.env` dentro da pasta do servidor:

   ```bash
   cp examples/courses/database/servers/minio-server/.env.example examples/courses/database/servers/minio-server/.env
   ```

2. **Iniciar o contêiner MinIO:**

   Execute o comando `docker compose up -d` para baixar a imagem e iniciar o serviço em segundo plano:

   ```bash
   docker compose -f examples/courses/database/servers/minio-server/docker-compose.yml up -d
   ```

3. **Verificar os logs de inicialização:**

   Confirme que o servidor iniciou e exibe os endpoints das portas 9000 (API S3) e 9001 (Console Web):

   ```bash
   docker logs minio
   ```

   A saída esperada deve confirmar o endereço da API e do Console:

   ```text
   API: http://172.18.0.2:9000  http://127.0.0.1:9000
   WebUI: http://172.18.0.2:9001 http://127.0.0.1:9001

   Documentation: https://min.io/docs/minio/linux/index.html
   ```

4. **Acessar o MinIO Web Console:**

   Abra o navegador no endereço `http://localhost:9001`. Insira o usuário `minioadmin` e a senha `miniopassword123` para visualizar o painel de controle, criar buckets e inspecionar arquivos.

5. **Configurar o cliente `mc` via Docker:**

   Você pode executar o utilitário oficial `mc` diretamente via contêiner e registrar o servidor local:

   ```bash
   docker run --rm -it --network host minio/mc alias set local http://localhost:9000 minioadmin miniopassword123
   ```

   Para criar o primeiro balde (*bucket*) de teste:

   ```bash
   docker run --rm -it --network host minio/mc mb local/invest-uploads
   ```
</Steps>

<Aside type="tip" title="Porta 9000 vs. Porta 9001">
  A **porta 9000** é reservada exclusivamente para o tráfego da API Amazon S3 (requisições HTTP REST feitas pelos SDKs da sua aplicação). A **porta 9001** é dedicada à interface gráfica (*Web Console*) para administração humana.
</Aside>

## Exercício

Com o servidor MinIO ativo em sua máquina:

1. Acesse o Console Web na porta 9001 e crie um bucket chamado `documentos-fiscais`.
2. Faça o upload manual de um arquivo de texto pelo Console Web.
3. Utilize o comando `mc ls local` para verificar se o bucket aparece na listagem do terminal.

## Desafio

Crie um usuário adicional no MinIO chamado `api-service` com permissões restritas de leitura e escrita apenas no bucket `invest-uploads`, garantindo que esse usuário não consiga acessar os demais buckets do servidor.

## Perguntas de revisão

<details>
<summary>1. Por que é recomendável separar o usuário de root do MinIO dos usuários de aplicações?</summary>
Assim como em bancos de dados relacionais, o usuário root possui privilégios totais de destruição e reconfiguração global. Criar chaves de acesso com políticas de permissão restritas (*Service Accounts / Access Keys*) reduz os danos caso as credenciais da aplicação vazem.
</details>

<details>
<summary>2. Como os dados enviados ao MinIO sobrevivem ao reinício do contêiner Docker?</summary>
O `docker-compose.yml` mapeia um volume nomeado (`minio_data:/data`). Todos os dados persistidos no diretório `/data` do contêiner residem no armazenamento do host do Docker, mantendo os arquivos intactos entre execuções de `down` e `up`.
</details>
