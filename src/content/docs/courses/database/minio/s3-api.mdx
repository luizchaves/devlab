A interação com o **MinIO** ocorre tanto por utilitários de terminal (`mc`) quanto programaticamente através da API Amazon S3. Neste tópico, você aprenderá a executar operações essenciais de ciclo de vida de objetos, aplicar metadados e gerar URLs pré-assinadas (*Presigned URLs*) em aplicações Node.js e TypeScript.

---

## Objetivo

Dominar as operações fundamentais de gerenciamento de objetos no MinIO via linha de comando e através do SDK oficial da AWS em aplicações backend. Ao final do tópico, o leitor deve ser capaz de:

- Utilizar os comandos essenciais do cliente `mc` (`mb`, `cp`, `ls`, `rm`, `share`, `anonymous`).
- Conectar uma aplicação Node.js ao MinIO utilizando a biblioteca `@aws-sdk/client-s3`.
- Realizar uploads e downloads com associação de metadados e tipo MIME (`ContentType`).
- Gerar URLs pré-assinadas (*Presigned URLs*) para upload e download direto pelo cliente.
- Configurar políticas de acesso anônimo para baldes de conteúdo público.

A tabela abaixo sintetiza os principais comandos do `mc`:

| Comando | Função | Exemplo |
| :--- | :--- | :--- |
| `mc mb` | Cria um novo balde (*Make Bucket*) | `mc mb local/fotos-perfil` |

| `mc share download` | Gera uma URL pré-assinada de download temporária | `mc share download --expire 1h local/fotos-perfil/u1.png` |
| `mc anonymous set` | Define política de leitura pública anônima no bucket | `mc anonymous set download local/fotos-perfil` |

## Integração com Node.js e AWS SDK v3

Como o MinIO implementa fielmente o protocolo S3, utiliza-se o cliente padrão da AWS (`@aws-sdk/client-s3`) apontando para o endpoint local:

<Mermaid title="Fluxo de autenticação do SDK Node.js com o MinIO local">
{`
flowchart LR
    App["Backend Node.js"] -->|"1. S3Client(endpoint: 'http://localhost:9000')"| MinIO[("MinIO Engine")]
    App -->|"2. PutObjectCommand(Bucket, Key, Body)"| MinIO
    MinIO -->|"3. Retorna ETag e status 200 OK"| App
`}
</Mermaid>

O exemplo abaixo demonstra como configurar o cliente S3 para conversar com o MinIO local:

```typescript
import { S3Client, PutObjectCommand, GetObjectCommand } from '@aws-sdk/client-s3';
import { getSignedUrl } from '@aws-sdk/s3-request-presigner';

// Configuração do cliente apontando para o MinIO local
const s3 = new S3Client({
  endpoint: 'http://localhost:9000',
  region: 'us-east-1',
  credentials: {
    accessKeyId: 'minioadmin',
    secretAccessKey: 'miniopassword123',
  },
  forcePathStyle: true, // Obrigatório para MinIO e endpoints locais
});
```

<Aside type="tip" title="Por que forcePathStyle é obrigatório?">
  Na AWS S3 pública, a URL costuma usar o estilo virtual host (`https://bucket-name.s3.amazonaws.com`). No MinIO local, o formato deve ser baseado em caminho (`http://localhost:9000/bucket-name/key`), o que é ativado pela flag `forcePathStyle: true`.
</Aside>

## Geração de URLs Pré-assinadas (Presigned URLs)

Para uploads de arquivos pesados (como vídeos ou PDFs), a melhor prática arquitetural é gerar uma **Presigned URL** no backend para que o frontend faça o upload diretamente no MinIO:

<Mermaid title="Arquitetura de upload direto com URL Pré-assinada">
{`
flowchart TD
    Client["Navegador / App Mobile"] -->|"1. POST /api/upload-request (Solicita permissão)"| API["API Backend"]
    API -->|"2. Gera Presigned URL (Válida por 15 min)"| S3["AWS SDK (@aws-sdk/s3-request-presigner)"]
    API -->|"3. Retorna { uploadUrl, key }"| Client
    Client -->|"4. PUT direto no MinIO com arquivo binário"| MinIO[("MinIO Storage")]
`}
</Mermaid>

Exemplo de geração da URL de upload no backend:

```typescript
// Gerar URL temporária para o frontend fazer upload diretamente
export async function generateUploadUrl(bucket: string, key: string): Promise<string> {
  const command = new PutObjectCommand({
    Bucket: bucket,
    Key: key,
    ContentType: 'image/png',
  });

  // URL expira automaticamente em 15 minutos (900 segundos)
  return await getSignedUrl(s3, command, { expiresIn: 900 });
}
```

## Perguntas de revisão

<details>
<summary>1. Qual é a vantagem do upload multipart (Multipart Upload) em arquivos grandes?</summary>
O *Multipart Upload* fatia arquivos gigantes (acima de 100 MB ou até 5 TB) em partes menores que são enviadas em paralelo. Se uma parte falhar por oscilação de rede, apenas essa fração é retransmitida, sem a necessidade de recomeçar o upload do arquivo inteiro do início.
</details>

<details>
<summary>2. Como o MinIO armazena os metadados de um objeto?</summary>
Os metadados (como `Content-Type`, data de criação e tags customizadas `x-amz-meta-*`) são armazenados de forma atômica junto com o cabeçalho do objeto no armazenamento persistente, sendo retornados instantaneamente na resposta HTTP das operações `HEAD` e `GET`.
</details>
