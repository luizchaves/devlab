## O schema

Três models e duas relações um-para-muitos:

```prisma title="prisma/schema.prisma" showLineNumbers {10-13,17,23}
generator client {
  provider = "prisma-client"
  output   = "../src/generated/prisma"
}

datasource db {
  provider = "sqlite"
}

model Investment {
  id         String   @id @default(cuid())
  name       String
  amount     Int
  interest   String
  createdAt  DateTime @default(now())
  dueDate    DateTime
  categoryId String
  category   Category @relation(fields: [categoryId], references: [id])
  brokerId   String
  broker     Broker   @relation(fields: [brokerId], references: [id])
}

model Category {
  id          String       @id @default(cuid())
  name        String
  color       String
  investments Investment[]
}

model Broker {
  id          String       @id @default(cuid())
  name        String
  investments Investment[]
}
```

## O client

Uma instância só, criada uma vez e importada por todos os models:

```ts title="src/database/prisma.ts" showLineNumbers {5-6}
import 'dotenv/config';
import { PrismaBetterSqlite3 } from '@prisma/adapter-better-sqlite3';
import { PrismaClient } from '@/generated/prisma/client.ts';

const adapter = new PrismaBetterSqlite3({ url: `${process.env.DATABASE_URL}` });
const prisma = new PrismaClient({ adapter });

export { prisma };
```

<Aside type="note" title="Prisma 7 exige um adapter">
  A partir da versão 7, a `url` sai do `schema.prisma` e vai para o `prisma.config.ts`, e o
  client passa a receber um *driver adapter*. Em Prisma 6, `new PrismaClient()` sem
  argumentos ainda funciona.
</Aside>

## O model, antes e depois

O contrato das funções não muda — `create`, `read`, `readById`, `update`, `remove`. O corpo,
sim:

```ts title="src/models/Investment.ts" del={1-8} ins={10-16}
const sql = `
  SELECT id, name, value
  FROM investments
  WHERE id = ?
`;

const investment = await db.get(sql, [id]);

async function readById(id: string): Promise<Investment> {
  return prisma.investment.findUniqueOrThrow({
    where: { id },
    include,
  }) as Promise<Investment>;
}
```

A definição do `include` fica em uma constante do próprio model, para que a entidade saia
com o mesmo formato em todas as rotas:

```ts title="src/models/Investment.ts" showLineNumbers {1-4}
const include = {
  category: true,
  broker: true,
};
```

## Migrations

```bash title="Terminal"
npx prisma migrate dev --name init
npx prisma generate
npx prisma studio
```

| Comando                 | Quando usar                                   |
| ----------------------- | --------------------------------------------- |
| `migrate dev`           | ao alterar o schema, em desenvolvimento        |
| `migrate deploy`        | em produção — aplica sem gerar nem resetar     |
| `migrate reset`         | recomeçar do zero (**apaga tudo**)             |
| `db seed`               | popular com os dados iniciais                  |
| `studio`                | inspecionar visualmente                        |

## O diff que importa

```bash title="Terminal"
git diff typescript prisma-js -- classroom/back-end/investment-api/src/models
git diff typescript prisma-js -- classroom/back-end/investment-api/src/controllers
```

O primeiro diff é grande: os models foram reescritos. O segundo é quase vazio — os
controllers seguiram chamando as mesmas funções. É a terceira vez no projeto que a camada de
dados é trocada sem que as camadas acima percebam.

<Aside type="caution" title="`src/generated/` não vai para o Git">
  O client é gerado a partir do schema por `prisma generate`, que roda no `postinstall`.
  Versioná-lo cria conflitos enormes e não acrescenta nada.
</Aside>
