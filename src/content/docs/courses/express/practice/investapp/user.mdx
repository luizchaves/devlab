Etapa **5 de 6** · Nível **Avançado** · TypeScript · Prisma · `node:crypto`

O InvestApp deixa de ser de uma pessoa só. Esta etapa acrescenta o model `User`, liga cada
investimento a um dono e guarda a senha do único jeito aceitável: como hash.

## A migration

Duas mudanças no schema: um model novo e uma chave estrangeira em `Investment`.

```prisma title="prisma/schema.prisma" showLineNumbers {2-3,10-16}
model Investment {
  userId     String
  user       User     @relation(fields: [userId], references: [id])
  categoryId String
  category   Category @relation(fields: [categoryId], references: [id])
  brokerId   String
  broker     Broker   @relation(fields: [brokerId], references: [id])
}

model User {
  id          String       @id @default(cuid())
  name        String
  email       String       @unique
  password    String
  investments Investment[]
}
```

<Aside type="caution" title="`userId` obrigatório em uma tabela com dados">
  Acrescentar uma coluna `NOT NULL` sem valor padrão quebra a migration se já houver
  investimentos. As saídas são: tornar o campo opcional, definir um usuário padrão na
  migration, ou resetar o banco de desenvolvimento — que é o que esta etapa faz.
</Aside>

## O hash da senha

A senha é derivada dentro do model, para que **toda** origem que crie usuário — a rota, o
seed, um script — passe pelo mesmo caminho:

```ts title="src/models/User.ts" showLineNumbers {1,5,10}
import { hashPassword } from '@/utils/password.ts';

const select = { id: true, name: true, email: true };

async function create({ id, name, email, password }: UserInput): Promise<User> {
  if (name && email && password) {
    return prisma.user.create({
      data: { ...(id ? { id } : {}), name, email, password: hashPassword(password) },
      // A senha nem sai do banco: o select não a inclui.
      select,
    });
  }

  throw new Error('Unable to create user');
}
```

E a implementação do hash é a mesma da aula de [Senhas e Hash](../../../auth/passwords/):
Argon2id do `node:crypto`, no formato PHC, sem `bcrypt`.

```ts title="src/utils/password.ts" showLineNumbers {1,4}
import { argon2Sync, randomBytes, timingSafeEqual } from 'node:crypto';

export function hashPassword(password: string): string {
  const salt = randomBytes(16);
  const hash = argon2Sync('argon2id', {
    message: password,
    nonce: salt,
    memory: 65536,
    passes: 3,
    parallelism: 4,
    tagLength: 64,
  });

  return `$argon2id$v=19$m=65536,t=3,p=4$${toBase64(salt)}$${toBase64(hash)}`;
}
```

<Aside type="danger" title="A exceção tem nome próprio">
  Só uma função devolve o hash — `readByEmailWithPassword`, usada exclusivamente pelo login
  da próxima etapa. Todas as demais usam `select`, e a senha simplesmente não existe no
  resultado.
</Aside>

## A rota

O cadastro é público; as demais operações sobre usuários, não:

```ts title="src/routes/users.routes.ts" showLineNumbers {3}
const router = Router();

router.post('/users', requireJson, UserController.create);
router.get('/users', UserController.read);
router.get('/users/:id', UserController.readById);
router.put('/users/:id', requireJson, UserController.update);
router.delete('/users/:id', UserController.remove);

export default router;
```

## O diff que importa

```bash title="Terminal"
git diff prisma-js create-user -- classroom/back-end/investment-api
```

Aparecem três coisas: a migration do `User`, o `utils/password.ts` e a camada de usuário
(model, controller, router, tipo). Nenhuma linha de autenticação ainda — cadastrar e
autenticar são problemas diferentes, e esta etapa resolve só o primeiro.

## Conceitos abordados

- Migration que acrescenta um model e uma chave estrangeira
- Hash de senha com Argon2id nativo, no formato PHC
- `select` do Prisma impedindo a senha de sair do banco
- Rota pública de cadastro e o restante protegido
- Formulário de cadastro consumindo a API
