## `HttpError`

A classe que faz o controller escolher o status sem tocar em `res`:

```ts title="src/errors/HttpError.ts" showLineNumbers
class HttpError extends Error {
  code: number;

  constructor(message: string, code: number = 400) {
    super(message);
    this.code = code;
  }
}

export default HttpError;
```

E o middleware que a traduz em resposta — o único lugar da aplicação que monta um erro:

```ts title="src/middlewares/errorHandlers.ts" showLineNumbers {2,6}
export const errorHandler = (err: Error, _req: Request, res: Response, _next: NextFunction) => {
  if (err instanceof HttpError) {
    return res.status(err.code).json({ error: err.message });
  }

  console.error(err.stack);
  res.status(500).json({ error: 'Internal Server Error' });
};
```

## O router e o controller

O router passa a listar apenas caminhos e middlewares:

```ts title="src/routes/investments.routes.ts" showLineNumbers {3,6}
const router = Router();

router.post('/investments', requireJson, InvestmentController.create);
router.get('/investments', InvestmentController.read);
router.get('/investments/:id', InvestmentController.readById);
router.put('/investments/:id', requireJson, InvestmentController.update);
router.delete('/investments/:id', InvestmentController.remove);

export default router;
```

E o controller cuida de HTTP, delegando o resto:

```ts title="src/controllers/investments.controller.ts" showLineNumbers {4,8}
async function readById(req: Request<{ id: string }>, res: Response) {
  try {
    const { id } = req.params;
    const investment = await Investment.readById(id);

    res.json(investment);
  } catch (error) {
    throw new HttpError('Unable to find investment', 400);
  }
}
```

<Aside type="note" title="O `try`/`catch` aqui traduz, não repassa">
  No Express 5 o erro de uma função `async` chega sozinho ao `errorHandler`. O `catch` existe
  para converter o erro do banco — que traria detalhes internos — em um `HttpError` com
  mensagem controlada.
</Aside>

## O `tsconfig.json`

Esta etapa usa o alias `@/` com `tsx`, alternativa aos *subpath imports* do guia:

```json title="tsconfig.json" showLineNumbers {6,10-13}
{
  "compilerOptions": {
    "module": "ESNext",
    "moduleResolution": "bundler",
    "target": "ES2023",
    "strict": true,
    "verbatimModuleSyntax": true,
    "allowImportingTsExtensions": true,
    "noEmit": true,
    "baseUrl": "./src",
    "paths": {
      "@/*": ["./*"]
    }
  },
  "include": ["src/**/*"]
}
```

<Aside type="caution" title="`paths` exige `tsx` para executar">
  O Node não lê `paths` do `tsconfig.json`: `import '@/models/Investment.ts'` quebraria em
  `node src/index.ts`. Por isso o script `dev` desta etapa usa `tsx watch`. A alternativa sem
  dependência é o `#` do `package.json`, mostrado em
  [TypeScript no Express](../../../basics/typescript/).
</Aside>

- Migração de JavaScript para TypeScript em um projeto existente
- Separação em routes, controllers, models, middlewares e errors
- `HttpError` e tratamento de erro centralizado
- `notFound` antes do `errorHandler`
- Middleware de `Content-Type`
- Tipos do domínio em `src/types/*.d.ts`
