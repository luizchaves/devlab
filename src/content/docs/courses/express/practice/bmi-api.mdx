## Comparação

| Origem      | Objeto       | Método | Rota                                 | Aparece no log de acesso? |
| ----------- | ------------ | ------ | ------------------------------------ | ------------------------- |
| Query param | `req.query`  | GET    | `/bmi?weight=100&height=1.5`         | sim                        |
| Route param | `req.params` | GET    | `/bmi/weight/100/height/1.5`         | sim                        |
| Body param  | `req.body`   | POST   | `/bmi`                               | não                        |

<Aside type="tip" title="A regra que sai daqui">
  O caminho identifica **qual** recurso; a query **modifica** a consulta; o corpo **envia**
  dados. Peso e altura são dados de entrada — o `POST` com corpo é a modelagem mais honesta
  das três.
</Aside>

<Aside type="caution" title="Tudo que vem da URL é string">
  `req.query.weight` e `req.params.weight` chegam como `'100'`. Sem o `Number()`, a conta
  vira concatenação e o resultado é `NaN` — silenciosamente.
</Aside>

## Executando

<Steps>

1. Entre em uma das variantes:

   ```bash title="Terminal"
   cd examples/courses/express/projects/bmi-query-param
   ```

2. Instale e suba:

   ```bash title="Terminal"
   npm install && npm start
   ```

3. Teste pelo `requests.http` ou pelo `curl`:

   ```bash title="Terminal"
   curl "http://localhost:3000/bmi?weight=100&height=1.5"
   ```

</Steps>

## Conceitos abordados

- `req.query`, `req.params` e `req.body` no mesmo problema
- `express.json()` como requisito do corpo JSON
- Conversão de string para número na entrada
- Separação entre a função de domínio e a camada HTTP

  A aula correspondente é [Rotas](../../basics/routes/).
</Aside>

## Desafio

Reúna as três variantes em um único projeto e acrescente validação: responda `422` quando
peso ou altura não forem números positivos, com uma mensagem por campo. Compare o esforço de
validar `req.query` e `req.body` — e por que o segundo é mais simples.
