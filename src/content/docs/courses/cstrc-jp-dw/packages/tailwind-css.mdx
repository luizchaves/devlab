Tailwind CSS é um framework CSS **utility-first**. A ideia não é começar por
componentes prontos, como acontece com Bootstrap, mas por classes pequenas que
representam decisões de CSS: `flex`, `gap-4`, `px-6`, `text-sm`, `rounded-lg`,
`bg-white`, `hover:bg-zinc-800` e `md:grid-cols-2`.

Isso muda a forma de construir a interface. Em vez de escrever primeiro uma classe
própria como `.card-produto` e depois preencher essa classe no CSS, o desenvolvedor
compõe a aparência diretamente no HTML usando um vocabulário padronizado.

## Objetivo

Entender a proposta do Tailwind CSS, ler classes utilitárias com segurança,
reconhecer variantes de estado e responsividade, entender o papel do tema e saber
quando extrair repetições para componentes ou CSS próprio.

costuma fazer. Em vez de "qual componente pronto eu uso?", a pergunta passa a ser
"quais decisões visuais este elemento precisa ter?".

## Anatomia das Classes

Uma classe Tailwind costuma ter uma leitura curta: propriedade, escala e, às vezes,
uma condição. Depois de entender esse padrão, fica mais fácil prever classes novas.

| Classe | Leitura | CSS aproximado |
| ------ | ------- | -------------- |
| `p-4` | padding na escala 4 | `padding` |
| `mt-6` | margem superior na escala 6 | `margin-top` |
| `flex` | elemento vira flex container | `display: flex` |
| `grid-cols-3` | grid com três colunas | `grid-template-columns` |
| `text-sm` | texto pequeno | `font-size` |
| `font-bold` | texto em negrito | `font-weight` |
| `bg-zinc-950` | fundo zinc na escala 950 | `background-color` |
| `rounded-md` | raio médio nas bordas | `border-radius` |
| `shadow-sm` | sombra pequena | `box-shadow` |
| `hover:bg-zinc-800` | fundo muda no hover | `:hover` |
| `md:grid-cols-3` | três colunas a partir de `md` | `@media` |

<Aside type="tip" title="Não é estilo inline">
  Tailwind parece "CSS no HTML", mas não é a mesma coisa que escrever `style=""`.
  As classes apontam para um sistema de utilitários e tokens. Isso mantém escala,
  nomes e responsividade consistentes no projeto.
</Aside>

## Cores e Tamanhos

Boa parte da fluência em Tailwind vem de reconhecer suas escalas. Em vez de escrever
um valor exato como `color: #18181b` ou `padding: 16px`, você usa nomes que apontam
para a paleta e para os tokens do framework.

### Cores

As cores seguem o formato `propriedade-cor-escala`. Em `bg-zinc-950`, `bg` indica
fundo, `zinc` é a família de cor e `950` é a intensidade. Números menores costumam
ser mais claros; números maiores costumam ser mais escuros.

| Classe | Leitura | Uso comum |
| ------ | ------- | --------- |
| `bg-white` | fundo branco | superfície principal |
| `bg-zinc-950` | fundo zinc muito escuro | header, footer ou botão escuro |
| `text-zinc-600` | texto zinc intermediário | texto secundário |
| `text-emerald-700` | texto emerald forte | estado positivo ou destaque |
| `border-zinc-200` | borda zinc clara | divisória discreta |
| `ring-cyan-300` | anel de foco cyan claro | foco visual em campo ou botão |

| Prefixo | Propriedade afetada |
| ------- | ------------------- |
| `bg-*` | cor de fundo |
| `text-*` | cor do texto |
| `border-*` | cor da borda |
| `ring-*` | cor do anel de foco |
| `fill-*` | preenchimento de SVG |
| `stroke-*` | traço de SVG |

<Aside type="note" title="Nome visual não é nome semântico">
  `emerald` descreve uma família visual de cor, não necessariamente "sucesso".
  Se o projeto precisa de nomes semânticos, como marca, perigo ou aviso, faz sentido
  declarar tokens próprios em `@theme`, por exemplo `--color-brand-500`.
</Aside>

### Tamanhos

Tamanhos também seguem escalas. Algumas classes usam números, como `p-4`, `gap-6`
e `size-10`; outras usam nomes, como `text-sm`, `rounded-lg`, `shadow-sm` e
`max-w-4xl`.

| Grupo | Exemplos | Leitura |
| ----- | -------- | ------- |
| Espaçamento | `p-4`, `px-6`, `mt-8`, `gap-3` | padding, margem e distância entre elementos |
| Largura e altura | `w-full`, `h-12`, `size-10`, `max-w-4xl` | dimensões e limite de largura |
| Tipografia | `text-xs`, `text-sm`, `text-base`, `text-2xl` | tamanho do texto |
| Borda | `rounded-sm`, `rounded-md`, `rounded-lg`, `rounded-full` | raio da borda |
| Sombra | `shadow-xs`, `shadow-sm`, `shadow-md`, `shadow-lg` | intensidade da sombra |

Por padrão, a escala numérica de espaçamento parte de uma unidade pequena. Assim,
`p-2`, `p-4` e `p-8` não são valores aleatórios: eles fazem parte de uma progressão
que ajuda a manter proporção entre seções, cards, botões e formulários.

<Aside type="tip" title="Comece pela escala, ajuste depois">
  Antes de usar valores arbitrários como `w-[37px]` ou `mt-[13px]`, tente resolver
  com a escala do Tailwind. Valores arbitrários são úteis, mas perdem parte da
  consistência quando viram a primeira opção.
</Aside>

## Variantes

Variantes são prefixos que aplicam uma classe apenas quando uma condição acontece.
Elas são uma parte central do Tailwind porque permitem resolver estados sem sair do
HTML.

| Variante | Exemplo | Quando aplica |
| -------- | ------- | ------------- |
| `hover:` | `hover:bg-zinc-800` | Quando o usuário passa o cursor |
| `focus:` | `focus:ring-2` | Quando o elemento recebe foco |
| `disabled:` | `disabled:opacity-50` | Quando um campo ou botão está desabilitado |
| `md:` | `md:grid-cols-3` | A partir do breakpoint `md` |
| `dark:` | `dark:bg-zinc-950` | Quando o tema escuro está ativo |
| `group-hover:` | `group-hover:text-teal-700` | Quando o elemento pai com `group` está em hover |

Uma classe como `hover:bg-zinc-800` não define o fundo padrão do botão. Ela define
apenas o que muda no hover. Por isso, o padrão e o estado costumam aparecer juntos:
`bg-zinc-950 hover:bg-zinc-800`.

## Responsividade

Tailwind é mobile first. Classes sem prefixo valem para todos os tamanhos; classes
com `sm:`, `md:`, `lg:`, `xl:` ou `2xl:` passam a valer a partir da largura
indicada.

/>

<SourceCode
  path="examples/dw/codes/package/tailwind-css/responsive-grid/index.html"
  title="Grid responsivo"
  showLineNumbers
  mark={[
    'class="mb-8 grid grid-cols-3 gap-3"',
    'class="grid grid-cols-1 gap-3 md:grid-cols-3"',
    'class="rounded-md bg-white p-4 shadow-sm"',
  ]}
/>

No exemplo, a primeira grade usa `grid-cols-3`, então tenta manter três colunas em
qualquer largura. A segunda começa com `grid-cols-1`, adequada para celular, e só
vira três colunas a partir do breakpoint `md`.

| Prefixo | Largura mínima | CSS gerado |
| ------- | -------------- | ---------- |
| `sm` | 40rem (640px) | `@media (width >= 40rem)` |
| `md` | 48rem (768px) | `@media (width >= 48rem)` |
| `lg` | 64rem (1024px) | `@media (width >= 64rem)` |
| `xl` | 80rem (1280px) | `@media (width >= 80rem)` |
| `2xl` | 96rem (1536px) | `@media (width >= 96rem)` |

<Aside type="tip" title="Leia da base para a exceção">
  `grid grid-cols-1 md:grid-cols-3` significa: é grid, começa com uma coluna e,
  em telas médias ou maiores, passa para três colunas.
</Aside>

## Tema e Tokens

Tailwind usa tokens de design para formar muitos nomes de classe. Cores, tamanhos,
fontes, sombras, raios de borda e breakpoints seguem escalas. Por isso aparecem
nomes como `zinc-950`, `text-sm`, `rounded-lg`, `shadow-sm` e `max-w-4xl`.

Na versão 4, a customização pode ser feita com `@theme`. Quando você declara um
token em um namespace reconhecido, Tailwind passa a gerar utilitários relacionados
a ele.

```css title="src/style.css"
@import "tailwindcss";

@theme {
  --color-brand-500: oklch(0.72 0.11 178);
  --font-display: "Inter", sans-serif;
  --breakpoint-3xl: 120rem;
}
```

Depois disso, classes como `bg-brand-500`, `text-brand-500`, `font-display` e
`3xl:grid-cols-6` passam a fazer parte do vocabulário do projeto.

<Aside type="note" title="Tema não é só variável CSS comum">
  Variáveis em `@theme` não servem apenas para guardar valores. Elas também informam
  ao Tailwind quais utilitários ou variantes devem existir. Para variáveis que não
  precisam gerar classes, `:root` ainda pode fazer sentido.
</Aside>

## Quando Extrair

No começo, escrever várias classes no HTML é o fluxo normal do Tailwind. A extração
entra quando existe repetição real.

| Situação | Caminho comum |
| -------- | ------------- |
| Um bloco aparece uma vez | Manter classes direto no HTML |
| O mesmo card aparece em várias telas | Criar componente, partial ou include |
| Uma integração externa exige seletor próprio | Criar CSS em `@layer components` |
| Um utilitário não existe no Tailwind | Criar utilitário com `@utility` |
| O valor pertence à identidade visual | Criar token em `@theme` |

```css title="src/style.css"
@import "tailwindcss";

@layer components {
  .product-card {
    border-radius: var(--radius-lg);
    background-color: var(--color-white);
    box-shadow: var(--shadow-sm);
  }
}
```

<Aside type="tip" title="Extraia por repetição, não por costume">
  Em Tailwind, criar uma classe própria cedo demais pode esconder justamente o
  benefício da ferramenta: deixar as decisões visuais explícitas no ponto em que o
  HTML é escrito.
</Aside>

## Preflight

Além dos utilitários, Tailwind inclui uma base chamada
[Preflight](https://tailwindcss.com/docs/preflight). Ela ajusta estilos padrão do
navegador para reduzir diferenças iniciais entre elementos HTML, como margens,
bordas, tipografia e `box-sizing`.

Preflight não transforma HTML em componentes prontos. Ele apenas cria uma base mais
previsível para que os utilitários funcionem de maneira consistente.

## Tailwind e Bootstrap

A comparação com Bootstrap ajuda a localizar a diferença de proposta, mas não deve
guiar a estrutura da aula. Bootstrap começa por componentes prontos; Tailwind começa
por utilitários e por um sistema de tokens.

| Critério | Bootstrap | Tailwind CSS |
| -------- | --------- | ------------ |
| Ponto de partida | Componentes prontos | Utilitários e tokens |
| Aparência inicial | Visual pronto de biblioteca | Visual definido pela composição |
| Customização | Adapta padrões existentes | Compõe padrões próprios desde o início |
| JavaScript | Inclui comportamento para alguns componentes | Não fornece comportamento interativo pronto |
| Reutilização | Classes de componente | Componentes/templates criados no projeto |

## Quando Usar

Tailwind é útil quando o projeto precisa de identidade visual própria, quando a
equipe quer consistência por escala e quando a interface é construída com
componentes, templates ou includes.

Ele pode ser menos adequado quando a equipe precisa de componentes prontos sem
desenhar a interface, ou quando o projeto é uma página HTML muito pequena e sem
build. Nesses casos, Bootstrap ou CSS simples podem ser mais diretos.

## Perguntas de revisão

**1. O que significa dizer que Tailwind é utility-first?**

<details>
  <summary>Possível resposta</summary>

  Significa que a construção visual parte de classes pequenas e focadas, em vez de
  classes grandes de componente. Cada utilitário representa uma decisão visual
  direta, como espaçamento, cor, display, tamanho de texto ou borda.
</details>

**2. Por que Tailwind não é a mesma coisa que usar `style=""`?**

<details>
  <summary>Possível resposta</summary>

  Porque as classes do Tailwind vêm de um sistema compartilhado de utilitários,
  tokens, variantes e breakpoints. O estilo inline aplica valores soltos diretamente
  no elemento, sem aproveitar esse vocabulário comum.
</details>

**3. Qual o papel das variantes?**

<details>
  <summary>Possível resposta</summary>

  Variantes aplicam uma classe apenas sob uma condição, como hover, foco, tema
  escuro ou largura mínima de tela. Exemplos: `hover:bg-zinc-800`,
  `focus:ring-2` e `md:grid-cols-3`.
</details>

**4. O que significa `md:grid-cols-3`?**

<details>
  <summary>Possível resposta</summary>

  Significa que a grade passa a ter três colunas a partir do breakpoint `md`, que
  no padrão do Tailwind começa em 48rem, ou 768px.
</details>

**5. Para que serve `@theme`?**

<details>
  <summary>Possível resposta</summary>

  `@theme` declara tokens que podem gerar novas classes e variantes no Tailwind,
  como cores, fontes, sombras, espaçamentos e breakpoints.
</details>

**6. Por que classes dinâmicas podem causar problema?**

<details>
  <summary>Possível resposta</summary>

  Porque o Tailwind gera CSS a partir das classes que consegue detectar nos arquivos
  do projeto. Se o nome da classe é montado por concatenação, o build pode não
  enxergar o nome completo e deixar de gerar o CSS necessário.
</details>

**7. Quando faz sentido extrair um trecho para componente ou CSS próprio?**

<details>
  <summary>Possível resposta</summary>

  Quando existe repetição real, integração externa ou um padrão do projeto que
  precisa ser reutilizado. A extração deve reduzir manutenção sem esconder
  desnecessariamente as decisões visuais.
</details>
