O npm é o registro de pacotes do ecossistema JavaScript e também o gerenciador que
acompanha o Node.js. Nesta disciplina usamos o **pnpm**, que é compatível com o mesmo
registro e reaproveita pacotes entre projetos.

## Criando um projeto

<Steps>

1. Crie o diretório e inicialize o `package.json`:

   ```bash
   mkdir minha-api
   cd minha-api
   npm init -y
   ```

2. Ative os ES Modules adicionando `"type": "module"`:

   ```json title="package.json" ins={4}
   {
     "name": "minha-api",
     "version": "1.0.0",
     "type": "module"
   }
   ```

3. Instale a primeira dependência:

   <PackageManagerTabs package="express" />

</Steps>

## Dependências vs. devDependencies

`dependencies` são necessárias para a aplicação rodar em produção.
`devDependencies` só existem durante o desenvolvimento (ferramentas, CLIs, testes).

<PackageManagerTabs package="prisma" dev />

## Scripts

Scripts dão nomes curtos a comandos longos e documentam como o projeto roda:

```json title="package.json" {3-4}
{
  "scripts": {
    "dev": "node --watch src/server.js",
    "start": "node src/server.js"
  }
}
```

## Lockfile

O arquivo de lock (`package-lock.json`, `pnpm-lock.yaml` ou `yarn.lock`) registra a
versão exata de cada pacote instalado.

<Aside type="caution" title="Sempre versione o lockfile">
  Ele é o que garante que a sua máquina, a do colega e o servidor de deploy instalem
  exatamente as mesmas versões. Já a pasta `node_modules` nunca vai para o Git.
</Aside>

## Versionamento semântico

```text
express: ^5.2.1
         │ │ │ └─ patch: correções
         │ │ └─── minor: novidades compatíveis
         │ └───── major: quebra compatibilidade
         └─────── aceita minor e patch mais recentes
```
