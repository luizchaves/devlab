A disciplina começa pelo que sustenta tudo o que vem depois: entender a Web como
plataforma e saber descrever conteúdo com HTML. Antes de escrever qualquer estilo ou
qualquer linha de JavaScript, é preciso que a página **signifique** alguma coisa —
que um título seja um título, uma lista seja uma lista e um formulário seja um
formulário.

Esse cuidado não é formalidade. Marcação correta é o que permite que um leitor de
tela navegue a página, que um buscador entenda o conteúdo e que o CSS e o JavaScript
tenham onde se apoiar. Todo problema de acessibilidade que aparece mais adiante
costuma nascer aqui.

## O que esperar deste tópico

Você vai partir da origem da Web no CERN e do papel de HTTP, URL e HTML, comparar o
HTML com outras linguagens de marcação, e então percorrer os elementos que
estruturam uma página real: texto, listas, links, imagens, tabelas, seções
semânticas e formulários.

Ao final, você deve conseguir escrever uma página completa do zero, validá-la sem
erros no validador do W3C e justificar a escolha de cada elemento pelo significado
do conteúdo — não pela aparência.

<Aside type="tip" title="Aparência vem depois">
  Se em algum momento você escolher uma tag porque ela "fica maior" ou "fica em
  negrito", pare: essa decisão é do CSS, o próximo tópico. Aqui a pergunta é sempre
  *o que este conteúdo é*.
</Aside>
