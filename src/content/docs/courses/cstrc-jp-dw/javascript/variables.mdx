Esta aula começa pelos valores que JavaScript consegue representar e depois mostra
como dar nome a esses valores com variáveis. Essa separação ajuda a entender uma
ideia central da linguagem: o tipo está no valor, não no nome da variável.

## Objetivo

Reconhecer os principais valores e tipos de JavaScript, observar tipos com
`typeof`, entender conversões comuns da linguagem e declarar variáveis com `const`,
`let` e `var`, considerando inicialização, reassociação, escopo e boas práticas de
nomeação.

## Valores e tipos

JavaScript possui valores primitivos e objetos. Variáveis não têm tipo fixo; o tipo
está no valor armazenado naquele momento.

| Categoria | Tipo | Exemplos |
| --------- | ---- | -------- |
| Primitivo | `undefined` | `undefined` |
| Primitivo | `null` | `null` |
| Primitivo | `boolean` | `true`, `false` |
| Primitivo | `number` | `42`, `-15`, `3.14`, `314e-2`, `0b1111`, `0o17`, `0xf`, `15_000` |
| Primitivo | `bigint` | `42n`, `9007199254740991n` |
| Primitivo | `string` | `"Alice"`, `'DW'`, `` `Olá, ${name}` `` |
| Primitivo | `symbol` | `Symbol("id")` |
| Objeto | `object` | `{ id: 1010, name: "Fulano" }`, `[1, 2, 3]`, `new Date()`, `/dw/i` |
| Objeto especial | `function` | `function sum(a, b) { return a + b; }` |

O bloco a seguir mostra valores primitivos sendo enviados diretamente para o
console, sem depender de variáveis.

```js title="Valores primitivos"
console.log(undefined); // undefined
console.log(null); // null
console.log(true); // true
console.log(false); // false
console.log("Programacao para Web 2"); // Programacao para Web 2
console.log(`Hello, ${1 + 1}`); // Hello, 2
console.log(42); // 42
console.log(42n); // 42n
console.log(Symbol("id")); // Symbol(id)
```

Já os objetos conseguem agrupar vários valores, comportamentos ou estruturas em uma
única representação.

```js title="Valores objeto"
console.log([]); // []
console.log([1, 2, 3]); // [1, 2, 3]
console.log([1, , 3]); // [1, <1 empty item>, 3]
console.log([1010, "Fulano", true, ["DW", "PW2"]]);
console.log({ id: 1010, name: "Fulano", active: true });
console.log(new Date("2026-08-12T00:00:00.000Z"));
console.log(/dw/i);
```

<Aside type="note" title="Objetos agrupam informação">
  Arrays, objetos, datas, expressões regulares e funções permitem representar
  estruturas mais ricas do que um único número, texto ou booleano.
</Aside>

Referência: [JavaScript data types and data structures | MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Data_structures).

### typeof

O operador `typeof` ajuda a observar o tipo de um valor em tempo de execução.

```js title="Inspecionando tipos"
console.log(typeof undefined); // "undefined"
console.log(typeof null); // "object"
console.log(typeof true); // "boolean"
console.log(typeof "Hello"); // "string"
console.log(typeof 42); // "number"
console.log(typeof 42n); // "bigint"
console.log(typeof Symbol("id")); // "symbol"
console.log(typeof []); // "object"
console.log(Array.isArray([])); // true
console.log(typeof {}); // "object"
console.log(typeof function () {}); // "function"
```

<Aside type="tip" title="Array precisa de teste próprio">
  Arrays retornam `"object"` com `typeof`. Para verificar se um valor é array, use
  `Array.isArray(value)`.
</Aside>

Referência: [`typeof` | MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/typeof).

### undefined e null

Com `typeof` apresentado, fica mais fácil observar dois valores especiais de
ausência. `undefined` costuma indicar ausência de inicialização. `null` costuma ser
usado para representar ausência intencional de valor.

```js title="Ausência de valor"
let notInitialized;
const empty = null;

console.log(notInitialized); // undefined
console.log(typeof notInitialized); // "undefined"
console.log(empty); // null
console.log(typeof empty); // "object"
```

<Aside type="note" title="typeof null">
  `typeof null` retorna `"object"` por uma decisão antiga da linguagem. Apesar
  desse retorno, `null` é tratado como valor primitivo.
</Aside>

<Aside type="tip" title="undefined, null e memória">
  No modelo da linguagem, `undefined` e `null` são valores primitivos. Uma variável
  declarada com `let notInitialized;` existe como nome no escopo e seu valor inicial
  é `undefined`. Já `null` é um valor atribuído intencionalmente, muitas vezes para
  indicar que ali não há objeto ou resultado. Detalhes como quantidade de memória,
  representação interna e otimizações dependem da engine JavaScript, como V8,
  SpiderMonkey ou JavaScriptCore; para a programação do dia a dia, pense neles como
  valores especiais de ausência.
</Aside>

### Booleanos e valores falsy

Quando JavaScript precisa avaliar um valor como condição, ele converte esse valor
para booleano. Alguns valores viram `false`; quase todo o restante vira `true`.

| Valor | Conversão |
| ----- | --------- |
| `false` | `false` |
| `0`, `-0`, `0n` | `false` |
| `""` | `false` |
| `null` | `false` |
| `undefined` | `false` |
| `NaN` | `false` |
| `[]`, `{}`, `"0"` | `true` |

A função `Boolean()` permite observar explicitamente como cada valor seria tratado
em uma condição.

```js title="Conversão booleana"
console.log(Boolean(false)); // false
console.log(Boolean(0)); // false
console.log(Boolean(0n)); // false
console.log(Boolean("")); // false
console.log(Boolean(null)); // false
console.log(Boolean(undefined)); // false
console.log(Boolean(NaN)); // false

console.log(Boolean([])); // true
console.log(Boolean({})); // true
console.log(Boolean("0")); // true
```

<Aside type="caution" title="Array vazio é truthy">
  Um array vazio `[]` e um objeto vazio `{}` são convertidos para `true`. Isso é
  diferente de linguagens em que coleções vazias podem ser tratadas como falsas.
</Aside>

### Números

O tipo `number` representa inteiros, decimais e valores especiais como `NaN`,
`Infinity` e `-Infinity`.

```js title="Formatos numéricos"
console.log(-15); // -15
console.log(15); // 15
console.log(0b1111); // 15
console.log(0o17); // 15
console.log(0xf); // 15
console.log(15_000); // 15000
console.log(3.14); // 3.14
console.log(314e-2); // 3.14
console.log(Math.PI); // 3.141592653589793
```

Além dos valores escritos diretamente no código, o objeto global `Number` expõe
constantes úteis para entender limites e precisão.

| Constante | Ideia principal |
| --------- | --------------- |
| [`Number.MAX_SAFE_INTEGER`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/MAX_SAFE_INTEGER) | Maior inteiro que pode ser representado com segurança |
| [`Number.MIN_SAFE_INTEGER`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/MIN_SAFE_INTEGER) | Menor inteiro que pode ser representado com segurança |
| [`Number.MAX_VALUE`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/MAX_VALUE) | Maior valor numérico positivo representável |
| [`Number.MIN_VALUE`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/MIN_VALUE) | Menor valor positivo representável acima de zero |
| [`Number.EPSILON`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/EPSILON) | Diferença mínima útil para comparar números próximos de `1` |

O limite seguro é importante quando o programa trabalha com identificadores,
contadores ou valores inteiros muito grandes.

```js title="Limites de Number"
console.log(Number.MAX_SAFE_INTEGER); // 9007199254740991, ou 2^53 - 1
console.log(Number.MIN_SAFE_INTEGER); // -9007199254740991, ou -(2^53 - 1)
console.log(Number.MAX_VALUE); // 1.7976931348623157e+308
console.log(Number.MIN_VALUE); // 5e-324
console.log(Number.EPSILON); // 2.220446049250313e-16
```

Depois do limite seguro, operações com inteiros podem perder precisão. Quando isso
for relevante, avalie `bigint` ou outra representação adequada ao domínio.

```js title="Inteiro fora do limite seguro"
console.log(Number.MAX_SAFE_INTEGER + 1); // 9007199254740992
console.log(Number.MAX_SAFE_INTEGER + 2); // 9007199254740992
console.log(Number.isSafeInteger(Number.MAX_SAFE_INTEGER)); // true
console.log(Number.isSafeInteger(Number.MAX_SAFE_INTEGER + 1)); // false
```

Mesmo fora do limite seguro, o valor continua sendo do tipo `number`. O sufixo `n`
aparece apenas quando o literal é escrito como `bigint`. O problema é que
comparações e operações inteiras próximas podem perder precisão.

```js title="Number fora do limite seguro não vira BigInt"
console.log(typeof 9007199254740992); // "number"
console.log(typeof 9007199254740992n); // "bigint"
console.log(Number.isSafeInteger(9007199254740992)); // false
console.log(9007199254740992 === 9007199254740993); // true
console.log(9007199254740992n === 9007199254740993n); // false
```

Essa igualdade parece errada, mas mostra que os dois inteiros ficaram
indistinguíveis nessa faixa quando representados como `number`. Com `bigint`, os
dois valores continuam distintos.

Para inteiros maiores que o limite seguro, JavaScript oferece `bigint`. Ele usa o
sufixo `n` ou a função `BigInt()`, mas não pode ser misturado diretamente com
valores do tipo `number` na mesma operação aritmética.

```js title="BigInt"
const big = 9007199254740991n;

console.log(typeof big); // "bigint"
console.log(big + 1n); // 9007199254740992n
console.log(big + BigInt(1)); // 9007199254740992n
console.log(big == 9007199254740991); // true
console.log(big === 9007199254740991); // false

// TypeError: Cannot mix BigInt and other types.
// console.log(big + 1);
```

`NaN` significa *Not a Number*, mas seu tipo ainda é `number`.

```js title="NaN"
console.log(0 / 0); // NaN
console.log(typeof (0 / 0)); // "number"
console.log(NaN === NaN); // false
console.log(Number.isNaN(0 / 0)); // true
```

Divisões por zero podem produzir infinitos:

```js title="Infinity"
console.log(1 / 0); // Infinity
console.log(-1 / 0); // -Infinity
```

Números decimais seguem aritmética de ponto flutuante, baseada na norma
[IEEE 754](https://standards.ieee.org/ieee/754/6210/). Por isso, alguns resultados
não são representados exatamente. O site
[0.30000000000000004.com](https://0.30000000000000004.com/) reúne exemplos desse
mesmo comportamento em várias linguagens e sugere formas de lidar com precisão e
arredondamento quando isso importa para o domínio do problema.

```js title="Precisão decimal"
console.log(0.1 + 0.2); // 0.30000000000000004
console.log(0.1 + 0.2 === 0.3); // false
```

<Aside type="tip" title="Precisão decimal">
  Quando o domínio exige comparação ou arredondamento cuidadoso, não assuma que uma
  soma decimal será representada exatamente. Defina uma tolerância para comparação,
  arredonde apenas nos pontos esperados da regra de negócio ou use uma estratégia de
  representação mais adequada ao problema.
</Aside>

<Aside type="caution" title="Valores monetários">
  Dinheiro parece decimal simples, mas `number` usa ponto flutuante binário. Isso
  pode gerar diferenças pequenas em somas, descontos, juros e comparações. Algumas
  formas recomendadas são: guardar valores em centavos como inteiros (`1099` para
  representar `R$ 10,99`), usar tipos decimais no banco de dados (`DECIMAL` ou
  `NUMERIC`) quando houver persistência, aplicar arredondamento em pontos bem
  definidos da regra de negócio e usar bibliotecas próprias para cálculo financeiro
  quando houver maior exigência de precisão. Para exibir o valor, formate apenas no
  final, por exemplo com `Intl.NumberFormat`.
</Aside>

Referências: [IEEE 754](https://standards.ieee.org/ieee/754/6210/) e
[Floating Point Math](https://0.30000000000000004.com/).

### Symbol

`symbol` cria identificadores únicos. Mesmo símbolos com a mesma descrição não são
iguais, exceto quando são recuperados pelo registro global com `Symbol.for()`.

```js title="Symbol"
const firstSymbol = Symbol("id");
const secondSymbol = Symbol("id");

console.log(typeof firstSymbol); // "symbol"
console.log(firstSymbol === secondSymbol); // false
console.log(Symbol.for("id") === Symbol.for("id")); // true
```

## Variáveis

Depois de entender os valores que JavaScript consegue representar, o próximo passo é
dar nomes a esses valores e controlar onde eles podem ser usados.

### Por que variáveis existem

Sem variáveis, o mesmo valor precisa ser repetido e o código perde intenção. Com uma
variável, o valor ganha nome e pode ser reutilizado.

```js title="Valor repetido"
console.log(79.9 * 0.9);
console.log(79.9 * 0.9 + 12);
```

Ao nomear os valores, o cálculo fica mais legível e cada parte passa a ter uma
responsabilidade clara.

```js title="Valor nomeado"
const price = 79.9;
const discountFactor = 0.9;
const shipping = 12;

const subtotal = price * discountFactor;
const total = subtotal + shipping;

console.log(subtotal); // 71.91
console.log(total); // 83.91
```

<Aside type="tip" title="Nome é parte do código">
  Um bom nome reduz a necessidade de comentário. `total`, `price` e `shipping`
  explicam melhor o cálculo do que nomes como `x`, `y` e `z`.
</Aside>

### Declaração de variáveis

Em JavaScript moderno, as declarações mais usadas são `const` e `let`. `var` ainda
aparece em códigos antigos, bibliotecas e materiais legados, mas deve ser evitado
como padrão em novos arquivos.

<CardGrid>
  <Card title="const" icon="lock">
    Declara uma associação que não pode ser trocada por outro valor. Use como padrão
    quando não houver reassociação.
  </Card>

  <Card title="let" icon="pencil">
    Declara uma variável que pode receber outro valor depois. Use quando o valor
    realmente precisa mudar.
  </Card>

  <Card title="var" icon="history">
    Declara variável com escopo de função e regras antigas de elevação. Leia quando
    aparecer, mas prefira `const` e `let`.
  </Card>
</CardGrid>

A tabela resume as diferenças práticas entre as três formas de declaração.

| Palavra-chave | Pode reassociar? | Escopo principal | Uso recomendado |
| -------------- | ---------------- | ---------------- | --------------- |
| `const` | Não | Bloco | Valor que não será trocado |
| `let` | Sim | Bloco | Valor que muda durante a execução |
| `var` | Sim | Função | Código legado |

No código, as três palavras-chave criam nomes que podem ser lidos depois pela
execução do programa.

```js title="Declarações"
var declaredWithVar = 10;
let declaredWithLet = 20;
const declaredWithConst = 30;

console.log(declaredWithVar); // 10
console.log(declaredWithLet); // 20
console.log(declaredWithConst); // 30
```

<Aside type="tip" title="Prefira const primeiro">
  Comece com `const`. Troque para `let` apenas quando o código precisar reassociar
  a variável. Esse hábito deixa claro quais valores mudam e quais permanecem
  estáveis.
</Aside>

### Identificadores

O nome da variável é chamado de identificador. Ele pode usar letras, dígitos,
`_` e `$`, mas não pode começar com dígito nem usar palavras reservadas como nome.

```js title="Identificadores válidos"
const _total = 10;
const $price = 19.9;
const fullName = "Fulano";

console.log(_total); // 10
console.log($price); // 19.9
console.log(fullName); // Fulano
```

Os exemplos abaixo estão comentados porque representam erros de sintaxe; se forem
descomentados, o arquivo deixa de executar.

```js title="Identificadores inválidos"
// SyntaxError: Invalid or unexpected token.
// const 2phase = "DW";

// SyntaxError: Identifier is a reserved word.
// const let = 10;

// O caractere - é operador de subtração, não parte do nome.
// const full-name = "Fulano";
```

<Aside type="note" title="Quando o erro acontece?">
  Nesta página aparecem erros de sintaxe, como `SyntaxError`, e erros em tempo de
  execução. Um `SyntaxError`, como em `const 2phase = "DW";`, impede o arquivo de
  ser interpretado. Já erros como `TypeError` e `RangeError` acontecem em tempo de
  execução: o código é sintaticamente válido, mas falha quando aquela linha roda. Em
  uma aplicação, um erro em tempo de execução pode interromper o fluxo atual se não
  for tratado com mecanismos como `try...catch`. Quando a execução parecer
  inconsistente ou incompleta, verifique sempre se o terminal ou o Console do
  navegador exibiu uma mensagem de erro ou *stack trace*. Normalmente eles indicam o
  tipo do erro, o arquivo, a linha e o caminho de chamadas que levou até a falha.

  ```js title="variables.js"
  const total = 1n + 1;
  console.log(total);
  ```

  ```txt title="Exemplo no console"
  TypeError: Cannot mix BigInt and other types
      at variables.js:1:17
  ```
</Aside>

Use nomes em `camelCase` para variáveis comuns e reserve nomes em maiúsculas para
constantes de configuração muito estáveis.

| Forma | Exemplo | Uso comum |
| ----- | ------- | --------- |
| `camelCase` | `userName`, `totalPrice` | Variáveis e funções |
| `PascalCase` | `UserProfile` | Classes e componentes |
| `UPPER_CASE` | `API_URL`, `MAX_ATTEMPTS` | Constantes de configuração |

### Inicialização

Declarar é criar o nome. Inicializar é atribuir o primeiro valor.

```js title="Declaração sem inicialização"
let value;

console.log(value); // undefined
console.log(typeof value); // "undefined"

value = 100;
value += 50;

console.log(value); // 150
```

`const` precisa ser inicializada na declaração.

```js title="const precisa de valor inicial"
const defaultChoice = "const";
console.log(defaultChoice); // "const"

// SyntaxError: Missing initializer in const declaration.
// const missingValue;
```

### Reassociação e mutação

Reassociar é fazer a variável apontar para outro valor. `var` e `let` permitem
isso; `const` não permite.

```js title="Reassociação"
var declaredWithVar = 10;
let declaredWithLet = 20;
const declaredWithConst = 30;

declaredWithVar = 100;
declaredWithLet = 200;

console.log(declaredWithVar); // 100
console.log(declaredWithLet); // 200

// TypeError: Assignment to constant variable.
// declaredWithConst = 300;
```

`const` impede a troca da associação, mas não transforma objetos e arrays em valores
imutáveis. O conteúdo interno ainda pode mudar.

```js title="Mutação de array declarado com const"
const values = [];

values.push("A");
values.push("B");

console.log(values); // ["A", "B"]

// TypeError: Assignment to constant variable.
// values = [1, 2];
```

O mesmo vale para objetos: a variável continua apontando para o mesmo objeto, mas
uma propriedade interna pode ser modificada.

```js title="Mutação de objeto declarado com const"
const user = { name: "Alice" };

user.name = "Bob";

console.log(user); // { name: "Bob" }
```

<Aside type="caution" title="const não significa imutável">
  `const` protege a variável contra reassociação. Para trabalhar com objetos
  realmente imutáveis, é necessário adotar outras técnicas e padrões de código.
</Aside>

### Redeclaração

`var` permite declarar novamente o mesmo nome no mesmo escopo. `let` e `const`
evitam isso.

```js title="Redeclaração com var"
var course = "DW";
var course = "Desenvolvimento Web";

console.log(course); // "Desenvolvimento Web"
```

Com `let` e `const`, a tentativa de repetir o mesmo nome no mesmo escopo é bloqueada
antes da execução.

```js title="Redeclaração bloqueada"
// SyntaxError: Identifier 'semester' has already been declared.
// let semester = "2026.2";
// let semester = "2027.1";

// SyntaxError: Identifier 'number' has already been declared.
// let number = 10;
// var number = 20;
```

### Escopo

Escopo define onde uma variável pode ser acessada. `let` e `const` respeitam escopo
de bloco, ou seja, o trecho entre `{` e `}`.

```js title="Escopo de bloco"
let semester = "2026.2";
console.log(semester); // "2026.2"

if (true) {
  let semester = "inside block";
  const period = "morning";

  console.log(semester); // "inside block"
  console.log(period); // "morning"
}

console.log(semester); // "2026.2"
```

`var` tem escopo de função. Por isso, uma variável declarada dentro de um bloco pode
continuar acessível fora dele quando está na mesma função. Fora da função, ela não
fica disponível.

```js title="Escopo de função com var"
function testBlockScope() {
  if (true) {
    var functionScoped = 1;
    let blockScoped = 2;

    console.log(blockScoped); // 2
  }

  console.log(functionScoped); // 1

  // ReferenceError: blockScoped is not defined.
  // console.log(blockScoped);
}

testBlockScope();

// ReferenceError: functionScoped is not defined.
// console.log(functionScoped);
```

O mesmo vale para `let` e `const`: variáveis declaradas dentro de uma função não
ficam disponíveis fora dela.

```js title="Escopo de função"
function greeting() {
  const message = "Hello";
  console.log(message); // "Hello"
}

greeting();

// ReferenceError: message is not defined.
// console.log(message);
```

### Hoisting e zona morta temporal

Declarações são processadas antes da execução do código, comportamento chamado de
*hoisting*. Com `var`, a variável existe antes da linha de declaração, mas começa
como `undefined`.

```js title="Hoisting com var"
console.log(hoistedVar); // undefined

var hoistedVar = 10;

console.log(hoistedVar); // 10
```

Com `let` e `const`, acessar a variável antes da declaração gera erro por causa da
*Temporal Dead Zone*.

```js title="Temporal Dead Zone"
// ReferenceError: Cannot access 'tdzLet' before initialization.
// console.log(tdzLet);
// let tdzLet = 10;

// ReferenceError: Cannot access 'tdzConst' before initialization.
// console.log(tdzConst);
// const tdzConst = 10;
```

<Aside type="tip" title="Declare antes de usar">
  Mesmo conhecendo *hoisting*, escreva o código na ordem de leitura: declare a
  variável antes de acessar seu valor.
</Aside>

### Globais implícitas

Quando uma atribuição é feita sem declaração, JavaScript pode criar uma variável
global implícita em scripts não estritos. Esse comportamento é perigoso porque
espalha estado pelo programa.

```js title="Global implícita"
function createImplicitGlobal() {
  implicitTotal = 100;
  return implicitTotal;
}

console.log(createImplicitGlobal()); // 100
console.log(globalThis.implicitTotal); // 100
delete globalThis.implicitTotal;

// Com "use strict" ou dentro de ES modules:
// ReferenceError: implicitTotal is not defined.
```

<Aside type="caution" title="Sempre declare variáveis">
  Use `const`, `let` ou, ao ler código antigo, `var`. Não dependa de globais
  implícitas.
</Aside>

### Escopo em laços

`let` cria uma nova associação por iteração em laços `for`. `var`, por ter escopo de
função, compartilha a mesma variável entre as iterações.

```js title="var e let em callbacks"
const callbacksWithVar = [];
const callbacksWithLet = [];

for (var i = 0; i < 3; i++) {
  callbacksWithVar.push(() => i);
}

for (let j = 0; j < 3; j++) {
  callbacksWithLet.push(() => j);
}

console.log(callbacksWithVar.map((callback) => callback())); // [3, 3, 3]
console.log(callbacksWithLet.map((callback) => callback())); // [0, 1, 2]
```

### Tipagem dinâmica

JavaScript tem tipagem dinâmica: uma variável pode receber valores de tipos
diferentes ao longo da execução.

```js title="Mesmo nome, tipos diferentes"
let variable = 10;
console.log(variable); // 10
console.log(typeof variable); // "number"

variable = "Fulano";
console.log(variable); // "Fulano"
console.log(typeof variable); // "string"
```

Essa flexibilidade é útil, mas pode esconder erros quando o programa muda valores
sem intenção.

```js title="Erro comum"
let total = 100;

total = "R$ 100";

console.log(total + 20); // "R$ 10020"
```

<Aside type="tip" title="Mantenha intenção estável">
  Mesmo que a linguagem permita trocar o tipo, prefira manter a mesma variável com
  a mesma intenção. Se `total` começa como número, evite transformá-la em texto.
</Aside>

### Conversão explícita

Conversão explícita deixa claro no código que um valor está sendo transformado em
outro tipo.

```js title="Conversão explícita"
console.log(Number("42") + 8); // 50
console.log(String(42) + 8); // "428"
console.log(Boolean(0)); // false
console.log(parseInt("42px")); // 42
console.log(Number("42px")); // NaN
console.log(Number("")); // 0
console.log((42).toString()); // "42"
```

### Coerção: conversão implícita

JavaScript também faz conversões implícitas em algumas operações. Esse comportamento
é chamado de coerção: a linguagem converte um valor automaticamente para conseguir
executar a operação.

```js title="Coerção"
console.log("5" + 9); // "59"
console.log("5" - 3); // 2
console.log(`total: ${42}`); // "total: 42"
console.log(Number("5") + 9); // 14
```

No primeiro caso, `9` foi convertido para texto. No segundo, `"5"` foi convertido
para número. A conversão explícita com `Number("5")` deixa a intenção mais clara.

Nem toda tentativa de combinar tipos termina em coerção bem-sucedida. Em alguns
casos, JavaScript prefere lançar erro para evitar perda de informação ou uma
conversão ambígua.

```js title="Coerção que gera erro"
// TypeError: Cannot mix BigInt and other types.
// console.log(1n + 1);

// TypeError: Cannot convert a Symbol value to a string.
// console.log("id: " + Symbol("id"));

// RangeError: The number 1.5 cannot be converted to a BigInt.
// console.log(BigInt(1.5));
```

Esses casos reforçam a regra prática: quando os tipos importam para o resultado,
converta explicitamente e confira se a conversão faz sentido.

<Aside type="caution" title="Use comparação estrita">
  Prefira `===` e `!==` para comparar valores. Eles evitam parte das conversões
  implícitas, ou coerções, que tornam `==` e `!=` difíceis de prever.
</Aside>

A comparação estrita considera valor e tipo; a comparação solta permite algumas
conversões antes de decidir o resultado.

```js title="Comparação"
const big = 9007199254740991n;

console.log(5 == "5"); // true
console.log(5 === "5"); // false
console.log(big == 9007199254740991); // true
console.log(big === 9007199254740991); // false
```

### Case sensitive

JavaScript diferencia letras maiúsculas e minúsculas. Portanto, `number`, `Number`
e `NUMBER` são nomes diferentes.

```js title="Case sensitive"
const number = 8;
const Number = 80;
const NUMBER = 800;

console.log(number); // 8
console.log(Number); // 80
console.log(NUMBER); // 800
```

### Boas práticas

A tabela final concentra escolhas que ajudam a reduzir surpresa em programas
pequenos e também em projetos maiores.

| Prática | Motivo |
| ------- | ------ |
| Prefira `const` | A maior parte dos nomes não precisa ser reassociada |
| Use `let` quando houver mudança | Deixa explícito que o valor varia com o tempo |
| Evite `var` em código novo | Reduz surpresas de escopo, redeclaração e *hoisting* |
| Declare sempre | Evita globais implícitas |
| Use nomes descritivos | Facilita leitura, revisão e depuração |
| Converta explicitamente quando necessário | Reduz resultados inesperados |

Este resumo mostra a regra mais comum em código moderno: `const` por padrão e `let`
quando o valor muda.

```js title="Resumo prático"
const defaultChoice = "const";
let changesOverTime = 0;

changesOverTime += 1;

console.log(defaultChoice); // "const"
console.log(changesOverTime); // 1
```

## Desafio

Crie um array `cart` com objetos de produto. O desafio deve mostrar a diferença
entre tipo de valor, reassociação de variável e mutação de objeto. Cada produto
deve ter `name`, `price` e `quantity`. Depois:

1. Adicione um novo produto com `push()`;
2. Altere o preço de um produto;
3. Calcule o total do carrinho;
4. Explique por que essas mudanças são possíveis mesmo quando `cart` foi declarado
   com `const`;
5. Inclua um caso com `0.1 + 0.2` e registre o que acontece.

<details>
  <summary>Possível resposta</summary>

  ```js title="cart.js"
  const cart = [
    {
      name: "Teclado",
      price: 129.9,
      quantity: 1,
    },
    {
      name: "Mouse",
      price: 59.9,
      quantity: 2,
    },
  ];

  cart.push({
    name: "Monitor",
    price: 899.9,
    quantity: 1,
  });

  cart[0].price = 119.9;

  const firstTotal = cart[0].price * cart[0].quantity;
  const secondTotal = cart[1].price * cart[1].quantity;
  const thirdTotal = cart[2].price * cart[2].quantity;
  const cartTotal = firstTotal + secondTotal + thirdTotal;

  console.log(cart);
  console.log(cartTotal); // 1139.6

  console.log(0.1 + 0.2); // 0.30000000000000004
  console.log(0.1 + 0.2 === 0.3); // false
  ```

  `cart` foi declarado com `const`, então a variável não pode receber outro array.
  Ainda assim, o array pode ser modificado com `push()` e os objetos dentro dele
  também podem ter propriedades alteradas. Isso é mutação, não reassociação da
  variável.
</details>

## Perguntas de revisão

### Valores e tipos

**1. O que significa dizer que o tipo está no valor, não na variável?**

<details>
  <summary>Possível resposta</summary>

  Significa que uma variável não declara um tipo fixo. Ela recebe valores, e cada
  valor tem seu próprio tipo em tempo de execução.
</details>

**2. Por que `typeof null` pode confundir?**

<details>
  <summary>Possível resposta</summary>

  Porque ele retorna `"object"`, embora `null` seja um valor primitivo usado para
  representar ausência intencional de valor.
</details>

**3. Quais valores são falsy em JavaScript?**

<details>
  <summary>Possível resposta</summary>

  `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined` e `NaN`. Valores como `[]`,
  `{}` e `"0"` são truthy.
</details>

**4. Por que `NaN === NaN` retorna `false`?**

<details>
  <summary>Possível resposta</summary>

  `NaN` representa um resultado numérico inválido e não é igual nem a ele mesmo.
  Para testar esse caso, use `Number.isNaN(value)`.
</details>

**5. Qual problema pode acontecer com coerção ou conversões implícitas?**

<details>
  <summary>Possível resposta</summary>

  O programa pode produzir resultados inesperados, como `"5" + 9` gerar `"59"` em
  vez de `14`, porque o operador `+` também concatena strings.
</details>

### Variáveis

**6. Qual é a diferença prática entre `let` e `const`?**

<details>
  <summary>Possível resposta</summary>

  `let` permite reassociar a variável a outro valor. `const` não permite
  reassociação, então deve ser usada quando a variável não precisa receber outro
  valor depois.
</details>

**7. Por que `const` não torna um objeto imutável?**

<details>
  <summary>Possível resposta</summary>

  Porque `const` protege a associação da variável, não o conteúdo interno do objeto.
  Um array declarado com `const` ainda pode receber `push()`, e um objeto ainda pode
  ter propriedades alteradas.
</details>

**8. Por que evitar `var` em código novo?**

<details>
  <summary>Possível resposta</summary>

  Porque `var` usa escopo de função, permite redeclaração no mesmo escopo e possui
  regras antigas de *hoisting*. `let` e `const` tornam o comportamento mais
  previsível.
</details>

**9. O que muda entre `var` e `let` dentro de um laço `for` com callbacks?**

<details>
  <summary>Possível resposta</summary>

  `var` compartilha a mesma variável entre as iterações, então callbacks podem ver o
  valor final do laço. `let` cria uma associação por iteração, preservando o valor
  correspondente a cada volta.
</details>

**10. Por que globais implícitas devem ser evitadas?**

<details>
  <summary>Possível resposta</summary>

  Porque elas criam estado fora do escopo esperado, podem sobrescrever nomes de
  outras partes do programa e deixam erros mais difíceis de encontrar.
</details>
