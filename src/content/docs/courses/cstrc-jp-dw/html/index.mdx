HTML (*HyperText Markup Language*) é uma linguagem de **marcação**: ela não executa
nada, apenas descreve o que cada pedaço de conteúdo *é*: um título, um parágrafo,
uma lista, um link. É a partir dessa descrição que o navegador monta a página, que o
leitor de tela narra o conteúdo e que o buscador entende do que trata o documento.

## Objetivo

Escrever um documento HTML válido do zero, sabendo escolher o elemento certo para
cada conteúdo e entender por que essa escolha importa.

## Sintaxe do HTML

A sintaxe do HTML é pequena: praticamente tudo que você vai escrever se resume a
elementos, atributos e entidades. Vale conhecer bem essas três peças antes de sair
decorando nomes de tags. Com elas, qualquer elemento novo que aparecer já faz
sentido à primeira vista.

### Elementos e tags

Um elemento é a unidade básica da marcação: ele envolve um trecho de conteúdo e
declara o que aquele trecho significa. As tags são as marcas que delimitam esse
envelope no arquivo de texto.

```plaintext title="Anatomia de um elemento"
 tag de                    tag de
abertura     conteúdo    fechamento
   ┌┴┐┌────────────────┐┌─┴─┐
   <p>Lorem ipsum dolor.</p>
   └────────────────────────┘
           elemento
```

Alguns elementos não têm conteúdo e por isso não têm tag de fechamento. São os
elementos **vazios**:

```html title="Elementos vazios"
<meta charset="utf-8" />
<img src="logo.svg" alt="Logotipo" />
<br />
<hr />
```

Elementos se aninham, e a ordem de fechamento importa:

```html title="Aninhamento" del={2} ins={5}
<!-- errado: as tags se cruzam -->
<p>Um texto <strong>importante</p></strong>

<!-- certo: o que abre por último fecha primeiro -->
<p>Um texto <strong>importante</strong></p>
```

<Aside type="tip" title="Escolha pelo significado, não pela aparência">
  `<strong>` e `<b>` deixam o texto em negrito, mas só `<strong>` comunica
  *importância* para o leitor de tela, para o buscador e para quem lê o código.
  A aparência é responsabilidade do CSS.
</Aside>

### Atributos

Se o elemento diz *o que* o conteúdo é, os atributos ajustam *como* ele se comporta:
o destino de um link, o arquivo de uma imagem, o idioma de um trecho. Eles são
escritos dentro da tag de abertura, sempre em pares de nome e valor.

```plaintext title="Formato de um atributo"
        atributo (nome="valor")
      ┌──────────┴──────────┐
<img src="logo.svg" alt="Logotipo" />
```

Alguns valem para qualquer elemento (**globais**), outros são específicos:

use uma entidade:

| Caractere | Descrição      | Nome      | Número     |

| `<`       | menor que      | `&lt;`    | `&#60;`    |
| `>`       | maior que      | `&gt;`    | `&#62;`    |
| `&`       | e comercial    | `&amp;`   | `&#38;`    |
| `"`       | aspas duplas   | `&quot;`  | `&#34;`    |
| `'`       | apóstrofo      | `&apos;`  | `&#39;`    |
| `©`       | copyright      | `&copy;`  | `&#169;`   |

Lista completa: [Named character references | WHATWG](https://html.spec.whatwg.org/multipage/named-characters.html).

Linha a linha, o que a parte marcada faz:

| Linha                  | Papel                                                         |
| ---------------------- | ------------------------------------------------------------- |
| `<!DOCTYPE html>`      | Declara HTML5 e evita o modo de compatibilidade do navegador   |
| `<html lang="pt-BR">`  | Idioma do documento, usado por leitores de tela e tradutores   |
| `<head>`               | Metadados sobre a página, que não aparecem no corpo renderizado |
| `<meta charset="UTF-8" />` | Codificação; sem ela, acentos podem quebrar                |
| `<title>`              | Nome da aba do navegador                                      |
| `<body>`               | Conteúdo que aparece na página                                |
| `<h1>`                 | Título principal do documento                                 |
| `<p>`                  | Parágrafo de texto                                            |
| `&copy;`               | Entidade HTML que mostra o símbolo ©                          |

<Aside type="caution" title="`<head>` e `<body>` têm papéis distintos">
  O `<head>` guarda **metadados**: informação sobre a página, que não aparece nela.
  Só o que está no `<body>` é renderizado.
</Aside>

## Elementos semânticos

Depois do esqueleto básico, páginas maiores precisam organizar o conteúdo em
regiões com significado. Os elementos de seccionamento dizem qual é o papel de cada
região:

| Elemento    | Papel na página                                                  |
| ----------- | ---------------------------------------------------------------- |
| `<header>`  | Cabeçalho: título, logotipo, identificação                        |
| `<nav>`     | Bloco de navegação principal                                      |
| `<main>`    | Conteúdo único da página, com apenas um por documento             |
| `<article>` | Conteúdo que faz sentido sozinho: um post, uma notícia, um card   |
| `<section>` | Agrupamento temático dentro do conteúdo, normalmente com título   |
| `<aside>`   | Conteúdo lateral, complementar ao principal                       |
| `<footer>`  | Rodapé: autoria, direitos, links secundários                      |

`<article>`, `<section>` e `<aside>` ficam **dentro** do `<main>`; `<header>`, `<nav>`
e `<footer>` são irmãos dele, na raiz do `<body>`.

`<div>` continua útil, mas apenas quando **nenhum** elemento semântico serve.

| ------------------ | ---------------------- | -------------------------------------------------------------------------------- |
| Lista não ordenada | `<ul>`, `<li>`         | Itens do mesmo grupo, sem ordem obrigatória, como links de navegação ou interesses |
| Lista ordenada     | `<ol>`, `<li>`         | Etapas ou classificações em que a posição muda o significado                      |
| Lista de descrição | `<dl>`, `<dt>`, `<dd>` | Pares de termo e descrição, como glossário, ficha técnica ou perguntas com respostas |

<Aside type="tip" title="Menu também é lista">
  Um menu de navegação é uma lista de links. Mesmo que o CSS remova os marcadores,
  a estrutura correta continua sendo `<ul>` com um `<li>` para cada link.
</Aside>

### Links

Um hyperlink é um destino (`href`) mais um conteúdo clicável:

```html title="Sintaxe"
<a href="url">conteúdo</a>
```

Um exemplo simples:

```html title="Link para outra página"
<a href="paginas/contato.html">Entre em contato</a>
```

Quem clica no texto "Entre em contato" navega para o arquivo indicado em `href`.

Entender a URL é o que permite escolher o `href` certo:

```plaintext title="Partes de uma URL"
                                                    query
 esquema      domínio    porta      caminho        string   fragmento
┌───┴──┐┌───────┴──────┐┌─┴┐┌──────────┴─────────┐┌───┴───┐┌────┴────┐
https://lucachaves.github.io:443/classroom/html/?busca=tag#links
```

O valor de `href` pode ser absoluto ou relativo. Um endereço absoluto informa o
destino completo, como protocolo e domínio. Um endereço relativo é resolvido a
partir da página atual ou da raiz do site. Com isso, links podem apontar para
endereços externos, arquivos do próprio projeto, trechos da página ou ações do
navegador:

| Forma do `href`                | Resolve para                                                  |
| ------------------------------ | ------------------------------------------------------------- |
| `https://exemplo.com/sobre.html` | URL completa, com protocolo, domínio e arquivo HTML         |
| `/sobre.html`                  | Caminho a partir da raiz do site atual, sem escrever o domínio |
| `contato.html`                 | Arquivo ao lado do atual                                      |
| `paginas/contato.html`         | Arquivo em subdiretório                                       |
| `../index.html`                | Sobe um diretório                                             |
| `#links`                       | Âncora dentro da própria página                               |
| `mailto:ana@exemplo.com`       | Abre o cliente de correio eletrônico                          |

Caminhos relativos ficam mais claros olhando a estrutura do projeto:

<FileTree>
{`
  html-basics/
  ├── fragments.html
  ├── index.html
  ├── texto.html
  ├── img/
  │   └── logo.svg
  └── paginas/
      └── contato.html
`}
</FileTree>

De `paginas/contato.html`, voltar para a raiz exige `../`:

<SourceCode
  path="examples/html-basics/paginas/contato.html"
  title="paginas/contato.html"
  showLineNumbers
  mark={['../index.html', '../img/logo.svg']}
/>

<Aside type="caution" title='Use rel="noopener" com target="_blank"'>
  Sem ele, a página aberta ganha uma referência à sua via `window.opener` e pode
  manipulá-la. Navegadores atuais já aplicam o `noopener` por padrão, mas declarar
  deixa a intenção explícita.
</Aside>

Fragmentos começam com `#` e apontam para um elemento que tem o `id`
correspondente. Esse recurso permite navegar entre partes da mesma página:

  <TabItem label="Código">

      title="fragments.html"
      showLineNumbers
      mark={[
        'id="inicio"',
        'href="#html"',
        'href="#css"',
        'href="#javascript"',
        'id="html"',
        'id="css"',
        'id="javascript"',
        'href="#inicio"',
      ]}
    />
  </TabItem>

### Imagens

A tag `<img>` é um elemento vazio: ela não envolve conteúdo, apenas aponta para um
arquivo externo. Por isso depende de dois atributos: `src`, com o caminho da imagem,
e `alt`, com o texto que a substitui quando ela não pode ser vista.

```html title="Sintaxe"
<img src="url" alt="texto alternativo" />
```

<Tabs syncKey="html-basics">
  <TabItem label="Código">
    <SourceCode
      path="examples/html-basics/imagens.html"
      title="imagens.html"
      showLineNumbers
      mark={[
        '<img src="img/logo.svg" alt="Logotipo azul com a palavra HTML" width="160" height="90" />',
        '<img src="imgs/none.png" alt="Imagem de exemplo não encontrada" width="160" height="90" />',
        '<figure>',
        '</figure>',
        '<img src="img/logo.svg" alt="" width="160" height="90" />',
        '<figcaption>',
        '</figcaption>',
      ]}
    />
  </TabItem>

  <TabItem label="Resultado">
    <HtmlPreview path="examples/html-basics/imagens.html" height="24rem" />
  </TabItem>
</Tabs>

O `alt` não é opcional:

- descreva **a função** da imagem, não o arquivo (`"Logotipo do IFPB"`, não `"logo.png"`);
- se a imagem é puramente decorativa, use `alt=""`, assim o leitor de tela a ignora;
- omitir o atributo faz o leitor narrar o nome do arquivo, que raramente ajuda.

O exemplo usa estas tags de imagem:

| Tag            | Papel no conteúdo                                                     |
| -------------- | --------------------------------------------------------------------- |
| `<img>`        | Insere uma imagem no documento. Precisa de `src` e `alt`              |
| `<figure>`     | Agrupa uma imagem com conteúdo relacionado, como uma legenda          |
| `<figcaption>` | Escreve a legenda da figura. Deve ficar dentro de um `<figure>`       |

Declarar `width` e `height` reserva o espaço antes de a imagem carregar e evita que o
texto "pule" durante o carregamento.

Também escolha arquivos com tamanho próximo ao tamanho exibido na página. Se a
imagem aparece com `160` por `90` pixels, carregar uma foto de `4000` por `2250`
pixels desperdiça dados, memória e tempo de carregamento. O CSS pode reduzir a
imagem visualmente, mas o navegador ainda precisa baixar o arquivo original.

Imagens podem ser vetoriais ou matriciais:

| Tipo       | Como funciona                                                         | Extensões comuns          | Uso comum                                      |
| ---------- | --------------------------------------------------------------------- | ------------------------- | ---------------------------------------------- |
| Vetorial   | Descreve formas, linhas e cores. Pode aumentar sem perder nitidez     | `.svg`                    | Logotipos, ícones, diagramas e ilustrações     |
| Matricial  | Guarda uma grade de pixels. Perde nitidez quando aumenta demais       | `.jpg`, `.png`, `.webp`   | Fotos, capturas de tela e imagens com textura  |

O `src` também pode receber uma imagem embutida em uma **Data URI**, também chamada
de **data URL**. Em SVG, os caracteres costumam aparecer codificados por URL:

```html title="Imagem vetorial codificada"
<img
  src="data:image/svg+xml,%3Csvg%20xmlns='http://www.w3.org/2000/svg'%20viewBox='0%200%20160%2090'%3E%3Crect%20width='160'%20height='90'%20fill='%230ea5e9'/%3E%3Ctext%20x='80'%20y='52'%20text-anchor='middle'%20font-size='24'%20fill='white'%3EHTML%3C/text%3E%3C/svg%3E"
  alt="Retângulo azul com o texto HTML"
  width="160"
  height="90"
/>
```

Uma imagem matricial também pode ser embutida em uma **Data URI**, normalmente com
PNG em base64:

```html title="Imagem matricial codificada"
<img
  src="data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAQAAAAECAYAAACp8Z5+AAAACXBIWXMAAAPoAAAD6AG1e1JrAAAAEklEQVQImWPgW/ryPzJmIF0AAHE3KbGj+UTXAAAAAElFTkSuQmCC"
  alt="Quadrado azul"
  width="16"
  height="16"
/>
```

Nos dois casos, os dados da imagem ficam escritos dentro do próprio atributo `src`.
Os termos mais comuns para isso são **Data URI**, **data URL**, **URL encoded**
quando os caracteres são codificados por URL, e **base64** quando os bytes do
arquivo são transformados em texto. Isso é útil para exemplos pequenos, mas não
substitui arquivos reais em imagens maiores.

<Aside type="tip" title="SVG também pode ser HTML">
  SVG também pode ser escrito diretamente no HTML, usando a tag `<svg>`. Nesse caso,
  ele deixa de ser apenas um arquivo carregado por `<img>` e passa a fazer parte da
  estrutura da página.
</Aside>

### Tabelas

Tabelas servem para **dados tabulares**: informações que só fazem sentido no
cruzamento entre uma linha e uma coluna. Durante anos elas foram usadas para
posicionar elementos na tela, mas esse papel hoje é do CSS. Usar tabela como layout
atrapalha quem navega por leitor de tela e quebra em telas pequenas.

<Tabs syncKey="html-basics">
  <TabItem label="Código">
    <SourceCode
      path="examples/html-basics/tabela.html"
      title="tabela.html"
      showLineNumbers
      mark={[
        '<!-- CSS: border-collapse: collapse une as bordas da tabela. -->',
        '<table border="1">',
        '</table>',
        '<caption>',
        '</caption>',
        '<thead>',
        '</thead>',
        '<tbody>',
        '</tbody>',
        '<tr>',
        '</tr>',
        '<th scope="col">',
        '<th scope="row">',
        '</th>',
        '<td>',
        '</td>',
      ]}
    />
  </TabItem>

  <TabItem label="Resultado">
    <HtmlPreview path="examples/html-basics/tabela.html" height="24rem" />
  </TabItem>
</Tabs>

`<th scope="col">` e `<th scope="row">` dizem qual célula é cabeçalho de qual eixo.
É assim que um leitor de tela consegue anunciar "Linguagem: Python, Utilização: 51%"
ao navegar pela tabela. O exemplo usa estas tags de tabela:

| Tag         | Papel no conteúdo                                                     |
| ----------- | --------------------------------------------------------------------- |
| `<table>`   | Define a tabela                                                        |
| `<caption>` | Dá um título ou resumo curto para a tabela                             |
| `<thead>`   | Agrupa as linhas de cabeçalho                                          |
| `<tbody>`   | Agrupa as linhas principais de dados                                   |
| `<tr>`      | Cria uma linha                                                         |
| `<th>`      | Cria uma célula de cabeçalho, para coluna ou linha                     |
| `<td>`      | Cria uma célula comum de dados                                         |

<Aside type="caution" title="Aparência da tabela">
  Neste exemplo, `border="1"` deixa a tabela visível enquanto ainda não usamos CSS.
  Você ainda pode encontrar HTML antigo com atributos como `border`, `width`,
  `cellpadding`, `cellspacing` e `bgcolor`. Em projetos atuais, largura, borda,
  colapso de bordas e cor de fundo devem ir para o CSS, com propriedades como
  `width`, `border`, `border-collapse` e `background-color`.
</Aside>

## Executando

Não há nada para instalar: HTML é interpretado direto pelo navegador.

<Steps>

1. Se você ainda não tem o projeto, clone o repositório:

   ```bash
   git clone https://github.com/lucachaves/classroom.git
   cd classroom
   ```

2. Entre no projeto de exemplo:

   ```bash
   cd examples/html-basics
   ```

3. Abra o arquivo direto no navegador:

   ```bash
   open index.html
   ```

   No Linux, use `xdg-open index.html`.

4. Se preferir usar o Visual Studio Code, abra a pasta do exemplo:

   ```bash
   code .
   ```

   Depois, abra `index.html` com o Integrated Browser ou use a extensão Live Server
   e clique em `Go Live`.

5. Abra as ferramentas de desenvolvedor com <kbd>F12</kbd> e inspecione os elementos
   para ver a árvore que o navegador construiu.

</Steps>

<Aside type="tip" title="Valide a marcação">
  O navegador conserta silenciosamente boa parte dos erros de HTML, o que esconde
  problemas. Cole o arquivo no [validador do W3C](https://validator.w3.org/nu/) para
  ver o que está de fato errado.
</Aside>

## Exercício

Crie sua própria página pessoal, em um arquivo `index.html`, contendo:

1. a estrutura básica completa, com `lang`, `charset`, `viewport` e `title`;
2. `<header>`, `<nav>`, `<main>` e `<footer>`;
3. um `<h1>` e ao menos dois `<h2>`;
4. uma lista não ordenada com três interesses;
5. uma tabela com as disciplinas do semestre e a carga horária;
6. uma imagem com `alt` descritivo;
7. uma segunda página `paginas/contato.html`, com link de ida e de volta.

Ao final, valide as duas páginas no validador do W3C. O resultado deve ficar sem
erros.

## Desafio

Marque a mesma página **sem usar nenhuma `<div>`**. Para cada trecho, escolha o
elemento semântico mais adequado (`<article>`, `<section>`, `<aside>`, `<figure>`,
`<time>`, `<address>`...). Depois, no DevTools, abra a aba de acessibilidade e
compare a árvore gerada com a da versão anterior.
