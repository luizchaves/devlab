Antes de aprender HTML como linguagem da Web, vale entender a ideia por trás de uma
**Linguagem de Marcação**. Marcar um texto é adicionar sinais que explicam a função
de cada parte do conteúdo: título, parágrafo, destaque, citação, lista ou estrutura
de documento.

O texto continua sendo texto, mas agora existe informação suficiente para outro
programa interpretar esse conteúdo e transformá-lo em uma página, um PDF, um
documento de escritório ou uma tela no navegador.

## Objetivo

Comparar diferentes linguagens de marcação e perceber que HTML não é uma linguagem
de programação: ele descreve a estrutura e o significado do conteúdo para que outra
ferramenta faça a renderização.

## O Problema

Este texto puro tem conteúdo, mas quase nenhuma estrutura explícita:

<SourceCode
  path="examples/dw/codes/markup/markup-language/text.txt"
  title="text.txt"
/>

Uma pessoa consegue inferir que a primeira linha provavelmente é um título, mas um
programa precisa de regras. A marcação resolve isso: ela transforma intenção em
sintaxe.

<Aside type="tip" title="Marcação não é aparência">
  Dizer que um trecho é importante, um título ou uma ênfase é diferente de escolher
  fonte, cor ou tamanho. A linguagem de marcação descreve o significado; a ferramenta
  de renderização decide como apresentar esse significado.
</Aside>

Cada linguagem tem um público e uma ferramenta principal:

| Linguagem | Uso comum | Ferramenta que interpreta |
| --------- | --------- | ------------------------- |
| Markdown  | Documentação, README, notas e textos técnicos | Renderizador Markdown |
| LaTeX     | Artigos acadêmicos, relatórios científicos e fórmulas | Compilador LaTeX |
| XML       | Troca de dados e formatos estruturados, como ODT e SVG | Aplicação que conhece o vocabulário XML |
| HTML      | Páginas Web | Navegador |

## Markdown

Markdown é uma linguagem de marcação leve. Ela foi criada para ser confortável de
ler mesmo antes da renderização. Por isso, seus marcadores são curtos:

| Estrutura | Markdown |
| --------- | -------- |
| Título principal | `# Título` |
| Parágrafo | linha de texto separada por linha em branco |
| Ênfase | `_texto_` ou `*texto*` |
| Importância | `**texto**` ou `__texto__` |

## LaTeX

LaTeX também marca texto, mas com foco em composição tipográfica. Ele é comum em
textos acadêmicos porque lida muito bem com seções, referências, fórmulas, figuras e
bibliografias.

| Estrutura | LaTeX |
| --------- | ----- |
| Seção sem numeração | `\section*{Título}` |
| Parágrafo | linha de texto no corpo do documento |
| Ênfase | `\emph{texto}` |
| Importância visual | `\textbf{texto}` |

  escrever e compilar sem instalar nada, o [Overleaf](https://www.overleaf.com/) é
  uma opção online bastante usada.
</Aside>

## XML

XML define uma sintaxe genérica para documentos estruturados. Sozinho, XML não diz
quais tags existem ou o que elas significam. Esse significado vem do vocabulário
usado por uma aplicação específica.

Por exemplo, um arquivo `.odt` é um pacote com vários XMLs internos. A pasta abaixo
foi criada a partir de `text.odt`: o arquivo foi convertido para `.zip` e depois
descompactado para inspecionar sua estrutura.

<FileTree>
{`
  text.odt
  ├── content.xml
  ├── manifest.rdf
  ├── meta.xml
  ├── mimetype
  ├── settings.xml
  └── styles.xml
`}
</FileTree>

Um trecho simplificado do `content.xml` mostra a marcação usada por documentos
OpenDocument:

<SourceCode
  path="examples/dw/codes/markup/markup-language/text-odt-content-clean.xml"
  title="text-odt-content-clean.xml"
  showLineNumbers
  mark={[
    '<text:h text:style-name="Heading_20_1" text:outline-level="1">Lorem ipsum</text:h>',
    '<text:p text:style-name="P1">',
    '<text:span text:style-name="T2">ipsum</text:span>',
    '<text:span text:style-name="T3">dolor</text:span>',
  ]}
/>

No trecho acima, cada marca indica uma parte do documento. A tabela abaixo resume
como as estruturas mais importantes aparecem no vocabulário OpenDocument.

| Estrutura | OpenDocument XML |
| --------- | ---------------- |
| Título | `<text:h>` |
| Parágrafo | `<text:p>` |
| Trecho em negrito | `<text:span>` com estilo de texto em negrito |
| Trecho em itálico | `<text:span>` com estilo de texto em itálico |

<Aside type="note" title="XML precisa de contexto">
  Um XML geralmente depende de um programa que saiba interpretar aquele vocabulário.
  No caso de um arquivo `.odt`, quem entende a estrutura é um pacote como o
  LibreOffice ou outro editor que reconheça o formato OpenDocument.
</Aside>

Referências:

- [Introdução ao XML | MDN](https://developer.mozilla.org/en-US/docs/Web/XML/XML_introduction)
- [OpenDocument](https://en.wikipedia.org/wiki/OpenDocument)

## HTML

HTML é a linguagem de marcação da Web. O navegador lê o documento, cria uma árvore de
elementos e renderiza a página.

A ideia é parecida com XML: o conteúdo é cercado por tags que indicam sua função.
A diferença é que o HTML já possui um vocabulário conhecido pelos navegadores. Em vez
de uma tag específica de um formato de documento, como `<text:p>`, o HTML usa tags
mais compactas e padronizadas para a Web, como `<p>` para parágrafo, `<h1>` para
título principal e `<strong>` para um trecho importante.

<Tabs syncKey="html-markup">
  <TabItem label="Código">

        '<strong>ipsum</strong>',
        '<em>dolor</em>',
      ]}
    />

  <TabItem label="Resultado">

      <p>
        Lorem <strong>ipsum</strong> <em>dolor</em> sit amet consectetur,
        adipisicing elit. Quos distinctio aliquid quisquam enim qui animi
        accusantium, officia quasi quam illum architecto minima sapiente,
        voluptas nesciunt perspiciatis. Facilis natus id explicabo?
      </p>
    </div>
  </TabItem>
</Tabs>

No HTML, a marcação é feita com elementos:

| Estrutura | HTML |
| --------- | ---- |
| Título principal | `<h1>` |
| Parágrafo | `<p>` |
| Ênfase | `<em>` |
| Importância | `<strong>` |

<Aside type="note" title="Preview de HTML">
  Para visualizar um arquivo HTML, você pode abri-lo diretamente no navegador. No
  editor, também dá para usar recursos como browser integrado ou extensões como
  [Live Server](https://marketplace.visualstudio.com/items?itemName=ritwickdey.LiveServer),
  que recarregam a página durante a edição.
</Aside>

<Aside type="caution" title="O navegador não adivinha intenção">
  Se todo o conteúdo for escrito dentro de `<div>` ou `<span>`, a página pode até
  parecer correta depois do CSS, mas perde estrutura semântica para leitores de tela,
  buscadores e manutenção do código.
</Aside>

## Comparação Entre Marcações de Texto

O mesmo conteúdo pode ser marcado de várias formas. A diferença está na sintaxe e no
ambiente em que cada linguagem será interpretada.

| Estrutura | Markdown | LaTeX | OpenDocument XML | HTML |
| --------- | -------- | ----- | ---------------- | ---- |
| Título | `# Título` | `\section*{Título}` | `<text:h>` | `<h1>` |
| Parágrafo | linha de texto | linha de texto | `<text:p>` | `<p>` |
| Ênfase | `_texto_` | `\emph{texto}` | `<text:span>` com estilo itálico | `<em>` |
| Importância | `**texto**` | `\textbf{texto}` | `<text:span>` com estilo negrito | `<strong>` |

## Como Pensar em Marcação

<Steps>

1. Identifique a função do conteúdo: título, parágrafo, lista, link, imagem,
   destaque ou região da página.

2. Escolha o marcador que comunica essa função.

3. Use a ferramenta adequada para interpretar o arquivo: navegador, renderizador de
   Markdown, compilador LaTeX ou editor de documentos.

4. Separe estrutura de aparência. Primeiro marque corretamente; depois estilize.

</Steps>

## Formatos Além de Texto Corrido

Nem todo formato estruturado existe para representar parágrafos, títulos e trechos
de texto. Alguns formatos usam marcação para descrever outros tipos de informação,
como imagens vetoriais ou documentos de escritório.

O SVG é um bom exemplo para comparar com HTML e OpenDocument. Um arquivo `.svg` é
escrito em XML e pode ser aberto como texto, mas sua função principal é descrever
uma imagem vetorial: formas, linhas, círculos, caminhos, cores e posições. Ou seja,
ele continua sendo marcação, mas a marcação representa um desenho, não um documento
textual como uma página HTML.

Outros formatos também carregam informações que vão além de texto corrido e mantêm
relação direta com linguagens de marcação:

| Formato | Tipo de conteúdo | Relação com marcação |
| ------- | ---------------- | -------------------- |
| SVG | Imagem vetorial descrita em XML | É uma linguagem de marcação baseada em XML |
| MathML | Fórmulas e expressões matemáticas | Usa marcação XML para representar a estrutura da fórmula |
| KML | Pontos, rotas e áreas em mapas | Usa XML para descrever dados geográficos |
| GPX | Trilhas, rotas e pontos de GPS | Usa XML para registrar dados de navegação |
| RSS e Atom | Feeds de notícias, blogs e podcasts | Usam XML para estruturar itens publicados |
| EPUB | Livro digital empacotado | Usa HTML/XHTML, CSS e metadados dentro do pacote |
| DOCX e ODT | Documentos de escritório empacotados | Usam XML internamente para estruturar conteúdo e estilos |

<Aside type="note" title="Texto do arquivo não é o mesmo que conteúdo textual">
  Um formato pode ser escrito com caracteres legíveis e ainda assim representar algo
  diferente de texto corrido. SVG é texto no arquivo e usa marcação, mas descreve
  gráficos. DOCX e ODT também usam XML internamente, embora normalmente sejam
  editados por programas como Word ou LibreOffice.
</Aside>

Referência:

- [SVG | MDN](https://developer.mozilla.org/en-US/docs/Web/SVG)

## Perguntas de revisão

**1. O que uma linguagem de marcação acrescenta a um texto puro?**

<details>
  <summary>Possível resposta</summary>

  Ela acrescenta sinais que indicam a função de cada parte do conteúdo. Com a
  marcação, um programa consegue reconhecer títulos, parágrafos, trechos importantes
  e outras estruturas em vez de tratar tudo como texto sem significado explícito.
</details>

**2. Por que HTML não é considerado uma linguagem de programação?**

<details>
  <summary>Possível resposta</summary>

  Porque HTML não executa lógica, cálculos, decisões ou repetições. Ele descreve a
  estrutura do conteúdo para que o navegador interprete e renderize a página.
</details>

**3. Qual é a diferença entre Markdown e HTML no contexto da Web?**

<details>
  <summary>Possível resposta</summary>

  Markdown é uma marcação mais simples, muito usada para documentação e textos
  técnicos. Normalmente ele é convertido para HTML antes de ser exibido no navegador.
  HTML é a linguagem de marcação que o navegador interpreta diretamente.
</details>

**4. Por que um arquivo XML depende do programa que o interpreta?**

<details>
  <summary>Possível resposta</summary>

  XML define uma sintaxe genérica, mas o significado das tags depende de um
  vocabulário específico. Um `.odt`, por exemplo, precisa de um editor que entenda
  OpenDocument, como o LibreOffice.
</details>

**5. O que muda entre `<text:p>` no OpenDocument e `<p>` no HTML?**

<details>
  <summary>Possível resposta</summary>

  Ambos podem representar um parágrafo, mas pertencem a vocabulários diferentes.
  `<text:p>` faz sentido dentro do formato OpenDocument; `<p>` é uma tag HTML
  padronizada para navegadores Web.
</details>

**6. Por que separar estrutura de aparência é importante?**

<details>
  <summary>Possível resposta</summary>

  Porque a marcação deve comunicar o significado do conteúdo. A aparência pode mudar
  com CSS, tema ou ferramenta de renderização, mas a estrutura correta continua
  ajudando acessibilidade, busca e manutenção.
</details>

**7. Por que SVG é diferente dos exemplos de texto da aula?**

<details>
  <summary>Possível resposta</summary>

  Porque SVG usa XML para descrever uma imagem vetorial. O arquivo pode ser lido como
  texto, mas sua finalidade principal é representar formas, cores e posições, não
  parágrafos e títulos de um documento textual.
</details>
