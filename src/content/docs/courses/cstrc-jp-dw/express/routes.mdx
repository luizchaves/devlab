Nesta aula vamos aprender como organizar as rotas. Um arquivo único funciona bem com
três rotas — com trinta, vira um problema.

## Objetivo

Extrair as rotas de `app.js` para módulos independentes usando `express.Router()`, e
separar a **montagem da aplicação** da **subida do servidor**.

## Conceitos

- `express.Router()` cria um mini-aplicativo com suas próprias rotas.
- `app.use('/users', userRouter)` monta esse router sob um **prefixo**.
- Dentro do router, os caminhos são relativos ao prefixo: `/` vira `/users`.
- `app.js` exporta a aplicação; `server.js` apenas a coloca para escutar uma porta.

<Aside type="tip" title="Por que separar `app.js` de `server.js`?">
  Porque `app` sem `listen` é testável: ferramentas de teste importam o `app` e fazem
  requisições sem ocupar nenhuma porta. `server.js` fica com a única
  responsabilidade de subir o processo.
</Aside>

## Do arquivo único para o router

A mudança em `app.js` é pequena, mas muda a arquitetura:

```js title="src/app.js" del={2-4} ins={6}
// antes
app.get('/users', (req, res) => {
  res.json(users);
});

app.use('/users', userRouter);
```

## Parâmetros de rota

Dentro do router, `/:id` já está sob o prefixo — o caminho final é `/users/:id`:

```js title="src/routes/user-router.js" {2}
router.get('/:id', (req, res) => {
  const user = users.find((item) => item.id === Number(req.params.id));

  if (!user) {
    return res.status(404).json({ message: 'Usuário não encontrado' });
  }

  res.json(user);
});
```

<Aside type="caution" title="`req.params` é sempre string">
  `/users/2` entrega `req.params.id === '2'`. Sem o `Number()`, a comparação com
  `item.id === 2` falha silenciosamente.
</Aside>
