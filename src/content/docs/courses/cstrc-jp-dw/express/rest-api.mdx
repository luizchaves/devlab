REST é um conjunto de convenções para expor **recursos** por HTTP. Seguir essas
convenções faz com que qualquer pessoa consiga usar a sua API sem ler documentação
extensa.

## Recursos, não ações

O caminho identifica **o quê**; o método diz **o que fazer**.

```text
/users            coleção de usuários
/users/1          um usuário
/users/1/posts    posts daquele usuário
```

```text
GET /listarUsuarios      ✗ ação no caminho
GET /users               ✓ recurso no caminho
```

Use substantivos no plural e sem verbos.

## Os cinco verbos

| Método   | Caminho      | Ação      | Sucesso            |
| -------- | ------------ | --------- | ------------------ |
| `GET`    | `/users`     | Listar    | `200 OK`           |
| `GET`    | `/users/:id` | Buscar um | `200 OK`           |
| `POST`   | `/users`     | Criar     | `201 Created`      |
| `PUT`    | `/users/:id` | Atualizar | `200 OK`           |
| `DELETE` | `/users/:id` | Remover   | `204 No Content`   |

## Status codes

| Faixa | Significado         | Exemplos                              |
| ----- | ------------------- | ------------------------------------- |
| `2xx` | Sucesso             | `200`, `201`, `204`                   |
| `4xx` | Erro do cliente     | `400`, `401`, `403`, `404`, `409`     |
| `5xx` | Erro do servidor    | `500`                                 |

Os que mais aparecem:

- **`200 OK`** — a requisição funcionou e há corpo na resposta.
- **`201 Created`** — recurso criado; devolva o recurso criado no corpo.
- **`204 No Content`** — funcionou e **não há corpo** (típico do `DELETE`).
- **`400 Bad Request`** — a entrada é inválida.
- **`404 Not Found`** — o recurso não existe.
- **`409 Conflict`** — conflito de estado, como e-mail já cadastrado.
- **`500 Internal Server Error`** — falha inesperada no servidor.

<Aside type="caution" title="Nunca responda 200 para um erro">
  `res.status(200).json({ erro: 'não encontrado' })` obriga todo cliente a inspecionar
  o corpo para descobrir o que aconteceu. O status **é** a resposta.
</Aside>

## Idempotência

- `GET`, `PUT` e `DELETE` são **idempotentes**: repetir a chamada leva ao mesmo
  estado final.
- `POST` **não** é: dois `POST /users` criam dois usuários.

Isso importa quando o cliente tem retry automático.
