Esta aula apresenta as **Promises** (promessas) e o ecossistema de programação assíncrona em JavaScript. Veremos como criar, manipular e encadear operações assíncronas, gerenciar seus três estados possíveis, utilizar combinadores estáticos, compreender a ordem de execução do *Event Loop* (microtasks) e simplificar o código assíncrono com a sintaxe `async` / `await`.

## Objetivo

Compreender o conceito de Promises em JavaScript, dominar a criação e o encadeamento de tarefas assíncronas com `.then()`, `.catch()` e `.finally()`, aplicar combinadores de Promises (`Promise.all`, `allSettled`, `race` e `any`), compreender a ordem de execução da *Microtask Queue* e tratar erros adequadamente utilizando a sintaxe `async/await`.

## O que é uma Promise e seus 3 Estados

Em JavaScript, uma **Promise** é um objeto que representa a eventual conclusão (ou falha) de uma operação assíncrona e seu valor resultante. Ela atua como um "comprovante" de uma tarefa que pode estar em andamento no momento ou ser concluída no futuro.

Uma Promise sempre se encontra em um dos **três estados mutuamente exclusivos**:

| Estado | Descrição | Transição de Estado |
| :--- | :--- | :--- |
| **`pending`** (Pendente) | Estado inicial da Promise. A operação assíncrona ainda está em andamento. | Pode mudar para `fulfilled` ou `rejected`. |
| **`fulfilled`** (Realizada / Resolvida) | A operação assíncrona foi concluída com sucesso. Retorna um **valor**. | Estado final (imutável). |
| **`rejected`** (Rejeitada) | A operação assíncrona falhou ou gerou um erro. Retorna um **motivo/erro**. | Estado final (imutável). |

```js title="Estados de uma Promise"
// Promise em estado PENDING (Pendente)
const pendingPromise = new Promise(() => {});
console.log(pendingPromise); //=> Promise { <pending> }

// Promise resolvida (FULFILLED)
const fulfilledPromise = Promise.resolve("Sucesso!");
console.log(fulfilledPromise); //=> Promise { 'Sucesso!' }

// Promise rejeitada (REJECTED)
const rejectedPromise = Promise.reject(new Error("Falha ao carregar dados"));
console.log(rejectedPromise); //=> Promise { <rejected> Error: Falha ao carregar dados }
```

<Aside type="caution" title="Imutabilidade do estado de uma Promise">
  Uma vez que a Promise transita do estado `pending` para `fulfilled` ou `rejected`, o seu estado torna-se **definitivo e imutável**. Chamadas subsequentes a `resolve()` ou `reject()` dentro do executor são ignoradas.
</Aside>

### Execução Síncrona do Executor

A função passada para o construtor `new Promise((resolve, reject) => { ... })` é chamada de **executor**. Um ponto fundamental do funcionamento de Promises é que a função executora é chamada **imediatamente e de forma síncrona** no momento da criação da Promise.

```js title="Execução síncrona do executor"
console.log("1. Antes de criar a Promise");

const promise = new Promise((resolve, reject) => {
  console.log("2. Dentro do executor da Promise (execução SÍNCRONA)");
  resolve("Dados prontos");
});

console.log("3. Depois de criar a Promise");

promise.then((data) => {
  console.log("4. Dentro do .then() (execução ASSÍNCRONA)");
});

console.log("5. Fim do script principal");

//=>
// 1. Antes de criar a Promise
// 2. Dentro do executor da Promise (execução SÍNCRONA)
// 3. Depois de criar a Promise
// 5. Fim do script principal
// 4. Dentro do .then() (execução ASSÍNCRONA)
```

## Criando Promises

A forma padrão de instanciar uma Promise é através do construtor `new Promise`, fornecendo a função executora com os manipuladores `resolve` e `reject`.

```js title="Exemplo de função que retorna Promise"
function checkAge(age) {
  return new Promise((resolve, reject) => {
    if (typeof age !== "number" || age < 0) {
      reject(new Error("Idade inválida fornecida"));
    } else if (age >= 18) {
      resolve("Acesso permitido: Usuário é maior de idade");
    } else {
      reject("Acesso negado: Usuário é menor de idade");
    }
  });
}
```

Além do construtor `new Promise`, a linguagem oferece métodos estáticos para criar Promises já resolvidas ou rejeitadas:

- **`Promise.resolve(valor)`:** Retorna uma Promise já resolvida com o valor especificado.
- **`Promise.reject(motivo)`:** Retorna uma Promise já rejeitada com o motivo/erro especificado.

## Consumo e Encadeamento (`.then`, `.catch`, `.finally`)

Promises fornecem três métodos principais para consumir e reagir a seus resultados:

- **`.then(onFulfilled)`:** Registra uma função callback para ser executada quando a Promise for resolvida com sucesso. Retorna uma nova Promise, permitindo encadear chamadas.
- **`.catch(onRejected)`:** Registra uma função callback para capturar qualquer rejeição ou erro lançado na cadeia de Promises.
- **`.finally(onFinally)`:** Registra um callback executado **sempre** que a Promise for finalizada (seja com sucesso ou falha). Útil para tarefas de limpeza (ex.: fechar conexões, ocultar *spinners* de carregamento).

```js title="Encadeamento de .then(), .catch() e .finally()"
function fetchUserData(userId) {
  console.log("Iniciando requisição...");
  
  checkAge(20)
    .then((message) => {
      console.log("Sucesso no primeiro passo:", message);
      return "Usuário ID: " + userId; // O retorno vira o valor do próximo .then()
    })
    .then((userInfo) => {
      console.log("Próximo passo:", userInfo);
    })
    .catch((error) => {
      console.error("Erro capturado:", error.message || error);
    })
    .finally(() => {
      console.log("Operação finalizada (limpeza de recursos).");
    });
}

fetchUserData(101);
```

<Aside type="tip" title="O comportamento do método .finally()">
  O callback passado para `.finally()` não recebe argumentos (não sabe se a Promise resolveu ou rejeitou). O valor retornado por `.finally()` é ignorado, repassando o resultado ou erro original da Promise para o restante da cadeia, a menos que `.finally()` lance uma exceção explicitamente.
</Aside>

## Combinadores de Promises

Quando trabalhamos com múltiplas tarefas assíncronas concorrentes, o JavaScript disponibiliza 4 métodos estáticos combinadores:

| Método Combinador | Quando Resolve? | Comportamento em caso de Rejeição |
| :--- | :--- | :--- |
| **`Promise.all(iterable)`** | Quando **todas** as Promises resolverem com sucesso. Retorna um array com todos os resultados. | Rejeita **imediatamente** ao encontrar a **primeira** Promise rejeitada (*fast-fail*). |
| **`Promise.allSettled(iterable)`** | Quando **todas** as Promises forem finalizadas (sejam resolvidas ou rejeitadas). | **Nunca rejeita** o conjunto. Retorna um array de objetos `{ status, value/reason }`. |
| **`Promise.race(iterable)`** | Quando a **primeira** Promise do iterável for finalizada (resolvida ou rejeitada). | Rejeita se a primeira a finalizar for uma rejeição. |
| **`Promise.any(iterable)`** | Quando a **primeira** Promise do iterável for **resolvida com sucesso**. | Ignora rejeições até que uma resolva. Se **todas** rejeitarem, lança um `AggregateError`. |

### 1. Promise.all()

```js title="Promise.all — Sucesso Coletivo vs Rejeição Rápida"
const p1 = Promise.resolve(10);
const p2 = new Promise((resolve) => setTimeout(() => resolve(20), 100));
const p3 = Promise.resolve(30);

// Executa todas em paralelo
Promise.all([p1, p2, p3])
  .then((results) => console.log("Resultados Promise.all:", results)) //=> [ 10, 20, 30 ]
  .catch((err) => console.error("Erro no Promise.all:", err));

// Exemplo com Rejeição (Fast-fail)
const pFail = Promise.reject("Falha de conexão no serviço B");

Promise.all([p1, pFail, p3])
  .then((res) => console.log(res))
  .catch((err) => console.log("Promise.all rejeitado:", err));
  //=> Promise.all rejeitado: Falha de conexão no serviço B
```

### 2. Promise.allSettled()

Diferente de `Promise.all()`, o método `Promise.allSettled()` espera a conclusão de todas as Promises sem interromper o fluxo caso alguma rejeite.

```js title="Promise.allSettled — Inspecionando o status de cada tarefa"
const promises = [
  Promise.resolve("Dados da API A"),
  Promise.reject("Erro 500 na API B"),
  Promise.resolve("Dados da API C")
];

Promise.allSettled(promises).then((results) => {
  console.log(results);
  // [
  //   { status: 'fulfilled', value: 'Dados da API A' },
  //   { status: 'rejected', reason: 'Erro 500 na API B' },
  //   { status: 'fulfilled', value: 'Dados da API C' }
  // ]
});
```

### 3. Promise.race() e Promise.any()

```js title="Promise.race vs Promise.any"
const slow = new Promise((resolve) => setTimeout(() => resolve("Lento"), 300));
const fastFail = new Promise((_, reject) => setTimeout(() => reject("Erro Rápido"), 50));
const fastSuccess = new Promise((resolve) => setTimeout(() => resolve("Rápido Rápido"), 100));

// Promise.race responde à primeira que finalizar (neste caso, o erro rápido)
Promise.race([slow, fastFail, fastSuccess])
  .then((res) => console.log("Race venceu:", res))
  .catch((err) => console.log("Race falhou primeiro com:", err));
  //=> Race falhou primeiro com: Erro Rápido

// Promise.any ignora erros e busca o primeiro SUCESSO
Promise.any([slow, fastFail, fastSuccess])
  .then((res) => console.log("Any venceu com primeiro sucesso:", res))
  //=> Any venceu com primeiro sucesso: Rápido Rápido
  .catch((err) => console.log("Todas falharam:", err));
```

## Ordem de Execução: Event Loop e Microtask Queue

Para compreender o comportamento assíncrono das Promises, é essencial entender a diferença de prioridades no **Event Loop** do JavaScript:

1. **Código Síncrono (Call Stack):** Executado imediatamente, de cima para baixo.
2. **Fila de Microtasks (*Microtask Queue*):** Armazena callbacks de Promises (`.then`, `.catch`, `.finally` e a continuação após um `await`). Possui **prioridade alta** e é esvaziada por completo logo após o encerramento do código síncrono atual.
3. **Fila de Macrotasks (*Macrotask / Task Queue*):** Armazena temporizadores (`setTimeout`, `setInterval`) e eventos de I/O. Executa apenas após o esvaziamento total da Fila de Microtasks.

```js title="Demonstração do Event Loop e Prioridade de Microtasks"
console.log("1. Síncrono - Início");

setTimeout(() => {
  console.log("2. Macrotask (setTimeout)");
}, 0);

Promise.resolve().then(() => {
  console.log("3. Microtask 1 (Promise)");
}).then(() => {
  console.log("4. Microtask 2 (Promise encadeada)");
});

console.log("5. Síncrono - Fim");

//=> Ordem exata de saída no console:
// 1. Síncrono - Início
// 5. Síncrono - Fim
// 3. Microtask 1 (Promise)
// 4. Microtask 2 (Promise encadeada)
// 2. Macrotask (setTimeout)
```

## Sintaxe Async & Await

A partir do ES2017, a sintaxe `async` / `await` foi introduzida como uma forma mais limpa e legível de trabalhar com Promises. Ela permite escrever código assíncrono com uma estrutura visualmente semelhante à de código síncrono.

- **`async`:** Transforma uma função comum em uma função assíncrona. Uma função marcada com `async` **sempre retorna uma Promise** implicitamente.
- **`await`:** Pausa a execução da função `async` até que a Promise seja resolvida ou rejeitada. O operador `await` só pode ser usado dentro de funções `async` (ou no nível superior de módulos ESM com *Top-level await*).

```js title="Reescrita com async / await e tratamento com try/catch"
function fetchNumber() {
  return new Promise((resolve) => setTimeout(() => resolve(42), 100));
}

async function processData() {
  try {
    console.log("Buscando número...");
    const num = await fetchNumber(); // Pausa a função até a promise resolver
    console.log("Número recebido:", num);
    return num * 2;
  } catch (error) {
    console.error("Erro durante o processamento:", error);
    throw error;
  } finally {
    console.log("Finalizado o processamento.");
  }
}

// Invocação da função assíncrona
processData().then((result) => console.log("Resultado final:", result));
//=> Buscando número...
//=> Número recebido: 42
//=> Finalizado o processamento.
//=> Resultado final: 84
```

## Consumo Prático da Fetch API e Validação de `response.ok`

No consumo de recursos de rede no navegador com a `Fetch API`, a função `fetch(url)` retorna uma Promise que é resolvida com um objeto `Response`.

<Aside type="caution" title="Pegadinha importante da Fetch API">
  A Promise retornada pelo `fetch()` **NÃO é rejeitada em respostas HTTP de erro (como 404 Not Found ou 500 Internal Server Error)**. A Promise só rejeita caso ocorra uma falha grave de rede ou o destino seja inalcançável. Por isso, é **obrigatório verificar a propriedade `response.ok`** antes de processar o corpo da resposta.
</Aside>

```js title="Consumo correto de API com fetch e async/await"
async function getUser(username) {
  try {
    const response = await fetch(`https://api.github.com/users/${username}`);
    
    // Verifica se o status HTTP está na faixa de sucesso (200-299)
    if (!response.ok) {
      throw new Error(`Erro na requisição HTTP: Status ${response.status}`);
    }
    
    const data = await response.json();
    console.log("Usuário encontrado:", data.name);
    return data;
  } catch (error) {
    console.error("Falha ao buscar usuário:", error.message);
  }
}

getUser("luizchaves");
```

## Resumo e Boas Práticas

1. **Prefira `async` / `await`** em vez de longas cadeias de `.then()`, pois torna o código mais legível e fácil de manter.
2. **Sempre trate exceções:** Envolva trechos com `await` em blocos `try / catch` ou adicione um `.catch()` ao retornar Promises.
3. **Lembre-se da execução síncrona do executor:** A função passada para `new Promise((resolve, reject) => ...)` roda imediatamente ao ser criada.
4. **Use o combinador correto:** Use `Promise.all()` para tarefas dependentes onde todas devem passar; use `Promise.allSettled()` quando quiser saber o resultado de todas independente de falhas; e `Promise.any()` quando apenas o primeiro sucesso importar.
5. **Cuidado com a `Fetch API`:** Lembre-se de validar `response.ok`, pois erros HTTP 404 ou 500 não disparam o `.catch()`.
