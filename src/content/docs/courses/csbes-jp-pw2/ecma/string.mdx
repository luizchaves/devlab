## Criação e Literais de String

Em JavaScript, uma **String** é uma sequência de caracteres imutável usada para representar texto. As strings podem ser criadas utilizando três tipos de delimitadores: aspas simples (`'`), aspas duplas (`"`) ou crases (`` ` ``).

| Delimitador | Nome | Uso Principal | Exemplo |
| ----------- | ---- | ------------- | ------- |
| `'...'` | Aspas Simples | Literal de texto simples | `'Desenvolvimento Web'` |
| `"..."` | Aspas Duplas | Literal de texto simples | `"JavaScript"` |
| `` `...` `` | Template Literal | Interpolação e textos multilinhas | `` `Olá, ${nome}` `` |

```js title="Formas de declaração de Strings"
// 1. Aspas simples e duplas (equivalentes no comportamento)
const single = 'Desenvolvimento Web';
const double = "Curso de Redes de Computadores";

// 2. Template Literals (crases)
const template = `Tecnologia em Redes`;

// 3. Função conversora String()
const converted = String(42); // "42"

// 4. Construtor new String() (EVITAR)
const objectString = new String("Texto"); // Cria um objeto Wrapper
```

<Aside type="tip" title="Prefira Strings Primitivas">
  Evite utilizar `new String()`. O operador `new` cria um objeto *wrapper* na memória em vez de uma string primitiva, fazendo com que `typeof new String("texto")` retorne `"object"`, o que pode causar comportamentos inesperados em comparações estritas (`===`).
</Aside>

```js title="Primitivo vs Objeto String"
const prim = "DevLab";
const obj = new String("DevLab");

console.log(typeof prim); // "string"
console.log(typeof obj);  // "object"
console.log(prim === obj); // false (tipos diferentes)
```

## Conversão para String

Qualquer tipo de dado em JavaScript pode ser convertido para String de forma explícita ou implícita.

1. **Função `String(valor)`**: É a forma mais direta e segura de conversão explícita, pois funciona com qualquer tipo de dado, incluindo `null` e `undefined`.
2. **Método `.toString()`**: Método presente no protótipo da maioria dos tipos de dados (números, booleanos, arrays, objetos).
   - **Sintaxe com literais numéricos**: Chamar `.toString()` diretamente em um número literal como `42.toString()` gera um erro de sintaxe (`SyntaxError`), pois o interpretador entende o ponto como separador decimal. Para resolver isso, utiliza-se **dois pontos** (`42..toString()`), parênteses (`(42).toString()`) ou atribuição prévia a uma variável (`const num = 42; num.toString()`).
   - **Bases numéricas com `.toString(radix)`**: Em valores numéricos, o método `.toString()` aceita um parâmetro opcional `radix` (base numérica de `2` a `36`). Isso permite converter números inteiros para suas representações em **binário** (base 2), **octal** (base 8) ou **hexadecimal** (base 16).
3. **Coerção Implícita e Template Literals**: O operador `+` converte operandos para string quando ao menos um deles for uma string (ex: `"" + 42`). O mesmo ocorre na interpolação com *template literals* (`` `${42}` ``).

```js title="Exemplos de conversão para String e bases numéricas"
// 1. Função conversora String() (funciona com todos os tipos)
console.log(String(42));        // "42"
console.log(String(true));      // "true"
console.log(String(null));      // "null"
console.log(String(undefined)); // "undefined"

// 2. Método .toString()
const active = true;
console.log(active.toString()); // "true"

// Sintaxe com literais numéricos:
// 42.toString(); // SyntaxError: Invalid or unexpected token
console.log(42..toString());   // "42" (primeiro ponto é decimal, segundo acessa o método)
console.log((42).toString());  // "42" (parênteses isolam o literal numérico)

const count = 42;
console.log(count.toString()); // "42" (em variáveis funciona diretamente)

// Conversão de bases numéricas com .toString(radix):
console.log((42).toString(2));   // "101010" (Binário - base 2)
console.log((42).toString(8));   // "52"     (Octal - base 8)
console.log((255).toString(16)); // "ff"     (Hexadecimal - base 16)

// 3. Coerção implícita
console.log("" + 100);          // "100"
console.log(`Valor: ${100}`);   // "Valor: 100"
```

Referência: [String | MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/String).

## Caracteres de Escape e Unicode

Quando uma string precisa conter caracteres reservados (como a própria aspa usada para delimitá-la) ou caracteres especiais de controle (como quebra de linha ou tabulação), utilizamos a barra invertida (`\`) como caractere de **escape**.

| Sequência | Descrição | Exemplo |
| --------- | --------- | ------- |
| `\'` | Aspa simples literal | `'D\'água'` |
| `\"` | Aspa dupla literal | `"Disse: \"Olá!\""` |
| `\\` | Barra invertida literal | `"C:\\Arquivos"` |
| `\n` | Nova linha (*Line Feed*) | `"Linha 1\nLinha 2"` |
| `\t` | Tabulação (*Tab*) | `"Item:\tValor"` |
| `\uXXXX` | Caractere Unicode (Hexadecimal 16-bit) | `"\u2661"` // `"♡"` |

```js title="Uso de sequências de escape"
const quote = "O professor disse: \"Pratiquem JavaScript!\"";
const path = "C:\\projetos\\devlab\\script.js";
const multiline = "Primeira linha\nSegunda linha";
const heart = "Eu \u2661 JavaScript!";

console.log(quote);     // "O professor disse: "Pratiquem JavaScript!""
console.log(path);      // "C:\projetos\devlab\script.js"
console.log(multiline); // "Primeira linha" e na linha seguinte "Segunda linha"
console.log(heart);     // "Eu ♡ JavaScript!"
```

## Imutabilidade e Acesso por Índice

Strings em JavaScript são **primitivos imutáveis**. Isso significa que, uma vez criada, uma string não pode ter seus caracteres alterados individualmente.

### Notação de Colchetes e .at()

Os caracteres de uma string podem ser lidos por índices inteiros a partir do zero (`0`), similar a um array.

```js title="Leitura de caracteres e propriedade length"
const text = "JavaScript";

// Propriedade length (quantidade de caracteres)
console.log(text.length); // 10

// Leitura por índice (colchetes)
console.log(text[0]); // "J"
console.log(text[4]); // "S"
console.log(text[9]); // "t"
console.log(text[10]); // undefined (índice inexistente)

// Método .at() (aceita índices negativos a partir do final)
console.log(text.at(0));  // "J"
console.log(text.at(-1)); // "t" (último caractere)
console.log(text.at(-2)); // "p" (penúltimo caractere)
```

### Inspeção de Códigos Unicode com `codePointAt()`

Além de obter os caracteres como texto, podemos consultar o valor numérico **Unicode (Code Point)** de qualquer caractere na string utilizando o método `.codePointAt(index)`:

- Cada caractere possui um número inteiro correspondente na tabela Unicode (por exemplo, o caractere `"1"` tem o código `49`, `"A"` é `65` e o emoji `"😀"` é `128512`).
- Dê preferência ao método `.codePointAt()` em relação ao antigo `.charCodeAt()`, pois ele suporta corretamente caracteres Unicode de 32-bit (como emojis e símbolos estendidos) sem truncá-los.
- Para realizar o caminho inverso (converter um número de código Unicode em caractere), utiliza-se o método estático `String.fromCodePoint(codePoint)`.

```js title="Códigos Unicode com codePointAt() e String.fromCodePoint()"
const str = "123 JavaScript 😀";

// Obtendo o código Unicode do caractere "1" na posição 0
console.log(str.codePointAt(0)); // 49 (código ASCII/Unicode de "1")
console.log(str.codePointAt(4)); // 74 (código de "J")

// Emojis possuem pontos de código Unicode de 32-bit
const emojiPos = str.indexOf("😀");
console.log(str.codePointAt(emojiPos)); // 128512

// Conversão inversa: de código Unicode numérico para caractere String
console.log(String.fromCodePoint(49));     // "1"
console.log(String.fromCodePoint(65));     // "A"
console.log(String.fromCodePoint(128512)); // "😀"
```

### Tentativa de Mutação de Strings

Tentativas de alterar um caractere de uma string usando colchetes são silenciosamente ignoradas (ou lançam erro no modo estrito `'use strict'`).

```js title="Imutabilidade de Strings"
let language = "JavaScript";

// Tentativa de alterar o primeiro caractere
language[0] = "Y";

console.log(language); // "JavaScript" (não mudou!)

// Para alterar, é necessário atribuir uma NOVA string à variável
language = "Y" + language.slice(1);
console.log(language); // "YavaScript"
```

<Aside type="caution" title="Strings são Imutáveis">
  Nenhum método do objeto `String` altera a string original. Métodos como `.toUpperCase()`, `.trim()` ou `.replace()` sempre retornam uma **nova string** resultante do processamento.
</Aside>

## Concatenação e Template Literals

A junção de textos pode ser realizada através da concatenação tradicional com o operador `+` ou via **Template Literals** (crases).

### Concatenação com o Operador `+`

O operador `+` realiza a junção de strings. Se um dos operandos for uma string, o outro será convertido para string automaticamente (coerção).

```js title="Concatenação tradicional"
const firstName = "Luiz";
const lastName = "Chaves";
const fullName = firstName + " " + lastName;

console.log(fullName); // "Luiz Chaves"

// Coerção automática de números para string
console.log("Aula " + 5); // "Aula 5"
```

### Template Literals (Interpolação de Expressões)

Introduzidas no ES6, as *template literals* permitem interpolar variáveis e expressões diretamente dentro do texto usando a sintaxe `${expressão}`. Elas também suportam **textos multilinhas** sem a necessidade de `\n`.

```js title="Interpolação e multilinhas com Template Literals"
const user = "Alice";
const role = "Desenvolvedora";
const age = 28;

// Interpolação de variáveis e expressões JavaScript
const greeting = `Usuário ${user} (${role}) tem ${age} anos. Próximo ano terá ${age + 1}.`;
console.log(greeting);
// "Usuário Alice (Desenvolvedora) tem 28 anos. Próximo ano terá 29."

// Criação de HTML multilinha de forma limpa
const cardHtml = `
<div class="user-card">
  <h2>${user}</h2>
  <p>Cargo: ${role}</p>
</div>
`;

console.log(cardHtml);
```

Referência: [Template literals | MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Template_literals).

## Métodos do Objeto String

O objeto `String` oferece um rico conjunto de métodos para buscar, fatiar, transformar e formatar textos.

### 1. Busca e Inspeção

Métodos usados para verificar a existência de padrões ou localizar posições de caracteres em uma string.

| Método | Descrição | Retorno |
| ------ | --------- | ------- |
| `includes(search)` | Verifica se a string contém o trecho informado | `boolean` |
| `startsWith(search)` | Verifica se a string começa com o trecho informado | `boolean` |
| `endsWith(search)` | Verifica se a string termina com o trecho informado | `boolean` |
| `indexOf(search)` | Retorna o primeiro índice onde o trecho foi encontrado | Índice ou `-1` |
| `lastIndexOf(search)` | Retorna o último índice onde o trecho foi encontrado | Índice ou `-1` |

```js title="Exemplo de métodos de busca"
const filename = "relatorio-financeiro-2026.pdf";

console.log(filename.includes("financeiro")); // true
console.log(filename.startsWith("relatorio"));// true
console.log(filename.endsWith(".pdf"));       // true

const phrase = "A linguagem JavaScript é a linguagem da Web";
console.log(phrase.indexOf("linguagem"));     // 2 (primeira ocorrência)
console.log(phrase.lastIndexOf("linguagem")); // 27 (última ocorrência)
console.log(phrase.indexOf("Python"));        // -1 (não encontrado)
```

### 2. Extração e Fatiamento

Métodos usados para extrair partes de uma string ou dividi-la em um array de pedaços.

| Método | Descrição | Retorno |
| ------ | --------- | ------- |
| `slice(start, end)` | Extrai um trecho do índice `start` até `end` (exclusivo). Suporta índices negativos. | Nova `string` |
| `substring(start, end)` | Extrai um trecho de `start` até `end`. Trata negativos como `0`. | Nova `string` |
| `split(separator)` | Divide a string em um array utilizando o separador informado | Novo `Array` |

```js title="Extração de trechos com slice() e split()"
const email = "usuario@redes.ifpb.edu.br";

// Encontrando a posição do caractere '@'
const atIndex = email.indexOf("@");

// Extraindo nome de usuário e domínio com slice()
const username = email.slice(0, atIndex);
const domain = email.slice(atIndex + 1);

console.log(username); // "usuario"
console.log(domain);   // "redes.ifpb.edu.br"

// Dividindo a string em um Array com split()
const parts = email.split("@");
console.log(parts); // [ "usuario", "redes.ifpb.edu.br" ]

const words = "HTML,CSS,JavaScript,Node.js".split(",");
console.log(words); // [ "HTML", "CSS", "JavaScript", "Node.js" ]
```

<Aside type="caution" title="Evite usar o método depreciado .substr()">
  O método `.substr(start, length)` foi marcado como obsoleto na especificação do JavaScript. Dê preferência ao método padrão `.slice(start, end)`.
</Aside>

### 3. Transformação e Ajustes de Formato

Métodos usados para alterar a caixa de texto (maiúsculas/minúsculas), remover espaços em branco ou preencher caracteres de borda.

| Método | Descrição | Retorno |
| ------ | --------- | ------- |
| `toUpperCase()` | Converte todos os caracteres para maiúsculas | Nova `string` |
| `toLowerCase()` | Converte todos os caracteres para minúsculas | Nova `string` |
| `trim()` | Remove espaços em branco do início e do final | Nova `string` |
| `trimStart()` / `trimEnd()` | Remove espaços apenas do início ou apenas do final | Nova `string` |
| `padStart(targetLength, pad)` | Preenche o **início** até atingir o tamanho alvo | Nova `string` |
| `padEnd(targetLength, pad)` | Preenche o **final** até atingir o tamanho alvo | Nova `string` |
| `repeat(count)` | Repete a string a quantidade de vezes informada | Nova `string` |
| `replace(search, replacement)` | Substitui a **primeira** ocorrência de um termo | Nova `string` |
| `replaceAll(search, replacement)` | Substitui **todas** as ocorrências de um termo | Nova `string` |

```js title="Exemplo de métodos de transformação"
// 1. Ajuste de caixa de texto e remoção de espaços
const rawInput = "  contato@EMPRESA.com  \n";
const cleanEmail = rawInput.trim().toLowerCase();
console.log(cleanEmail); // "contato@empresa.com"

// 2. Preenchimento de texto com padStart()
const code = "42";
const formattedCode = code.padStart(6, "0");
console.log(formattedCode); // "000042"

// 3. Substituição de texto com replace() e replaceAll()
const text = "O gato subiu no telhado. O gato é esperto.";
console.log(text.replace("gato", "cachorro"));    // "O cachorro subiu no telhado. O gato é esperto."
console.log(text.replaceAll("gato", "cachorro")); // "O cachorro subiu no telhado. O cachorro é esperto."

// 4. Repetição de strings
const echo = "Olá! ".repeat(3);
console.log(echo); // "Olá! Olá! Olá! "
```

### 4. Comparação de Strings e `localeCompare()`

Quando comparamos strings utilizando os operadores relacionais (`<`, `>`, `<=`, `>=`), o JavaScript realiza uma **comparação lexicográfica baseada nos códigos Unicode** (Code Points / tabela ASCII) de cada caractere, e não na ordem alfabética gramatical.

- **Comparação por Unicode (Operadores `<` e `>`)**:
  - Letras maiúsculas possuem códigos Unicode menores que minúsculas (`"Mesa" < "cadeira"` é `true` porque `'M'` tem valor 77 e `'c'` tem valor 99).
  - Comparações textuais de números comparam caractere a caractere (`"2" > "10"` é `true` porque o caractere `"2"` vem depois do caractere `"1"`).
  - Vogais acentuadas possuem códigos Unicode elevados (`"á" > "b"` é `true`, contrariando a ordem alfabética).

- **Comparação por Regras de Idioma (`localeCompare()`)**:
  - O método `strA.localeCompare(strB, locale, options)` compara duas strings respeitando as regras gramaticais e de acentuação de um idioma ou região específica (ex: `"pt-BR"`).
  - Retorna um número **negativo** se `strA` vier antes de `strB`, **positivo** se vier depois, e `0` se forem consideradas equivalentes.

| Tipo de Comparação | Sintaxe / Exemplo | Resultado | Explicação |
| ------------------ | ----------------- | --------- | ---------- |
| Operador `>` | `"á" > "b"` | `true` | Comparação simples por código Unicode |
| `localeCompare()` | `"á".localeCompare("b", "pt-BR")` | `-1` (negativo) | No português ("pt-BR"), "á" vem antes de "b" |
| Ignorando case e acentos | `"á".localeCompare("A", "pt-BR", { sensitivity: 'base' })` | `0` | Trata acentos e maiúsculas como equivalentes |

```js title="Comparação de Strings e Ordenação"
// Comparação lexicográfica tradicional (Unicode)
console.log("banana" > "abacaxi"); // true
console.log("Mesa" < "cadeira");   // true ('M' = 77, 'c' = 99 em Unicode)
console.log("2" > "10");           // true ("2" vem depois de "1")
console.log("á" > "b");            // true (código Unicode de 'á' é 225, de 'b' é 98)

// Comparação correta por idioma com localeCompare()
console.log("á".localeCompare("b", "pt-BR")); // -1 ("á" vem antes de "b")
console.log("b".localeCompare("á", "pt-BR")); // 1 ("b" vem depois de "á")

// Ignorando diferenças de maiúsculas/minúsculas e acentos:
console.log("á".localeCompare("A", "pt-BR", { sensitivity: "base" })); // 0

// Aplicação prática: Ordenação de arrays de texto com sort()
const frutas = ["Maçã", "abacaxi", "Água", "banana"];

// Ordenação incorreta com sort() padrão (usa Unicode):
console.log([...frutas].sort());
// ["Maçã", "banana", "abacaxi", "Água"] ('M' e 'Á' vêm antes/depois de minúsculas)

// Ordenação correta usando localeCompare():
const frutasOrdenadas = [...frutas].sort((a, b) => a.localeCompare(b, "pt-BR"));
console.log(frutasOrdenadas);
// ["abacaxi", "Água", "banana", "Maçã"]
```

### 5. Métodos que Aceitam Expressões Regulares (Regex)

Vários métodos do protótipo `String` aceitam **Expressões Regulares (Regex)** como parâmetro, permitindo realizar buscas complexas, extrações e substituições baseadas em padrões.

| Método | Aceita Regex? | Descrição | Retorno |
| ------ | ------------- | --------- | ------- |
| `match(regex)` | Sim | Busca correspondências do padrão regex na string | `Array` ou `null` |
| `matchAll(regex)` | Sim (requer flag `/g`) | Retorna um iterador com todas as correspondências e grupos de captura | Iterador |
| `search(regex)` | Sim | Retorna a posição do primeiro caractere que casa com a regex | Índice ou `-1` |
| `replace(regex, sub)` | Sim | Substitui o padrão encontrado pela string de substituição | Nova `string` |
| `replaceAll(regex, sub)` | Sim (requer flag `/g`) | Substitui todas as ocorrências do padrão regex | Nova `string` |
| `split(regex)` | Sim | Divide a string utilizando a regex como delimitador | Novo `Array` |

```js title="Exemplo de métodos de string com Regex"
const input = "Contatos: ana@email.com, bob123@site.org e carla_2026@dev.io";

// 1. search(regex) - Retorna o índice do primeiro dígito numérico
console.log(input.search(/\d+/)); // 31 (posição do dígito '1' em bob123)

// 2. match(regex) - Extrai a primeira ocorrência que combina com o padrão de e-mail
const firstEmail = input.match(/[\w.-]+@[\w.-]+\.\w+/);
console.log(firstEmail[0]); // "ana@email.com"

// 3. matchAll(regex) - Iterador para extrair todos os e-mails com grupos de captura
const allEmails = input.matchAll(/([\w.-]+)@([\w.-]+\.\w+)/g);
for (const match of allEmails) {
  console.log(`Usuário: ${match[1]} | Domínio: ${match[2]}`);
}

// 4. replace(regex) - Oculta sequências de números por um marcador
const sanitized = input.replace(/\d+/g, "[OCULTO]");
console.log(sanitized); // "Contatos: ana@email.com, bob[OCULTO]@site.org e carla_[OCULTO]@dev.io"

// 5. split(regex) - Divide o texto por múltiplos delimitadores (vírgula, ponto e vírgula ou espaço)
const tags = "javascript; web, frontend   backend".split(/[\s,;]+/);
console.log(tags); // [ "javascript", "web", "frontend", "backend" ]
```

### 6. Normalização de Unicode com `normalize()`

Em Unicode, um mesmo caractere acentuado pode ser representado de duas formas diferentes na memória:
1. **Forma Composta (NFC)**: Um único ponto de código Unicode (ex: `"é"` como `"\u00E9"`).
2. **Forma Decomposta (NFD)**: O caractere base acompanhado do caractere combinador de acento (ex: `"e"` + `"\u0301"`).

O método `str.normalize(form)` padroniza a string em uma das formas normais Unicode (`"NFC"` ou `"NFD"`).

```js title="Normalização Unicode e Remoção de Acentos"
// Duas representações visivelmente idênticas, mas com códigos Unicode diferentes:
const strNFC = "é";          // "\u00E9" (NFC)
const strNFD = "e\u0301";    // "e" + "\u0301" (NFD)

console.log(strNFC === strNFD); // false (código na memória é diferente!)
console.log(strNFC.normalize("NFC") === strNFD.normalize("NFC")); // true

// Aplicação clássica: Remoção elegante de acentos combinando NFD e Regex
function removeAccents(text) {
  return text.normalize("NFD").replace(/[\u0300-\u036f]/g, "");
}

console.log(removeAccents("Atenção! Olá, programação!"));
// "Atencao! Ola, programacao!"
```

Referência: [String.prototype | MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/String#instance_methods).

- Para converter números literais em string usando `.toString()`, utilize `(42).toString()` ou `42..toString()` para evitar o erro de sintaxe do ponto decimal.
- Para converter números para outras bases (binário, hexadecimal), passe o `radix` para `.toString(radix)` (ex: `(42).toString(2)` resulta em `"101010"`).
- Para consultar o código Unicode completo de um caractere (incluindo emojis de 32-bit), prefira `codePointAt()` em vez de `charCodeAt()`.
- Para extrair partes de uma string conhecendo os índices de início e fim, prefira o método `.slice(start, end)`.
- Use `.padStart()` para formatar códigos, números de protocolo e identificadores numéricos com zeros à esquerda.
- Ao comparar ou ordenar strings considerando acentuação e regras do idioma (ex: Português), prefira `a.localeCompare(b, "pt-BR")` em vez dos operadores `<` e `>`.
- Para remover acentos de forma robusta, combine `.normalize("NFD")` com substituição Regex (`.replace(/[\u0300-\u036f]/g, "")`).

  <summary>Possível resposta</summary>

  ```js title="slug-generator.js"

      .trim()

      .replaceAll("!", "")
  ```

</details>

## Perguntas de revisão

### Criação, Imutabilidade e Concatenação

**1. O que significa dizer que as Strings em JavaScript são imutáveis?**

<details>
  <summary>Possível resposta</summary>

  Significa que os caracteres de uma string não podem ser alterados individualmente após sua criação. Qualquer método de string retorna uma **nova string** com o resultado, deixando a string original intocada.
</details>

**2. Qual é a vantagem de utilizar Template Literals (crases) em relação às aspas tradicionais?**

<details>
  <summary>Possível resposta</summary>

  As *template literals* permitem interpolar variáveis e expressões diretamente com a sintaxe `${expressão}` e suportam textos multilinhas de forma nativa e limpa sem precisar de `\n` ou concatenações com `+`.
</details>

**3. Por que a instrução `42.toString()` lança um erro de sintaxe (`SyntaxError`) e como podemos corrigi-la?**

<details>
  <summary>Possível resposta</summary>

  O erro ocorre porque o interpretador JavaScript entende o primeiro ponto após um número literal como a parte decimal do número de ponto flutuante. Para corrigir, podemos utilizar **dois pontos** (`42..toString()`), envolver o número em **parênteses** (`(42).toString()`), utilizar a função conversora `String(42)` ou atribuir o número a uma variável antes de chamar `.toString()`.
</details>

**4. Como converter um número inteiro para sua representação em binário ou hexadecimal em JavaScript utilizando `.toString()`?**

<details>
  <summary>Possível resposta</summary>

  Passando o parâmetro `radix` (a base numérica de 2 a 36) para o método `.toString(radix)`. Por exemplo: `(42).toString(2)` retorna `"101010"` (binário) e `(255).toString(16)` retorna `"ff"` (hexadecimal).
</details>

**5. O que acontece ao tentar modificar um caractere de uma string usando colchetes (ex: `str[0] = "A"`)?**

<details>
  <summary>Possível resposta</summary>

  A operação falha silenciosamente (o valor original permanece inalterado). Se o código estiver executando em modo estrito (`'use strict'`), uma exceção de erro será lançada.
</details>

### Métodos de Busca e Extração

**6. Qual é a diferença entre os métodos `.slice(start, end)` e `.substring(start, end)`?**

<details>
  <summary>Possível resposta</summary>

  `.slice()` aceita índices negativos (que contam a partir do final da string). `.substring()` trata valores negativos como `0` e inverte a ordem dos parâmetros se `start > end`.
</details>

**7. Por que o método `.substr()` deve ser evitado em código JavaScript moderno?**

<details>
  <summary>Possível resposta</summary>

  Porque `.substr()` foi marcado como obsoleto (*deprecated*) pela especificação da linguagem. Deve-se padronizar o uso do método `.slice()`.
</details>

**8. Como o método `.split()` funciona e qual o tipo de dado do seu retorno?**

<details>
  <summary>Possível resposta</summary>

  O método `.split(separador)` divide a string em partes onde o separador for encontrado e retorna um **Array** contendo as fatias de texto resultantes.
</details>

**9. Qual é a vantagem do método `codePointAt()` em relação ao método legado `charCodeAt()`?**

<details>
  <summary>Possível resposta</summary>

  O método `codePointAt()` retorna o ponto de código Unicode completo de 32 bits do caractere, suportando adequadamente emojis e caracteres estendidos. O método `charCodeAt()` retorna apenas a unidade de código UTF-16 de 16 bits, podendo truncar caracteres complexos.
</details>

### Transformação e Boas Práticas

**10. Para que serve o método `.padStart(targetLength, padString)` e em que cenário ele é útil?**

<details>
  <summary>Possível resposta</summary>

  Ele preenche o início da string com o caractere desejado até que a string atinja o tamanho limite especificado. É útil para formatar números de protocolo, matrículas ou valores numéricos com zeros à esquerda (ex: `"42".padStart(4, "0")` -> `"0042"`).
</details>

**11. Qual é a diferença entre os métodos `.replace()` e `.replaceAll()`?**

<details>
  <summary>Possível resposta</summary>

  `.replace(busca, substituto)` substitui apenas a **primeira ocorrência** do termo encontrado (a menos que seja usada uma Expressão Regular global). `.replaceAll()` substitui **todas as ocorrências** do termo na string.
</details>

**12. Por que é uma boa prática aplicar `.trim()` em dados recebidos de formulários de usuários?**

<details>
  <summary>Possível resposta</summary>

  Porque usuários frequentemente inserem espaços acidentais no início ou no final de campos de texto (como e-mails ou nomes). O `.trim()` remove esses espaços em branco indesejados antes do processamento ou salvamento.
</details>

**13. Por que `typeof new String("teste")` retorna `"object"` e por que isso deve ser evitado?**

<details>
  <summary>Possível resposta</summary>

  Porque o operador `new` instancia um objeto *wrapper* da classe String. Isso deve be evitado porque objetos não se comportam como primitivos em comparações estritas (`===`), além de consumir mais memória sem necessidade.
</details>

**14. Qual é a limitação dos operadores `<` e `>` ao comparar strings e por que o método `.localeCompare()` deve ser utilizado?**

<details>
  <summary>Possível resposta</summary>

  Os operadores `<` e `>` realizam comparações estritamente lexicográficas baseadas nos códigos Unicode (Code Points). Isso faz com que letras maiúsculas venham antes de minúsculas (`"Mesa" < "cadeira"`) e vogais acentuadas fiquem fora da ordem alfabética (`"á" > "b"`). O método `.localeCompare()` resolve isso ao comparar strings respeitando as regras gramaticais e de acentuação de um idioma especificado (ex: `"pt-BR"`).
</details>

**15. Quais métodos do protótipo `String` aceitam Expressões Regulares (Regex) e para que serve o método `.normalize()`?**

<details>
  <summary>Possível resposta</summary>

  Os métodos `match()`, `matchAll()`, `search()`, `replace()`, `replaceAll()` e `split()` aceitam expressões regulares como parâmetro. O método `.normalize()` padroniza a representação Unicode da string (NFC ou NFD), permitindo comparar strings acentuadas de forma consistente e remover diacríticos/acentos.
</details>
