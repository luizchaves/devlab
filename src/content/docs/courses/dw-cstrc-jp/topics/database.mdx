Até aqui os dados da aplicação viviam em memória ou em um arquivo JSON — some o
processo, somem os dados. Este tópico fecha essa lacuna: a API passa a guardar
informação em um banco de dados, com esquema definido, relacionamentos e consultas.

O caminho é deliberado. Primeiro fundamentos, modelagem relacional, normalização e SQL na mão, para entender o que realmente acontece;
só depois o ORM, que gera essas mesmas consultas a partir de um schema. Quem começa
pelo ORM sem ver o SQL tende a tratá-lo como caixa-preta e trava quando a consulta
gerada não é a esperada.

## O que esperar deste tópico?

Conceito de SGBD e modelo relacional, arquitetura ACID, modelagem conceitual/lógica (MER/DER), normalização até a 3FN, comandos DDL/DML do CRUD em SQL, junções e agregações, acesso ao banco a partir do Node.js e, por fim, o Prisma: schema, migrations, client, CRUD e relacionamentos.

<Aside type="note" title="Integração com o tópico anterior">
  Os tópicos de persistência assumem a API já organizada em MVC do tópico de
  [Node.js e Express.js](../node-express/). O banco entra na camada de model, sem
  alterar rotas nem controllers.
</Aside>
