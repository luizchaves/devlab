Este é o tópico mais longo da disciplina, e por um motivo: JavaScript é usado nos
dois lados da aplicação. A mesma linguagem que valida um formulário no navegador
constrói a API HTTP no servidor, mais adiante. O que você aprende aqui é reaproveitado
integralmente nos tópicos de Node.js e Express.

O recorte é a linguagem em si — o que a especificação ECMAScript define. Tudo que
depende do navegador (DOM, eventos, `fetch`, `localStorage`) fica no tópico seguinte,
de Web APIs. Essa fronteira costuma confundir no começo, mas é ela que explica por
que o mesmo código roda no Node.js sem `document` nem `window`.

## O que esperar deste tópico

Da declaração de uma variável até o tratamento de erros em código assíncrono. Pelo
caminho: tipos e coerção — a fonte de boa parte dos comportamentos "estranhos" da
linguagem —, funções e closures, módulos ES, as estruturas de dados do dia a dia e o
modelo de execução assíncrona com Promises e `async`/`await`.

<Aside type="tip" title="Duas páginas de consulta">
  O [Guia de Referência](../../../ecmascript/reference/cheat-sheet/) reúne as
  assinaturas de todos os métodos nativos, e [Evolução e TC39](../../../ecmascript/evolution/tc39/)
