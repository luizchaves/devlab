O SDK cliente oficial **`@supabase/supabase-js`** fornece uma API fluente, tipada e assíncrona para interagir com todos os serviços do Supabase (Banco de Dados, Autenticação, Storage e Realtime) diretamente do front-end ou de projetos Node.js sem a necessidade de compor requisições HTTP manuais.

## Objetivo

Dominar a instalação e inicialização do cliente `@supabase/supabase-js`, implementar o padrão de repositório de dados (*Service/Storage*) para operações CRUD e gerenciar o tratamento de erros em aplicações web reais.

---

## Arquitetura do Supabase JS Client

O SDK cliente do Supabase abstrai as chamadas HTTP do PostgREST através de uma interface encadeada baseada em Promises:

<Mermaid title="Fluxo de Dados com o Supabase JS Client">
{`
flowchart TD
  App["Aplicação Front-End (main.js)"] -- "supabase.from('investments').select()" --> SDK["@supabase/supabase-js Client"]
  SDK -- "Compõe HTTP + Header apikey" --> API["PostgREST API (Supabase Cloud)"]
  API -- "Executa Query no Postgres" --> DB[(PostgreSQL)]
  DB -- "Retorna { data, error }" --> App
`}
</Mermaid>

## 1. Instalação e Inicialização

Instale a biblioteca cliente oficial no projeto através do gerenciador de pacotes:

<PackageManagerTabs package="@supabase/supabase-js" />

### Inicialização Básica

Para instanciar o cliente, forneça a URL do projeto e a chave anônima pública (*anon key*):

```js title="Exemplo básico de inicialização"
import { createClient } from '@supabase/supabase-js';

const API_URL = 'https://xyz.supabase.co';
const API_KEY = 'public-anon-key';

const supabase = createClient(API_URL, API_KEY);

// Consulta dados da tabela investments
const { data, error } = await supabase
  .from('investments')
  .select();

if (error) {
  console.error('Erro na consulta:', error.message);
} else {
  console.log('Investimentos:', data);
}
```

## 3. Implementação do Módulo de Serviço CRUD (`storage.js`)

Configuração inicial das variáveis de ambiente usando o Vite (`import.meta.env`):

```js title="js/services/storage.js (Inicialização do Cliente)"
import { createClient } from '@supabase/supabase-js';

const API_KEY = import.meta.env.VITE_APP_SUPABASE_KEY;
const API_URL = import.meta.env.VITE_APP_SUPABASE_URL;

const supabase = createClient(API_URL, API_KEY);
```

### Operação de Criação (`create`)

O método `.insert()` aceita um objeto ou array de objetos. Adicionamos `.select('*')` para receber o item recém-criado com o `id` gerado:

```js title="js/services/storage.js (Criar investimento)"
async function create(resource, data) {
  const { data: createdData, error } = await supabase
    .from(resource)
    .insert(data)
    .select('*');

  if (error) {
    throw error;
  }

  return createdData[0];
}
```

### Operação de Leitura (`read`)

O método `.select()` permite buscar todos os registros ou aplicar filtros encadeados como `.eq()`:

```js title="js/services/storage.js (Ler investimentos)"
async function read(resource, id) {
  let query = supabase.from(resource).select('*');

  if (id) {
    query = query.eq('id', id);
  }

  const { data, error } = await query;

  if (error) {
    throw error;
  }

  return id ? data[0] : data;
}
```

### Operação de Atualização (`update`)

O método `.update()` atualiza os campos informados filtrando pelo `id`:

```js title="js/services/storage.js (Atualizar investimento)"
async function update(resource, id, data) {
  const { data: updatedData, error } = await supabase
    .from(resource)
    .update(data)
    .eq('id', id)
    .select('*');

  if (error) {
    throw error;
  }

  return updatedData[0];
}
```

### Operação de Remoção (`remove`)

O método `.delete()` exclui o registro correspondente ao `id`:

```js title="js/services/storage.js (Remover investimento)"
async function remove(resource, id) {
  const { error } = await supabase
    .from(resource)
    .delete()
    .eq('id', id);

  if (error) {
    throw error;
  }

  return true;
}

export default { create, read, update, remove };
```

## Exercício

1. Qual objeto retornado pelas chamadas do `@supabase/supabase-js` contém a mensagem de erro caso uma operação falhe no banco de dados?
2. Por que é necessário chamar `.select('*')` logo após um `.insert(data)` se desejamos obter o objeto completo criado com o `id` retornado?

<details>
  <summary>Possível resposta</summary>

  1. A propriedade `error` (desestruturada da resposta `{ data, error }`).

  2. Por padrão, o `.insert()` apenas executa a inserção. Chamar `.select('*')` força o Supabase a retornar o registro em sua forma final com os campos calculados e gerados pelo banco (como `id` e `created_at`).
</details>

## Perguntas de revisão

1. **Como encadear múltiplos filtros em uma consulta com o Supabase Client (ex: valor maior que 1000 e categoria igual a 'Pós')?**
   <details>
     <summary>Possível resposta</summary>
     Encadeando métodos na consulta: `supabase.from('investments').select('*').gt('value', 1000).eq('category', 'Pós')`.
   </details>

2. **Qual a diferença entre a chave `anon public key` e a chave `service_role key` no Supabase?**
   <details>
     <summary>Possível resposta</summary>
     A chave `anon` respeita todas as regras de segurança RLS e deve ser usada no front-end. A chave `service_role` ignora o RLS e tem acesso administrativo total, devendo ser mantida estritamente secreta no servidor backend.
   </details>
