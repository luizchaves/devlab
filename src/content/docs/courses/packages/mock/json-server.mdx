O **JSON Server** é uma biblioteca popular do Node.js que permite criar uma API REST funcional completa a partir de um simples arquivo `db.json` em segundos. Ele permite que o desenvolvimento do front-end avance de forma independente, simulando requisições `GET`, `POST`, `PUT`, `PATCH` e `DELETE` com suporte a filtros, ordenação e paginação.

## Objetivo

Aprender a instalar, configurar e rodar uma API REST falsa com JSON Server, dominando o uso via CLI (linha de comando) e via script em módulo Node.js, além de compreender o mapeamento de rotas e códigos de status HTTP em operações CRUD.

---

## Como Funciona o JSON Server

O JSON Server lê a estrutura de um arquivo JSON e mapeia cada chave de nível superior para um recurso da API:

<Mermaid title="Arquitetura de Prototipagem com JSON Server">
{`
flowchart TD
  App["Aplicação Front-End (Fetch / Axios)"] -- "Requisição HTTP (GET/POST/PUT/DELETE)" --> JS["JSON Server (localhost:3000)"]
  JS -- "Persiste Mudanças" --> DB["db.json (Arquivo Local)"]
  JS -- "Responde JSON + Status (200, 201, 204)" --> App
`}
</Mermaid>

<Aside type="tip" title="Prototipagem Rápida">
Todas as alterações (`POST`, `PUT`, `DELETE`) enviadas ao JSON Server são gravadas diretamente no arquivo `db.json`, simulando um banco de dados persistente real.
</Aside>

### Comandos de Execução

No terminal, inicialize o projeto Node.js e inicie o servidor com a opção `--watch`:

## 3. Mapeamento de Rotas HTTP

O JSON Server gera automaticamente rotas REST convencionais para cada coleção definida no `db.json`:

| Método | Caminho | Ação / Resposta |
| --- | --- | --- |
| **`POST`** | `/hosts` | Cria um novo host no banco de dados |
| **`GET`** | `/hosts` | Retorna a lista completa de hosts |
| **`GET`** | `/hosts?id=1` | Retorna o host aplicando filtro de consulta |
| **`GET`** | `/hosts/1` | Retorna o host específico pelo parâmetro de rota `:id` |
| **`PUT`** | `/hosts/1` | Atualiza completamente o host com `id` igual a 1 |
| **`PATCH`** | `/hosts/1` | Atualiza parcialmente os campos do host 1 |
| **`DELETE`** | `/hosts/1` | Exclui o host com `id` igual a 1 |

## 4. Códigos de Status HTTP Retornados

O JSON Server respeita as convenções oficiais de [HTTP Status Codes](https://developer.mozilla.org/en-US/docs/Web/HTTP/Status):

- **100–199**: Respostas informacionais.
- **200–299**: Respostas de sucesso (`200 OK`, `201 Created`, `204 No Content`).
- **300–399**: Redirecionamentos.
- **400–499**: Erros do cliente (`400 Bad Request`, `401 Unauthorized`, `404 Not Found`).
- **500–599**: Erros do servidor (`500 Internal Server Error`).

| Código | Nome | Significado na API |
| --- | --- | --- |
| **`200`** | **OK** | Solicitação gerada e processada com sucesso (`GET`, `PUT`, `PATCH`). |
| **`201`** | **Created** | Solicitação gerada com sucesso e um novo recurso foi criado (`POST`). |
| **`204`** | **No Content** | Solicitação processada com sucesso e sem corpo na resposta (`DELETE`). |
| **`400`** | **Bad Request** | Requisição não compreendida por erro de sintaxe ou dados inválidos. |
| **`401`** | **Unauthorized** | Acesso bloqueado por ausência de credenciais válidas. |
| **`404`** | **Not Found** | O recurso ou rota solicitada não existe no banco de dados. |
| **`500`** | **Internal Server Error** | O servidor encontrou uma situação de erro inesperado. |

## 5. Testando Operações CRUD

### Criar um Recurso (POST /hosts)

Exemplo de requisição para cadastrar um novo host:

```http title="Criando um host via VS Code REST Client (.http)"
@server=http://localhost:3000

# @name createHost
POST {{server}}/hosts
Content-Type: application/json

{
  "name": "DNS Server",
  "address": "1.1.1.1"
}
```

```bash title="Criando um host via cURL"
curl -X POST http://localhost:3000/hosts \
   -H "Content-Type: application/json" \
   -d '{"name":"DNS Server","address":"1.1.1.1"}'
```

### Ler Recursos (GET /hosts)

```http title="Buscando todos os hosts via REST Client"
@server=http://localhost:3000

GET {{server}}/hosts
```

```bash title="Buscando todos os hosts via cURL"
curl -X GET http://localhost:3000/hosts
```

### Atualizar um Recurso (PUT /hosts/1)

```http title="Atualizando o host 1 via REST Client"
@server=http://localhost:3000

PUT {{server}}/hosts/1
Content-Type: application/json

{
  "name": "DNS Primary Server",
  "address": "1.1.1.1"
}
```

### Deletar um Recurso (DELETE /hosts/1)

```http title="Removendo o host 1 via REST Client"
@server=http://localhost:3000

DELETE {{server}}/hosts/1
```

## Executando

Siga o passo a passo para colocar a API falsa no ar:

<Steps>
1. Abra um terminal e crie uma pasta para o projeto: `mkdir teste-api && cd teste-api`.
2. Crie o arquivo `db.json` com o conteúdo inicial.
3. Execute o comando `npx json-server --watch db.json`.
4. Abra o navegador em `http://localhost:3000/hosts` e veja os dados retornados em formato JSON.
</Steps>

## Perguntas de revisão

1. **O que acontece com o arquivo `db.json` quando enviamos uma requisição `DELETE` para o JSON Server?**
   <details>
     <summary>Possível resposta</summary>
     O JSON Server remove a entrada correspondente ao `id` informado diretamente do arquivo `db.json` e salva a alteração no disco.
   </details>

2. **Como podemos ordenar os resultados retornados pelo JSON Server em uma busca `GET`?**
   <details>
     <summary>Possível resposta</summary>
     Adicionando os parâmetros de consulta `_sort` e `_order` na URL (ex: `/hosts?_sort=name&_order=asc`).
   </details>
