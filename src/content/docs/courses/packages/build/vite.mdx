O **Vite** é uma ferramenta de compilação (*build tool*) moderna desenvolvida para proporcionar um ambiente de desenvolvimento extremamente rápido e eficiente para aplicações web front-end. Ele substituiu empacotadores tradicionais (como o Webpack) ao tirar proveito dos módulos ES nativos (*ES Modules*) do navegador durante o desenvolvimento e utilizar o **Rollup** altamente otimizado para gerar os arquivos estáticos de produção.

## Objetivo

Compreender os conceitos fundamentais do Vite, criar novos projetos front-end com templates predefinidos, utilizar o servidor de desenvolvimento com Hot Module Replacement (HMR), configurar opções de compilação e realizar a publicação (*deploy*) de um site estático.

---

## Por que o Vite é Rápido?

Empacotadores tradicionais precisam processar, compilar e juntar todo o código da aplicação em um único arquivo de saída (*bundle*) antes mesmo de iniciar o servidor de desenvolvimento.

O Vite revoluciona essa abordagem dividindo os módulos em duas categorias: **dependências** (pré-compiladas via `esbuild` em Go) e **código-fonte da aplicação** (servido sob demanda via ES Modules nativos do navegador):

<Mermaid title="Diferença entre Bundler Tradicional e Vite">
{`
flowchart TD
  subgraph Tradicional["Bundler Tradicional (Webpack / Parcel)"]
    Src1["Código-Fonte"] --> Bundle["Processa Todo o Código"]
    Bundle --> DevServer1["Servidor de Dev Pronto"]
  end

  subgraph ViteFlow["Vite (ES Modules Nativos)"]
    DevServer2["Servidor de Dev Pronto Instantaneamente"] --> Route["Navegador Solicita Rota"]
    Route --> Dynamic["Transpila Apenas o Módulo Necessário"]
  end
`}
</Mermaid>

<Aside type="tip" title="Hot Module Replacement (HMR)">
O Vite atualiza os módulos alterados na tela quase instantaneamente, sem recarregar a página inteira e preservando o estado atual da aplicação.
</Aside>

## 1. Criando um Projeto com Vite

Para criar uma nova aplicação front-end utilizando o gerador oficial `create-vite`, execute o comando no terminal:

```bash title="Scaffolding de projeto via terminal"
npm create vite@latest monitor-app -- --template vanilla
```

Saída no terminal durante o processo de criação:

```txt title="Output do terminal"
Need to install the following packages:
create-vite@5.2.0
Ok to proceed? (y)

Scaffolding project in /home/.../monitor-app...

Done. Now run:

  cd monitor-app
  npm install
  npm run dev
```

### Estrutura de Arquivos Gerada

O Vite gera uma estrutura mínima e limpa para o projeto:

<FileTree>
{`
monitor-app/
    public/
        vite.svg
    .gitignore
    counter.js
    index.html
    javascript.svg
    main.js
    package.json
    style.css
`}
</FileTree>

<Aside type="note" title="index.html na Raiz">
No Vite, o arquivo `index.html` fica localizado na **raiz do projeto** (e não na pasta `public`). Ele atua diretamente como o ponto de entrada da aplicação através da tag `<script type="module" src="/main.js">`.
</Aside>

## 2. Servidor de Desenvolvimento

Após acessar a pasta do projeto e instalar as dependências, inicie o servidor de desenvolvimento:

```bash title="Instalando dependências e iniciando o servidor de dev"
cd monitor-app
npm install
npm run dev
```

Terminal após a inicialização:

```txt title="Output do Vite Dev Server"
  VITE v5.0.0  ready in 191 ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: use --host to expose
  ➜  press h to show help
```

Acesse `http://localhost:5173/` no navegador para visualizar a página padrão do projeto.

---

## 3. Gerando o Build para Produção

Quando a aplicação estiver pronta para ser enviada para produção, execute o comando de compilação:

```bash title="Gerando o bundle otimizado de produção"
npm run build
```

Saída do processo de build:

```txt title="Output do comando npm run build"
vite v5.0.0 building for production...
✓ 7 modules transformed.
dist/index.html                      0.45 kB │ gzip: 0.29 kB
dist/assets/javascript-8dac5379.svg  1.00 kB │ gzip: 0.60 kB
dist/assets/index-48a8825f.css       1.24 kB │ gzip: 0.65 kB
dist/assets/index-44b5bae5.js        1.45 kB │ gzip: 0.75 kB
✓ built in 132ms
```

Para testar localmente os arquivos de produção gerados na pasta `dist/`, execute:

```bash title="Testando o build localmente"
npm run preview
```

Output:

```txt title="Output do Vite Preview"
  ➜  Local:   http://localhost:4173/
  ➜  Network: use --host to expose
```

## 4. Principais Opções de Configuração (`vite.config.js`)

É possível criar um arquivo `vite.config.js` na raiz do projeto para personalizar o comportamento do build:

```js title="vite.config.js"
import { defineConfig } from 'vite';

export default defineConfig({
  // Define o diretório de saída do build (padrão: 'dist')
  build: {
    outDir: 'dist',
    // Compatibilidade com navegadores legados ('esnext', 'modules', 'es2015')
    target: 'modules',
    // Minificação de código ('terser' ou 'esbuild')
    minify: 'esbuild',
  },
  // Configuração do servidor de dev
  server: {
    port: 3000,
    open: true, // Abre o navegador automaticamente
  },
});
```

## 5. Deploy de Sites Estáticos

Como o comando `npm run build` gera arquivos HTML, CSS e JavaScript estáticos puros dentro da pasta `dist/`, a publicação pode ser feita facilmente em qualquer provedor de hospedagem de sites estáticos:

- **[GitHub Pages](https://vitejs.dev/guide/static-deploy.html#github-pages)**: Configurado via GitHub Actions ou branch `gh-pages`.
- **[Netlify](https://vitejs.dev/guide/static-deploy.html#netlify)**: Definindo o comando de build como `npm run build` e a pasta de publicação como `dist`.
- **[Vercel](https://vitejs.dev/guide/static-deploy.html#vercel)**: Detecção automática do Vite com um único clique.

## Perguntas de revisão

1. **Por que o servidor de desenvolvimento do Vite é consideravelmente mais rápido que o do Webpack?**
   <details>
     <summary>Possível resposta</summary>
     Porque o Vite não realiza o empacotamento (*bundling*) completo do código antes de iniciar o servidor. Ele utiliza ES Modules nativos do navegador para carregar cada arquivo sob demanda.
   </details>

2. **Como podemos testar a versão compilada de produção da pasta `dist/` antes de realizar o deploy?**
   <details>
     <summary>Possível resposta</summary>
     Executando o comando `npm run preview` (que roda `vite preview`).
   </details>
