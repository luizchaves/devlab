Quase todo programa precisa guardar **vários** valores: os itens de um pedido, as respostas de
uma API, os alunos de uma turma. Python embute quatro coleções para isso — `list`, `tuple`,
`dict` e `set` —, cada uma com garantias diferentes sobre ordem, mutabilidade e velocidade de
busca.

Escolher a estrutura certa costuma render mais em legibilidade e desempenho do que otimizar
o código depois. Esta aula apresenta as quatro e os critérios para decidir entre elas.

## Objetivo

Criar e manipular listas, tuplas, dicionários e conjuntos, diferenciar métodos mutadores de
acessores, ordenar coleções com `sorted()` e `key`, entender cópia rasa versus profunda,
aplicar operações de conjunto e escolher a estrutura adequada para cada problema.

## Panorama das Coleções

As quatro coleções embutidas diferem em três eixos: mantêm ordem, aceitam alteração e
permitem duplicatas.

| Coleção | Literal | Ordenada | Mutável | Duplicatas | Busca por |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `list` | `[1, 2, 3]` | Sim | Sim | Sim | Índice |
| `tuple` | `(1, 2, 3)` | Sim | Não | Sim | Índice |
| `dict` | `{"id": 1}` | Sim (inserção) | Sim | Chaves únicas | Chave |
| `set` | `{1, 2, 3}` | Não | Sim | Não | Pertencimento |

```python title="As quatro coleções lado a lado"
languages_list = ["python", "go", "python"]
languages_tuple = ("python", "go")
languages_dict = {"python": 1991, "go": 2009}
languages_set = {"python", "go", "python"}

print(languages_list)    # ['python', 'go', 'python']
print(languages_tuple)   # ('python', 'go')
print(languages_dict)    # {'python': 1991, 'go': 2009}
print(languages_set)     # {'go', 'python'} — duplicata removida, ordem não garantida
```

<Aside type="note" title="Dicionários preservam a ordem de inserção">
  Desde o Python 3.7 essa é uma garantia da linguagem, não um detalhe de implementação.
  Conjuntos, por outro lado, **não** têm ordem definida: não confie na sequência ao iterar.
</Aside>

## Listas

A lista é a coleção de uso geral: sequência ordenada, mutável e heterogênea.

### Criação e acesso

Índices e fatiamento funcionam como em strings, mas listas aceitam atribuição por índice:

```python title="Criando e acessando"
numbers = [10, 20, 30, 40, 50]
mixed = [42, "texto", True, None, [1, 2]]
empty = []
from_range = list(range(5))

print(numbers[0], numbers[-1])   # 10 50
print(numbers[1:4])              # [20, 30, 40]
print(numbers[::-1])             # [50, 40, 30, 20, 10]

numbers[0] = 99                  # listas são mutáveis
print(numbers)                   # [99, 20, 30, 40, 50]

print(len(numbers), 30 in numbers, numbers.index(30))
print(mixed[4][1], from_range)
```

### Métodos que alteram a lista

Estes métodos modificam o objeto no lugar e devolvem `None`:

| Método | Efeito |
| :--- | :--- |
| `append(x)` | Adiciona um item ao final |
| `extend(iterável)` | Adiciona todos os itens de outro iterável |
| `insert(i, x)` | Insere na posição `i` |
| `remove(x)` | Remove a **primeira** ocorrência do valor |
| `pop([i])` | Remove e **devolve** o item (último por padrão) |
| `clear()` | Esvazia a lista |
| `sort()` | Ordena no lugar |
| `reverse()` | Inverte no lugar |

```python title="Alterando a lista"
stack = ["html", "css"]

stack.append("javascript")
stack.extend(["python", "sql"])
stack.insert(0, "git")
print(stack)

removed = stack.pop()        # remove o último e devolve
stack.remove("css")
print(stack, "| removido:", removed)

print(stack.sort())          # None — o retorno não é a lista!
print(stack)
```

```txt title="Output"
['git', 'html', 'css', 'javascript', 'python', 'sql']
['git', 'html', 'javascript', 'python'] | removido: sql
None
['git', 'html', 'javascript', 'python']
```

<Aside type="caution" title="Métodos mutadores devolvem None">
  `lista = lista.sort()` destrói a lista, porque `sort()` devolve `None`. Use `lista.sort()`
  sozinho para ordenar no lugar, ou `nova = sorted(lista)` para obter uma cópia ordenada.
</Aside>

### Ordenação

`sorted()` devolve uma nova lista; `list.sort()` reordena a original. Ambos aceitam `key` e
`reverse`:

```python title="Ordenando com critério"
words = ["banana", "kiwi", "abacaxi", "uva"]
people = [("Ana", 32), ("Bia", 25), ("Caio", 41)]

print(sorted(words))                       # alfabética
print(sorted(words, key=len))              # por comprimento
print(sorted(words, reverse=True))
print(sorted(people, key=lambda item: item[1]))       # por idade
print(sorted(people, key=lambda item: -item[1])[:2])  # dois mais velhos

numbers = [3, 1, 2]
numbers.sort()
print(numbers)
```

### Cópia rasa e profunda

Atribuir uma lista a outro nome **não** copia; para copiar é preciso pedir explicitamente:

```python title="Copiando listas"
import copy

original = [1, 2, [3, 4]]

reference = original          # mesmo objeto
shallow = original.copy()     # cópia rasa (também: list(original) ou original[:])
deep = copy.deepcopy(original)  # cópia profunda

original[0] = 99
original[2].append(5)

print(reference)   # [99, 2, [3, 4, 5]] — acompanha tudo
print(shallow)     # [1, 2, [3, 4, 5]]  — nível 1 copiado, aninhado compartilhado
print(deep)        # [1, 2, [3, 4]]     — independente
```

<Aside type="tip" title="Cópia rasa basta na maioria dos casos">
  Use `deepcopy` apenas quando a estrutura tiver objetos mutáveis aninhados que precisam ser
  independentes: ela percorre a árvore inteira e é bem mais cara.
</Aside>

## Tuplas

A tupla é a sequência **imutável**: uma vez criada, não muda de tamanho nem de conteúdo.

### Criação e desempacotamento

Os parênteses são opcionais; o que define a tupla é a vírgula:

```python title="Tuplas e desempacotamento"
point = (10, 20)
without_parentheses = 10, 20
single = (42,)          # a vírgula é obrigatória em tupla de 1 item
not_a_tuple = (42)      # isto é apenas o número entre parênteses

print(type(single), type(not_a_tuple))

x, y = point                    # desempacotamento
first, *rest = (1, 2, 3, 4)     # com resto
print(x, y, first, rest)

# point[0] = 99                 # TypeError: 'tuple' object does not support item assignment
```

### Quando preferir tupla

A imutabilidade não é limitação: é garantia. Tuplas comunicam que o conjunto de valores é
fixo e podem ser usadas onde listas não podem:

```python title="Usos típicos"
# 1. Retorno múltiplo de função
def min_max(values):
    return min(values), max(values)


print(min_max([4, 9, 1]))

# 2. Chave de dicionário (listas não são hasheáveis)
distances = {("joao-pessoa", "recife"): 120}
print(distances[("joao-pessoa", "recife")])

# 3. Registros de tamanho fixo
rgb = (255, 128, 0)
print(f"#{rgb[0]:02x}{rgb[1]:02x}{rgb[2]:02x}")
```

<Aside type="note" title="Tupla imutável pode conter objeto mutável">
  `(1, [2, 3])` é uma tupla válida, e a lista interna continua alterável. A imutabilidade
  vale para as **referências** guardadas na tupla, não para os objetos apontados. Uma tupla
  com lista dentro deixa de ser hasheável.
</Aside>

## Dicionários

O dicionário associa **chaves únicas** a valores, com busca em tempo praticamente constante.

### Criação e acesso seguro

Acessar chave inexistente com colchetes levanta `KeyError`; `get()` devolve um padrão:

```python title="Leitura de chaves"
user = {"id": 1, "name": "Ana", "active": True}

print(user["name"])
print(user.get("email"))                 # None
print(user.get("email", "não informado"))
print("id" in user, "email" in user)

# print(user["email"])                   # KeyError: 'email'

user.setdefault("tags", []).append("admin")
print(user)
```

```txt title="Output"
Ana
None
não informado
True False
{'id': 1, 'name': 'Ana', 'active': True, 'tags': ['admin']}
```

### Alteração e remoção

Chaves são criadas por atribuição simples e removidas por `pop` ou `del`:

```python title="Escrita e remoção"
config = {"host": "localhost", "port": 5432}

config["debug"] = True          # cria
config["port"] = 3306           # atualiza
config.update({"timeout": 30, "host": "db.devlab.dev"})

removed = config.pop("debug")
del config["timeout"]

print(config, "| removido:", removed)

defaults = {"port": 5432, "ssl": False}
merged = defaults | config      # união de dicionários (3.9+)
print(merged)
```

### Iteração

Três métodos definem o que aparece no laço:

| Método | Produz |
| :--- | :--- |
| `keys()` | As chaves (padrão ao iterar direto) |
| `values()` | Os valores |
| `items()` | Pares `(chave, valor)` |

```python title="Percorrendo dicionários"
scores = {"ana": 9.5, "bia": 8.0, "caio": 7.5}

for name in scores:
    print(name, end=" ")
print()

for name, score in scores.items():
    print(f"{name:<6} {score:>5.1f}")

print(max(scores, key=scores.get))          # aluno com maior nota
print(sum(scores.values()) / len(scores))   # média
print(dict(sorted(scores.items(), key=lambda item: -item[1])))
```

## Conjuntos

O conjunto guarda elementos **únicos** e não ordenados, com teste de pertencimento muito
rápido.

### Criação e operações

Os operadores de conjunto substituem laços de comparação:

| Operação | Operador | Método |
| :--- | :--- | :--- |
| União | `a \| b` | `a.union(b)` |
| Interseção | `a & b` | `a.intersection(b)` |
| Diferença | `a - b` | `a.difference(b)` |
| Diferença simétrica | `a ^ b` | `a.symmetric_difference(b)` |
| Subconjunto | `a <= b` | `a.issubset(b)` |

```python title="Álgebra de conjuntos"
backend = {"python", "go", "sql"}
frontend = {"javascript", "css", "html"}
fullstack = {"python", "javascript", "sql"}

print(backend | frontend)
print(backend & fullstack)
print(backend - fullstack)
print(backend ^ fullstack)
print({"python"} <= backend)

empty = set()          # {} cria um dicionário vazio, não um conjunto!
print(type(empty), type({}))
```

### Remoção de duplicatas

O uso mais frequente de `set` é eliminar repetições e testar pertencimento:

```python title="Únicos e pertencimento"
visits = ["ana", "bia", "ana", "caio", "bia", "ana"]

unique = set(visits)
print(unique, len(unique))
print(sorted(unique))                     # ordem previsível para exibir

# Preservando a ordem da primeira aparição
print(list(dict.fromkeys(visits)))

banned = {"spam", "bot"}
print("bot" in banned)                    # busca rápida mesmo em conjuntos grandes
```

<Aside type="caution" title="Elementos precisam ser hasheáveis">
  Conjuntos e chaves de dicionário só aceitam objetos imutáveis (`str`, `int`, `tuple`).
  `{[1, 2]}` levanta `TypeError: unhashable type: 'list'`. Converta para tupla quando
  precisar de uma sequência como chave.
</Aside>

## Desafio

Escreva `inventory.py`, um controle de estoque que usa as quatro coleções.

1. Mantenha os produtos em um dicionário indexado pelo código (`dict`);
2. Guarde as categorias de cada produto em um conjunto (`set`);
3. Represente cada movimentação como uma tupla `(código, quantidade, tipo)` em uma lista;
4. Calcule o saldo por produto aplicando as movimentações de entrada e saída;
5. Descubra quais categorias não têm nenhum produto com saldo positivo, usando operação de conjuntos;
6. Emita um relatório com produtos em falta, saldo total e as categorias ativas.

<details>
  <summary>Possível resposta</summary>

  ```python title="inventory.py"
  PRODUCTS = {
      "TEC-01": {"name": "Teclado", "categories": {"periferico", "usb"}},
      "MON-02": {"name": "Monitor", "categories": {"video"}},
      "CAB-03": {"name": "Cabo HDMI", "categories": {"video", "cabo"}},
  }

  MOVEMENTS = [
      ("TEC-01", 10, "entrada"),
      ("TEC-01", 4, "saida"),
      ("MON-02", 3, "entrada"),
      ("MON-02", 3, "saida"),
      ("CAB-03", 7, "entrada"),
  ]

  balance = dict.fromkeys(PRODUCTS, 0)

  for code, quantity, kind in MOVEMENTS:
      balance[code] += quantity if kind == "entrada" else -quantity

  all_categories = set()
  active_categories = set()

  for code, product in PRODUCTS.items():
      all_categories |= product["categories"]
      if balance[code] > 0:
          active_categories |= product["categories"]

  print(f"{'Código':<10}{'Produto':<14}{'Saldo':>7}")
  print("-" * 32)
  for code, product in PRODUCTS.items():
      print(f"{code:<10}{product['name']:<14}{balance[code]:>7}")

  missing = [code for code, value in balance.items() if value == 0]

  print(f"\nSaldo total:        {sum(balance.values())}")
  print(f"Produtos em falta:  {', '.join(missing) or 'nenhum'}")
  print(f"Categorias ativas:  {', '.join(sorted(active_categories))}")
  print(f"Categorias paradas: {', '.join(sorted(all_categories - active_categories)) or 'nenhuma'}")
  ```
</details>

## Perguntas de revisão

### Listas e tuplas

**1. Qual a diferença entre `lista.sort()` e `sorted(lista)`?**

<details>
  <summary>Possível resposta</summary>

  `sort()` ordena a lista no lugar e devolve `None`; `sorted()` não altera o original e
  devolve uma nova lista ordenada. `sorted()` também funciona com qualquer iterável, não só
  listas.
</details>

**2. O que define uma tupla: os parênteses ou a vírgula?**

<details>
  <summary>Possível resposta</summary>

  A vírgula. `1, 2` já é uma tupla, e `(42,)` é uma tupla de um elemento — enquanto `(42)` é
  apenas o número entre parênteses. Os parênteses servem para agrupar e dar clareza.
</details>

**3. Por que uma tupla pode ser chave de dicionário e uma lista não?**

<details>
  <summary>Possível resposta</summary>

  Porque chaves precisam ser *hasheáveis*, o que exige imutabilidade. Tuplas de elementos
  imutáveis têm hash estável; listas mudam de conteúdo e por isso não podem ser usadas como
  chave.
</details>

**4. Qual a diferença entre cópia rasa e profunda?**

<details>
  <summary>Possível resposta</summary>

  A cópia rasa (`lista.copy()`, `list(lista)`, `lista[:]`) duplica apenas o primeiro nível: os
  objetos aninhados continuam compartilhados. `copy.deepcopy()` percorre toda a estrutura e
  cria cópias independentes de tudo.
</details>

### Dicionários

**5. Qual a diferença entre `user["email"]` e `user.get("email")`?**

<details>
  <summary>Possível resposta</summary>

  Com colchetes, uma chave ausente levanta `KeyError`. `get()` devolve `None` (ou o padrão
  informado) quando a chave não existe, sendo indicado para dados opcionais.
</details>

**6. Como percorrer chaves e valores ao mesmo tempo?**

<details>
  <summary>Possível resposta</summary>

  Com `for chave, valor in dicionario.items():`. Iterar diretamente sobre o dicionário produz
  apenas as chaves.
</details>

**7. Dicionários mantêm ordem?**

<details>
  <summary>Possível resposta</summary>

  Sim: desde o Python 3.7 a ordem de inserção é garantida pela linguagem. Conjuntos, por sua
  vez, não têm ordem definida.
</details>

### Conjuntos e escolha

**8. Como criar um conjunto vazio?**

<details>
  <summary>Possível resposta</summary>

  Com `set()`. As chaves vazias `{}` criam um **dicionário** vazio, não um conjunto.
</details>

**9. Qual a forma idiomática de remover duplicatas preservando a ordem?**

<details>
  <summary>Possível resposta</summary>

  `list(dict.fromkeys(itens))`, que aproveita a unicidade das chaves e a ordem de inserção
  dos dicionários. `set(itens)` remove duplicatas, mas perde a ordem.
</details>

**10. Quando um `set` é preferível a uma `list`?**

<details>
  <summary>Possível resposta</summary>

  Quando a pergunta é sobre pertencimento ou unicidade. `x in conjunto` é praticamente
  instantâneo, enquanto `x in lista` percorre os elementos; conjuntos também eliminam
  duplicatas automaticamente e oferecem união, interseção e diferença.
</details>
