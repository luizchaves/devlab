Todo programa guarda valores em algum lugar para reusá-los depois. Em Python, uma variável
não é uma caixa que contém o valor: é um **nome ligado a um objeto** na memória. Entender
essa diferença explica de uma vez o comportamento de listas compartilhadas, o resultado de
`is` versus `==` e por que somar `0.1 + 0.2` não dá exatamente `0.3`.

Esta aula percorre a atribuição, as regras de nomes, os tipos embutidos mais usados e as
conversões entre eles.

## Objetivo

Criar e reatribuir variáveis seguindo a PEP 8, explicar o modelo de referências e a
diferença entre objetos mutáveis e imutáveis, reconhecer os tipos embutidos (`int`,
`float`, `bool`, `str`, `None`), converter valores entre tipos de forma explícita,
identificar valores *truthy* e *falsy* e ler anotações de tipo.

## Atribuição e Nomes

A atribuição usa `=` e não exige declaração prévia nem palavra-chave como `let` ou `var`.

```python title="Atribuição básica"
name = "DevLab"      # str
attempts = 3         # int
price = 19.90        # float
is_active = True     # bool
result = None        # NoneType

attempts = attempts + 1
print(name, attempts, price, is_active, result)
```

```txt title="Output"
DevLab 4 19.9 True None
```

## Regras e Convenções de Nomes

O interpretador impõe poucas regras para nomes válidos; o restante é convenção de estilo:

| Regra | Exemplo válido | Exemplo inválido |
| :--- | :--- | :--- |
| Começa com letra ou `_` | `total`, `_cache` | `2total` |
| Só letras, dígitos e `_` | `user_name` | `user-name` |
| Diferencia maiúsculas | `Total` e `total` são nomes distintos | — |
| Não pode ser palavra reservada | `class_` | `class` |

A PEP 8 padroniza o estilo dos nomes:

| Elemento | Convenção | Exemplo |
| :--- | :--- | :--- |
| Variáveis e funções | `snake_case` | `total_price`, `read_file()` |
| Constantes | `UPPER_SNAKE_CASE` | `TAX_RATE`, `MAX_RETRIES` |
| Classes | `PascalCase` | `InvoiceItem` |
| Uso interno | prefixo `_` | `_cache`, `_helper()` |

<Aside type="caution" title="Constante é convenção, não garantia">
  Python não tem `const`. Escrever `TAX_RATE = 0.1` em maiúsculas comunica a intenção de
  não reatribuir, mas o interpretador permite alterar o valor. A disciplina é do time, não
  da linguagem.
</Aside>

```python title="Palavras reservadas"
import keyword

print(len(keyword.kwlist))
print(keyword.kwlist[:8])
```

```txt title="Output"
35
['False', 'None', 'True', 'and', 'as', 'assert', 'async', 'await']
```

## O Modelo de Referências

Em Python, **tudo é objeto**. A atribuição cria um vínculo entre um nome e um objeto que já
existe na memória. Reatribuir um nome não altera o objeto: apenas aponta o nome para outro.

```python title="Nomes e objetos"
a = [1, 2, 3]
b = a           # b referencia o MESMO objeto

b.append(4)
print(a)        # [1, 2, 3, 4] — a mudança é visível pelos dois nomes
print(a is b)   # True — mesmo objeto na memória

b = [9, 9]      # agora b aponta para outro objeto
print(a)        # [1, 2, 3, 4]
print(a is b)   # False
```

### `is` versus `==`

Os dois operadores parecem sinônimos em testes rápidos, mas respondem a perguntas diferentes:

| Operador | Compara | Pergunta que responde |
| :--- | :--- | :--- |
| `==` | Valor | "Os conteúdos são iguais?" |
| `is` | Identidade | "É o mesmo objeto na memória?" |

```python title="Igualdade e identidade"
x = [1, 2]
y = [1, 2]

print(x == y)        # True  — mesmo conteúdo
print(x is y)        # False — objetos diferentes
print(id(x) == id(y))  # False

value = None
print(value is None)  # forma idiomática de testar None
```

<Aside type="caution" title="Use is apenas para None, True e False">
  `is` compara identidade. Para valores, use `==`. Comparar números ou strings com `is`
  pode funcionar por acaso (o CPython reaproveita objetos pequenos) e falhar em outro
  contexto.
</Aside>

### Mutável e imutável

A distinção entre tipos mutáveis e imutáveis explica quando uma alteração é visível por outros nomes ligados ao mesmo objeto:

| Categoria | Tipos | Efeito |
| :--- | :--- | :--- |
| **Imutáveis** | `int`, `float`, `bool`, `str`, `tuple`, `frozenset` | Qualquer "alteração" cria um novo objeto |
| **Mutáveis** | `list`, `dict`, `set`, objetos de classes | Podem ser alterados no lugar |

```python title="Imutabilidade na prática"
text = "python"
upper = text.upper()

print(text)   # 'python' — o original não muda
print(upper)  # 'PYTHON' — novo objeto

numbers = [1, 2, 3]
numbers.append(4)  # altera o próprio objeto
print(numbers)     # [1, 2, 3, 4]
```

## Tipos Numéricos

Python embute três tipos numéricos, todos imutáveis:

| Tipo | Descrição | Literal |
| :--- | :--- | :--- |
| `int` | Inteiro de precisão arbitrária | `42`, `-7`, `1_000_000` |
| `float` | Ponto flutuante de dupla precisão (IEEE 754) | `3.14`, `2e-3` |
| `complex` | Número complexo | `3 + 4j` |

```python title="Inteiros sem limite de tamanho"
big = 2 ** 200
print(big)
print(len(str(big)), "dígitos")

# Separador visual em literais longos
population = 8_100_000_000
print(population)
```

```txt title="Output"
1606938044258990275541962092341162602522202993782792835301376
61 dígitos
8100000000
```

<Aside type="tip" title="int não estoura">
  Diferente de C ou Java, `int` em Python cresce conforme necessário — limitado apenas pela
  memória disponível. Não existe `long`, nem overflow silencioso.
</Aside>

## Precisão de Ponto Flutuante

Como `float` segue o padrão IEEE 754, frações decimais simples não têm representação exata em binário:

```python title="IEEE 754 em ação"
print(0.1 + 0.2)              # 0.30000000000000004
print(0.1 + 0.2 == 0.3)       # False
print(round(0.1 + 0.2, 2))    # 0.3

from decimal import Decimal
print(Decimal("0.1") + Decimal("0.2"))       # 0.3
print(Decimal("0.1") + Decimal("0.2") == Decimal("0.3"))  # True
```

<Aside type="caution" title="Nunca use float para dinheiro">
  Valores monetários exigem `Decimal` (com os literais em **string**) ou aritmética em
  centavos usando `int`. `float` acumula erro de arredondamento em somas repetidas.
</Aside>

## Booleanos, `None` e valores *truthy*

`bool` é subtipo de `int`: `True` vale `1` e `False` vale `0`.

```python title="Booleanos são inteiros"
print(True + True)     # 2
print(isinstance(True, int))  # True
```

Qualquer objeto pode ser avaliado em contexto booleano. São **falsy**:

| Falsy | Exemplo |
| :--- | :--- |
| Zero numérico | `0`, `0.0`, `Decimal("0")` |
| Sequências e coleções vazias | `""`, `[]`, `()`, `{}`, `set()` |
| Ausência de valor | `None` |
| `False` | `False` |

```python title="Truthy e falsy"
values = [0, 1, "", "texto", [], [0], None, {}]

for value in values:
    print(f"{str(value):<8} -> {bool(value)}")
```

```txt title="Output"
0        -> False
1        -> True
         -> False
texto    -> True
[]       -> False
[0]      -> True
None     -> False
{}       -> False
```

<Aside type="note" title="None não é zero, nem string vazia">
  `None` é o único valor do tipo `NoneType` e representa "ausência de valor". Funções que
  não usam `return` devolvem `None` implicitamente. Teste com `if value is None:`, e não
  com `if not value:` — este último também captura `0` e `""`.
</Aside>

## Conversão de Tipos

Como a tipagem é forte, a conversão precisa ser explícita.

| Função | Converte para | Exemplo |
| :--- | :--- | :--- |
| `int(x)` | Inteiro (trunca floats) | `int("42")`, `int(3.9)` → `3` |
| `float(x)` | Ponto flutuante | `float("3.14")` |
| `str(x)` | Texto | `str(42)` → `"42"` |
| `bool(x)` | Booleano | `bool("")` → `False` |
| `list(x)` | Lista a partir de um iterável | `list("abc")` |

```python title="Conversões e entrada do usuário"
raw = input("Quantidade: ")   # input() SEMPRE devolve str
quantity = int(raw)

price = float("19.90")
total = quantity * price

print(f"Total: R$ {total:.2f}")
print(int(3.99))     # 3 — trunca, não arredonda
print(round(3.99))   # 4 — arredonda
print(int("0b1010", 0))  # 10 — interpreta a base pelo prefixo
```

<Aside type="caution" title="int() falha em texto não numérico">
  `int("abc")` levanta `ValueError: invalid literal for int() with base 10: 'abc'`. Entradas
  vindas do usuário ou de arquivos devem ser validadas — veja
  [Erros e Exceções](../../structure/errors/).
</Aside>

## Atribuições Múltiplas e Especiais

Além da atribuição simples, a linguagem oferece formas que encurtam trocas, desempacotamentos e acumulações:

```python title="Formas de atribuição"
# Múltipla
x, y, z = 1, 2, 3

# Troca sem variável auxiliar
x, y = y, x

# Mesmo valor para vários nomes
a = b = c = 0

# Desempacotamento com resto
first, *rest = [10, 20, 30, 40]
print(first, rest)   # 10 [20, 30, 40]

# Atribuição aumentada
total = 10
total += 5    # equivale a total = total + 5
print(total)  # 15

# Operador morsa (:=) — atribui dentro da expressão
if (size := len("DevLab")) > 3:
    print(f"Nome com {size} caracteres")
```

```txt title="Output"
10 [20, 30, 40]
15
Nome com 6 caracteres
```

## Anotações de Tipo

Anotações documentam a intenção e alimentam ferramentas de análise estática. Elas **não**
são verificadas em tempo de execução.

```python title="Anotações (PEP 484)"
name: str = "DevLab"
attempts: int = 0
price: float = 19.9
tags: list[str] = ["python", "guia"]
nickname: str | None = None


def total(price: float, quantity: int = 1) -> float:
    return price * quantity


print(total(19.9, 3))
print(total.__annotations__)
```

```txt title="Output"
59.699999999999996
{'price': <class 'float'>, 'quantity': <class 'int'>, 'return': <class 'float'>}
```

<Aside type="tip" title="Anotação não impede erro">
  `attempts: int = "três"` executa normalmente. Quem verifica a coerência são ferramentas
  externas como `mypy`, `pyright` ou o editor. A anotação vale como documentação executável.
</Aside>

## Desafio

Escreva `money.py` demonstrando por que `float` não serve para dinheiro.

1. Some `0.1` dez vezes com `float` e compare o resultado com `1.0`;
2. Repita a soma usando `Decimal` com literais em string;
3. Repita usando aritmética em centavos com `int`;
4. Imprima uma tabela comparando os três resultados e a igualdade com o valor esperado;
5. Conclua em um comentário qual abordagem usar em um sistema de vendas.

<details>
  <summary>Possível resposta</summary>

  ```python title="money.py"
  from decimal import Decimal

  EXPECTED = 1.0

  float_total = 0.0
  for _ in range(10):
      float_total += 0.1

  decimal_total = Decimal("0")
  for _ in range(10):
      decimal_total += Decimal("0.1")

  cents_total = 0
  for _ in range(10):
      cents_total += 10  # 10 centavos

  print(f"{'Abordagem':<12} {'Resultado':<24} {'Igual a 1.0?'}")

  print(f"{'Decimal':<12} {str(decimal_total):<24} {decimal_total == Decimal('1.0')}")
  print(f"{'int (centavos)':<12} {cents_total / 100!r:<24} {cents_total == 100}")
  ```

## Perguntas de revisão

### Nomes e referências

**1. O que acontece na memória ao executar `a = [1, 2]` seguido de `b = a`?**

<details>
  <summary>Possível resposta</summary>

  Um único objeto lista é criado, e os dois nomes passam a referenciá-lo. Alterações feitas
  por `b` (como `b.append(3)`) são visíveis por `a`, porque não existem duas listas — existe
  uma lista com dois nomes.
</details>

**2. Qual a diferença entre `==` e `is`?**

<details>
  <summary>Possível resposta</summary>

  `==` compara o conteúdo dos objetos; `is` compara identidade, ou seja, se os dois nomes
  apontam para o mesmo objeto na memória. Na prática, `is` só deve ser usado com `None`,
  `True` e `False`.
</details>

**3. Python tem constantes?**

<details>
  <summary>Possível resposta</summary>

  Não no nível da linguagem. A convenção é escrever o nome em `UPPER_SNAKE_CASE` para
  indicar que o valor não deve ser reatribuído, mas o interpretador permite a mudança.
</details>

### Tipos e conversões

**4. Por que `0.1 + 0.2 == 0.3` é `False`?**

<details>
  <summary>Possível resposta</summary>

  Porque `float` segue o padrão IEEE 754 (binário), e frações decimais como `0.1` não têm
  representação exata em base 2. A soma acumula um erro mínimo, resultando em
  `0.30000000000000004`. Para valores exatos, use `Decimal` ou inteiros em centavos.
</details>

**5. Qual a diferença entre `int(3.99)` e `round(3.99)`?**

<details>
  <summary>Possível resposta</summary>

  `int()` trunca a parte decimal e devolve `3`. `round()` arredonda para o inteiro mais
  próximo e devolve `4`.
</details>

**6. `input()` devolve qual tipo? Qual a consequência?**

<details>
  <summary>Possível resposta</summary>

  Sempre `str`. Para cálculos é preciso converter com `int()` ou `float()`; caso contrário,
  `"10" * 2` produz `"1010"` em vez de `20`.
</details>

**7. Quais valores são considerados *falsy* em Python?**

<details>
  <summary>Possível resposta</summary>

  `False`, `None`, zero de qualquer tipo numérico (`0`, `0.0`), sequências e coleções vazias
  (`""`, `[]`, `()`, `{}`, `set()`) e objetos cujo `__bool__` ou `__len__` devolva falso.
</details>

### Mutabilidade e anotações

**8. Quais tipos embutidos são imutáveis?**

<details>
  <summary>Possível resposta</summary>

  `int`, `float`, `complex`, `bool`, `str`, `tuple`, `frozenset` e `bytes`. Operações que
  parecem alterá-los, como `text.upper()`, na verdade devolvem um novo objeto.
</details>

**9. Por que `bool` é considerado um subtipo de `int`?**

<details>
  <summary>Possível resposta</summary>

  Porque `True` e `False` se comportam como `1` e `0` em contexto numérico:
  `True + True` resulta em `2` e `isinstance(True, int)` é `True`. Isso permite somar
  booleanos para contar ocorrências.
</details>

**10. Uma anotação como `age: int = "vinte"` gera erro em execução?**

<details>
  <summary>Possível resposta</summary>

  Não. Anotações de tipo são metadados: ficam disponíveis em `__annotations__` e são
  verificadas por ferramentas externas (`mypy`, `pyright`), mas o interpretador executa o
  código normalmente.
</details>
