Todo programa guarda valores para reutilizá-los depois. Em Python, uma variável não é uma
caixa que contém o valor: é um **nome ligado a um objeto** na memória.

Essa diferença explica por que duas variáveis podem enxergar a mesma lista, por que `is` e
`==` respondem a perguntas diferentes e por que uma "constante" em Python é uma convenção
do time, não uma proteção do interpretador.

## Objetivo

Criar e reatribuir variáveis seguindo a PEP 8, diferenciar nome de objeto, explicar o modelo
de referências, usar `is` e `==` corretamente, reconhecer quando uma operação muta um objeto
existente e ler anotações de tipo como documentação estática.

## Atribuição e Nomes

A atribuição usa `=` e não exige declaração prévia. O nome passa a apontar para o objeto
produzido pela expressão do lado direito.

```python title="Atribuição básica"
name = "DevLab"
attempts = 3
price = 19.90
is_active = True
result = None

attempts = attempts + 1
print(name, attempts, price, is_active, result)
```

```txt title="Output"
DevLab 4 19.9 True None
```

Reatribuir um nome não edita o objeto anterior. O nome simplesmente passa a apontar para
outro objeto.

```python title="Reatribuição"
status = "draft"
print(status) # draft

status = "published"
print(status) # published
```

<Aside type="note" title="Variável é nome, valor é objeto">
  Em Python, valores como números, strings, listas e dicionários são objetos. A variável é
  apenas o nome usado para encontrar aquele objeto durante a execução.
</Aside>

## Regras e Convenções de Nomes

O interpretador impõe poucas regras para nomes válidos; o restante é convenção de estilo.

| Regra | Exemplo válido | Exemplo inválido |
| :--- | :--- | :--- |
| Começa com letra ou `_` | `total`, `_cache` | `2total` |
| Só letras, dígitos e `_` | `user_name` | `user-name` |
| Diferencia maiúsculas | `Total` e `total` são nomes distintos | — |
| Não pode ser palavra reservada | `class_` | `class` |

A PEP 8 padroniza o estilo dos nomes em projetos Python:

| Elemento | Convenção | Exemplo |
| :--- | :--- | :--- |
| Variáveis e funções | `snake_case` | `total_price`, `read_file()` |
| Constantes | `UPPER_SNAKE_CASE` | `TAX_RATE`, `MAX_RETRIES` |
| Classes | `PascalCase` | `InvoiceItem` |
| Uso interno | prefixo `_` | `_cache`, `_helper()` |

<Aside type="caution" title="Constante é convenção, não garantia">
  Python não tem `const`. Escrever `TAX_RATE = 0.1` em maiúsculas comunica a intenção de
  não reatribuir, mas o interpretador permite alterar o valor.
</Aside>

O módulo `keyword` mostra as palavras reservadas da versão instalada.

```python title="Palavras reservadas"
import keyword

print(len(keyword.kwlist))
print(keyword.kwlist[:8])
```

```txt title="Output"
35
['False', 'None', 'True', 'and', 'as', 'assert', 'async', 'await']
```

## O Modelo de Referências

Em Python, **tudo é objeto**. A atribuição cria um vínculo entre um nome e um objeto que já
existe na memória. Reatribuir um nome não altera o objeto anterior: apenas aponta o nome para
outro objeto.

```python title="Nomes e objetos"
a = [1, 2, 3]
b = a           # b referencia o MESMO objeto

b.append(4)
print(a)        # [1, 2, 3, 4]
print(a is b)   # True

b = [9, 9]      # agora b aponta para outro objeto
print(a)        # [1, 2, 3, 4]
print(a is b)   # False
```

### `is` versus `==`

Os dois operadores parecem sinônimos em testes rápidos, mas respondem a perguntas diferentes:

| Operador | Compara | Pergunta que responde |
| :--- | :--- | :--- |
| `==` | Valor | "Os conteúdos são iguais?" |
| `is` | Identidade | "É o mesmo objeto na memória?" |

```python title="Igualdade e identidade"
x = [1, 2]
y = [1, 2]

print(x == y) # True: mesmo conteúdo
print(x is y) # False: objetos diferentes

value = None
print(value is None) # forma idiomática de testar None
```

<Aside type="caution" title="Use is para identidade">
  `is` compara identidade. Para valores comuns, use `==`. O uso idiomático mais frequente de
  `is` é testar singletons como `None`, `True` e `False`.
</Aside>

### Mutação versus reatribuição

A distinção entre mutar um objeto e reatribuir um nome é essencial quando listas, dicionários
e conjuntos são compartilhados entre variáveis.

```python title="Mutação e reatribuição"
numbers = [1, 2]
alias = numbers

alias.append(3)      # muta o mesmo objeto
print(numbers)       # [1, 2, 3]

alias = [10, 20]     # reatribui apenas o nome alias
print(numbers)       # [1, 2, 3]
print(alias)         # [10, 20]
```

Objetos imutáveis não mudam no lugar. Operações com strings, números e tuplas produzem novos
objetos.

```python title="Imutabilidade na prática"
text = "python"
upper = text.upper()

print(text)  # python
print(upper) # PYTHON
```

<Aside type="tip" title="Mutável não significa ruim">
  Listas e dicionários são mutáveis porque isso é útil. O cuidado é saber quando uma função
  altera o objeto recebido e quando devolve uma nova estrutura.
</Aside>

## Atribuições Múltiplas e Especiais

Além da atribuição simples, Python oferece formas que encurtam trocas, desempacotamentos e
acumulações.

```python title="Formas de atribuição"
# Múltipla
x, y, z = 1, 2, 3

# Troca sem variável auxiliar
x, y = y, x

# Mesmo valor para vários nomes
a = b = c = 0

# Desempacotamento com resto
first, *rest = [10, 20, 30, 40]
print(first, rest) # 10 [20, 30, 40]

# Atribuição aumentada
total = 10
total += 5
print(total) # 15

# Operador morsa (:=): atribui dentro da expressão
if (size := len("DevLab")) > 3:
    print(f"Nome com {size} caracteres")
```

```txt title="Output"
10 [20, 30, 40]
15
Nome com 6 caracteres
```

<Aside type="note" title="Use atalhos quando melhorarem a leitura">
  Desempacotamento e troca de valores são idiomáticos em Python. Já o operador `:=` deve ser
  usado com moderação, quando evita repetição sem esconder a intenção.
</Aside>

## Anotações de Tipo

Anotações documentam a intenção e alimentam ferramentas de análise estática. Elas **não** são
verificadas em tempo de execução pelo interpretador padrão.

```python title="Anotações (PEP 484)"
name: str = "DevLab"
attempts: int = 0
tags: list[str] = ["python", "guia"]
nickname: str | None = None


def total(price: float, quantity: int = 1) -> float:
    return price * quantity


print(total(19.9, 3))
print(total.__annotations__)
```

```txt title="Output"
59.699999999999996
{'price': <class 'float'>, 'quantity': <class 'int'>, 'return': <class 'float'>}
```

<Aside type="tip" title="Anotação não impede erro">
  `attempts: int = "três"` executa normalmente. Quem verifica a coerência são ferramentas
  externas como `mypy`, `pyright` ou o editor.
</Aside>

## Exercício

Crie um arquivo `references.py` para praticar nomes e referências.

1. Declare uma lista `original` com três números;
2. Crie `alias = original`;
3. Adicione um novo número usando `alias.append()`;
4. Mostre que `original` também mudou;
5. Crie `copy = original.copy()`;
6. Altere `copy` e mostre que `original` não mudou;
7. Compare `original == copy` e `original is copy`;
8. Use uma constante por convenção chamada `MAX_ATTEMPTS`.

<details>
  <summary>Possível resposta</summary>

  ```python title="references.py"
  MAX_ATTEMPTS = 3

  original = [1, 2, 3]
  alias = original

  alias.append(4)
  print(original) # [1, 2, 3, 4]
  print(original is alias) # True

  copy = original.copy()
  copy.append(5)

  print(original) # [1, 2, 3, 4]
  print(copy) # [1, 2, 3, 4, 5]
  print(original == copy) # False
  print(original is copy) # False
  print(MAX_ATTEMPTS) # 3
  ```
</details>

## Desafio

Escreva uma função `add_tag(tags, tag)` que deixe claro se ela muta a lista recebida ou
devolve uma nova lista. Depois implemente as duas versões e compare o efeito.

<details>
  <summary>Possível resposta</summary>

  ```python title="mutation-vs-copy.py"
  def add_tag_in_place(tags: list[str], tag: str) -> None:
      tags.append(tag)


  def add_tag_copy(tags: list[str], tag: str) -> list[str]:
      return [*tags, tag]


  original = ["python"]

  add_tag_in_place(original, "variables")
  print(original) # ['python', 'variables']

  next_tags = add_tag_copy(original, "types")
  print(original)  # ['python', 'variables']
  print(next_tags) # ['python', 'variables', 'types']
  ```
</details>

## Perguntas de revisão

### Nomes e referências

**1. O que acontece ao executar `b = a` quando `a` referencia uma lista?**

<details>
  <summary>Possível resposta</summary>

  Nenhuma lista nova é criada. `b` passa a apontar para o mesmo objeto lista referenciado por
  `a`.
</details>

**2. Qual é a diferença entre reatribuição e mutação?**

<details>
  <summary>Possível resposta</summary>

  Reatribuição troca o objeto apontado por um nome. Mutação altera o conteúdo de um objeto
  existente.
</details>

**3. Quando usar `is` em vez de `==`?**

<details>
  <summary>Possível resposta</summary>

  Use `is` para identidade, especialmente com `None`. Para comparar conteúdo, use `==`.
</details>

### Convenções e anotações

**4. Python tem uma palavra-chave equivalente a `const`?**

<details>
  <summary>Possível resposta</summary>

  Não. Constantes são indicadas por convenção com `UPPER_SNAKE_CASE`, mas o interpretador não
  impede reatribuição.
</details>

**5. Por que usar `snake_case` em variáveis e funções?**

<details>
  <summary>Possível resposta</summary>

  Porque é a convenção recomendada pela PEP 8 e facilita a leitura consistente em projetos
  Python.
</details>

**6. Anotações de tipo são validação em runtime?**

<details>
  <summary>Possível resposta</summary>

  Não. Elas servem para documentação e ferramentas de análise estática. O interpretador não
  bloqueia automaticamente um valor incompatível.
</details>
