Antes de escrever laços, funções ou classes, vale entender o que é Python, quem cuida da
linguagem, como o código sai do arquivo de texto e vira execução, e onde ela é usada hoje.
Python não é apenas "a linguagem de scripts": ela roda em automações de terminal, análise
de dados, APIs web, jogos, dispositivos embarcados e infraestrutura em nuvem.

Este tópico prepara o terreno: instala o interpretador, apresenta o modo interativo (REPL),
mostra como executar um arquivo `.py` e explica as características que diferenciam Python
de linguagens como JavaScript, Java ou C.

## Objetivo

Entender a origem e o modelo de evolução do Python, diferenciar linguagem de implementação
(CPython, PyPy, MicroPython), reconhecer as características fundamentais da linguagem,
instalar e verificar o interpretador com `uv`, usar o REPL para experimentar e executar o
primeiro script a partir do terminal.

## Por Que Python Importa?

Python se consolidou como uma das linguagens mais usadas do mundo por combinar sintaxe
enxuta com uma biblioteca padrão ampla — a filosofia conhecida como *batteries included*.
Escrever um script que lê um arquivo, filtra linhas e gera um relatório costuma exigir
poucas linhas e nenhuma dependência externa.

- **Automação e scripts**: renomear arquivos em lote, consumir uma API, gerar planilhas.
- **Dados e ciência**: `pandas`, `NumPy`, `matplotlib` e todo o ecossistema científico.
- **Inteligência artificial**: PyTorch, scikit-learn e a maior parte das bibliotecas de
  aprendizado de máquina expõem API em Python.
- **Web e APIs**: Django, Flask e FastAPI para servidores HTTP.
- **Infraestrutura**: Ansible, AWS CLI e ferramentas de automação de nuvem.
- **Ensino**: sintaxe próxima do pseudocódigo, o que reduz o ruído ao aprender lógica.

<Aside type="note" title="Sintaxe legível é um requisito de projeto">
  A PEP 20 (*O Zen do Python*) resume a filosofia da linguagem em aforismos como
  "legibilidade conta" e "explícito é melhor que implícito". Isso explica escolhas de
  sintaxe que surpreendem quem vem de outras linguagens, como usar **indentação** no lugar
  de chaves para delimitar blocos.
</Aside>

## Origem e Evolução

Python foi criado por **Guido van Rossum** no CWI, na Holanda, e teve sua primeira versão
pública (0.9.0) publicada em **fevereiro de 1991**. O nome não vem da cobra: é uma
homenagem ao grupo de humor britânico *Monty Python's Flying Circus*.

| Marco | Ano | O que mudou |
| :--- | :--- | :--- |
| **Python 0.9.0** | 1991 | Primeira versão pública, já com funções, exceções e os tipos básicos |
| **Python 2.0** | 2000 | *List comprehensions* e coletor de lixo com detecção de ciclos |
| **Python 3.0** | 2008 | Quebra intencional de compatibilidade: `print()` como função, texto Unicode por padrão |
| **Fim do Python 2** | 2020 | O Python 2.7 deixou de receber correções; hoje só existe Python 3 |
| **Python 3.10** | 2021 | `match`/`case` (*structural pattern matching*) e união de tipos com `|` |
| **Python 3.12** | 2023 | Sintaxe mais livre em f-strings e nova sintaxe de tipos genéricos |
| **Python 3.14** | 2025 | Versão de referência deste guia |

<Aside type="caution" title="Python 2 é história, não opção">
  Tutoriais antigos usam `print "texto"` sem parênteses e `raw_input()`. Esse código é
  Python 2 e **não executa** em Python 3. Ao pesquisar, confira sempre a data e a versão
  do material.
</Aside>

## O Processo de PEPs

A evolução da linguagem acontece por **PEPs** (*Python Enhancement Proposals*): documentos
públicos que descrevem uma proposta, sua motivação, alternativas consideradas e o efeito
sobre o código existente. Uma PEP é discutida pela comunidade e aprovada pelo *Steering
Council*, eleito anualmente entre os desenvolvedores do núcleo.

| PEP | Assunto | Por que importa |
| :--- | :--- | :--- |
| **PEP 8** | Guia de estilo | Define a formatação idiomática (4 espaços, `snake_case`, limite de linha) |
| **PEP 20** | O Zen do Python | Princípios de projeto da linguagem |
| **PEP 257** | Docstrings | Convenção de documentação embutida no código |
| **PEP 484** | Anotações de tipo | Base do `typing` e das ferramentas de checagem estática |
| **PEP 572** | Operador `:=` | Atribuição dentro de expressões (*walrus*) |
| **PEP 634** | `match`/`case` | Casamento de padrões estruturais |

<Aside type="tip" title="Leia o Zen no próprio interpretador">
  Abra o REPL e digite `import this`. A PEP 20 é impressa como um *easter egg* embutido
  na biblioteca padrão.
</Aside>

## Linguagem, Implementação e Interpretador

Assim como ECMAScript é a especificação e V8 é uma implementação, Python tem uma
*referência de linguagem* e várias implementações. A implementação oficial e mais usada é
o **CPython**, escrita em C — é o que você instala em [python.org](https://www.python.org/).

| Implementação | Escrita em | Uso típico |
| :--- | :--- | :--- |
| **CPython** | C | Implementação de referência; o padrão em qualquer instalação |
| **PyPy** | RPython | Execução mais rápida via compilação JIT em cargas de CPU |
| **MicroPython** | C | Microcontroladores (ESP32, Raspberry Pi Pico) |
| **Jython** / **IronPython** | Java / C# | Integração com a JVM e com o .NET |

O CPython **compila** o código-fonte para *bytecode* (arquivos `.pyc` em `__pycache__/`) e
executa esse bytecode em uma máquina virtual. Por isso Python é chamado de interpretado:
não existe binário nativo no fim do processo, e sim uma execução mediada pelo interpretador.

<Mermaid title="Do código-fonte à saída no terminal">
{`
flowchart LR
  A["main.py<br/>código-fonte"] --> B["Compilação<br/>automática"]
  B --> C["Bytecode .pyc<br/>__pycache__/"]
  C --> D["Máquina Virtual<br/>CPython"]
  D --> E["Saída no terminal"]
`}
</Mermaid>

<Aside type="note" title="__pycache__ não vai para o repositório">
  O diretório `__pycache__/` é gerado automaticamente para acelerar execuções seguintes.
  Ele é derivado do código-fonte e deve entrar no `.gitignore`.
</Aside>

## Características da Linguagem

As decisões de projeto do Python aparecem em um conjunto de características que explicam boa parte do comportamento da linguagem no dia a dia:

| Característica | O que significa na prática |
| :--- | :--- |
| **Interpretada** | Não há passo manual de compilação: `python3 main.py` executa direto |
| **Tipagem dinâmica** | O tipo pertence ao valor; a variável só guarda uma referência |
| **Tipagem forte** | `"1" + 1` levanta `TypeError` em vez de converter silenciosamente |
| **Indentação significativa** | Blocos são delimitados por recuo, não por chaves |
| **Multiparadigma** | Suporta código imperativo, funcional e orientado a objetos |
| **Tudo é objeto** | Números, funções, módulos e classes têm atributos e métodos |
| **Gerência de memória** | Contagem de referências + coletor de ciclos; não existe `free()` |
| **Biblioteca padrão ampla** | JSON, HTTP, CSV, datas, regex e testes sem instalar nada |

```python title="Tipagem dinâmica e forte"
value = 42          # int
value = "quarenta"  # a mesma variável passa a referenciar uma str

print(type(value))  # <class 'str'>

# Tipagem forte: a conversão precisa ser explícita
total = "1" + 1     # TypeError: can only concatenate str (not "int") to str
total = int("1") + 1
print(total)        # 2
```

<Aside type="caution" title="Dinâmica não é fraca">
  JavaScript é dinâmico **e** fraco: `"1" + 1` resulta em `"11"`. Python é dinâmico e
  **forte**: a mesma expressão levanta `TypeError`. A conversão precisa ser pedida com
  `int()`, `float()` ou `str()`.
</Aside>

## O Modo Interativo (REPL)

O REPL (*Read–Eval–Print Loop*) avalia uma expressão por vez e imprime o resultado. É o
lugar certo para testar uma dúvida rápida sobre um método ou sobre um tipo.

```bash title="Terminal"
uv run python
```

```txt title="Sessão interativa"
>>> 2 + 3 * 4
14
>>> name = "DevLab"
>>> f"Olá, {name}!"
'Olá, DevLab!'
>>> len(name)
6
>>> help(str.upper)
>>> exit()
```

| Recurso do REPL | Para que serve |
| :--- | :--- |
| `_` | Guarda o resultado da última expressão avaliada |
| `help(objeto)` | Abre a documentação embutida (`q` sai) |
| `dir(objeto)` | Lista atributos e métodos disponíveis |
| `type(objeto)` | Mostra o tipo do valor |
| `exit()` ou <kbd>Ctrl</kbd>+<kbd>D</kbd> | Encerra a sessão |

<Aside type="tip" title="O REPL imprime, o script não">
  No REPL, digitar `2 + 3` já mostra `5`. Dentro de um arquivo `.py`, a mesma linha calcula
  o valor e o descarta — para ver algo no terminal é preciso `print()`.
</Aside>

## Estrutura de um Programa

Um arquivo Python típico combina docstring de módulo, constantes, funções e um bloco de execução protegido. O exemplo a seguir reúne todos esses elementos:

```python title="main.py"
"""Relatório de vendas do dia.

Este texto é a docstring do módulo (PEP 257) e aparece em help(main).
"""

# Comentário de linha: explica a intenção, não repete o código.
TAX_RATE = 0.1  # constantes por convenção em MAIÚSCULAS


def total_with_tax(amount):
    """Devolve o valor com o imposto aplicado."""
    return amount * (1 + TAX_RATE)


def main():
    sales = [120.0, 89.9, 340.5]
    total = sum(total_with_tax(value) for value in sales)
    print(f"Total com imposto: R$ {total:.2f}")


if __name__ == "__main__":
    main()
```

```txt title="Output"
Total com imposto: R$ 605.44
```

O bloco `if __name__ == "__main__":` só executa quando o arquivo é rodado diretamente.
Se o mesmo arquivo for importado por outro módulo, as funções ficam disponíveis sem
disparar a execução — o assunto volta em
[Módulos e Pacotes](../../structure/modules/).

<Aside type="caution" title="Indentação é sintaxe">
  Misturar tabulações e espaços, ou recuar com quantidades diferentes dentro do mesmo
  bloco, levanta `IndentationError` ou `TabError`. A PEP 8 pede **4 espaços** por nível —
  configure o editor para converter <kbd>Tab</kbd> em espaços.
</Aside>

## Exercício

Crie um arquivo `profile.py` que se apresente e mostre informações do ambiente.

1. Peça o nome e a cidade da pessoa com `input()`;
2. Guarde o ano de nascimento e calcule a idade aproximada usando um valor fixo para o ano atual;
3. Imprima uma frase de apresentação usando f-string;
4. Importe o módulo `sys` e mostre a versão do Python e a plataforma (`sys.platform`);
5. Use `type()` para mostrar o tipo de cada variável criada;
6. Proteja a execução com `if __name__ == "__main__":`.

<details>
  <summary>Possível resposta</summary>

  ```python title="profile.py"
  import sys

  CURRENT_YEAR = 2026


  def main():
      name = input("Nome: ")
      city = input("Cidade: ")
      birth_year = int(input("Ano de nascimento: "))
      age = CURRENT_YEAR - birth_year

      print(f"{name}, de {city}, tem cerca de {age} anos.")
      print(f"Python {sys.version_info.major}.{sys.version_info.minor} em {sys.platform}")

      print(type(name), type(birth_year), type(age))


  if __name__ == "__main__":
      main()
  ```

  `input()` sempre devolve `str`; por isso o ano precisa de `int()` antes da subtração.
</details>

## Desafio

Escreva `env_report.py`, um relatório do ambiente de execução em uma única tela.

1. Mostre a versão completa do interpretador e o caminho do executável (`sys.executable`);
2. Mostre o diretório de trabalho atual usando o módulo `os`;
3. Liste os três primeiros caminhos de busca de módulos (`sys.path`);
4. Calcule e mostre quantos módulos já estão carregados (`sys.modules`);
5. Formate a saída com títulos e alinhamento, sem bibliotecas externas.

<details>
  <summary>Possível resposta</summary>

  ```python title="env_report.py"
  import os
  import sys


  def line(label, value):
      print(f"{label:<22} {value}")


  def main():
      print("=" * 60)
      print("RELATÓRIO DO AMBIENTE PYTHON")
      print("=" * 60)

      line("Versão:", sys.version.split()[0])
      line("Executável:", sys.executable)
      line("Plataforma:", sys.platform)
      line("Diretório atual:", os.getcwd())
      line("Módulos carregados:", len(sys.modules))

      print("\nCaminhos de busca (3 primeiros):")
      for path in sys.path[:3]:
          print(f"  - {path or '(diretório atual)'}")


  if __name__ == "__main__":
      main()
  ```

  `f"{label:<22}"` alinha o rótulo à esquerda em 22 colunas — o mesmo mini-idioma de
  formatação usado em [Strings](../../data/strings/).
</details>

## Perguntas de revisão

### Linguagem e implementação

**1. Qual é a diferença entre Python e CPython?**

<details>
  <summary>Possível resposta</summary>

  Python é a linguagem, descrita pela referência oficial e evoluída por PEPs. CPython é a
  implementação de referência dessa linguagem, escrita em C — a que você instala por
  padrão. PyPy, MicroPython e Jython são outras implementações da mesma linguagem.
</details>

**2. Se Python é interpretado, por que existem arquivos `.pyc`?**

<details>
  <summary>Possível resposta</summary>

  O CPython compila o código-fonte para *bytecode* antes de executar. O `.pyc` guarda esse
  bytecode em `__pycache__/` para evitar recompilar a cada execução. Ainda assim não é um
  binário nativo: o bytecode precisa da máquina virtual do interpretador.
</details>

**3. O que é uma PEP e para que serve a PEP 8?**

<details>
  <summary>Possível resposta</summary>

  Uma PEP (*Python Enhancement Proposal*) é o documento que propõe e registra decisões
  sobre a linguagem. A PEP 8 é o guia de estilo: define indentação de 4 espaços,
  `snake_case` para funções e variáveis, limite de comprimento de linha e organização de
  imports.
</details>

### Características da linguagem

**4. Python tem tipagem dinâmica e forte. O que cada termo significa?**

<details>
  <summary>Possível resposta</summary>

  **Dinâmica**: o tipo está associado ao valor, e uma variável pode referenciar valores de
  tipos diferentes ao longo do programa. **Forte**: o interpretador não converte tipos
  incompatíveis por conta própria — `"1" + 1` levanta `TypeError` em vez de produzir
  `"11"`.
</details>

**5. Por que a indentação é considerada parte da sintaxe?**

<details>
  <summary>Possível resposta</summary>

  Porque Python usa o recuo para delimitar blocos, no lugar de chaves. Um recuo incorreto
  não é apenas estilo: muda o bloco a que a linha pertence ou levanta `IndentationError`.
</details>

**6. Qual a diferença entre executar código no REPL e em um arquivo `.py`?**

<details>
  <summary>Possível resposta</summary>

  O REPL avalia cada expressão e imprime o resultado automaticamente, mantendo o estado
  entre linhas. Em um arquivo, as expressões são avaliadas mas não impressas — é preciso
  chamar `print()` — e o programa termina ao chegar na última linha.
</details>

### Execução e organização

**7. Para que serve o bloco `if __name__ == "__main__":`?**

<details>
  <summary>Possível resposta</summary>

  Ele separa o que deve rodar quando o arquivo é executado diretamente do que deve apenas
  ser definido quando o arquivo é importado como módulo. Ao importar, `__name__` recebe o
  nome do módulo, e o bloco não executa.
</details>

**8. Como executar um trecho curto de Python sem criar arquivo?**

<details>
  <summary>Possível resposta</summary>

  Com `uv run python -c "código"` (ou `python3 -c "código"`) no terminal, ou abrindo o REPL
  com `uv run python` e digitando as linhas. Para módulos executáveis da biblioteca padrão
  existe ainda `python3 -m módulo`, que em uv vira `uv run -m módulo`.
</details>

**9. Qual erro aparece ao somar `"1" + 1` e como corrigir?**

<details>
  <summary>Possível resposta</summary>

  `TypeError: can only concatenate str (not "int") to str`. A correção é converter
  explicitamente: `int("1") + 1` para somar números ou `"1" + str(1)` para concatenar
  texto.
</details>

**10. Por que `__pycache__/` deve entrar no `.gitignore`?**

<details>
  <summary>Possível resposta</summary>

  Porque é conteúdo derivado: o bytecode é regenerado automaticamente a partir do
  código-fonte e depende da versão do interpretador. Versioná-lo gera ruído no histórico
  e conflitos desnecessários.
</details>
