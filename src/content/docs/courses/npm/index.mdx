O **Guia de Pacotes npm** cobre o ecossistema de pacotes do JavaScript em duas camadas: o **gerenciador** em si, com `package.json`, versionamento, *lockfile*, scripts e `npx`, e os **pacotes de apoio** que ampliam uma aplicação web moderna, como ferramentas de compilação (*build tools*), APIs falsas para prototipagem (*mock APIs*), clientes HTTP e bibliotecas de gráficos e mapas.

O recorte é deliberado: cada linguagem tem o seu gerenciador e o seu registro de pacotes, e misturá-los em um guia único apagaria as diferenças que importam. Aqui o assunto é o **npm**, o registro `npmjs.com` e o que se instala a partir dele. Em Python, o assunto equivalente é tratado no tópico de [uv](../python/tools/uv/), do Guia de Python.

Enquanto o [Guia de ECMAScript](../ecmascript/) cobre a linguagem e o [Guia de Web APIs](../web-api/) trata do navegador nativo, este guia ensina a gerenciar dependências e a integrar ferramentas do registro npm em projetos reais.

<Aside type="tip" title="Modelo Mental">
Pacotes e bibliotecas não substituem o conhecimento fundamental da linguagem. Eles entram quando o projeto precisa de uma ferramenta, uma integração ou uma camada de infraestrutura que seria cara, arriscada ou repetitiva demais para manter à mão.
</Aside>

## Ecossistema, Pacotes e Serviços

O npm é parte de uma cadeia maior: o desenvolvedor declara dependências, o gerenciador resolve versões, o registro entrega os arquivos e o código instalado passa a integrar o projeto. Entender essa cadeia ajuda a separar o que pertence ao JavaScript, ao navegador, ao Node.js e aos serviços externos.

O diagrama abaixo mostra onde cada peça atua dentro de uma aplicação web moderna:

<Mermaid title="Relação entre projeto, npm registry, pacotes instalados e serviços externos">
{`
flowchart TD
  A["Projeto<br/>package.json"] --> B["Gerenciador npm<br/>install, ci, run"]
  B --> C["Registro npm<br/>pacotes publicados"]
  C --> D["node_modules<br/>código instalado"]
  D --> E["Aplicação<br/>front-end ou Node.js"]
  E --> F["Web APIs<br/>navegador nativo"]
  E --> G["Serviços externos<br/>plataformas de nuvem"]
  E --> H["Bibliotecas locais<br/>Axios, Zod, Chart.js, D3, ECharts, Leaflet"]
  E --> I["Ferramentas locais<br/>Vite, Vitest, ESLint, Prettier, TypeScript"]
`}
</Mermaid>

Essa separação evita duas confusões comuns. Um pacote como `axios` é código instalado no projeto; uma Web API como `fetch()` já vem no navegador; um serviço como Supabase combina pacote cliente, API HTTP, autenticação e banco de dados remoto.

| Camada | O que é | Exemplos no guia | Pergunta prática |
| --- | --- | --- | --- |
| **Gerenciador** | Ferramenta que instala, trava versões e executa scripts. | `npm install`, `npm ci`, `npm run` | Como reproduzir o ambiente do projeto? |
| **Pacote local** | Código baixado do registro e importado pela aplicação. | Vite, Axios, Chart.js | Vale trazer uma dependência para este problema? |
| **API nativa** | Recurso fornecido pelo navegador ou pelo Node.js. | `fetch()`, `crypto`, `fs` | Preciso mesmo instalar algo? |
| **Serviço remoto** | Plataforma hospedada, consumida por SDK ou HTTP. | Supabase e Firebase, no [Guia de Computação em Nuvem](../cloud/) | Estou terceirizando banco, auth ou storage? |
| **Ferramenta de projeto** | Comando que roda no desenvolvimento ou no CI. | Vite, Vitest, ESLint, Prettier, TypeScript | Como construir, testar e publicar? |

Na prática, a decisão mais importante não é escolher o pacote “mais famoso”. É reconhecer se o problema pede uma dependência, uma Web API, uma ferramenta de build ou um serviço com estado e cobrança próprios.

## Roteiro Sugerido de Estudos

Se esta é a sua primeira passagem pelo guia, comece pelos fundamentos antes de instalar bibliotecas específicas. O objetivo é saber ler um `package.json`, entender o que o *lockfile* congela e reconhecer quando um comando vem de um script local.

<Steps>
1. **Fundamentos do ecossistema**: Comece por [Introdução e package.json](basics/introduction/), [Dependências e SemVer](basics/dependencies/) e [Scripts e npx](basics/scripts/) para entender manifesto, instalação, *lockfile* e automação.
2. **Ferramentas de desenvolvimento**: Siga para [Pacotes de Desenvolvimento](dev/dev-dependencies/) para separar `dependencies` de `devDependencies`, antes de estudar [Vite](build/vite/) como servidor local e build de produção.
3. **Prototipagem de back-end**: Use o [JSON Server](mock/json-server/) para simular banco de dados e rotas REST enquanto a API real ainda não existe.
4. **Consumo de APIs**: Estude [Axios](http/axios/) depois de conhecer `fetch()`, para comparar cliente nativo, biblioteca externa, interceptores e tratamento global de erros.
5. **Validação de dados**: Use [Zod](validation/zod/) para transformar entradas externas em dados confiáveis antes da regra de negócio.
6. **Visualização e mapas**: Integre o [Chart.js](ui/chartjs/) para gráficos rápidos, [D3.js](ui/d3/) para visualizações sob medida, [Apache ECharts](ui/echarts/) para dashboards declarativos e [Leaflet](ui/leaflet/) para mapas interativos baseados em tiles.
7. **Serviços na nuvem**: Quando o projeto passar a depender de banco, autenticação ou storage hospedados, siga para o [Guia de Computação em Nuvem](../cloud/), onde Supabase e Firebase têm trilhas próprias.
8. **Consulta rápida**: Use o [Mapa de Pacotes](reference/package-map/) para escolher entre API nativa, pacote local e serviço externo antes de adicionar uma nova dependência.
</Steps>

## Decisões Frequentes de Pacotes

As decisões abaixo resumem o recorte atual do guia. Elas não substituem a leitura das páginas, mas ajudam a localizar rapidamente o ponto de entrada quando o projeto já tem um problema concreto.

| Necessidade do Projeto | Pacote Recomendado | Vantagem Principal |
| --- | --- | --- |
| Testar, lintar, formatar e checar tipos | **Vitest, ESLint, Prettier, TypeScript** | Criam contratos de desenvolvimento e CI via `devDependencies`. |
| Criar projeto front-end moderno rápido | **Vite** | HMR instantâneo usando módulos ES nativos (*ESM*). |
| Testar front-end sem API pronta no backend | **JSON Server** | Transforma um arquivo `db.json` em rotas REST completas. |
| Fazer chamadas HTTP com interceptores | **Axios** | Trata exceções HTTP 4xx/5xx e permite injetar Tokens JWT via interceptores. |
| Validar dados externos em runtime | **Zod** | Gera schemas reutilizáveis, mensagens por campo e tipos derivados. |
| Exibir relatórios gráficos na tela | **Chart.js** | Gráficos responsivos renderizados em HTML5 Canvas. |
| Criar visualização de dados sob medida | **D3.js** | Controla SVG, escalas, eixos e ligação de dados. |
| Montar dashboards interativos declarativos | **Apache ECharts** | Combina séries, tooltip, legenda e eixos em um objeto de configuração. |
| Mostrar pontos e rotas em mapa | **Leaflet** | Renderiza mapas 2D com tiles, marcadores, popups e camadas. |

Terceirizar banco de dados, autenticação ou storage é uma decisão de outra natureza, e está no [Guia de Computação em Nuvem](../cloud/). Para decisões fora desse recorte, como testes, formatação, ORM, autenticação no servidor e estado assíncrono no React, consulte o [Mapa de Pacotes](reference/package-map/). Ele separa pacotes já cobertos por páginas completas de candidatos relevantes para expansão futura do guia.
