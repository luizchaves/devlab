Este tópico apresenta o **Leaflet**, uma biblioteca JavaScript leve para criar mapas interativos no navegador. Ele não fornece os mapas sozinho: o Leaflet controla a interface, os marcadores, as camadas e os eventos, enquanto os tiles vêm de um provedor como OpenStreetMap, MapTiler ou outro serviço cartográfico.

## Objetivo

Compreender como integrar o Leaflet a uma aplicação web, diferenciando a biblioteca de mapas, a fonte de tiles e os dados geográficos exibidos. Ao final do tópico, o leitor deve ser capaz de:

- Instalar o Leaflet em um projeto front-end com Vite e npm.
- Criar um mapa com `L.map()`, `setView()` e `L.tileLayer()`.
- Exibir marcadores, popups e linhas usando latitude e longitude.
- Explicar por que a atribuição dos tiles precisa aparecer na interface.
- Identificar quando o projeto precisa de Leaflet, MapLibre GL ou uma API de mapas hospedada.

## Biblioteca, Tiles e Dados Geográficos

Um mapa web combina pelo menos três responsabilidades. A biblioteca desenha e controla a interação; o provedor de tiles entrega as imagens ou vetores de fundo; os dados da aplicação informam pontos, rotas, áreas e eventos.

O diagrama abaixo separa essas camadas:

<Mermaid title="Camadas de uma integração com Leaflet">
{`
flowchart TD
  A["Aplicação<br/>pontos e rotas"] --> B["Leaflet<br/>L.map, markers, popups"]
  C["Provedor de tiles<br/>OpenStreetMap, MapTiler"] --> B
  B --> D["DOM<br/>div#map"]
  D --> E["Usuário<br/>zoom, pan, clique"]
`}
</Mermaid>

Essa separação evita uma confusão frequente: instalar `leaflet` não cria uma base cartográfica própria. Você ainda precisa escolher uma URL de tile, respeitar a licença do provedor e exibir a atribuição exigida.

<Aside type="caution" title="Tiles não são imagens decorativas">
  Um mapa interativo consome infraestrutura externa. Mesmo usando OpenStreetMap como dado aberto, o servidor de tiles tem política de uso, limite de tráfego e exigência de atribuição. Em produção, avalie hospedar tiles próprios ou contratar um provedor adequado ao volume da aplicação.
</Aside>

## Quando Usar Leaflet?

Leaflet é uma boa escolha quando a aplicação precisa de mapas 2D interativos, marcadores, popups e camadas simples. Para visualização vetorial pesada, milhares de feições dinâmicas ou mapas 3D, outras ferramentas podem ser mais adequadas.

| Necessidade | Leaflet atende bem? | Observação |
| --- | --- | --- |
| Marcadores, popups e rotas simples | Sim | É o caso de dashboards, cadastros com localização e mapas institucionais. |
| Camadas raster de tiles | Sim | Basta configurar `L.tileLayer()` e atribuição. |
| GeoJSON moderado | Sim | `L.geoJSON()` cobre muitos mapas temáticos. |
| Vetores massivos e estilo dinâmico | Parcialmente | MapLibre GL costuma lidar melhor com renderização vetorial por WebGL. |
| Geocodificação e cálculo de rotas | Não sozinho | Normalmente exigem serviços externos ou APIs próprias. |

Antes de escolher, separe mapa, dado e serviço. O Leaflet mostra informação geográfica; ele não substitui banco espacial, geocodificador, roteador nem política de cobrança de tiles.

## Exercício

Altere o exemplo para representar três pontos de interesse de uma cidade que você conhece. O objetivo é praticar a diferença entre dado geográfico e configuração visual.

1. Troque o centro inicial do mapa.
2. Adicione três marcadores com `L.marker()`.
3. Crie um popup diferente para cada ponto.
4. Use `L.polyline()` para ligar os pontos na ordem de visita.
5. Ajuste o `fitBounds()` para enquadrar todos os pontos.

Uma resposta aceitável deve manter a atribuição dos tiles e usar coordenadas no formato esperado pelo Leaflet:

<details>
  <summary>Possível resposta</summary>

  A solução cria um array `points`, percorre cada item com `forEach()` para adicionar marcadores e passa `points.map((point) => point.coords)` para `L.polyline()` e `map.fitBounds()`. O importante é manter cada coordenada como `[latitude, longitude]`, com nomes de variáveis que deixem essa ordem explícita.
</details>

## Desafio

Integre o mapa com dados vindos de uma API. Em vez de declarar as coordenadas direto no arquivo, busque um JSON com pontos e renderize os marcadores dinamicamente.

1. Modele cada ponto com `id`, `name`, `description`, `latitude` e `longitude`.
2. Busque os dados com `fetch()`.
3. Transforme cada ponto em marcador com popup.
4. Mostre uma mensagem de erro se a API falhar.
5. Explique se `latitude` e `longitude` deveriam ser validadas no front-end, no back-end ou nos dois.

Use a resposta abaixo como referência de arquitetura:

<details>
  <summary>Possível resposta</summary>

  O front-end deve validar o formato mínimo antes de renderizar, para não quebrar o mapa com coordenadas ausentes. O back-end também precisa validar, porque é a fronteira confiável do sistema. No front-end, uma função `toLatLng(point)` pode devolver `[point.latitude, point.longitude]` apenas quando os dois valores são números dentro dos limites geográficos.
</details>

## Perguntas de revisão

As perguntas abaixo verificam se você separou corretamente biblioteca, tiles, dados e responsabilidades do mapa.

### Fundamentos do Leaflet

1. **Qual é o papel de `L.map()` em uma aplicação Leaflet?**

<details>
  <summary>Possível resposta</summary>

  `L.map()` cria a instância do mapa dentro de um elemento do DOM. Essa instância controla zoom, centro, camadas, eventos e interações do usuário.
</details>

2. **Por que o contêiner `#map` precisa ter altura definida?**

<details>
  <summary>Possível resposta</summary>

  Porque o Leaflet renderiza dentro do elemento existente. Se o elemento não tiver altura, o mapa ocupa zero pixels e parece não ter carregado.
</details>

3. **O que `L.tileLayer()` adiciona ao mapa?**

<details>
  <summary>Possível resposta</summary>

  Ele adiciona a camada de tiles, que são as imagens ou vetores de fundo do mapa. A URL da camada define de onde vêm esses tiles.
</details>

### Decisão de ferramenta

4. **Por que instalar Leaflet não basta para ter um mapa completo?**

<details>
  <summary>Possível resposta</summary>

  Porque Leaflet é a biblioteca de interação e renderização. A aplicação ainda precisa de fonte de tiles, dados geográficos, atribuição e, em alguns casos, serviços externos de geocodificação ou rotas.
</details>

5. **Quando MapLibre GL pode ser mais adequado que Leaflet?**

<details>
  <summary>Possível resposta</summary>

  Quando o mapa usa muitos vetores dinâmicos, estilos cartográficos complexos ou renderização acelerada por WebGL. Leaflet continua excelente para mapas 2D com camadas e marcadores simples.
</details>
