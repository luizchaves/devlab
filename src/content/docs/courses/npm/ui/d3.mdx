Este tópico apresenta o **D3.js**, uma biblioteca JavaScript para visualizações sob medida. Diferente de bibliotecas que recebem uma configuração pronta de gráfico, o D3 ajuda a transformar dados em DOM, SVG, escalas, eixos e transições com controle fino sobre cada elemento visual.

## Objetivo

Compreender quando o D3.js é uma boa escolha para visualização de dados personalizada, diferenciando manipulação de SVG, ligação de dados e configuração declarativa de gráficos. Ao final do tópico, o leitor deve ser capaz de:

- Instalar `d3` como dependência de uma aplicação front-end.
- Explicar o papel de seleções, escalas, eixos e `join()` em um gráfico SVG.
- Relacionar dados de entrada a elementos visuais criados no DOM.
- Diferenciar D3, Chart.js e Apache ECharts por nível de abstração.
- Identificar quando o controle fino do D3 compensa a complexidade extra.

## Modelo Mental

D3 não é apenas uma biblioteca de gráfico pronto. Ele fornece ferramentas para mapear dados em atributos visuais, como posição, largura, altura, cor e texto. O gráfico nasce da composição dessas peças.

O diagrama abaixo resume a cadeia de transformação mais comum:

<Mermaid title="Fluxo de dados em uma visualização com D3">
{`
flowchart TD
  A["Dados<br/>array de objetos"] --> B["Escalas<br/>scaleBand, scaleLinear"]
  B --> C["Seleção<br/>d3.select, selectAll"]
  C --> D["Data join<br/>data, join"]
  D --> E["SVG<br/>rect, text, axis"]
  E --> F["Tela<br/>visualização sob medida"]
`}
</Mermaid>

Essa cadeia explica por que o D3 aparece em visualizações customizadas: a biblioteca não escolhe o desenho por você. Ela oferece as ferramentas para que os dados controlem o desenho.

<Aside type="tip" title="D3 é mais linguagem visual que componente pronto">
  Se a aplicação precisa apenas de gráfico de linha, barras ou pizza com tooltip padrão, Chart.js ou ECharts costumam entregar mais rápido. O D3 fica mais interessante quando o desenho, a escala, a transição ou a interação fogem do formato comum.
</Aside>

## Criando SVG a Partir de Dados

A função `renderD3Chart()` monta o gráfico em etapas: define dimensões, cria escalas, desenha eixos e usa `selectAll().data().join()` para criar um `rect` por item do array.

<SourceCode path="examples/courses/npm/dataviz/chart-libraries/src/main.js" title="src/main.js" lines="14-54" mark="25-35,44-53" />

O ponto central está no `join()`: ele relaciona os dados aos elementos visuais. Se a lista de meses mudar, o D3 sabe quais retângulos precisam entrar, atualizar ou sair.

## Quando Usar D3?

D3 brilha quando o gráfico não cabe bem em um componente pronto. A decisão depende do quanto o projeto precisa controlar a geometria e o comportamento da visualização.

| Necessidade | D3 atende bem? | Observação |
| --- | --- | --- |
| Gráfico comum com poucas customizações | Parcialmente | Funciona, mas pode exigir mais código que Chart.js ou ECharts. |
| Visualização sob medida em SVG | Sim | Escalas, eixos e seleções dão controle fino. |
| Animações guiadas por dados | Sim | Transições e data join ajudam a expressar mudanças. |
| Dashboard rápido com tooltip e legenda prontos | Parcialmente | ECharts tende a entregar mais recursos prontos. |
| Controle total de marcação acessível | Sim | O projeto decide quais elementos, atributos e textos entram no DOM. |

Antes de escolher D3, escreva o desenho que a visualização precisa ter. Se ele cabe em uma configuração declarativa comum, uma biblioteca de gráficos pronta pode ser suficiente.

## Exercício

Altere o gráfico D3 para representar a latência em vez do tráfego. O objetivo é praticar a ligação entre dado, escala e atributo visual.

1. Troque a escala `y` para usar `latency`.
2. Atualize a altura das barras para refletir a nova métrica.
3. Mude a cor das barras para indicar que o dado mudou.
4. Explique por que a escala precisa ser recalculada quando a métrica muda.

Uma resposta aceitável deve alterar o domínio da escala e os atributos `y` e `height` dos retângulos:

<details>
  <summary>Possível resposta</summary>

  A solução troca `item.traffic` por `item.latency` em `d3.max()`, em `y(item.latency)` e no cálculo de altura. A mudança precisa aparecer nos três pontos porque a escala define o limite do eixo, a posição vertical e o tamanho visual de cada barra.
</details>

## Desafio

Transforme o gráfico de barras em uma visualização de pontos. Em vez de `rect`, use `circle` para posicionar cada mês em um eixo horizontal e cada valor em um eixo vertical.

1. Use `svg.selectAll('circle')`.
2. Ligue os dados com `.data(data).join('circle')`.
3. Defina `cx`, `cy` e `r`.
4. Adicione um título acessível ou texto associado para cada ponto.
5. Compare a legibilidade do gráfico de pontos com a versão de barras.

Use a resposta abaixo como referência de raciocínio:

<details>
  <summary>Possível resposta</summary>

  A visualização de pontos usa a mesma escala `x` para encontrar o centro de cada mês e a mesma escala `y` para posicionar o valor. O principal ajuste é trocar largura e altura por coordenadas `cx` e `cy`, mantendo a escala como ponte entre dados abstratos e posição visual.
</details>

## Perguntas de revisão

As perguntas abaixo verificam se você entendeu o papel do D3 como ferramenta de transformação de dados em elementos visuais.

### Fundamentos do D3

1. **Qual é a função de uma escala em D3?**

<details>
  <summary>Possível resposta</summary>

  A escala converte valores do domínio dos dados, como meses ou números, em valores visuais, como posições, larguras, alturas ou cores.
</details>

2. **Por que `selectAll().data().join()` é central em D3?**

<details>
  <summary>Possível resposta</summary>

  Porque ele liga uma coleção de dados a uma coleção de elementos. A partir dessa ligação, o D3 cria, atualiza ou remove elementos conforme os dados mudam.
</details>

3. **O D3 cria gráficos prontos como Chart.js?**

<details>
  <summary>Possível resposta</summary>

  Não no mesmo nível de abstração. D3 oferece primitivas para construir visualizações, enquanto Chart.js e ECharts oferecem tipos de gráfico configuráveis.
</details>

### Decisão de ferramenta

4. **Quando D3 pode ser uma escolha exagerada?**

<details>
  <summary>Possível resposta</summary>

  Quando o projeto precisa apenas de gráficos comuns, com tooltip, legenda e responsividade padrão. Nesses casos, Chart.js ou ECharts costumam reduzir código e manutenção.
</details>

5. **Por que D3 é útil em visualizações customizadas?**

<details>
  <summary>Possível resposta</summary>

  Porque permite controlar diretamente elementos SVG, escalas, eixos, transições e atributos visuais. Isso ajuda quando o desenho final não cabe em um gráfico pronto.
</details>
