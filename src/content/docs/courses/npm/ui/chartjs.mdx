Este tópico apresenta o **Chart.js**, uma das bibliotecas JavaScript open-source mais populares, intuitivas e flexíveis para visualização de dados em aplicações web.

Apresentar grandes volumes de dados brutos ou tabelas densas dificulta a tomada de decisão pelos usuários. Gráficos visuais transformam números complexos em tendências imediatas. Utilizando o elemento nativo `<canvas>` do HTML5 por baixo dos panos, o Chart.js renderiza gráficos responsivos, animados e com interatividade pronta (como tooltips e legendas) através de uma estrutura de configuração simples e declarativa.

## Objetivo

Compreender a instalação, configuração e integração do Chart.js no front-end, formatando dados recebidos de APIs e manipulando o ciclo de vida dos gráficos em Canvas. Ao final do tópico, o leitor deve ser capaz de:

- Explicar o papel do elemento `<canvas>` na renderização gráfica de alta performance com Chart.js.
- Instalar a biblioteca via npm e importá-la em projetos modernos com Vite.
- Estruturar o objeto de configuração com rótulos (*labels*), datasets, paletas de cores e escalas.
- Atualizar dinamicamente os dados de um gráfico existente sem recriar a instância do zero.
- Evitar vazamentos de memória (*memory leaks*) destruindo instâncias obsoletas em aplicações SPA.

## O que é o Chart.js?

O Chart.js é uma biblioteca orientada a gráficos pré-configurados que entrega oito tipos fundamentais de visualização prontos para uso: linhas (*line*), barras (*bar*), pizza (*pie*), rosca (*doughnut*), radar, área polar, bolhas (*bubble*) e dispersão (*scatter*).

A tabela a seguir compara o Chart.js com outras soluções do ecossistema:

| Biblioteca | Renderizador | Nível de Abstração | Curva de Aprendizado | Caso de uso principal |
| :--- | :--- | :--- | :--- | :--- |
| **Chart.js** | HTML5 Canvas | Alto (declarativo) | Muito suave | Gráficos corporativos clássicos, relatórios e dashboards. |
| **D3.js** | SVG / Canvas | Baixo (primitivas) | Alta | Visualizações customizadas sob medida e arte generativa. |
| **Canvas / SVG Nativo** | Canvas / DOM | Muito baixo | Alta | Desenho vetorial procedural ou jogos sem dependências externas. |

O Chart.js é a escolha ideal quando a aplicação precisa de gráficos bonitos e responsivos rapidamente, sem a necessidade de desenhar eixos ou geometrias manualmente do zero.

## Fundamentos e Modelo Mental

O Chart.js consome dados estruturados em JavaScript e desenha o gráfico diretamente no contexto 2D de um elemento `<canvas>`. Ao contrário do SVG, que cria nós individuais para cada barra ou ponto, o Canvas desenha pixels diretamente em um bitmap com aceleração de hardware.

O diagrama abaixo ilustra o fluxo de dados desde a consulta até a renderização animada na tela:

<Mermaid title="Fluxo de Renderização de Gráficos com Chart.js">
{`
flowchart TD
  API["API / JSON Server<br/>(dados brutos JSON)"] --> Fetch["JavaScript da Aplicação<br/>(fetch / axios)"]
  Fetch --> Config["Objeto de Configuração<br/>{ type, data, options }"]
  Config --> ChartInst["new Chart(canvasElement, config)"]
  ChartInst --> Canvas["Elemento canvas nativo<br/>contexto 2D bitmap"]
  Canvas --> DOM["Renderização a 60 FPS<br/>com tooltips e hover"]
`}
</Mermaid>

Como o gráfico opera em bitmap, renderizar centenas de pontos de dados não degrada a árvore do DOM.

## Como Usar: Instalação e Configuração

Para adicionar a biblioteca ao seu projeto front-end baseado em Vite/npm, instale o pacote `chart.js`:

<PackageManagerTabs package="chart.js" />

Em projetos modernos com Vite, você pode importar o pacote completo com registro automático de componentes ou importar submódulos seletivos para otimização de tamanho:

```js title="src/main.js"
import Chart from 'chart.js/auto';

// Seleciona o elemento canvas no DOM
const ctx = document.getElementById('myChart');

// Instancia o gráfico
new Chart(ctx, {
  type: 'line',
  data: {
    labels: ['Janeiro', 'Fevereiro', 'Março', 'Abril'],
    datasets: [
      {
        label: 'Vendas (R$)',
        data: [12000, 19000, 15000, 22000],
        borderColor: '#2563eb',
        backgroundColor: 'rgba(37, 99, 235, 0.1)',
        tension: 0.3,
      },
    ],
  },
  options: {
    responsive: true,
    plugins: {
      legend: { position: 'top' },
      tooltip: { enabled: true },
    },
  },
});
```

## Boas Práticas e Armadilhas

A tabela a seguir consolida as recomendações para garantir performance e responsividade:

| Cenário | O que fazer | O que evitar |
| :--- | :--- | :--- |
| **Gráficos em SPAs** | Chame sempre `chart.destroy()` antes de recriar o gráfico no mesmo `<canvas>`. | Não crie `new Chart()` repetidamente sobre o mesmo canvas (causa sobreposição fantasma e vazamento). |
| **Atualização de dados** | Modifique `chart.data.datasets` e invoque `chart.update()`. | Não destrua e recrie a instância se apenas os números mudaram. |
| **Layout responsivo** | Envolva o `<canvas>` em uma `<div>` com `position: relative` e altura definida. | Não defina larguras fixas em pixels diretamente no elemento canvas via CSS. |

<Aside type="caution" title="Dica de IA: Cuidado com recriação de instâncias">
  Assistentes de IA frequentemente sugerem instanciar `new Chart()` dentro de callbacks de eventos periódicos (`setInterval` ou polling de API), o que acumula instâncias na memória e congela a aba.

  **Prompt:** *"Refatore a função de atualização do gráfico para atualizar o array `chart.data.datasets[0].data` e chamar `chart.update('none')`, reutilizando a mesma instância existente."*
</Aside>

## Exercício

Crie uma função `updateChartData(chart, newLabels, newValues)` que receba uma instância existente do Chart.js e atualize os rótulos e valores do primeiro dataset de forma suave com animação padrão.

<details>
  <summary>Possível resposta</summary>

  ```js title="Solução do exercício"
  export function updateChartData(chart, newLabels, newValues) {
    chart.data.labels = newLabels;
    chart.data.datasets[0].data = newValues;
    chart.update();
  }
  ```
</details>

## Desafio

Implemente um gráfico de barras comparativo com dois datasets (ex: "Receitas" em verde e "Despesas" em vermelho). Adicione um botão no DOM que permita alternar a visibilidade de um dos datasets em tempo de execução utilizando o método `chart.setDatasetVisibility(index, isVisible)`.

<details>
  <summary>Possível resposta</summary>

  ```js title="Solução do desafio"
  import Chart from 'chart.js/auto';

  const ctx = document.getElementById('financeChart');
  const chart = new Chart(ctx, {
    type: 'bar',
    data: {
      labels: ['Jan', 'Fev', 'Mar', 'Abr'],
      datasets: [
        { label: 'Receitas', data: [5000, 7000, 6500, 8000], backgroundColor: '#16a34a' },
        { label: 'Despesas', data: [3200, 4100, 3900, 4500], backgroundColor: '#dc2626' },
      ],
    },
  });

  const toggleBtn = document.getElementById('toggle-expenses');
  let expensesVisible = true;

  toggleBtn.addEventListener('click', () => {
    expensesVisible = !expensesVisible;
    chart.setDatasetVisibility(1, expensesVisible);
    chart.update();
  });
  ```
</details>

## Perguntas de revisão

Responda às questões para consolidar o aprendizado:

1. **Quais são os dois pilares principais do objeto de configuração passado ao instanciar um `new Chart()`?**
   <details>
     <summary>Possível resposta</summary>
     O tipo do gráfico (`type: 'line'`, `'bar'`, `'pie'`) e o objeto `data` (contendo os rótulos do eixo X e o array de `datasets` com valores e estilos visuais).
   </details>

2. **Qual é a importância de chamar `chart.destroy()` ao remover um gráfico da tela em aplicações monopágina (SPA)?**
   <details>
     <summary>Possível resposta</summary>
     Destruir a instância anterior evita vazamentos de memória (*memory leaks*) e impede que instâncias antigas continuem escutando eventos de redimensionamento na janela.
   </details>

3. **Por que o elemento `<canvas>` é vantajoso para gráficos com grande volume de dados?**
   <details>
     <summary>Possível resposta</summary>
     Porque ele desenha os gráficos em um bitmap acelerado por hardware com performance de 60 FPS, sem inflar a árvore do DOM com centenas de nós HTML.
   </details>

4. **Como atualizar dados em um gráfico sem causar recriação de tela?**
   <details>
     <summary>Possível resposta</summary>
     Atribuindo novos valores a `chart.data.labels` e `chart.data.datasets` e chamando `chart.update()`.
   </details>
