Este tópico apresenta o **Apache ECharts**, uma biblioteca de visualização para criar gráficos interativos a partir de objetos de configuração. Ele é útil quando a aplicação precisa de dashboards com múltiplas séries, tooltip, legenda, responsividade e tipos de gráfico prontos sem desenhar cada elemento SVG manualmente.

## Objetivo

Compreender como o Apache ECharts organiza um gráfico por configuração declarativa, diferenciando inicialização, eixos, séries, legenda e tooltip. Ao final do tópico, o leitor deve ser capaz de:

- Instalar `echarts` em um projeto front-end com Vite e npm.
- Criar uma instância com `echarts.init()` e configurar o gráfico com `setOption()`.
- Mapear dados de aplicação para `xAxis`, `yAxis` e `series`.
- Explicar quando ECharts é mais adequado que D3 ou Chart.js.
- Prever cuidados de ciclo de vida, como `resize()` e descarte da instância.

## Modelo Mental

O ECharts trabalha com uma ideia simples: a aplicação prepara um objeto de opções e a biblioteca transforma esse contrato em gráfico interativo. O código não cria cada barra ou ponto manualmente; ele declara eixos, séries, componentes e comportamento.

O diagrama abaixo mostra essa separação:

<Mermaid title="Fluxo de configuração em um gráfico ECharts">
{`
flowchart TD
  A["Dados<br/>metrics"] --> B["Mapeamento<br/>labels e series"]
  B --> C["Option<br/>tooltip, legend, xAxis, yAxis"]
  C --> D["echarts.init<br/>instância do gráfico"]
  D --> E["setOption<br/>renderização"]
  E --> F["Canvas/SVG<br/>interação pronta"]
`}
</Mermaid>

Essa abordagem favorece dashboards: boa parte do comportamento comum já vem na biblioteca, e o código da aplicação fica concentrado em preparar os dados corretamente.

<Aside type="tip" title="Configuração não dispensa modelo de dados">
  ECharts facilita o desenho, mas não corrige dados mal modelados. Antes de montar `series`, separe unidade, período, métrica e rótulo. Um gráfico bonito com eixo ambíguo continua sendo uma visualização ruim.
</Aside>

## Configuração Declarativa

A configuração do ECharts deve ser lida como um contrato entre dados e visualização. Cada chave descreve uma responsabilidade do gráfico.

| Chave | Papel | No exemplo |
| --- | --- | --- |
| `tooltip` | Define a interação ao passar o mouse ou tocar no gráfico. | `trigger: 'axis'` mostra valores por mês. |
| `legend` | Mostra nomes das séries e permite alternar visibilidade. | Fica no rodapé do gráfico. |
| `grid` | Controla margens internas da área de desenho. | Abre espaço para legenda e eixos. |
| `xAxis` | Define o eixo horizontal. | Recebe os meses como categorias. |
| `yAxis` | Define o eixo vertical. | Usa escala numérica. |
| `series` | Declara os conjuntos de dados. | Mistura uma série de linha e uma de barras. |

Quando a tela muda de tamanho, a instância precisa ser redimensionada. Em componentes React, Vue ou Svelte, essa mesma ideia entra no ciclo de montagem e desmontagem do componente.

<Aside type="caution" title="Dica de IA: Não aceite gráfico sem ciclo de vida">
  Assistentes costumam mostrar `echarts.init()` e `setOption()`, mas esquecem `resize()` e descarte da instância quando o componente sai da tela. Em SPAs, isso pode deixar ouvintes e canvases antigos vivos.

  **Prompt:** *"Reescreva esta integração com ECharts incluindo `resize()`, descarte da instância no ciclo de desmontagem e um comentário explicando onde isso entraria em React, Vue ou Svelte."*
</Aside>

## Quando Usar ECharts?

ECharts é uma boa escolha quando o projeto precisa de gráficos interativos ricos, mas não precisa controlar cada primitiva de desenho. Ele fica entre a simplicidade do Chart.js e o controle fino do D3.

| Necessidade | ECharts atende bem? | Observação |
| --- | --- | --- |
| Dashboard com várias séries | Sim | Série, legenda, tooltip e eixos são declarados no mesmo objeto. |
| Gráficos comuns com interação pronta | Sim | Reduz código de infraestrutura visual. |
| Visualização completamente sob medida | Parcialmente | D3 costuma dar mais controle sobre geometria e DOM. |
| Primeiro gráfico simples de uma turma | Parcialmente | Chart.js pode ser mais direto para começar. |
| Grande variedade de tipos de gráfico | Sim | A biblioteca cobre muitos tipos e combinações. |

Use ECharts quando a pergunta principal for “como configurar bem este dashboard?”. Use D3 quando a pergunta for “como desenhar uma visualização que não existe pronta?”.

## Perguntas de revisão

As perguntas abaixo verificam se você separou configuração, dados e ciclo de vida da biblioteca.

### Fundamentos do ECharts

1. **Qual é o papel de `echarts.init()`?**

<details>
  <summary>Possível resposta</summary>

  `echarts.init()` cria uma instância de gráfico associada a um elemento do DOM. Essa instância recebe opções, renderiza o gráfico e controla interações.
</details>

2. **O que `setOption()` recebe?**

<details>
  <summary>Possível resposta</summary>

  Recebe um objeto de configuração com componentes como `tooltip`, `legend`, `xAxis`, `yAxis` e `series`.
</details>

3. **Por que `series` costuma usar `data.map()`?**

<details>
  <summary>Possível resposta</summary>

  Porque os dados da aplicação normalmente vêm como objetos de domínio, e cada série precisa extrair apenas a métrica que será desenhada.
</details>

### Decisão de ferramenta

4. **Quando ECharts pode ser melhor que D3?**

<details>
  <summary>Possível resposta</summary>

  Quando a aplicação precisa de dashboards com gráficos conhecidos, tooltip, legenda, eixos e responsividade prontos, sem controlar cada elemento SVG manualmente.
</details>

5. **Qual cuidado de ciclo de vida aparece em aplicações com componentes?**

<details>
  <summary>Possível resposta</summary>

  A instância deve responder a mudanças de tamanho com `resize()` e ser descartada quando o componente sai da tela, para evitar vazamento de recursos.
</details>
