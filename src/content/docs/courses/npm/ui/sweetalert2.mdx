Este tópico apresenta o **SweetAlert2**, uma biblioteca JavaScript para criação de caixas de diálogo, modais de confirmação e notificações flutuantes (*toasts*) elegantes, responsivas e totalmente customizáveis.

Os métodos nativos do navegador (`window.alert()`, `window.confirm()` e `window.prompt()`) foram criados nos primórdios da web e possuem limitações graves: bloqueiam a *thread* principal do JavaScript, congelam animações na página, não são personalizáveis visualmente e oferecem uma experiência inconsistente entre diferentes sistemas operacionais. O SweetAlert2 resolve esses problemas com modais não-bloqueantes baseados em Promises (`async/await`), animações fluidas e suporte nativo a acessibilidade.

## Objetivo

Dominar a implementação de modais interativos, diálogos de confirmação assíncronos e notificações do tipo *toast* no front-end utilizando o pacote SweetAlert2. Ao final do tópico, o leitor deve ser capaz de:

- Explicar os problemas de usabilidade e arquitetura dos alertas nativos (`alert`, `confirm`).
- Instalar e configurar o pacote `sweetalert2` em conjunto com seus estilos CSS.
- Disparar alertas informativos, de erro, sucesso e aviso utilizando a sintaxe `Swal.fire()`.
- Criar fluxos de confirmação de ações críticas (como exclusão de registros) com `async/await`.
- Configurar notificações flutuantes automáticas (*toasts*) não-intrusivas com temporizador.
- Garantir a acessibilidade do modal por meio do gerenciamento de foco e navegação via teclado.

## O que é o SweetAlert2?

O SweetAlert2 é uma biblioteca completa para a camada de apresentação e feedback ao usuário. Ao contrário dos alertas nativos que congelam a execução do navegador, os diálogos do SweetAlert2 são renderizados diretamente como elementos HTML e nós de estilo no DOM, retornando uma Promise JavaScript com a ação escolhida pelo usuário.

A tabela abaixo compara o SweetAlert2 com as alternativas nativas e outros padrões de notificação:

| Recurso | `window.alert` / `confirm` | SweetAlert2 (`Swal.fire`) | HTML5 `<dialog>` nativo |
| :--- | :--- | :--- | :--- |
| **Comportamento da Thread** | Bloqueante (síncrono) | Não-bloqueante (Promise) | Não-bloqueante (Eventos / Métodos) |
| **Estilização Visual** | Bloqueada pelo SO | Totalmente customizável (CSS/Temas) | Totalmente customizável (CSS puro) |
| **Ícones e Animações** | Inexistentes | Ícones animados embutidos | Requer implementação manual |
| **Notificações Toast** | Não suportado | Suportado nativamente (`toast: true`) | Requer implementação manual |
| **Acessibilidade WAI-ARIA** | Básica do SO | Pronta (Foco automático, ESC, Tab trap) | Nativa com `showModal()` |

O SweetAlert2 é a escolha recomendada quando a aplicação precisa de confirmações ricas com botões personalizados, formulários embutidos em caixas de diálogo ou mensagens de status com *look and feel* profissional.

## Fundamentos e Modelo Mental

O funcionamento do SweetAlert2 gira em torno de uma função central: `Swal.fire()`. Ao ser invocada, a função cria a sobreposição (*overlay*) na tela, injeta a janela modal, captura os eventos de teclado e clique, e resolve uma Promise quando o usuário interage.

O diagrama a seguir demonstra o ciclo de vida assíncrono de um diálogo de confirmação:

<Mermaid title="Ciclo de vida assíncrono de um diálogo com SweetAlert2">
{`
flowchart TD
  A["Ação do usuário<br/>(ex: Clicar em Excluir)"] --> B["Swal.fire({ ... })<br/>Renderiza modal no DOM"]
  B --> C{"Decisão do usuário"}
  C -->|"Confirmar"| D["Promise resolve com<br/>{ isConfirmed: true }"]
  C -->|"Cancelar ou ESC"| E["Promise resolve com<br/>{ isDismissed: true }"]
  D --> F["Executa requisição DELETE<br/>no back-end"]
  E --> G["Aborta operação<br/>sem efeitos colaterais"]
`}
</Mermaid>

Como o fluxo é baseado em Promises, você pode encadear a resposta com blocos `try/catch` e estados de carregamento (*loading states*) enquanto aguarda requisições HTTP.

## Como Usar: Instalação e Configuração

O SweetAlert2 é distribuído como pacote npm e inclui tanto o código JavaScript quanto as folhas de estilo CSS necessárias para as animações e o layout.

No terminal do projeto, instale o pacote:

```bash title="Terminal"
npm install sweetalert2
```

Em projetos com Vite ou empacotadores modernos, importe o módulo JavaScript e o arquivo CSS padrão no ponto de entrada:

```js title="src/main.js"
import Swal from 'sweetalert2';
import 'sweetalert2/dist/sweetalert2.min.css';

// Teste rápido de exibição
Swal.fire({
  title: 'Bem-vindo!',
  text: 'O SweetAlert2 está pronto para uso.',
  icon: 'success',
  confirmButtonText: 'Continuar',
});
```

A importação do CSS é obrigatória para que as sombras, o fundo translúcido (*backdrop*) e as animações de abertura funcionem corretamente.

## Sintaxe e Principais Recursos

A seguir, são apresentadas as principais formas de uso do SweetAlert2: alertas simples, diálogos de confirmação com `async/await` e notificações do tipo *toast*.

### Alertas com Ícones de Status

O SweetAlert2 possui cinco tipos pré-configurados de ícones com animações SVG nativas: `success`, `error`, `warning`, `info` e `question`.

O trecho de código abaixo demonstra a sintaxe básica com diferentes status:

```js title="Exemplos de alertas informativos com SweetAlert2"
import Swal from 'sweetalert2';

// Alerta de sucesso
Swal.fire({
  icon: 'success',
  title: 'Dados Salvos!',
  text: 'O perfil foi atualizado com sucesso.',
  timer: 2000,
  showConfirmButton: false,
});

// Alerta de erro com detalhes
Swal.fire({
  icon: 'error',
  title: 'Falha na Operação',
  text: 'Não foi possível conectar ao servidor. Tente novamente.',
  footer: '<a href="#ajuda">Precisa de suporte técnico?</a>',
});
```

A tabela abaixo resume as principais propriedades de configuração do objeto `Swal.fire()`:

| Propriedade | Tipo | Descrição |
| :--- | :--- | :--- |
| `title` | `string` | Título principal exibido em destaque no topo do modal. |
| `text` ou `html` | `string` | Mensagem do corpo do modal (em texto simples ou HTML seguro). |
| `icon` | `string` | Ícone temático (`'success'`, `'error'`, `'warning'`, `'info'`, `'question'`). |
| `showCancelButton` | `boolean` | Se `true`, exibe o botão de cancelamento ao lado do botão principal. |
| `confirmButtonText` | `string` | Rótulo textual do botão de confirmação (padrão: `"OK"`). |
| `cancelButtonText` | `string` | Rótulo textual do botão de cancelamento (padrão: `"Cancel"`). |
| `confirmButtonColor` | `string` | Código de cor CSS para o botão de confirmação (ex: `"#2563eb"`). |
| `timer` | `number` | Tempo em milissegundos para fechamento automático da janela. |

### Diálogo de Confirmação Assíncrono com `async/await`

Para ações destrutivas (como remover itens ou cancelar assinaturas), utilize a propriedade `showCancelButton: true` e analise o objeto de resultado retornado pela Promise:

```js title="Fluxo de confirmação de exclusão"
import Swal from 'sweetalert2';

async function handleDeleteItem(itemId) {
  const result = await Swal.fire({
    title: 'Tem certeza?',
    text: 'Esta ação não poderá ser desfeita!',
    icon: 'warning',
    showCancelButton: true,
    confirmButtonColor: '#dc2626',
    cancelButtonColor: '#6b7280',
    confirmButtonText: 'Sim, excluir!',
    cancelButtonText: 'Cancelar',
  });

  // Verifica se o usuário clicou no botão de confirmação
  if (result.isConfirmed) {
    // Exibe o estado de loading enquanto a API processa
    Swal.showLoading();
    
    // Simula exclusão na API
    await fetch(`/api/items/${itemId}`, { method: 'DELETE' });

    await Swal.fire({
      icon: 'success',
      title: 'Excluído!',
      text: 'O registro foi removido com sucesso.',
      timer: 1500,
    });
  }
}
```

### Notificações Flutuantes (*Toasts*) com `Swal.mixin`

Para avisos rápidos que não devem interromper o fluxo do usuário (como confirmações de cópia para o *clipboard* ou salvamento automático), você pode criar uma instância reutilizável do tipo *toast* com `Swal.mixin()`:

```js title="Configuração de Toast reutilizável"
import Swal from 'sweetalert2';

// Cria um modelo customizado de Toast
const Toast = Swal.mixin({
  toast: true,
  position: 'top-end',
  showConfirmButton: false,
  timer: 3000,
  timerProgressBar: true,
  didOpen: (toast) => {
    toast.addEventListener('mouseenter', Swal.stopTimer);
    toast.addEventListener('mouseleave', Swal.resumeTimer);
  },
});

// Dispara a notificação
export function showSuccessToast(message) {
  Toast.fire({
    icon: 'success',
    title: message,
  });
}
```

## Exemplo Prático no Front-end

O exemplo a seguir integra o SweetAlert2 com um formulário de cadastro de contatos, demonstrando a validação visual, o diálogo de confirmação antes de descartar alterações e o toast de sucesso ao salvar.

O arquivo HTML define a interface do formulário:

```html title="index.html"
<!DOCTYPE html>
<html lang="pt-BR">
  <head>
    <meta charset="UTF-8" />
    <title>Formulário com SweetAlert2</title>
    <link rel="stylesheet" href="./style.css" />
  </head>
  <body>
    <div class="card">
      <h2>Novo Contato</h2>
      <form id="contact-form">
        <label for="name">Nome completo</label>
        <input type="text" id="name" required placeholder="Digite o nome" />

        <label for="email">E-mail</label>
        <input type="email" id="email" required placeholder="email@exemplo.com" />

        <div class="form-actions">
          <button type="button" id="btn-cancel" class="btn-secondary">Cancelar</button>
          <button type="submit" class="btn-primary">Salvar Contato</button>
        </div>
      </form>
    </div>

    <script type="module" src="./main.js"></script>
  </body>
</html>
```

O arquivo JavaScript controla os eventos de envio e cancelamento com modais e toasts:

```js title="src/main.js"
import Swal from 'sweetalert2';
import 'sweetalert2/dist/sweetalert2.min.css';

const form = document.getElementById('contact-form');
const cancelBtn = document.getElementById('btn-cancel');

// Configuração do Toast
const Toast = Swal.mixin({
  toast: true,
  position: 'bottom-end',
  showConfirmButton: false,
  timer: 2500,
  timerProgressBar: true,
});

// Manipulador do envio do formulário
form.addEventListener('submit', async (e) => {
  e.preventDefault();
  
  const name = document.getElementById('name').value.trim();
  const email = document.getElementById('email').value.trim();

  if (!name || !email) {
    Swal.fire({
      icon: 'error',
      title: 'Campos incompletos',
      text: 'Por favor, preencha todos os campos obrigatórios.',
    });
    return;
  }

  // Notificação de sucesso sem bloquear a tela
  Toast.fire({
    icon: 'success',
    title: `Contato ${name} cadastrado com sucesso!`,
  });

  form.reset();
});

// Manipulador do botão de cancelamento
cancelBtn.addEventListener('click', async () => {
  const result = await Swal.fire({
    title: 'Descartar alterações?',
    text: 'Os dados preenchidos serão perdidos.',
    icon: 'question',
    showCancelButton: true,
    confirmButtonText: 'Sim, descartar',
    cancelButtonText: 'Continuar editando',
  });

  if (result.isConfirmed) {
    form.reset();
  }
});
```

## Boas Práticas e Acessibilidade

O uso de modais e alertas na interface deve ser equilibrado para evitar a frustração do usuário.

A tabela abaixo resume os cuidados essenciais:

| Cenário | O que fazer | O que evitar |
| :--- | :--- | :--- |
| **Notificações secundárias** | Use *toasts* no canto da tela com fechamento automático. | Não abra modais centrais que exigem clique para avisos corriqueiros. |
| **Ações destrutivas** | Use diálogos modais com botões de cores contrastantes (`#dc2626`). | Não execute exclusões em lote sem confirmação explícita. |
| **Navegação por Teclado** | Mantenha o foco preso no modal (*focus trap*) e feche com `ESC`. | Não permita que o foco do teclado navegue por trás do modal aberto. |
| **Carregamento de CSS** | Importe sempre o arquivo `sweetalert2.min.css`. | Não confie em estilos inline sem importar as folhas de animação e layout. |

<Aside type="caution" title="Dica de IA: Cuidado com validação síncrona dentro do modal">
  Assistentes costumam sugerir o fechamento manual do modal antes da conclusão da chamada de rede com `fetch()`. Se a requisição falhar, o usuário já perdeu o contexto visual do erro.

  **Prompt:** *"Refatore a função com SweetAlert2 para usar a opção `preConfirm` com Promise assíncrona, exibindo o indicador de loading no botão e mantendo o modal aberto se a API retornar erro HTTP."*
</Aside>

## Desafio

Implemente um modal de autenticação com campo de entrada de texto (*input*) embutido no SweetAlert2. O modal deve solicitar a senha de administrador antes de autorizar a exclusão de um recurso, validando se o campo foi preenchido através da propriedade `preConfirm`.

<details>
  <summary>Possível resposta</summary>

  ```js title="Solução do desafio"
  import Swal from 'sweetalert2';
  import 'sweetalert2/dist/sweetalert2.min.css';

  export async function requestAdminPassword() {
    const { value: password } = await Swal.fire({
      title: 'Acesso Restrito',
      text: 'Digite a senha mestra de administrador para continuar:',
      input: 'password',
      inputPlaceholder: 'Senha de segurança',
      inputAttributes: {
        autocapitalize: 'off',
        autocorrect: 'off',
      },
      showCancelButton: true,
      confirmButtonText: 'Autenticar',
      cancelButtonText: 'Cancelar',
      preConfirm: (value) => {
        if (!value) {
          Swal.showValidationMessage('A senha é obrigatória!');
          return false;
        }
        return value;
      },
    });

    if (password) {
      Swal.fire({
        icon: 'success',
        title: 'Acesso autorizado',
        timer: 1500,
        showConfirmButton: false,
      });
      return true;
    }
    return false;
  }
  ```
</details>

## Perguntas de revisão

Responda às perguntas abaixo para consolidar seu aprendizado:

1. **Por que o método nativo `window.alert()` é desaconselhado em aplicações web modernas?**
   <details>
     <summary>Possível resposta</summary>
     Porque ele bloqueia a thread principal do navegador (congelando a renderização e animações da interface), não pode ser estilizado e oferece acessibilidade limitada.
   </details>

2. **Como o SweetAlert2 comunica ao código JavaScript qual botão foi clicado pelo usuário?**
   <details>
     <summary>Possível resposta</summary>
     Através do retorno de uma Promise que resolve em um objeto de resultado contendo propriedades booleanas como `isConfirmed`, `isDenied` e `isDismissed`.
   </details>

3. **Qual é a finalidade do método `Swal.mixin()`?**
   <details>
     <summary>Possível resposta</summary>
     Criar instâncias pré-configuradas reutilizáveis do SweetAlert2 com parâmetros padrão fixos, como é comum para notificações flutuantes do tipo *toast*.
   </details>

4. **Por que é essencial importar o arquivo `sweetalert2.min.css` no projeto?**
   <details>
     <summary>Possível resposta</summary>
     Para garantir que as classes de estilo, posicionamento fixo, transições, animações de ícones e fundo escurecido (*backdrop*) sejam aplicados corretamente.
   </details>
