Este tópico apresenta o **React Native** e o ecossistema **Expo**, as tecnologias líderes para construir aplicativos móveis nativos para **iOS** e **Android** utilizando JavaScript, TypeScript e o modelo de componentes do React.

Diferente de abordagens híbridas baseadas em WebViews encapsuladas (como Cordova ou Ionic), o React Native renderiza componentes de interface de usuário verdadeiramente nativos do sistema operacional, garantindo desempenho suave de 60/120 FPS, gestos fluidos e acesso direto às APIs de hardware (câmera, biometria, acelerômetro e notificações push).

## Objetivo

Compreender a arquitetura, os componentes fundamentais e o fluxo de desenvolvimento de aplicativos móveis com React Native e Expo, aplicando os conceitos de interfaces nativas. Ao final do tópico, o leitor deve ser capaz de:

- Diferenciar a renderização de elementos web (HTML/DOM) da renderização de componentes nativos (`<View>`, `<Text>`, `<Pressable>`).
- Explicar a evolução arquitetural da antiga *Bridge* assíncrona para a **Nova Arquitetura** baseada em **JSI (JavaScript Interface)** e **Fabric**.
- Utilizar o **Expo** para prototipagem rápida, configuração de dependências e automação de builds nativos.
- Estilizar telas com `StyleSheet` e flexbox no modelo de eixos do React Native.
- Gerenciar navegação entre telas através do Expo Router / React Navigation.
- Executar e depurar aplicativos em emuladores e em dispositivos físicos.

## O Modelo Mental: Web vs Mobile Nativo

No desenvolvimento web com React, os componentes produzem nós do DOM do navegador (como `<div>`, `<button>` e `<p>`). No React Native, a árvore de componentes controla widgets nativos do sistema operacional correspondente:

A tabela a seguir compara os elementos equivalentes entre as duas plataformas:

| Conceito | React Web (DOM) | React Native (Nativo) | Comportamento no SO |
| :--- | :--- | :--- | :--- |
| **Contêiner / Bloco** | `<div>` | `<View>` | `UIView` no iOS / `android.view.ViewGroup` no Android. |
| **Texto / Parágrafo** | `<p>`, `<span>`, `<h1>` | `<Text>` | `UILabel` / `UITextView` no iOS / `TextView` no Android. |
| **Imagens** | `<img>` | `<Image>` | `UIImageView` no iOS / `ImageView` no Android. |
| **Botão e Cliques** | `<button>`, `<a>` | `<Pressable>` ou `<TouchableOpacity>` | Gerencia toques, feedback háptico e eventos de pressão. |
| **Listas com Scroll** | `<div>` com overflow | `<FlatList>` ou `<ScrollView>` | Reciclagem virtualizada de memória em listas longas. |
| **Entrada de Texto** | `<input type="text">` | `<TextInput>` | Teclado nativo com suporte a autocorreção e máscaras. |

No React Native, **todo texto precisa obrigatoriamente estar dentro de uma tag `<Text>`**, e o modelo padrão de Flexbox adota `flexDirection: 'column'` por padrão (otimizado para telas verticais de smartphones).

## Fundamentos: A Evolução da Arquitetura

O React Native passou por uma modernização estrutural profunda, migrando de uma ponte assíncrona para comunicação síncrona em C++:

### 1. Arquitetura Clássica (A *Bridge*)
O código JavaScript rodava em uma thread separada e se comunicava com o código nativo (Objective-C/Swift/Java/Kotlin) serializando mensagens JSON assíncronas através de uma ponte (*bridge*). Em animações complexas ou scrolls rápidos com muitos dados, essa ponte podia gerar gargalos de latência (*bridge congestion*).

### 2. A Nova Arquitetura (JSI, Fabric e TurboModules)
- **JSI (JavaScript Interface)**: Uma camada escrita em C++ que permite ao motor JavaScript (Hermes) invocar métodos nativos diretamente em memória, sem serialização JSON.
- **Fabric**: O novo renderizador concorrente que unifica a árvore de renderização com suporte a renderização síncrona e prioritária.
- **TurboModules**: Carregamento sob demanda (*lazy loading*) de módulos nativos, acelerando o tempo de inicialização do app.

O diagrama abaixo compara os dois modelos:

## O Papel do Expo no Ecossistema

O **Expo** é a ferramenta e suíte de serviços oficial recomendada pela equipe do React para criar aplicações React Native. Ele elimina a necessidade imediata de configurar ambientes pesados com Xcode ou Android Studio durante os primeiros passos de desenvolvimento.

A tabela abaixo resume as duas formas de trabalhar com Expo:

| Modo Expo | Como funciona | Quando utilizar |
| :--- | :--- | :--- |
| **Expo Go** | Aplicativo cliente baixado na App Store/Play Store que carrega o código do projeto via QR Code. | Prototipagem rápida, aulas e testes instantâneos em dispositivos físicos. |
| **Expo Prebuild (CNG)** | Gera os diretórios nativos `ios/` e `android/` sob demanda a partir de plugins declarativos no `app.json`. | Projetos profissionais com bibliotecas nativas customizadas e publicação em lojas. |

O serviço **EAS (Expo Application Services)** permite compilar os binários finais `.ipa` (iOS) e `.aab` (Android) na nuvem, dispensando a posse de um computador Mac para gerar builds de produção para iPhone.

## Anatomia de uma Tela com React Native e Expo

Veja um exemplo prático de tela com formulário e lista utilizando componentes primitivos e a API `StyleSheet`:

```tsx title="src/screens/HomeScreen.tsx"
import { useState } from 'react';
import {
  View,
  Text,
  TextInput,
  Pressable,
  FlatList,
  StyleSheet,
  SafeAreaView,
  StatusBar,
} from 'react-native';

export default function HomeScreen() {
  const [tarefas, setTarefas] = useState<string[]>(['Estudar React Native', 'Configurar Expo']);
  const [novaTarefa, setNovaTarefa] = useState('');

  function adicionarTarefa() {
    if (novaTarefa.trim()) {
      setTarefas([...tarefas, novaTarefa]);
      setNovaTarefa('');
    }
  }

  return (
    <SafeAreaView style={styles.container}>
      <StatusBar barStyle="dark-content" />
      <Text style={styles.titulo}>Minhas Tarefas Mobile</Text>

      <View style={styles.inputContainer}>
        <TextInput
          style={styles.input}
          placeholder="Digite uma nova tarefa..."
          value={novaTarefa}
          onChangeText={setNovaTarefa}
        />
        <Pressable style={styles.botao} onPress={adicionarTarefa}>
          <Text style={styles.textoBotao}>Adicionar</Text>
        </Pressable>
      </View>

      <FlatList
        data={tarefas}
        keyExtractor={(_, index) => index.toString()}
        renderItem={({ item }) => (
          <View style={styles.itemCard}>
            <Text style={styles.itemTexto}>{item}</Text>
          </View>
        )}
      />
    </SafeAreaView>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: '#F8FAFC',
    paddingHorizontal: 20,
    paddingTop: 40,
  },
  titulo: {
    fontSize: 24,
    fontWeight: 'bold',
    color: '#0F172A',
    marginBottom: 20,
  },
  inputContainer: {
    flexDirection: 'row',
    marginBottom: 20,
    gap: 10,
  },
  input: {
    flex: 1,
    backgroundColor: '#FFFFFF',
    borderWidth: 1,
    borderColor: '#CBD5E1',
    borderRadius: 8,
    paddingHorizontal: 12,
    fontSize: 16,
    height: 48,
  },
  botao: {
    backgroundColor: '#4F46E5',
    justifyContent: 'center',
    alignItems: 'center',
    paddingHorizontal: 16,
    borderRadius: 8,
    height: 48,
  },
  textoBotao: {
    color: '#FFFFFF',
    fontWeight: '600',
    fontSize: 16,
  },
  itemCard: {
    backgroundColor: '#FFFFFF',
    padding: 16,
    borderRadius: 8,
    marginBottom: 10,
    borderWidth: 1,
    borderColor: '#E2E8F0',
  },
  itemTexto: {
    fontSize: 16,
    color: '#334155',
  },
});
```

**Prompt:** *"Converta este componente React Web para React Native utilizando apenas primitivos nativos (`<View>`, `<Text>`, `<Pressable>`), estilos compatíveis com StyleSheet e tratamento de safe areas."*
</Aside>

## Executando

Para criar e testar um aplicativo móvel em minutos utilizando o Expo:

<Steps>
1. **Crie um novo projeto Expo:**


   ```bash title="Terminal"

   npx expo start
   ```

## Exercício

Identifique os erros no trecho de código React Native abaixo e reescreva-o de forma correta:

```tsx title="Trecho com erros conceituais"
export function CartaoUsuario({ nome, bio }) {
  return (
    <div className="cartao" onClick={() => alert('Clicou')}>
      <h1>{nome}</h1>
      <p>{bio}</p>
    </div>
  );
}
```

<details>
  <summary>Possível resposta</summary>

  O código possui três erros conceituais principais:
  1. Uso de tags HTML web (`<div>`, `<h1>`, `<p>`) em vez de primitivos nativos (`<View>`, `<Text>`, `<Pressable>`).
  2. Uso de `className` com classes CSS web em vez do atributo `style={styles...}` com `StyleSheet`.
  3. Uso do evento web `onClick` em uma `<div>` em vez do evento `onPress` em um `<Pressable>`.

  ```tsx title="Versão corrigida"
  import { View, Text, Pressable, StyleSheet, Alert } from 'react-native';

  export function CartaoUsuario({ nome, bio }: { nome: string; bio: string }) {
    return (
      <Pressable style={styles.cartao} onPress={() => Alert.alert('Aviso', 'Clicou')}>
        <Text style={styles.titulo}>{nome}</Text>
        <Text style={styles.descricao}>{bio}</Text>
      </Pressable>
    );
  }

  const styles = StyleSheet.create({
    cartao: {
      backgroundColor: '#FFF',
      padding: 16,
      borderRadius: 8,
      borderWidth: 1,
      borderColor: '#E2E8F0',
    },
    titulo: {
      fontSize: 20,
      fontWeight: 'bold',
      marginBottom: 4,
    },
    descricao: {
      fontSize: 14,
      color: '#64748B',
    },
  });
  ```
</details>

## Desafio

Explique o mecanismo de reciclagem de elementos da `<FlatList>` no React Native e justifique por que utilizar `<ScrollView>` com o método `.map()` em listas com milhares de itens causa esgotamento de memória (Out-Of-Memory / OOM) em smartphones.

<details>
  <summary>Possível resposta</summary>

  O `<ScrollView>` renderiza **todos** os elementos filhos de uma só vez na memória do dispositivo, mesmo aqueles que estão fora da tela e nunca foram visualizados pelo usuário. Se a lista contiver 1.000 itens com fotos, o sistema operacional tentará alocar memória gráfica para todas as imagens simultaneamente, causando lentidão severa ou fechamento forçado do app (crash por OOM).

  A `<FlatList>` implementa **virtualização e reciclagem de células**:
  - Ela renderiza apenas os itens atualmente visíveis na janela de exibição (*viewport*) mais uma pequena margem de buffer.
  - À medida que o usuário rola a tela, os componentes que saem do topo são desmontados da memória e suas estruturas nativas são recicladas para exibir os novos itens que entram na parte inferior.
  - Isso mantém o consumo de memória constante e previsível, independentemente de a lista ter 10 ou 100.000 registros.
</details>

## Perguntas de revisão

Responda às questões para consolidar o aprendizado:

1. **O que é o motor Hermes e qual é a sua principal vantagem no React Native?**
   <details>
     <summary>Possível resposta</summary>
     Hermes é um motor JavaScript de código aberto otimizado especificamente para rodar aplicativos móveis. Ele pré-compila o código JavaScript em bytecode durante o build, reduzindo o tempo de inicialização (*Time to Interactive*), o consumo de memória RAM e o tamanho do pacote do app.
   </details>

2. **Qual é a principal diferença entre o React Native e abordagens baseadas em WebView (como Cordova/Capacitor)?**
   <details>
     <summary>Possível resposta</summary>
     Abordagens baseadas em WebView renderizam um navegador web comum dentro de uma janela do app; o React Native executa o JavaScript em uma thread dedicada e mapeia a interface para componentes nativos reais do iOS e Android, proporcionando desempenho e sensação tátil nativa.
   </details>

3. **Por que no React Native o Flexbox adota `flexDirection: 'column'` como padrão?**
   <details>
     <summary>Possível resposta</summary>
     Porque a grande maioria das interfaces em smartphones é consumida em orientação vertical (retrato), tornando o empilhamento vertical a convenção mais natural para o fluxo de telas móveis.
   </details>

4. **Como o Expo Application Services (EAS) resolve a limitação de compilar apps iOS sem possuir um Mac?**
   <details>
     <summary>Possível resposta</summary>
     O EAS Build recebe o código-fonte do projeto e executa a compilação nativa do Xcode em servidores macOS remotos na nuvem, entregando o arquivo `.ipa` assinado e pronto para envio à App Store.
   </details>
