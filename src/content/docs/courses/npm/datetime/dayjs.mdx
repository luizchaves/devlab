Este tópico apresenta o **Day.js**, uma biblioteca JavaScript minimalista e imutável para manipular, validar, formatar e calcular datas e horários no navegador e no Node.js.

Trabalhar com datas nativas no JavaScript através do objeto `Date` tradicional costuma ser fonte de inconsistências, especialmente em operações de adição, comparação, cálculo de tempo relativo ("há 5 minutos") e formatação localizada. O Day.js resolve essas dificuldades com uma interface fluente e previsível inspirada no Moment.js, mantendo uma pegada ultra-leve de apenas 2 KB no *bundle* final.

## Objetivo

Dominar o uso da biblioteca Day.js para operações temporais no front-end, compreendendo sua arquitetura baseada em imutabilidade e plugins modulares. Ao final do tópico, o leitor deve ser capaz de:

- Explicar as vantagens do Day.js em relação ao objeto nativo `Date` e ao legado Moment.js.
- Instalar e instanciar objetos temporais a partir de strings, timestamps e objetos existentes.
- Formatar datas em múltiplos padrões textuais e idiomas (incluindo Português do Brasil).
- Estender a funcionalidade central carregando plugins oficiais como *relativeTime*, *customParseFormat* e *utc*.
- Realizar operações de cálculo, comparação e verificação de intervalos no front-end.

## O que é o Day.js?

O Day.js é uma biblioteca que encapsula a manipulação de datas sob uma estrutura imutável. No JavaScript clássico, métodos como `date.setMonth()` modificam o objeto original diretamente (*mutabilidade*), o que pode causar efeitos colaterais silenciosos em diferentes partes de uma interface. No Day.js, qualquer operação gera uma nova instância sem alterar a anterior.

A tabela a seguir compara as principais características do Day.js com outras abordagens disponíveis no ecossistema:

| Abordagem | Tamanho aproximado | Imutável? | Sistema de Plugins | Cenário ideal de uso |
| :--- | :--- | :--- | :--- | :--- |
| **`Date` nativo + `Intl`** | 0 KB (nativo) | Não (`Date`) | Não aplicável | Formatações simples sem operações complexas. |
| **Day.js** | ~2 KB | Sim | Sim (modular) | Aplicações web modernas que precisam de cálculos e tempo relativo. |
| **date-fns** | Modular (por função) | Sim | Não (funções puras) | Projetos com foco extremo em *tree-shaking* funcional. |
| **Moment.js** | ~70 KB | Não | Legado | Projetos legados em fase de manutenção. |

A escolha pelo Day.js é indicada quando a equipe busca uma API orientada a objetos fluente, de fácil leitura e com suporte a localização e plugins sem comprometer o tempo de carregamento da página.

## Fundamentos e Modelo Mental

O funcionamento do Day.js se apoia em dois pilares: a imutabilidade do objeto temporal e o carregamento seletivo de recursos por meio de plugins. O núcleo da biblioteca contém apenas os métodos essenciais de leitura e formatação básica. Recursos especializados (como cálculo de fuso horário, tempo relativo e formatação avançada) são ativados sob demanda.

O diagrama abaixo ilustra o fluxo de dados desde a criação da instância até a formatação para a interface:

<Mermaid title="Fluxo de criação, transformação e formatação com Day.js">
{`
flowchart TD
  A["Entrada bruta<br/>(ISO string, timestamp, Date)"] --> B["dayjs(...)<br/>Instância Imutável"]
  B --> C{"Operação necessária?"}
  C -->|"Cálculo"| D["clone transformado<br/>.add() / .subtract()"]
  C -->|"Formatação"| E["Texto pronto<br/>.format() / .fromNow()"]
  C -->|"Comparação"| F["Booleano<br/>.isBefore() / .isAfter()"]
  D --> E
`}
</Mermaid>

Como cada transformação gera uma nova referência, componentes de interface podem compartilhar instâncias de datas sem o perigo de que uma modificação em um cartão altere os dados exibidos em outro componente.

## Como Usar: Instalação e Configuração

A biblioteca pode ser instalada diretamente via npm em projetos empacotados por ferramentas como Vite, ou consumida via CDN para demonstrações rápidas.

No terminal do seu projeto, execute o comando de instalação:

```bash title="Terminal"
npm install dayjs
```

Após a instalação, importe a biblioteca e os módulos de localização necessários para formatar datas no idioma do usuário:

```js title="src/main.js"
import dayjs from 'dayjs';
import 'dayjs/locale/pt-br';
import relativeTime from 'dayjs/plugin/relativeTime';
import customParseFormat from 'dayjs/plugin/customParseFormat';

// Define o idioma padrão da aplicação para Português do Brasil
dayjs.locale('pt-br');

// Registra os plugins necessários
dayjs.extend(relativeTime);
dayjs.extend(customParseFormat);
```

Com os plugins registrados globalmente, todos os novos objetos `dayjs` passam a contar com os métodos estendidos de forma integrada.

## Sintaxe e Principais Recursos

A API do Day.js é encadeável e expressiva. A seguir, exploramos as principais operações de criação, formatação, manipulação e comparação.

### Criação e Formatação de Datas

Para instanciar uma data, basta invocar a função principal `dayjs()` passando uma data, string ISO ou deixando em branco para obter a data e hora atuais.

O trecho a seguir demonstra a formatação em múltiplos padrões textuais:

```js title="Exemplos de formatação com Day.js"
import dayjs from 'dayjs';

const now = dayjs();

// Formatação padrão com tokens
console.log(now.format('DD/MM/YYYY')); // Ex: "15/05/2026"
console.log(now.format('DD/MM/YYYY [às] HH:mm:ss')); // Ex: "15/05/2026 às 14:30:00"
console.log(now.format('dddd, D [de] MMMM [de] YYYY')); // Ex: "Sexta-feira, 15 de Maio de 2026"
```

A tabela abaixo resume os principais identificadores (*tokens*) aceitos pelo método `.format()`:

| Token | Exemplo de saída | Descrição |
| :--- | :--- | :--- |
| `DD` | `05`, `28` | Dia do mês com dois dígitos preenchidos. |
| `MM` | `01`, `12` | Mês do ano em formato numérico de dois dígitos. |
| `MMMM` | `Janeiro`, `Dezembro` | Nome por extenso do mês no idioma ativo. |
| `YYYY` | `2026` | Ano com quatro dígitos. |
| `HH:mm` | `14:30` | Horas e minutos no formato de 24 horas. |
| `[texto]` | `às`, `de` | Escapa texto literal para não ser interpretado como token. |

### Manipulação e Cálculo de Intervalos

Operações aritméticas como somar dias, subtrair meses ou calcular o início de um período utilizam métodos encadeáveis e sem efeitos colaterais:

```js title="Operações de adição e subtração temporal"
import dayjs from 'dayjs';

const baseDate = dayjs('2026-05-10');

// Adiciona 7 dias e 2 meses
const futureDate = baseDate.add(7, 'day').add(2, 'month');
console.log(futureDate.format('DD/MM/YYYY')); // "17/07/2026"

// Início do mês atual
const startOfMonth = baseDate.startOf('month');
console.log(startOfMonth.format('DD/MM/YYYY')); // "01/05/2026"
```

### Tempo Relativo (*Relative Time*)

Com o plugin `relativeTime` ativado, a biblioteca converte intervalos em frases legíveis para seres humanos, recurso fundamental para notificações, redes sociais e históricos de logs:

```js title="Exemplo de cálculo de tempo relativo"
import dayjs from 'dayjs';
import relativeTime from 'dayjs/plugin/relativeTime';
import 'dayjs/locale/pt-br';

dayjs.locale('pt-br');
dayjs.extend(relativeTime);

const postDate = dayjs().subtract(45, 'minute');
console.log(postDate.fromNow()); // "há 45 minutos"

const deadline = dayjs().add(3, 'day');
console.log(deadline.fromNow()); // "em 3 dias"
```

## Exemplo Prático no Front-end

O exemplo a seguir constrói um feed de notificações em uma página web. Ele consome dados de eventos com timestamps e formata tanto a data legível quanto o tempo decorrido desde a ocorrência do evento.

O arquivo HTML define a estrutura dos cartões de notificação:

```html title="index.html"
<!DOCTYPE html>
<html lang="pt-BR">
  <head>
    <meta charset="UTF-8" />
    <title>Feed de Notificações com Day.js</title>
    <link rel="stylesheet" href="./style.css" />
  </head>
  <body>
    <main class="container">
      <h1>Notificações Recentes</h1>
      <div id="notifications-list" class="list"></div>
    </main>
    <script type="module" src="./main.js"></script>
  </body>
</html>
```

O arquivo JavaScript configura o Day.js com localização em português e renderiza a lista dinamicamente:

```js title="src/main.js"
import dayjs from 'dayjs';
import 'dayjs/locale/pt-br';
import relativeTime from 'dayjs/plugin/relativeTime';

dayjs.locale('pt-br');
dayjs.extend(relativeTime);

const notifications = [
  { id: 1, title: 'Deploy concluído com sucesso', timestamp: '2026-05-15T18:00:00Z' },
  { id: 2, title: 'Novo comentário no chamado #104', timestamp: '2026-05-15T14:30:00Z' },
  { id: 3, title: 'Backup automático agendado', timestamp: '2026-05-18T03:00:00Z' },
];

const container = document.getElementById('notifications-list');

container.innerHTML = notifications
  .map((item) => {
    const date = dayjs(item.timestamp);
    const isFuture = date.isAfter(dayjs());
    const relativeText = date.fromNow();
    const formattedDate = date.format('DD/MM/YYYY [às] HH:mm');

    return `
      <article class="card ${isFuture ? 'card-future' : ''}">
        <h3>${item.title}</h3>
        <p class="timestamp"><strong>Quando:</strong> ${formattedDate} (${relativeText})</p>
      </article>
    `;
  })
  .join('');
```

## Boas Práticas e Armadilhas

O trabalho com datas exige cuidados específicos em relação a fusos horários, formatos de parsing e importação de idiomas.

A tabela abaixo resume as principais armadilhas e as recomendações práticas:

| Cenário / Armadilha | Risco no projeto | Como proceder corretamente |
| :--- | :--- | :--- |
| **Parsing de formatos customizados** | `dayjs('15/05/2026')` pode falhar ou inverter mês e dia sem aviso. | Ative o plugin `customParseFormat` e declare a máscara: `dayjs('15/05/2026', 'DD/MM/YYYY')`. |
| **Fuso horário do servidor vs cliente** | Exibir horários UTC crus causa confusão para usuários em diferentes fusos. | Formate os dados no fuso local do navegador ou utilize o plugin oficial `timezone`. |
| **Importar todos os idiomas** | Importar pacotes completos de idiomas sem necessidade infla o *bundle*. | Importe explicitamente apenas os idiomas suportados pelo seu sistema (`import 'dayjs/locale/pt-br'`). |
| **Comparação de igualdade** | `dateA === dateB` compara referências de memória, retornando `false`. | Utilize métodos de comparação dedicados como `dateA.isSame(dateB, 'day')`. |

<Aside type="caution" title="Dica de IA: Cuidado com fusos horários implícitos">
  Assistentes de código costumam sugerir o parsing direto de strings no formato `YYYY-MM-DD` sem considerar que alguns navegadores interpretam datas sem horário como UTC à meia-noite, provocando deslocamentos de 1 dia para trás em fusos como o de Brasília (UTC-3).

  **Prompt:** *"Revise a manipulação de datas abaixo, garantindo que o parsing trate o fuso horário de forma explícita e não cause retrocesso de um dia ao renderizar em fusos negativos."*
</Aside>

## Exercício

Crie uma função utilitária chamada `formatTimelineDate(isoString)` que receba uma string de data em formato ISO e retorne uma string formatada conforme as regras:

1. Se a data for de hoje, retorne `"Hoje às HH:mm"`.
2. Se a data for de ontem, retorne `"Ontem às HH:mm"`.
3. Para qualquer outra data anterior, retorne `"DD/MM/YYYY às HH:mm"`.

Utilize os métodos de comparação do Day.js (`.isSame()`, `.subtract()`).

<details>
  <summary>Possível resposta</summary>

  ```js title="Solução do exercício"
  import dayjs from 'dayjs';
  import 'dayjs/locale/pt-br';

  dayjs.locale('pt-br');

  export function formatTimelineDate(isoString) {
    const target = dayjs(isoString);
    const now = dayjs();
    const yesterday = now.subtract(1, 'day');

    if (target.isSame(now, 'day')) {
      return target.format('[Hoje às] HH:mm');
    }

    if (target.isSame(yesterday, 'day')) {
      return target.format('[Ontem às] HH:mm');
    }

    return target.format('DD/MM/YYYY [às] HH:mm');
  }
  ```
</details>

## Desafio

Implemente um contador regressivo dinâmico (*countdown*) para uma data limite futura (ex: prazo final de entrega de projeto). A cada segundo, atualize no DOM os dias, horas, minutos e segundos restantes utilizando os métodos `.diff()` do Day.js, tratando o estado quando o prazo for atingido.

<details>
  <summary>Possível resposta</summary>

  ```js title="Solução do desafio"
  import dayjs from 'dayjs';

  export function startCountdown(targetIsoDate, element) {
    const target = dayjs(targetIsoDate);

    const intervalId = setInterval(() => {
      const now = dayjs();
      const diffMs = target.diff(now);

      if (diffMs <= 0) {
        element.textContent = 'Prazo encerrado!';
        clearInterval(intervalId);
        return;
      }

      const days = target.diff(now, 'day');
      const hours = target.diff(now.add(days, 'day'), 'hour');
      const minutes = target.diff(now.add(days, 'day').add(hours, 'hour'), 'minute');
      const seconds = target.diff(now.add(days, 'day').add(hours, 'hour').add(minutes, 'minute'), 'second');

      element.textContent = `${days}d ${hours}h ${minutes}m ${seconds}s restantes`;
    }, 1000);

    return () => clearInterval(intervalId);
  }
  ```
</details>

## Perguntas de revisão

Responda às questões abaixo para fixar os conceitos abordados:

1. **Por que a imutabilidade do Day.js evita bugs em aplicações front-end?**
   <details>
     <summary>Possível resposta</summary>
     Porque operações de alteração de data geram uma nova instância em vez de modificar o objeto existente na memória, prevenindo efeitos colaterais indesejados em componentes que compartilham a mesma data.
   </details>

2. **Qual é a vantagem do sistema de plugins do Day.js sobre bibliotecas monolíticas?**
   <details>
     <summary>Possível resposta</summary>
     Permite que o núcleo da biblioteca permaneça minúsculo (~2 KB), importando apenas os módulos específicos necessários para a aplicação (como cálculo de fuso ou tempo relativo).
   </details>

3. **Como evitar que tokens de formatação interpretem palavras literais como letras de data?**
   <details>
     <summary>Possível resposta</summary>
     Envolvendo o texto literal entre colchetes dentro da máscara de formatação, como em `[às]` ou `[de]`.
   </details>

4. **Qual método deve ser utilizado para calcular a diferença entre duas datas em dias?**
   <details>
     <summary>Possível resposta</summary>
     O método `.diff(outraData, 'day')`.
   </details>
