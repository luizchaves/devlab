Etapa **1 de 6** · Nível **Iniciante** · HTML · Tailwind CSS · Vite · Sem BaaS conectado

Esta etapa constrói a superfície do InvestBaaS antes de persistir dados. As páginas definem os campos, os estados visuais e a navegação que as sprints seguintes vão conectar ao Supabase. Os números da carteira, a autenticação e os indicadores administrativos são exemplos estáticos.

<Aside type="note" title="Tópicos conceituais associados">
  A etapa usa HTML semântico e organização de projetos com [npm](../../../). O contrato de dados começa na etapa de [Banco de dados e RLS](../database/).
</Aside>

## Objetivo

Construir um protótipo navegável que descreva a experiência do InvestBaaS antes da infraestrutura. Ao final da etapa, o leitor deve ser capaz de:

- Diferenciar dado demonstrativo de dado persistido.
- Identificar as telas e os contratos visuais que a trilha vai implementar.
- Executar e revisar a interface estática com Vite e Biome.

## O que muda nesta etapa?

Como é a primeira etapa, tudo entra pela primeira vez. A fronteira mais importante é negativa: o protótipo não tem SDK, credencial, banco ou comportamento de domínio. Isso mantém a UX revisável sem criar a falsa impressão de que um formulário já cadastrou uma conta.

| Entra | Fica para a Sprint 2 ou posterior |
| ----- | --------------------------------- |
| HTML semântico, Tailwind por CDN e CSS de componentes. | `@supabase/supabase-js`, sessão e chamadas remotas. |
| Links e formulários navegáveis. | Cadastro, login e redirecionamento por sessão real. |
| Valores de exemplo em tabelas e cards. | Dados de `assets`, `transactions` e `quotes_history`. |
| Scripts Vite e qualidade. | Migrations, Edge Functions, bucket e policies. |

<Aside type="tip" title="Dica de IA: Gerar o AGENTS.md com governança e convenções para IA">
  O arquivo `AGENTS.md` define as regras operacionais, os padrões arquiteturais e o fluxo de trabalho para assistentes e agentes autônomos de IA. Utilize o prompt abaixo para gerá-lo:

  ```markdown
  Atue como Arquiteto de Sistemas BaaS e Engenheiro de IA Sênior.
  Gere o arquivo `AGENTS.md` para o InvestBaaS, definindo as diretrizes completas de governança para agentes de código:

  1. **Papel e Escopo**: plataforma de gestão patrimonial com front-end em HTML5, Tailwind CSS e JavaScript modular, e back-end fornecido pelo Supabase.
  2. **Regras Invioláveis de Arquitetura**:
     - BaaS e serverless: banco, identidade, arquivos e funções residem no Supabase; proibido criar servidor Express ou API intermediária.
     - Row Level Security em 100% das tabelas de domínio (`enable row level security`), com policies comparando `auth.uid()` a `user_id` em `using` e `with check`.

     - Cotações e qualquer segredo (chave de serviço, token de provedor) exclusivamente em Edge Functions; no navegador só `VITE_SUPABASE_URL` e `VITE_SUPABASE_ANON_KEY`.

  5. **Fluxo Spec-Driven Development**: ciclo de 5 passos (consulta no PRD → branch `feat/tkXX-Y-...` → spec via skill em `specs/active/` → implementação e validação → PR via skill e arquivamento em `specs/archived/`).
  ```

</Aside>

## Conceitos abordados

## Exercício

Liste os campos visuais de `dashboard.html` que devem virar dados de `assets` e os que devem ser calculados a partir de `transactions`. Justifique cada escolha.

## Desafio

Desenhe o estado vazio de uma carteira recém-criada: sem ativos, sem rentabilidade e com uma ação clara para iniciar o primeiro cadastro. Não introduza dados falsos para preencher a interface.

## Perguntas de revisão

1. Por que o protótipo não deve guardar uma sessão falsa no navegador?
2. Qual tela serve para validar a leitura de rentabilidade mensal?
3. Por que `admin.html` não deve mostrar ativos individuais?
4. Qual é a diferença entre campo visual preparado e dado já persistido?
