Etapa **4 de 6** · Nível **Avançado** · Deno · Edge Functions · Idempotência · Agendamento

O preço de mercado não deve ser buscado pelo navegador com uma chave de provedor. Nesta etapa, a Edge Function concentra a integração externa, atualiza o preço atual e acrescenta uma observação ao histórico sem parar toda a execução quando um ticker falha.

<Aside type="note" title="Tópicos conceituais associados">
  Compare este desenho com [chamadas de sistema](../../../../expressjs/advanced/system-call/): nos dois casos, uma integração externa fica fora da superfície exposta diretamente ao usuário.
</Aside>

## Objetivo

Projetar uma atualização de cotações que preserve segredos, histórico e transparência operacional. Ao final da etapa, o leitor deve ser capaz de:

- Justificar por que a integração de mercado reside em uma Edge Function.
- Definir resultado idempotente para cada ticker e para a execução completa.
- Tratar falha parcial sem fabricar preço ou ocultar atraso de cotação.

## Caminho de uma cotação

A invocação do usuário não recebe privilégio de banco. A função valida a chamada, usa os segredos do ambiente para falar com o provedor e devolve apenas um resumo que a interface pode exibir.

## O que muda nesta etapa?

Pela primeira vez a trilha escreve código que roda **fora** do navegador e com privilégio que o navegador não tem. É a única camada da aplicação que conhece a chave de serviço e o token do provedor de mercado.

| Antes (Sprint 3) | Agora (Sprint 4) |
| ---------------- | ---------------- |
| `current_price` digitado à mão ou nulo | Preenchido pela função a partir do provedor |
| `quotes_history` vazia | Uma linha por ativo e por dia, idempotente |
| Botão **Atualizar Cotações** sem efeito | `supabase.functions.invoke('update-quotes')` com o JWT da sessão |
| Só a chave anônima existe | `SUPABASE_SERVICE_ROLE_KEY` e `MARKET_API_TOKEN`, ambos só no ambiente da função |
| Nenhum registro de operação | `quote_runs` com instante, totais e falhas de cada execução |
| Nada agendado | `pg_cron` chamando a função uma vez por dia |

## Descrição das tarefas

Abaixo estão detalhadas as tarefas de implementação desta etapa, com orientações e os trechos de código que cada uma produz.

### TK04-1 · Criar a estrutura da `update-quotes`

A CLI cria a pasta e o esqueleto. Uma Edge Function é um servidor HTTP em Deno: `Deno.serve` recebe uma `Request` e devolve uma `Response`, o mesmo par que o navegador usa no `fetch`. O contrato de saída é definido antes do primeiro `fetch` ao provedor, porque é ele que o dashboard e o admin vão consumir.

```bash title="Terminal"
supabase init
supabase functions new update-quotes
```

```ts title="Contrato da funcao (alvo de supabase/functions/update-quotes/types.ts)"
export type Quote = { ticker: string; price: number; quoteDate: string };
export type QuoteFailure = { ticker: string; reason: 'not_found' | 'provider_error' };

export type RunSummary = {
  ranAt: string;
  updated: number;
  failed: QuoteFailure[];
};
```

### TK04-2 · Buscar os ativos elegíveis com a chave de serviço

A função precisa dos tickers de **todas** as contas, e o RLS impediria isso com a chave anônima. Por isso ela cria um segundo cliente, com a `service_role`, lida de `Deno.env`. É a única linha da aplicação em que essa chave aparece, e ela nunca sai da função.

Antes disso, a função confere quem chamou: o cabeçalho `Authorization` do `invoke` é validado com um cliente comum, e uma chamada sem sessão válida termina em `401` antes de qualquer acesso privilegiado.

```ts title="Dois clientes, dois privilegios (alvo de supabase/functions/update-quotes/index.ts)"
import { createClient } from 'npm:@supabase/supabase-js@2';

Deno.serve(async (req) => {
  // 1. Quem chamou? O JWT do usuario e verificado com a chave anonima.
  const anon = createClient(
    Deno.env.get('SUPABASE_URL')!,
    Deno.env.get('SUPABASE_ANON_KEY')!,
    { global: { headers: { Authorization: req.headers.get('Authorization') ?? '' } } },
  );
  const { data: { user } } = await anon.auth.getUser();
  if (!user) return Response.json({ error: 'Sessao invalida' }, { status: 401 });

  // 2. O que atualizar? A chave de servico ignora o RLS e ve todos os ativos.
  const admin = createClient(
    Deno.env.get('SUPABASE_URL')!,
    Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')!,
  );
  const { data: assets } = await admin
    .from('assets')
    .select('id, ticker')
    .in('category', ['acoes', 'fiis']);

  // ... TK04-3 a TK04-5
});
```

Só `acoes` e `fiis` são elegíveis: são as categorias com ticker negociado em bolsa. Renda fixa, fundos e cripto ficam com o preço informado pela pessoa, e a página deixa esse limite explícito.

### TK04-3 · Criar o adaptador do provedor

O provedor real muda de contrato, de limite de requisições e de preço. O adaptador isola isso atrás de uma função `fetchQuotes(tickers)` que devolve o tipo `Quote[]` da TK04-1, e um adaptador **simulado** implementa o mesmo contrato com uma tabela fixa de preços. O simulado é escolhido por variável de ambiente, e é o que os testes locais usam: ele nunca inventa preço para um ticker que não conhece.

```ts title="Adaptador real e simulado (alvo de supabase/functions/update-quotes/market-provider.ts)"
import type { Quote } from './types.ts';

export interface MarketProvider {
  fetchQuotes(tickers: string[]): Promise<Quote[]>;
}

export const brapiProvider: MarketProvider = {
  async fetchQuotes(tickers) {
    const token = Deno.env.get('MARKET_API_TOKEN')!;
    const res = await fetch(`https://brapi.dev/api/quote/${tickers.join(',')}?token=${token}`);
    if (!res.ok) throw new Error(`Provedor respondeu ${res.status}`);

    const { results } = await res.json();
    return results.map((r: any) => ({
      ticker: r.symbol,
      price: r.regularMarketPrice,
      quoteDate: new Date().toISOString().slice(0, 10),
    }));
  },
};

export const fakeProvider: MarketProvider = {
  async fetchQuotes(tickers) {
    const table: Record<string, number> = { PETR4: 38.42, VALE3: 61.1, HGLG11: 162.3 };
    // Ticker desconhecido fica de fora: a falha e registrada, nao mascarada.
    return tickers.filter((t) => t in table).map((ticker) => ({
      ticker, price: table[ticker], quoteDate: new Date().toISOString().slice(0, 10),
    }));
  },
};

export const provider = Deno.env.get('MARKET_PROVIDER') === 'fake' ? fakeProvider : brapiProvider;
```

### TK04-4 · Persistir preço e histórico de forma idempotente

Duas escritas por ticker: o `current_price` em `assets` e a linha do dia em `quotes_history`. A segunda usa `upsert` com `onConflict: 'asset_id,quote_date'`, a chave única da Sprint 3. Rodar a função duas vezes no mesmo dia sobrescreve a mesma linha em vez de duplicar a série.

```ts title="Gravar preco atual e historico (trecho de index.ts)"
for (const quote of quotes) {
  const asset = assets.find((a) => a.ticker === quote.ticker)!;

  await admin.from('assets').update({ current_price: quote.price }).eq('id', asset.id);

  await admin
    .from('quotes_history')
    .upsert(
      { asset_id: asset.id, price: quote.price, quote_date: quote.quoteDate },
      { onConflict: 'asset_id,quote_date' },
    );
}
```

### TK04-5 · Registrar falhas por ticker sem abortar a execução

Um ticker que o provedor não conhece não pode derrubar a atualização dos outros trinta. O resultado é calculado pela diferença entre o que foi pedido e o que voltou; um erro do provedor inteiro (rede, `429`, `500`) marca **todos** os tickers como `provider_error`, e a função ainda responde `200` com o resumo, porque a chamada em si funcionou.

```ts title="Falha parcial vira dado, nao excecao (trecho de index.ts)"
const tickers = assets.map((a) => a.ticker);
let quotes: Quote[] = [];
let failed: QuoteFailure[] = [];

try {
  quotes = await provider.fetchQuotes(tickers);
  const found = new Set(quotes.map((q) => q.ticker));
  failed = tickers.filter((t) => !found.has(t)).map((ticker) => ({ ticker, reason: 'not_found' }));
} catch {
  failed = tickers.map((ticker) => ({ ticker, reason: 'provider_error' }));
}
```

### TK04-6 · Ligar o botão do dashboard

Do lado do navegador, uma linha: `functions.invoke` já envia o JWT da sessão no `Authorization`. O botão fica desabilitado durante a chamada, e o resumo devolvido vira uma frase: "12 atualizados, 1 sem cotação (XPTO3)". Em seguida a carteira é recarregada, porque os `current_price` mudaram.

```js title="Invocacao autenticada (alvo de src/services/quotes.js)"
import { supabase } from '../lib/supabase-client.js';

export async function updateQuotes() {
  return supabase.functions.invoke('update-quotes');
}
```

```js title="O botao do dashboard (trecho de src/pages/dashboard.js)"
refreshButton.addEventListener('click', async () => {
  refreshButton.disabled = true;

  const { data, error } = await updateQuotes();

  refreshButton.disabled = false;
  if (error) return showToast('Nao foi possivel atualizar as cotacoes');

  showToast(`${data.updated} atualizados, ${data.failed.length} sem cotacao`);
  await renderPortfolio();
});
```

### TK04-7 · Registrar o status operacional

O admin da Sprint 6 precisa responder "quando foi a última atualização, e ela deu certo?" sem ler carteira nenhuma. A tabela `quote_runs` guarda um resumo por execução, gravado pela função com a chave de serviço no fim do processamento. O RLS fica ligado e sem policy: ninguém lê pela chave anônima, e a Sprint 6 abre a leitura só para `role = 'admin'`.

```sql title="Migration de quote_runs (alvo de supabase/migrations/0006_quote_runs.sql)"
create table public.quote_runs (
  id uuid primary key default gen_random_uuid(),
  ran_at timestamptz not null default now(),
  requested integer not null,
  updated integer not null,
  failed jsonb not null default '[]'::jsonb
);

alter table public.quote_runs enable row level security;
```

```ts title="O resumo gravado e devolvido (fim de index.ts)"
const summary: RunSummary = { ranAt: new Date().toISOString(), updated: quotes.length, failed };

await admin.from('quote_runs').insert({ requested: tickers.length, updated: quotes.length, failed });

return Response.json(summary);
```

### TK04-8 · Agendar a execução diária

O botão cobre o uso manual; o agendamento cobre o dia em que ninguém clica. O `pg_cron` roda dentro do PostgreSQL e chama a função por HTTP com `pg_net`, uma vez por dia depois do fechamento do pregão. O segredo usado nessa chamada é o mesmo `service_role`, guardado no cofre do banco (`vault`), não na string do `cron.schedule`.

```sql title="Agendamento (alvo de supabase/migrations/0007_schedule_quotes.sql)"
select cron.schedule(
  'update-quotes-daily',
  '30 21 * * 1-5',  -- 18h30 em Brasilia, de segunda a sexta
  $$
  select net.http_post(
    url := 'https://<projeto>.supabase.co/functions/v1/update-quotes',
    headers := jsonb_build_object(
      'Authorization', 'Bearer ' || (select decrypted_secret from vault.decrypted_secrets where name = 'service_role_key')
    )
  );
  $$
);
```

Na chamada agendada não há usuário: a função reconhece a `service_role` no `Authorization` e pula a checagem de sessão da TK04-2. É a única exceção, e ela está documentada no `README.md` do projeto junto com o horário.

## Decisões de implementação

| Decisão | Regra | Razão |
| ------- | ----- | ----- |
| Segredo | Token do provedor em variável do ambiente Edge. | O navegador não pode reutilizá-lo. |
| Histórico | Uma cotação por ativo e data, ou chave de idempotência equivalente. | Reexecuções não duplicam a série. |
| Erro | Resultado por ticker. | Um ativo indisponível não invalida os demais. |
| Auditoria | Guardar data, totais e mensagem de falha. | Admin identifica atraso sem ler carteiras. |

<Aside type="caution" title="Dica de IA: Não use preços aleatórios como cotação">
  Um fallback aleatório parece manter a tela viva, mas contamina rentabilidade e mascara uma falha de integração. Um adaptador simulado é aceitável somente quando identificado e isolado para teste.

  **Prompt:** *"Revise o contrato de update-quotes do InvestBaaS; proponha um resultado por ticker que diferencie preço válido, ativo sem cotação e erro temporário, sem inventar valores financeiros."*
</Aside>

## Conceitos abordados

- Edge Function como o único lugar da aplicação com privilégio de serviço
- Dois clientes na mesma função: o anônimo verifica quem chamou, o de serviço lê o que precisa
- Adaptador de provedor com contrato estável e alternativa simulada para testes
- `upsert` sobre chave única como garantia de idempotência
- Falha parcial registrada por ticker, sem preço inventado e sem abortar a execução
- Resumo operacional gravado em tabela fechada por RLS
- `pg_cron` e `pg_net` para a execução diária, com o segredo no `vault`
