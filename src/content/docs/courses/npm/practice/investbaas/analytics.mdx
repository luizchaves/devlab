Etapa **6 de 7** · Nível **Avançado** · SQL analítico · Views · Agregação · Autorização por papel

Analytics só é confiável quando parte de transações e cotações reais. Esta etapa conecta a matriz visual a consultas reproduzíveis e cria um painel administrativo cujo valor está na agregação, não na visibilidade de carteiras individuais.

## Objetivo

Transformar fatos financeiros em indicadores auditáveis e fornecer operação administrativa sem abrir carteiras individuais. Ao final da etapa, o leitor deve ser capaz de:

- Diferenciar retorno, aporte, dado ausente e acumulado anual.
- Definir uma consulta que alimente a matriz somente com dados do investidor autenticado.
- Projetar métricas administrativas agregadas e protegidas por papel.

### TK06-1 · Criar a view de rentabilidade mensal

O retorno de um mês é a variação do patrimônio **descontados os aportes**: se a carteira valia 10.000, recebeu 1.000 de compras e fechou em 11.500, o ganho de mercado foi 500, não 1.500. A view calcula, para cada investidor e mês, o valor da carteira no último dia com cotação e o fluxo líquido de transações; a diferença entre meses consecutivos, menos o fluxo, é o retorno.

```sql title="View monthly_returns (alvo de supabase/migrations/0010_analytics_views.sql)"
create view public.monthly_returns with (security_invoker = true) as
with month_value as (
  -- Patrimonio de cada ativo no ultimo dia com cotacao do mes
  select a.user_id, date_trunc('month', q.quote_date)::date as month,
         sum(p.quantity * q.price) as value
  from public.assets a
  join public.quotes_history q on q.asset_id = a.id
  join lateral (
    select coalesce(sum(case when t.type = 'buy' then t.quantity else -t.quantity end), 0) as quantity
    from public.transactions t
    where t.asset_id = a.id and t.transaction_date <= q.quote_date
  ) p on true
  where q.quote_date = (
    select max(quote_date) from public.quotes_history
    where asset_id = a.id and date_trunc('month', quote_date) = date_trunc('month', q.quote_date)
  )
  group by a.user_id, 2
),
month_flow as (
  select user_id, date_trunc('month', transaction_date)::date as month,
         sum(case when type = 'buy' then quantity * price else -quantity * price end) as net_flow
  from public.transactions
  group by user_id, 2
)
select v.user_id, v.month,
       v.value,
       coalesce(f.net_flow, 0) as net_flow,
       v.value
         - coalesce(lag(v.value) over (partition by v.user_id order by v.month), 0)
         - coalesce(f.net_flow, 0) as return_brl
from month_value v
left join month_flow f on f.user_id = v.user_id and f.month = v.month;
```

`security_invoker = true` é a linha que mantém o RLS: a view roda com os privilégios de quem consulta, então o `auth.uid()` das policies de `assets` e `transactions` continua filtrando. Sem essa opção, a view rodaria como o dono (o `postgres`) e devolveria a matriz de todo mundo.

### TK06-2 · Calcular o acumulado anual

O acumulado do ano não é a soma dos retornos mensais em reais dividida pelo patrimônio: é a **composição** dos percentuais. Um mês de +10% seguido de -10% deixa a carteira em 99%, não em 100%. A função é pura e recebe a lista de meses da view.

```js title="Composicao anual (alvo de src/lib/returns.js)"
export function monthlyPct(row) {
  const base = Number(row.value) - Number(row.return_brl);
  return base ? Number(row.return_brl) / base : null;
}

export function yearlyPct(rows) {
  const factors = rows.map(monthlyPct).filter((pct) => pct !== null);
  if (factors.length === 0) return null;
  return factors.reduce((acc, pct) => acc * (1 + pct), 1) - 1;
}
```

Mês sem dado devolve `null`, e `null` não entra na composição. É o que impede um mês sem cotação de virar "0%" e achatar o ano.

### TK06-3 · Ligar `analytics.html` à view

A tela pede a view pelo SDK, agrupa por ano e desenha a matriz que a Sprint 1 desenhou à mão. A lógica de cor é a mesma do protótipo (verde para positivo, vermelho para negativo), e a célula sem dado recebe `—`, sem classe de cor.

```js title="Da view para a matriz (alvo de src/pages/analytics.js)"
import { supabase } from '../lib/supabase-client.js';
import { monthlyPct, yearlyPct } from '../lib/returns.js';

const { data: rows } = await supabase
  .from('monthly_returns')
  .select('month, value, net_flow, return_brl')
  .order('month');

const byYear = Object.groupBy(rows, (row) => row.month.slice(0, 4));

for (const [year, months] of Object.entries(byYear)) {
  const cells = Array.from({ length: 12 }, (_, i) => {
    const row = months.find((m) => Number(m.month.slice(5, 7)) === i + 1);
    return row ? monthlyPct(row) : null;
  });

  matrixBody.append(renderYearRow(year, cells, yearlyPct(months)));
}
```

Repare que a consulta não filtra `user_id`: a view é `security_invoker`, e o RLS entrega só os meses de quem está logado.

### TK06-4 · Criar a distribuição por classe e a evolução patrimonial

A distribuição é uma view curta sobre `assets` e a posição atual; a evolução patrimonial reutiliza `month_value` da TK06-1, então a migration a expõe como uma segunda view em vez de repetir o SQL.

```sql title="View allocation_by_category (continuacao de 0010_analytics_views.sql)"
create view public.allocation_by_category with (security_invoker = true) as
select a.user_id, a.category,
       sum(p.quantity * coalesce(a.current_price, 0)) as value
from public.assets a
join lateral (
  select coalesce(sum(case when type = 'buy' then quantity else -quantity end), 0) as quantity
  from public.transactions where asset_id = a.id
) p on true
group by a.user_id, a.category;
```

### TK06-5 · Criar a métrica administrativa agregada

`admin_metrics()` devolve **uma linha**: contas ativas, AUM (a soma de todas as carteiras) e o instante da última execução de cotações. Ela é `security definer` para enxergar todas as contas, e por isso a primeira coisa que faz é conferir o papel de quem chama. Um investidor recebe zero linhas.

```sql title="Funcao admin_metrics (alvo de supabase/migrations/0011_admin_metrics.sql)"
create function public.admin_metrics()
returns table (active_accounts bigint, aum numeric, last_quote_run timestamptz)
language sql security definer set search_path = public as $$
  select
    (select count(*) from public.profiles),
    (select coalesce(sum(value), 0) from public.allocation_by_category),
    (select max(ran_at) from public.quote_runs)
  where exists (select 1 from public.profiles where id = auth.uid() and role = 'admin');
$$;

create policy "quote_runs: admin le" on public.quote_runs
  for select using (
    exists (select 1 from public.profiles where id = auth.uid() and role = 'admin')
  );
```

A agregação acontece **dentro** da função. Uma alternativa que devolvesse uma linha por conta para o JavaScript somar já teria exposto o patrimônio de cada pessoa, ainda que a tela mostrasse só o total.

### TK06-6 · Proteger o painel por papel

A guarda de admin estende a de sessão: além de exigir login, lê `profiles.role`. Como a policy de `profiles` da Sprint 2 só deixa cada pessoa ler a própria linha, essa consulta é segura por construção. E, como toda guarda de front, ela é cortesia: quem realmente barra o investidor é o `exists` da função `admin_metrics()`.

```js title="Guarda por papel (alvo de src/guards/require-admin.js)"
import { supabase } from '../lib/supabase-client.js';
import { requireSession } from './require-session.js';

export async function requireAdmin() {
  const session = await requireSession();

  const { data: profile } = await supabase
    .from('profiles')
    .select('role')
    .eq('id', session.user.id)
    .single();

  if (profile?.role !== 'admin') {
    window.location.replace('./dashboard.html');
    return new Promise(() => {});
  }

  return session;
}
```

O papel é promovido no SQL Editor, nunca por uma tela: `update public.profiles set role = 'admin' where id = '<id>'`. Não existe policy de `update` em `role`, então nem o próprio usuário consegue se promover pelo SDK.

### TK06-7 · Exibir o status operacional

Os cinco indicadores do `admin.html` da Sprint 1 ganham fonte. Cada um é uma chamada barata e independente, e um indicador que falha não derruba os outros: o `Promise.allSettled` transforma cada resultado em verde, vermelho ou "sem dado".

| Indicador | Como é medido | Verde quando |
| --------- | ------------- | ------------ |
| Auth | `supabase.auth.getSession()` | há sessão válida |
| Banco | `select 1` via `rpc('ping')` ou leitura de `profiles` | responde em menos de 1 s |
| Cotações | `last_quote_run` de `admin_metrics()` | última execução nas últimas 24 h |
| Storage | `admin_receipts_stats()` da Sprint 5 | a função responde |
| Jobs | `select * from cron.job_run_details order by 1 desc limit 1` via função `security definer` | último status é `succeeded` |

```js title="Status com falhas independentes (trecho de src/pages/admin.js)"
const checks = await Promise.allSettled([checkAuth(), checkDatabase(), checkQuotes(), checkStorage(), checkJobs()]);

checks.forEach((result, i) => {
  const ok = result.status === 'fulfilled' && result.value;
  statusCells[i].dataset.status = ok ? 'up' : 'down';
});
```

### TK06-8 · Revisar a responsividade com dados reais

A matriz tem treze colunas, e em um celular ela não cabe. O protótipo já a envolvia em `overflow-x-auto`; com dados reais a revisão confere três coisas: a primeira coluna (ano) fixa com `sticky left-0` enquanto os meses rolam, a fonte não menor que `text-xs`, e a tabela do admin quebrando em cartões abaixo de `sm`. A verificação é feita no *device toolbar* do navegador, em 375 px e 1280 px.

| Dado | Investidor | Administrador |
| ---- | ---------- | ------------- |
| Própria matriz e distribuição | permitido por RLS. | não é necessário para operação. |

Como Ana, cadastre `PETR4`, registre uma compra de 100 a `R$ 30,00` em 10 de janeiro e outra de 100 a `R$ 32,00` em 10 de fevereiro, e insira as cotações abaixo pelo SQL Editor (a Edge Function faria isso, mas o teste precisa de datas passadas).

```sql title="SQL Editor: cotacoes de referencia"
insert into public.quotes_history (asset_id, price, quote_date)
select id, p.price, p.quote_date
from public.assets, (values (31.0, date '2026-01-31'), (33.0, date '2026-02-28')) as p(price, quote_date)
where ticker = 'PETR4';
```

A planilha de referência tem duas linhas, e a view precisa reproduzi-las:

| Mês | Patrimônio no fim | Aportes | Retorno (R$) | Retorno (%) |
| --- | ----------------- | ------- | ------------ | ----------- |
| jan | 100 × 31 = 3.100 | 3.000 | 3.100 − 0 − 3.000 = **100** | 100 / 3.000 = **3,33%** |
| fev | 200 × 33 = 6.600 | 3.200 | 6.600 − 3.100 − 3.200 = **300** | 300 / 6.300 = **4,76%** |

```sql title="SQL Editor: a view como a Ana"
select month, value, net_flow, return_brl from public.monthly_returns order by month;
-- Esperado: 2026-01-01 | 3100 | 3000 | 100  e  2026-02-01 | 6600 | 3200 | 300 (CA06.2)
```

Março não tem cotação nem transação: a matriz mostra `—` na célula e o acumulado do ano fica em `(1,0333 × 1,0476) − 1 = 8,25%`, sem que o mês vazio o dilua (CA06.1). Logado como Bruno, a mesma view devolve zero linhas (CA06.3).

## Conceitos abordados

| Conceito | Aplicação nesta etapa |
| -------- | --------------------- |
| Série temporal | Cotações e posições são interpretadas por data. |
| Dados ausentes | Falta de observação não equivale a retorno zero. |
| Composição | Acumulado anual é uma regra explícita, não soma ingênua. |
| Agregação | AUM soma patrimônio sem expor a linha que o compõe. |
| Papel | Administração é uma capacidade adicional, não um bypass geral. |
