A disciplina de [Linguagem e Técnicas de Programação II](../../courses/lp2-ctii-jp/docs/plano-de-ensino.pdf) (LP2)
faz parte do 3º ano do Curso Técnico de Nível Médio Integrado em Informática do IFPB. Ela
possui carga horária de 80 horas (30 teóricas e 50 práticas), com dois encontros semanais,
e é ministrada pelo professor Luiz Carlos Chaves.

O foco da disciplina é compreender, projetar e desenvolver aplicações cliente/servidor
para a plataforma Web. Ao longo do ano, revisamos o JavaScript e seu uso no navegador,
construímos um back-end com Node.js e Express.js, integramos a aplicação a um banco de
dados com SQL e com o ORM Prisma e, por fim, adicionamos autenticação, validação, envio
de e-mail, upload de arquivos e testes automatizados.

A trilha principal evolui um projeto em etapas, no mesmo ritmo dos tópicos. Começamos
com um front-end que gera páginas a partir de dados em JSON, avançamos para uma **API
REST** organizada em MVC e persistida em banco de dados e terminamos com uma aplicação
completa, autenticada e testada.

Os tópicos combinam exposição, leitura de código, exercícios e atividades práticas. As
avaliações são as entregas do projeto em equipe, uma a cada etapa, com apresentação e
arguição individual sobre o código.

Como pré-requisito, espera-se conhecimento prévio de Linguagem e Técnicas de
Programação I (algoritmos e JavaScript) e de HTML e CSS.

## Avaliações

A nota de cada bimestre vem das entregas do [projeto da disciplina](project/), com duas
etapas por bimestre. O tema do projeto é livre, definido pela equipe antes da primeira
entrega, e a mesma aplicação ganha uma camada a cada etapa. Cada entrega tem critérios
pontuados, apresentação e arguição individual, e a página do projeto traz um prompt de
autoavaliação com IA para cada uma.

A composição das 4 avaliações ao longo do ano é estruturada da seguinte forma:

<Steps>

1. **Avaliação I — Front-end e Back-end**

   Pontuada pelas entregas [B1.1 - Front-end](project/#b11---front-end) (páginas
   estilizadas, dados em JSON, módulos ESM e eventos) e
   [B1.2 - Back-end e Integração com o Front-end](project/#b12---back-end-e-integração-com-o-front-end)
   (API REST com Express, dados em memória, REST Client e `fetch`).

2. **Avaliação II — Banco de Dados**

   Pontuada pelas entregas [B2.1 - Banco de Dados com SQL](project/#b21---banco-de-dados-com-sql)
   (modelagem relacional, MVC, migration e seed em SQL) e
   [B2.2 - Banco de Dados com Prisma](project/#b22---banco-de-dados-com-prisma)
   (`schema.prisma`, ERD, migrations, Prisma Client e CRUD pelo front-end).

3. **Avaliação III — Autenticação e Validação**

   Pontuada pelas entregas [B3.1 - Autenticação de usuário](project/#b31---autenticação-de-usuário)
   (hash de senha, login, JWT e middleware de proteção) e
   [B3.2 - Validação e Envio de E-mail](project/#b32---validação-e-envio-de-e-mail)
   (schemas com Zod, respostas `400` e serviço de e-mail).

4. **Avaliação IV — Upload e Testes**

   Pontuada pelas entregas [B4.1 - Upload de Arquivos](project/#b41---upload-de-arquivos)
   (Multer, rotas protegidas e `FormData`) e
   [B4.2 - Testes Automatizados](project/#b42---testes-automatizados)
   (unidade, rotas, front, E2E e cobertura).

</Steps>

## Ferramentas

Estas ferramentas serão usadas com frequência durante a disciplina. Outras opções podem
funcionar, mas os exemplos e orientações nas aulas partem deste conjunto.

| Categoria | Ferramenta | Uso principal |
| --------- | ---------- | ------------- |
| Ambiente de execução | [Node.js](https://nodejs.org/en/) | Executar JavaScript no servidor e instalar dependências |
| Editor | [Visual Studio Code](http://code.visualstudio.com) | Escrever, organizar e testar o código dos projetos |
| Cliente HTTP | [REST Client](https://marketplace.visualstudio.com/items?itemName=humao.rest-client) | Testar as rotas da API em arquivos `requests.http` |
| Banco de dados | [SQLite](https://www.sqlite.org/) e [Prisma](https://www.prisma.io/) | Persistir os dados da aplicação, com SQL e com ORM |
| Navegador | [Chrome](https://www.google.com/chrome/browser/index.html) | Testar páginas, usar DevTools e depurar comportamento |
| Versionamento | [Git](https://git-scm.com/) | Controlar histórico, publicar código e acompanhar entregas |

<Aside type="tip" title="Todo código é executável">
  Os exemplos dos tópicos vivem em projetos reais dentro de `examples/` no repositório
  e são importados pela documentação. Você pode clonar, instalar e rodar qualquer um
  deles.
</Aside>
