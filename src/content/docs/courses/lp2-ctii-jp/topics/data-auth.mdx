A API do tópico anterior guarda os dados em memória: reiniciou o servidor, perdeu
tudo. Este tópico resolve isso e, na sequência, decide **quem** pode ver e alterar
cada informação.

São dois problemas distintos que costumam aparecer juntos. Persistência responde
"onde os dados ficam"; autenticação responde "quem está fazendo esta requisição".

## O que esperar deste tópico

SQL a partir do Node.js, depois o Prisma com schema, migrations e relacionamentos.
Em seguida o cadastro de usuário com senha protegida e a autenticação com **JWT**,
incluindo o middleware que barra requisições sem token válido.

<Aside type="caution" title="Senha nunca é armazenada em texto puro">
  O cadastro de usuário usa hash. Guardar a senha como veio do formulário expõe todos
  os usuários caso o banco vaze — e é um erro que a disciplina trata como grave.
</Aside>
