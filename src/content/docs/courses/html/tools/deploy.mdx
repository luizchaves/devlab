Após criar e estilizar páginas HTML e CSS no computador local, o passo fundamental seguinte é tornar a aplicação acessível publicamente para qualquer pessoa no mundo através da internet.

O processo de enviar os arquivos do projeto para um servidor na nuvem é chamado de **Deploy** (ou Publicação).

Hoje, existem plataformas de hospedagem estática gratuitas de alta performance (como **GitHub Pages**, **Vercel** e **Netlify**) que automatizam a publicação direta a partir do controle de versão com Git.

---

## Objetivo

Compreender o fluxo de publicação de um site estático, configurar um repositório Git local, subir o código para o GitHub e realizar o deploy automatizado utilizando GitHub Pages e Vercel.

## Testando Localmente com Live Server

Antes de publicar o site para o mundo, você deve testar o comportamento dos arquivos no seu computador.

A extensão **Live Server** para o Visual Studio Code cria um servidor HTTP local simples com recarregamento automático (*Hot Reload*):

1. **Instale a extensão `Live Server`** no VS Code.
2. **Clique com o botão direito** no arquivo `index.html`.
3. **Selecione `Open with Live Server`**. O site abrirá em `http://127.0.0.1:5500/`.

<Aside type="note" title="Por que usar um servidor local?">
  Abrir o arquivo clicando duas vezes (`file:///C:/meu-site/index.html`) pode quebrar links relativos de imagens e impedir o funcionamento de requisições assíncronas. O Live Server simula o comportamento real de um servidor HTTP.
</Aside>

## Publicando no GitHub Pages (Passo a Passo)

O **GitHub Pages** é o serviço gratuito do GitHub que transforma qualquer repositório público em um site no ar.

Siga os passos a seguir para publicar seu primeiro site:

<Steps>

1. **Inicialize o Git na pasta do seu projeto**:
   ```bash title="Terminal"
   git init
   git add -A
   git commit -m "Primeira versão do site"
   ```

2. **Crie um repositório público no GitHub** (ex: `meu-primeiro-site`).

3. **Vincule o repositório local ao GitHub e faça o push**:
   ```bash title="Terminal"
   git remote add origin https://github.com/seu-usuario/meu-primeiro-site.git
   git branch -M main
   git push -u origin main
   ```

4. **Ative o GitHub Pages**:
   - No GitHub, acesse a aba **Settings** do seu repositório.
   - Na barra lateral esquerda, clique em **Pages**.
   - Em **Source**, selecione a branch `main` e a pasta `/ (root)`.
   - Clique em **Save**.

5. **Acesse seu site no ar**: Após cerca de 1 minuto, seu site estará disponível na URL `https://seu-usuario.github.io/meu-primeiro-site/`.

</Steps>

## Publicando na Vercel ou Netlify

Plataformas como **Vercel** e **Netlify** oferecem publicação instantânea conectando diretamente sua conta do GitHub:

1. Acesse o painel da [Vercel](https://vercel.com) ou [Netlify](https://netlify.com).
2. Clique em **Add New Project** e escolha **Import from GitHub**.
3. Selecione o repositório do seu site.
4. Clique em **Deploy**. A plataforma fornecerá um domínio gratuito com certificado SSL/HTTPS automático (ex: `meu-site.vercel.app`).

Toda vez que você fizer um novo `git push` no GitHub, a Vercel/Netlify atualizará o site automaticamente em segundos!

## Desafio

<details>
  <summary>Possível resposta</summary>

  3. Cole o link público gerado pelo GitHub Pages (`https://seu-usuario.github.io/meu-portfolio/`).

## Perguntas de revisão

### Conceitos de Deploy

1. **O que significa fazer o *deploy* de uma aplicação Web?**
   <details>
     <summary>Possível resposta</summary>

     Significa transferir os arquivos do projeto para um servidor web na nuvem para tornar a aplicação acessível publicamente via URL na internet.
   </details>

2. **Qual a vantagem de usar o Live Server em relação a abrir o arquivo HTML diretamente clicando duas vezes?**
   <details>
     <summary>Possível resposta</summary>

     O Live Server simula um protocolo HTTP real (`http://`), permitindo que caminhos relativos e recursos de rede funcionem exatamente como funcionariam em produção, além de oferecer recarregamento automático.
   </details>

3. **Qual é o formato da URL padrão gerada pelo GitHub Pages?**
   <details>
     <summary>Possível resposta</summary>

     `https://seu-usuario.github.io/nome-do-repositorio/`
   </details>

### Controle de Versão e CI/CD

4. **Por que o arquivo principal da página deve ser nomeado exatamente como `index.html`?**
   <details>
     <summary>Possível resposta</summary>

     Porque os servidores Web (Nginx, Apache, GitHub Pages) buscam por padrão o arquivo `index.html` como a página inicial raiz daquele diretório.
   </details>

5. **O que acontece quando você envia um novo `git push` para um repositório conectado à Vercel?**
   <details>
     <summary>Possível resposta</summary>

     A Vercel detecta a alteração automaticamente, compila a nova versão e atualiza o site no ar sem interrupção de serviço.
   </details>

6. **O GitHub Pages é gratuito para repositórios públicos?**
   <details>
     <summary>Possível resposta</summary>

     Sim, o GitHub Pages oferece hospedagem estática gratuita para repositórios públicos.
   </details>

7. **Sites hospedados no GitHub Pages e Vercel possuem certificado de segurança SSL (HTTPS)?**
   <details>
     <summary>Possível resposta</summary>

     Sim, ambas as plataformas emitem certificados HTTPS/SSL criptografados automaticamente para todas as URLs.
   </details>

8. **Qual o primeiro comando necessário para transformar uma pasta comum em um repositório Git?**
   <details>
     <summary>Possível resposta</summary>

     `git init`
   </details>

9. **Podemos publicar sites dinâmicos com banco de dados MySQL diretamente no GitHub Pages?**
   <details>
     <summary>Possível resposta</summary>

     Não. O GitHub Pages suporta apenas arquivos estáticos (HTML, CSS, JS no cliente, imagens). Aplicações com banco de dados precisam de servidores backend (como Render, Railway ou Supabase).
   </details>

10. **Como cancelar ou desativar uma publicação no GitHub Pages?**
    <details>
      <summary>Possível resposta</summary>

      Acessando **Settings > Pages** no repositório do GitHub e alterando a fonte da branch para **None**.
    </details>
