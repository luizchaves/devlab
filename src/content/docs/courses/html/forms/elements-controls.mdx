Formulários são a principal forma de uma página Web coletar dados: login, cadastro,
busca, contato, filtros, comentários, upload de arquivos e escolhas em geral. Em
HTML, o objetivo não é desenhar o formulário, mas marcar corretamente cada controle
para que navegador, leitores de tela, validação e scripts entendam o que está sendo
pedido.

## Objetivo

Construir formulários HTML com campos, rótulos, botões e agrupamentos básicos,
entendendo o papel de `name`, `id`, `for`, `type`, `value`, `placeholder` e
`required`.

## Estrutura de um Formulário

O elemento `<form>` agrupa controles relacionados. Ele pode enviar dados para um
servidor, mas mesmo antes de aprender back-end já é importante escrever a estrutura
correta.

```plaintext title="Anatomia de um formulário"
   formulário        rótulo             campo               botão
┌─────┴─────┐   ┌─────┴─────┐   ┌────────┴────────┐   ┌──────┴──────┐
<form>       <label>Nome</label> <input name="nome"> <button>Enviar</button>
```

A tabela a seguir apresenta os papéis dos principais elementos que compõem a estrutura de um formulário HTML:

| Elemento | Papel |
| -------- | ----- |
| `<form>` | Agrupa campos e define como os dados podem ser enviados |
| `<label>` | Descreve um campo para pessoas e tecnologias assistivas |
| `<input>` | Cria campos de entrada de diferentes tipos |
| `<textarea>` | Cria um campo de texto com várias linhas |
| `<select>` | Cria uma lista de opções |
| `<button>` | Cria uma ação, como enviar ou limpar o formulário |

<Aside type="tip" title="Rótulo não é enfeite">
  Um campo sem `<label>` pode até funcionar visualmente, mas fica pior para
  acessibilidade, clique, leitura por tecnologias assistivas e manutenção. Sempre que
  possível, associe o texto do rótulo ao campo.
</Aside>

## Rótulos e Identificação

A ligação entre `<label>` e campo é feita com dois atributos: `for` no rótulo e `id`
no controle. Os valores precisam ser iguais.

<div class="form-preview not-content my-4 rounded-lg border border-sl-gray-5 bg-white p-4 text-slate-900">
  <label for="cpf">CPF:</label>{' '}
  <input type="text" name="cpf" id="cpf" />
</div>

```html title="Campo com rótulo"
<div>
  <label for="cpf">CPF:</label>
  <input type="text" name="cpf" id="cpf" />
</div>
```

| Atributo | Onde aparece | Papel |
| -------- | ------------ | ----- |
| `id` | no campo | Identifica um elemento específico na página |
| `for` | no `<label>` | Aponta para o `id` do campo descrito |
| `name` | no campo | Nome usado quando o valor é enviado ou lido por scripts |

<Aside type="note" title="`id` e `name` não são a mesma coisa">
  `id` identifica o elemento dentro da página. `name` identifica o dado do campo no
  formulário. Eles podem ter o mesmo valor, mas cumprem papéis diferentes.
</Aside>

Referências: [label | MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/label)
e [input | MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input).

## Campos de Texto

Campos de texto recebem pequenas entradas digitadas pelo usuário. O mesmo elemento
`<input>` muda de comportamento conforme o valor do atributo `type`.

### Texto simples

<div class="form-preview not-content my-4 rounded-lg border border-sl-gray-5 bg-white p-4 text-slate-900">
  <input type="text" name="cpf" />
</div>

```html
<input type="text" name="cpf" />
```

### Obrigatório

O atributo `required` informa ao navegador que o campo precisa ser preenchido antes
do envio do formulário.

<div class="form-preview not-content my-4 rounded-lg border border-sl-gray-5 bg-white p-4 text-slate-900">
  <form>
    <input type="text" name="cpf" required /> *
  </form>
</div>

```html
<input type="text" name="cpf" required /> *
```

### Dica e valor inicial

`placeholder` mostra uma dica temporária. `value` define um valor já preenchido.

<div class="form-preview not-content my-4 rounded-lg border border-sl-gray-5 bg-white p-4 text-slate-900">
  <input type="text" name="cpf" placeholder="000.000.000-00" />{' '}
  <input type="text" name="cpfExemplo" value="000.000.000-00" />
</div>

```html
<input type="text" name="cpf" placeholder="000.000.000-00" />
<input type="text" name="cpfExemplo" value="000.000.000-00" />
```

<Aside type="caution" title="Placeholder não substitui label">
  `placeholder` desaparece quando a pessoa começa a digitar. Use-o como dica, não
  como o único texto que explica o campo.
</Aside>

### Senha, número, data e e-mail

Tipos específicos ajudam o navegador a oferecer teclado adequado, validação inicial
e controles nativos. No celular, essa diferença fica mais visível: `type="number"`
pode abrir um teclado numérico, `type="email"` pode exibir `@` com mais destaque e
`type="date"` pode abrir um seletor de data do próprio sistema.

<div class="form-preview not-content my-4 flex flex-wrap gap-3 rounded-lg border border-sl-gray-5 bg-white p-4 text-slate-900">
  <input type="password" name="password" placeholder="Senha" />
  <input type="number" name="number" placeholder="Número" />
  <input type="date" name="date" />
  <input type="email" name="email" placeholder="email@exemplo.com" />
</div>

```html
<input type="password" name="password" placeholder="Senha" />
<input type="number" name="number" placeholder="Número" />
<input type="date" name="date" />
<input type="email" name="email" placeholder="email@exemplo.com" />
```

<Aside type="tip" title="Tipo comunica intenção">
  Usar `type="text"` para tudo tira pistas importantes do navegador. Escolher um
  tipo mais específico melhora a experiência em dispositivos móveis, ajuda na
  validação inicial e deixa o código mais claro. Por exemplo, `type="email"` permite
  ao navegador verificar se o valor parece um e-mail, `required` impede envio vazio
  e campos numéricos podem usar `min`, `max` e `step` para restringir valores.
</Aside>

Referências:
[input text](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/text),
[input password](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/password),
[input number](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/number),
[input date](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/date) e
[input email](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/email).

## Escolhas

Quando o usuário precisa escolher entre alternativas, o HTML oferece controles com
comportamentos diferentes.

| Controle | Quando usar |
| -------- | ----------- |
| `radio` | escolher uma opção entre alternativas exclusivas |
| `checkbox` | marcar zero, uma ou várias opções |
| `select` | escolher uma opção em uma lista compacta |

### Radio button

Campos `radio` com o mesmo `name` formam um grupo. Nesse grupo, apenas uma opção pode
ficar marcada.

<div class="form-preview not-content my-4 rounded-lg border border-sl-gray-5 bg-white p-4 text-slate-900">
  Sexo:{' '}
  <input type="radio" name="sexo" value="masculino" id="masculino" checked />
  <label for="masculino">masculino</label>{' '}
  <input type="radio" name="sexo" value="feminino" id="feminino" />
  <label for="feminino">feminino</label>
</div>

```html
<div>
  Sexo:
  <input type="radio" name="sexo" value="masculino" id="masculino" checked />
  <label for="masculino">masculino</label>
  <input type="radio" name="sexo" value="feminino" id="feminino" />
  <label for="feminino">feminino</label>
</div>
```

### Checkbox

Checkboxes são independentes. Vários campos podem compartilhar o mesmo `name` quando
representam uma lista de valores relacionados.

<div class="form-preview not-content my-4 rounded-lg border border-sl-gray-5 bg-white p-4 text-slate-900">
  Linguagens:{' '}
  <input type="checkbox" name="linguagens" value="javascript" id="javascript" />
  <label for="javascript">Javascript</label>{' '}
  <input type="checkbox" name="linguagens" value="c" id="c" />
  <label for="c">C</label>{' '}
  <input type="checkbox" name="linguagens" value="java" id="java" />
  <label for="java">Java</label>{' '}
  <input type="checkbox" name="linguagens" value="python" id="python" />
  <label for="python">Python</label>
</div>

```html
<div>
  Linguagens:
  <input type="checkbox" name="linguagens" value="javascript" id="javascript" />
  <label for="javascript">Javascript</label>
  <input type="checkbox" name="linguagens" value="c" id="c" />
  <label for="c">C</label>
  <input type="checkbox" name="linguagens" value="java" id="java" />
  <label for="java">Java</label>
  <input type="checkbox" name="linguagens" value="python" id="python" />
  <label for="python">Python</label>
</div>
```

### Select

`<select>` é útil quando a lista de opções ficaria longa demais para aparecer toda
na tela.

<div class="form-preview not-content my-4 rounded-lg border border-sl-gray-5 bg-white p-4 text-slate-900">
  <label for="place">Estado:</label>{' '}
  <select name="place" id="place">
    <option value="PB">Paraíba</option>
    <option value="PE">Pernambuco</option>
  </select>
</div>

```html
<div>
  <label for="place">Estado:</label>
  <select name="place" id="place">
    <option value="PB">Paraíba</option>
    <option value="PE">Pernambuco</option>
  </select>
</div>
```

Referências:
[input radio](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/radio),
[input checkbox](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/checkbox)
e [select | MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/select).

## Outros Controles

Alguns controles representam ações ou entradas menos comuns, mas aparecem com
frequência em formulários reais.

### Botões

<div class="form-preview not-content my-4 rounded-lg border border-sl-gray-5 bg-white p-4 text-slate-900">
  <input type="button" name="button" value="Create" />{' '}
  <input type="submit" name="submit" value="Create" />{' '}
  <button>Create</button>
</div>

```html
<input type="button" name="button" value="Create" />
<input type="submit" name="submit" value="Create" />
<button>Create</button>
```

### Arquivo e intervalo

<div class="form-preview not-content my-4 rounded-lg border border-sl-gray-5 bg-white p-4 text-slate-900">
  <input type="file" name="file" />
  <input type="range" name="number" min="1" max="100" step="1" />
</div>

```html
<input type="file" name="file" />
<input type="range" name="number" min="1" max="100" step="1" />
```

### Texto com várias linhas

<div class="form-preview not-content my-4 rounded-lg border border-sl-gray-5 bg-white p-4 text-slate-900">
  <label for="message">Mensagem:</label><br />
  <textarea name="message" id="message" rows="3" cols="60">digite uma mensagem</textarea>
</div>

```html
<label for="message">Mensagem:</label><br />
<textarea name="message" id="message" rows="3" cols="60">
  digite uma mensagem
</textarea>
```

Referências:
[input button](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/button),
[input file](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/file),
[input range](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/range) e
[textarea | MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/textarea).

## Formulário sem Estilo

Depois de conhecer os controles isolados, vale observar um formulário completo sem
CSS próprio. Esse exemplo mostra o que o navegador oferece por padrão antes de
qualquer camada de apresentação visual.

<Tabs syncKey="form-simple">
  <TabItem label="Código">
    <SourceCode
      path="examples/html/forms-simple/index.html"
      mark={[
        '<form action="sucesso.html" method="post">',
        '<fieldset>',
        '<select name="curso" id="curso">',
        '<option value="" selected>escolha um curso</option>',
        '<input type="submit" value="Enviar">',
      ]}
    />
  </TabItem>

  <TabItem label="Resultado">
    <HtmlPreview path="examples/html/forms-simple/index.html" height="30rem" />
  </TabItem>
</Tabs>

Algumas tags e atributos aparecem aqui pela primeira vez em um formulário completo:

| Trecho | Papel |
| ------ | ----- |
| `<form action="sucesso.html" method="post">` | Define para onde os dados seriam enviados e qual método HTTP seria usado |
| `<fieldset>` | Agrupa campos relacionados dentro do formulário |
| `<select>` | Cria uma lista de opções |
| `<option>` | Define cada alternativa dentro do `<select>` |
| `<input type="submit">` | Cria um botão que tenta enviar o formulário |

<Aside type="note" title="Envio depende do servidor">
  No exemplo, `action="sucesso.html"` indica um destino para o envio. Em uma aplicação
  real, esse destino normalmente seria uma rota no servidor preparada para receber e
  processar os dados do formulário.
</Aside>

Referências:
[form | MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/form),
[fieldset | MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/fieldset),
[option | MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/option) e
[input submit | MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/submit).

## Exercício

Crie um formulário HTML de contato contendo:

1. nome;
2. e-mail;
3. assunto;
4. mensagem;
5. preferência de contato com `radio`;
6. aceite dos termos com `checkbox`;
7. botão de envio.

Associe todos os campos aos seus rótulos com `label`, `for` e `id`. Depois valide a
marcação no [validador do W3C](https://validator.w3.org/nu/).

## Perguntas de revisão

**1. Qual é a função do elemento `<form>`?**

<details>
  <summary>Possível resposta</summary>

  Agrupar controles relacionados e definir a estrutura dos dados que podem ser
  preenchidos e enviados.
</details>

**2. Por que `label` deve ser associado ao campo?**

<details>
  <summary>Possível resposta</summary>

  Porque melhora acessibilidade, aumenta a área clicável e deixa claro qual texto
  descreve qual controle.
</details>

**3. Qual é a diferença entre `id` e `name`?**

<details>
  <summary>Possível resposta</summary>

  `id` identifica um elemento específico na página. `name` identifica o dado do
  campo quando ele é enviado ou lido por scripts.
</details>

**4. Quando usar `radio` e quando usar `checkbox`?**

<details>
  <summary>Possível resposta</summary>

  Use `radio` quando a pessoa deve escolher apenas uma opção dentro de um grupo. Use
  `checkbox` quando cada opção pode ser marcada ou desmarcada independentemente.
</details>

**5. Por que `placeholder` não substitui `label`?**

<details>
  <summary>Possível resposta</summary>

  Porque o placeholder desaparece durante a digitação e não cumpre o mesmo papel
  semântico de um rótulo associado ao campo.
</details>
