Esta aula apresenta os **Elementos Semânticos** do HTML5: como substituir contêineres genéricos (`<div>`) por tags com significado próprio, melhorando a estrutura do documento para leitores de tela e motores de busca (SEO).

## Objetivo

Compreender o conceito de semântica na Web. Dominar o uso dos elementos `<header>`, `<nav>`, `<main>`, `<article>`, `<section>`, `<aside>` e `<footer>`, e aplicar princípios de acessibilidade para tornar as aplicações inclusivas.

## Elementos Semânticos

Semântica significa dar **significado** ao conteúdo. Em HTML antigo, páginas utilizavam divisões genéricas `<div id="header">` ou `<div class="menu">`. O HTML5 introduziu elementos semânticos nativos que descrevem claramente o propósito daquela região.

### Principais Tags Semânticas de Layout

A tabela a seguir descreve a função e o uso semântico recomendado de cada um dos principais elementos de layout do HTML5:

| Elemento | Propósito e Uso Semântico |
| :--- | :--- |
| **`<header>`** | Cabeçalho do documento ou de uma seção. Contém títulos, logotipos, busca ou navegação. |
| **`<nav>`** | Bloco de links de navegação principal da aplicação. |
| **`<main>`** | Conteúdo principal e exclusivo do documento. Deve existir apenas um por página. |
| **`<article>`** | Conteúdo autônomo e independente que faz sentido por si só (post de blog, notícia, comentário). |
| **`<section>`** | Agrupamento temático de conteúdo dentro do documento, geralmente com um cabeçalho próprio. |
| **`<aside>`** | Conteúdo indiretamente relacionado ao redor (barra lateral, avisos, publicidade, links correlatos). |
| **`<footer>`** | Rodapé da página ou seção (informações de autor, copyright, termos de uso, contatos). |

O aninhamento entre eles segue uma regra simples: `<article>`, `<section>` e `<aside>`
ficam **dentro** do `<main>`; `<header>`, `<nav>` e `<footer>` são irmãos dele, na raiz
do `<body>`.

```html title="Exemplo de Layout Semântico"
<!DOCTYPE html>
<html lang="pt-BR">
  <head>
    <meta charset="UTF-8">
    <title>DevLab Blog</title>
  </head>
  <body>
    <header>
      <h1>DevLab - Portal Acadêmico</h1>
      <nav>
        <ul>
          <li><a href="/">Início</a></li>
          <li><a href="/courses/html/">HTML</a></li>
        </ul>
      </nav>
    </header>

    <main>
      <article>
        <h2>Introdução à Semântica Web</h2>
        <p>A semântica melhora a indexação em buscadores e a usabilidade em leitores de tela...</p>
      </article>
    </main>

    <aside>
      <h3>Tópicos Relacionados</h3>
      <p>Confira também o Guia de CSS e ECMAScript.</p>
    </aside>

    <footer>
      <p>&copy; 2026 DevLab - Todos os direitos reservados.</p>
    </footer>
  </body>
</html>
```

<Aside type="tip" title="Não Abuse de `<div>` e `<span>`">
  `<div>` (bloco) e `<span>` (inline) são elementos não-semânticos legítimos quando o único objetivo é criar ganchos para estilização CSS ou manipulação via JS sem alterar o significado do texto. `<div>` continua útil, mas apenas quando **nenhum** elemento semântico serve. Para estruturar o layout, prefira sempre as tags semânticas.
</Aside>

## Acessibilidade (a11y)

Acessibilidade Web significa garantir que qualquer pessoa, independente de suas capacidades motoras, visuais ou cognitivas, consiga navegar e interagir com a aplicação.

- **Leitores de Tela**: Pessoas com deficiência visual utilizam leitores de tela (como NVDA, TalkBack, VoiceOver) que navegam pelos elementos semânticos do HTML.
- **Atributos ARIA**: Quando os elementos nativos não cobrem um comportamento complexo, utilizamos atributos `aria-*` (como `aria-label`, `aria-expanded`, `role="..."`).

## Executando

<Steps>

1. Crie um arquivo `semantic.html`:

   ```html title="semantic.html"
   <!DOCTYPE html>
   <html lang="pt-BR">
     <head>
       <meta charset="UTF-8">
       <title>Teste Semântico</title>
     </head>
     <body>
       <header>
         <h1>DevLab Portal</h1>
       </header>
       <main>
         <section>
           <h2>Aula de HTML</h2>
           <p>Estrutura semântica correta.</p>
         </section>
       </main>
     </body>
   </html>
   ```

2. Abra o arquivo no navegador e inspecione a aba **Accessibility** (Acessibilidade) nas ferramentas do desenvolvedor (<kbd>F12</kbd>).

</Steps>

### Exercício integrador

Crie sua própria página pessoal, em um arquivo `index.html`, contendo:

1. a estrutura básica completa, com `lang`, `charset`, `viewport` e `title`;
2. `<header>`, `<nav>`, `<main>` e `<footer>`;
3. um `<h1>` e ao menos dois `<h2>`;
4. uma lista não ordenada com três interesses;
5. uma tabela com as disciplinas do semestre e a carga horária;
6. uma imagem com `alt` descritivo;
7. uma segunda página `paginas/contato.html`, com link de ida e de volta.

Ao final, valide as duas páginas no validador do W3C. O resultado deve ficar sem erros.

## Desafio

Marque a mesma página **sem usar nenhuma `<div>`**. Para cada trecho, escolha o
elemento semântico mais adequado (`<article>`, `<section>`, `<aside>`, `<figure>`,
`<time>`, `<address>`...). Depois, no DevTools, abra a aba de acessibilidade e
compare a árvore gerada com a da versão anterior.

## Perguntas de revisão

**1. Qual é a vantagem de utilizar `<header>` e `<main>` em vez de `<div id="header">`?**

<details>
  <summary>Possível resposta</summary>

  Tags semânticas fornecem significado nativo ao documento, permitindo que leitores de tela naveguem diretamente para a área desejada e que motores de busca entendam a relevância das regiões da página.
</details>

**2. Quantos elementos `<main>` devem existir em um documento HTML?**

<details>
  <summary>Possível resposta</summary>

  Exatamente um por documento, pois ele engloba o conteúdo exclusivo e principal daquela página específica.
</details>
