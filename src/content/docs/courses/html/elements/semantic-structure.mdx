Esta aula apresenta os **Elementos Semânticos** do HTML5: como substituir contêineres genéricos (`<div>`) por tags com significado próprio, melhorando a estrutura do documento para leitores de tela e motores de busca (SEO).

Com a evolução da Web, o HTML deixou de ser usado apenas para definir a aparência visual da página e passou a focar na descrição precisa do significado de cada bloco de informação.

---

## Objetivo

Compreender o conceito de semântica na Web. Dominar o uso dos elementos `<header>`, `<nav>`, `<main>`, `<article>`, `<section>`, `<aside>` e `<footer>`, e aplicar princípios de acessibilidade para tornar as aplicações inclusivas.

---

## O que é Semântica no HTML5?

Semântica significa dar **significado** e contexto ao conteúdo de um documento. 

Nas versões antigas do HTML, a estrutura das páginas dependia quase exclusivamente de divisões genéricas não-semânticas com identificadores ou classes de CSS (como `<div id="header">` ou `<div class="footer">`).

O HTML5 introduziu elementos semânticos nativos que informam explicitamente aos navegadores, leitores de tela e robôs de busca (*web crawlers*) o papel de cada região.

## Principais Tags Semânticas de Layout

Cada tag de layout semântica possui um propósito específico na arquitetura da informação:

| Elemento | Propósito e Uso Semântico |
| :--- | :--- |
| **`<header>`** | Cabeçalho do documento ou de uma seção. Contém títulos, logotipos, busca ou navegação. |
| **`<nav>`** | Bloco de links de navegação principal da aplicação. |
| **`<main>`** | Conteúdo principal e exclusivo do documento. Deve existir apenas um por página. |
| **`<article>`** | Conteúdo autônomo e independente que faz sentido por si só (post de blog, notícia, comentário). |
| **`<section>`** | Agrupamento temático de conteúdo dentro do documento, geralmente com um cabeçalho próprio. |
| **`<aside>`** | Conteúdo indiretamente relacionado ao redor (barra lateral, avisos, publicidade, links correlatos). |
| **`<footer>`** | Rodapé da página ou seção (informações de autor, copyright, termos de uso, contatos). |

O aninhamento de tags deve respeitar a hierarquia da informação: `<article>`, `<section>` e `<aside>` ficam contidos dentro do `<main>`, enquanto `<header>`, `<nav>` e `<footer>` são comumente organizados na raiz do `<body>`.

```html title="Exemplo de Layout Semântico"
<!DOCTYPE html>
<html lang="pt-BR">
  <head>
    <meta charset="UTF-8">
    <title>DevLab Blog</title>
  </head>
  <body>
    <header>
      <h1>DevLab - Portal Acadêmico</h1>
      <nav>
        <ul>
          <li><a href="/">Início</a></li>
          <li><a href="/courses/html/">HTML</a></li>
        </ul>
      </nav>
    </header>

    <main>
      <article>
        <h2>Introdução à Semântica Web</h2>
        <p>A semântica melhora a indexação em buscadores e a usabilidade em leitores de tela...</p>
      </article>
    </main>

    <aside>
      <h3>Tópicos Relacionados</h3>
      <p>Confira também o Guia de CSS e ECMAScript.</p>
    </aside>

    <footer>
      <p>&copy; 2026 DevLab - Todos os direitos reservados.</p>
    </footer>
  </body>
</html>
```

<Aside type="tip" title="Não Abuse de `<div>` e `<span>`">
  `<div>` (bloco) e `<span>` (inline) são elementos não-semânticos legítimos quando o único objetivo é criar ganchos para estilização CSS ou manipulação via JS sem alterar o significado do texto. Para estruturar o layout, prefira sempre as tags semânticas.
</Aside>

## Acessibilidade Web (a11y)

Acessibilidade Web significa garantir que qualquer pessoa, independente de suas capacidades visuais, motoras, auditivas ou cognitivas, consiga navegar e interagir com a página.

Usar elementos semânticos fornece nativamente pontos de referência (*landmarks*) reconhecidos pelos leitores de tela (como NVDA, VoiceOver e TalkBack).

Quando os elementos nativos não cobrem um comportamento dinâmico complexo, utilizamos os atributos da especificação **WAI-ARIA** (`aria-label`, `aria-expanded`, `aria-hidden` e `role="..."`):

```html title="Exemplo de acessibilidade com ARIA"
<!-- Botão de menu hamburguer para leitores de tela -->
<button aria-label="Abrir menu de navegação" aria-expanded="false">
  ☰
</button>
```

## Executando e inspecionando no DevTools

Você pode visualizar a árvore de acessibilidade gerada pelas tags semânticas no seu navegador:

<Steps>

1. **Crie um arquivo `index.html`** contendo os elementos `<header>`, `<nav>`, `<main>`, `<article>` e `<footer>`.

2. **Abra a página no navegador** e pressione <kbd>F12</kbd> para abrir o DevTools.

3. **Selecione a aba Acessibilidade (Accessibility)** localizada junto ao painel de estilos.

4. **Examine a Árvore de Acessibilidade (Accessibility Tree)** para verificar como os leitores de tela enxergam as regiões *landmark* da sua página.

</Steps>

## Exercício

Crie a estrutura semântica de uma página de portal de notícias:

1. Um cabeçalho `<header>` contendo o título da página e um menu de navegação `<nav>` com 3 links.
2. Uma área principal `<main>` contendo dois artigos `<article>`, cada um com seu próprio título `<h2>` e um parágrafo de texto.
3. Um rodapé `<footer>` com os direitos autorais.

<details>
  <summary>Possível resposta</summary>

  ```html title="noticias.html"
  <!DOCTYPE html>
  <html lang="pt-BR">
    <head>
      <meta charset="UTF-8">
      <title>Portal de Notícias Semântico</title>
    </head>
    <body>
      <header>
        <h1>Tech News</h1>
        <nav>
          <a href="#">Home</a> | <a href="#">Tecnologia</a> | <a href="#">Contato</a>
        </nav>
      </header>

      <main>
        <article>
          <h2>HTML5 Semântico</h2>
          <p>Melhorando a experiência de navegação e a indexação no SEO.</p>
        </article>

        <article>
          <h2>Acessibilidade Digital</h2>
          <p>Como tornar a Web inclusiva para todos os usuários.</p>
        </article>
      </main>

      <footer>
        <p>&copy; 2026 Tech News. Todos os direitos reservados.</p>
      </footer>
    </body>
  </html>
  ```
</details>

## Desafio

Reestruture a página de notícias acima garantindo que ela não utilize **nenhuma tag `<div>`**. 

Utilize `<section>` para agrupar visualmente os artigos, `<aside>` para um bloco lateral de publicidade e `<time>` para declarar as datas de publicação das notícias.

<details>
  <summary>Possível resposta</summary>

  ```html title="desafio_semantico.html"
  <!DOCTYPE html>
  <html lang="pt-BR">
    <head>
      <meta charset="UTF-8">
      <title>Portal Completo</title>
    </head>
    <body>
      <header>
        <h1>Tech News</h1>
      </header>

      <main>
        <section>
          <h2>Últimas Notícias</h2>
          <article>
            <h3>Lançamento do HTML5</h3>
            <p>Publicado em <time datetime="2026-08-28">28 de Agosto</time>.</p>
          </article>
        </section>

        <aside>
          <h3>Publicidade</h3>
          <p>Anuncie conosco!</p>
        </aside>
      </main>

      <footer>
        <p>Copyright 2026</p>
      </footer>
    </body>
  </html>
  ```
</details>

## Perguntas de revisão

### Semântica no HTML5

1. **Qual a vantagem de usar `<header>` e `<main>` em vez de `<div class="header">` e `<div class="main">`?**
   <details>
     <summary>Possível resposta</summary>

     Tags semânticas transmitem significado nativo. Leitores de tela utilizam esses marcos (*landmarks*) para permitir navegação rápida, e mecanismos de busca identificam o conteúdo principal com maior relevância.
   </details>

2. **Quantos elementos `<main>` podem estar ativos por página HTML?**
   <details>
     <summary>Possível resposta</summary>

     Apenas um por documento, pois ele engloba o conteúdo central e exclusivo daquela página.
   </details>

3. **Qual a diferença semântica entre `<article>` e `<section>`?**
   <details>
     <summary>Possível resposta</summary>

     `<article>` representa um conteúdo independente e autônomo (ex: um post de blog). `<section>` representa um agrupamento temático de conteúdo dentro de um documento ou artigo.
   </details>

4. **Quando o elemento `<aside>` deve ser utilizado?**
   <details>
     <summary>Possível resposta</summary>

     Quando o conteúdo for tangencial ou indiretamente relacionado ao conteúdo ao redor, como barras de navegação lateral, biografias de autor, listas de links relacionados ou anúncios.
   </details>

### Acessibilidade (a11y) e WAI-ARIA

5. **O que são *landmarks* em acessibilidade?**
   <details>
     <summary>Possível resposta</summary>

     São regiões principais da página identificadas por elementos semânticos nativos (como `<header>`, `<nav>`, `<main>`, `<footer>`) que permitem aos usuários de leitores de tela saltar diretamente para blocos de interesse.
   </details>

6. **Para que serve o atributo `aria-label`?**
   <details>
     <summary>Possível resposta</summary>

     Fornece um rótulo de texto descritivo para leitores de tela em elementos interativos que não possuem texto visível (como botões apenas com ícone).
   </details>

7. **Qual é o papel da tag `<footer>`?**
   <details>
     <summary>Possível resposta</summary>

     Conter informações de encerramento da página ou seção, como dados de autoria, links de termos de uso, direitos autorais e contatos.
   </details>

8. **Elementos como `<div>` e `<span>` devem ser completamente abolidos?**
   <details>
     <summary>Possível resposta</summary>

     Não. Eles continuam sendo usados legitimamente quando se busca apenas agrupar elementos para fins de estilização CSS ou manipulação via JS sem atribuir significado semântico adicional.
   </details>

9. **Por que a tag `<nav>` não deve ser usada em todos os conjuntos de links da página?**
   <details>
     <summary>Possível resposta</summary>

     A tag `<nav>` deve ser reservada para os blocos de navegação principal da aplicação. Links secundários no rodapé geralmente ficam contidos no `<footer>`.
   </details>

10. **Como verificar se a estrutura semântica da sua página está correta sem um leitor de tela físico?**
    <details>
      <summary>Possível resposta</summary>

      Inspecionando a árvore de acessibilidade no DevTools do navegador ou utilizando o validador oficial do W3C.
    </details>
