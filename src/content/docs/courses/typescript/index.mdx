Este guia apresenta o **TypeScript** de forma progressiva, da primeira anotação de tipo até
tipos condicionais, configuração do compilador e migração de um projeto JavaScript existente.
Ele pressupõe familiaridade com JavaScript moderno — se essa base ainda não está firme, comece
pela trilha de [JavaScript](../cstrc-jp-dw/javascript/ecmascript/).

TypeScript é um **superset** do JavaScript: todo código JS válido é código TS válido. O que
ele acrescenta é um sistema de tipos que existe apenas em tempo de desenvolvimento — o
compilador verifica o código, aponta erros antes da execução e depois **apaga** os tipos,
gerando JavaScript comum. Nada de tipos sobra em produção.

O ganho aparece em código que você não escreveu: autocompletar preciso, renomeação segura,
erros de contrato detectados no editor em vez de em produção. É por isso que a maior parte do
ecossistema JavaScript — React, Vue, Angular, Node, Deno, Bun — publica tipos oficiais.

## Como o guia está organizado

<Steps>

1. **Entender o papel do compilador** — [Introdução](basics/introduction/): o que o `tsc` faz, o que ele não faz e como montar o primeiro projeto.

2. **Anotar e inferir** — [Tipos Básicos](basics/types/) e [Funções](basics/functions/): quando escrever o tipo e quando deixar o compilador deduzir.

3. **Estreitar tipos** — [Narrowing](basics/narrowing/): como o TypeScript acompanha o fluxo do código e refina o que cada variável pode ser.

4. **Modelar dados** — [Objetos e Interfaces](types/objects/) e [Uniões e Interseções](types/unions/): descrever a forma dos dados do domínio.

5. **Reutilizar com segurança** — [Generics](types/generics/): tipos parametrizados que preservam a informação em vez de descartá-la.

6. **Transformar tipos** — [Utility Types](advanced/utility-types/) e [Manipulação de Tipos](advanced/type-manipulation/): derivar tipos a partir de outros, sem duplicação.

7. **Configurar o projeto** — [tsconfig.json](tooling/tsconfig/), [Módulos e Declarações](tooling/modules/) e [Execução e Build](tooling/runtime/).

8. **Aplicar no mundo real** — [Migrando de JavaScript](practice/migration/) e [TypeScript no Node.js](practice/nodejs/).

</Steps>

<Aside type="note" title="Versão de referência">
  O guia usa a série **TypeScript 5.x** como referência e sinaliza os recursos que exigem
  versões específicas (`satisfies` chegou no 5.0, `using` no 5.2). Verifique a sua versão com
  `npx tsc --version` antes de começar.
</Aside>

## Ferramentas

As ferramentas abaixo cobrem o ciclo de trabalho com TypeScript, do editor ao build:

| Categoria | Ferramenta | Uso principal |
| --------- | ---------- | ------------- |
| Compilador | [TypeScript](https://www.typescriptlang.org/) | Verificar tipos e gerar JavaScript |
| Editor | [Visual Studio Code](https://code.visualstudio.com/) | Servidor de tipos embutido, refatoração e diagnósticos |
| Execução direta | [tsx](https://tsx.is/) | Rodar arquivos `.ts` sem passo de build |
| Empacotamento | [Vite](https://vite.dev/) / [esbuild](https://esbuild.github.io/) | Bundle rápido, com os tipos removidos |
| Tipos de terceiros | [DefinitelyTyped](https://www.typescriptlang.org/dt/search) | Pacotes `@types/*` para bibliotecas sem tipos |
| Validação em execução | [Zod](https://zod.dev/) | Garantir no runtime o que o tipo promete |
| Playground | [TS Playground](https://www.typescriptlang.org/play) | Testar tipos e ver o JavaScript gerado |

<Aside type="tip" title="O melhor laboratório é o Playground">
  O [TS Playground](https://www.typescriptlang.org/play) mostra, lado a lado, o código
  TypeScript, o JavaScript gerado e os erros do compilador — sem instalar nada. Vários
  exemplos deste guia ficam mais claros colados lá.
</Aside>
