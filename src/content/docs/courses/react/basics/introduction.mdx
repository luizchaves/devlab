Este tópico apresenta o primeiro contato com React: o que a biblioteca resolve, como criar um
projeto, quando escolher Vite ou Next.js e como ler a estrutura inicial sem se perder em arquivos
gerados por ferramenta.

## Objetivo

Compreender React como uma biblioteca para construir interfaces a partir de componentes e estado,
conectando a escolha da ferramenta inicial ao tipo de produto que será desenvolvido. Ao final do
tópico, o leitor deve ser capaz de:

- Explicar React como UI derivada de estado.
- Criar um projeto inicial com Vite ou Next.js.
- Diferenciar biblioteca, framework e ferramenta de build.
- Identificar os arquivos essenciais de uma aplicação React.
- Escolher uma base de projeto adequada ao escopo do produto.

## Modelo Mental do React

React parte de uma ideia simples: a tela é uma função dos dados atuais. Você descreve a interface
para um estado específico, e o React atualiza o navegador quando esse estado muda.

```jsx title="UI como função de estado"
function StatusCard({ name, online }) {
  return (
    <article>
      <h2>{name}</h2>
      <p>{online ? 'Disponível' : 'Indisponível'}</p>
    </article>
  );
}
```

O componente acima não manipula o DOM diretamente. Ele descreve o resultado esperado para os
valores recebidos em `name` e `online`.

<Aside type="note" title="JSX não é HTML">
  JSX parece HTML, mas é sintaxe JavaScript transformada pela ferramenta de build. Por isso usamos
  `className`, expressões entre `{}` e componentes com letra maiúscula.
</Aside>

## Vite ou Next.js?

As duas opções criam aplicações React, mas resolvem problemas diferentes. Leia a tabela pensando
no produto que você pretende construir, não apenas no comando de instalação.

| Escolha | Melhor quando | Vantagem | Cuidado |
| ------- | ------------- | -------- | ------- |
| **Vite** | SPA, painel interno, protótipo, app consumindo API separada | Simples, rápido e explícito | Você escolhe roteador, SSR e convenções |
| **Next.js** | Produto com rotas, SEO, renderização no servidor ou backend junto | Convenções prontas e App Router | A curva inclui regras do framework |

Para aprender React do zero, Vite costuma deixar o funcionamento da biblioteca mais visível. Para
construir uma aplicação de produção com rotas, layouts e renderização no servidor, Next.js entrega
mais decisões prontas.

<Aside type="tip" title="Dica de IA: Compare a stack antes de criar o projeto">
  Assistentes tendem a recomendar a ferramenta mais popular sem perguntar o tipo de aplicação.
  Force a comparação entre requisitos, não entre marcas.

  **Prompt:** *"Compare Vite e Next.js para um painel React que consome uma API externa, tem rotas autenticadas e não precisa de SEO; conclua com uma recomendação e três riscos."*
</Aside>

## Criando o Projeto

Os comandos abaixo mostram as duas formas mais comuns de começar. Use apenas uma no seu projeto,
mantendo o restante da trilha coerente com a escolha.

<Steps>

1. Crie uma aplicação React simples com Vite quando quiser estudar a biblioteca sem as convenções
   de um framework completo.

   ```bash title="Terminal"
   pnpm create vite@latest painel-react -- --template react
   cd painel-react
   pnpm install
   pnpm dev
   ```

2. Crie uma aplicação com Next.js quando o projeto já precisa de rotas por arquivo, layouts e
   renderização integrada no servidor.

   ```bash title="Terminal"
   pnpm create next-app@latest painel-react
   cd painel-react
   pnpm dev
   ```

</Steps>

## Estrutura Inicial

Em uma aplicação Vite, a estrutura inicial é pequena. O ponto de entrada monta a árvore React no
HTML, e `App.jsx` contém o primeiro componente.

```txt title="Estrutura inicial com Vite"
painel-react
├── index.html
├── package.json
└── src
    ├── App.jsx
    ├── main.jsx
    └── index.css
```

Em Next.js, a pasta `app` já representa rotas e layouts. Isso acelera produtos com navegação, mas
adiciona conceitos que não existem em uma SPA mínima.

```txt title="Estrutura inicial com Next.js"
painel-react
├── package.json
└── src
    └── app
        ├── layout.jsx
        ├── page.jsx
        └── globals.css
```

## Exercício

Crie uma aplicação chamada `painel-estudos` usando Vite ou Next.js. Em seguida, substitua a tela
inicial por um componente que mostre o nome do projeto, uma frase de objetivo e uma lista com três
funcionalidades futuras.

<details>
  <summary>Possível resposta</summary>

  ```jsx title="Componente inicial"
  export default function App() {
    return (
      <main>
        <h1>Painel de Estudos</h1>
        <p>Organize tarefas, revisões e metas semanais.</p>
        <ul>
          <li>Registrar tópicos estudados</li>
          <li>Acompanhar progresso</li>
          <li>Consultar uma API de recomendações</li>
        </ul>
      </main>
    );
  }
  ```
</details>

## Desafio

Escreva uma decisão técnica curta explicando se o seu projeto final usará Vite ou Next.js. Inclua
o motivo, uma vantagem e um risco da escolha.

<details>
  <summary>Possível resposta</summary>

  Para um painel interno sem SEO, Vite é suficiente: deixa a aplicação leve, facilita entender o
  React puro e permite escolher React Router depois. O risco é ter que montar manualmente
  convenções que o Next.js já entregaria, como layouts e carregamento por rota.
</details>

## Perguntas de revisão

### Fundamentos

1. **Por que React é descrito como UI derivada de estado?**

<details>
  <summary>Possível resposta</summary>

  Porque a tela renderizada é recalculada a partir dos dados atuais. Quando esses dados mudam,
  React renderiza novamente os componentes afetados.
</details>

2. **Qual é a diferença prática entre Vite e Next.js para um iniciante?**

<details>
  <summary>Possível resposta</summary>

  Vite expõe uma aplicação React mais direta. Next.js adiciona convenções de framework, como rotas
  por arquivo, layouts e renderização no servidor.
</details>

### Projeto

3. **Quando Next.js tende a ser uma escolha melhor?**

<details>
  <summary>Possível resposta</summary>

  Quando o produto precisa de SEO, rotas estruturadas, renderização no servidor, layouts
  persistentes ou integração de backend no mesmo framework.
</details>
