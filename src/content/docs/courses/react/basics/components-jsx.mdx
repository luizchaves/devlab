Este tópico apresenta JSX e componentes, a base de qualquer aplicação React. A ideia central é
dividir a interface em funções pequenas, previsíveis e combináveis.

## Objetivo

Dominar a escrita de componentes React com JSX, entendendo como a marcação se mistura ao
JavaScript e como React decide o que precisa atualizar na tela. Ao final do tópico, o leitor deve
ser capaz de:

- Declarar componentes de função com nomes claros.
- Escrever JSX válido com atributos, expressões e fragmentos.
- Compor componentes por aninhamento e `children`.
- Renderizar conteúdo condicional e listas com `key`.
- Explicar o papel do Virtual DOM sem confundi-lo com o DOM real.

## Componentes de Função

Um componente React é uma função que retorna JSX. Ele pode representar um botão, um cartão, uma
tela inteira ou qualquer parte reutilizável da interface.

```jsx title="Componente de função"
function InvestmentSummary() {
  return (
    <section>
      <h2>Carteira</h2>
      <p>Total investido: R$ 12.500,00</p>
    </section>
  );
}
```

Componentes começam com letra maiúscula para que o React diferencie `InvestmentSummary` de uma
tag HTML como `section`.

## Regras de JSX

JSX aceita expressões JavaScript entre `{}` e usa nomes de atributos próximos da API do DOM. As
diferenças mais comuns aparecem quando você sai do HTML puro.

| Em HTML | Em JSX | Motivo |
| ------- | ------ | ------ |
| `class` | `className` | `class` é palavra reservada em JavaScript |
| `for` | `htmlFor` | `for` também é palavra reservada |
| `onclick` | `onClick` | eventos seguem camelCase |
| `style="color: red"` | `style={{ color: 'red' }}` | estilo inline recebe objeto |

O exemplo abaixo combina texto, atributos e expressões. Repare que o valor calculado fica entre
chaves, enquanto textos literais continuam escritos como marcação.

```jsx title="Expressões em JSX"
function AssetBadge({ name, category, value }) {
  const isLarge = value > 10000;

  return (
    <article className={isLarge ? 'asset asset-large' : 'asset'}>
      <h2>{name}</h2>
      <p>Categoria: {category}</p>
    </article>
  );
}
```

<Aside type="note" title="Virtual DOM em linguagem simples">
  O Virtual DOM é uma representação em memória da UI que o React usa para comparar renderizações.
  Quando o estado muda, React calcula uma nova árvore, compara com a anterior e aplica no DOM real
  apenas as mudanças necessárias.
</Aside>

## Composição

React favorece composição: em vez de herdar de uma classe base, você monta componentes menores
dentro de componentes maiores. A prop `children` permite criar componentes de layout.

```jsx title="Composição com children"
function Panel({ title, children }) {
  return (
    <section className="panel">
      <h2>{title}</h2>
      <div>{children}</div>
    </section>
  );
}

function Dashboard() {
  return (
    <Panel title="Resumo da carteira">
      <p>3 ativos cadastrados</p>
      <p>Rentabilidade média: 10,5%</p>
    </Panel>
  );
}
```

## Condições, Listas e Chaves

Renderização condicional decide o que aparece para um estado específico. Listas normalmente usam
`map()`, e a prop `key` dá ao React uma identidade estável para cada item.

```jsx title="Lista com key estável"
function AssetList({ assets }) {
  if (assets.length === 0) {
    return <p>Nenhum ativo cadastrado.</p>;
  }

  return (
    <ul>
      {assets.map((asset) => (
        <li key={asset.id}>
          {asset.name}: {asset.category}
        </li>
      ))}
    </ul>
  );
}
```

Usar o índice do array como `key` parece funcionar, mas quebra quando itens mudam de ordem,
entram no meio ou são removidos.

<Aside type="caution" title="Dica de IA: Desconfie de `key={index}`">
  Assistentes sugerem `key={index}` com frequência porque o exemplo fica curto. Em uma lista
  editável, isso pode reaproveitar estado visual no item errado.

  **Prompt:** *"Reescreva esta lista React para usar uma `key` estável baseada em `asset.id`; explique qual bug pode acontecer se eu usar `key={index}` ao remover um item do meio."*
</Aside>

## Exercício

Crie três componentes: `PageHeader`, `EmptyState` e `AssetList`. A lista deve mostrar uma mensagem
quando não houver itens e deve usar `asset.id` como chave quando houver dados.

<details>
  <summary>Possível resposta</summary>

  ```jsx title="Componentes de lista"
  function PageHeader() {
    return <h1>Investimentos</h1>;
  }

  function EmptyState() {
    return <p>Cadastre o primeiro ativo para começar.</p>;
  }

  function AssetList({ assets }) {
    if (assets.length === 0) return <EmptyState />;

    return assets.map((asset) => <article key={asset.id}>{asset.name}</article>);
  }
  ```
</details>

## Desafio

Transforme um cartão grande em quatro componentes menores: cabeçalho, valor, metadados e ações.

## Perguntas de revisão

### JSX

1. **Por que componentes React começam com letra maiúscula?**

<details>
  <summary>Possível resposta</summary>

  Para que o React trate o nome como componente, não como uma tag HTML nativa.
</details>

2. **O que muda entre `class` no HTML e `className` no JSX?**

<details>
  <summary>Possível resposta</summary>

  Em JSX, `className` evita conflito com a palavra reservada `class` do JavaScript e acompanha a
  API do DOM.
</details>

### Renderização

3. **Por que a prop `key` deve ser estável?**

<details>
  <summary>Possível resposta</summary>

  Porque React usa a chave para identificar cada item entre renderizações. Chaves instáveis podem
  misturar estado, foco e animações entre itens diferentes.
</details>
