Este tópico apresenta o fluxo de dados que sustenta React: o componente pai passa props, o
componente guarda estado quando precisa lembrar algo, e eventos disparam atualizações que geram
uma nova renderização.

## Objetivo

Dominar a diferença entre props e estado, aplicando eventos e atualizações imutáveis para manter
a interface previsível. Ao final do tópico, o leitor deve ser capaz de:

- Diferenciar dados recebidos por props de dados mantidos em estado.
- Atualizar estado com `useState` sem mutar arrays e objetos.
- Lidar com eventos de clique, digitação e envio de formulário.
- Criar formulários controlados em React.
- Elevar estado quando dois componentes precisam compartilhar a mesma informação.

## Props

Props são dados de entrada. Elas vêm do componente pai, são somente leitura dentro do componente
filho e deixam a UI reutilizável.

```jsx title="Props como contrato de entrada"
function InvestmentCard({ name, amount, onSelect }) {
  return (
    <button type="button" onClick={onSelect}>
      <strong>{name}</strong>
      <span>R$ {amount}</span>
    </button>
  );
}
```

Um bom componente deixa explícito o que precisa receber. Se o filho começa a buscar dados sozinho
sem necessidade, ele fica mais difícil de reaproveitar e testar.

## Estado Local

Estado é dado que muda ao longo do tempo e afeta a renderização. O `useState` devolve o valor
atual e uma função para pedir uma nova renderização.

```jsx title="Estado local com useState"
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button type="button" onClick={() => setCount(count + 1)}>
      Cliques: {count}
    </button>
  );
}
```

O valor de `count` não muda no lugar. O React recebe um novo valor por `setCount()`, agenda uma
renderização e chama o componente outra vez.

<Aside type="note" title="Estado não é variável comum">
  Alterar uma variável local não faz React renderizar novamente. Use estado para qualquer dado que
  muda e precisa aparecer na tela, como filtros, campos de formulário, item selecionado ou dados
  carregados de uma API.
</Aside>

## Atualização Imutável

Arrays e objetos em estado devem ser substituídos por novas versões. Isso facilita a comparação
entre renderizações e evita bugs em componentes filhos.

```jsx title="Adicionar item sem mutar o array"
function addInvestment(investments, newInvestment) {
  return [...investments, newInvestment];
}

function removeInvestment(investments, id) {
  return investments.filter((investment) => investment.id !== id);
}
```

Quando a próxima versão depende da anterior, use a forma funcional do setter. Ela evita usar um
valor antigo capturado por uma função.

```jsx title="Setter funcional"
setInvestments((currentInvestments) => [
  ...currentInvestments,
  { id: crypto.randomUUID(), name: 'Tesouro Selic', amount: 1000 },
]);
```

## Formulários Controlados

Um formulário controlado guarda o valor do campo em estado. O usuário digita, o evento atualiza o
estado, e o valor exibido volta do React para o input.

```jsx title="Campo controlado"
function InvestmentForm({ onCreate }) {
  const [name, setName] = useState('');

  function handleSubmit(event) {
    event.preventDefault();
    onCreate({ id: crypto.randomUUID(), name });
    setName('');
  }

  return (
    <form onSubmit={handleSubmit}>
      <label htmlFor="investment-name">Nome</label>
      <input
        id="investment-name"
        value={name}
        onChange={(event) => setName(event.target.value)}
      />
      <button type="submit">Cadastrar</button>
    </form>
  );
}
```

O atributo `htmlFor` conecta o rótulo ao campo, o que melhora a acessibilidade e facilita o uso
por teclado e leitores de tela.

<Aside type="tip" title="Dica de IA: Peça atualização imutável e acessibilidade juntas">
  Em formulários, a IA costuma focar no estado e esquecer `label`, `id`, `type` e tratamento de
  envio. Inclua esses critérios no pedido.

  **Prompt:** *"Crie um formulário React controlado para cadastrar investimentos; use `label` com `htmlFor`, `event.preventDefault()`, atualização imutável de `investments` e limpeza do campo após o envio."*
</Aside>

## Elevação de Estado

Quando dois componentes precisam enxergar a mesma informação, mova o estado para o ancestral em
comum. O pai guarda o dado, passa valores por props e passa funções para os filhos dispararem
mudanças.

```jsx title="Estado compartilhado no pai"
function Dashboard() {
  const [selectedId, setSelectedId] = useState(null);

  return (
    <>
      <InvestmentList selectedId={selectedId} onSelect={setSelectedId} />
      <InvestmentDetails id={selectedId} />
    </>
  );
}
```

Essa técnica resolve muitos casos antes de qualquer estado global. Context API ou Redux entram
quando o estado precisa atravessar várias camadas ou quando a lógica de atualização fica grande.

## Exercício

Crie uma lista de tarefas com um formulário controlado. Cada tarefa deve ter `id`, `title` e
`done`. A tela deve permitir cadastrar, marcar como concluída e filtrar apenas pendentes.

<details>
  <summary>Possível resposta</summary>

  Use `useState` para `tasks`, `title` e `showOnlyPending`. Cadastre com
  `setTasks((current) => [...current, newTask])`, altere com `map()` e filtre a lista antes de
  renderizar.
</details>

## Desafio

Separe a tela em `TaskForm`, `TaskFilters`, `TaskList` e `TaskItem`. O estado deve ficar no menor
ancestral que todos os componentes conseguem compartilhar.

<details>
  <summary>Possível resposta</summary>

  O componente `TasksPage` pode guardar `tasks` e `showOnlyPending`. Ele passa `onCreate` para
  `TaskForm`, `showOnlyPending` para `TaskFilters` e `onToggle` para `TaskItem`.
</details>

## Perguntas de revisão

### Fluxo de dados

1. **Por que props são consideradas somente leitura?**

<details>
  <summary>Possível resposta</summary>

  Porque elas pertencem ao componente pai. O filho pode usá-las para renderizar, mas não deve
  tentar alterar diretamente os dados recebidos.
</details>

2. **Quando um dado deve virar estado?**

<details>
  <summary>Possível resposta</summary>

  Quando ele muda ao longo do tempo e essa mudança precisa alterar o que aparece na tela.
</details>

### Eventos

3. **Por que usar `event.preventDefault()` no envio de formulário?**

<details>
  <summary>Possível resposta</summary>

  Para impedir o recarregamento padrão da página e permitir que React trate o envio dentro da
  aplicação.
</details>
