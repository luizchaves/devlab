Este tópico apresenta formas comuns de estilizar aplicações React. O foco não é escolher uma
ferramenta única, mas entender o custo de cada abordagem para componentes, páginas e design
system.

## Objetivo

Compreender estratégias de estilo em React e escolher uma abordagem compatível com o tamanho e a
organização do projeto. Ao final do tópico, o leitor deve ser capaz de:

- Diferenciar CSS global, CSS Modules, Tailwind CSS e estilo inline.
- Aplicar classes de forma condicional em JSX.
- Preservar acessibilidade visual em estados de foco, erro e desabilitado.
- Evitar acoplamento excessivo entre componente e página.
- Organizar tokens simples de cor, espaçamento e tipografia.

## CSS Global

CSS global é útil para base visual: reset, fonte, variáveis, estilos do `body` e classes muito
compartilhadas. O risco é criar seletores amplos que afetam componentes sem querer.

```css title="CSS global"
:root {
  color-scheme: light;
  font-family: Inter, system-ui, sans-serif;
}

body {
  margin: 0;
  background: #f8fafc;
  color: #0f172a;
}
```

Use CSS global para fundamentos do documento. Para detalhes de um componente, prefira uma
estratégia mais localizada.

## CSS Modules

CSS Modules geram classes com escopo local. Eles são úteis quando o componente tem estilo próprio
e você quer evitar colisão de nomes.

```css title="CSS Module do cartão"
.card {
  border: 1px solid #e2e8f0;
  border-radius: 0.5rem;
  padding: 1rem;
}

.positive {
  color: #047857;
}
```

O componente importa o objeto `styles` e usa as classes como propriedades. A classe final no HTML
é gerada pela ferramenta de build.

```jsx title="Componente com CSS Module"
import styles from './InvestmentCard.module.css';

function InvestmentCard({ name, isPositive }) {
  return (
    <article className={styles.card}>
      <h2 className={isPositive ? styles.positive : undefined}>{name}</h2>
    </article>
  );
}
```

## Tailwind CSS

Tailwind usa classes utilitárias para montar estilos diretamente no JSX. Ele acelera protótipos e
design systems pequenos, mas exige disciplina para não transformar cada `className` em uma linha
longa demais.

```jsx title="Componente com Tailwind"
function MetricCard({ label, value }) {
  return (
    <article className="rounded-lg border border-slate-200 bg-white p-4 shadow-sm">
      <p className="text-sm text-slate-500">{label}</p>
      <strong className="text-2xl text-slate-900">{value}</strong>
    </article>
  );
}
```

Quando várias classes se repetem, extraia um componente. Isso mantém a consistência sem esconder
completamente o estilo.

<Aside type="tip" title="Dica de IA: Peça estados acessíveis junto do visual">
  Assistentes costumam gerar o cartão bonito no estado padrão e esquecer foco, erro, desabilitado
  e contraste. Inclua os estados no pedido para receber um componente mais próximo do uso real.

  **Prompt:** *"Revise este componente React com Tailwind; reduza classes repetidas, preserve foco visível, inclua estado de erro acessível e explique quais classes pertencem ao layout e quais pertencem à intenção visual."*
</Aside>

<Aside type="note" title="Acessibilidade também é estilo">
  Estados de foco, contraste, tamanho de alvo clicável e feedback de erro fazem parte da camada
  visual. Um botão bonito que não mostra foco no teclado ainda é um botão incompleto.
</Aside>

## Escolhendo a Estratégia

A escolha deve considerar a equipe, o projeto e o tipo de interface. A tabela abaixo resume uma
regra prática para começar.

| Estratégia | Use para | Evite quando |
| ---------- | -------- | ------------ |
| CSS global | base visual e variáveis | estilos específicos de componente |
| CSS Modules | componentes com aparência própria | design system muito utilitário |
| Tailwind CSS | prototipação e consistência por tokens | classes longas escondem a intenção |
| Inline style | valores dinâmicos pontuais | estados complexos, media queries e hover |

## Exercício

Crie um `Button` reutilizável com variantes `primary` e `secondary`. Garanta estado de foco
visível e texto legível em fundo claro.

<details>
  <summary>Possível resposta</summary>

  ```jsx title="Botão com classes por variante"
  const variants = {
    primary: 'bg-blue-700 text-white hover:bg-blue-800',
    secondary: 'bg-white text-blue-700 border border-blue-700',
  };

  function Button({ variant = 'primary', children }) {
    return (
      <button className={`${variants[variant]} rounded-md px-4 py-2 focus:outline focus:outline-2`}>
        {children}
      </button>
    );
  }
  ```
</details>

## Desafio

Escolha uma tela do seu projeto final e escreva um mini guia visual: cores principais,
espaçamento, tamanho de título, estado de foco e estado de erro.

<details>
  <summary>Possível resposta</summary>

  Para um painel de estudos, use fundo claro, cartões brancos, texto escuro, links azuis, erro em
  vermelho com texto explicativo e foco visível em botões e campos.

## Perguntas de revisão

### Estratégias

1. **Quando CSS Modules são mais úteis que CSS global?**

<details>
  <summary>Possível resposta</summary>

  Quando o estilo pertence a um componente específico e você quer evitar colisões com outras
  partes da aplicação.
</details>

2. **Qual é o risco de usar Tailwind sem extrair componentes?**

<details>
  <summary>Possível resposta</summary>

  O JSX pode acumular classes repetidas e longas, dificultando leitura e manutenção.
</details>

### Acessibilidade

3. **Por que foco visível é requisito de interface?**

<details>
  <summary>Possível resposta</summary>

  Porque pessoas que navegam por teclado precisam saber qual elemento está ativo antes de acionar
  uma ação.
</details>
