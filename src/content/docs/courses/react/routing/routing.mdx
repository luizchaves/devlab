Este tópico apresenta roteamento em aplicações React: como transformar componentes em páginas,
como ler parâmetros de URL, como navegar por links e quando faz sentido trocar uma SPA com React
Router por um framework como Next.js.

## Objetivo

Construir navegação em React com rotas declarativas, parâmetros e layouts, entendendo a diferença
entre roteamento no cliente e roteamento por arquivo em frameworks. Ao final do tópico, o leitor
deve ser capaz de:

- Configurar rotas com React Router.
- Criar links acessíveis entre páginas.
- Ler parâmetros dinâmicos de URL.
- Organizar layouts e rotas aninhadas.
- Comparar React Router com Next.js App Router.
- Planejar carregamento de dados e tratamento de erro por rota.

## Roteamento no Cliente

Em uma SPA, o navegador carrega um HTML inicial e o React troca o conteúdo visível sem recarregar
a página inteira. O roteador observa a URL e decide qual componente renderizar.

```jsx title="Rotas com React Router"
import { createBrowserRouter, RouterProvider } from 'react-router-dom';

const router = createBrowserRouter([
  { path: '/', element: <DashboardPage /> },
  { path: '/investments/:id', element: <InvestmentDetailsPage /> },
  { path: '/settings', element: <SettingsPage /> },
]);

export default function App() {
  return <RouterProvider router={router} />;
}
```

O componente `InvestmentDetailsPage` será renderizado para URLs como `/investments/abc-123`.

## Links e Parâmetros

Use `Link` em vez de `<a>` para navegação interna em uma SPA. Ele evita recarregar a página e
mantém a navegação sob controle do roteador.

```jsx title="Link e parâmetro de rota"
import { Link, useParams } from 'react-router-dom';

function InvestmentCard({ investment }) {
  return <Link to={`/investments/${investment.id}`}>{investment.name}</Link>;
}

function InvestmentDetailsPage() {
  const { id } = useParams();

  return <h1>Investimento {id}</h1>;
}
```

Mesmo usando navegação no cliente, preserve semântica: links navegam, botões executam ações.

<Aside type="note" title="Acessibilidade da navegação">
  Um link deve indicar destino e funcionar por teclado. Um botão deve disparar ação. Trocar tudo
  por `div onClick` quebra navegação por teclado, leitores de tela e comportamento esperado do
  navegador.
</Aside>

## Rotas Aninhadas e Layouts

Rotas aninhadas permitem reaproveitar um layout para várias páginas. Isso é útil para áreas
autenticadas, painéis com menu lateral e módulos com navegação própria.

```jsx title="Layout com rotas filhas"
const router = createBrowserRouter([
  {
    path: '/app',
    element: <AppLayout />,
    children: [
      { index: true, element: <DashboardPage /> },
      { path: 'investments/:id', element: <InvestmentDetailsPage /> },
    ],
  },
]);
```

Dentro de `AppLayout`, o componente `Outlet` marca onde a rota filha aparece.

```jsx title="Outlet do layout"
import { Outlet } from 'react-router-dom';

function AppLayout() {
  return (
    <>
      <Navigation />
      <main>
        <Outlet />
      </main>
    </>
  );
}
```

## Next.js App Router

Next.js usa roteamento por sistema de arquivos. Uma pasta vira segmento de URL, `page.jsx`
representa a página e `layout.jsx` define UI compartilhada.

```txt title="Rotas no App Router"
src/app
├── layout.jsx
├── page.jsx
├── investments
│   └── [id]
│       └── page.jsx
└── settings
    └── page.jsx
```

Essa escolha reduz configuração manual e aproxima rotas de renderização no servidor, dados e
layouts. O custo é aprender as regras do framework, como Server Components, Client Components e
arquivos especiais.

<Aside type="tip" title="Dica de IA: Peça a árvore de rotas antes do código">
  Para rotas, a IA costuma escrever componentes antes de confirmar a navegação. Peça primeiro a
  árvore, os parâmetros e os estados de erro.

  **Prompt:** *"Desenhe a árvore de rotas de um painel React com dashboard, lista, detalhe `/items/:id`, configurações e rota 404; indique quais rotas carregam dados e quais erros precisam de tela própria."*
</Aside>

## Carregamento e Erro por Rota

Rotas reais precisam lidar com dado ausente, carregamento e erro. Em React Router moderno, loaders
podem aproximar a busca de dados da definição da rota. Em Next.js, a estrutura do App Router usa
arquivos e componentes especiais para loading e erro.

| Caso | React Router | Next.js App Router |
| ---- | ------------ | ------------------ |
| Página | objeto de rota | `page.jsx` |
| Layout | `element` com `Outlet` | `layout.jsx` |
| Parâmetro | `:id` e `useParams()` | pasta `[id]` e `params` |
| Loading | estado, Suspense ou loader | `loading.jsx` |
| Erro | `errorElement` ou estado | `error.jsx` |

## Exercício

Projete as rotas de um app de estudos com `/`, `/topics`, `/topics/:slug`, `/progress` e
`/settings`. Indique qual componente aparece em cada rota e quais delas precisam buscar dados.

<details>
  <summary>Possível resposta</summary>

  `/topics/:slug` precisa carregar o tópico pelo `slug`; `/progress` pode buscar métricas do
  usuário; `/settings` pode usar estado local e salvar apenas no envio.
</details>

## Desafio

Implemente a mesma árvore mental em duas versões: uma com React Router e outra como estrutura de
pastas do Next.js App Router. Compare o que ficou explícito em cada uma.

<details>
  <summary>Possível resposta</summary>

  No React Router, a árvore aparece em um objeto JavaScript. No Next.js, a árvore aparece nas
  pastas. React Router deixa a configuração centralizada; Next.js transforma rota em convenção de
  projeto.
</details>

## Perguntas de revisão

### Navegação

1. **Por que usar `Link` para navegação interna em uma SPA?**

<details>
  <summary>Possível resposta</summary>

  Porque ele navega sem recarregar a página inteira e mantém o estado do roteador.
</details>

2. **Qual é a diferença entre rota dinâmica no React Router e no Next.js?**

<details>
  <summary>Possível resposta</summary>

  No React Router, o parâmetro aparece como `:id` na configuração. No Next.js, ele aparece como
  uma pasta dinâmica, por exemplo `[id]`.
</details>

### Arquitetura

3. **Quando Next.js tende a simplificar o roteamento?**

<details>
  <summary>Possível resposta</summary>

  Quando a aplicação precisa de layouts persistentes, renderização no servidor, convenções de
  página e integração forte entre rota e carregamento.
</details>
