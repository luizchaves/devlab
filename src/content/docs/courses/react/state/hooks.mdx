Este tópico apresenta hooks como funções especiais que conectam componentes a recursos do React:
estado, efeitos, referências, memoização, reducers, contexto e reutilização de lógica.

## Objetivo

Dominar os hooks essenciais do React, entendendo quando cada um resolve um problema real e quando
ele apenas adiciona complexidade. Ao final do tópico, o leitor deve ser capaz de:

- Usar `useState` para memória local de componente.
- Usar `useEffect` apenas para sincronizar com sistemas externos.
- Guardar referências mutáveis com `useRef` sem disparar renderização.
- Aplicar `useMemo` e `useCallback` por necessidade, não por hábito.
- Modelar transições de estado com `useReducer`.
- Criar hooks próprios para reutilizar lógica de interface.

## Regras dos Hooks

Hooks só podem ser chamados no topo de componentes ou de outros hooks. Eles não devem ficar dentro
de `if`, `for`, callbacks ou funções comuns.

```jsx title="Hook no topo do componente"
function SearchBox() {
  const [query, setQuery] = useState('');

  return <input value={query} onChange={(event) => setQuery(event.target.value)} />;
}
```

Essa regra permite que React preserve a ordem das chamadas entre renderizações. Se a ordem muda, o
React não consegue associar cada estado ao hook correto.

<Aside type="caution" title="Dica de IA: Verifique as regras dos hooks">
  Assistentes às vezes colocam `useEffect` ou `useState` dentro de uma condição para resolver um
  caso específico. Isso quebra a regra estrutural dos hooks.

  **Prompt:** *"Revise este componente e aponte qualquer hook chamado dentro de condição, loop ou função interna; reescreva mantendo todos os hooks no topo do componente."*
</Aside>

## Hooks Essenciais

A tabela abaixo resume a pergunta que cada hook responde. Antes de usar um hook, formule o
problema nessa forma.

| Hook | Pergunta que responde | Exemplo de uso |
| ---- | --------------------- | -------------- |
| `useState` | O componente precisa lembrar um valor que muda? | campo, filtro, aba ativa |
| `useEffect` | Preciso sincronizar com algo fora do React? | API, timer, evento global |
| `useRef` | Preciso guardar algo mutável sem renderizar? | input, timeout, medida |
| `useMemo` | Um cálculo caro depende de poucos valores? | lista filtrada grande |
| `useCallback` | Uma função estável evita trabalho em filhos memoizados? | callbacks em listas pesadas |
| `useReducer` | O estado muda por ações com regras claras? | carrinho, wizard, editor |
| `useContext` | Vários níveis precisam ler o mesmo valor? | tema, usuário, locale |

## `useState`

`useState` é o hook mais comum. Ele guarda memória local e pede nova renderização quando recebe
um valor diferente.

```jsx title="Alternar visibilidade"
function BalanceToggle({ balance }) {
  const [isVisible, setIsVisible] = useState(true);

  return (
    <button type="button" onClick={() => setIsVisible((current) => !current)}>
      {isVisible ? `R$ ${balance}` : 'R$ ****'}
    </button>
  );
}
```

## `useEffect`

`useEffect` sincroniza o componente com sistemas externos, como rede, armazenamento, timers ou
APIs do navegador. Se você só quer calcular algo a partir de props e estado, provavelmente não
precisa de efeito.

```jsx title="Efeito com limpeza"
useEffect(() => {
  const id = setInterval(() => {
    console.log('atualizando relógio');
  }, 1000);

  return () => clearInterval(id);
}, []);
```

O retorno do efeito faz a limpeza. Sem ele, timers, inscrições e conexões podem continuar ativos
depois que o componente sai da tela.

## `useRef`

`useRef` guarda um valor mutável que não participa da renderização. Alterar `current` não redesenha
a tela.

```jsx title="Foco em um input"
function FocusableInput() {
  const inputRef = useRef(null);

  return (
    <>
      <input ref={inputRef} />
      <button type="button" onClick={() => inputRef.current?.focus()}>
        Focar
      </button>
    </>
  );
}
```

## `useMemo` e `useCallback`

Memoização só vale quando existe custo real: cálculo pesado, lista grande ou componente filho
memoizado. Usar em tudo deixa o código mais difícil sem melhorar a interface.

```jsx title="Lista filtrada memoizada"
const filteredInvestments = useMemo(() => {
  return investments.filter((investment) => investment.category === selectedCategory);
}, [investments, selectedCategory]);
```

## `useReducer`

`useReducer` organiza transições de estado por ações. Ele é uma boa ponte entre estado local e
gerenciamento global.

```jsx title="Reducer de filtro"
function filterReducer(state, action) {
  if (action.type === 'change-query') {
    return { ...state, query: action.query };
  }

  if (action.type === 'change-category') {
    return { ...state, category: action.category };
  }

  return state;
}
```

## Hooks Próprios

Um hook próprio extrai lógica reutilizável sem extrair marcação. Ele deve começar com `use` e pode
combinar hooks nativos.

```jsx title="Hook próprio"
function useLocalStorageState(key, initialValue) {
  const [value, setValue] = useState(() => {
    const stored = localStorage.getItem(key);
    return stored ? JSON.parse(stored) : initialValue;
  });

  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);

  return [value, setValue];
}
```

<Aside type="note" title="Ciclo de vida em componentes de função">
  Em componentes modernos, não pensamos em `componentDidMount` e `componentDidUpdate` como métodos.
  Pensamos em renderizações e sincronizações: o componente renderiza, React atualiza a tela e os
  efeitos rodam quando suas dependências mudam.
</Aside>

## Exercício

Crie um hook `useToggle(initialValue)` que devolva `[value, toggle]`. Use esse hook para alternar
entre mostrar e esconder valores financeiros na tela.

<details>
  <summary>Possível resposta</summary>

  ```jsx title="useToggle"
  function useToggle(initialValue = false) {
    const [value, setValue] = useState(initialValue);
    const toggle = () => setValue((current) => !current);
    return [value, toggle];
  }
  ```
</details>

## Desafio

Reescreva três estados relacionados de um formulário usando `useReducer`. Defina ações para
alterar campo, limpar formulário e marcar envio concluído.

<details>
  <summary>Possível resposta</summary>

  O reducer pode receber ações `change-field`, `reset` e `submit-success`. A vantagem é concentrar
  as transições em uma função previsível, em vez de espalhar vários setters pelo componente.
</details>

## Perguntas de revisão

### Regras

1. **Por que hooks precisam ser chamados sempre na mesma ordem?**

<details>
  <summary>Possível resposta</summary>

  Porque React associa cada chamada de hook à posição em que ela aparece durante a renderização.
  Condições e loops podem mudar essa ordem.
</details>

2. **Quando `useEffect` não é necessário?**

<details>
  <summary>Possível resposta</summary>

  Quando o valor pode ser derivado diretamente de props ou estado durante a renderização.
</details>

### Escolha de hook

3. **Quando `useReducer` é melhor que vários `useState`?**

<details>
  <summary>Possível resposta</summary>

  Quando o estado tem várias transições relacionadas e fica mais claro descrevê-las por ações.
</details>
