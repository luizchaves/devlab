Nível **Avançado** · Next.js · React 19 · NextAuth · Prisma · PostgreSQL · TanStack · Tailwind CSS

Este projeto reconstrói o [InvestFlow](../../../npm/practice/investflow/) em React. O produto é o mesmo: uma plataforma de gestão patrimonial para investidores individuais, com carteira, cotações, comprovantes, rentabilidade, proventos, dólar e perfil. O que muda é a implementação: o HTML com JavaScript modular vira Next.js com App Router, o Supabase Auth vira NextAuth, as policies RLS viram consultas filtradas pelo dono no servidor, e as Edge Functions viram route handlers. O banco e o Storage continuam no Supabase.

<ProjectLinks path="examples/courses/react/investflow-react" devcontainer="investflow-react" />

<Aside type="note" title="Por que reconstruir em vez de migrar?">
  A versão vanilla existe para ensinar BaaS: o navegador fala direto com o banco e a segurança mora nas policies. A versão React existe para ensinar uma aplicação com servidor próprio: o navegador só fala com rotas da aplicação, e a segurança mora no código que recebe o `userId` da sessão. Os dois caminhos são legítimos, e comparar os dois é parte do aprendizado. Por isso os requisitos são compartilhados e a implementação é separada.
</Aside>

## Objetivo

Construir uma aplicação React completa, com servidor, banco, arquivos e testes, aplicando os conceitos do Guia de React em um produto que já tem requisitos, critérios de aceitação e testes numerados. Ao final do projeto, o leitor deve ser capaz de:

- Separar regras de negócio puras (`core/`), acesso a dados no servidor (`server/`) e componentes de tela (`features/`) em um projeto Next.js com App Router.
- Implementar identidade com NextAuth e autorização por `userId` em cada consulta, sem RLS.
- Usar TanStack React Query para dados do servidor, TanStack Table para tabelas e Zustand só para preferências de interface.
- Compor uma biblioteca de primitivas acessíveis com Base UI, CVA e Tailwind CSS v4.
- Escrever testes em três camadas (unit, browser, integration) e E2E com Playwright, cada um nomeado pelo critério que prova.
- Entregar telas que funcionam em celular desde o primeiro commit (RNF07).

O resto é próprio desta implementação: os requisitos não funcionais reescritos para um servidor sem RLS, o RNF07 de design responsivo, os critérios que só fazem sentido nesta stack, as 57 tasks das dez etapas e a camada de teste que prova cada critério. <Aside type="caution" title="RNF07: o requisito que a versão vanilla não tinha">
  O InvestFlow original foi desenhado para o desktop e suas tabelas largas quebram no celular. A versão React nasce *mobile-first* e prova isso com critérios próprios (CA12.1 a CA12.4): nenhuma página rola na horizontal a 360 px, a barra expõe os links por um botão de menu acessível, as tabelas mostram as colunas essenciais em qualquer largura e os alvos de toque têm 44 px. Um projeto Playwright roda esses testes em um Pixel 7.
</Aside>

## Arquitetura da aplicação

O diagrama mostra por onde cada tipo de dado passa: o navegador só conhece as rotas da aplicação, e o servidor conhece o banco, o Storage e o provedor de cotações.

<Mermaid title="Por onde cada dado passa">
{`
flowchart LR
  subgraph Navegador
    RSC[Server Components] --> UI[Client Components]
    UI --> RQ[TanStack React Query]
    UI --> Z[Zustand: tema, ocultar valores]
  end
  subgraph Next.js
    RQ --> API[Route handlers /api/*]
    RSC --> SRV[src/server: sessão + Prisma]
    API --> SRV
    SRV --> CORE[src/core: regras puras]
    ACT[Server Actions: conta] --> SRV
  end
  SRV --> PG[(PostgreSQL do Supabase)]
  SRV --> ST[(Supabase Storage)]
  SRV --> Y[Yahoo Finance]
`}
</Mermaid>

Três decisões sustentam essa arquitetura, e cada etapa as repete:

1. **`src/core/` é puro.** Simulador, posição, retornos, proventos, câmbio, calendário e validação não importam React nem Prisma. É o que os testes `unit` cobrem e o que as páginas desta trilha recortam.
2. **`src/server/` só roda no servidor.** Toda consulta recebe o `userId` da sessão e filtra por ele; uma linha de outra conta responde `404`, nunca `403`, para não confirmar que ela existe. É o substituto do RLS.
3. **Dados remotos ficam no React Query; preferências, no Zustand.** O store guarda tema, ocultar valores e a paleta aberta. Carteira, cotações e proventos nunca entram nele.

O projeto é um só e cresce por etapa; as páginas recortam o estado final com `<SourceCode>`. A árvore resume o papel de cada pasta.

```txt title="Mapa do repositório"
examples/courses/react/investflow-react/
├── app/                   rotas: (public) landing e conta, (private) telas com a barra comum, api/
├── prisma/                schema, migrations e seed
├── src/core/              regras puras, testadas em jsdom
├── src/server/            Prisma, NextAuth, senha, guards, Storage, provedores
├── src/features/          componentes, hooks e ações de cada tela
├── src/components/ui/     Button, Input, Select, Field, Badge, Dialog, AlertDialog, Segmented

├── src/store/             Zustand: preferências
├── supabase/              config.toml da stack local (portas 5434x) e os buckets
└── tests/                 integration (schema `integration`), e2e (schema `e2e`), build
```

## Estratégia de testes

Cada camada tem uma pergunta própria, e o título de cada teste leva o critério que ele prova, com a numeração do backlog (`CA03.4 — cada conta lê apenas os próprios ativos`). A tabela resume as camadas e o que cada uma exige.

| Camada | Arquivos | Ambiente | O que prova |
| ------ | -------- | -------- | ----------- |
| `unit` | `src/**/*.test.ts` | jsdom | `core`, hooks e stores |
| `browser` | `src/components/ui/*.browser.test.tsx` | Chromium real (Vitest Browser Mode) | papéis, rótulos, foco e teclado das primitivas |
| `integration` | `tests/integration/*.integration.test.ts` | Prisma no schema `integration`, sessão simulada | rotas, isolamento entre contas, Storage real |
| `e2e` | `tests/e2e/*.spec.ts` | Playwright contra `next dev`, schema `e2e` | jornadas completas; `*.mobile.spec.ts` em um Pixel 7 |
| `build` | `tests/deploy/*.test.ts` | `next build` real | nenhum segredo no bundle, cabeçalhos de segurança |

Ao fim da décima etapa o projeto soma 123 testes Vitest, 2 de build e 36 de Playwright, todos verdes.

## Execução local

A stack local do Supabase fornece o PostgreSQL e o Storage; o Next roda por cima. As portas ficam em `5434x` para não colidir com a stack do InvestFlow vanilla (`5432x`), então as duas podem subir ao mesmo tempo.

```bash
cd examples/courses/react/investflow-react
pnpm install
cp .env.example .env
supabase start
pnpm db:buckets
pnpm db:migrate
pnpm db:seed
pnpm dev
```

O seed cria `admin@example.com` com a senha `admin12345` e a posição demonstrativa `Tesouro Reserva 2036` valendo R$ 1. A aplicação abre em `http://localhost:3000`.
