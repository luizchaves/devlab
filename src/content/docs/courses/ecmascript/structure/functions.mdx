Funções são os blocos de construção fundamentais em JavaScript. Elas permitem
agrupar um conjunto de instruções para executar uma tarefa, evitar repetição de
código, criar abstrações e modularizar a lógica de uma aplicação.

## Objetivo

Compreender as diferentes formas de declarar e invocar funções (*Function Declaration*,
*Function Expression* e *Arrow Function*), controlar o fluxo de retorno, utilizar
parâmetros padrão, *rest parameters* e desestruturação, reconhecer o objeto especial
`arguments`, dominar conceitos de *hoisting*, *closures*, operador `this`, IIFE,
vinculação de contexto com `call()`, `apply()` e `bind()`, e funções geradoras (*generators*).


## Formas de declaração

Em JavaScript, uma função pode ser definida de diferentes maneiras: por meio de uma
declaração tradicional, de uma expressão de função atribuída a uma variável ou por
meio da sintaxe enxuta de *arrow function*.

```js title="Declaração de função (Function Declaration)"
function addition(param1, param2) {
  return param1 + param2;
}

console.log(addition(1)); // NaN
console.log(addition(1, 2)); // 3
console.log(addition(1, 2, 3)); // 3
```

Quando argumentos extras são fornecidos, eles são ignorados pela assinatura da
função; quando argumentos esperados são omitidos, eles assumem o valor `undefined`
(o que faz `1 + undefined` resultar em `NaN`).

Uma *Function Expression* define uma função anônima ou nomeada e a atribui a uma
variável ou constante:

```js title="Expressão de função (Function Expression)"
const subtraction = function (param1, param2) {
  return param1 - param2;
};

console.log(subtraction); // [Function: subtraction]
console.log(subtraction(2, 1)); // 1
```

As *Arrow Functions* (introduzidas no ES6) fornecem uma sintaxe mais curta utilizando a
notação `=>`:

```js title="Arrow Functions"
const multiplication = (param1, param2) => {
  return param1 * param2;
};

const division = (param1, param2) => param1 / param2;
const double = (number) => number * 2;

console.log(multiplication(2, 3)); // 6
console.log(division(6, 2)); // 3
console.log(double(5)); // 10
```

<Aside type="note" title="Retorno explícito vs. implícito em Arrow Functions">
  Quando a *arrow function* possui corpo entre chaves `{...}`, o uso da instrução
  `return` é **obrigatório** para devolver um valor. Quando as chaves são omitidas,
  a expressão seguinte é avaliada e retornada **implicitamente**.
</Aside>

Para retornar um objeto literal de forma implícita em uma *arrow function*, envolva
o objeto entre parênteses `({ ... })`. Caso contrário, as chaves serão interpretadas
como um bloco de código vazio ou com *labels*, resultando em `undefined`.

```js title="Retorno implícito de objetos"
const createObject = (name) => ({ name });
const wrongCreateObject = (name) => { name };

console.log(createObject("Fulano")); // { name: 'Fulano' }
console.log(wrongCreateObject("Fulano")); // undefined
```

Não é permitido misturar a palavra-chave `function` com a notação de atribuição `=>`:

```js title="Sintaxe incorreta"
// SyntaxError: Unexpected token '='.
// function wrongAddition = (param1, param2) {
//   return param1 + param2;
// }
```

<Aside type="caution" title="Comportamento do operador this em Arrow Functions">
  Diferente das funções tradicionais (cujo `this` é dinâmico e definido no momento da chamada),
  as *Arrow Functions* possuem **`this` léxico**: elas herdam o `this` do escopo onde foram criadas.
  Por essa razão, evite declarar *arrow functions* como métodos diretos de objetos.

  ```js title="this em métodos e arrow functions"
  const calculator = {
    factor: 2,
    regularDouble(number) {
      return number * this.factor;
    },
    arrowDouble: (number) => number * this.factor,
    createArrowDouble() {
      return (number) => number * this.factor;
    },
  };

  console.log(calculator.regularDouble(5)); // 10
  console.log(calculator.arrowDouble(5)); // NaN
  console.log(calculator.createArrowDouble()(5)); // 10
  ```

  `calculator.arrowDouble(5)` retorna `NaN` porque a *arrow function* foi criada no
  escopo global (onde `this.factor` é `undefined`). Já `createArrowDouble()` retorna uma
  *arrow function* criada dentro de um método tradicional, capturando corretamente o
  `this` do objeto `calculator`.
</Aside>

## Retorno

Toda função em JavaScript retorna um valor. Se nenhum `return` for especificado ou
se o `return` for chamado sem um operando, a função retornará `undefined`.

```js title="Retorno padrão é undefined"
function greeting(name) {
  console.log(`Hello, ${name}`);
}

const greetingResult = greeting("Fulano"); // Hello, Fulano
console.log(greetingResult); // undefined

function greetingMessage(name) {
  return `Hello, ${name}`;
}

console.log(greetingMessage("Fulano")); // "Hello, Fulano"
```

A instrução `return` interrompe imediatamente a execução da função. Isso é muito
utilizado no padrão *guard clause* (retorno antecipado) para evitar aninhamento
desnecessário de blocos `if/else`.

```js title="Retorno antecipado (Guard Clause)"
function checkAge(age) {
  if (age < 18) {
    return "minor";
  }

  return "adult";
}

console.log(checkAge(17)); // "minor"
console.log(checkAge(18)); // "adult"
```

## Hoisting

*Hoisting* é o comportamento do JavaScript de mover declarações para o topo do seu
escopo antes da execução do código. No entanto, o comportamento difere entre
*Function Declarations* e *Function Expressions*.

*Function Declarations* são completamente elevadas, podendo ser invocadas antes da
linha onde foram declaradas:

```js title="Hoisting com Function Declaration"
console.log(hoistedAddition(2, 3)); // 5

function hoistedAddition(param1, param2) {
  return param1 + param2;
}
```

*Function Expressions* atribuídas a `const` ou `let` permanecem na *Temporal Dead Zone*
(TDZ) e não podem ser acessadas antes da sua inicialização:

```js title="Hoisting com Function Expression (const/let)"
// ReferenceError: Cannot access 'notHoistedSubtraction' before initialization.
// console.log(notHoistedSubtraction(2, 3));
// const notHoistedSubtraction = function (param1, param2) {
//   return param1 - param2;
// };
```

Se a expressão for declarada com `var`, a variável é elevada com o valor `undefined`,
gerando um erro de execução ao tentar chamá-la como função:

```js title="Hoisting com Function Expression (var)"
// TypeError: notHoistedMultiplication is not a function.
// console.log(notHoistedMultiplication(2, 3));
// var notHoistedMultiplication = function (param1, param2) {
//   return param1 * param2;
// };
```

## Redefinição de função

Em JavaScript **não existe sobrecarga de métodos** (*overloading*) nativa baseada na
quantidade de argumentos. Se duas funções com o mesmo nome forem declaradas no mesmo
escopo usando *Function Declaration*, a última definição irá **sobrescrever** a anterior.

```js title="Redefinição no mesmo escopo"
function runRedefinitionExample() {
  function operation(param1, param2) {
    return param1 + param2;
  }

  function operation(param) {
    return param + 1;
  }

  console.log(operation(1)); // 2
  console.log(operation(1, 2)); // 2
}

runRedefinitionExample();
```

## Case Sensitive

Assim como nomes de variáveis, os nomes de funções em JavaScript diferenciam letras
maiúsculas de minúsculas (*case sensitive*). `sumLower` e `SumLower` são identificadores
totalmente independentes.

```js title="Diferenciação de maiúsculas e minúsculas"
function sumLower(param1, param2) {
  return param1 + param2;
}

function SumLower(param) {
  return param + 1;
}

console.log(sumLower(1, 2)); // 3
console.log(SumLower(1, 2)); // 2
```

### Parâmetros padrão (Default Parameters)

É possível atribuir um valor padrão para um parâmetro usando `= defaultValue`. O valor
padrão só é ativado se o argumento for omitido ou se for passado explicitamente o valor
`undefined`.

```js title="Valores padrão para parâmetros"
function power(base, exponent = 1) {
  return base ** exponent;
}

console.log(power(2)); // 2
console.log(power(2, 3)); // 8
console.log(power(2, undefined)); // 2
console.log(power(2, null)); // 1
```

<Aside type="caution" title="null não ativa o valor padrão">
  Passar `null` como argumento não dispara o parâmetro padrão, pois `null` é um valor
  atribuído intencionalmente. Na operação `2 ** null`, `null` é coagido numericamente
  para `0`, resultando em `1`.
</Aside>

Os valores padrão também podem ser expressões dinâmicas calculadas em tempo de execução
ou depender de parâmetros anteriores:

```js title="Valores padrão dinâmicos"
function register(message, date = new Date("2026-08-12T00:00:00.000Z"), prefix = message.length) {
  return `${prefix}: ${message} (${date.toISOString()})`;
}

console.log(register("PW2")); // "3: PW2 (2026-08-12T00:00:00.000Z)"
```

### Rest parameters (`...rest`)

Os *rest parameters* utilizam a sintaxe `...` para capturar os argumentos restantes e
armazená-los em um **array de verdade**.

```js title="Coletando argumentos com rest"
function collect(first, ...rest) {
  console.log(first); // 1
  console.log(rest); // [2, 3]
  console.log(Array.isArray(rest)); // true
}

collect(1, 2, 3);
```

Diferente do objeto `arguments`, o *rest parameter* resulta em uma instância legítima
de `Array`, permitindo o uso direto de métodos como `map`, `reduce`, `filter` e laços
`for...of`.

```js title="Iterando sobre rest parameters"
function sumAll(...numbers) {
  let total = 0;

  for (const number of numbers) {
    total += number;
  }

  return total;
}

console.log(sumAll()); // 0
console.log(sumAll(1, 2, 3)); // 6
console.log(sumAll(1, 2, 3, 4, 5)); // 15

const values = [1, 2, 3];
console.log(sumAll(...values)); // 6
```

<Aside type="caution" title="Posição do rest parameter">
  O parâmetro *rest* deve ser obrigatoriamente o **último** parâmetro na declaração da
  função. Tentar colocar outros parâmetros após um *rest parameter* gera um erro de
  sintaxe.
</Aside>

```js title="Rest parameter em posição inválida"
// SyntaxError: Rest parameter must be last formal parameter.
// function invalidRest(...rest, last) {}
```

### Objeto `arguments`

Em funções declaradas com `function`, a variável local `arguments` contém todos os
argumentos passados para a função. Trata-se de um objeto *array-like* (possui
propriedade `.length` e índices numéricos, mas não é um `Array` real).

```js title="Inspecionando o objeto arguments"
function showArguments() {
  console.log(arguments.length); // 3
  console.log(arguments[0]); // 1
  console.log(Array.isArray(arguments)); // false
  console.log(typeof arguments); // "object"
}

showArguments(1, 2, 3);
```

Para aplicar métodos de array sobre `arguments`, é necessário convertê-lo primeiro
com `Array.from()` ou preferir o uso de *rest parameters*:

```js title="Convertendo arguments para Array"
function sumArguments() {
  return Array.from(arguments).reduce((total, number) => total + number, 0);
}

console.log(sumArguments(1, 2, 3)); // 6
```

<Aside type="note" title="Arrow Functions não possuem arguments próprio">
  *Arrow functions* não possuem seu próprio objeto `arguments`. Se `arguments` for
  acessado dentro de uma *arrow function*, ele será resolvido no escopo léxico externo.
</Aside>

```js title="arguments em Arrow Functions"
function outerArguments() {
  const arrow = () => arguments.length;
  return arrow(9, 9);
}

console.log(outerArguments(1, 2, 3)); // 3
```

### Parâmetros desestruturados

Podemos desestruturar objetos diretamente na lista de parâmetros da função, podendo
inclusive combinar essa sintaxe com valores padrão para cada propriedade e um valor
padrão para o objeto inteiro.

```js title="Desestruturação de parâmetros"
function createUser({ name = "anonymous", active = true } = {}) {
  return `${name} / ${active}`;
}

console.log(createUser({ name: "Fulano" })); // "Fulano / true"
console.log(createUser({ name: "Beltrano", active: false })); // "Beltrano / false"
console.log(createUser()); // "anonymous / true"
```

<Aside type="tip" title="Sempre forneça o fallback de objeto = {}">
  Fornecer `= {}` como padrão para o objeto desestruturado evita erros de execução caso
  a função seja chamada sem nenhum argumento. Sem ele, a tentativa de desestruturar
  `undefined` lança um `TypeError`.
</Aside>

```js title="Desestruturação sem fallback de objeto"
// TypeError: Cannot destructure property 'name' of 'undefined'.
// function createInvalidUser({ name }) {
//   return name;
// }
// createInvalidUser();
```

## Callbacks e funções de primeira classe

Em JavaScript, funções são **cidadãs de primeira classe** (*first-class citizens*).
Isso significa que elas podem ser armazenadas em variáveis, passadas como argumentos
para outras funções e retornadas por outras funções.

Uma função passada como argumento para ser executada posteriormente é chamada de **callback**.

```js title="Passando funções como callbacks"
function addition(param1, param2) {
  return param1 + param2;
}

function subtraction(param1, param2) {
  return param1 - param2;
}

function calc(param1, param2, callback) {
  return callback(param1, param2);
}

console.log(calc(2, 1, addition)); // 3
console.log(calc(2, 1, subtraction)); // 1
console.log(calc(2, 1, (x, y) => x * y)); // 2
console.log(calc(2, 1, (x, y) => x / y)); // 2
console.log(calc(2, 1, (base, exponent) => base ** exponent)); // 2
```

Callbacks também são comuns em predicados de filtragem e validação:

```js title="Callback como predicado de validação"
function isValidNumber(number, callback) {
  return Boolean(callback(number));
}

console.log(isValidNumber(1, (number) => number > 0)); // true
console.log(isValidNumber(1, (number) => number < 0)); // false
console.log(isValidNumber(1, (number) => number & 1)); // true
```

<Aside type="caution" title="Passe a referência da função, não sua invocação">
  Ao passar um callback, envie o **nome** ou a **referência** da função (ex: `addition`).
  Se você passar `addition()`, a função será executada imediatamente e seu resultado será
  enviado no lugar da função, gerando um erro de tipo em tempo de execução.
</Aside>

```js title="Invocação incorreta de callback"
// TypeError: callback is not a function.
// console.log(calc(2, 1, addition()));
```

## Recursos Avançados de Funções

Além das declarações e callbacks básicas, o JavaScript disponibiliza recursos avançados para controle de escopo, encapsulamento, gerenciamento do contexto `this` e controle do fluxo de execução.

### Closures

Uma **Closure** ocorre quando uma função interna guarda a referência ao seu escopo léxico externo, mesmo após a execução da função externa ter sido concluída. Esse comportamento permite criar dados e estados privados que persistem entre chamadas.

```js title="Exemplo de Closure"
function createCounter() {
  let count = 0;

  return function increment() {
    count += 1;
    return count;
  };
}

const counter = createCounter();

console.log(counter()); // 1
console.log(counter()); // 2
```

No exemplo acima, a função `increment` mantém acesso à variável `count` mesmo após a função `createCounter` ter terminado de rodar.

### IIFE (Immediately Invoked Function Expression)

Uma **IIFE** (Expressão de Função Invocada Imediatamente) é uma função em JavaScript que é executada assim que é definida. Ela é estruturada envolvendo uma expressão de função entre parênteses e invocando-a imediatamente com `()`.

```js title="Sintaxe e uso de IIFE"
// 1. IIFE Tradicional
(function () {
  const secret = "TokenSecreto123";
  console.log("IIFE executada automaticamente!");
})();

// 2. IIFE com Arrow Function e parâmetros
((name) => {
  console.log(`Olá, ${name}! Inicializando módulo...`);
})("DevLab");

// Tentativa de acessar a variável interna fora da IIFE:
// console.log(secret); // ReferenceError: secret is not defined
```

**Principais casos de uso de IIFEs:**
- **Encapsulamento e Isolamento de Escopo**: Evita poluir o escopo global com variáveis temporárias ou de inicialização.
- **Padrão Módulo (Module Pattern)**: Permite criar dados e estados privados acessíveis apenas por funções internas.

### Manipulação de Contexto (`call`, `apply` e `bind`)

Em JavaScript, o valor de `this` em funções tradicionais é dinâmico e depende de como a função é chamada. Os métodos `call()`, `apply()` e `bind()` (herdados de `Function.prototype`) permitem configurar e fixar o valor de `this` explicitamente.

| Método | Execução | Passagem de Argumentos | Retorno |
| :--- | :--- | :--- | :--- |
| **`call()`** | Imediata | Lista individual (`arg1, arg2, ...`) | O retorno da função invocada |
| **`apply()`** | Imediata | Array de argumentos (`[arg1, arg2]`) | O retorno da função invocada |
| **`bind()`** | Diferida | Lista individual (parcial ou completa) | Uma **nova função** com `this` vinculado |

```js title="Exemplo: call, apply e bind"
const user1 = { name: "Ana", role: "Desenvolvedora" };
const user2 = { name: "Carlos", role: "Designer" };

function introduce(greeting, punctuation) {
  console.log(`${greeting}, eu sou ${this.name}, atuando como ${this.role}${punctuation}`);
}

// 1. call(): Invoca imediatamente passando argumentos individuais
introduce.call(user1, "Olá", "!"); 
// Output: Olá, eu sou Ana, atuando como Desenvolvedora!

// 2. apply(): Invoca imediatamente passando argumentos em um Array
introduce.apply(user2, ["Bem-vindo", "."]); 
// Output: Bem-vindo, eu sou Carlos, atuando como Designer.

// 3. bind(): Retorna uma nova função com o 'this' fixado permanentemente
const introduceAna = introduce.bind(user1, "Oi");
introduceAna("!!!"); 
// Output: Oi, eu sou Ana, atuando como Desenvolvedora!!!
```

### Funções Geradoras (*Generators*: `function*`)

Uma **Função Geradora** (*Generator Function*) é uma função especial que pode ter sua execução pausada e retomada posteriormente. Ao invés de executar todo o código até o `return`, o gerador utiliza a instrução **`yield`** para produzir valores sob demanda (*lazy evaluation*).

- É declarada com a sintaxe `function* name()`.
- Ao ser invocada, retorna um objeto **Generator** (que implementa o protocolo de iteração).
- O método **`.next()`** retoma a execução até encontrar o próximo `yield`, retornando um objeto no formato `{ value, done }`.

```js title="Exemplo: Generator Function"
function* idGenerator() {
  let id = 1;
  while (true) {
    yield id++;
  }
}

const gen = idGenerator();

console.log(gen.next()); // { value: 1, done: false }
console.log(gen.next()); // { value: 2, done: false }
console.log(gen.next()); // { value: 3, done: false }

// Iterando sobre geradores com limites usando for...of
function* colorsGenerator() {
  yield "vermelho";
  yield "verde";
  yield "azul";
}

for (const color of colorsGenerator()) {
  console.log(color); // vermelho, verde, azul
}
```

## Perguntas de revisão

### Declaração e Arrow Functions

**1. Qual a diferença de sintaxe e comportamento entre retorno explícito e implícito em Arrow Functions?**

<details>
  <summary>Possível resposta</summary>

  Quando uma *arrow function* usa chaves `{...}`, a instrução `return` é obrigatória para retornar um valor. Quando as chaves são omitidas, a expressão seguinte é retornada implicitamente.
</details>

**2. Por que a expressão `const foo = (name) => { name }` retorna `undefined` ao ser executada?**

<details>
  <summary>Possível resposta</summary>

  Porque as chaves `{ name }` são interpretadas como o bloco de código da função e não como um objeto literal. Para retornar um objeto implicitamente, deve-se usar parênteses: `(name) => ({ name })`.
</details>

### Parâmetros e argumentos

**3. O que acontece quando se passa `null` para um parâmetro que possui valor padrão?**

<details>
  <summary>Possível resposta</summary>

  O valor padrão **não** é acionado, pois o padrão só é ativado quando o argumento é omitido ou recebe `undefined`. `null` é mantido como o valor do parâmetro.
</details>

**4. Qual é a vantagem de utilizar Rest Parameters (`...rest`) em relação ao objeto `arguments`?**

<details>
  <summary>Possível resposta</summary>

  Os *rest parameters* resultam em um `Array` real (permitindo uso direto de métodos como `.map()` e `.reduce()`), funcionam em *arrow functions* e permitem selecionar apenas os argumentos restantes a partir de uma posição.
</details>

**5. Por que é recomendável fornecer o valor padrão `= {}` na assinatura de uma função com parâmetros desestruturados?**

<details>
  <summary>Possível resposta</summary>

  Porque se a função for invocada sem argumentos, o parâmetro assumirá o valor `{}`. Sem o `= {}`, a tentativa de desestruturar `undefined` causaria um `TypeError`.
</details>

### Callbacks e Elevação

**6. Qual é a diferença entre passar `myFunc` e `myFunc()` como parâmetro de callback?**

<details>
  <summary>Possível resposta</summary>

  `myFunc` passa a referência da função para que a função receptora possa executá-la quando desejar. `myFunc()` executa a função imediatamente e passa o seu valor de retorno no lugar da função.
</details>

**7. O que acontece ao tentar invocar uma Function Declaration e uma Function Expression antes de suas definições no código?**

<details>
  <summary>Possível resposta</summary>

  *Function Declarations* são completamente elevadas (*hoisted*) e funcionam normalmente. *Function Expressions* com `const`/`let` causam `ReferenceError` devido à Temporal Dead Zone (TDZ).
</details>

### Conceitos avançados

**8. O que é uma Closure em JavaScript?**

<details>
  <summary>Possível resposta</summary>

  É a capacidade de uma função de lembrar e acessar seu escopo léxico externo (variáveis locais), mesmo quando executada fora desse escopo.
</details>

**9. Como o operador `this` se comporta dentro de uma Arrow Function comparado a uma função tradicional?**

<details>
  <summary>Possível resposta</summary>

  Em funções tradicionais, `this` é dinâmico e definido pelo modo de invocação. Em *arrow functions*, `this` é léxico, herdando o contexto do escopo onde a *arrow function* foi definida.
</details>

**10. O que acontece ao declarar duas funções com o mesmo nome no mesmo escopo usando Function Declaration?**

<details>
  <summary>Possível resposta</summary>

  JavaScript não possui sobrecarga nativa de funções. A segunda declaração substitui (sobrescreve) completamente a primeira declaração.
</details>
