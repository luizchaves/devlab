## Formas de Declaração

Em JavaScript, uma função pode ser definida de diferentes maneiras: por meio de uma declaração tradicional, de uma expressão de função atribuída a uma variável ou por meio da sintaxe enxuta de *arrow function*.

### Declaração Tradicional (Function Declaration)

Uma *Function Declaration* define uma função nomeada usando a palavra-chave `function`. Ela é completamente elevada (*hoisted*) para o topo do seu escopo de execução.

O exemplo a seguir demonstra a declaração de uma função e a passagem de argumentos:

```js title="Declaração de função (Function Declaration)"
function addition(param1, param2) {
  return param1 + param2;
}

console.log(addition(1)); // NaN (1 + undefined)
console.log(addition(1, 2)); // 3
console.log(addition(1, 2, 3)); // 3 (argumento extra ignorado)
```

Quando argumentos extras são fornecidos, eles são ignorados pela assinatura da função; quando argumentos esperados são omitidos, eles assumem o valor `undefined` (o que faz `1 + undefined` resultar em `NaN`).

### Expressão de Função (Function Expression)

Uma *Function Expression* define uma função anônima ou nomeada e a atribui a uma variável ou constante.

O exemplo a seguir demonstra a criação e invocação de uma expressão de função:

```js title="Expressão de função (Function Expression)"
const subtraction = function (param1, param2) {
  return param1 - param2;
};

console.log(subtraction); // [Function: subtraction]
console.log(subtraction(2, 1)); // 1
```

### Arrow Functions

Introduzidas no ES6, as *Arrow Functions* fornecem uma sintaxe compacta para definir funções: a palavra-chave `function` desaparece e a notação `=>` liga a lista de parâmetros ao corpo.

Essa sintaxe admite duas formas de corpo. Com chaves, a função se comporta como qualquer outra e precisa de `return`; sem chaves, a expressão à direita da seta já é o valor devolvido.

O exemplo a seguir demonstra as duas formas, além do caso de um único parâmetro:

```js title="Arrow Functions"
const multiplication = (param1, param2) => {
  return param1 * param2;
};

const division = (param1, param2) => param1 / param2;
const double = (number) => number * 2;

console.log(multiplication(2, 3)); // 6
console.log(division(6, 2)); // 3
console.log(double(5)); // 10
```

<Aside type="note" title="Retorno explícito vs. implícito em Arrow Functions">
  Quando a *arrow function* possui corpo entre chaves `{...}`, o uso da instrução `return` é **obrigatório** para devolver um valor. Quando as chaves são omitidas, a expressão seguinte é avaliada e retornada **implicitamente**.
</Aside>

Para retornar um objeto literal de forma implícita em uma *arrow function*, envolva o objeto entre parênteses `({ ... })`. Caso contrário, as chaves serão interpretadas como o corpo da função, resultando em `undefined`.

O exemplo a seguir compara o retorno implícito correto e incorreto de objetos literais:

```js title="Retorno implícito de objetos"
const createObject = (name) => ({ name });
const wrongCreateObject = (name) => { name };

console.log(createObject("Fulano")); // { name: 'Fulano' }
console.log(wrongCreateObject("Fulano")); // undefined
```

Não é permitido misturar a palavra-chave `function` com a notação de seta `=>`:

```js title="Sintaxe incorreta"
// SyntaxError: Unexpected token '='.
// function wrongAddition = (param1, param2) {
//   return param1 + param2;
// }
```

Além da sintaxe enxuta, as *arrow functions* diferem das funções tradicionais em um ponto decisivo: elas não criam o próprio `this`, e essa característica define onde elas devem (ou não) ser usadas.

<Aside type="caution" title="Comportamento do operador this em Arrow Functions">
  Diferente das funções tradicionais (cujo `this` é dinâmico e definido no momento da chamada), as *Arrow Functions* possuem **`this` léxico**: elas herdam o `this` do escopo onde foram criadas. Por essa razão, evite declarar *arrow functions* como métodos diretos de objetos.

  ```js title="this em métodos e arrow functions"
  const calculator = {
    factor: 2,
    regularDouble(number) {
      return number * this.factor;
    },
    arrowDouble: (number) => number * this.factor,
    createArrowDouble() {
      return (number) => number * this.factor;
    },
  };

  console.log(calculator.regularDouble(5)); // 10
  console.log(calculator.arrowDouble(5)); // NaN
  console.log(calculator.createArrowDouble()(5)); // 10
  ```

  `calculator.arrowDouble(5)` retorna `NaN` porque a *arrow function* foi criada no escopo global (onde `this.factor` é `undefined`). Já `createArrowDouble()` retorna uma *arrow function* criada dentro de um método tradicional, capturando corretamente o `this` do objeto `calculator`.
</Aside>

### Comparação entre Formas de Declaração

A tabela a seguir compara as três principais formas de definir funções em JavaScript:

| Característica | Function Declaration | Function Expression | Arrow Function |
| :--- | :--- | :--- | :--- |
| **Sintaxe básica** | `function f() {}` | `const f = function() {}` | `const f = () => {}` |
| **Hoisting** | Completo (corpo e nome) | Apenas variável (`TDZ` com `const`/`let`) | Apenas variável (`TDZ` com `const`/`let`) |
| **Contexto `this`** | Dinâmico (momento da chamada) | Dinâmico (momento da chamada) | Léxico (herdado do escopo pai) |
| **Objeto `arguments`** | Presente | Presente | Ausente (resolvido no escopo léxico) |
| **Construtor (`new`)** | Sim (possui `prototype`) | Sim (se não for arrow) | Não (`TypeError`) |

## Retorno e Fluxo de Execução

Toda função em JavaScript retorna um valor. Se nenhum `return` for especificado ou se a instrução `return` for invocada sem um operando, a função retornará `undefined`.

### Retorno Padrão e Retorno Explícito

Uma função sem `return` ainda produz um valor: o interpretador devolve `undefined` ao chegar ao fim do bloco. É por isso que o resultado de uma função que apenas imprime no console não pode ser reaproveitado em cálculos ou expressões seguintes.

O exemplo a seguir contrasta uma função que apenas imprime a potência com outra que devolve o valor calculado:

```js title="Retorno padrão é undefined"
function showPower(base, exponent) {
  console.log(base ** exponent);
}

const result = showPower(2, 3); // 8 (apenas exibe no console)
console.log(result);            // undefined (não há retorno)
console.log(result * 2);        // NaN (undefined * 2)

function calculatePower(base, exponent) {
  return base ** exponent;
}

const value = calculatePower(2, 3);
console.log(value);             // 8 (valor retornado)
console.log(value * 2);         // 16 (reutilizável em cálculos)
```

A função `showPower` escreve o resultado no console e devolve `undefined` (o que gera `NaN` ao tentar multiplicá-lo por 2), enquanto `calculatePower` devolve o valor numérico com `return`, permitindo que quem chamou utilize o resultado em outros cálculos ou estruturas.

### Retorno Antecipado (Guard Clauses)

A instrução `return` encerra imediatamente a execução da função. Esse recurso é muito utilizado no padrão *guard clause* (retorno antecipado) para tratar condições especiais logo no início da função, evitando o aninhamento profundo de blocos `if/else`.

O exemplo a seguir aplica *guard clauses* para validar fluxos condicionais de forma direta:

```js title="Retorno antecipado (Guard Clause)"
function checkAge(age) {
  if (age < 18) {
    return "minor";
  }

  return "adult";
}

console.log(checkAge(17)); // "minor"
console.log(checkAge(18)); // "adult"
```

## Hoisting e Elevação de Escopo

*Hoisting* é o comportamento do interpretador JavaScript de elevar declarações para o topo do seu escopo durante a fase de compilação. O que sobe, porém, muda conforme a forma de declaração: uma *Function Declaration* é elevada com nome e corpo, enquanto uma *Function Expression* eleva apenas a variável que a recebe.

A tabela a seguir resume o que acontece ao invocar cada forma antes da linha em que ela foi escrita:

| Forma de declaração | O que é elevado | Chamada antecipada |
| :--- | :--- | :--- |
| `function f() {}` | Nome e corpo da função | Funciona normalmente |
| `const f = function () {}` | Apenas o identificador, em TDZ | `ReferenceError` |
| `var f = function () {}` | Identificador com valor `undefined` | `TypeError` |

As subseções a seguir demonstram cada uma dessas linhas em código executável.

### Hoisting em Function Declarations

*Function Declarations* têm tanto seu identificador quanto seu corpo completamente elevados, permitindo que sejam invocadas antes da linha onde foram escritas:

```js title="Hoisting com Function Declaration"
console.log(hoistedAddition(2, 3)); // 5

function hoistedAddition(param1, param2) {
  return param1 + param2;
}
```

### Hoisting em Function Expressions

*Function Expressions* atribuídas a variáveis com `const` ou `let` permanecem na *Temporal Dead Zone* (TDZ) e lançam um erro de referência caso sejam invocadas antes da linha de inicialização:

```js title="Hoisting com Function Expression (const/let)"
// ReferenceError: Cannot access 'notHoistedSubtraction' before initialization.
// console.log(notHoistedSubtraction(2, 3));
// const notHoistedSubtraction = function (param1, param2) {
//   return param1 - param2;
// };
```

Quando declaradas com `var`, a variável é elevada com o valor inicial `undefined`, gerando um erro `TypeError` ao tentar invocá-la como função:

```js title="Hoisting com Function Expression (var)"
// TypeError: notHoistedMultiplication is not a function.
// console.log(notHoistedMultiplication(2, 3));
// var notHoistedMultiplication = function (param1, param2) {
//   return param1 * param2;
// };
```

## Redefinição e Sensibilidade a Caixa

O JavaScript possui particularidades em relação à nomenclatura e à declaração repetida de funções.

### Redefinição no Mesmo Escopo

Em JavaScript **não existe sobrecarga de métodos** (*overloading*) nativa baseada na quantidade ou nos tipos de argumentos. Se duas *Function Declarations* com o mesmo nome forem declaradas no mesmo escopo, a última definição irá **sobrescrever** a anterior por completo.

O exemplo a seguir demonstra o comportamento de sobrescrita de funções no mesmo escopo:

```js title="Redefinição no mesmo escopo"
function runRedefinitionExample() {
  function operation(param1, param2) {
    return param1 + param2;
  }

  function operation(param) {
    return param + 1;
  }

  console.log(operation(1)); // 2
  console.log(operation(1, 2)); // 2
}

runRedefinitionExample();
```

### Sensibilidade a Maiúsculas e Minúsculas (Case Sensitive)

Assim como variáveis, identificadores de funções diferenciam letras maiúsculas de minúsculas (*case sensitive*). Por exemplo, `power` e `Power` são tratados pelo interpretador como duas funções completamente distintas na memória.

O exemplo a seguir demonstra a diferenciação entre identificadores com caixas diferentes, ambos mantendo a fidelidade semântica de cálculo de potência através de abordagens válidas:

```js title="Diferenciação de maiúsculas e minúsculas"
function power(base, exponent) {
  return base ** exponent;
}

function Power(base, exponent) {
  return Math.pow(base, exponent);
}

console.log(power(2, 3)); // 8 (usa operador de exponenciação)
console.log(Power(2, 3)); // 8 (usa Math.pow nativo)
```

## Parâmetros e Argumentos

JavaScript oferece flexibilidade na manipulação de entradas em funções, permitindo valores de contingência (*fallback*), coleta de múltiplos argumentos em arrays e extração direta de propriedades.

### Parâmetros Padrão (Default Parameters)

É possível atribuir um valor padrão para um parâmetro utilizando `= defaultValue`. O valor padrão só é ativado se o argumento correspondente for omitido ou se for passado *explicitamente* o valor `undefined`.

O exemplo a seguir demonstra o uso de parâmetros padrão e o comportamento ao receber valores nulos ou omitidos:

```js title="Valores padrão para parâmetros"
function power(base, exponent = 1) {
  return base ** exponent;
}

console.log(power(2)); // 2
console.log(power(2, 3)); // 8
console.log(power(2, undefined)); // 2
console.log(power(2, null)); // 1
```

<Aside type="caution" title="null não ativa o valor padrão">
  Passar `null` como argumento não dispara o parâmetro padrão, pois `null` é considerado um valor atribuído intencionalmente. Na operação `2 ** null`, `null` é coagido numericamente para `0`, resultando em `1`.
</Aside>

Os valores padrão também podem ser expressões dinâmicas avaliadas em tempo de execução ou fazer referência a parâmetros anteriores da mesma assinatura:

```js title="Valores padrão dinâmicos"
function register(message, date = new Date("2026-08-12T00:00:00.000Z"), prefix = message.length) {
  return `${prefix}: ${message} (${date.toISOString()})`;
}

console.log(register("PW2")); // "3: PW2 (2026-08-12T00:00:00.000Z)"
```

### Rest Parameters (`...rest`)

Os *rest parameters* utilizam a sintaxe `...` para capturar todos os argumentos restantes passados na invocação e agrupá-los em um **Array legítimo**.

O exemplo a seguir demonstra a captura de argumentos posicionais e do array de elementos restantes:

```js title="Coletando argumentos com rest"
function collect(first, ...rest) {
  console.log(first); // 1
  console.log(rest); // [2, 3]
  console.log(Array.isArray(rest)); // true
}

collect(1, 2, 3);
```

Por ser uma instância real de `Array`, os *rest parameters* permitem aplicar diretamente métodos como `map`, `filter`, `reduce` e iterações com loops `for...of`:

```js title="Iterando sobre rest parameters"
function sumAll(...numbers) {
  let total = 0;

  for (const number of numbers) {
    total += number;
  }

  return total;
}

console.log(sumAll()); // 0
console.log(sumAll(1, 2, 3)); // 6
console.log(sumAll(1, 2, 3, 4, 5)); // 15

const values = [1, 2, 3];
console.log(sumAll(...values)); // 6
```

<Aside type="caution" title="Posição do rest parameter">
  O parâmetro *rest* deve ser obrigatoriamente o **último** parâmetro na assinatura da função. Tentar declarar outros parâmetros após um *rest parameter* gera um erro de sintaxe imediato.
</Aside>

O trecho comentado a seguir registra o erro produzido pelo interpretador ao declarar um parâmetro depois do *rest*:

```js title="Rest parameter em posição inválida"
// SyntaxError: Rest parameter must be last formal parameter.
// function invalidRest(...rest, last) {}
```

### Objeto `arguments`

Em funções tradicionais declaradas com `function`, a variável local `arguments` contém todos os valores passados na chamada. Trata-se de um objeto *array-like* (possui índices numéricos e a propriedade `.length`, mas não herda os métodos de `Array.prototype`).

O exemplo a seguir demonstra a inspeção de propriedades do objeto `arguments`:

```js title="Inspecionando o objeto arguments"
function showArguments() {
  console.log(arguments.length); // 3
  console.log(arguments[0]); // 1
  console.log(Array.isArray(arguments)); // false
  console.log(typeof arguments); // "object"
}

showArguments(1, 2, 3);
```

Para aplicar métodos de array sobre `arguments`, é necessário convertê-lo primeiro em array com `Array.from()` ou preferir diretamente o uso de *rest parameters*:

```js title="Convertendo arguments para Array"
function sumArguments() {
  return Array.from(arguments).reduce((total, number) => total + number, 0);
}

console.log(sumArguments(1, 2, 3)); // 6
```

<Aside type="note" title="Arrow Functions não possuem arguments próprio">
  *Arrow functions* não possuem seu próprio objeto `arguments`. Se `arguments` for referenciado dentro de uma *arrow function*, ele será resolvido no escopo léxico externo.
</Aside>

No exemplo a seguir, a *arrow function* interna é chamada com dois argumentos, mas `arguments.length` reporta os três argumentos recebidos pela função externa:

```js title="arguments em Arrow Functions"
function outerArguments() {
  const arrow = () => arguments.length;
  return arrow(9, 9);
}

console.log(outerArguments(1, 2, 3)); // 3
```

### Parâmetros Desestruturados

Podemos desestruturar propriedades de objetos ou elementos de arrays diretamente na assinatura da função. Essa técnica simplifica o código ao evitar repetições como `user.name` ou `user.role`.

O aprendizado dessa sintaxe torna-se mais natural quando dividido em três passos progressivos:

#### Desestruturação Direta de Objetos

No nível básico, especificamos entre chaves `{ ... }` as propriedades que a função deve extrair do objeto recebido como argumento:

```js title="Desestruturação básica de parâmetros"
function formatUser({ name, role }) {
  return `${name} (${role})`;
}

const user = { name: "Maria", role: "admin", age: 30 };
console.log(formatUser(user)); // "Maria (admin)"
```

A função extrai diretamente `name` e `role`, ignorando propriedades adicionais (como `age`) que não interessam àquela operação.

#### Valores Padrão para Propriedades Opcionais

Podemos definir valores de contingência (*fallbacks*) para propriedades que possam vir omitidas ou com valor `undefined`:

```js title="Valores padrão em propriedades desestruturadas"
function formatProfile({ name, role = "visitante" }) {
  return `${name} (${role})`;
}

console.log(formatProfile({ name: "Carlos", role: "editor" })); // "Carlos (editor)"
console.log(formatProfile({ name: "Ana" }));                    // "Ana (visitante)"
```

#### Fallback para o Objeto Completo

Se uma função com parâmetros desestruturados for chamada sem nenhum argumento, o JavaScript tenta desestruturar `undefined`, o que lança um erro `TypeError`:

```js title="Erro ao desestruturar sem argumento"
// TypeError: Cannot destructure property 'name' of 'undefined'.
// formatProfile();
```

Para proteger a função e torná-la totalmente segura para chamadas sem parâmetros, atribuímos um objeto vazio como valor padrão da assinatura (`= {}`):

```js title="Desestruturação segura com fallback de objeto"
function createUser({ name = "anônimo", role = "visitante" } = {}) {
  return `${name} (${role})`;
}

console.log(createUser({ name: "Beatriz", role: "admin" })); // "Beatriz (admin)"
console.log(createUser({ name: "Lucas" }));                   // "Lucas (visitante)"
console.log(createUser());                                   // "anônimo (visitante)"
```

<Aside type="tip" title="Sempre forneça o fallback de objeto = {}">
  Ao desestruturar parâmetros de configuração ou opções opcionais, inclua `= {}` no final da assinatura. Assim, a função poderá ser chamada tanto com opções parciais `fn({ role: "admin" })` quanto sem nenhum parâmetro `fn()`.
</Aside>

## Callbacks e Funções de Primeira Classe

Em JavaScript, funções são **cidadãs de primeira classe** (*first-class citizens*). Isso significa que elas podem ser atribuídas a variáveis, passadas como argumentos para outras funções e retornadas por outras funções.

Uma função passada como argumento para ser executada posteriormente é denominada **callback**.

O exemplo a seguir demonstra o recebimento e execução de callbacks para operações matemáticas:

```js title="Passando funções como callbacks"
function addition(param1, param2) {
  return param1 + param2;
}

function subtraction(param1, param2) {
  return param1 - param2;
}

function calc(param1, param2, callback) {
  return callback(param1, param2);
}

console.log(calc(2, 1, addition)); // 3
console.log(calc(2, 1, subtraction)); // 1
console.log(calc(2, 1, (x, y) => x * y)); // 2
console.log(calc(2, 1, (x, y) => x / y)); // 2
console.log(calc(2, 1, (base, exponent) => base ** exponent)); // 2
```

Callbacks também são amplamente utilizados em predicados de validação e filtragem:

```js title="Callback como predicado de validação"
function isValidNumber(number, callback) {
  return Boolean(callback(number));
}

console.log(isValidNumber(1, (number) => number > 0)); // true
console.log(isValidNumber(1, (number) => number < 0)); // false
console.log(isValidNumber(1, (number) => number & 1)); // true
```

<Aside type="caution" title="Passe a referência da função, não sua invocação">
  Ao passar um callback, envie a **referência** da função (ex: `addition`). Se você passar `addition()`, a função será executada imediatamente e seu resultado será enviado no lugar da função, gerando um erro de tipo em tempo de execução.
</Aside>

O trecho comentado a seguir registra o erro gerado ao enviar o resultado da chamada no lugar da referência:

```js title="Invocação incorreta de callback"
// TypeError: callback is not a function.
// console.log(calc(2, 1, addition()));
```

## Recursos Avançados de Funções

Além dos padrões básicos de invocação e callbacks, o JavaScript disponibiliza recursos para retenção de escopo, encapsulamento, vinculação de contexto e controle sob demanda do fluxo de execução.

### Closures

Uma **Closure** ocorre quando uma função interna guarda a referência ao seu escopo léxico de criação, mesmo após a função externa ter concluído sua execução. Esse mecanismo permite encapsular dados e preservar estados privados entre invocações.

O diagrama a seguir acompanha a variável `count` desde a sua criação até as chamadas feitas muito depois de a função externa ter terminado:

<Mermaid title="Mecanismo de closure e retenção do escopo léxico">
{`
flowchart TD
  subgraph Outer["1. createCounter() em execução"]
    A["let count = 0"]
    B["function increment()"]
    A -- "captura léxica" --> B
  end

  B --> C["2. return increment<br/>createCounter() encerra"]
  C --> D["3. const counter = createCounter()"]
  D --> E["4. counter() incrementa e devolve count"]
  E -. "count segue vivo na memória" .-> A
`}
</Mermaid>

O exemplo a seguir demonstra a criação de um contador com estado privado utilizando closures:

```js title="Exemplo de Closure"
function createCounter() {
  let count = 0;

  return function increment() {
    count += 1;
    return count;
  };
}

const counter = createCounter();

console.log(counter()); // 1
console.log(counter()); // 2
```

No exemplo acima, a função `increment` mantém acesso à variável `count` mesmo após a função `createCounter` ter encerrado sua execução.

### IIFE (Immediately Invoked Function Expression)

Uma **IIFE** (Expressão de Função Invocada Imediatamente) é uma função executada no momento exato em que é definida. Ela é construída envolvendo a função entre parênteses e invocando-a com `()` logo em seguida.

O exemplo a seguir demonstra a sintaxe tradicional de IIFE e uma variação com arrow functions e parâmetros:

```js title="Sintaxe e uso de IIFE"
// 1. IIFE Tradicional
(function () {
  const secret = "TokenSecreto123";
  console.log("IIFE executada automaticamente!");
})();

// 2. IIFE com Arrow Function e parâmetros
((name) => {
  console.log(`Olá, ${name}! Inicializando módulo...`);
})("DevLab");

// Tentativa de acessar a variável interna fora da IIFE:
// console.log(secret); // ReferenceError: secret is not defined
```

A constante `secret` existe apenas enquanto a IIFE executa: ao terminar, o escopo é descartado e o identificador deixa de ser alcançável de fora. Esse isolamento explica os dois usos mais comuns do padrão:

- **Encapsulamento e Isolamento de Escopo**: Evita a poluição do escopo global com variáveis temporárias ou de inicialização.
- **Padrão Módulo (Module Pattern)**: Permite expor apenas APIs públicas e manter implementações internas protegidas.

### Manipulação de Contexto (`call`, `apply` e `bind`)

Em JavaScript, o valor de `this` em funções tradicionais é dinâmico e depende da forma como a função é chamada. Os métodos `call()`, `apply()` e `bind()` (disponíveis em `Function.prototype`) permitem configurar e fixar o valor de `this` explicitamente.

A tabela a seguir compara o comportamento dos três métodos:

| Método | Execução | Passagem de Argumentos | Retorno |
| :--- | :--- | :--- | :--- |
| **`call()`** | Imediata | Lista individual (`arg1, arg2, ...`) | O retorno da função invocada |
| **`apply()`** | Imediata | Array de argumentos (`[arg1, arg2]`) | O retorno da função invocada |
| **`bind()`** | Diferida | Lista individual (parcial ou completa) | Uma **nova função** com `this` vinculado |

O exemplo a seguir demonstra a aplicação prática de `call()`, `apply()` e `bind()` para reutilização de métodos com contextos distintos:

```js title="Exemplo: call, apply e bind"
const user1 = { name: "Ana", role: "Desenvolvedora" };
const user2 = { name: "Carlos", role: "Designer" };

function introduce(greeting, punctuation) {
  console.log(`${greeting}, eu sou ${this.name}, atuando como ${this.role}${punctuation}`);
}

// 1. call(): Invoca imediatamente passando argumentos individuais
introduce.call(user1, "Olá", "!");
// Output: Olá, eu sou Ana, atuando como Desenvolvedora!

// 2. apply(): Invoca imediatamente passando argumentos em um Array
introduce.apply(user2, ["Bem-vindo", "."]);
// Output: Bem-vindo, eu sou Carlos, atuando como Designer.

// 3. bind(): Retorna uma nova função com o 'this' fixado permanentemente
const introduceAna = introduce.bind(user1, "Oi");
introduceAna("!!!");
// Output: Oi, eu sou Ana, atuando como Desenvolvedora!!!
```

A mesma função `introduce` produziu três saídas diferentes sem ser reescrita. `call()` e `apply()` se distinguem apenas pela forma de entregar os argumentos, enquanto `bind()` não imprime nada por conta própria: ela devolve uma função nova, com `user1` fixado e o argumento `"Oi"` já preenchido, para ser chamada depois.

### Funções Geradoras (*Generators*: `function*`)

Uma **Função Geradora** (*Generator Function*) é uma função especial que pode ter sua execução pausada e retomada sob demanda. Ao invés de executar todo o bloco até o `return`, o gerador utiliza a palavra-chave **`yield`** para produzir valores de forma preguiçosa (*lazy evaluation*).

Três características definem o funcionamento desse tipo de função:

- É declarada com a sintaxe `function* name()`.
- Ao ser invocada, retorna um objeto **Generator** que implementa o protocolo de iteração.
- O método **`.next()`** retoma a execução até o próximo `yield`, retornando um objeto no formato `{ value, done }`.

O diagrama a seguir mostra o ciclo entre a chamada de `.next()` e a pausa do corpo da função no `yield`:

<Mermaid title="Ciclo de pausa e retomada de uma função geradora">
{`
flowchart TD
  A["idGenerator() é invocada"] --> B["Objeto Generator criado<br/>corpo ainda não executou"]
  B --> C["Chamada de gen.next()"]
  C --> D["Corpo executa até o próximo yield"]
  D --> E["Devolve value e done: false<br/>e congela o estado local"]
  E --> C
  D --> F["Fim do corpo ou return<br/>devolve done: true"]
`}
</Mermaid>

O exemplo a seguir demonstra a criação de um gerador infinito de IDs e a iteração sobre geradores finitos com loops `for...of`:

```js title="Exemplo: Generator Function"
function* idGenerator() {
  let id = 1;
  while (true) {
    yield id++;
  }
}

const gen = idGenerator();

console.log(gen.next()); // { value: 1, done: false }
console.log(gen.next()); // { value: 2, done: false }
console.log(gen.next()); // { value: 3, done: false }

// Iterando sobre geradores com limites usando for...of
function* colorsGenerator() {
  yield "vermelho";
  yield "verde";
  yield "azul";
}

for (const color of colorsGenerator()) {
  console.log(color); // vermelho, verde, azul
}
```

## Resumo e Boas Práticas

Esta seção consolida as decisões práticas do tópico. Use-a como referência rápida para escolher formas de declaração, gerenciar argumentos e aplicar recursos avançados de escopo.

### Formas de Declaração e Arrow Functions

Escolha a sintaxe adequada considerando o contexto de execução e o operador `this`.

- Prefira *Arrow Functions* para callbacks, funções de alta ordem (`map`, `filter`) e métodos que necessitam herdar o `this` léxico do escopo pai.
- Utilize *Function Declarations* ou métodos tradicionais de objeto quando a função precisar de seu próprio `this` dinâmico ou se beneficiar de *hoisting*.
- Ao retornar objetos literais implicitamente em *arrow functions*, envolva-os sempre entre parênteses: `(x) => ({ val: x })`.
- Utilize *guard clauses* (retorno antecipado) para tratar exceções e casos limites no início da função, reduzindo aninhamento desnecessário de `if/else`.

### Parâmetros, Rest e Desestruturação

Manipule entradas de dados de forma previsível e imutável.

- Utilize parâmetros padrão (`param = fallback`) em vez de checagens manuais com `||` ou `typeof`.
- Lembre-se de que `null` é um valor intencional e **não** dispara o parâmetro padrão.
- Prefira *Rest Parameters* (`...rest`) ao objeto legado `arguments`, pois eles produzem instâncias reais de `Array`.
- Sempre forneça o valor padrão de objeto vazio `= {}` ao desestruturar parâmetros, prevenindo erros `TypeError` caso a função seja chamada sem argumentos.

### Closures, Contexto (this) e Recursos Avançados

Gerencie estados privados e vincule contextos de execução com precisão.

- Aplique *Closures* para encapsular variáveis privadas e criar fábricas de funções com estado persistente.
- Utilize *IIFE* ou módulos ES para isolar escopos e evitar a contaminação do escopo global.
- Use `.call()` e `.apply()` para invocar funções imediatamente com contexto customizado, e `.bind()` quando precisar criar uma função com `this` pré-fixado para ser chamada posteriormente.
- Empregue *Generators* (`function*` e `yield`) para computações sob demanda (*lazy evaluation*) e criação de iteráveis customizados.

## Perguntas de revisão

### Declaração e Arrow Functions

**1. Qual a diferença de sintaxe e comportamento entre retorno explícito e implícito em Arrow Functions?**

<details>
  <summary>Possível resposta</summary>

  Quando uma *arrow function* usa chaves `{...}`, a instrução `return` é obrigatória para retornar um valor. Quando as chaves são omitidas, a expressão seguinte é retornada implicitamente.
</details>

**2. Por que a expressão `const foo = (name) => { name }` retorna `undefined` ao ser executada?**

<details>
  <summary>Possível resposta</summary>

  Porque as chaves `{ name }` são interpretadas como o bloco de código da função e não como um objeto literal. Para retornar um objeto implicitamente, deve-se usar parênteses: `(name) => ({ name })`.
</details>

### Parâmetros e argumentos

**3. O que acontece quando se passa `null` para um parâmetro que possui valor padrão?**

<details>
  <summary>Possível resposta</summary>

  O valor padrão **não** é acionado, pois o padrão só é ativado quando o argumento é omitido ou recebe `undefined`. `null` é mantido como o valor do parâmetro.
</details>

**4. Qual é a vantagem de utilizar Rest Parameters (`...rest`) em relação ao objeto `arguments`?**

<details>
  <summary>Possível resposta</summary>

  Os *rest parameters* resultam em um `Array` real (permitindo uso direto de métodos como `.map()` e `.reduce()`), funcionam em *arrow functions* e permitem selecionar apenas os argumentos restantes a partir de uma posição.
</details>

**5. Por que é recomendável fornecer o valor padrão `= {}` na assinatura de uma função com parâmetros desestruturados?**

<details>
  <summary>Possível resposta</summary>

  Porque se a função for invocada sem argumentos, o parâmetro assumirá o valor `{}`. Sem o `= {}`, a tentativa de desestruturar `undefined` causaria um `TypeError`.
</details>

### Callbacks e hoisting

**6. Qual é a diferença entre passar `myFunc` e `myFunc()` como parâmetro de callback?**

<details>
  <summary>Possível resposta</summary>

  `myFunc` passa a referência da função para que a função receptora possa executá-la quando desejar. `myFunc()` executa a função imediatamente e passa o seu valor de retorno no lugar da função.
</details>

**7. O que acontece ao tentar invocar uma Function Declaration e uma Function Expression antes de suas definições no código?**

<details>
  <summary>Possível resposta</summary>

  *Function Declarations* são completamente elevadas (*hoisted*) e funcionam normalmente. *Function Expressions* com `const`/`let` causam `ReferenceError` devido à Temporal Dead Zone (TDZ).
</details>

### Conceitos avançados

**8. O que é uma Closure em JavaScript?**

<details>
  <summary>Possível resposta</summary>

  É a capacidade de uma função de lembrar e acessar seu escopo léxico externo (variáveis locais), mesmo quando executada fora desse escopo.
</details>

**9. Como o operador `this` se comporta dentro de uma Arrow Function comparado a uma função tradicional?**

<details>
  <summary>Possível resposta</summary>

  Em funções tradicionais, `this` é dinâmico e definido pelo modo de invocação. Em *arrow functions*, `this` é léxico, herdando o contexto do escopo onde a *arrow function* foi definida.
</details>

**10. O que acontece ao declarar duas funções com o mesmo nome no mesmo escopo usando Function Declaration?**

<details>
  <summary>Possível resposta</summary>

  JavaScript não possui sobrecarga nativa de funções. A segunda declaração substitui (sobrescreve) completamente a primeira declaração.
</details>

**11. Qual é a diferença prática entre `call()`, `apply()` e `bind()`?**

<details>
  <summary>Possível resposta</summary>

  `call()` e `apply()` invocam a função imediatamente com o `this` informado, diferindo apenas na entrega dos argumentos (lista individual em `call()`, array em `apply()`). `bind()` não invoca nada: devolve uma nova função com o `this` fixado, que pode ser chamada depois.
</details>

**12. O que o método `.next()` devolve ao ser chamado em um objeto Generator?**

<details>
  <summary>Possível resposta</summary>

  Um objeto no formato `{ value, done }`, onde `value` é o valor produzido pelo `yield` alcançado e `done` indica se a função já chegou ao fim. Entre duas chamadas de `.next()`, o corpo da função permanece pausado com o estado local preservado.
</details>
