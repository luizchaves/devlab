## Criação de Objetos e Notação Literal

Em JavaScript, um **Objeto** é uma coleção dinâmica de propriedades, onde cada propriedade é uma associação entre uma **chave** (*key* ou nome) e um **valor** (*value*). O valor de uma propriedade pode ser de qualquer tipo: primitivos, arrays, outros objetos ou funções (que recebem o nome de **métodos**).

O diagrama a seguir ilustra a representação de um objeto literal na memória Heap e sua ligação com a cadeia de protótipos padrão (`Object.prototype`):

A variável guarda apenas o endereço do objeto, enquanto os dados e a ligação com `Object.prototype` ficam na memória Heap.

O exemplo a seguir demonstra as duas formas de criar objetos, a notação literal (recomendada) e o construtor `new Object()`, além de um método declarado com a sintaxe abreviada do ES6:

```js title="Formas de criação de objetos"
// 1. Literal de Objeto (Recomendado)
const student = {
  id: 2026101,
  name: "Fulano de Tal",
  email: "fulano@ifpb.edu.br",
  active: true,
  courses: ["DW", "Redes"],
  // Método do objeto (sintaxe abreviada do ES6)
  getSummary() {
    return `${this.name} (${this.email})`;
  },
};

// 2. Construtor new Object() (Evitar)
const server = new Object();
server.ip = "192.168.0.1";
server.port = 8080;

console.log(student.name);        // "Fulano de Tal"
console.log(student.getSummary()); // "Fulano de Tal (fulano@ifpb.edu.br)"
console.log(server.ip);           // "192.168.0.1"
```

Dentro de um método, a palavra-chave especial **`this`** faz referência ao próprio objeto que invocou a função (`student`), permitindo acessar e manipular suas demais propriedades, como `this.name` e `this.email`.

O exemplo reúne, em um só lugar, as características e a terminologia usadas no restante do tópico. A tabela a seguir detalha cada uma delas:

| Característica | Descrição | Exemplo |
| -------------- | --------- | ------- |
| **Notação Literal** | Forma mais comum e legível de criar objetos com `{}` | `const user = { name: "Ana" };` |
| **Chave (Key)** | Identificador da propriedade (string ou Symbol) | `name`, `age`, `"end-point"` |
| **Valor (Value)** | Qualquer dado associado à chave | `"Ana"`, `28`, `true`, `[1, 2]` |
| **Método** | Uma função armazenada como valor de uma propriedade | `getSummary() { return ...; }` |
| **Palavra-chave `this`** | Referência ao próprio objeto que está executando o método | `this.name` // `"Fulano de Tal"` |
| **Tipo de Dado** | Tipo de dado não primitivo em JavaScript | `typeof {}` // `"object"` |

## Property Shorthand (Sintaxe Abreviada de Propriedades)

Quando o nome da variável local é idêntico ao nome da chave do objeto que se deseja criar, o JavaScript permite omitir a repetição do nome.

O exemplo a seguir compara a forma tradicional, que repete cada identificador, com a forma abreviada:

```js title="Uso de Property Shorthand"
const name = "Alice";
const email = "alice@gmail.com";
const role = "admin";

// Forma tradicional (verbosa)
const userOld = { name: name, email: email, role: role };

// Forma moderna com Property Shorthand
const user = { name, email, role };

console.log(user); // { name: 'Alice', email: 'alice@gmail.com', role: 'admin' }
```

Os objetos `userOld` e `user` são idênticos: a diferença está apenas na quantidade de repetição que cada declaração exige.

<Aside type="tip" title="Notação de Propriedades Abreviada">
  A sintaxe abreviada `{ name, email }` é amplamente utilizada em código moderno para construir objetos de forma limpa a partir de variáveis locais existentes.
</Aside>

## Acesso, Modificação e Remoção de Propriedades

O acesso às propriedades de um objeto pode ser feito por **Notação de Ponto** (`obj.prop`) ou por **Notação de Colchetes** (`obj["prop"]`).

Além da leitura, um objeto aceita a adição, a alteração e a remoção de propriedades em tempo de execução, e oferece formas seguras de verificar se uma chave existe antes de utilizá-la.

### Notação de Ponto vs Notação de Colchetes

As duas notações acessam a mesma propriedade, mas só uma delas aceita nomes calculados em tempo de execução:

```js title="Acessando e alterando propriedades"
const host = {
  hostname: "web-server-01",
  ip: "192.168.1.10",
  "content-type": "application/json", // Chave com hífen precisa de aspas!
  200: "OK",                         // Chave numérica
};

// 1. Notação de Ponto (mais comum)
console.log(host.hostname); // "web-server-01"
console.log(host.ip);       // "192.168.1.10"

// 2. Notação de Colchetes (obrigatória para chaves com hífens, espaços ou números)
console.log(host["content-type"]); // "application/json"
console.log(host[200]);            // "OK"

// 3. Notação de Colchetes com Chaves Dinâmicas (variáveis)
const targetKey = "ip";
console.log(host[targetKey]); // "192.168.1.10" (equivale a host.ip)
```

### Adição, Alteração e Remoção

Objetos em JavaScript são mutáveis por padrão. Propriedades podem ser atribuídas ou removidas a qualquer momento.

O exemplo a seguir adiciona a propriedade `retries`, altera o valor de `timeout` e depois remove `retries` com o operador `delete`:

```js title="Alterando a estrutura de um objeto"
const config = {
  theme: "dark",
  timeout: 5000,
};

// Adicionando nova propriedade
config.retries = 3;

// Alterando valor de propriedade existente
config.timeout = 10000;

console.log(config); // { theme: 'dark', timeout: 10000, retries: 3 }

// Removendo propriedade com o operador delete
delete config.retries;
console.log(config); // { theme: 'dark', timeout: 10000 }
console.log(config.retries); // undefined
```

Essa mutabilidade convive com a palavra-chave `const`, gerando uma confusão frequente entre a reassociação de variáveis e a mutação de propriedades internas.

<Aside type="caution" title="Variáveis const e Mutabilidade de Objetos">
  Declarar um objeto com `const` impede que a variável seja reassociada a um novo objeto na memória. No entanto, as **propriedades internas** do objeto continuam mutáveis, podendo ser alteradas, adicionadas ou deletadas normalmente.

  ```js title="const impede a reassociação, não a mutação"
  const server = { port: 8080 };
  server.port = 9090; // PERMITIDO (altera propriedade interna)

  // server = { port: 3000 }; // ERRO: TypeError (Assignment to constant variable)
  ```
</Aside>

### Verificação de Existência de Propriedades (Operador `in` e `Object.hasOwn`)

Para verificar se uma propriedade existe em um objeto, o JavaScript disponibiliza o **operador `in`** e o método estático **`Object.hasOwn()`** (que substitui com mais segurança o antigo `hasOwnProperty()`).

- **Operador `in`**: Retorna `true` se a propriedade existir no objeto **ou em qualquer nível da sua cadeia de protótipos** (*prototype chain*).
- **`Object.hasOwn(obj, prop)`**: Retorna `true` **apenas se a propriedade for direta/própria** do objeto (*own property*), ignorando propriedades herdadas.

A diferença entre os dois só aparece no terceiro caso do exemplo a seguir, quando a propriedade consultada (`toString`) é herdada de `Object.prototype` em vez de declarada no objeto:

```js title="Diferença entre o operador in e Object.hasOwn()"
const user = { name: "Bruno", age: 25 };

// 1. Verificando propriedades diretas do objeto:
console.log("name" in user);               // true
console.log(Object.hasOwn(user, "name")); // true

// 2. Propriedade inexistente:
console.log("email" in user);              // false
console.log(Object.hasOwn(user, "email")); // false

// 3. Propriedades herdadas do protótipo (ex: toString de Object.prototype):
console.log("toString" in user);               // true (encontrado na cadeia de protótipos)
console.log(Object.hasOwn(user, "toString")); // false (não é propriedade direta)
```

### Natureza Dinâmica e Opcionalidade de Propriedades

No JavaScript, os objetos não seguem esquemas rígidos ou contratos de tipos em tempo de execução: todas as propriedades são intrinsecamente dinâmicas e opcionais.

Tentar ler uma chave que não existe em um objeto não dispara exceção, retornando silenciosamente o valor `undefined`. No entanto, é fundamental distinguir três estados diferentes:

1. **Propriedade inexistente**: a chave nunca foi definida no objeto (`!("nickname" in user)` é `true`).
2. **Propriedade definida com `undefined`**: a chave existe na estrutura do objeto, mas seu valor associado é `undefined` (`Object.hasOwn(user, "nickname")` é `true`).
3. **Propriedade removida com `delete`**: a chave é completamente expurgada do objeto em tempo de execução.

O exemplo a seguir ilustra a diferença prática entre esses estados:

```js title="Opcionalidade de chaves e valor undefined vs ausência real"
const account = {
  id: 101,
  username: "ana.dev",
  nickname: undefined, // Chave existe, mas com valor undefined
};

// 1. Ambas as leituras retornam undefined:
console.log(account.nickname); // undefined
console.log(account.avatar);   // undefined (propriedade inexistente)

// 2. Verificação de presença com Object.hasOwn revela a diferença:
console.log(Object.hasOwn(account, "nickname")); // true (a chave existe no objeto)
console.log(Object.hasOwn(account, "avatar"));   // false (a chave nunca foi criada)

// 3. Remoção com delete expurga a chave do objeto:
delete account.nickname;
console.log(Object.hasOwn(account, "nickname")); // false (agora a chave foi removida)
```

### Encadear Opcional (Optional Chaining: `?.`)

Ao acessar propriedades encadeadas em objetos aninhados, tentar ler um atributo de um valor `null` ou `undefined` causa um erro de execução (`TypeError`). O operador de **Encadear Opcional** (`?.`) permite acessar propriedades com segurança: caso o alvo seja `null` ou `undefined`, a expressão interrompe a avaliação (*short-circuiting*) e retorna `undefined` sem lançar exceções.

```js title="Acesso seguro com Optional Chaining"
const user = {
  id: 1,
  name: "Carlos",
  profile: {
    address: {
      city: "João Pessoa",
    },
  },
};

// ❌ Sem Optional Chaining: se 'settings' for undefined, o acesso gera TypeError
// const theme = user.settings.theme; // TypeError: Cannot read properties of undefined

// ✅ Com Optional Chaining (?.): retorna undefined de forma segura
const city = user?.profile?.address?.city;   // "João Pessoa"
const zipCode = user?.profile?.address?.zip;  // undefined (propriedade não existe)
const theme = user?.settings?.theme;          // undefined (objeto 'settings' não existe)

// 💡 Combinando com Coalescência Nula (??) para definir valor padrão
const userCity = user?.profile?.address?.city ?? "Cidade não cadastrada";
const userTheme = user?.settings?.theme ?? "light";
```

Antes da introdução do operador `?.` no ES2020, o código precisava recorrer a encadeamentos manuais com o operador lógico `&&`.

<Aside type="note" title="Padrão clássico pré-ES2020 (Operador Lógico &&)">
  Antes do ES2020, a forma idiomática de navegar em estruturas aninhadas utilizava o operador lógico `&&` para interromper a avaliação no primeiro valor falso (*falsy*). Embora funcional, essa abordagem tornava o código extenso e podia apresentar comportamentos inesperados diante de valores falsos válidos, como `0`, `""` ou `false`:

  ```js title="Comparação: Padrão clássico com && vs Optional Chaining"
  // 1. Padrão clássico com operador lógico && (verboso e repetitivo)
  const cityOld =
    user && user.profile && user.profile.address && user.profile.address.city;

  // 2. Padrão moderno com Optional Chaining (?.): conciso e seguro
  const cityModern = user?.profile?.address?.city;

  console.log(cityOld === cityModern); // true
  ```
</Aside>

## Desestruturação de Objetos (Destructuring)

A desestruturação de objetos permite extrair propriedades de um objeto e atribuí-las diretamente a variáveis locais com uma sintaxe concisa.

O recurso aparece em dois contextos principais no dia a dia: na criação de variáveis a partir de um objeto existente e na assinatura de funções que recebem objetos de opções.

### Extração Básica por Chaves

A forma básica declara entre chaves os nomes das propriedades que se deseja extrair. Diferente dos arrays, em que a desestruturação é posicional e depende da ordem dos elementos, nos objetos a correspondência ocorre exclusivamente pelo nome da propriedade. Isso significa que a ordem em que as variáveis são declaradas na desestruturação não precisa coincidir com a ordem em que foram definidas no objeto.

O exemplo a seguir demonstra a extração básica de propriedades a partir de um objeto de usuário:

```js title="Extração básica de propriedades"
const person = {
  firstName: "Maria",
  lastName: "Silva",
  age: 30,
  city: "João Pessoa",
};

// Extraindo propriedades por nome da chave (a ordem é irrelevante)
const { age, firstName } = person;
console.log(firstName); // "Maria"
console.log(age);       // 30
```

### Renomeação e Valores Padrão

Após dominar a extração simples, duas variações ampliam a flexibilidade do recurso: a sintaxe `chave: novoNome` permite renomear a variável local criada (evitando conflito de nomes no escopo) e `chave = valor` define um valor padrão quando a propriedade for inexistente ou `undefined`.

O exemplo a seguir aplica a renomeação e os valores padrão sobre o mesmo objeto:

```js title="Renomeação e valores padrão na desestruturação"
const person = {
  firstName: "Maria",
  city: "João Pessoa",
};

// Extraindo com renomeação de variáveis (chave: novoNome)
const { city: location } = person;
console.log(location); // "João Pessoa"

// Extraindo com valor padrão caso a propriedade não exista no objeto
const { role = "visitante" } = person;
console.log(role); // "visitante"
```

### Desestruturação em Parâmetros de Funções

A desestruturação é especialmente poderosa em parâmetros de funções, viabilizando o padrão de parâmetros nomeados (*named parameters*). Em vez de depender de uma ordem rígida de argumentos posicionais, a função recebe um único objeto de opções e declara na própria assinatura quais propriedades consome. Quem chama a função pode fornecer os argumentos em qualquer sequência, além de aproveitar valores padrão para propriedades opcionais.

A função a seguir recebe um objeto de configuração de servidor e extrai `hostname`, `ip` e `port` (com valor padrão `80`), independentemente da ordem em que foram enviados:

```js title="Desestruturação no parâmetro da função"
function displayServerInfo({ hostname, ip, port = 80 }) {
  console.log(`Servidor ${hostname} rodando em http://${ip}:${port}`);
}

const webServer = {
  ip: "10.0.0.15",
  port: 3000,
  hostname: "api-server",
};

// As propriedades são enviadas em qualquer ordem no objeto
displayServerInfo(webServer); // "Servidor api-server rodando em http://10.0.0.15:3000"
```

### Omissão Imutável de Propriedades com Rest (`...rest`)

Combinar a desestruturação com o operador rest (`...`) é o padrão idiomático para remover propriedades de um objeto de forma puramente imutável (sem utilizar o operador mutador `delete`). Esse padrão é amplamente utilizado em autenticação e APIs para expurgar senhas ou dados sensíveis antes de enviar o objeto:

```js title="Remoção imutável de propriedades sensíveis com Rest"
const userWithSensitiveData = {
  id: 101,
  name: "Carlos Silva",
  email: "carlos@devlab.org",
  passwordHash: "a8f5c1e9b2...",
  role: "admin",
};

// Extrai passwordHash isolando todo o restante no novo objeto publicUser
const { passwordHash: _password, ...publicUser } = userWithSensitiveData;

console.log(publicUser);
// { id: 101, name: 'Carlos Silva', email: 'carlos@devlab.org', role: 'admin' }
console.log("passwordHash" in publicUser); // false
```

## Operador Spread e Imutabilidade em Objetos

Atualizar um objeto sem modificar a instância original é uma prática essencial em JavaScript moderno, especialmente em interfaces reativas e em código que compara estados anteriores e atuais. Para trabalhar com imutabilidade de forma segura, é fundamental compreender a diferença entre atribuir referências e criar cópias reais.

### Comparação por Referência (Operadores == e ===)

Diferente dos valores primitivos (em que a atribuição e a comparação lidam com o valor diretamente), nos objetos o JavaScript opera exclusivamente por **endereço de memória** (a referência alocada na *Heap*). Esse modelo traz duas consequências práticas fundamentais:

1. **Atribuição não duplica o objeto**: Criar uma variável atribuindo um objeto existente copia apenas o ponteiro da memória. Ambas as variáveis passam a apontar para a mesma instância.
2. **Comparação avalia referências, não conteúdo**: Tanto a igualdade estrita (`===`) quanto a igualdade solta (`==`) comparam se dois operandos apontam para o exato mesmo endereço de memória na *Heap*. Duas instâncias com propriedades e valores idênticos continuam resultando em `false` porque foram alocadas em posições distintas.

O exemplo a seguir demonstra a atribuição de referências e o contraste na comparação de objetos com mesmo conteúdo:

```js title="Atribuição e comparação de objetos por referência"
// 1. Efeito colateral da atribuição por referência
const originalUser = { name: "Ana", role: "user" };
const aliasUser = originalUser; // Copia apenas o endereço de memória

aliasUser.role = "admin";
console.log(originalUser.role); // "admin" (originalUser foi afetado!)
console.log(originalUser === aliasUser); // true (apontam para o mesmo objeto na Heap)
console.log(originalUser == aliasUser);  // true (mesma referência)

// 2. Instâncias independentes com o mesmo conteúdo
const userA = { name: "Carlos", age: 28 };
const userB = { name: "Carlos", age: 28 };

console.log(userA === userB); // false (endereços de memória distintos)
console.log(userA == userB);  // false (endereços de memória distintos)
console.log({} === {});       // false (cada {} aloca uma nova referência na Heap)
```

O diagrama a seguir ilustra a representação na memória desses dois cenários, contrastando o apontamento para o mesmo endereço com a criação de instâncias independentes na *Heap*:

Como `userA` e `userB` ocupam posições diferentes na memória, `userA === userB` é avaliado como `false`, mesmo que suas chaves e valores sejam exatamente iguais.

### Comparação Profunda de Objetos (Deep Equality)

Para determinar se dois objetos independentes contêm exatamente as mesmas propriedades e valores em todos os níveis de profundidade, é necessário realizar uma **comparação profunda** (*deep equality*).

Uma abordagem tentada frequentemente por iniciantes é a conversão para string com `JSON.stringify(a) === JSON.stringify(b)`. No entanto, essa técnica é frágil e falha em cenários reais por três motivos:

1. **Ordem das chaves**: `{ a: 1, b: 2 }` e `{ b: 2, a: 1 }` geram strings JSON distintas, mesmo representando dados equivalentes.
2. **Perda e coerção de tipos**: valores como `undefined`, funções e símbolos são ignorados pelo JSON, enquanto `Date` vira string e `NaN` vira `null`.
3. **Referências circulares**: disparam exceções de execução (`TypeError`).

Para realizar uma comparação profunda real, percorrem-se recursivamente as chaves e os valores de cada objeto.

O exemplo a seguir implementa uma função recursiva de comparação profunda (`isDeepEqual`) e demonstra sua aplicação prática:

```js title="Implementação de comparação profunda (Deep Equality)"
function isDeepEqual(objA, objB) {
  // 1. Identidade de referência ou tipos primitivos iguais
  if (objA === objB) return true;

  // 2. Se um dos valores for nulo ou não for objeto, não são iguais
  if (
    typeof objA !== "object" ||
    objA === null ||
    typeof objB !== "object" ||
    objB === null
  ) {
    return false;
  }

  const keysA = Object.keys(objA);
  const keysB = Object.keys(objB);

  // 3. Devem ter a mesma quantidade de chaves
  if (keysA.length !== keysB.length) return false;

  // 4. Cada chave de A deve existir em B e possuir valor idêntico (recursivo)
  for (const key of keysA) {
    if (!Object.hasOwn(objB, key) || !isDeepEqual(objA[key], objB[key])) {
      return false;
    }
  }

  return true;
}

const itemA = { id: 1, config: { retries: 3, debug: true } };
const itemB = { id: 1, config: { retries: 3, debug: true } };
const itemC = { id: 1, config: { retries: 5, debug: true } };

console.log(itemA === itemB);           // false (referências diferentes)
console.log(isDeepEqual(itemA, itemB)); // true (conteúdo estrutural idêntico)
console.log(isDeepEqual(itemA, itemC)); // false (retries diverge: 3 vs 5)
```

Em projetos de back-end e suítes de testes automatizados (como Vitest, Jest ou Node.js nativo), essa verificação costuma ser executada por utilitários dedicados, como o módulo nativo `assert.deepStrictEqual()` de `node:assert` ou asserções `.toEqual()`.

Para evitar mutações acidentais ao criar novas variáveis, o JavaScript oferece técnicas de clonagem como o **operador spread** (para cópias rasas) e a função **`structuredClone()`** (para cópias profundas).

### Cópia Rasa e Mesclagem com Spread

O operador de espalhamento (`...`) resolve o problema da atribuição por referência ao gerar uma cópia rasa (*shallow copy*) das propriedades em um novo objeto na memória. Ele também permite mesclar múltiplos objetos e sobrescrever campos específicos de forma declarativa.

O exemplo a seguir percorre esse fluxo: `prodConfig` recebe todas as propriedades de `baseConfig` e sobrescreve `env` e `port`, mantendo o objeto original intacto:

```js title="Operador Spread em Objetos"
const baseConfig = {
  env: "development",
  debug: true,
  port: 3000,
};

// Criando uma cópia independente no primeiro nível e sobrescrevendo propriedades
const prodConfig = {
  ...baseConfig,
  env: "production",
  port: 8080,
};

console.log(baseConfig); // { env: 'development', debug: true, port: 3000 }
console.log(prodConfig); // { env: 'production', debug: true, port: 8080 }
console.log(baseConfig === prodConfig); // false (são objetos diferentes na memória)
```

O diagrama a seguir ilustra visualmente esse processo de mesclagem e criação de um novo objeto na memória:

No operador spread, a **ordem em que as propriedades são declaradas** define a precedência dos valores. Propriedades declaradas **após** o spread sobrescrevem os valores herdados do objeto base; propriedades declaradas **antes** do spread são sobrescritas pelos valores do objeto base:

```js title="Ordem de precedência no Spread de objetos"
const base = { name: "Tesouro Selic", value: 17476 };

// 1. Sobrescrita: a propriedade declarada após o spread tem precedência
const custom = { ...base, name: "CDB XYZ" };
console.log(custom); // { name: 'CDB XYZ', value: 17476 }

// 2. Precedência do spread: o objeto base sobrescreve a chave declarada antes
const overridden = { name: "CDB XYZ", ...base };
console.log(overridden); // { name: 'Tesouro Selic', value: 17476 }
```

### Cópia Rasa vs Cópia Profunda (structuredClone)

O operador spread realiza uma **cópia rasa** (*shallow copy*). Isso significa que apenas as propriedades do primeiro nível são duplicadas; quaisquer propriedades que contenham objetos, arrays ou funções aninhadas continuam compartilhando suas referências originais na *Heap*.

Quando é necessário clonar um objeto complexo com múltiplos níveis de aninhamento de forma 100% independente, utiliza-se a função nativa **`structuredClone()`** (disponível no Node.js 17+ e navegadores modernos).

O exemplo a seguir contrasta o problema da mutação acidental na cópia rasa com a clonagem profunda e isolada:

```js title="Cópia rasa com spread vs Cópia profunda com structuredClone"
const originalProfile = {
  name: "Beatriz",
  address: {
    city: "João Pessoa",
    state: "PB",
  },
};

// 1. Cópia Rasa com Spread: primeiro nível é novo, mas 'address' é compartilhado
const shallowCopy = { ...originalProfile };
shallowCopy.name = "Bruna";                 // Não afeta originalProfile.name
shallowCopy.address.city = "Campina Grande"; // AFETA originalProfile.address.city!

console.log(originalProfile.name);         // "Beatriz" (intacto)
console.log(originalProfile.address.city); // "Campina Grande" (mutado acidentalmente!)

// 2. Cópia Profunda com structuredClone(): duplica todos os níveis recursivamente
const deepCopy = structuredClone(originalProfile);
deepCopy.address.city = "Cabedelo";

console.log(originalProfile.address.city); // "Campina Grande" (intacto!)
console.log(deepCopy.address.city);        // "Cabedelo" (100% independente)
```

## Recursos Estáticos de `Object`

Depois de entender que objetos são referências mutáveis na memória, faz sentido agrupar a API estática de `Object` pelo papel que ela exerce no código: alguns métodos inspecionam propriedades, outros transformam pares chave-valor, outros controlam mutabilidade e alguns permitem manipular protótipos ou descritores.

Esses métodos são chamados diretamente em `Object`, sem instanciar nada com `new`. Eles não substituem a notação literal, o spread ou a desestruturação; eles complementam essas sintaxes quando o código precisa tratar um objeto como uma estrutura de dados.

### Inspeção e Iteração

Diferente de arrays, objetos comuns não são diretamente iteráveis com `for...of`. Para percorrer chaves, valores ou pares, usa-se o laço `for...in` ou os métodos estáticos de enumeração.

A tabela a seguir compara as opções mais comuns de inspeção e iteração:

| Método / Estrutura | Retorno | Uso principal |
| ------------------ | ------- | ------------- |
| `for...in` | Chaves (`string`) | Percorrer chaves enumeráveis, incluindo herdadas |
| `Object.hasOwn(obj, prop)` | `boolean` | Confirmar se uma chave pertence diretamente ao objeto |
| `Object.keys(obj)` | `Array<string>` | Obter uma lista com as chaves próprias enumeráveis |
| `Object.values(obj)` | `Array<any>` | Obter uma lista com os valores das propriedades |
| `Object.entries(obj)` | `Array<[string, any]>` | Obter pares `[chave, valor]` para usar com `for...of`, `map` ou `filter` |

O exemplo a seguir aplica os métodos estáticos sobre o mesmo objeto de notas e termina iterando com `for...of` sobre os pares devolvidos por `Object.entries()`:

```js title="Inspeção e iteração com métodos estáticos de Object"
const scores = {
  Alice: 95,
  Bruno: 80,
  Carla: 90,
};

console.log(Object.hasOwn(scores, "Bruno")); // true
console.log(Object.keys(scores));            // [ 'Alice', 'Bruno', 'Carla' ]
console.log(Object.values(scores));          // [ 95, 80, 90 ]
console.log(Object.entries(scores));
// [ [ 'Alice', 95 ], [ 'Bruno', 80 ], [ 'Carla', 90 ] ]

for (const [student, score] of Object.entries(scores)) {
  console.log(`Estudante: ${student} | Nota: ${score}`);
}
```

### Transformação e Mesclagem

Quando o objetivo é transformar a estrutura de um objeto, `Object.entries()` costuma aparecer em conjunto com `Object.fromEntries()`. O primeiro converte o objeto em uma lista de pares; o segundo reconstrói um objeto a partir dessa lista.

A tabela a seguir resume os métodos mais úteis para transformação e mesclagem:

| Método | Retorno | Uso principal |
| ------ | ------- | ------------- |
| `Object.entries(obj)` | `Array<[string, any]>` | Converter um objeto em pares manipuláveis por métodos de array |
| `Object.fromEntries(entries)` | `object` | Reconstruir um objeto a partir de pares `[chave, valor]` |
| `Object.assign(target, ...sources)` | `object` | Copiar propriedades de objetos de origem para um objeto alvo |

O exemplo a seguir remove configurações desativadas e cria um novo objeto somente com as entradas habilitadas:

```js title="Transformação com Object.entries() e Object.fromEntries()"
const featureFlags = {
  dashboard: true,
  legacyReport: false,
  notifications: true,
};

const enabledFlags = Object.fromEntries(
  Object.entries(featureFlags).filter(([_key, enabled]) => enabled)
);

console.log(enabledFlags);
// { dashboard: true, notifications: true }
```

`Object.assign()` também copia propriedades, mas modifica o primeiro argumento recebido. Por isso, em código moderno, o spread costuma ser mais legível para criar novos objetos, enquanto `Object.assign()` aparece com mais frequência em bases legadas, bibliotecas e situações em que o alvo mutável é intencional.

O exemplo a seguir mostra a diferença prática entre mesclar em um objeto novo e mesclar dentro do próprio alvo:

```js title="Mesclagem com spread e Object.assign()"
const defaults = { retries: 3, timeout: 1000 };
const overrides = { timeout: 5000 };

const immutableOptions = { ...defaults, ...overrides };
const mutableOptions = Object.assign(defaults, overrides);

console.log(immutableOptions); // { retries: 3, timeout: 5000 }
console.log(mutableOptions);   // { retries: 3, timeout: 5000 }
console.log(defaults.timeout); // 5000 (defaults foi alterado por Object.assign)
```

### Protótipos e Descritores

Alguns recursos de `Object` são menos frequentes no código de aplicação, mas explicam como a linguagem representa objetos por baixo da sintaxe de classes e literais. Eles aparecem em bibliotecas, ferramentas, *frameworks* e cenários em que é preciso controlar herança, enumeração ou escrita de propriedades.

A tabela a seguir resume os métodos mais importantes desse grupo:

| Método | Retorno | Uso principal |
| ------ | ------- | ------------- |
| `Object.create(proto)` | `object` | Criar um objeto usando um protótipo específico |
| `Object.getPrototypeOf(obj)` | `object \| null` | Ler o protótipo efetivo de um objeto |
| `Object.defineProperty(obj, prop, descriptor)` | `object` | Definir uma propriedade com controle de escrita, enumeração e configuração |

O exemplo a seguir cria um objeto a partir de um protótipo explícito e define uma propriedade não enumerável, ou seja, que existe no objeto, mas não aparece em `Object.keys()`:

```js title="Protótipo explícito e descritor de propriedade"
const accountPrototype = {
  describe() {
    return `${this.owner}: R$ ${this.balance}`;
  },
};

const account = Object.create(accountPrototype);
account.owner = "Ana";
account.balance = 500;

Object.defineProperty(account, "internalId", {
  value: "acct-001",
  enumerable: false,
});

console.log(account.describe()); // "Ana: R$ 500"
console.log(Object.getPrototypeOf(account) === accountPrototype); // true
console.log(Object.keys(account)); // [ 'owner', 'balance' ]
console.log(Object.hasOwn(account, "internalId")); // true
```

### Controle de Mutabilidade e Comparação

Nem todo objeto deve permanecer aberto para mudanças. Configurações, tabelas de constantes e objetos compartilhados entre módulos frequentemente precisam de algum nível de proteção contra alteração acidental.

A tabela a seguir organiza os recursos mais comuns de controle e comparação:

| Método | Efeito | Observação |
| ------ | ------ | ---------- |
| `Object.freeze(obj)` | Bloqueia alteração, inclusão e exclusão de propriedades | Congelamento raso (*shallow freeze*) |
| `Object.seal(obj)` | Permite alterar valores existentes, mas bloqueia inclusão e exclusão | Útil quando a forma do objeto deve ser fixa |
| `Object.is(a, b)` | Compara dois valores com semântica semelhante a `===` | Diferencia `+0` e `-0`, e considera `NaN` igual a `NaN` |

O exemplo a seguir congela um objeto de configuração e demonstra que tanto a alteração de `version` quanto a adição de `timeout` são descartadas:

```js title="Imutabilidade com Object.freeze()"
const immutableConfig = Object.freeze({
  apiUrl: "https://api.devlab.org",
  version: "v1",
});

// Tentativa de alteração é ignorada em modo padrão (ou lança erro em strict mode)
immutableConfig.version = "v2";
immutableConfig.timeout = 5000;

console.log(immutableConfig); // { apiUrl: 'https://api.devlab.org', version: 'v1' }
```

O congelamento também é raso: objetos aninhados dentro de um objeto congelado continuam mutáveis e precisam ser congelados individualmente.

## Classes em JavaScript (ES6+ e POO)

Introduzidas no ES2015 (ES6), as **Classes** oferecem uma sintaxe moderna baseada em protótipos (*prototype-based inheritance*) mais limpa e alinhada com os conceitos da Programação Orientada a Objetos (POO).

A tabela a seguir resume os tipos de membro que uma classe pode declarar, todos detalhados nas subseções seguintes:

| Membro | Sintaxe | Pertence a | Acesso |
| ------ | ------- | ---------- | ------ |
| **Construtor** | `constructor(name) { }` | à instância, executado pelo `new` | `new User("Ana")` |
| **Método de instância** | `getProfile() { }` | ao protótipo (`User.prototype`) | `user1.getProfile()` |
| **Campo privado** | `#balance = 0` | à instância, visível só dentro da classe | `this.#balance` |
| **Getter / Setter** | `get balance() { }` | à instância, com leitura controlada | `account.balance` |
| **Membro estático** | `static PI = 3.14159` | à própria classe | `MathUtils.PI` |

### Declaração de Classes e o Construtor

Uma classe é declarada com a palavra-chave `class`. O método especial `constructor()` é executado automaticamente quando um novo objeto é instanciado com o operador `new`.

A classe a seguir define duas propriedades de instância no construtor e um método compartilhado por todas as instâncias:

```js title="Declaração básica de uma Classe"
class User {
  constructor(name, email) {
    this.name = name;
    this.email = email;
  }

  // Método de instância (armazenado no User.prototype)
  getProfile() {
    return `${this.name} (${this.email})`;
  }
}

const user1 = new User("Ana Silva", "ana@devlab.org");
console.log(user1.getProfile()); // "Ana Silva (ana@devlab.org)"
```

### Mapeamento entre Classes e a Cadeia de Protótipos

No JavaScript, a instrução `class` é apenas um **açúcar sintático** (*syntactic sugar*) construído sobre a cadeia de protótipos (`prototype chain`).

O diagrama a seguir ilustra a estrutura de memória de uma instância criada via `class` e sua vinculação com `User.prototype` e `Object.prototype`:

### Métodos Fundamentais de Object.prototype

Como `Object.prototype` fica no topo da cadeia de quase todos os objetos em JavaScript, os métodos nele definidos são herdados automaticamente por todas as instâncias e objetos literais.

A tabela a seguir detalha os principais métodos herdados de `Object.prototype`, seu papel e quando são acionados pelo motor JavaScript:

| Método | Retorno | Finalidade e Contexto de Execução |
| ------ | ------- | --------------------------------- |
| `toString()` | `string` | Retorna a representação textual do objeto (padrão `"[object Object]"`). É acionado automaticamente em interpolações de strings (`${obj}`) e conversões com `String(obj)`. |
| `valueOf()` | `any` | Retorna o valor primitivo do objeto. É chamado automaticamente em operações aritméticas (`obj + 10`) e comparações relacionais. |
| `hasOwnProperty(prop)` | `boolean` | Método legado para checar se a propriedade pertence diretamente ao objeto. Substituído pelo método estático mais seguro `Object.hasOwn(obj, prop)`. |
| `isPrototypeOf(obj)` | `boolean` | Verifica se o objeto atual existe em algum nível da cadeia de protótipos do objeto informado. |
| `propertyIsEnumerable(prop)` | `boolean` | Indica se uma propriedade direta é enumerável em laços `for...in` e no array de `Object.keys()`. |
| `toLocaleString()` | `string` | Versão sensível à localidade de `toString()`, frequentemente especializada em instâncias de `Date` e `Number`. |

Esses métodos podem ser sobrescritos nos seus próprios objetos para personalizar comportamentos de conversão e formatação.

O exemplo a seguir demonstra a personalização de `toString()` e `valueOf()` e como eles respondem a coerções implícitas:

```js title="Comportamento e sobrescrita de métodos do Object.prototype"
const product = {
  name: "Monitor Gamer",
  price: 1500,

  // Sobrescrevendo a representação textual
  toString() {
    return `${this.name} - R$ ${this.price}`;
  },

  // Sobrescrevendo a coerção para valor primitivo/numérico
  valueOf() {
    return this.price;
  },
};

// 1. Interpolação e coerção textual invocam toString()
console.log(`Produto: ${product}`); // "Produto: Monitor Gamer - R$ 1500"
console.log(String(product));        // "Monitor Gamer - R$ 1500"

// 2. Operações matemáticas invocam valueOf()
console.log(product + 200);          // 1700
console.log(product * 0.9);          // 1350 (desconto de 10%)
```

### Extensão de Protótipos e Cuidados com o `this`

É possível estender protótipos de construtores nativos ou personalizados adicionando novos métodos compartilhados. No entanto, métodos adicionados a protótipos **devem utilizar funções tradicionais (`function`)** para que a palavra-chave `this` seja vinculada dinamicamente à instância chamadora. Arrow functions capturam o `this` do escopo léxico externo e não funcionam como métodos de protótipo:

```js title="Extensão de protótipo e vinculação de this"
// ✅ Função tradicional: 'this' aponta dinamicamente para a instância chamadora
Array.prototype.last = function () {
  return this[this.length - 1];
};

const numbers = [10, 20, 30];
console.log(numbers.last()); // 30

// ❌ Arrow function: captura o 'this' léxico externo (undefined/globalThis), falhando no protótipo
// Array.prototype.lastArrow = () => this[this.length - 1]; // TypeError ou undefined
```

### Encapsulamento com Atributos Privados (`#`) e Getters/Setters

No ES2022, o JavaScript introduziu os **campos privados** prefixados com `#`. Atributos e métodos privados não podem ser acessados diretamente de fora da classe, garantindo encapsulamento no tempo de execução.

A classe a seguir mantém o saldo em um campo privado e expõe apenas um getter de leitura e um método de depósito que valida o valor recebido:

```js title="Atributos privados e métodos de acesso get/set"
class BankAccount {
  owner;
  // Atributo privado (ES2022+) - inacessível fora da classe
  #balance = 0;

  constructor(owner, initialBalance) {
    this.owner = owner;
    this.#balance = initialBalance;
  }

  // Getter para leitura controlada
  get balance() {
    return this.#balance;
  }

  // Método público que altera o estado privado com validação
  deposit(amount) {
    if (amount <= 0) {
      throw new Error("O valor do depósito deve ser positivo.");
    }
    this.#balance += amount;
  }
}

const account = new BankAccount("Carlos", 500);
account.deposit(200);
console.log(account.balance); // 700

// ❌ Tentativa de acesso direto gera erro de sintaxe:
// console.log(account.#balance); // SyntaxError: Private field '#balance' must be declared in an enclosing class
```

<Aside type="note" title="Pilar da POO: Encapsulamento">
  O encapsulamento visa proteger o estado interno do objeto contra modificações diretas e indevidas, expondo apenas interfaces públicas controladas. No JavaScript moderno (ES2022+), isso é garantido nativamente no tempo de execução pelos campos privados prefixados com `#`, complementados por métodos de acesso *get/set* que validam leituras e escritas.
</Aside>

### Herança de Classes com `extends` e `super`

Uma classe pode herdar propriedades e métodos de outra classe utilizando a palavra-chave `extends`. No construtor da subclasse, a função `super()` deve ser obrigatoriamente chamada antes de utilizar a referência `this`.

O diagrama a seguir ilustra a relação de herança entre a classe base `User` e a subclasse `Admin`:

        +String email
        +getProfile() String
    }

        +getProfile() String

<Aside type="tip" title="Como Ler um Diagrama de Classes (UML)">
  Em diagramas de classes da UML (Linguagem de Modelagem Unificada):

  - **Estrutura da caixa**: Cada retângulo representa uma classe e é dividido em três seções: o **nome da classe** no topo, os **atributos (propriedades)** no meio e os **métodos (comportamentos)** na base.
  - **Símbolos de visibilidade**: O prefixo `+` indica membro **público** (acessível externamente) e `-` indica membro **privado** (no JavaScript moderno, equivalente aos atributos com `#`).
  - **Tipagem de dados e retornos**: Os tipos indicam a natureza do dado esperado em um atributo (ex: `+String name` armazena texto; `+Array permissions` armazena uma lista) ou o tipo do valor devolvido por um método (ex: `+getProfile() String` retorna uma string).
  - **Seta de herança (`<|--`)**: O triângulo oco apontando para a classe base (`User`) indica uma relação de **generalização/herança** (`Admin extends User`), mostrando que `Admin` herda a estrutura e os métodos de `User`.
</Aside>

A implementação a seguir exemplifica esse diagrama: define a classe base `User` e a subclasse `Admin`, utilizando `super()` para reaproveitar o construtor pai e sobrescrevendo `getProfile()`:

```js title="Herança com extends e invocação de super()"
// Classe base
class User {
  constructor(name, email) {
    this.name = name;
    this.email = email;
  }

  getProfile() {
    return `${this.name} (${this.email})`;
  }
}

// Subclasse que herda de User
class Admin extends User {
  constructor(name, email, permissions) {
    // Chama o construtor da classe pai (User)
    super(name, email);
    this.permissions = permissions;
  }

  // Sobrescrita de método (Method Overriding)
  getProfile() {
    return `[ADMIN] ${super.getProfile()} - Permissões: ${this.permissions.join(", ")}`;
  }
}

const admin = new Admin("Beatriz", "beatriz@devlab.org", ["CREATE", "DELETE"]);
console.log(admin.getProfile());
// "[ADMIN] Beatriz (beatriz@devlab.org) - Permissões: CREATE, DELETE"
```

<Aside type="note" title="Pilar da POO: Polimorfismo">
  O polimorfismo permite que diferentes classes derivadas respondam à mesma chamada de método (como `greet()` ou `getProfile()`) executando lógicas específicas de cada subclasse. Em JavaScript, o polimorfismo é viabilizado principalmente pela herança e sobrescrita de métodos com `extends` e `super()`, permitindo tratar diferentes objetos especializados por meio de uma interface comum.
</Aside>

### Sobrescrita de Métodos vs Ausência de Sobrecarga

Ao trabalhar com orientação a objetos, é fundamental distinguir dois conceitos frequentemente confundidos:

- **Sobrescrita (*Method Overriding*)**: Uma subclasse redefine a implementação de um método herdado da classe pai para especializar seu comportamento. O JavaScript suporta sobrescrita plenamente, permitindo inclusive reaproveitar a lógica base com `super.metodo()`.
- **Sobrecarga (*Method Overloading*)**: Uma mesma classe declara múltiplos métodos com o mesmo nome e parâmetros diferentes. **O JavaScript não suporta sobrecarga de métodos nativamente por assinatura**.

Se dois métodos com o mesmo nome forem declarados na mesma classe, a última declaração substitui a anterior por completo. Para oferecer assinaturas flexíveis em JavaScript, utilizam-se parâmetros com valores padrão ou objetos de opções.

O exemplo a seguir contrasta a sobrescrita com a tentativa de sobrecarga e sua solução idiomática:

```js title="Sobrescrita (suportada) vs Ausência de Sobrecarga"
// 1. Sobrescrita (Overriding): classe filha redefine o método da classe pai
class User {
  greet() {
    return "Olá!";
  }
}

class Admin extends User {
  greet() {
    return `${super.greet()} Eu sou um administrador.`;
  }
}

const admin = new Admin();
console.log(admin.greet()); // "Olá! Eu sou um administrador."

// 2. Sobrecarga (Overloading): a última declaração apaga a anterior
class Calculator {
  // ❌ add(a) é descartado: a definição add(a, b) abaixo sobrescreve esta
  add(a) {
    return a + 10;
  }

  add(a, b) {
    return a + b;
  }

  // ✅ Forma idiomática em JS: parâmetros com valor padrão
  sum(a, b = 10) {
    return a + b;
  }
}

const calc = new Calculator();
console.log(calc.add(5));     // NaN (a + undefined, pois o 2º add prevaleceu)
console.log(calc.add(5, 20)); // 25
console.log(calc.sum(5));     // 15 (usa o valor padrão b = 10)
console.log(calc.sum(5, 20)); // 25
```

<Aside type="tip" title="POO Avançada: O que o TypeScript adiciona?">
  Embora o JavaScript moderno ofereça as estruturas fundamentais de classes, o **TypeScript** expande significativamente o ecossistema de Orientação a Objetos com recursos estáticos de tempo de compilação:

  - **Interfaces e Contratos (`interface` / `implements`)**: Permite definir contratos explícitos que classes devem implementar, fortalecendo o polimorfismo baseado em interfaces.
  - **Classes e Métodos Abstratos (`abstract class`)**: Permite criar classes base estruturais que não podem ser instanciadas diretamente, apenas estendidas.
  - **Modificadores de Acesso Estáticos (`public`, `private`, `protected`, `readonly`)**: Oferece controle de visibilidade em tempo de compilação sem depender exclusivamente da sintaxe `#`.
  - **Parameter Properties**: Cria e inicializa propriedades diretamente na assinatura do construtor (`constructor(public name: string, private role: string) {}`).
  - **Assinaturas de Sobrecarga (*Method Overloading*)**: Permite declarar múltiplas assinaturas de tipos para uma mesma função ou método, viabilizando checagem estática precisa de argumentos antes da execução.
</Aside>

### Métodos e Campos Estáticos (`static`)

Métodos e propriedades marcados com a palavra-chave `static` pertencem à **própria classe**, e não às instâncias criadas a partir dela. Por isso, são acessados diretamente pelo nome da classe, sem `new`, o que os torna adequados para funções utilitárias e constantes de domínio.

A classe utilitária a seguir declara uma constante e um método de cálculo, ambos estáticos:

```js title="Uso de métodos e atributos estáticos"
class MathUtils {
  static PI = 3.14159;

  static calculateCircleArea(radius) {
    return this.PI * radius * radius;
  }
}

console.log(MathUtils.PI); // 3.14159
console.log(MathUtils.calculateCircleArea(5)); // 78.53975
```

## JSON (JavaScript Object Notation)

**JSON** (*JavaScript Object Notation*) é um formato leve e estritamente textual para troca de dados entre sistemas (por exemplo, no envio e recebimento de dados em APIs REST).

Como tudo que trafega em rede é texto, trabalhar com JSON envolve duas frentes: conhecer as regras do formato e utilizar o objeto global `JSON` para converter dados entre memória e texto.

### O Formato JSON e suas Regras

Apesar de derivar da sintaxe de objetos do JavaScript, o formato JSON possui **regras estritas**, resumidas na tabela a seguir:

| Característica | Objeto JavaScript | Formato JSON |
| -------------- | ----------------- | ------------ |
| **Nomes de Chaves** | Podem ser sem aspas (`name: "Ana"`) | **Devem** estar entre aspas duplas (`"name": "Ana"`) |
| **Strings** | Aspas simples, duplas ou crases | **Devem** usar apenas aspas duplas (`"..."`) |
| **Tipos de Dados Aceitos** | Primitivos, arrays, objetos e **funções** | Apenas primitivos (número, string, boolean, null), arrays e objetos |
| **Vírgula Final (Trailing Comma)** | Permitida (`{ a: 1, }`) | **Proibida** (`{ "a": 1 }`) |

O trecho a seguir respeita todas essas regras e representa um servidor com valores primitivos, um array e um objeto aninhado:

```json title="Exemplo de arquivo ou payload JSON válido"
{
  "id": 101,
  "name": "Servidor Principal",
  "active": true,
  "tags": ["web", "production"],
  "specs": {
    "cpu": 4,
    "ram": "16GB"
  }
}
```

### O Objeto Global JSON (stringify e parse)

Em JavaScript, o objeto global `JSON` oferece dois métodos essenciais para converter dados entre o objeto em memória e o texto que trafega na rede:

- `JSON.stringify(obj)`: Converte um objeto/valor JavaScript em uma **string no formato JSON**.
- `JSON.parse(jsonString)`: Converte uma **string JSON** em um **objeto/valor JavaScript**.

O fluxo a seguir ilustra a conversão bidirecional entre dados em memória e representação textual para transmissão:

<Mermaid title="Ciclo de Serialização e Deserialização com o Objeto Global JSON">
{`
flowchart TD
  subgraph Memory["Aplicação JavaScript (memória Heap)"]
    A["Objeto JavaScript<br/>id: 1, name: 'Carlos'"]
  end

  subgraph Format["Texto trafegado na rede (JSON)"]
    B["String no formato JSON<br/>id: 1, name: Carlos"]
  end

  A -->|"JSON.stringify(obj)<br/>serialização"| B
  B -->|"JSON.parse(jsonString)<br/>desserialização"| A
`}
</Mermaid>

O exemplo a seguir percorre o ciclo completo, serializando um objeto de usuário e desserializando a string resultante de volta para um objeto:

```js title="Uso de JSON.stringify() e JSON.parse()"
const userObject = {
  id: 1,
  name: "Carlos",
  email: "carlos@gmail.com",
};

// 1. Serialização (Objeto JS -> String JSON)
const jsonString = JSON.stringify(userObject);
console.log(typeof jsonString); // "string"
console.log(jsonString);        // '{"id":1,"name":"Carlos","email":"carlos@gmail.com"}'

// 2. Deserialização (String JSON -> Objeto JS)
const parsedObject = JSON.parse(jsonString);
console.log(typeof parsedObject); // "object"
console.log(parsedObject.name);   // "Carlos"
```

Por padrão, o `JSON.stringify()` gera uma string compacta em linha única, o que economiza bytes no tráfego de rede. Para fins de inspeção visual, logs ou depuração (*debugging*), o método aceita um terceiro parâmetro (`space`) que define o recuo de indentação:

```js title="Formatação legível para depuração (Pretty-print com indentação 2)"
const user = {
  id: 1,
  name: "Carlos",
  roles: ["admin", "editor"],
};

// Saída compacta (padrão para tráfego na rede)
console.log(JSON.stringify(user));
// '{"id":1,"name":"Carlos","roles":["admin","editor"]}'

// Saída formatada com 2 espaços de recuo (ideal para depuração no terminal)
console.log(JSON.stringify(user, null, 2));
/*
{
  "id": 1,
  "name": "Carlos",
  "roles": [
    "admin",
    "editor"
  ]
}
*/
```

### Restrições de Tipos e Incompatibilidades na Serialização

Nem todas as estruturas e tipos de dados do JavaScript possuem representação direta no padrão JSON. Durante a conversão com `JSON.stringify()`, certos valores são transformados, omitidos ou provocam erros de execução:

- **Instâncias de `Date`**: São convertidas para strings no formato ISO 8601 (como `"2026-09-02T15:00:00.000Z"`). Ao desserializar com `JSON.parse()`, o valor permanece como string e não retorna automaticamente para um objeto `Date`.
- **`undefined`, funções e `Symbol`**: Em propriedades de objetos, esses campos são simplesmente omitidos do texto gerado. Em arrays, são convertidos para `null` para preservar os índices dos demais elementos.
- **`NaN`, `Infinity` e `-Infinity`**: Como o formato JSON aceita apenas números decimais finitos, esses valores especiais são convertidos para `null`.
- **`BigInt`**: Lança um erro de execução (`TypeError: Do not know how to serialize a BigInt`), exigindo conversão manual para string ou número antes da serialização.
- **Coleções (`Map`, `Set`) e expressões (`RegExp`)**: Não possuem representação em JSON e são convertidas em objetos vazios (`{}`).
- **Referências Circulares**: Objetos que contêm propriedades referenciando a si mesmos provocam um erro de execução (`TypeError: Converting circular structure to JSON`).

O exemplo a seguir demonstra na prática como o `JSON.stringify()` lida com esses diferentes tipos de dados:

```js title="Comportamento de tipos incompatíveis na serialização JSON"
const data = {
  createdAt: new Date(),        // Vira string ISO 8601
  score: NaN,                   // Vira null
  extra: undefined,             // Omitido no objeto
  greet() { return "Olá"; },    // Omitido no objeto
  items: [undefined, 10, NaN],  // Vira [null, 10, null] dentro de array
};

const json = JSON.stringify(data);
console.log(json);
// '{"createdAt":"2026-09-02T15:00:00.000Z","score":null,"items":[null,10,null]}'

// Desserialização: datas continuam como string
const parsed = JSON.parse(json);
console.log(typeof parsed.createdAt); // "string" (requer new Date(parsed.createdAt))
```

## Objetos na Era da Inteligência Artificial

Assistentes de código produzem estruturas de objeto, cópias e mesclagens com uma frase de pedido, e o trabalho passou de **escrever a manipulação** para **definir a profundidade da cópia e verificar o que sobreviveu a ela**.

Objetos são o ponto do JavaScript em que uma sugestão plausível erra sem avisar: o *spread* copia apenas o primeiro nível, `Object.freeze()` congela apenas o primeiro nível e `JSON.parse(JSON.stringify(obj))` descarta silenciosamente tudo o que não tem representação em JSON. Nenhum desses três problemas aparece no `console.log()` do exemplo feliz.

O diagrama mostra o que uma cópia rasa realmente produz: dois objetos independentes no primeiro nível, apontando para o **mesmo** objeto aninhado.

  B["cópia com spread<br/>{ user, settings }"] --> N

As duas primeiras caixas compartilham o objeto `settings`, e por isso alterar `copia.settings.theme` muda também o original. Só a terceira, produzida por `structuredClone()`, tem um objeto aninhado próprio.

| :--- | :--- |
| Lembrar a sintaxe de desestruturação com alias, padrão e aninhamento. | Definir o formato do objeto e quais campos são obrigatórios. |
| Escrever a transformação com `Object.entries()`, `map()` e `fromEntries()`. | Decidir se a operação precisa de cópia rasa, cópia profunda ou referência. |
| Explicar protótipo, `this` e a diferença entre método e função solta. | Julgar se o dado merece uma classe, um objeto literal ou um `Map`. |
| Sugerir validações de presença de propriedade. | Avaliar o risco de mesclar chaves vindas do corpo de uma requisição. |

### Descreva a estrutura, não a operação

Pedir "mescle as configurações" descreve uma ação e devolve um `Object.assign()` sobre o primeiro nível. O que muda a resposta é descrever **o objeto**: quantos níveis ele tem, que tipos moram em cada campo e de onde vêm as chaves.

Os elementos abaixo são os que o modelo não consegue adivinhar a partir do verbo:

| Elemento do prompt | Por que importa |
| :--- | :--- |
| **O objeto de exemplo colado por inteiro** | O aninhamento visível é o que decide entre cópia rasa e cópia profunda. |
| **Tipos não triviais presentes** (`Date`, `Map`, `undefined`) | Elimina a sugestão de `JSON.parse(JSON.stringify(...))`, que descarta os três. |
| **Quem é dono do objeto** (constante do módulo ou dado da requisição) | Define se alterar a entrada é aceitável ou é defeito. |
| **Origem das chaves** (escritas no código ou digitadas por alguém) | Determina se é preciso bloquear `__proto__` e `constructor`. |
| **O que fazer com chave ausente** | Decide entre manter o padrão, omitir a chave ou lançar erro. |

O prompt a seguir descreve a estrutura de preferências de usuário antes de pedir qualquer código:

```txt title="Prompt que descreve o objeto antes da operação"

- chaves aninhadas devem ser combinadas, não substituídas por inteiro;
```

### Verificação: mexa na cópia e olhe para o original

Toda revisão de código que copia objeto tem o mesmo movimento: altere um campo **aninhado** do resultado e vá conferir o objeto de origem. É esse passo que separa uma cópia de verdade de uma cópia aparente, e é exatamente o passo que um `console.log()` do caso feliz não faz.

No arquivo abaixo, o executor de testes nativo do Node.js cobre a combinação aninhada, a preservação dos objetos de entrada, a sobrevivência do campo `Date` e o bloqueio de chaves de protótipo:

```js title="preferences.test.js"
import { test } from "node:test";
import assert from "node:assert/strict";
import { mergePreferences } from "./preferences.js";

const defaults = { theme: "light", notifications: { email: true, push: false } };

test("mescla chaves aninhadas sem descartar as ausentes", () => {
  const result = mergePreferences(defaults, { notifications: { push: true } });
  assert.deepEqual(result.notifications, { email: true, push: true });
});

test("não altera os objetos recebidos", () => {
  mergePreferences(defaults, { theme: "dark" });
  assert.equal(defaults.theme, "light");
});

test("preserva o campo Date em vez de convertê-lo em texto", () => {
  const withDate = { ...defaults, updatedAt: new Date("2026-01-10T12:00:00Z") };
  assert.ok(mergePreferences(withDate, { theme: "dark" }).updatedAt instanceof Date);
});

test("ignora chaves de protótipo vindas de entrada externa", () => {
  const hostile = JSON.parse('{ "__proto__": { "isAdmin": true } }');
```

```js title="preferences.js (versão corrigida)"
const BLOCKED_KEYS = ["__proto__", "constructor", "prototype"];

const isPlainObject = (value) =>
  typeof value === "object" && value !== null && !Array.isArray(value);

export function mergePreferences(defaults, overrides) {
  const result = { ...defaults };

  for (const [key, value] of Object.entries(overrides)) {
    if (BLOCKED_KEYS.includes(key)) continue;

    result[key] = isPlainObject(value) && isPlainObject(defaults[key])
      ? mergePreferences(defaults[key], value)
      : value;
  }

  return result;
}
```

### Auditoria de objetos herdados: peça a explicação, não só o código

O ganho mais imediato da IA em objetos não é gerar, é **explicar**. Antes de alterar uma transformação herdada que funciona mas ninguém da equipe consegue ler, peça a decomposição trecho a trecho:

```js title="Transformação herdada, correta porém ilegível"
const normalize = (o) =>
  Object.fromEntries(
    Object.entries(o).filter(([, v]) => v != null).map(([k, v]) => [k.toLowerCase(), v]),
  );

console.log(normalize({ Name: "Ana", Email: null, CITY: "João Pessoa" }));
// { name: 'Ana', city: 'João Pessoa' }
```

A decomposição traduz cada trecho em uma regra de negócio nomeada:

| Trecho | Significado | Regra de negócio |
| :--- | :--- | :--- |
| `Object.entries(o)` | Converte o objeto em um array de pares `[chave, valor]`. | Permite tratar propriedades como uma lista. |
| `.filter(([, v]) => v != null)` | Descarta pares cujo valor é `null` ou `undefined`. | Campos não preenchidos não entram no registro. |
| `.map(([k, v]) => [k.toLowerCase(), v])` | Reescreve cada chave em minúsculas. | Padroniza nomes vindos de fontes diferentes. |
| `Object.fromEntries(...)` | Reconstrói o objeto a partir dos pares. | Devolve o mesmo formato de entrada, já normalizado. |

A versão reescrita preserva o comportamento e nomeia cada etapa, o que permite testar as regras isoladamente:

```js title="normalize.js"
const isFilled = ([, value]) => value !== null && value !== undefined;
const toLowerKey = ([key, value]) => [key.toLowerCase(), value];

export function normalizeRecord(record) {
  const filled = Object.entries(record).filter(isFilled);

  return Object.fromEntries(filled.map(toLowerKey));
}

console.log(normalizeRecord({ Name: "Ana", Email: null, CITY: "João Pessoa" }));
// { name: 'Ana', city: 'João Pessoa' }
```

### Armadilhas frequentes em código de objetos gerado por IA

Modelos de linguagem aprendem com código de todas as eras do JavaScript, boa parte dele anterior a `structuredClone()` e a `Object.hasOwn()`, e repetem um conjunto reconhecível de falhas:

| Armadilha | Como se manifesta | Como mitigar |
| :--- | :--- | :--- |
| **Cópia rasa apresentada como cópia** | `{ ...obj }` ou `Object.assign({}, obj)` com objetos aninhados que continuam compartilhados. | Testar alterando o objeto interno da cópia e conferindo o original. |
| **Clone por JSON** | `JSON.parse(JSON.stringify(obj))` perdendo `Date`, `undefined`, `Map` e funções. | Trocar por `structuredClone()` e testar com um campo `Date`. |
| **`Object.freeze()` tratado como imutabilidade** | O objeto raiz congela, mas os objetos aninhados continuam graváveis. | Congelar recursivamente ou trabalhar com cópias em vez de congelamento. |
| **Mesclagem recursiva de entrada externa** | Mesclagem por atribuição (`alvo[chave] = valor`) sobre `req.body`, capaz de gravar em `__proto__` e afetar todos os objetos. | Filtrar chaves reservadas e validar o corpo antes da mesclagem. |
| **`hasOwnProperty` chamado direto no objeto** | `obj.hasOwnProperty(k)` quebra em objetos criados com `Object.create(null)`. | Usar `Object.hasOwn(obj, k)`, disponível desde o ES2022. |
| **Método extraído do objeto** | `const fn = obj.metodo` seguido de `fn()`, com `this` perdido. | Chamar pelo objeto ou fixar o contexto com `bind()`. |

A primeira armadilha **falha em silêncio**, porque a cópia parece independente até alguém alterar um campo aninhado:

```js title="Cópia rasa apresentada como cópia independente"
const original = { user: "ana", settings: { theme: "dark" } };

// Sugestão comum quando o pedido é "faça uma cópia do objeto"
const shallow = { ...original };
shallow.settings.theme = "light";

console.log(original.settings.theme); // "light" (o original mudou junto)

// Cópia profunda nativa, sem perda de tipos
const deep = structuredClone(original);
deep.settings.theme = "solarized";

console.log(original.settings.theme); // "light" (o original permanece)
```

<Aside type="caution" title="Dica de IA: Trate código de objeto gerado por IA como código de terceiro">
  Uma manipulação sugerida por um assistente entra no projeto com o mesmo status de um trecho copiado de um fórum. A responsabilidade pelo estado compartilhado que chega à produção é de quem abre o *pull request*, não do modelo que o escreveu.

  **Prompt:** *"Explique, propriedade por propriedade, o que esta cópia compartilha com o objeto original e o que é realmente independente. Mostre um exemplo de alteração que afeta os dois."*
</Aside>

### Checklist de revisão antes do merge

Antes de aprovar qualquer manipulação de objetos gerada com auxílio de IA, percorra as verificações abaixo:

1. **A cópia é rasa ou profunda?** Altere um campo aninhado do resultado e confira o original antes de aprovar;
2. **Há `JSON.parse(JSON.stringify(...))` no diff?** Troque por `structuredClone()` ou justifique a perda de tipos por escrito;
3. **As chaves vêm de entrada externa?** Filtre `__proto__`, `constructor` e `prototype` antes de qualquer mesclagem;
4. **A verificação de propriedade usa `Object.hasOwn()`?** O `in` também enxerga o protótipo e o `hasOwnProperty` direto quebra em objetos sem protótipo;
5. **Algum método foi extraído do objeto?** Guardar `obj.metodo` em uma variável perde o `this`;
6. **O objeto devolvido tem formato estável?** Chaves que aparecem apenas em alguns caminhos quebram quem consome o retorno;
7. **A estrutura merece mesmo ser um objeto?** Chaves dinâmicas vindas de dados costumam pedir `Map`, que preserva ordem e aceita qualquer tipo de chave.

A inteligência artificial reduziu o custo de escrever a manipulação de um objeto, mas não alterou em nada o custo de compartilhar estado sem perceber em produção.

## Resumo e Boas Práticas

As diretrizes a seguir reúnem as decisões mais importantes do tópico. A organização em blocos textuais evita cartões apertados e facilita a leitura em telas com barra lateral ativa.

### Criação e Acesso Seguro

Ao modelar objetos comuns, prefira a sintaxe mais direta e reserve recursos especiais para casos em que eles deixam a intenção mais clara:

- Prefira a notação literal `{}` e Property Shorthand (`{ name, age }`).
- Use colchetes (`obj[key]`) para chaves dinâmicas ou com caracteres especiais.
- Combine `?.` com `??` ao ler dados aninhados de APIs.

### Existência de Propriedades

Ao verificar se uma chave existe, escolha a ferramenta de acordo com a profundidade da busca desejada:

- Use `Object.hasOwn(obj, prop)` para propriedades diretas.
- Use `in` quando a busca também deve considerar a cadeia de protótipos.
- Diferencie chave inexistente de chave criada com valor `undefined`.

### Imutabilidade e Clonagem

Ao copiar ou atualizar objetos, lembre-se de que variáveis guardam referências para dados na Heap:

- Lembre-se de que `==` e `===` comparam referências, não conteúdo estrutural.
- Use spread (`{ ...obj }`) para cópias rasas e sobreposição declarativa.
- Use `structuredClone(obj)` quando precisar isolar objetos aninhados.

### Recursos Estáticos de Object

Ao tratar objetos como estruturas de dados, agrupe os métodos de `Object` pela intenção do código:

- Use `Object.keys()`, `Object.values()` e `Object.entries()` para inspeção e iteração.
- Combine `Object.entries()` com `Object.fromEntries()` para transformar objetos.
- Reserve `Object.create()` e `Object.defineProperty()` para protótipos e descritores.

### Proteção de Objetos

Ao compartilhar configurações ou constantes entre módulos, proteja a estrutura quando mutações acidentais forem perigosas:

- Use `Object.freeze()` para bloquear alterações, inclusões e exclusões.
- Use `Object.seal()` quando a forma deve ser fixa, mas os valores ainda podem mudar.
- Lembre-se de que `freeze` e `seal` atuam de forma rasa.

### Classes e POO

Ao reunir estado e comportamento no mesmo modelo, use classes como sintaxe organizada sobre a cadeia de protótipos:

- Estruture dados e comportamentos com `class` e `constructor`.
- Use campos privados (`#`) e acessores `get`/`set` para encapsulamento.
- Use `extends` e `super()` para herança e sobrescrita.

### JSON

Ao trocar dados com APIs ou arquivos textuais, separe o objeto em memória do formato serializado:

- Converta dados com `JSON.stringify()` e `JSON.parse()`.
- Respeite chaves com aspas duplas e ausência de vírgula final.
- Evite funções, `undefined`, `Symbol`, `BigInt` e referências circulares.

## Perguntas de revisão

### Criação e Acesso

**1. Qual é a diferença entre Notação de Ponto (`obj.prop`) e Notação de Colchetes (`obj["prop"]`)?**

<details>
  <summary>Possível resposta</summary>

  A notação de ponto é mais simples e legível, mas exige que a chave seja um identificador válido sem espaços ou hifens. A notação de colchetes permite usar chaves arbitrárias (com hífens, espaços ou números) e utilizar variáveis dinâmicas para acessar o nome da propriedade (`obj[variable]`).
</details>

**2. O que acontece ao tentar acessar uma propriedade que não existe em um objeto?**

<details>
  <summary>Possível resposta</summary>

  O JavaScript retorna o valor `undefined` (não lança erro, a menos que você tente acessar uma propriedade encadeada a partir desse `undefined`). O operador de encadear opcional (`?.`) evita esse erro, interrompendo a avaliação e devolvendo `undefined`.
</details>

**3. Qual é a diferença entre uma chave inexistente e uma chave explicitamente definida com `undefined`?**

<details>
  <summary>Possível resposta</summary>

  Ambas retornam `undefined` ao serem lidas (`obj.key`), mas `Object.hasOwn(obj, "key")` ou o operador `in` retornam `true` se a chave foi definida no objeto e `false` se a chave nunca existiu ou foi removida com `delete`.
</details>

**4. O que é Property Shorthand e quando podemos utilizá-lo?**

<details>
  <summary>Possível resposta</summary>

  É a sintaxe abreviada do ES6 que permite criar propriedades de objetos omitindo o valor quando o nome da chave é idêntico ao nome da variável local (ex: `{ name, age }` em vez de `{ name: name, age: age }`).
</details>

### Desestruturação e Imutabilidade

**5. Como funciona a atribuição por desestruturação em objetos e como renomear uma variável durante a extração?**

<details>
  <summary>Possível resposta</summary>

  A desestruturação extrai valores de chaves de um objeto para variáveis com o mesmo nome (`const { name } = user`). Para renomear a variável extraída, utiliza-se a sintaxe `chave: novoNome` (ex: `const { name: fullName } = user`).
</details>

**6. Declarar um objeto com `const` impede a alteração de suas propriedades internas?**

<details>
  <summary>Possível resposta</summary>

  Não. A palavra-chave `const` impede apenas a reassociação da variável a outro objeto na memória. As propriedades internas do objeto continuam podendo ser alteradas, adicionadas ou excluídas. Para tornar o objeto imutável, deve-se usar `Object.freeze()`.
</details>

**7. Por que os operadores `==` e `===` retornam `false` ao comparar dois objetos com as mesmas propriedades e como realizar uma comparação profunda (*deep equality*)?**

<details>
  <summary>Possível resposta</summary>

  Tanto `==` quanto `===` comparam apenas o endereço de memória (a referência na Heap), e não o conteúdo interno. Duas instâncias `{ a: 1 }` ocupam endereços distintos. Para checar o conteúdo estrutural, realiza-se uma comparação profunda (*deep equality*) percorrendo recursivamente as chaves e valores, ou utilizando utilitários como `assert.deepStrictEqual()` do Node.js.
</details>

**8. Como o operador Spread (`...`) auxilia na atualização imutável de um objeto?**

<details>
  <summary>Possível resposta</summary>

  O operador spread permite copiar todas as propriedades de um objeto existente para um novo objeto `{ ...oldObj, newProp: value }`, permitindo adicionar ou sobrescrever propriedades sem modificar o objeto original.
</details>

### Métodos do Object e JSON

**9. Quais são as diferenças entre os métodos `Object.keys()`, `Object.values()`, `Object.entries()` e `Object.fromEntries()`?**

<details>
  <summary>Possível resposta</summary>

  `Object.keys()` retorna um array com os nomes das chaves. `Object.values()` retorna um array com os valores das propriedades. `Object.entries()` retorna um array de pares `[chave, valor]`. `Object.fromEntries()` faz o caminho inverso: recebe pares `[chave, valor]` e reconstrói um objeto.
</details>

**10. Quando usar spread, `Object.assign()` e `Object.freeze()`?**

<details>
  <summary>Possível resposta</summary>

  Use spread (`{ ...obj }`) para criar cópias rasas e mesclagens imutáveis de forma declarativa. Use `Object.assign()` quando precisar copiar propriedades para um alvo específico, sabendo que o primeiro argumento é modificado. Use `Object.freeze()` para bloquear alterações, inclusões e exclusões em objetos que devem permanecer estáveis em tempo de execução.
</details>

**11. Quais são as principais diferenças entre um Objeto JavaScript e uma string no formato JSON?**

<details>
  <summary>Possível resposta</summary>

  No formato JSON, todas as chaves DEVEM estar obrigatoriamente entre aspas duplas, strings devem usar aspas duplas, vírgulas no último elemento (*trailing commas*) são proibidas e métodos/funções ou `undefined` não são permitidos.
</details>

**12. Para que servem os métodos `JSON.stringify()` e `JSON.parse()`?**

<details>
  <summary>Possível resposta</summary>

  `JSON.stringify(obj)` converte um objeto JavaScript em uma string codificada em JSON (serialização). `JSON.parse(jsonString)` converte uma string formatada em JSON de volta para um objeto JavaScript (deserialização).
</details>

**13. O que acontece com propriedades de valor `undefined` ou funções ao executar `JSON.stringify()`?**

<details>
  <summary>Possível resposta</summary>

  Propriedades cujo valor seja uma função, `undefined` ou `Symbol` são omitidas da string JSON resultante.
</details>

### Classes e Orientação a Objetos

**14. Qual é a relação entre a sintaxe de `class` no ES6+ e a cadeia de protótipos em JavaScript?**

<details>
  <summary>Possível resposta</summary>

  No JavaScript, a palavra-chave `class` é um açúcar sintático (*syntactic sugar*) construído sobre o sistema de herança baseado em protótipos (*prototypal inheritance*). Métodos definidos dentro da classe são armazenados no protótipo (`User.prototype`) e compartilhados por todas as instâncias.
</details>

**15. Como funcionam os campos privados (`#`) e qual a diferença em relação à convenção de prefixar atributos com `_`?**

<details>
  <summary>Possível resposta</summary>

  Campos iniciados com `#` (ES2022) são verdadeiramente privados e inacessíveis fora do corpo da classe no tempo de execução, lançando erro de sintaxe em caso de acesso externo. Já o prefixo `_` é apenas uma convenção de nomenclatura: nada impede a leitura ou a escrita da propriedade a partir de fora da classe.
</details>

**16. Qual é a diferença entre sobrescrita (*overriding*) e sobrecarga (*overloading*) em JavaScript?**

<details>
  <summary>Possível resposta</summary>

  A sobrescrita ocorre quando uma subclasse redefine um método herdado da classe pai (podendo invocar `super.metodo()`). A sobrecarga (múltiplos métodos de mesmo nome com assinaturas diferentes) NÃO é suportada nativamente em JavaScript: a última declaração sobrescreve as anteriores. Para simular sobrecargas, utilizam-se parâmetros com valores padrão ou validação dinâmica de argumentos.
</details>

**17. Para que servem a palavra-chave `extends` e a função `super()` em subclasses?**

<details>
  <summary>Possível resposta</summary>

  `extends` especifica que uma classe herda métodos e propriedades de uma classe pai. A função `super()` chama o construtor da classe pai e deve ser invocada no construtor da subclasse antes de acessar `this`.
</details>
