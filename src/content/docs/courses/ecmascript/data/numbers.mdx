## Criação e Representação Numérica

Em JavaScript, o tipo primitivo **`number`** representa tanto números inteiros quanto números de ponto flutuante (decimais). Internamente, o JavaScript utiliza o padrão internacional **IEEE 754 de 64 bits** (dupla precisão) para armazenar todos os valores numéricos.

As numerações podem ser declaradas usando notação decimal comum, notação exponencial ou notações de bases alternativas (binária, octal e hexadecimal).

| Notação | Prefixo / Sintaxe | Exemplo | Valor em Base 10 |
| :--- | :--- | :--- | :--- |
| **Decimal** | Nenhuma | `42` / `3.14159` | `42` / `3.14159` |
| **Exponencial (Científica)** | `e` / `E` | `1.5e3` (1.5 × 10³) | `1500` |
| **Hexadecimal** | `0x` / `0X` | `0xFF` / `0x2A` | `255` / `42` |
| **Octal** | `0o` / `0O` | `0o52` | `42` |
| **Binária** | `0b` / `0B` | `0b101010` | `42` |
| **Separador Numérico** | `_` (ES2021) | `1_000_000` | `1000000` |

```js title="Formas de declaração de Numbers"
// 1. Decimais e Ponto Flutuante, positivos e negativos
const age = 28;
const price = 49.90;
const temperature = -7;
const balance = -1250.75;

// 2. Notação Exponencial
const bigVal = 2.5e6; // 2.500.000
const smallVal = 1e-3; // 0.001

// 3. Bases Alternativas (Binária, Octal e Hexadecimal)
const binary = 0b101010; // 42
const octal = 0o52;       // 42
const hex = 0x2A;         // 42

// 4. Separadores Numéricos (ES2021) para melhor legibilidade
const billion = 1_000_000_000; // 1000000000

console.log(temperature);    // -7
console.log(balance);        // -1250.75
console.log(binary === hex); // true (ambos valem 42)
console.log(billion);        // 1000000000
```

O sinal de menos não faz parte do literal numérico: ele é o operador unário de negação aplicado ao número escrito à direita. Por isso vale para qualquer uma das notações da tabela, e não apenas para a decimal:

```js title="Negação em outras notações"
console.log(-0b1111); // -15 (binário negado)
console.log(-0x2A);   // -42 (hexadecimal negado)
console.log(-2.5e6);  // -2500000 (exponencial negado)
```

<Aside type="tip" title="Prefira Numbers Primitivos">
  Assim como no caso das strings, evite utilizar `new Number(42)`. O operador `new` instancia um objeto *wrapper* na memória em vez de um primitivo, fazendo com que `typeof new Number(42)` retorne `"object"`, prejudicando comparações de igualdade estrita (`===`).
</Aside>

O exemplo a seguir ilustra o impacto do uso de primitivos em comparação com objetos instanciados via `new Number()`:

```js title="Primitivo vs Objeto Number"
const numPrim = 42;
const numObj = new Number(42);

console.log(typeof numPrim); // "number"
console.log(typeof numObj);  // "object"
console.log(numPrim === numObj); // false
```

## Limites de Precisão e Valores Especiais

Guardar todo número em 64 bits impõe dois limites práticos: existe um maior inteiro representável com exatidão, e nem toda fração decimal cabe exatamente em base binária. O objeto global `Number` expõe constantes que descrevem essas fronteiras.

A tabela a seguir reúne as constantes usadas ao longo desta seção:

| Constante | Ideia principal |
| --------- | --------------- |
| [`Number.MAX_SAFE_INTEGER`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/MAX_SAFE_INTEGER) | Maior inteiro que pode ser representado com segurança |
| [`Number.MIN_SAFE_INTEGER`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/MIN_SAFE_INTEGER) | Menor inteiro que pode ser representado com segurança |
| [`Number.MAX_VALUE`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/MAX_VALUE) | Maior valor numérico positivo representável |
| [`Number.MIN_VALUE`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/MIN_VALUE) | Menor valor positivo representável acima de zero |
| [`Number.EPSILON`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/EPSILON) | Diferença mínima útil para comparar números próximos de `1` |

### Anatomia de um Número de 64 Bits

Os 64 bits não guardam o número em binário puro: eles são repartidos em três campos definidos pelo formato de dupla precisão do IEEE 754. É essa repartição que fixa, de uma só vez, o maior inteiro exato, o maior valor representável e o tamanho do menor degrau entre dois números.

O esquema a seguir mostra a distribuição dos bits entre os três campos:

```txt title="Os 64 bits do formato IEEE 754 (dupla precisão)"
  bit 63     bits 62-52              bits 51-0
┌─────────┬──────────────┬────────────────────────────────┐
│  Sinal  │   Expoente   │       Fração (mantissa)        │
│  1 bit  │   11 bits    │            52 bits             │
└─────────┴──────────────┴────────────────────────────────┘
    ±        escala 2ⁿ         dígitos significativos
```

Cada campo responde por um limite diferente do tipo `number`, como resume a tabela a seguir:

| Campo | Bits | Papel | Limite que ele explica |
| :--- | :--- | :--- | :--- |
| **Sinal** | 1 | `0` para positivo, `1` para negativo | A existência de `+0` e `-0` distintos |
| **Expoente** | 11 | Escala do valor, uma potência de 2 | `Number.MAX_VALUE` e `Number.MIN_VALUE` |
| **Fração (mantissa)** | 52 | Dígitos significativos do valor | `Number.MAX_SAFE_INTEGER` e `Number.EPSILON` |

A fração tem 52 bits gravados, mas o formato assume um bit `1` implícito à esquerda, totalizando **53 dígitos binários significativos**. É daí que saem tanto o limite dos inteiros seguros quanto o valor de `Number.EPSILON`.

O exemplo a seguir confirma que as duas constantes são consequência direta do tamanho dos campos:

```js title="Os limites derivam do tamanho dos campos"
// 52 bits gravados + 1 bit implícito = 53 dígitos binários significativos
console.log(2 ** 53 - 1 === Number.MAX_SAFE_INTEGER); // true

// EPSILON é o degrau entre 1 e o próximo número representável: 2⁻⁵²
console.log(Number.EPSILON === 2 ** -52); // true

// Os 11 bits de expoente definem o alcance total da escala
console.log(Number.MAX_VALUE); // 1.7976931348623157e+308
console.log(Number.MIN_VALUE); // 5e-324
```

Os três campos também podem ser lidos diretamente, gravando o número em um buffer de 8 bytes e convertendo cada byte para binário:

```js title="Inspecionando os 64 bits de um número"
function toBits(value) {
  const view = new DataView(new ArrayBuffer(8));
  view.setFloat64(0, value);

  return Array.from({ length: 8 }, (_, i) =>
    view.getUint8(i).toString(2).padStart(8, "0")
  ).join("");
}

const bits = toBits(0.1);

console.log(bits[0]);           // "0" (sinal positivo)
console.log(bits.slice(1, 12)); // "01111111011" (expoente)
console.log(bits.slice(12));    // "1001100110011001100110011001100110011001100110011010"
```

Na fração de `0.1` aparece o padrão `1001` repetido indefinidamente: é a dízima binária tratada na subseção sobre imprecisão, cortada no 52º bit e arredondada no fim (`...1010` em vez de `...1001`). Esse arredondamento é a origem exata do `0.30000000000000004`.

### Limites de Inteiros Seguros

Devido ao formato IEEE 754 de 64 bits, apenas inteiros no intervalo entre `-(2⁵³ - 1)` e `2⁵³ - 1` são representados com exatidão. Esse limite importa sempre que o programa lida com identificadores, contadores ou valores inteiros muito grandes.

O exemplo a seguir mostra os valores das constantes e o momento em que somar `1` e somar `2` passam a produzir o mesmo resultado:

```js title="Limites de inteiros seguros"
console.log(Number.MAX_SAFE_INTEGER); // 9007199254740991, ou 2^53 - 1
console.log(Number.MIN_SAFE_INTEGER); // -9007199254740991
console.log(Number.MAX_VALUE);        // 1.7976931348623157e+308
console.log(Number.MIN_VALUE);        // 5e-324

// Acima do limite seguro, o passo entre inteiros consecutivos deixa de ser 1:
console.log(Number.MAX_SAFE_INTEGER + 1); // 9007199254740992
console.log(Number.MAX_SAFE_INTEGER + 2); // 9007199254740992 (erro de arredondamento!)

console.log(Number.isSafeInteger(Number.MAX_SAFE_INTEGER));     // true
console.log(Number.isSafeInteger(Number.MAX_SAFE_INTEGER + 1)); // false
```

A explicação está nos bits. Reutilizando a função `toBits` da subseção anterior, os dois valores acima do limite produzem exatamente a mesma sequência de 64 bits:

```js title="Acima do limite, dois inteiros compartilham os mesmos bits"
const limit = 2 ** 53; // 9007199254740992

console.log(toBits(limit) === toBits(limit + 1)); // true (bits idênticos!)
console.log(toBits(limit) === toBits(limit + 2)); // false (aqui o valor muda)

console.log(limit + 1 === limit); // true (o +1 não tem onde ser gravado)

// O expoente subiu para 1023 + 53:
console.log(toBits(limit).slice(1, 12)); // "10000110100" (1076)
```

Com o expoente em `2⁵³`, o bit menos significativo da mantissa deixa de valer 1 e passa a valer 2. A partir daí só os pares são representáveis, e somar `1` devolve o mesmo número. Cada vez que o expoente sobe, esse degrau dobra.

### BigInt para Inteiros Grandes

Ultrapassar o limite seguro não muda o tipo do valor: ele continua sendo `number`, apenas deixa de ser exato. Dois inteiros diferentes podem ficar indistinguíveis nessa faixa.

O exemplo a seguir compara o mesmo par de valores nos dois tipos, evidenciando a igualdade indevida em `number`:

```js title="Number fora do limite seguro não vira BigInt"
console.log(typeof 9007199254740992);  // "number"
console.log(typeof 9007199254740992n); // "bigint"
console.log(Number.isSafeInteger(9007199254740992)); // false

console.log(9007199254740992 === 9007199254740993);   // true (indistinguíveis!)
console.log(9007199254740992n === 9007199254740993n); // false (BigInt preserva a diferença)
```

Para inteiros acima desse limite, o JavaScript oferece o tipo **`bigint`**, escrito com o sufixo `n` ou criado pela função `BigInt()`. Ele não pode ser misturado com valores `number` na mesma operação aritmética.

O exemplo a seguir cria um `bigint`, opera sobre ele e mostra por que a comparação estrita com um `number` falha:

```js title="Operações com BigInt"
const big = 9007199254740991n;

console.log(typeof big);        // "bigint"
console.log(big + 1n);          // 9007199254740992n
console.log(big + BigInt(1));   // 9007199254740992n
console.log(big == 9007199254740991);  // true (compara só o valor)
console.log(big === 9007199254740991); // false (tipos diferentes)

// TypeError: Cannot mix BigInt and other types.
// console.log(big + 1);
```

### Imprecisão de Ponto Flutuante

Números decimais seguem a aritmética de ponto flutuante da norma [IEEE 754](https://standards.ieee.org/ieee/754/6210/). Assim como `1/3` não tem representação decimal finita, frações como `0.1` não têm representação binária finita, e o valor guardado é uma aproximação.

O diagrama a seguir acompanha o caminho de `0.1` até o resultado surpreendente da soma:

<Mermaid title="Por que 0.1 + 0.2 não resulta exatamente em 0.3">
{`
flowchart TD
  A["Literal decimal 0.1"] --> B["Fração binária periódica<br/>0.000110011001100..."]
  B --> C["IEEE 754 guarda 64 bits<br/>e trunca a dízima"]
  C --> D["Valor armazenado é levemente<br/>diferente de 0.1"]
  D --> E["A soma acumula o desvio<br/>de 0.1 e o de 0.2"]
  E --> F["Resultado: 0.30000000000000004"]
  F --> G["Comparar a diferença com<br/>Number.EPSILON, e não com === 0.3"]
`}
</Mermaid>

O exemplo a seguir reproduz a soma clássica e mostra a comparação por tolerância com `Number.EPSILON`:

```js title="Precisão decimal e comparação por tolerância"
console.log(0.1 + 0.2);        // 0.30000000000000004
console.log(0.1 + 0.2 === 0.3); // false

// Comparação correta usando uma tolerância:
const diff = Math.abs(0.1 + 0.2 - 0.3);
console.log(Number.EPSILON);   // 2.220446049250313e-16
console.log(diff < Number.EPSILON); // true (praticamente iguais)
```

O site [0.30000000000000004.com](https://0.30000000000000004.com/) reúne exemplos desse mesmo comportamento em várias linguagens e sugere formas de lidar com precisão e arredondamento quando isso importa para o domínio do problema.

<Aside type="tip" title="Precisão decimal">
  Quando o domínio exige comparação ou arredondamento cuidadoso, não assuma que uma
  soma decimal será representada exatamente. Defina uma tolerância para comparação,
  arredonde apenas nos pontos esperados da regra de negócio ou use uma estratégia de
  representação mais adequada ao problema.
</Aside>

<Aside type="caution" title="Valores monetários">
  Dinheiro parece decimal simples, mas `number` usa ponto flutuante binário. Isso
  pode gerar diferenças pequenas em somas, descontos, juros e comparações. Algumas
  formas recomendadas são: guardar valores em centavos como inteiros (`1099` para
  representar `R$ 10,99`), usar tipos decimais no banco de dados (`DECIMAL` ou
  `NUMERIC`) quando houver persistência, aplicar arredondamento em pontos bem
  definidos da regra de negócio e usar bibliotecas próprias para cálculo financeiro
  quando houver maior exigência de precisão. Para exibir o valor, formate apenas no
  final, por exemplo com `Intl.NumberFormat`.
</Aside>

## Valores Especiais: `NaN` e `Infinity`

Além dos números comuns, o padrão IEEE 754 define dois valores especiais que o JavaScript expõe diretamente na linguagem:

- **`Infinity` e `-Infinity`**: Representam resultados além do maior valor representável, produzidos por divisões por zero ou por transbordo de expoente (ex: `1 / 0`).
- **`NaN` (*Not-a-Number*)**: Apesar do nome ("não é um número"), `typeof NaN` retorna `"number"`. Ele representa um resultado numérico matematicamente indefinido ou não real.

### Como `NaN` e `Infinity` Aparecem

Quatro famílias de operação produzem `NaN`, e vale reconhecê-las para localizar a origem do problema em um cálculo que "virou NaN".

A tabela a seguir organiza esses cenários:

| Cenário | Operação | Resultado |
| :--- | :--- | :--- |
| **Divisão Indefinida / Operações Indeterminadas com `Infinity`** | `0 / 0`, `Infinity - Infinity`, `0 * Infinity`, `Infinity / Infinity` | `NaN` |
| **Matemática Não-Real (Raízes de Negativos)** | `Math.sqrt(-1)`, `Math.log(-1)`, `Math.asin(2)` | `NaN` |
| **Conversões Numéricas Inválidas** | `Number("abc")`, `parseInt("texto")` | `NaN` |
| **Aritmética com `undefined`** | `undefined + 1`, `undefined * 5` | `NaN` |

O código a seguir demonstra a execução dessas operações na prática:

```js title="Exemplos práticos de geração de NaN e Infinity"
// 1. Divisão por zero e infinitos
console.log(10 / 0);              // Infinity
console.log(-10 / 0);             // -Infinity

// 2. Divisão indefinida de zero por zero e operações indeterminadas com Infinity
console.log(0 / 0);               // NaN (O clássico 0 / 0!)
console.log(Infinity - Infinity); // NaN
console.log(0 * Infinity);        // NaN
console.log(Infinity / Infinity); // NaN

// 3. Operações matemáticas sem resultado real (raízes e logaritmos negativos)
console.log(Math.sqrt(-1));       // NaN
console.log(Math.log(-1));        // NaN
console.log(Math.asin(2));        // NaN

// 4. Conversões numéricas inválidas e aritmética com undefined
console.log(Number("devlab"));    // NaN
console.log(parseInt("texto"));   // NaN
console.log(undefined + 10);      // NaN
console.log(undefined * 5);       // NaN
```

<Aside type="caution" title="Armadilha de Igualdade: `NaN !== NaN`">
  No ECMAScript, **`NaN` é o único valor da linguagem que não é igual a si mesmo!**

  ```js
  console.log(NaN === NaN); // false!
  ```

  Para testar se um valor é `NaN` de forma segura, **nunca utilize `=== NaN`**. Prefira `Number.isNaN(valor)` ou `Object.is(valor, NaN)`:

  ```js
  console.log(Number.isNaN(Math.sqrt(-1))); // true (Seguro!)
  console.log(Object.is(NaN, NaN));         // true (Seguro!)
  ```
</Aside>

### Métodos Estáticos de Verificação do Number

O objeto `Number` oferece métodos estáticos para testar a validade e o tipo de valores numéricos sem realizar coerções indesejadas de tipo:

| Método | Descrição | Exemplo |
| :--- | :--- | :--- |
| **`Number.isNaN(val)`** | Testa estritamente se o valor é `NaN` (sem coerção de tipo). | `Number.isNaN("abc")` // `false` |
| **`Number.isFinite(val)`** | Testa se o valor é um número finito válido (não `NaN` nem `Infinity`). | `Number.isFinite(100)` // `true` |
| **`Number.isInteger(val)`** | Testa se o valor é um número inteiro sem casas decimais. | `Number.isInteger(4.2)` // `false` |
| **`Number.isSafeInteger(val)`**| Testa se é um inteiro dentro do limite de precisão segura. | `Number.isSafeInteger(10)` // `true` |


## Conversão Numérica e Métodos do Protótipo

Texto e número trafegam juntos o tempo todo: entradas de formulário, parâmetros de URL e arquivos chegam como string, e valores calculados precisam voltar a ser texto para serem exibidos. As duas direções têm ferramentas distintas.

Para transformar texto em número existem as funções globais de conversão. Para transformar número em texto formatado existem os métodos do protótipo `Number`, e é essa a divisão das duas subseções a seguir.

### Conversão Explícita: `Number()`, `parseInt()` e `parseFloat()`

O JavaScript oferece três funções principais para converter textos ou outros tipos em números. A tabela a seguir resume suas principais diferenças:

| Função | Comportamento | Exemplo `"42.5px"` | Exemplo `"abc"` |
| :--- | :--- | :--- | :--- |
| **`Number(val)`** | Converte a string inteira. Se houver caracteres inválidos, retorna `NaN`. | `NaN` | `NaN` |
| **`parseInt(str, radix?)`** | Converte o início da string até encontrar um caractere não numérico, ignorando o resto. Retorna inteiro. | `42` | `NaN` |
| **`parseFloat(str)`** | Converte o início da string permitindo ponto decimal. | `42.5` | `NaN` |

Abaixo estão exemplos práticos de uso e conversão com diferentes formatos e bases numéricas:

```js title="Comparação de conversões numéricas"
// 1. Função Number() (conversão estrita da string inteira)
console.log(Number("42"));     // 42
console.log(Number("42.5"));   // 42.5
console.log(Number("42.5px")); // NaN (falha por causa do "px")
console.log(Number(true));     // 1
console.log(Number(null));     // 0

// 2. parseInt() e parseFloat() (extraem o número do início da string)
console.log(parseInt("42.5px"));   // 42 (descarta a fração e "px")
console.log(parseFloat("42.5px")); // 42.5 (preserva decimal, descarta "px")

// Sempre informe a base (radix) no parseInt() para evitar ambiguidades!
console.log(parseInt("1010", 2));  // 10 (interpreta "1010" em binário)
console.log(parseInt("FF", 16));   // 255 (interpreta "FF" em hexadecimal)
```

### Métodos de Instância e Formatação do Protótipo Number

Os métodos do protótipo `Number.prototype` permitem formatar números em strings com casas decimais fixas, precisão significativa ou notações específicas:

| Método | Assinatura | Retorno | Descrição |
| :--- | :--- | :--- | :--- |
| **`toFixed()`** | `num.toFixed(digits?)` | `string` | Formata o número com um número fixo de casas decimais (arredonda se necessário). |
| **`toPrecision()`** | `num.toPrecision(precision?)` | `string` | Formata o número com a quantidade especificada de dígitos significativos totais. |
| **`toExponential()`** | `num.toExponential(digits?)` | `string` | Retorna o número formatado em notação científica exponencial. |
| **`toString()`** | `num.toString(radix?)` | `string` | Converte o número em string na base numérica fornecida (`2` a `36`). |

O exemplo abaixo demonstra a utilização prática de cada um desses métodos de formatação:

```js title="Exemplo de métodos do protótipo Number"
const val = 1234.5678;

// 1. toFixed() - Define casas decimais
console.log(val.toFixed(2)); // "1234.57" (arredonda para cima)
console.log(val.toFixed(0)); // "1235"

// 2. toPrecision() - Define total de dígitos significativos
console.log(val.toPrecision(4)); // "1235"
console.log((0.001234).toPrecision(2)); // "0.0012"

// 3. toExponential() - Notação científica
console.log((12345).toExponential(2)); // "1.23e+4"

// 4. toString(radix) - Conversão de base
const n = 255;
console.log(n.toString(16)); // "ff" (hexadecimal)
console.log(n.toString(2));  // "11111111" (binário)
```

## O Objeto Estático Math

O objeto **`Math`** é um objeto estático nativo do JavaScript que fornece constantes matemáticas e funções utilitárias para trigonometria, arredondamento, exponenciação e números aleatórios. Como é um objeto estático, ele **não possui construtor** e não pode ser instanciado com `new Math()`.

### Constantes Matemáticas

O objeto `Math` disponibiliza constantes matemáticas fundamentais prontas para uso:

```js title="Constantes do objeto Math"
console.log(Math.PI);     // 3.141592653589793 (Pi)
console.log(Math.E);      // 2.718281828459045 (Número de Euler)
console.log(Math.SQRT2);  // 1.4142135623730951 (Raiz quadrada de 2)
```

### Funções de Arredondamento

O `Math` oferece quatro formas distintas de arredondar valores numéricos, cujas diferenças são destacadas na tabela a seguir:

| Função | Comportamento | `3.7` | `3.2` | `-3.7` |
| :--- | :--- | :--- | :--- | :--- |
| **`Math.floor(x)`** | Arredonda sempre **para baixo** (menor inteiro). | `3` | `3` | `-4` |
| **`Math.ceil(x)`** | Arredonda sempre **para cima** (maior inteiro). | `4` | `4` | `-3` |
| **`Math.round(x)`** | Arredonda para o **inteiro mais próximo**. | `4` | `3` | `-4` |
| **`Math.trunc(x)`** | Trunca o número, descartando a parte decimal. | `3` | `3` | `-3` |

O exemplo a seguir ilustra a aplicação prática destas quatro funções de arredondamento:

```js title="Exemplo de arredondamentos"
console.log(Math.floor(4.9)); // 4
console.log(Math.ceil(4.1));  // 5
console.log(Math.round(4.5)); // 5
console.log(Math.trunc(4.9)); // 4
```

### Funções Matemáticas Utilitárias

Para realizar operações matemáticas comuns como potências, raízes, valores absolutos e identificação de extremos, o `Math` oferece métodos utilitários essenciais:

```js title="Operações com Math"
// Potência e Raiz
console.log(Math.pow(2, 3));  // 8 (equivalente a 2 ** 3)
console.log(Math.sqrt(16));   // 4 (raiz quadrada)
console.log(Math.cbrt(27));   // 3 (raiz cúbica)
console.log(Math.hypot(3, 4));// 5 (hipotenusa: sqrt(3² + 4²))

// Absoluto e Sinal
console.log(Math.abs(-15));   // 15 (valor positivo)
console.log(Math.sign(-42));  // -1 (retorna -1, 0 ou 1 dependendo do sinal)

// Mínimo e Máximo
console.log(Math.min(10, 5, 20, 3)); // 3
console.log(Math.max(10, 5, 20, 3)); // 20

// Espalhando arrays em Math.max/min:
const scores = [80, 95, 70, 88];
console.log(Math.max(...scores)); // 95
```

### Geração de Números Aleatórios (`Math.random()`)

`Math.random()` retorna um número pseudo-aleatório no intervalo **`[0, 1)`** (inclui 0, mas exclui 1). A seguir está o padrão recomendado para gerar inteiros aleatórios dentro de um limite pré-definido:

```js title="Gerando números aleatórios em um intervalo [min, max]"
// Função utilitária para gerar inteiro aleatório entre min (inclusivo) e max (inclusivo)
function getRandomInt(min, max) {
  min = Math.ceil(min);
  max = Math.floor(max);
  return Math.floor(Math.random() * (max - min + 1)) + min;
}

console.log(getRandomInt(1, 10)); // Retorna um inteiro entre 1 e 10
console.log(getRandomInt(1, 6));  // Simulação de um dado de 6 lados
```

## Formatação de Números e Moedas (`Intl.NumberFormat`)

Embora o método `.toFixed()` permita formatar casas decimais, ele retorna uma string simples sem separadores de milhar ou símbolos monetários adequados à localidade do usuário. Para formatar moedas, porcentagens e valores numéricos respeitando as convenções internacionais, utiliza-se a API nativa **`Intl.NumberFormat`**.

### Sintaxe Básica

Para criar um formatador internacional, instanciamos `Intl.NumberFormat` passando a localidade desejada (ex: `'pt-BR'`) e o objeto com as opções de formatação:

```js
const formatter = new Intl.NumberFormat(locales?, options?);
formatter.format(number);
```

### Formatação de Moedas (*Currency*)

Para formatar valores Monetários (como Real Brasileiro `BRL`, Dólar Americano `USD` ou Euro `EUR`), configuramos `style: 'currency'` e definimos o código ISO da moeda em `currency`:

```js title="Formatação de moedas com Intl.NumberFormat"
const price = 1250.5;

// Real Brasileiro (pt-BR)
const formatterBRL = new Intl.NumberFormat("pt-BR", {
  style: "currency",
  currency: "BRL",
});
console.log(formatterBRL.format(price)); // "R$ 1.250,50"

// Dólar Americano (en-US)
const formatterUSD = new Intl.NumberFormat("en-US", {
  style: "currency",
  currency: "USD",
});
console.log(formatterUSD.format(price)); // "$1,250.50"

// Euro na Alemanha (de-DE)
const formatterEUR = new Intl.NumberFormat("de-DE", {
  style: "currency",
  currency: "EUR",
});
console.log(formatterEUR.format(price)); // "1.250,50 €"
```

### Formatação de Porcentagem (*Percent*)

Para exibir taxas, descontos e porcentagens, utilizamos `style: 'percent'`, que multiplica o valor por 100 e adiciona o símbolo `%`:

```js title="Formatação de porcentagens"
const discount = 0.155; // 15.5%

const percentFormatter = new Intl.NumberFormat("pt-BR", {
  style: "percent",
  minimumFractionDigits: 1,
});

console.log(percentFormatter.format(discount)); // "15,5%"
```

### Casas Decimais e Notação Compacta

Além de moedas e porcentagens, é possível formatar grandes valores numéricos com separadores de milhar adequados ou notações compactas (como `mil` ou `mi`):

```js title="Casas decimais e notação compacta"
const population = 214300000;

// Formatação Decimal Padrão com Separador de Milhar
const numberFormatter = new Intl.NumberFormat("pt-BR");
console.log(numberFormatter.format(population)); // "214.300.000"

// Notação Compacta (ex: 214 mi)
const compactFormatter = new Intl.NumberFormat("pt-BR", {
  notation: "compact",
  compactDisplay: "short",
});
console.log(compactFormatter.format(population)); // "214 mi"
```

<Aside type="note" title="Vantagens do Intl.NumberFormat">
  O `Intl.NumberFormat` trata automaticamente separadores de milhar (ponto no Brasil, vírgula nos EUA), símbolos de moedas, ordenação de caracteres e regras de arredondamento sem a necessidade de bibliotecas externas.
</Aside>

## Resumo e Boas Práticas

Esta seção consolida as decisões práticas do tópico. Use-a como referência rápida para escolher entre tipos numéricos, comparar decimais e formatar valores para o usuário.

### Precisão e Escolha do Tipo

O tipo `number` cobre a maioria dos casos, mas tem fronteiras que precisam ser respeitadas.

- Trabalhe com primitivos e evite `new Number()`, que cria um objeto *wrapper* e quebra a comparação estrita.
- Verifique inteiros grandes com `Number.isSafeInteger()` antes de confiar em somas e comparações.
- Use `bigint` para identificadores e contadores acima de `2⁵³ - 1`, lembrando que ele não se mistura com `number` na mesma operação.
- Nunca compare decimais com `===`; compare a diferença absoluta contra `Number.EPSILON` ou uma tolerância do domínio.

### Valores Especiais e Conversão

Entradas vindas de formulários, arquivos e APIs chegam como texto e produzem `NaN` com facilidade.

- Teste `NaN` com `Number.isNaN()` ou `Object.is()`, nunca com `=== NaN`.
- Prefira os métodos estáticos de `Number` às funções globais `isNaN()` e `isFinite()`, que fazem coerção de tipo.
- Use `Number()` quando a string inteira deve ser válida, e `parseInt()` ou `parseFloat()` quando o número está no início do texto.
- Informe sempre a base em `parseInt(str, radix)` para evitar ambiguidade na leitura.

### Cálculo e Apresentação

Separe o cálculo, que trabalha com números, da exibição, que trabalha com texto.

- Guarde valores monetários em centavos inteiros e arredonde apenas nos pontos definidos pela regra de negócio.
- Use `Math.trunc()` quando quiser descartar a parte decimal, e não `Math.floor()`, cujo comportamento difere em negativos.
- Formate para o usuário apenas no final, com `Intl.NumberFormat`, que resolve separadores, símbolos e regras de cada localidade.

## Perguntas de revisão

### Precisão e Verificação Numérica

**1. Por que `0.1 + 0.2 === 0.3` resulta em `false` em JavaScript?**

<details>
  <summary>Possível resposta</summary>

  Porque o JavaScript utiliza o padrão IEEE 754 de ponto flutuante de 64 bits em base binária. Certas frações decimais (como `0.1` e `0.2`) não possuem representação binária exata finita, gerando uma pequena imprecisão de arredondamento que resulta em `0.30000000000000004`.
</details>

**2. Qual é a diferença entre `Number.isNaN(val)` e a função global `isNaN(val)`?**

<details>
  <summary>Possível resposta</summary>

  A função global `isNaN(val)` realiza a coerção de tipo do valor para número antes de testar (fazendo `isNaN("abc")` retornar `true`). Já o método `Number.isNaN(val)` não realiza coerção e só retorna `true` se o argumento for estritamente do tipo `number` e com valor `NaN`.
</details>

**3. Qual é a diferença entre `parseInt("10px")` e `Number("10px")`?**

<details>
  <summary>Possível resposta</summary>

  `parseInt("10px")` lê a string caractere a caractere a partir do início e interrompe a conversão ao encontrar o primeiro caractere não-numérico (`"p"`), retornando o inteiro `10`. `Number("10px")` tenta converter a string inteira de forma estrita e, como ela contém caracteres inválidos, retorna `NaN`.
</details>

### Objeto Math e Formatação Intl

**4. Qual é a diferença entre `Math.floor()`, `Math.ceil()` e `Math.trunc()` para números negativos?**

<details>
  <summary>Possível resposta</summary>

  Para o número `-3.7`: `Math.floor(-3.7)` arredonda para baixo (menor inteiro), resultando em `-4`. `Math.ceil(-3.7)` arredonda para cima (maior inteiro), resultando em `-3`. `Math.trunc(-3.7)` simplesmente remove a parte decimal, resultando em `-3`.
</details>

**5. Quais opções são obrigatórias em `Intl.NumberFormat` para formatar um valor como moeda em Reais (`R$`)?**

<details>
  <summary>Possível resposta</summary>

  É necessário definir o parâmetro de localidade como `"pt-BR"` e passar um objeto de opções contendo `{ style: 'currency', currency: 'BRL' }`.
</details>

**6. Por que `9007199254740992 === 9007199254740993` resulta em `true`?**

<details>
  <summary>Possível resposta</summary>

  Porque os dois valores estão acima de `Number.MAX_SAFE_INTEGER`. Nessa faixa, o formato IEEE 754 de 64 bits não consegue mais representar cada inteiro individualmente, e os dois acabam armazenados como o mesmo valor. Com `bigint` (`9007199254740992n === 9007199254740993n`) o resultado é `false`.
</details>

**7. Quando utilizar `bigint` em vez de `number` e qual é a principal restrição do tipo?**

<details>
  <summary>Possível resposta</summary>

  Use `bigint` para inteiros que ultrapassam `2⁵³ - 1`, como identificadores e contadores muito grandes. A principal restrição é que ele não pode ser misturado com `number` na mesma operação aritmética, o que lança `TypeError: Cannot mix BigInt and other types`.
</details>

**8. Como comparar dois números decimais de forma segura em JavaScript?**

<details>
  <summary>Possível resposta</summary>

  Comparando a diferença absoluta entre eles com uma tolerância, em vez de usar `===`. O padrão é `Math.abs(a - b) < Number.EPSILON` para valores próximos de `1`, ajustando a tolerância conforme a escala e a regra de negócio do domínio.
</details>

**9. Por que valores monetários não devem ser somados diretamente como `number`?**

<details>
  <summary>Possível resposta</summary>

  Porque `number` usa ponto flutuante binário, e frações decimais como `0.1` não têm representação exata. Somas, descontos e juros acumulam pequenos desvios. A recomendação é guardar o valor em centavos como inteiro, usar tipos decimais no banco de dados e formatar apenas na exibição.
</details>

**10. Qual é a diferença entre `Math.trunc()` e `Math.floor()`?**

<details>
  <summary>Possível resposta</summary>

  Para números positivos os dois coincidem. Para negativos eles divergem: `Math.trunc(-3.7)` apenas descarta a parte decimal e devolve `-3`, enquanto `Math.floor(-3.7)` arredonda para o menor inteiro e devolve `-4`.
</details>
