## O Objeto Map

Um **`Map`** é uma coleção ordenada de pares chave-valor na qual qualquer valor (seja um objeto, função ou tipo primitivo) pode atuar tanto como chave quanto como valor.

### Comparativo: Map vs Objeto Literal

Embora objetos literais (`{}`) sejam historicamente utilizados como dicionários em JavaScript, eles possuem limitações fundamentais em relação ao `Map`:

| Característica | Objeto Literal (`{}`) | Estrutura `Map` |
| :--- | :--- | :--- |
| **Tipos de Chaves** | Apenas `String` ou `Symbol`. | **Qualquer valor** (objetos, funções, números, booleans). |
| **Ordem de Inserção** | Nem sempre garantida para chaves numéricas. | **Garantida estritamente** na ordem de inserção. |
| **Tamanho da Coleção** | Manual via `Object.keys(obj).length`. | Direto via propriedade **`.size`**. |
| **Desempenho** | Otimizado para dados estruturados estáticos. | Otimizado para **inserções e remoções frequentes**. |
| **Iteração** | Exige `Object.keys()` ou `for...in`. | **Iterável nativo** via `for...of` ou `.forEach()`. |
| **Chaves Padrão** | Contém protótipo (`Object.prototype`) com chaves herdadas. | Contém apenas as chaves explicitamente inseridas. |

### Instanciação e Métodos Principais

A API do `Map` opera inteiramente por meio de métodos dedicados (`set`, `get`, `has`, `delete`, `clear`), em vez do acesso direto por colchetes ou ponto:

```js title="Uso do Objeto Map"
// 1. Instanciação e inserção com .set(chave, valor)
const userRoles = new Map();

const userAna = { name: "Ana" };
const userCarlos = { name: "Carlos" };

// Usando objetos e números como chaves legítimas do Map:
userRoles.set(userAna, "Admin");
userRoles.set(userCarlos, "Editor");
userRoles.set(100, "ID_Numeric");

// 2. Leitura de valores com .get(chave)
console.log(userRoles.get(userAna)); // "Admin"
console.log(userRoles.get(userCarlos)); // "Editor"
console.log(userRoles.get(100)); // "ID_Numeric"

// 3. Verificação com .has(chave) e tamanho com .size
console.log(userRoles.has(userAna)); // true
console.log(userRoles.size); // 3

// 4. Remoção individual com .delete(chave)
userRoles.delete(userCarlos);
console.log(userRoles.size); // 2

// 5. Esvaziamento completo com .clear()
userRoles.clear();
console.log(userRoles.size); // 0
```

<Aside type="tip" title="Chaves por Referência de Memória">
  Ao utilizar objetos ou arrays como chaves em um `Map`, a comparação é baseada na **referência de memória**, e não no conteúdo estrutural. Por isso, duas instâncias de objetos com propriedades idênticas são tratadas como chaves totalmente distintas.
</Aside>

O trecho a seguir demonstra a diferença entre buscar uma chave por referência existente e passar um novo objeto literal em tempo de execução:

```js title="Referência de memória em chaves do Map"
const productMap = new Map();

// Tentativa incorreta: criar o objeto direto no .set() perde a referência
productMap.set({ id: 1 }, "Mouse Sem Fio");
console.log(productMap.get({ id: 1 })); // undefined (endereços de memória distintos!)

// Abordagem correta: reter a referência da variável
const mouseKey = { id: 1 };
productMap.set(mouseKey, "Mouse Sem Fio");
console.log(productMap.get(mouseKey)); // "Mouse Sem Fio"
```

### O Algoritmo SameValueZero e o Tratamento de NaN

O `Map` compara chaves utilizando o algoritmo interno da especificação denominado **SameValueZero**. Esse algoritmo funciona de forma análoga ao operador de estrita igualdade (`===`), com duas exceções fundamentais:

1. **`NaN` é considerado igual a `NaN`**: diferentemente de `===`, onde `NaN === NaN` é `false`, no `Map` é possível armazenar e recuperar valores associados à chave `NaN`.
2. **`+0` e `-0` são considerados iguais**: ambas as representações numéricas de zero apontam para a mesma chave na tabela.

```js title="Comportamento do algoritmo SameValueZero no Map"
const specialMap = new Map();

// NaN é uma chave válida e recuperável
specialMap.set(Number.NaN, "Valor Especial");
console.log(specialMap.get(Number.NaN)); // "Valor Especial"

// +0 e -0 compartilham a mesma entrada
specialMap.set(+0, "Zero Positivo");
specialMap.set(-0, "Zero Negativo"); // Sobrescreve a chave anterior!
console.log(specialMap.size); // 2 (entradas: NaN e 0)
```

### Conversão entre Map e Objeto Literal

Na integração com APIs REST e serialização em JSON, converter entre instâncias de `Map` e objetos tradicionais é uma rotina essencial. O JavaScript disponibiliza os métodos utilitários `Object.entries()` e `Object.fromEntries()` para essa ponte:

```js title="Conversão bidirecional entre Map e Objeto"
// 1. Objeto literal para Map (new Map com Object.entries)
const configObj = { theme: "dark", autoSave: true, maxRetries: 3 };
const configMap = new Map(Object.entries(configObj));

console.log(configMap.get("theme")); // "dark"
console.log(configMap.size); // 3

// 2. Map para Objeto literal (Object.fromEntries)
configMap.set("language", "pt-BR");
const updatedObj = Object.fromEntries(configMap);

console.log(updatedObj);
// { theme: "dark", autoSave: true, maxRetries: 3, language: "pt-BR" }
```

## O Objeto Set

Um **`Set`** é uma coleção de valores **únicos**. Qualquer tentativa de inserir um valor já presente na coleção é ignorada de forma transparente.

### Instanciação e Métodos Principais

Diferente do `Map` que armazena pares chave-valor, o `Set` armazena apenas elementos individuais:

```js title="Uso do Objeto Set"
// 1. Criando um Set a partir de um iterável (duplicatas são removidas na origem)
const skills = new Set(["JavaScript", "TypeScript", "Node.js", "JavaScript"]);
console.log(skills.size); // 3 ("JavaScript" foi computado apenas uma vez)

// 2. Inserindo elementos com .add()
skills.add("React");
skills.add("TypeScript"); // Ignorado silenciosamente pois já existe
console.log(skills.size); // 4

// 3. Verificando presença com .has()
console.log(skills.has("React")); // true
console.log(skills.has("Python")); // false

// 4. Removendo elemento com .delete()
skills.delete("Node.js");
console.log(skills.size); // 3
```

### Complexidade de Busca: Set versus Array

Uma das maiores motivações técnicas para a escolha entre `Set` e `Array` reside na complexidade computacional da operação de busca:

- **`Array.prototype.includes()`**: realiza uma varredura sequencial linear em tempo **O(n)**. Em listas volumosas (como 100.000 itens), o tempo de resposta cresce proporcionalmente ao número de elementos.
- **`Set.prototype.has()`**: opera por meio de tabela hash interna em tempo amortizado constante **O(1)**, realizando o teste de existência de forma praticamente instantânea, independentemente da quantidade de itens.

```js title="Comparação de tempo de busca O(1) versus O(n)"
const size = 100_000;
const arrayData = Array.from({ length: size }, (_, i) => `item_${i}`);
const setData = new Set(arrayData);

const searchItem = "item_99999";

// No Array: O(n) percorre potencialmente todos os elementos
const inArray = arrayData.includes(searchItem);

// No Set: O(1) localiza a chave via hashing imediato
const inSet = setData.has(searchItem);
console.log({ inArray, inSet }); // { inArray: true, inSet: true }
```

### Eliminação de Duplicatas em Arrays

A combinação de `Set` com o operador *spread* (`...`) é o padrão idiomático mais rápido para remover valores duplicados de um array em uma única linha:

```js title="Removendo duplicatas de um Array"
const rawScores = [10, 20, 10, 30, 40, 20, 50, 40];

// Array -> Set (deduplicação imediata) -> Array
const uniqueScores = [...new Set(rawScores)];

console.log(uniqueScores); // [10, 20, 30, 40, 50]
```

### Operações de Conjuntos (ES2024 / Baseline)

A especificação ECMAScript 2024 introduziu métodos nativos para cálculo formal de teoria dos conjuntos no protótipo de `Set`. Todos os métodos retornam uma **nova instância** de `Set`, preservando a imutabilidade dos conjuntos originais:

| Método | Operação Matemática | Descrição |
| :--- | :--- | :--- |
| `setA.union(setB)` | A ∪ B | Elementos presentes em A ou em B. |
| `setA.intersection(setB)` | A ∩ B | Elementos presentes simultaneamente em A e B. |
| `setA.difference(setB)` | A \ B | Elementos que pertencem a A, mas não pertencem a B. |
| `setA.symmetricDifference(setB)` | A Δ B | Elementos presentes em A ou em B, mas não em ambos. |
| `setA.isSubsetOf(setB)` | A ⊆ B | Retorna booleano indicando se todos os itens de A estão em B. |
| `setA.isSupersetOf(setB)` | A ⊇ B | Retorna booleano indicando se A contém todos os itens de B. |
| `setA.isDisjointFrom(setB)` | A ∩ B = ∅ | Retorna booleano indicando se A e B não têm elementos em comum. |

O código a seguir exemplifica o uso dessas operações em conjuntos de permissões de usuários:

```js title="Operações com conjuntos no Set (ES2024)"
const adminPermissions = new Set(["read", "write", "delete", "audit"]);
const editorPermissions = new Set(["read", "write", "publish"]);

// 1. União: conjunto consolidado de permissões
const allPermissions = adminPermissions.union(editorPermissions);
console.log([...allPermissions]); // ["read", "write", "delete", "audit", "publish"]

// 2. Interseção: permissões compartilhadas por ambos os papéis
const common = adminPermissions.intersection(editorPermissions);
console.log([...common]); // ["read", "write"]

// 3. Diferença: exclusivas de admin que editor não possui
const adminOnly = adminPermissions.difference(editorPermissions);
console.log([...adminOnly]); // ["delete", "audit"]

// 4. Diferença simétrica: privilégios que não são mútuos
const nonShared = adminPermissions.symmetricDifference(editorPermissions);
console.log([...nonShared]); // ["delete", "audit", "publish"]

// 5. Testes relacionais booleanos
const guestPermissions = new Set(["read"]);
console.log(guestPermissions.isSubsetOf(adminPermissions)); // true
console.log(adminPermissions.isDisjointFrom(guestPermissions)); // false
```

## Iteração sobre Map e Set

Tanto o `Map` quanto o `Set` implementam o protocolo de iteração (`Iterable`), permitindo o uso direto em laços `for...of`, desestruturação e chamadas com `.forEach()`.

### Iterando sobre um Map

Ao iterar diretamente sobre um `Map`, cada passo devolve uma tupla `[chave, valor]`, facilitando a desestruturação no cabeçalho do laço:

```js title="Formas de iterar sobre um Map"
const catalog = new Map([
  ["Notebook", 4500],
  ["Monitor", 1200],
  ["Teclado", 350],
]);

// 1. Laço for...of com desestruturação de par [chave, valor]
for (const [item, price] of catalog) {
  console.log(`${item}: R$ ${price.toFixed(2)}`);
}

// 2. Iterando exclusivamente sobre chaves (.keys())
for (const item of catalog.keys()) {
  console.log(`Produto: ${item}`);
}

// 3. Iterando exclusivamente sobre valores (.values())
for (const price of catalog.values()) {
  console.log(`Preço: R$ ${price}`);
}

// 4. Método forEach: recebe (valor, chave, map)
catalog.forEach((price, item) => {
  console.log(`${item} -> R$ ${price}`);
});
```

### Iterando sobre um Set

No `Set`, como cada elemento é seu próprio identificador, a iteração devolve os valores diretamente na ordem em que foram inseridos:

```js title="Formas de iterar sobre um Set"
const categories = new Set(["Eletrônicos", "Acessórios", "Móveis"]);

// 1. Laço for...of direto
for (const category of categories) {
  console.log(`Categoria: ${category}`);
}

// 2. Método forEach
categories.forEach((category) => {
  console.log(`Item: ${category}`);
});
```

## WeakMap e WeakSet (Coleções de Referência Fraca)

O JavaScript fornece duas variantes especializadas chamadas **`WeakMap`** e **`WeakSet`**. O termo *Weak* ("fraco") diz respeito ao modo como o Coletor de Lixo (*Garbage Collector*) trata as referências aos objetos guardados: referências fracas não impedem que os objetos sejam desalocados da memória quando não houverem outros apontamentos ativos na aplicação.

| Característica | `Map` / `Set` | `WeakMap` / `WeakSet` |
| :--- | :--- | :--- |
| **Tipos Permitidos de Chave** | Qualquer tipo primitivo ou objeto. | **Apenas Objetos** (e Symbols não registrados). |
| **Coleta de Lixo (GC)** | Mantém a referência forte, **impedindo a coleta**. | **Referência Fraca**: permite a liberação imediata da memória. |
| **Propriedade `.size`** | Presente (ex: `map.size`). | **Ausente** (o tamanho é não determinístico). |
| **Iterabilidade** | Suporta `for...of`, `.keys()`, `.values()`. | **Não iterável** (não é possível listar os elementos). |
| **Método `.clear()`** | Suportado. | **Ausente**. |

### Casos de Uso: Metadados e Ciclo de Vida

O `WeakMap` é especialmente valioso para associar metadados ou informações privadas a instâncias de objetos sem modificar as propriedades do objeto e sem risco de vazamentos de memória (*memory leaks*):

```js title="Exemplo prático de WeakMap para metadados privados"
const accessLogs = new WeakMap();

class SecureSession {
  constructor(userId) {
    this.userId = userId;
    // Vincula metadados confidenciais à instância (this)
    accessLogs.set(this, {
      createdAt: new Date(),
      lastPing: Date.now(),
      authToken: "JWT_TOKEN_SECRET_987",
    });
  }

  getPing() {
    return accessLogs.get(this).lastPing;
  }
}

let session = new SecureSession("user_42");
console.log(session.getPing()); // Timestamp numérico

// Se a variável 'session' for anulada, o Garbage Collector descarta
// tanto o objeto session quanto os metadados associados no WeakMap!
session = null;
```

O `WeakSet`, por sua vez, é frequentemente utilizado para **marcação de instâncias** (*tagging* ou *branding*), validando se um objeto foi criado por uma fábrica autorizada antes de executar operações sensíveis:

```js title="Exemplo de validação de instância com WeakSet"
const authorizedWidgets = new WeakSet();

class Widget {
  constructor(name) {
    this.name = name;
    authorizedWidgets.add(this);
  }

  render() {
    if (!authorizedWidgets.has(this)) {
      throw new Error("Objeto não autorizado a renderizar.");
    }
    return `<div>${this.name}</div>`;
  }
}

const legitimateWidget = new Widget("Card");
console.log(legitimateWidget.render()); // "<div>Card</div>"
```

## Resumo e Boas Práticas

A escolha criteriosa da estrutura de dados adequada previne gargalos de desempenho e problemas de retenção de memória.

| Prática Recomendada | Motivo Técnico |
| :--- | :--- |
| **Usar `Map` quando as chaves não são strings fixas** | Objeto literal converte chaves complexas para `"[object Object]"`, causando colisões graves. |
| **Preferir `Set.has()` em vez de `Array.includes()`** | A verificação no `Set` opera em tempo amortizado constante O(1), enquanto o array exige varredura O(n). |
| **Usar `WeakMap` para metadados de ciclo de vida** | Permite que o Coletor de Lixo libere instâncias destruídas sem gerar vazamentos de memória. |
| **Guardar referências de objetos usados como chave** | A busca no `Map` avalia referências de memória; instanciar um novo `{ id: 1 }` na consulta retorna `undefined`. |
| **Utilizar os métodos de conjunto do ES2024** | Funções nativas como `union()` e `intersection()` são imutáveis, padronizadas e otimizadas em baixo nível pelo motor. |
| **Converter via `Object.fromEntries()` ao exportar JSON** | O formato JSON padrão suporta apenas pares chave-valor string; o `Map` puro não é serializado como dicionário por `JSON.stringify()`. |

O bloco a seguir reúne essas práticas em uma rotina de gerenciamento de permissões de usuários com deduplicação, cruzamento de conjuntos e cache:

```js title="Resumo prático de coleções"
// 1. Deduplicação com Set
const rawRoles = ["editor", "author", "editor", "subscriber"];
const userRoles = new Set(rawRoles);

// 2. Operação de conjuntos nativa (ES2024)
const requiredRoles = new Set(["editor", "admin"]);
const hasPermission = userRoles.intersection(requiredRoles).size > 0;

// 3. Mapeamento com Map e conversão com Object.fromEntries
const userStatus = new Map([
  ["user_1", { active: true, roles: [...userRoles] }],
  ["user_2", { active: false, roles: ["subscriber"] }],
]);

const exportedStatus = Object.fromEntries(userStatus);
console.log({ hasPermission, totalActive: userStatus.size });
```

## Exercício

Crie um arquivo chamado `access-control.js` para construir um gerenciador de permissões de sistema:

1. Crie uma classe `AccessController` com uma propriedade interna `userPermissions` baseada em `Map`;
2. Implemente o método `grant(userId, permissionsList)` que associe um `Set` de permissões a um determinado usuário;
3. Se o usuário já possuir permissões cadastradas, o método deve mesclar as novas permissões com as antigas garantindo a unicidade dos elementos;
4. Implemente o método `hasAccess(userId, permission)` que retorne um booleano validando se o usuário possui o privilégio solicitado;
5. Instancie o controlador, atribua permissões a dois usuários diferentes e imprima no console os testes de acesso.

Tente implementar as instruções acima antes de inspecionar a solução de referência a seguir.

<details>
  <summary>Possível resposta</summary>

  ```js title="access-control.js"
  class AccessController {
    #userPermissions = new Map();

    grant(userId, newPermissions) {
      const currentPermissions = this.#userPermissions.get(userId) || new Set();

      for (const permission of newPermissions) {
        currentPermissions.add(permission);
      }

      this.#userPermissions.set(userId, currentPermissions);
    }

    hasAccess(userId, permission) {
      const permissions = this.#userPermissions.get(userId);
      if (!permissions) return false;
      return permissions.has(permission);
    }

    listPermissions(userId) {
      const permissions = this.#userPermissions.get(userId);
      return permissions ? [...permissions] : [];
    }
  }

  const acl = new AccessController();

  acl.grant("user_101", ["read_post", "write_post"]);
  acl.grant("user_101", ["delete_post", "write_post"]); // "write_post" não duplica

  acl.grant("user_102", ["read_post"]);

  console.log("User 101 pode deletar?", acl.hasAccess("user_101", "delete_post")); // true
  console.log("User 102 pode deletar?", acl.hasAccess("user_102", "delete_post")); // false
  console.log("Permissões de 101:", acl.listPermissions("user_101")); // ['read_post', 'write_post', 'delete_post']
  ```
</details>

## Desafio

Crie um arquivo chamado `event-comparator.js` que receba os conjuntos de participantes de dois eventos da empresa e utilize os novos métodos de conjunto do ES2024 para gerar um relatório analítico:

1. Crie dois conjuntos `workshopA` e `workshopB` contendo listas de e-mails com participantes;
2. Escreva uma função `generateParticipationReport(setA, setB)` que calcule:
   - O total de participantes únicos em ambos os eventos (`union`);
   - Os participantes que estiveram em ambos os eventos (`intersection`);
   - Os participantes exclusivos do evento A (`difference`);
   - Os participantes que estiveram em apenas um dos eventos, mas não em ambos (`symmetricDifference`);
3. Retorne um objeto com os resultados e exiba no console formatado com `console.table()`.

Implemente a solução no seu arquivo antes de conferir a resolução comentada abaixo.

<details>
  <summary>Possível resposta</summary>

  ```js title="event-comparator.js"
  const workshopA = new Set(["ana@test.com", "carlos@test.com", "beatriz@test.com", "daniel@test.com"]);
  const workshopB = new Set(["carlos@test.com", "daniel@test.com", "eduardo@test.com", "fernanda@test.com"]);

  function generateParticipationReport(setA, setB) {
    const totalUnique = setA.union(setB);
    const presentInBoth = setA.intersection(setB);
    const exclusiveToA = setA.difference(setB);
    const exclusiveToB = setB.difference(setA);

      presentesEmAmbos: [...presentInBoth].join(", "),
      apenasEventoA: [...exclusiveToA].join(", "),
      apenasEventoB: [...exclusiveToB].join(", "),
      naoRepetidos: [...nonOverlapping].join(", "),
    };
  }

  const report = generateParticipationReport(workshopA, workshopB);
  console.log("--- Relatório de Participação ---");
  console.table(report);
  ```

## Perguntas de revisão

### Map e Mapeamento Chave-Valor

**1. Por que utilizar um `Map` em vez de um Objeto literal (`{}`) quando as chaves são objetos ou funções?**

<details>
  <summary>Possível resposta</summary>

  Porque objetos literais convertem automaticamente qualquer chave não-string para string (transformando diferentes instâncias de objetos na mesma chave `"[object Object]"` e sobrescrevendo valores). O `Map` permite usar qualquer tipo de dado como chave preservando referências sem coerção.
</details>

**2. Qual é o comportamento do algoritmo SameValueZero adotado pelo `Map` em relação a `NaN` e zeros com sinais diferentes (`+0` e `-0`)?**

<details>
  <summary>Possível resposta</summary>

  O algoritmo considera `NaN` igual a `NaN` (permitindo que `NaN` seja usado e recuperado como chave com sucesso) e considera `+0` e `-0` equivalentes, apontando para a mesma entrada na coleção.
</details>

**3. Como converter um `Map` em um Objeto literal e vice-versa?**

<details>
  <summary>Possível resposta</summary>

  Para converter de Objeto para `Map`, utiliza-se `new Map(Object.entries(objeto))`. Para converter de `Map` para Objeto literal, utiliza-se `Object.fromEntries(map)`.
</details>

**4. Por que a busca por uma chave de objeto literal recém-criada como `map.get({ id: 1 })` retorna `undefined`?**

<details>
  <summary>Possível resposta</summary>

  Porque o `Map` compara chaves baseadas em objetos pela sua referência de endereço de memória. O objeto `{ id: 1 }` passado no momento da leitura é uma nova instância na memória heap, distinta da referência utilizada no momento da inserção.
</details>

### Set, Complexidade e Operações de Conjuntos

**5. Qual é a diferença de complexidade assintótica de busca entre `Array.prototype.includes()` e `Set.prototype.has()`?**

<details>
  <summary>Possível resposta</summary>

  O `Array.prototype.includes()` possui complexidade O(n), pois realiza uma varredura sequencial linear em toda a lista. Já o `Set.prototype.has()` possui complexidade média constante O(1), pois localiza elementos via indexação por tabela hash.
</details>

**6. Como funciona a eliminação de duplicatas com `[...new Set(array)]`?**

<details>
  <summary>Possível resposta</summary>

  O construtor `new Set(array)` itera sobre o array original e descarta automaticamente qualquer valor repetido por definição da estrutura. Em seguida, o operador *spread* (`...`) descompacta os valores únicos de volta em uma nova instância de `Array`.
</details>

**7. Quais são as operações de conjuntos introduzidas no ES2024 para a estrutura `Set`?**

<details>
  <summary>Possível resposta</summary>

  A especificação ES2024 introduziu os métodos `union()`, `intersection()`, `difference()`, `symmetricDifference()`, além dos métodos relacionais de comparação `isSubsetOf()`, `isSupersetOf()` e `isDisjointFrom()`.
</details>

**8. O método `setA.intersection(setB)` altera o conjunto `setA` original?**

<details>
  <summary>Possível resposta</summary>

  Não. Todos os novos métodos de conjuntos do ES2024 são imutáveis e retornam uma **nova instância** de `Set` contendo o resultado da operação, sem modificar os conjuntos originais.
</details>

### Coleções Fracas (WeakMap e WeakSet)

**9. O que significa o termo "fraco" (*Weak*) em `WeakMap` e `WeakSet`?**

<details>
  <summary>Possível resposta</summary>

  Significa que a coleção retém apenas referências fracas para os objetos armazenados como chave. Se não houver outras referências fortes para o objeto no restante da aplicação, o Coletor de Lixo (*Garbage Collector*) pode liberar a memória do objeto a qualquer momento.
</details>

**10. Por que `WeakMap` e `WeakSet` não possuem a propriedade `.size` e não podem ser iterados com `for...of`?**

<details>
  <summary>Possível resposta</summary>

  Porque o processo de liberação de memória pelo Coletor de Lixo é não determinístico. Se a iteração ou o tamanho fossem permitidos, o resultado dependeria do momento exato em que o ciclo de coleta de lixo foi executado pelo motor, gerando comportamentos imprevisíveis.
</details>

**11. Quais tipos de dados são permitidos como chaves em um `WeakMap`?**

<details>
  <summary>Possível resposta</summary>

  Apenas objetos (como `{}` ou instâncias de classes) e Symbols não registrados na tabela global. Tipos primitivos como números, strings e booleans não são permitidos como chave porque não podem ser coletados pelo Garbage Collector.
</details>

**12. Qual é um caso de uso prático típico para o `WeakMap` em arquitetura de software?**

<details>
  <summary>Possível resposta</summary>

  O armazenamento de dados privados ou metadados associados a instâncias de classes ou nós do DOM. Quando o objeto principal for descartado, todos os metadados associados a ele no `WeakMap` serão desalocados automaticamente, prevenindo vazamentos de memória.
</details>
