## Objetivo

Compreender o modelo assíncrono e monotthread do JavaScript, dominar o conceito e o ciclo de vida de uma **Promise**, utilizar a sintaxe de encadeamento com `.then()`, `.catch()` e `.finally()`, aplicar combinadores estáticos (`Promise.all`, `Promise.allSettled`, `Promise.race`, `Promise.any`) e entender a relação direta entre Promises e a sintaxe `async/await`.

## O que é Assincronismo em JavaScript?

O JavaScript executa código em um ambiente de linha de execução única (*single-threaded*) guiado por um **Event Loop**. Operações de entrada e saída (I/O) — como buscar dados em uma API, ler um arquivo do disco ou aguardar um temporizador — demoram um tempo imprevisível para responder.

Se o JavaScript congelasse a execução até essas operações terminarem, a interface do usuário travaria. Para evitar isso, as operações de I/O são executadas de forma **assíncrona**.

| Modelo | Funcionamento | Problema / Desafio |
| ------ | ------------- | ------------------ |
| **Síncrono** | Cada instrução é executada em sequência, bloqueando a próxima até terminar | Bloqueia a aplicação durante operações lentas |
| **Callbacks** | Funções passadas como argumento para serem executadas após a conclusão | Gera aninhamento excessivo e difícil manutenção (*Callback Hell*) |
| **Promises** | Objetos que representam o resultado futuro de uma operação assíncrona | Permite código assíncrono estruturado, encadeável e legível |

```js title="Do Callback Hell às Promises"
// 1. Abordagem antiga com Callbacks (Callback Hell / Pyramids of Doom)
buscarUsuario(1, (usuario) => {
  buscarPedidos(usuario.id, (pedidos) => {
    buscarDetalhesPedido(pedidos[0].id, (detalhes) => {
      console.log(detalhes);
    });
  });
});

// 2. Abordagem moderna com Promises encadeadas
buscarUsuario(1)
  .then((usuario) => buscarPedidos(usuario.id))
  .then((pedidos) => buscarDetalhesPedido(pedidos[0].id))
  .then((detalhes) => console.log(detalhes))
  .catch((erro) => console.error("Erro na cadeia:", erro));
```

## O Conceito e Estados de uma Promise

Uma **Promise** é um objeto JavaScript que atua como um "contrato" para um valor que pode estar disponível agora, no futuro ou nunca.

Uma Promise possui **três estados mutuamente exclusivos**:

| Estado | Nome | Descrição |
| ------ | ---- | --------- |
| **Pending** | Pendente | Estado inicial. A operação assíncrona ainda está em execução |
| **Fulfilled** | Realizada / Resolvida | A operação foi concluída com sucesso e retornou um **valor** |
| **Rejected** | Rejeitada | A operação falhou e retornou uma **razão de erro** (*reason*) |

<Aside type="caution" title="Imutabilidade do Estado de uma Promise">
  Uma Promise transita do estado `Pending` para `Fulfilled` (sucesso) ou `Rejected` (erro) uma **única vez**. Após ser resolvida ou rejeitada, seu estado e seu valor tornam-se **imutáveis**.
</Aside>

## Criando e Consumindo Promises

### Criando uma Promise com `new Promise()`

Uma Promise é criada passando uma função executora (*executor*) que recebe duas funções de retorno: `resolve` e `reject`.

```js title="Criando uma Promise personalizada"
function checkServerStatus(isOnline) {
  return new Promise((resolve, reject) => {
    // Simula uma operação assíncrona de 1 segundo
    setTimeout(() => {
      if (isOnline) {
        resolve("Servidor operacional (Status 200 OK)");
      } else {
        reject(new Error("Falha na conexão: Servidor indisponível"));
      }
    }, 1000);
  });
}
```

### Execução Síncrona do Executor

A função passada para o construtor `new Promise((resolve, reject) => { ... })` é chamada de **executor**. Um ponto fundamental do funcionamento de Promises é que a função executora é chamada **imediatamente e de forma síncrona** no momento da criação da Promise.

```js title="Execução síncrona do executor"
console.log("1. Antes de criar a Promise");

const promise = new Promise((resolve, reject) => {
  console.log("2. Dentro do executor da Promise (execução SÍNCRONA)");
  resolve("Dados prontos");
});

console.log("3. Depois de criar a Promise");

promise.then((data) => {
  console.log("4. Dentro do .then() (execução ASSÍNCRONA)");
});

console.log("5. Fim do script principal");

//=>
// 1. Antes de criar a Promise
// 2. Dentro do executor da Promise (execução SÍNCRONA)
// 3. Depois de criar a Promise
// 5. Fim do script principal
// 4. Dentro do .then() (execução ASSÍNCRONA)
```

### Consumindo com `.then()`, `.catch()` e `.finally()`

| Método | Quando é Executado? | Função |
| ------ | ------------------- | ------ |
| `.then(onFulfilled)` | Quando a Promise transita para `Fulfilled` | Recebe o valor resolvido |
| `.catch(onRejected)` | Quando a Promise transita para `Rejected` ou lança um erro | Recebe o erro ocorrido |
| `.finally(onFinally)` | Quando a Promise é liquidada (independente de sucesso ou erro) | Executa código de limpeza |

```js title="Consumindo a Promise"
console.log("Iniciando verificação...");

checkServerStatus(true)
  .then((message) => {
    console.log("Sucesso:", message);
  })
  .catch((error) => {
    console.error("Erro:", error.message);
  })
  .finally(() => {
    console.log("Verificação concluída.");
  });
```

Referência: [Promise | MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise).

## Encadeamento de Promises (Promise Chaining)

Uma das maiores vantagens das Promises é a capacidade de encadear chamadas `.then()`.

Quando uma função dentro de um `.then()` retorna um valor simples, o JavaScript o envolve automaticamente em uma nova Promise resolvida. Se ela retornar outra Promise, o próximo `.then()` aguardará a resolução dessa nova Promise antes de prosseguir.

```js title="Encadeamento de Promises com transformações sucessivas"
function fetchUser(userId) {
  return new Promise((resolve) => {
    setTimeout(() => resolve({ id: userId, name: "Alice", points: 100 }), 500);
  });
}

function calculateBonus(user) {
  return new Promise((resolve) => {
    setTimeout(() => resolve(user.points * 1.5), 500);
  });
}

// Cadeia de Promises
fetchUser(42)
  .then((user) => {
    console.log(`Usuário encontrado: ${user.name}`);
    return calculateBonus(user); // Retorna uma nova Promise
  })
  .then((bonusPoints) => {
    console.log(`Pontuação com bônus: ${bonusPoints}`); // 150
    return bonusPoints > 100; // Retorna um booleano simples
  })
  .then((isEligible) => {
    console.log(`Elegível para prêmio? ${isEligible}`); // true
  })
  .catch((error) => {
    console.error("Erro em alguma etapa do processo:", error);
  });
```

<Aside type="caution" title="Tratamento Único de Erro na Cadeia">
  Um único bloco `.catch()` ao final da cadeia é capaz de capturar erros ocorridos em **qualquer uma das etapas anteriores** do encadeamento.
</Aside>

## Combinadores de Promises

Quando precisamos gerenciar múltiplas Promises simultaneamente, a classe `Promise` oferece quatro métodos estáticos combinadores.

| Método Estático | Comportamento de Sucesso | Comportamento de Falha |
| --------------- | ----------------------- | ---------------------- |
| `Promise.all([p1, p2])` | Resolve quando **todas** forem resolvidas (retorna array de resultados) | Rejeita imediatamente no **primeiro erro** (*All-or-Nothing*) |
| `Promise.allSettled([p1, p2])` | Resolve quando **todas forem liquidadas** (sucesso ou falha) | Nunca rejeita globalmente; retorna status individual de cada uma |
| `Promise.race([p1, p2])` | Resolve/rejeita assim que a **primeira** Promise da lista for liquidada | Acompanha a primeira a responder (vencedora da corrida) |
| `Promise.any([p1, p2])` | Resolve assim que a **primeira com sucesso** for resolvida | Rejeita apenas se **todas falharem** (`AggregateError`) |

```js title="Exemplo de Promise.all e Promise.allSettled"
const fetchPosts = new Promise((res) => setTimeout(() => res(["Post 1", "Post 2"]), 300));
const fetchComments = new Promise((res) => setTimeout(() => res(["Comentário 1"]), 500));
const fetchFail = new Promise((_, rej) => setTimeout(() => rej("Falha no servidor D"), 200));

// 1. Promise.all() - Falha rápido se qualquer uma falhar
Promise.all([fetchPosts, fetchComments])
  .then(([posts, comments]) => {
    console.log("Resultados:", posts, comments);
  })
  .catch((err) => console.error("Erro no Promise.all:", err));

// 2. Promise.allSettled() - Aguarda todas independente de falha
Promise.allSettled([fetchPosts, fetchFail])
  .then((results) => {
    console.log("Status de cada operação:", results);
    /*
    [
      { status: 'fulfilled', value: ['Post 1', 'Post 2'] },
      { status: 'rejected', reason: 'Falha no servidor D' }
    ]
    */
  });
```

Referência: [Promise.all() | MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise/all).

## Ordem de Execução: Event Loop e Microtask Queue

Para compreender o comportamento assíncrono das Promises, é essencial entender a diferença de prioridades no **Event Loop** do JavaScript:

1. **Código Síncrono (Call Stack):** Executado imediatamente, de cima para baixo.
2. **Fila de Microtasks (*Microtask Queue*):** Armazena callbacks de Promises (`.then`, `.catch`, `.finally` e a continuação após um `await`). Possui **prioridade alta** e é esvaziada por completo logo após o encerramento do código síncrono atual.
3. **Fila de Macrotasks (*Macrotask / Task Queue*):** Armazena temporizadores (`setTimeout`, `setInterval`) e eventos de I/O. Executa apenas após o esvaziamento total da Fila de Microtasks.

```js title="Demonstração do Event Loop e Prioridade de Microtasks"
console.log("1. Síncrono - Início");

setTimeout(() => {
  console.log("2. Macrotask (setTimeout)");
}, 0);

Promise.resolve().then(() => {
  console.log("3. Microtask 1 (Promise)");
}).then(() => {
  console.log("4. Microtask 2 (Promise encadeada)");
});

console.log("5. Síncrono - Fim");

//=> Ordem exata de saída no console:
// 1. Síncrono - Início
// 5. Síncrono - Fim
// 3. Microtask 1 (Promise)
// 4. Microtask 2 (Promise encadeada)
// 2. Macrotask (setTimeout)
```

## Consumo Prático da Fetch API e Validação de `response.ok`

No consumo de recursos de rede no navegador com a `Fetch API`, a função `fetch(url)` retorna uma Promise que é resolvida com um objeto `Response`.

<Aside type="caution" title="Pegadinha importante da Fetch API">
  A Promise retornada pelo `fetch()` **NÃO é rejeitada em respostas HTTP de erro (como 404 Not Found ou 500 Internal Server Error)**. A Promise só rejeita caso ocorra uma falha grave de rede ou o destino seja inalcançável. Por isso, é **obrigatório verificar a propriedade `response.ok`** antes de processar o corpo da resposta.
</Aside>

```js title="Consumo correto de API com fetch"
fetch("https://api.github.com/users/luizchaves")
  .then((response) => {
    if (!response.ok) {
      throw new Error(`Erro na requisição HTTP: Status ${response.status}`);
    }
    return response.json();
  })
  .then((data) => {
    console.log("Usuário encontrado:", data.name);
  })
  .catch((error) => {
    console.error("Falha ao buscar usuário:", error.message);
  });
```

## Conexão com Async/Await

Embora a sintaxe com `.then()` e `.catch()` seja poderosa, encadear dezenas de Promises ainda pode tornar o código verboso.

No ES2017, o JavaScript introduziu as palavras-chave `async` e `await`, que oferecem uma **camada de sintaxe mais limpa (*syntactic sugar*) construída diretamente sobre Promises**.

```js title="Comparação: Promises .then() vs Async/Await"
// Abordagem 1: Usando .then() tradicional
function loadDataThen() {
  fetchUser(42)
    .then((user) => calculateBonus(user))
    .then((bonus) => console.log("Bônus:", bonus))
    .catch((err) => console.error(err));
}

// Abordagem 2: Usando Async/Await (mesmo comportamento por baixo dos panos!)
async function loadDataAsync() {
  try {
    const user = await fetchUser(42);
    const bonus = await calculateBonus(user);
    console.log("Bônus:", bonus);
  } catch (err) {
    console.error(err);
  }
}
```

<Aside type="tip" title="Promises continuam existindo!">
  O uso de `async/await` não substitui as Promises. Por baixo dos panos, o operador `await` está aguardando a resolução de uma **Promise**, e toda função `async` retorna uma **Promise**.
</Aside>

    - Lembre-se dos 3 estados de uma Promise: `Pending`, `Fulfilled` e `Rejected`.
    - O estado de uma Promise transita uma única vez e torna-se imutável após ser liquidado.

    - Use `Promise.all()` quando precisar de todas as respostas em paralelo e uma falha deva cancelar o processo.

  </Card>

- Retorne Promises dentro das funções para permitir que quem as chama consiga utilizar encadeamento `.then()` ou `await`.
- Evite aninhar blocos `.then()` uns dentro dos outros; prefira retornar a Promise interna para manter a cadeia plana (*flat chaining*).

## Perguntas de revisão

### Conceitos e Estados

**1. O que é o modelo assíncrono em JavaScript e por que ele é necessário?**

<details>
  <summary>Possível resposta</summary>

  Como o JavaScript executa em uma única linha de execução (*single-thread*), o modelo assíncrono permite disparar operações lentas de entrada e saída (como chamadas de rede e banco de dados) sem congelar a execução do restante da aplicação.
</details>

**2. Quais são os 3 estados possíveis de uma Promise e como ela transita entre eles?**

<details>
  <summary>Possível resposta</summary>

  Os estados são `Pending` (pendente/inicial), `Fulfilled` (realizada/sucesso) e `Rejected` (rejeitada/erro). A Promise inicia em `Pending` e transita uma única vez para `Fulfilled` (via `resolve()`) ou para `Rejected` (via `reject()`).
</details>

**3. O que significa dizer que o estado final de uma Promise é imutável?**

<details>
  <summary>Possível resposta</summary>

  Significa que uma vez resolvida ou rejeitada, o resultado e o valor da Promise não podem mais ser alterados ou disparados novamente por chamadas posteriores a `resolve()` ou `reject()`.
</details>

### Encadeamento e Métodos

**4. Como funciona o encadeamento de Promises com o método `.then()`?**

<details>
  <summary>Possível resposta</summary>

  Cada chamada a `.then()` retorna uma nova Promise. Se a função executada dentro do `.then()` retornar um valor comum ou outra Promise, o próximo `.then()` da cadeia receberá o resultado dessa resolução.
</details>

**5. Qual é o papel do método `.catch()` em uma cadeia de Promises?**

<details>
  <summary>Possível resposta</summary>

  O método `.catch()` funciona como um manipulador global de erros para a cadeia, capturando rejeições ou exceções lançadas em **qualquer** `.then()` anterior da cadeia.
</details>

**6. Quando o método `.finally()` é executado?**

<details>
  <summary>Possível resposta</summary>

  O método `.finally()` é executado sempre ao final do ciclo de vida da Promise, independente de ela ter sido resolvida com sucesso ou rejeitada com erro, sendo ideal para limpeza de recursos.
</details>

### Combinadores e Async/Await

**7. Qual é a principal diferença de comportamento entre `Promise.all()` e `Promise.allSettled()`?**

<details>
  <summary>Possível resposta</summary>

  `Promise.all()` falha imediatamente ao primeiro erro encontrado na lista de Promises (*all-or-nothing*). `Promise.allSettled()` aguarda a conclusão de todas as Promises (sejam resolvidas ou rejeitadas) e retorna o status individual de cada uma.
</details>

**8. O que acontece quando passamos um array de Promises para `Promise.race()`?**

<details>
  <summary>Possível resposta</summary>

  `Promise.race()` retorna uma nova Promise que se resolve ou rejeita com o resultado da **primeira** Promise da lista que for liquidada (a mais rápida).
</details>

**9. Qual é a relação entre Promises e a sintaxe `async/await`?**

<details>
  <summary>Possível resposta</summary>

  `async/await` é uma sintaxe simplificada (*syntactic sugar*) construída diretamente sobre Promises. Toda função `async` retorna uma Promise, e a palavra-chave `await` pausa a execução até que uma Promise seja resolvida.
</details>

**10. O que é o problema do Callback Hell e como as Promises ajudaram a resolvê-lo?**

<details>
  <summary>Possível resposta</summary>

  Callback Hell é o aninhamento excessivo de funções de retorno de chamada (*callbacks*) em formato de pirâmide, dificultando a leitura e o tratamento de erros. As Promises resolveram esse problema permitindo o encadeamento plano e linear de operações com `.then()` e tratamento unificado de erros com `.catch()`.
</details>

## Objetivo

Compreender o papel de `async` e `await` como camada de sintaxe (*syntactic sugar*) sobre **Promises**, declarar e consumir funções assíncronas, tratar erros e exceções utilizando estruturas `try...catch...finally`, diferenciar execução sequencial de execução paralela, utilizar *Top-Level Await* e integrar funções assíncronas em controladores do **Express 5** e ORMs no Node.js.

## O que é Async/Await? (Açúcar Sintático sobre Promises)

Introduzidas no ES2017 (ES8), as palavras-chave `async` e `await` não substituem as Promises — elas trabalham **juntas com as Promises**, oferecendo uma sintaxe mais limpa, sequencial e intuitiva para gerenciar o assincronismo.

| Recurso | Descrição | Comportamento |
| ------- | --------- | ------------- |
| **`async`** | Modificador colocado antes da declaração de uma função | Faz a função **retornar obrigatoriamente uma Promise** |
| **`await`** | Operador utilizado dentro de uma função `async` | **Pausa a execução** da função até que a Promise seja liquidada |

```js title="Comparação de Sintaxe: Promises .then() vs Async/Await"
// 1. Consumo com Promises e encadeamento .then()
function fetchUserThen(id) {
  return fetch(`https://api.devlab.org/users/${id}`)
    .then((response) => response.json())
    .then((user) => console.log(user))
    .catch((error) => console.error(error));
}

// 2. Consumo idêntico usando Async/Await
async function fetchUserAsync(id) {
  try {
    const response = await fetch(`https://api.devlab.org/users/${id}`);
    const user = await response.json();
    console.log(user);
  } catch (error) {
    console.error(error);
  }
}
```

<Aside type="tip" title="async/await NÃO substitui Promises!">
  Por baixo dos panos, a instrução `await` só funciona quando colocada antes de um valor ou função que retorne uma **Promise**. Além disso, o retorno de toda função marcada com `async` é automaticamente envolvido em uma Promise.
</Aside>

Referência: [async function | MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/async_function).

## Declaração e Comportamento de Funções Async

Você pode utilizar a palavra-chave `async` em qualquer tipo de declaração de função em JavaScript.

```js title="Formas de declaração de funções async"
// 1. Declaração de Função Tradicional
async function getData() {
  return "Dados carregados";
}

// 2. Arrow Function Assíncrona
const getCategories = async () => {
  return ["Tecnologia", "Redes", "Web"];
};

// 3. Método Assíncrono em Objeto ou Classe
const apiService = {
  async fetchStatus() {
    return { status: "OK", uptime: 99.9 };
  },
};
```

### Coerção de Retorno e Exceções

Dentro de uma função `async`:
- Retornar um valor comum (ex: `return "sucesso"`) equivale a retornar `Promise.resolve("sucesso")`.
- Lançar um erro com `throw` (ex: `throw new Error("falha")`) equivale a retornar `Promise.reject(erro)`.

```js title="Coerção de retornos em funções async"
async function checkNumber(num) {
  if (num < 0) {
    throw new Error("Número negativo não permitido"); // Vira Promise.reject
  }
  return num * 2; // Vira Promise.resolve
}

// Consumindo o retorno da função async como uma Promise normal
checkNumber(5)
  .then((res) => console.log("Resultado:", res)) // "Resultado: 10"
  .catch((err) => console.error(err.message));

checkNumber(-1)
  .catch((err) => console.error("Erro capturado:", err.message)); // "Erro capturado: Número..."
```

## Tratamento de Erros com `try...catch...finally`

Em código assíncrono baseado em `.then()`, os erros são capturados com `.catch()`. Com `async/await`, o tratamento de erros utiliza a estrutura tradicional **`try...catch...finally`** do JavaScript.

```js title="Estrutura completa de tratamento de erros"
async function loadUserProfile(userId) {
  try {
    console.log("Buscando usuário...");
    const response = await fetch(`https://jsonplaceholder.typicode.com/users/${userId}`);

    // Verificação de erros de status HTTP (ex: 404 Not Found ou 500 Server Error)
    if (!response.ok) {
      throw new Error(`Erro na requisição: Status ${response.status}`);
    }

    const user = await response.json();
    return user;

  } catch (error) {
    // Trata erros de rede, falha de parse JSON ou erros lançados com throw
    if (error instanceof Error) {
      console.error("Falha no carregamento:", error.message);
    } else {
      console.error("Erro desconhecido:", error);
    }
    return null; // Retorno de fallback seguro

  } finally {
    console.log("Operação de busca encerrada.");
  }
}
```

<Aside type="caution" title="O HTTP fetch não lança erro no status 404 ou 500!">
  A função nativa `fetch()` só rejeita a Promise em caso de falha de conexão de rede. Para códigos de erro HTTP (como 404 Not Found ou 500 Server Error), a Promise resolve normalmente com `response.ok = false`. Sempre verifique `if (!response.ok)` para lançar um erro intencional!
</Aside>

Referência: [await | MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/await).

## Execução Sequencial vs. Execução Paralela

Uma das armadilhas mais comuns ao utilizar `async/await` é criar **gargalos de desempenho** executando operações independentes de forma sequencial.

### O Gargalo da Execução Sequencial

Quando colocamos `await` na frente de cada chamada de forma isolada, a segunda requisição só começará a ser executada **após** a primeira ter sido totalmente concluída.

```js title="Execução Sequencial (Lenta: 2s + 2s = 4s total)"
function delay(ms, value) {
  return new Promise((resolve) => setTimeout(() => resolve(value), ms));
}

async function loadDataSequentially() {
  console.time("Tempo Sequencial");

  // A segunda busca aguarda a primeira terminar!
  const users = await delay(2000, ["Ana", "Bruno"]);
  const posts = await delay(2000, ["Post A", "Post B"]);

  console.timeEnd("Tempo Sequencial"); // ~4000ms
  return { users, posts };
}
```

### A Solução em Paralelo com `Promise.all()` e `await`

Se as operações forem independentes, devemos disparar ambas as Promises simultaneamente e aguardar o resultado combinado com `await Promise.all()`.

```js title="Execução Paralela com Promise.all (Rápida: Max(2s, 2s) = 2s total)"
async function loadDataInParallel() {
  console.time("Tempo Paralelo");

  // Dispara ambas as requisições em paralelo (sem await inicial)
  const usersPromise = delay(2000, ["Ana", "Bruno"]);
  const postsPromise = delay(2000, ["Post A", "Post B"]);

  // Aguarda a resolução simultânea das duas Promises
  const [users, posts] = await Promise.all([usersPromise, postsPromise]);

  console.timeEnd("Tempo Paralelo"); // ~2000ms
  return { users, posts };
}
```

| Abordagem | Funcionamento | Tempo de Execução Total | Quando Utilizar? |
| --------- | ------------- | ----------------------- | ---------------- |
| **Sequencial** | Um `await` após o outro | Soma de todos os tempos ($\sum t$) | Quando a 2ª chamada depende dos dados da 1ª |
| **Paralela** | Dispara todas e faz `await Promise.all()` | Tempo da operação mais longa ($\max t$) | Quando as chamadas são independentes |

<Aside type="caution" title="Evite o uso de await em laços forEach!">
  O método `.forEach()` de arrays **não aguarda Promises**. Colocar `await` dentro do callback de um `.forEach()` fará o laço continuar executando sem esperar pelas requisições!
  
  Para executar requisições em paralelo a partir de um array de itens, utilize `.map()` com `Promise.all()`:
  
  ```js
  const users = await Promise.all(userIds.map((id) => fetchUser(id)));
  ```
</Aside>

## Top-Level Await e Aplicações no Node.js / Express

### Top-Level Await

Em Módulos ES (ESM com `"type": "module"` no `package.json`), você pode utilizar a palavra-chave `await` no nível superior do arquivo, **fora de qualquer função `async`**.

```js title="Exemplo de Top-Level Await em arquivo ES Module"
// database.js (Módulo ES)

const prisma = new PrismaClient();

// Top-Level Await: aguarda a conexão com o banco antes de exportar
await prisma.$connect();
console.log("Conexão com o banco de dados estabelecida com sucesso!");

export default prisma;
```

### Controllers Assíncronos no Express 5

No ecossistema Node.js (especialmente com **Express** e ORMs como **Prisma** ou **Sequelize**), as funções de controller que acessam o banco de dados são declaradas como funções `async`.

A partir do **Express 5**, qualquer rejeição de Promise ou erro lançado em um controller `async` é repassado automaticamente para o *middleware* de erro global do servidor!

```js title="src/controllers/user-controller.js"

// Controller de listagem de usuários
export async function index(req, res) {
  // O await aguarda a consulta ao banco de dados sem travar o servidor Node.js
  const users = await prisma.user.findMany();
  res.json(users);
}

// Controller de busca por ID
export async function show(req, res) {
  const { id } = req.params;
  const user = await prisma.user.findUnique({ where: { id: Number(id) } });

  if (!user) {
    return res.status(404).json({ error: "Usuário não encontrado" });
  }

  res.json(user);
}
```

## Resumo e Boas Práticas

<CardGrid>
  <Card title="Sintaxe e Erros" icon="pencil">
    - Toda função declarada com `async` retorna uma **Promise**.
    - Utilize blocos `try...catch...finally` em volta dos comandos `await` para gerenciar exceções.
    - Lembre-se de verificar `response.ok` ao usar a Fetch API nativa.
  </Card>

  <Card title="Desempenho e Paralelismo" icon="star">
    - Não encadeie `await` sequenciais para chamadas independentes; utilize `await Promise.all()` para disparar requisições em paralelo.
    - Substitua laços `.forEach()` com `await` por `array.map()` combinado a `Promise.all()`.
  </Card>
</CardGrid>

- Utilize *Top-Level Await* apenas no nível raiz de módulos para tarefas de inicialização pesada (como conexões de banco de dados).
- No Express 5, aproveite o repasse automático de erros em rotas `async` para manter seus controllers limpos e centralizar o tratamento no middleware de erro.

<details>
  <summary>Possível resposta</summary>

  ```js title="api-aggregator.js"
  const fetchServerHealth = () =>
    new Promise((res) => setTimeout(() => res({ status: "Healthy", uptime: "99.9%" }), 300));

  const fetchStorageMetrics = () =>
    new Promise((res) => setTimeout(() => res({ usedGb: 450, totalGb: 1000 }), 400));

  const fetchBackupLogs = () =>
    new Promise((_, rej) => setTimeout(() => rej("Falha ao conectar ao serviço de backup"), 200));

    // Disparando em paralelo
    const results = await Promise.allSettled([
      fetchServerHealth(),
      fetchStorageMetrics(),
      fetchBackupLogs(),
    ]);

    const [health, storage, backup] = results;

    console.log("\n--- STATUS DO PAINEL ---");

    if (health.status === "fulfilled") {
      console.log("Servidor:", health.value.status, `(Uptime: ${health.value.uptime})`);
    }

    if (storage.status === "fulfilled") {
      console.log("Armazenamento:", `${storage.value.usedGb}GB de ${storage.value.totalGb}GB`);
    }

    if (backup.status === "rejected") {
      console.warn("Módulo de Backup:", `[AVISO] ${backup.reason}`);
    }
  }

  loadDashboardData();
  ```
</details>

## Perguntas de revisão

### Declaração e Funcionamento

**1. O que são as palavras-chave `async` e `await` e qual é a sua relação com Promises?**

<details>
  <summary>Possível resposta</summary>

  `async` e `await` são uma camada de sintaxe mais limpa (*syntactic sugar*) construída diretamente sobre Promises. A palavra-chave `async` faz uma função retornar obrigatoriamente uma Promise, enquanto `await` pausa a execução da função até que uma Promise seja resolvida ou rejeitada.
</details>

**2. O que acontece com o valor retornado por uma função declarada como `async`?**

<details>
  <summary>Possível resposta</summary>

  O valor retornado é automaticamente encapsulado em uma Promise resolvida (`Promise.resolve(valor)`). Se a função lançar uma exceção com `throw`, ela retornará uma Promise rejeitada (`Promise.reject(erro)`).
</details>

**3. É possível utilizar o operador `await` fora de uma função marcada como `async`?**

<details>
  <summary>Possível resposta</summary>

  Em funções tradicionais, não (resultará em erro de sintaxe). A única exceção é o *Top-Level Await*, que permite usar `await` no nível raiz de arquivos configurados como Módulos ES (ESM).
</details>

### Tratamento de Erros e Fetch API

**4. Como é feito o tratamento de erros ao utilizar a sintaxe `async/await`?**

<details>
  <summary>Possível resposta</summary>

  O tratamento de erros é feito utilizando a estrutura tradicional `try...catch...finally`. Qualquer rejeição de Promise aguardada com `await` é capturada como uma exceção dentro do bloco `catch`.
</details>

**5. Por que a função nativa `fetch()` não entra no bloco `catch` em respostas com status HTTP 404 ou 500?**

<details>
  <summary>Possível resposta</summary>

  Porque a função `fetch()` só rejeita a Promise em caso de falha de conexão física de rede. Respostas do servidor com códigos de erro HTTP (como 404 ou 500) resolvem normalmente com a propriedade `response.ok = false`.
</details>

**6. Para que serve o bloco `finally` em uma estrutura `try...catch...finally` assíncrona?**

<details>
  <summary>Possível resposta</summary>

  O bloco `finally` é executado obrigatoriamente ao término da operação assíncrona, independente de ter havido sucesso ou erro, sendo ideal para desligar indicadores de carregamento (*spinners*) ou fechar conexões.
</details>

### Desempenho e Aplicações

**7. O que é o gargalo da execução sequencial com `await` e como evitá-lo em chamadas independentes?**

<details>
  <summary>Possível resposta</summary>

  O gargalo ocorre quando colocamos `await` seguidos antes de disparar cada requisição, fazendo uma esperar o término da outra. Para evitá-lo em requisições independentes, devemos disparar todas em paralelo e aguardar os resultados combinados com `await Promise.all([p1, p2])`.
</details>

**8. Por que não devemos usar `await` dentro de um laço `.forEach()` ao iterar sobre arrays?**

<details>
  <summary>Possível resposta</summary>

  Porque a função de callback do `.forEach()` não aguarda o retorno de Promises, fazendo o laço continuar executando sem esperar pela conclusão das operações. Para requisições em arrays, deve-se usar `.map()` com `await Promise.all()`.
</details>

**9. Por que os controllers que acessam banco de dados no Node.js/Express são declarados como funções `async`?**

<details>
  <summary>Possível resposta</summary>

  Porque operações de banco de dados (como consultas do Prisma ou Sequelize) são assíncronas. O uso de `async/await` permite aguardar os dados sem bloquear o servidor Node.js, e no Express 5 os erros assíncronos são automaticamente encaminhados para o middleware de erro.
</details>

**10. Qual é a vantagem de utilizar `Promise.allSettled()` junto com `await` em vez de `Promise.all()`?**

<details>
  <summary>Possível resposta</summary>

  `Promise.all()` falha imediatamente ao primeiro erro encontrado. `Promise.allSettled()` aguarda todas as Promises terminarem (com sucesso ou falha) e permite tratar cada resultado individualmente sem interromper as demais operações.
</details>
