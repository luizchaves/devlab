Este tópico reúne comportamentos famosos do JavaScript que parecem errados à primeira vista:
`NaN !== NaN`, `typeof null === "object"`, `0.1 + 0.2 !== 0.3`, coerções inesperadas e
arrays com espaços vazios.

Quase todos esses casos deixam de ser "mágica" quando você separa três temas: representação
numérica, compatibilidade histórica e conversão implícita de tipos.

## Objetivo

Entender os principais casos estranhos do JavaScript, identificar a regra que explica cada
um, escolher APIs mais seguras (`Number.isNaN()`, `Object.is()`, `Array.isArray()`, `===`)
e evitar que coerções implícitas transformem entradas comuns em bugs difíceis de rastrear.

## Três Fontes de Estranheza

é melhor classificar a origem do comportamento.

## `NaN !== NaN`

`NaN` significa *Not-a-Number*, mas o próprio nome engana: o tipo de `NaN` é `number`. Ele
representa um resultado numérico inválido, como converter texto não numérico ou calcular uma
operação sem resultado representável.

O detalhe importante é que `NaN` não é igual a nenhum valor, nem a ele mesmo:

```js title="NaN não é igual a si mesmo"
const value = Number("abc");

console.log(value); // NaN
console.log(typeof value); // "number"
console.log(value === NaN); // false
console.log(value !== value); // true
console.log(Number.isNaN(value)); // true
```

<Aside type="caution" title="Não compare com NaN diretamente">
  Use `Number.isNaN(value)` para verificar `NaN` sem coerção. A função global `isNaN()`
  converte o valor antes do teste e pode aceitar entradas que você não queria aceitar.
</Aside>

## `typeof null === "object"`

`null` representa ausência intencional de valor, mas `typeof null` retorna `"object"`. Esse
é um comportamento antigo da linguagem, preservado porque mudar isso quebraria código real
publicado na web.

O teste correto para `null` é comparação direta:

```js title="Testando null corretamente"
const selectedUser = null;

console.log(typeof selectedUser); // "object"
console.log(selectedUser === null); // true
console.log(selectedUser == undefined); // true, mas depende de coerção
console.log(selectedUser === undefined); // false
```

Para diferenciar objetos reais de `null`, combine os testes:

```js title="Objeto não nulo"
function isObject(value) {
  return typeof value === "object" && value !== null;
}

console.log(isObject({})); // true
console.log(isObject([])); // true
console.log(isObject(null)); // false
```

<Aside type="tip" title="Array também retorna object">
  `typeof []` também é `"object"`. Para arrays, use `Array.isArray(value)`. Para `null`, use
  `value === null`.
</Aside>

## `0.1 + 0.2 !== 0.3`

JavaScript usa o tipo `number` baseado em ponto flutuante binário de 64 bits. Alguns decimais
simples para humanos não têm representação exata em binário, então pequenas diferenças de
arredondamento aparecem.

O exemplo clássico mostra a diferença:

```js title="Precisão decimal em number"
const result = 0.1 + 0.2;

console.log(result); // 0.30000000000000004
console.log(result === 0.3); // false
console.log(Math.abs(result - 0.3) < Number.EPSILON); // true
```

Em dinheiro, uma alternativa comum é trabalhar em centavos:

```js title="Dinheiro em centavos"
const priceInCents = 10;
const taxInCents = 20;
const totalInCents = priceInCents + taxInCents;

console.log(totalInCents); // 30
console.log(totalInCents / 100); // 0.3
```

<Aside type="caution" title="toFixed formata, não corrige o modelo">
  `toFixed(2)` é útil para exibir valores, mas devolve string e não transforma ponto
  flutuante em decimal exato. Para regras financeiras sérias, use inteiros ou biblioteca
  decimal apropriada.
</Aside>

## Igualdade: `==` vs `===`

O operador `==` compara depois de aplicar coerções. O operador `===` compara sem converter
tipos. Em código de aplicação, `===` é a escolha padrão porque a leitura fica previsível.

Os exemplos abaixo mostram por que `==` surpreende:

```js title="Coerções com igualdade solta"
console.log(0 == false); // true
console.log("" == false); // true
console.log("5" == 5); // true
console.log(null == undefined); // true

console.log(0 === false); // false
console.log("" === false); // false
console.log("5" === 5); // false
console.log(null === undefined); // false
```

O fluxo mental para comparar valores em JavaScript deve favorecer a igualdade estrita:

<Mermaid title="Escolha do operador de igualdade">
{`
flowchart TD
  A["Preciso comparar valores"] --> B{"Quero conversão automática?"}
  B -->|"Quase nunca"| C["Use === ou !=="]
  B -->|"Caso especial documentado"| D["Use == com comentário claro"]
  C --> E["Converta explicitamente antes, se necessário"]
  D --> F["Exemplo comum: value == null para null ou undefined"]
`}
</Mermaid>

<Aside type="tip" title="Regra prática">
  Use `===` e `!==` como padrão. Quando quiser aceitar dois tipos de entrada, converta antes
  com `Number()`, `String()` ou uma função de parsing do domínio.
</Aside>

## Soma, Concatenação e Conversão

O operador `+` é ambíguo: ele soma números, mas concatena se algum lado virar string. Outros
operadores aritméticos, como `-`, `*` e `/`, forçam conversão numérica.

O contraste fica claro nestes exemplos:

```js title="O operador + tem dois papéis"
console.log(5 + 2); // 7
console.log("5" + 2); // "52"
console.log(5 + "2"); // "52"
console.log("5" - 2); // 3
console.log("5" * "2"); // 10
```

Quando o valor vem de formulário, faça a conversão de forma explícita:

```js title="Entrada de formulário como texto"
const quantityInput = "3";
const price = 25;

const quantity = Number(quantityInput);
const total = quantity * price;

console.log(total); // 75
```

<Aside type="caution" title="Todo input HTML começa como string">
  Mesmo um `<input type="number">` entrega texto em `input.value`. Converta antes de calcular
  e valide `Number.isFinite()` para rejeitar entradas inválidas.
</Aside>

## Objetos, Arrays e Referências

Primitivos são comparados por valor. Objetos e arrays são comparados por referência: duas
estruturas com o mesmo conteúdo continuam sendo objetos diferentes se foram criadas em lugares
diferentes da memória.

O exemplo abaixo parece estranho só até lembrar que cada literal cria uma nova referência:

```js title="Comparação por referência"
console.log([] === []); // false
console.log({} === {}); // false

const first = [];
const second = first;

console.log(first === second); // true
```

Para comparar conteúdo, escolha uma regra explícita:

```js title="Comparando conteúdo de arrays simples"
function sameNumbers(a, b) {
  return a.length === b.length && a.every((value, index) => value === b[index]);
}

console.log(sameNumbers([1, 2], [1, 2])); // true
console.log(sameNumbers([1, 2], [2, 1])); // false
```

<Aside type="note" title="JSON.stringify não é comparação universal">
  Serializar pode funcionar em exemplos pequenos, mas falha com ordem de propriedades,
  funções, `undefined`, símbolos, datas, `Map`, `Set` e referências circulares.
</Aside>

## Arrays Esparsos

Um array pode ter "buracos": posições sem valor definido. Isso é diferente de uma posição
que existe contendo `undefined`.

O comportamento aparece quando alguns métodos pulam posições vazias:

```js title="Buracos em arrays"
const sparse = [1, , 3];
const explicit = [1, undefined, 3];

console.log(sparse.length); // 3
console.log(1 in sparse); // false
console.log(1 in explicit); // true

sparse.forEach((value) => console.log(value));
// 1
// 3
```

Prefira criar arrays preenchidos quando quiser percorrer todas as posições:

```js title="Array preenchido"
const scores = Array.from({ length: 3 }, () => 0);

console.log(scores); // [0, 0, 0]
console.log(scores.map((score) => score + 1)); // [1, 1, 1]
```

<Aside type="tip" title="Buraco não é valor">
  Em um array esparso, a posição nem existe. Em `[undefined]`, a posição existe e guarda o
  valor `undefined`. Alguns métodos tratam esses casos de maneira diferente.
</Aside>

## map() com parseInt: a Armadilha dos Argumentos Extras

Passar `parseInt` diretamente para `.map()` é uma das pegadinhas mais famosas do JavaScript. O método `.map(callback)` repassa três argumentos ao callback: `(elemento, índice, array)`.

Por sua vez, `parseInt(string, radix)` aceita um segundo parâmetro: a base numérica (*radix*). O índice do array acaba sendo repassado silenciosamente como base da conversão:

```js title="Comportamento inesperado de ['1', '2', '3'].map(parseInt)"
console.log(["1", "2", "3"].map(parseInt)); // [1, NaN, NaN]

// O que realmente acontece em cada iteração:
// 1. parseInt("1", 0) -> radix 0 é tratado como base 10 -> 1
// 2. parseInt("2", 1) -> base 1 é inválida no sistema posicional -> NaN
// 3. parseInt("3", 2) -> "3" não é um dígito válido em binário (base 2) -> NaN
```

Para converter strings numéricas de um array com segurança, utilize `Number` ou uma arrow function com a base 10 explícita:

```js title="Forma correta de mapear números"
console.log(["1", "2", "3"].map(Number)); // [1, 2, 3]
console.log(["1", "2", "3"].map((n) => parseInt(n, 10))); // [1, 2, 3]
```

## Desafio

Escreva uma função `safeSum(a, b)` que aceite números ou strings numéricas, rejeite valores
inválidos e compare o resultado com um valor esperado usando tolerância decimal.

<details>
  <summary>Possível resposta</summary>

  ```js title="safe-sum.js"
  function toFiniteNumber(value) {
    const number = Number(value);

    if (!Number.isFinite(number)) {
      throw new TypeError(`Valor inválido: ${value}`);
    }

    return number;
  }

  function safeSum(a, b) {
    return toFiniteNumber(a) + toFiniteNumber(b);
  }

  function almostEqual(a, b, tolerance = Number.EPSILON) {
    return Math.abs(a - b) <= tolerance;
  }

  const result = safeSum("0.1", "0.2");

  console.log(result); // 0.30000000000000004
  console.log(almostEqual(result, 0.3)); // true
  ```
</details>

## Perguntas de revisão

### Números e valores especiais

**1. Por que `NaN === NaN` retorna `false`?**

<details>
  <summary>Possível resposta</summary>

  Porque `NaN` representa um resultado numérico inválido e, pela semântica de ponto flutuante,
  não é igual a nenhum valor, nem a ele mesmo.
</details>

**2. Qual é a forma recomendada de testar `NaN`?**

<details>
  <summary>Possível resposta</summary>

  Use `Number.isNaN(value)`, que testa `NaN` sem converter valores antes da comparação.
</details>

**3. Por que `0.1 + 0.2` não resulta exatamente em `0.3`?**

<details>
  <summary>Possível resposta</summary>

  Porque `number` usa ponto flutuante binário. Alguns decimais não têm representação exata
  nesse formato e geram pequenas diferenças de arredondamento.
</details>

### Tipos, coerção e referência

**4. Por que `typeof null` retorna `"object"`?**

<details>
  <summary>Possível resposta</summary>

  Por um comportamento histórico preservado por compatibilidade. Para testar `null`, use
  `value === null`.
</details>

**5. Por que `"5" + 2` resulta em `"52"`?**

<details>
  <summary>Possível resposta</summary>

  Porque, quando há string na operação, `+` pode agir como concatenação. O número é convertido
  para texto.
</details>

**6. Por que `[] === []` retorna `false`?**

<details>
  <summary>Possível resposta</summary>

  Porque cada literal de array cria um objeto novo. Objetos são comparados por referência,
  não por conteúdo.
</details>
