Este tópico reúne comportamentos famosos do JavaScript que parecem estranhos à primeira vista: `NaN !== NaN`, `typeof null === "object"`, `0.1 + 0.2 !== 0.3`, coerções inesperadas de tipos e comparações contraintuitivas.

Materiais: [slides do tópico](../../../../slides/courses/ecmascript/reference/weird-cases/)

Quase todos esses casos deixam de ser inexplicáveis quando separamos quatro fundamentos da linguagem: representação numérica sob o padrão IEEE 754, compatibilidade histórica com as primeiras versões da web, regras de conversão implícita de tipos e comparação de referências de objetos na memória.

## Objetivo

Entender os principais casos estranhos do JavaScript, identificar a regra formal da especificação que explica cada um, escolher APIs seguras (`Number.isNaN()`, `Object.is()`, `Array.isArray()`, `===`) e evitar que coerções implícitas transformem entradas comuns em bugs difíceis de rastrear.

## `NaN !== NaN`

`NaN` significa *Not-a-Number*, mas seu tipo primitivo formal é `number`. Ele representa um resultado numérico indefinido ou matematicamente inválido (como converter texto não-numérico ou calcular a raiz quadrada de um número negativo).

Pela especificação IEEE 754, `NaN` não é igual a nenhum valor, nem mesmo a outro `NaN`:

```js title="Comportamento de NaN"
const value = Number("abc");

console.log(value);              // NaN
console.log(typeof value);       // "number"
console.log(value === NaN);      // false (nunca use === para testar NaN!)
console.log(value !== value);    // true
console.log(Number.isNaN(value));// true
console.log(Object.is(NaN, NaN));// true
```

<Aside type="caution" title="Use Number.isNaN() em vez do isNaN() global">
  O método estrito `Number.isNaN(value)` verifica se o valor atual é `NaN` sem realizar conversões prévias. A função global `isNaN("texto")` tenta converter a entrada para número antes do teste, retornando `true` para qualquer string não-numérica.
</Aside>

## `typeof null === "object"`

`null` representa a ausência intencional de qualquer valor de objeto. No entanto, o operador `typeof null` devolve a string `"object"`. Esse comportamento decorre da implementação original do JavaScript em 1995 (onde valores eram marcados com tags de tipo em binário e o ponteiro nulo compartilhava a tag de objeto `000`), sendo mantido até hoje para preservar a compatibilidade da web.

O teste correto para `null` deve ser realizado com igualdade estrita:

```js title="Testando null com segurança"
const selectedUser = null;

console.log(typeof selectedUser);        // "object"
console.log(selectedUser === null);       // true
console.log(selectedUser == undefined);   // true (coerção do operador frouxo)
console.log(selectedUser === undefined);  // false
```

Para validar se um dado é de fato um objeto sem falsos positivos com `null`:

```js title="Função utilitária para verificar objetos reais"
function isPlainObject(value) {
  return typeof value === "object" && value !== null && !Array.isArray(value);
}

console.log(isPlainObject({ name: "Ana" })); // true
console.log(isPlainObject([1, 2]));          // false
console.log(isPlainObject(null));            // false
```

## `0.1 + 0.2 !== 0.3` e Ponto Flutuante

O JavaScript utiliza o formato de ponto flutuante de precisão dupla (64 bits) definido pela norma IEEE 754. Frações decimais simples como `0.1` (1/10) e `0.2` (1/5) transformam-se em dízimas periódicas quando convertidas para a base binária, acumulando resíduos infinitesimais de arredondamento.

O exemplo a seguir demonstra a divergência e a forma correta de comparação:

```js title="Precisão decimal em números de ponto flutuante"
const result = 0.1 + 0.2;

console.log(result); // 0.30000000000000004
console.log(result === 0.3); // false

// Comparação segura usando a margem de tolerância Number.EPSILON:
const areClose = Math.abs(result - 0.3) < Number.EPSILON;
console.log(areClose); // true
```

Ao lidar com cálculos monetários e valores financeiros, a melhor prática consiste em operar com números inteiros (centavos) ou utilizar tipos como `BigInt`:

```js title="Cálculos financeiros em centavos inteiros"
const priceInCents = 10; // R$ 0,10
const taxInCents = 20;   // R$ 0,20
const totalInCents = priceInCents + taxInCents; // 30 centavos

console.log(totalInCents / 100); // 0.3
```

## Limite de Inteiros Seguros e `BigInt`

Como todos os números convencionais em JavaScript compartilham a representação de 64 bits, apenas 53 bits são reservados para a mantissa. Isso significa que inteiros acima de 2⁵³ - 1 (`Number.MAX_SAFE_INTEGER`, ou `9007199254740991`) perdem a capacidade de representar cada número sucessivo com precisão.

O exemplo a seguir ilustra a perda de precisão com números gigantes:

```js title="Perda de precisão com inteiros não-seguros"
const max = Number.MAX_SAFE_INTEGER; // 9007199254740991

console.log(max + 1 === max + 2); // true (ambos viram 9007199254740992!)

// Solução moderna: utilizar BigInt com o sufixo 'n'
const bigA = 9007199254740991n + 1n;
const bigB = 9007199254740991n + 2n;

console.log(bigA === bigB); // false (precisão arbitrária preservada!)
```

## `Math.min() > Math.max()`

Quando executadas sem nenhum argumento, as funções matemáticas `Math.min()` e `Math.max()` produzem um resultado que parece paradoxal:

```js title="Math.min() e Math.max() sem argumentos"
console.log(Math.min()); // Infinity
console.log(Math.max()); // -Infinity
console.log(Math.min() > Math.max()); // true (Infinity > -Infinity)
```

**Por que isso acontece?**
Para calcular o menor elemento de uma lista de valores, o algoritmo inicia sua variável acumuladora com o maior número possível (`Infinity`). Qualquer número fornecido será menor que `Infinity`. Analogamente, `Math.max()` inicia com `-Infinity`. Ao não receber argumentos, o valor inicial é retornado diretamente.

## Coerções com Objetos e Arrays: `[] + {}` vs `{} + []`

O operador `+` possui regras estritas de conversão: se um dos operandos não for primitivo, o interpretador tenta convertê-lo através dos métodos internos `[Symbol.toPrimitive]`, `valueOf()` e `toString()`.

- `[]` (Array vazio) converte para a string vazia `""`.
- `{}` (Objeto vazio) converte para a string `"[object Object]"`.

O exemplo a seguir demonstra os resultados dessas somas:

```js title="Soma de arrays e objetos literais"
console.log([] + []); // "" (duas strings vazias concatenadas)
console.log([] + {}); // "[object Object]" ("" + "[object Object]")
console.log([1, 2] + [3, 4]); // "1,23,4" (concatena as representações textuais)
```

<Aside type="note" title="{} no início de uma linha no REPL">
  Em alguns consoles ou REPLs, digitar `{}` no início de uma instrução faz com que as chaves sejam interpretadas como um **bloco de código vazio** (e não como objeto). Assim, `{} + []` vira `+[]` (que coage o array vazio para o número `0`). Quando avaliado como expressão regular, `({} + [])` resulta em `"[object Object]"`.
</Aside>

## Objetos Wrapper e Valores Truthy: `new Boolean(false)`

Valores primitivos (`false`, `0`, `""`) são *falsy*. No entanto, instanciar objetos invólucros (*wrappers*) com a palavra-chave `new` cria instâncias no Heap. Em JavaScript, **qualquer objeto é truthy**, independentemente do valor interno que ele envelopa.

O exemplo a seguir demonstra essa armadilha:

```js title="Instanciação de objetos wrapper"
const primitiveBool = false;
const objectBool = new Boolean(false);

console.log(Boolean(primitiveBool)); // false
console.log(Boolean(objectBool));    // true (objetos são sempre truthy!)

if (objectBool) {
  console.log("Este bloco executa mesmo com false dentro do objeto!");
}
```

<Aside type="caution" title="Nunca use new com tipos primitivos">
  Evite `new Boolean()`, `new String()` ou `new Number()`. Para realizar conversões de tipo, invoque a função conversora pura sem `new`: `Boolean(val)`, `String(val)` ou `Number(val)`.
</Aside>

## Igualdade: `==` vs `===`

O operador `==` (igualdade solta) aplica um algoritmo complexo de coerção automática de tipos antes de comparar os valores. O operador `===` (igualdade estrita) compara tipo e valor sem nenhuma conversão prévia.

O fluxo de decisão a seguir orienta a escolha do operador:

<Mermaid title="Escolha do operador de igualdade">
{`
flowchart TD
  A["Preciso comparar valores"] --> B{"Quero conversão automática?"}
  B -->|"Quase nunca"| C["Use === ou !=="]
  B -->|"Caso especial documentado"| D["Use == com comentário claro"]
  C --> E["Converta explicitamente antes, se necessário"]
  D --> F["Exemplo comum: value == null para null ou undefined"]
`}
</Mermaid>

Os exemplos a seguir contrastam os dois operadores:

```js title="Coerções com igualdade solta vs estrita"
console.log(0 == false);        // true (coerção numérica)
console.log("" == false);       // true (coerção numérica de string vazia)
console.log("5" == 5);          // true (coerção de string para número)
console.log(null == undefined); // true (regra especial da especificação)

console.log(0 === false);        // false
console.log("" === false);       // false
console.log("5" === 5);          // false
console.log(null === undefined); // false
```

## O Enigma da Coerção: `a == 1 && a == 2 && a == 3`

Um enigma clássico de entrevistas técnicas pergunta se uma única variável `a` pode satisfazer a seguinte expressão condicional:

```js title="Condicional com comparações sucessivas"
if (a == 1 && a == 2 && a == 3) {
  console.log("Condição satisfeita!");
}
```

À primeira vista, parece uma impossibilidade lógica. No entanto, o operador de igualdade ampla (`==`) aciona a operação abstrata `ToPrimitive` sempre que compara um objeto com um tipo primitivo. Se a variável `a` for um objeto que implementa o método `valueOf()`, esse método será executado a cada uma das três comparações da expressão.

O código a seguir demonstra como obter esse resultado alterando o estado interno do objeto a cada invocação de `valueOf()`:

```js title="Implementação com valueOf mutável"
const a = {
  current: 1,

  valueOf() {
    return this.current++;
  },
};

// 1ª comparação: a == 1 -> a.valueOf() retorna 1 (1 == 1 é true; current vira 2)
// 2ª comparação: a == 2 -> a.valueOf() retorna 2 (2 == 2 é true; current vira 3)
// 3ª comparação: a == 3 -> a.valueOf() retorna 3 (3 == 3 é true; current vira 4)
console.log(a == 1 && a == 2 && a == 3); // true
```

<Aside type="caution" title="Por que a igualdade estrita (===) previne o truque">
  Se utilizarmos igualdade estrita (`a === 1 && a === 2 && a === 3`), a expressão retornará `false` imediatamente. O operador `===` compara valor e tipo sem acionar coerção nem executar `valueOf()`. Como `typeof a` é `"object"` e `1` é `"number"`, a comparação é rejeitada de imediato.
</Aside>

## Soma, Concatenação e Conversão de Entradas

O operador `+` atua como operador de soma ou de concatenação: se qualquer um dos operandos for uma string, todos os demais serão convertidos para texto. Em contrapartida, operadores aritméticos como `-`, `*` e `/` sempre forçam a conversão dos operandos para números.

O exemplo a seguir ilustra a diferença de comportamento dos operadores aritméticos:

```js title="Ambiguidade do operador +"
console.log(5 + 2);     // 7
console.log("5" + 2);   // "52"
console.log(5 + "2");   // "52"
console.log("5" - 2);   // 3 (força número)
console.log("5" * "2"); // 10 (força número)
```

Ao processar valores recebidos de elementos HTML ou formulários, converta explicitamente o texto para número antes de realizar operações matemáticas:

```js title="Tratamento explícito de entradas de formulário"
const quantityInput = "3";
const unitPrice = 25;

const quantity = Number(quantityInput);
const total = quantity * unitPrice;

console.log(total); // 75
```

## Objetos, Arrays e Comparação de Referências

Valores primitivos (números, strings, booleanos) são comparados por **valor**. Objetos, funções e arrays são comparados estritamente por **referência**: dois literais idênticos alocados em posições diferentes da memória nunca serão iguais.

O exemplo a seguir ilustra a comparação por referência na memória:

```js title="Comparação de referências de objetos"
console.log([] === []); // false (referências distintas na memória Heap)
console.log({} === {}); // false

const listA = [1, 2];
const listB = listA;

console.log(listA === listB); // true (ambos apontam para a mesma referência)
```

Para verificar se o conteúdo de dois arrays é equivalente:

```js title="Comparando o conteúdo de arrays"
function areArraysEqual(a, b) {
  return a.length === b.length && a.every((val, i) => val === b[i]);
}

console.log(areArraysEqual([1, 2], [1, 2])); // true
console.log(areArraysEqual([1, 2], [2, 1])); // false
```

## Arrays Esparsos

Um array esparso é um array que contém posições vazias (*holes*). Uma posição vazia é fundamentalmente diferente de uma posição que existe e armazena o valor `undefined`.

O exemplo a seguir demonstra o comportamento de arrays esparsos:

```js title="Buracos em arrays esparsos"
const sparse = [1, , 3];
const explicit = [1, undefined, 3];

console.log(sparse.length);   // 3
console.log(1 in sparse);     // false (o índice 1 não existe no objeto array!)
console.log(1 in explicit);   // true (o índice 1 existe e contém undefined)

sparse.forEach((val) => console.log(val));
// 1
// 3 (a posição vazia é ignorada pelo forEach)
```

Para criar arrays de tamanho pré-definido com valores reais preenchidos, utilize `Array.from()`:

```js title="Criando arrays preenchidos de forma segura"
const scores = Array.from({ length: 3 }, () => 0);
console.log(scores); // [0, 0, 0]
```

## `map()` com `parseInt`: a Armadilha dos Argumentos Extras

Passar `parseInt` diretamente como callback para `.map()` produz resultados surpreendentes porque o método `.map(fn)` repassa três argumentos a cada iteração: `(elemento, índice, array)`.

Por sua vez, `parseInt(string, radix)` aceita como segundo argumento a base numérica (*radix*), que acaba recebendo o índice do array:

```js title="Armadilha clássica: map com parseInt"
console.log(["1", "2", "3"].map(parseInt)); // [1, NaN, NaN]

// O que ocorre internamente em cada passo:
// 1. parseInt("1", 0) -> radix 0 assume base 10 padrão -> 1
// 2. parseInt("2", 1) -> base 1 é matematicamente inválida -> NaN
// 3. parseInt("3", 2) -> "3" não é um dígito válido no sistema binário -> NaN
```

Para converter strings numéricas em um array com total segurança, utilize `Number` ou uma arrow function especificando a base 10:

```js title="Forma segura de mapear números"
console.log(["1", "2", "3"].map(Number)); // [1, 2, 3]
console.log(["1", "2", "3"].map((str) => parseInt(str, 10))); // [1, 2, 3]
```

## Desafio

Crie uma função `safeSum(a, b)` capaz de somar dois valores (números ou strings numéricas), rejeitar entradas não-finitas e comparar o resultado contra um valor esperado utilizando uma tolerância de ponto flutuante:

<details>
  <summary>Possível resposta</summary>

  ```js title="safe-sum.js"
  function toFiniteNumber(value) {
    const number = Number(value);

    if (!Number.isFinite(number)) {
      throw new TypeError(`Valor numérico inválido: ${value}`);
    }

    return number;
  }

  function safeSum(a, b) {
    return toFiniteNumber(a) + toFiniteNumber(b);
  }

  function almostEqual(a, b, tolerance = Number.EPSILON) {
    return Math.abs(a - b) <= tolerance;
  }

  const result = safeSum("0.1", "0.2");

  console.log(result); // 0.30000000000000004
  console.log(almostEqual(result, 0.3)); // true
  ```
</details>

## Perguntas de revisão

### Números e valores especiais

**1. Por que `NaN === NaN` retorna `false`?**

<details>
  <summary>Possível resposta</summary>

  Porque `NaN` representa um resultado numérico inválido ou indefinido e, pela especificação IEEE 754, não é igual a nenhum valor, nem a si mesmo. Para testá-lo, utilize `Number.isNaN(val)` ou `Object.is(val, NaN)`.
</details>

**2. Por que `0.1 + 0.2` não resulta exatamente em `0.3`?**

<details>
  <summary>Possível resposta</summary>

  Porque os números em JavaScript usam ponto flutuante binário (IEEE 754 de 64 bits). Frações como 1/10 e 1/5 tornam-se dízimas periódicas em binário, gerando pequenos resíduos de arredondamento.
</details>

**3. Por que `Math.min() > Math.max()` retorna `true` quando ambas são invocadas sem argumentos?**

<details>
  <summary>Possível resposta</summary>

  Porque `Math.min()` inicializa sua busca com `Infinity` e `Math.max()` inicializa com `-Infinity`. Sem argumentos passados, os valores iniciais são devolvidos, resultando na comparação `Infinity > -Infinity`, que é `true`.
</details>

### Tipos, coerção e referência

**4. Por que `typeof null` retorna `"object"`?**

<details>
  <summary>Possível resposta</summary>

  Por conta de um bug histórico na primeira versão do JavaScript em 1995 (onde o ponteiro nulo compartilhava a tag de tipo de objetos em C), que foi preservado para garantir a compatibilidade com a web existente.
</details>

**5. Por que `[] === []` retorna `false`?**

<details>
  <summary>Possível resposta</summary>

  Porque cada literal de array `[]` aloca uma nova instância distinta na memória Heap. Objetos e arrays são comparados por referência de memória, e não pelo seu conteúdo interno.
</details>

**6. Por que `['1', '2', '3'].map(parseInt)` resulta em `[1, NaN, NaN]`?**

<details>
  <summary>Possível resposta</summary>

  Porque o método `.map()` passa o índice de cada elemento como segundo argumento para o callback. A função `parseInt(string, radix)` interpreta esse índice como a base numérica da conversão, gerando bases inválidas como 1 e 2 para os números subsequentes.
</details>
