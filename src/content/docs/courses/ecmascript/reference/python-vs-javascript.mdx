Este tópico compara **Python** e **JavaScript** para ajudar quem já estudou uma das linguagens a transferir conceitos para a outra. As duas são dinâmicas, populares e multiparadigma, mas nasceram em contextos diferentes e tomam decisões de sintaxe, execução e ecossistema bem distintas.

Materiais: [slides do tópico](../../../../slides/courses/ecmascript/reference/python-vs-javascript/) e [mapa mental](../../../../mindmaps/courses/ecmascript/reference/python-vs-javascript/)

## Objetivo

Comparar JavaScript e Python em modelo de execução, sintaxe, tipagem, valores falsy/truthy, coleções (strings, listas, tuplas, dicionários e conjuntos), funções, orientação a objetos, módulos, assincronismo e APIs nativas. Ao final, você deve conseguir traduzir estruturas comuns entre as duas linguagens, evitar falsas equivalências e escolher a abordagem idiomática adequada em cada ecossistema.

## Panorama Geral

Python e JavaScript são linguagens de alto nível, com tipagem dinâmica e suporte a múltiplos estilos de programação (imperativo, orientado a objetos e funcional). A principal diferença histórica reside no ambiente original: JavaScript nasceu no navegador web para manipular interfaces visuais; Python nasceu como linguagem de script e propósito geral no sistema operacional, consolidando-se em automação, backend, ciência de dados e inteligência artificial.

A tabela a seguir resume as principais características estruturais de cada linguagem:

| Aspecto | Python | JavaScript |
| :--- | :--- | :--- |
| **Origem** | Scripting e propósito geral no SO (1991) | Scripting para navegadores web (1995) |
| **Ambientes clássicos** | Terminal, servidores, scripts e ciência de dados | Navegador (front-end) e Node.js/Bun (backend) |
| **Delimitação de blocos** | Indentação obrigatória por espaços | Chaves `{ ... }` |
| **Final de instrução** | Quebra de linha | Ponto e vírgula `;` (opcional via ASI) |
| **Sistema de tipos** | Dinâmico e forte (sem coerções implícitas perigosas) | Dinâmico e flexível (com coerções implícitas) |
| **Gerenciadores de pacotes** | PyPI via `pip` ou `uv` | npm registry via `npm`, `pnpm` ou `yarn` |
| **Arquivo de manifesto** | `pyproject.toml` ou `requirements.txt` | `package.json` |
| **Estruturas fundamentais** | `list`, `dict`, `set`, `tuple` | `Array`, `Object`, `Map`, `Set` |

<Aside type="note" title="Dinâmica não significa igual">
  Embora ambas descubram os tipos em tempo de execução (*runtime*), Python é fortemente tipada: a tentativa de somar `"Texto" + 10` lança um `TypeError` imediato. Em contrapartida, JavaScript converte o número para string silenciosamente e devolve `"Texto10"`.
</Aside>

## Execução e Ambiente

Python compila o código-fonte `.py` em bytecode, executado sequencialmente pela máquina virtual CPython (PVM). Em JavaScript, motores modernos (como V8 no Chrome/Node.js, JavaScriptCore no Safari e SpiderMonkey no Firefox) utilizam uma arquitetura híbrida: o interpretador (Ignition no V8) compila a árvore sintática (AST) diretamente em **bytecode em memória** para inicialização quase instantânea, enquanto o compilador *Just-In-Time* (TurboFan) compila funções frequentes (*hot code*) em código de máquina nativo para máxima performance.

Em Python, a execução clássica de um script ocorre diretamente pelo terminal:

```py title="hello.py"
name = "Ana"
print(f"Olá, {name}!")
```

Em JavaScript, o mesmo código pode rodar no servidor via Node.js ou interativamente no Console do navegador:

```js title="hello.js"
const name = "Ana";
console.log(`Olá, ${name}!`);
```

<Aside type="tip" title="O ambiente define as APIs disponíveis">
  Em JavaScript, `console.log()` está presente tanto no Node.js quanto no navegador, mas comandos de interface visual como `document.querySelector()` pertencem às Web APIs do navegador. Em Python, manipulação de arquivos com `open()` e variáveis de ambiente com `os` integram a biblioteca padrão da linguagem.
</Aside>

## Sintaxe e Estruturas de Controle

Python e JavaScript adotam filosofias divergentes tanto na organização física dos blocos quanto na interpretação lógica de valores em condicionais.

### Delimitação de Blocos e Operadores Lógicos

Python estrutura seu fluxo de código através de **indentação obrigatória por espaços**. JavaScript utiliza **chaves `{}`** para delimitar blocos lógicos e parênteses `(...)` para envolver as expressões condicionais, tornando a indentação uma convenção visual para legibilidade humana.

O exemplo a seguir compara uma estrutura de decisão condicional:

```py title="Python: controle por indentação"
score = 8.5

if score >= 9.0:
    print("Excelente")
elif score >= 7.0:
    print("Aprovado")
else:
    print("Recuperação")
```

Em JavaScript, parênteses e chaves delimitam a condição e o bloco de execução:

```js title="JavaScript: controle por chaves"
const score = 8.5;

if (score >= 9.0) {
  console.log("Excelente");
} else if (score >= 7.0) {
  console.log("Aprovado");
} else {
  console.log("Recuperação");
}
```

A tabela a seguir correlaciona os operadores lógicos e estruturas sintáticas fundamentais:

| Recurso | Python | JavaScript |
| :--- | :--- | :--- |
| **Comentário de linha** | `# comentário` | `// comentário` |
| **Comentário multilinha** | `""" docstring / bloco """` | `/* comentário */` |
| **Interpolação de texto** | `f"Olá, {nome}"` | `` `Olá, ${nome}` `` |
| **Condicional if / elif / else** | `if / elif / else:` | `if / else if / else { ... }` |
| **Operador E lógico** | `and` | `&&` |
| **Operador OU lógico** | `or` | `\|\|` |
| **Operador NÃO lógico** | `not` | `!` |
| **Operador de coalescência nula** | `val if val is not None else fallback` | `val ?? fallback` |
| **Operador ternário** | `resultado if cond else fallback` | `cond ? resultado : fallback` |

### A Armadilha dos Valores Falsy e Truthy

A interpretação booleana de valores vazios representa uma das maiores fontes de confusão entre quem transita entre Python e JavaScript:

| Valor Testado | Booleano em Python | Booleano em JavaScript |
| :--- | :--- | :--- |
| **Zero numérico** (`0`, `0.0`, `-0`) | `False` | `false` |
| **String vazia** (`""`) | `False` | `false` |
| **Ausência de valor** | `None` → `False` | `null` e `undefined` → `false` |
| **Não-número** (`NaN`) | `float('nan')` → `True` | `NaN` → `false` |
| **Lista / Array vazio** (`[]`) | **`False`** (coleções vazias são falsy) | **`true`** (qualquer objeto/array é truthy!) |
| **Dicionário / Objeto vazio** (`{}`) | **`False`** (coleções vazias são falsy) | **`true`** (qualquer objeto/array é truthy!) |

<Aside type="caution" title="Coleções vazias são Truthy em JavaScript!">
  Em Python, é idiomático checar `if not items:` para verificar se uma lista está vazia. Em JavaScript, `Boolean([])` é `true`! Para verificar arrays vazios em JS, você **deve** checar o tamanho: `if (items.length === 0)`.
</Aside>

## Tipos, Coerções e Operadores de Igualdade

Ambas as linguagens são de tipagem dinâmica, descobrindo tipos em tempo de execução, mas tratam coerções e testes de equivalência de formas opostas.

### Tipagem Forte versus Coerção Implícita

Python emprega **tipagem forte**, o que significa que o interpretador recusa operações entre tipos incompatíveis sem uma conversão explícita prévia via funções como `str()`, `int()` ou `float()`. Em contrapartida, JavaScript possui **tipagem fraca/flexível**, realizando coerções automáticas em operações com operadores aritméticos como `+`, `-` ou `*`.

O exemplo a seguir ilustra o comportamento de soma e concatenação em Python:

```py title="Python: conversão estrita e explícita"
price = 50

# print("Total: " + price)
# TypeError: can only concatenate str (not "int") to str

print("Total: " + str(price)) # "Total: 50"
```

Em JavaScript, o operador `+` prioriza a concatenação de strings sempre que um dos operandos for string, enquanto operadores aritméticos como `-` coagem strings numéricas para números:

```js title="JavaScript: coerções implícitas"
const price = 50;

console.log("Total: " + price); // "Total: 50" (converte 50 para string)
console.log("100" - 20);         // 80 (converte "100" para número)
console.log("100" + 20);         // "10020" (concatena texto!)
```

### Operadores de Igualdade e Comparação de Referência

A checagem de igualdade exige atenção redobrada: em Python, o operador `==` compara valores por equivalência semântica e `is` compara a identidade física do objeto na memória. Em JavaScript, adote sempre a igualdade estrita `===` (que verifica valor e tipo sem coerção) para evitar conversões indesejadas:

```py title="Python: == (valor) vs is (identidade)"
list_a = [1, 2]
list_b = [1, 2]

print(list_a == list_b) # True (valores idênticos)
print(list_a is list_b) # False (instâncias distintas na memória)
```

```js title="JavaScript: === (estrito) vs == (frouxo)"
console.log(42 == "42");  // true (coerção implícita - EVITE!)
console.log(42 === "42"); // false (tipos distintos: number vs string)

const arrA = [1, 2];
const arrB = [1, 2];
console.log(arrA === arrB); // false (compara referências de memória)
```

## Coleções e Estruturas de Dados

As duas linguagens contam com estruturas para coleções ordenadas, conjuntos únicos e mapas de chave-valor, embora as APIs idiomáticas e métodos disponíveis variem.

### Strings: `str` vs `String`

Strings são sequências primitivas imutáveis em ambas as linguagens. Todos os métodos de transformação produzem novas instâncias sem alterar a string original:

| Operação | Python `str` | JavaScript `String` |
| :--- | :--- | :--- |
| **Comprimento** | `len(text)` | `text.length` |
| **Acesso por índice** | `text[0]` ou `text[-1]` | `text[0]` ou `text.at(-1)` |
| **Fatiamento** | `text[0:4]` | `text.slice(0, 4)` |
| **Minúsculas / Maiúsculas** | `text.lower()`, `text.upper()` | `text.toLowerCase()`, `text.toUpperCase()` |
| **Remover espaços pontas** | `text.strip()` | `text.trim()` |
| **Verificar prefixo / sufixo**| `text.startswith("A")`, `text.endswith(".js")` | `text.startsWith("A")`, `text.endsWith(".js")` |
| **Verificar substring** | `"dev" in text` | `text.includes("dev")` |
| **Localizar índice** | `text.find("sub")` | `text.indexOf("sub")` |
| **Substituição** | `text.replace("antigo", "novo")` | `text.replace("antigo", "novo")` ou `text.replaceAll(...)` |
| **Divisão em lista** | `text.split(",")` | `text.split(",")` |
| **Junção de coleção** | `", ".join(items)` | `items.join(", ")` |

O exemplo a seguir demonstra o encadeamento de transformações em strings:

```py title="Python: limpeza e junção de strings"
raw = "  JavaScript,Python,TypeScript  "
items = [item.strip().lower() for item in raw.split(",")]

print(items)             # ['javascript', 'python', 'typescript']
print(" / ".join(items)) # javascript / python / typescript
```

Em JavaScript, obtemos o mesmo resultado através de métodos encadeados:

```js title="JavaScript: limpeza e junção de strings"
const raw = "  JavaScript,Python,TypeScript  ";
const items = raw
  .split(",")
  .map((item) => item.trim().toLowerCase());

console.log(items);             // [ 'javascript', 'python', 'typescript' ]
console.log(items.join(" / ")); // javascript / python / typescript
```

<Aside type="caution" title="length conta unidades UTF-16, não caracteres visuais">
  Em JavaScript, `string.length` conta unidades de código UTF-16 de 16 bits. Emojis e símbolos complexos (como `"😀"`) ocupam 2 unidades (`"😀".length === 2`), enquanto em Python 3 `len("😀")` retorna `1`. Para contar caracteres Unicode reais em JavaScript, utilize a desestruturação com spread `[..."😀"].length` ou `Intl.Segmenter`.
</Aside>

### Sequências Mutáveis: `list` vs `Array`

Em Python, a `list` costuma ser manipulada com funções globais (`len()`, `sorted()`) e *list comprehensions*. Em JavaScript, o `Array` utiliza métodos de alta ordem (`map()`, `filter()`, `reduce()`) encadeados:

| Operação | Python `list` | JavaScript `Array` |
| :--- | :--- | :--- |
| **Tamanho** | `len(items)` | `items.length` |
| **Acesso por índice direto** | `items[0]` | `items[0]` ou `items.at(0)` |
| **Acesso relativo (do fim)** | `items[-1]`, `items[-2]` | `items.at(-1)`, `items.at(-2)` |
| **Inserir no final** | `items.append(val)` | `items.push(val)` |
| **Remover do final** | `items.pop()` | `items.pop()` |
| **Inserir no início** | `items.insert(0, val)` | `items.unshift(val)` |
| **Remover do início** | `items.pop(0)` | `items.shift()` |
| **Concatenar listas** | `items.extend(outros)` ou `items + outros` | `items.push(...outros)` ou `[...items, ...outros]` |
| **Filtrar elementos** | `[x for x in items if cond(x)]` | `items.filter(cond)` |
| **Transformar elementos**| `[fn(x) for x in items]` | `items.map(fn)` |
| **Acumular valores** | `functools.reduce(fn, items, init)` | `items.reduce(fn, init)` |
| **Ordenar mutando** | `items.sort()` | `items.sort((a, b) => a - b)` |
| **Ordenar sem mutar** | `sorted(items)` | `items.toSorted((a, b) => a - b)` |

O exemplo a seguir compara um pipeline de processamento em ambas as linguagens:

```py title="Python: processamento com List Comprehension"
numbers = [1, 2, 3, 4, 5, 6]
evens_doubled = [n * 2 for n in numbers if n % 2 == 0]

print(evens_doubled) # [4, 8, 12]
```

Em JavaScript, o mesmo pipeline combina métodos funcionais de array:

```js title="JavaScript: processamento com filter e map"
const numbers = [1, 2, 3, 4, 5, 6];
const evensDoubled = numbers
  .filter((n) => n % 2 === 0)
  .map((n) => n * 2);

console.log(evensDoubled); // [ 4, 8, 12 ]
```

<Aside type="caution" title="sort() em JavaScript ordena como texto por padrão">
  O método `array.sort()` de JavaScript converte valores em strings antes de ordenar se você não fornecer uma função de comparação. Para ordenar números corretamente, utilize sempre `array.sort((a, b) => a - b)` ou a versão imutável `array.toSorted((a, b) => a - b)`.
</Aside>

O acesso a elementos contando a partir do final da sequência ilustra uma diferença conceitual marcante entre os modelos das duas linguagens. Enquanto Python aceita números inteiros negativos diretamente na indexação por colchetes (`items[-1]`), em JavaScript a sintaxe `items[-1]` busca a chave textual `"-1"` no objeto do array e resulta silenciosamente em `undefined`.

Para exemplificar o comportamento do acesso relativo em ambas as linguagens:

```py title="Python: índices negativos diretos"
fruits = ["maçã", "banana", "laranja", "uva"]

print(fruits[0])   # maçã (primeiro elemento)
print(fruits[-1])  # uva (último elemento)
print(fruits[-2])  # laranja (penúltimo elemento)
```

Em JavaScript moderno (ES2022+), o método nativo `.at()` introduz paridade com essa funcionalidade, aceitando números inteiros positivos e negativos tanto em arrays quanto em strings:

```js title="JavaScript: acesso relativo com .at()"
const fruits = ["maçã", "banana", "laranja", "uva"];

console.log(fruits[0]);    // "maçã"
console.log(fruits.at(0)); // "maçã"

// Acesso relativo a partir do fim:
console.log(fruits.at(-1)); // "uva"
console.log(fruits.at(-2)); // "laranja"

// Armadilha dos colchetes em JavaScript:
console.log(fruits[-1]); // undefined (procura a chave literal "-1")
```

<Aside type="tip" title="Sintaxe legada versus método .at()">
  Antes da padronização do ES2022, o acesso ao último item de um array em JavaScript exigia o cálculo manual `fruits[fruits.length - 1]`. O método `.at(-1)` elimina essa redundância de forma concisa e opera de maneira equivalente em strings, como em `"DevLab".at(-1)`, que retorna `"b"`.
</Aside>

### Fatiamento: *slicing* de Python versus `slice()` de JavaScript

O fatiamento é a diferença mais visível entre as duas linguagens no trato com sequências, porque em Python ele é **sintaxe** e em JavaScript é **método**. A notação `items[inicio:fim:passo]` vale para qualquer sequência de Python (`list`, `str`, `tuple`, `bytes` e `range`), enquanto o `slice()` de JavaScript existe apenas em `Array` e `String`, e não tem parâmetro de passo.

A tabela abaixo alinha as operações equivalentes. Repare que as três últimas linhas não têm tradução direta: é onde o modelo de Python é mais expressivo.

| Operação | Python `list` | JavaScript `Array` |
| :--- | :--- | :--- |
| **Intervalo (fim exclusivo)** | `items[1:4]` | `items.slice(1, 4)` |
| **Do início até N** | `items[:3]` | `items.slice(0, 3)` |
| **De N até o fim** | `items[2:]` | `items.slice(2)` |
| **Contado a partir do fim** | `items[-2:]` | `items.slice(-2)` |
| **Cópia rasa completa** | `items[:]` | `items.slice()` ou `[...items]` |
| **Passo (*step*)** | `items[::2]` | Sem equivalente: `items.filter((_, i) => i % 2 === 0)` |
| **Inverter a sequência** | `items[::-1]` | `items.toReversed()` |
| **Substituir uma faixa** | `items[1:3] = ["X", "Y", "Z"]` | `items.splice(1, 2, "X", "Y", "Z")` (muta) |
| **Remover uma faixa** | `del items[1:3]` | `items.splice(1, 2)` (muta) |

Em Python, a fatia é uma expressão que também pode ocupar o lado esquerdo de uma atribuição, e nesse caso o comprimento da lista muda conforme o número de itens fornecidos:

```py title="Python: fatiamento com passo e atribuição em fatia"
items = ["a", "b", "c", "d", "e", "f"]

print(items[1:4])   # ['b', 'c', 'd']
print(items[-2:])   # ['e', 'f']
print(items[::2])   # ['a', 'c', 'e']  (passo 2)
print(items[::-1])  # ['f', 'e', 'd', 'c', 'b', 'a']  (invertido)

# A fatia como alvo de atribuição altera o comprimento da lista
items[1:3] = ["X", "Y", "Z"]
print(items, len(items))  # ['a', 'X', 'Y', 'Z', 'd', 'e', 'f'] 7
```

Em JavaScript, o recorte simples é feito por `slice()`, que **não** altera o original. Já a substituição de uma faixa exige `splice()`, que muta o array e devolve os elementos removidos:

```js title="JavaScript: slice para recortar e splice para substituir"
const items = ["a", "b", "c", "d", "e", "f"];

console.log(items.slice(1, 4)); // [ 'b', 'c', 'd' ]
console.log(items.slice(-2)); // [ 'e', 'f' ]
console.log(items.filter((_, i) => i % 2 === 0)); // [ 'a', 'c', 'e' ]
console.log(items.toReversed()); // [ 'f', 'e', 'd', 'c', 'b', 'a' ]

// splice muta o array original e devolve o que foi retirado
const copy = [...items];
console.log(copy.splice(1, 2, "X", "Y", "Z")); // [ 'b', 'c' ]  (removidos)
console.log(copy, copy.length); // [ 'a', 'X', 'Y', 'Z', 'd', 'e', 'f' ] 7
```

Note que `splice()` recebe **posição e quantidade** (`1, 2`), enquanto a fatia de Python recebe **início e fim** (`1:3`). Essa diferença de contrato é a origem de boa parte dos erros de quem alterna entre as duas linguagens.

<Aside type="caution" title="slice não é splice">
  Em JavaScript, `slice()` e `splice()` têm nomes quase idênticos e comportamentos opostos: `slice()` é acessor e devolve uma cópia do recorte, enquanto `splice()` é mutador, altera o array original e devolve os elementos removidos. Python não tem esse par ambíguo, porque usa a mesma notação de fatia para ler, substituir e remover.
</Aside>

<Aside type="tip" title="Índices fora do intervalo não geram erro">
  Nas duas linguagens, o fatiamento tolera limites fora da faixa e devolve uma sequência vazia em vez de lançar exceção: `items[10:20]` em Python e `items.slice(10, 20)` em JavaScript resultam em `[]`. O mesmo vale quando o início é maior que o fim, como em `items[4:2]`. Esse comportamento contrasta com o acesso por índice único, que em Python lança `IndexError` e em JavaScript devolve `undefined`.
</Aside>

### Sequências Imutáveis: `tuple` vs Array Imutável

Python disponibiliza nativamente o tipo `tuple` (como `point = (10, 20)`), uma sequência ordenada imutável e com hash, muito usada para retornos múltiplos de funções e chaves compostas em dicionários.

Em JavaScript, não há tipo primitivo de tupla embutido. As convenções equivalentes são:
- Retornos múltiplos via arrays desestruturados: `const [x, y] = getCoordinates();`
- Imutabilidade via congelamento: `const point = Object.freeze([10, 20]);`
- Em TypeScript: anotações de tupla tipada como `const point: readonly [number, number] = [10, 20];`

### Chave-Valor: `dict` vs `Object` e `Map`

O `dict` de Python representa tabelas de dispersão dinâmicas. Em JavaScript, existem duas opções complementares:
1. **`Object` literal (`{}`):** Ideal para registros com propriedades e esquemas estruturados.
2. **`Map`:** Ideal para dicionários dinâmicos com chaves de qualquer tipo (números, objetos, booleanos) e operações frequentes de inserção/deleção.

| Operação | Python `dict` | JavaScript `Object` | JavaScript `Map` |
| :--- | :--- | :--- | :--- |
| **Criação** | `d = {"a": 1}` | `const obj = { a: 1 };` | `const map = new Map();` |
| **Leitura** | `d["a"]` ou `d.get("a", 0)` | `obj.a` ou `obj.a ?? 0` | `map.get("a") ?? 0` |
| **Escrita** | `d["b"] = 2` | `obj.b = 2;` | `map.set("b", 2);` |
| **Remoção** | `del d["a"]` | `delete obj.a;` | `map.delete("a");` |
| **Checar chave** | `"a" in d` | `Object.hasOwn(obj, "a")` | `map.has("a")` |
| **Listar chaves** | `d.keys()` | `Object.keys(obj)` | `map.keys()` |
| **Listar valores** | `d.values()` | `Object.values(obj)` | `map.values()` |
| **Listar pares** | `d.items()` | `Object.entries(obj)` | `map.entries()` |

O exemplo a seguir demonstra o uso de `Object` como registro e `Map` como dicionário de contagem dinâmica:

```js title="JavaScript: Object como registro e Map como contador dinâmico"
// 1. Objeto literal para dados estruturados
const user = { name: "Ana", role: "developer" };
console.log(user.name); // "Ana"

// 2. Map para contagem dinâmica de ocorrências
const accessCounts = new Map();
accessCounts.set("login", 1);
accessCounts.set("login", (accessCounts.get("login") ?? 0) + 1);

console.log(accessCounts.get("login")); // 2
console.log(accessCounts.has("logout")); // false
```

### Conjuntos: `set` vs `Set`

Ambas as linguagens contam com coleções de valores únicos sem duplicatas:

| Operação | Python `set` | JavaScript `Set` |
| :--- | :--- | :--- |
| **Criação** | `s = {1, 2, 3}` | `const s = new Set([1, 2, 3]);` |
| **Tamanho** | `len(s)` | `s.size` |
| **Adicionar** | `s.add(4)` | `s.add(4);` |
| **Remover** | `s.remove(1)` ou `s.discard(1)` | `s.delete(1);` |
| **Checar presença** | `1 in s` | `s.has(1)` |
| **União** | `a \| b` ou `a.union(b)` | `new Set([...a, ...b])` |
| **Interseção** | `a & b` ou `a.intersection(b)` | `new Set([...a].filter((x) => b.has(x)))` |
| **Diferença** | `a - b` ou `a.difference(b)` | `new Set([...a].filter((x) => !b.has(x)))` |

O exemplo a seguir compara operações de conjuntos:

```py title="Python: operações com conjuntos"
frontend = {"html", "css", "javascript"}
backend = {"javascript", "sql", "python"}

print(frontend | backend) # União: {'html', 'css', 'javascript', 'sql', 'python'}
print(frontend & backend) # Interseção: {'javascript'}
print(frontend - backend) # Diferença: {'html', 'css'}
```

Em JavaScript, as operações podem ser realizadas com sintaxe de espalhamento (*spread*) ou com os novos métodos de `Set` (ECMAScript 2024 / Node.js 22+):

```js title="JavaScript: operações com Set"
const frontend = new Set(["html", "css", "javascript"]);
const backend = new Set(["javascript", "sql", "python"]);

const union = new Set([...frontend, ...backend]);
const intersection = new Set([...frontend].filter((item) => backend.has(item)));
const difference = new Set([...frontend].filter((item) => !backend.has(item)));

console.log([...union]);        // [ 'html', 'css', 'javascript', 'sql', 'python' ]
console.log([...intersection]); // [ 'javascript' ]
console.log([...difference]);   // [ 'html', 'css' ]
```

## Funções e Escopo

Em ambas as linguagens, funções são cidadãs de primeira classe: podem ser atribuídas a variáveis, recebidas como argumentos (*callbacks*) e devolvidas como retorno por outras funções.

### Declaração de Funções e Sintaxe Anônima

Python define funções com a palavra-chave `def` e suporta funções anônimas de linha única via `lambda`. JavaScript oferece funções tradicionais com a palavra-chave `function` e funções anônimas enxutas via *Arrow Functions* (`=>`), que suportam corpos com múltiplas instruções e retenção léxica de contexto.

O exemplo a seguir compara a sintaxe de funções nomeadas e anônimas em Python:

```py title="Python: def e lambda"
# Função tradicional
def calculate_total(price, tax=0.1):
    return price * (1 + tax)

# Função anônima (limitada a uma única expressão)
double = lambda x: x * 2

print(calculate_total(100)) # 110.0
print(double(5))            # 10
```

Em JavaScript, *Arrow Functions* oferecem sintaxe enxuta e suporte a corpos com múltiplas instruções:

```js title="JavaScript: function e arrow function"
// Função tradicional
function calculateTotal(price, tax = 0.1) {
  return price * (1 + tax);
}

// Arrow function concisa com retorno implícito
const double = (x) => x * 2;

console.log(calculateTotal(100)); // 110
console.log(double(5));            // 10
```

### Argumentos Variáveis e Regras de Escopo

Além da sintaxe de declaração, o empacotamento de parâmetros excedentes e o confinamento de variáveis em blocos condicionais e laços exibem regras distintas:

| Recurso | Python | JavaScript |
| :--- | :--- | :--- |
| **Parâmetros posicionais extras** | `*args` (tupla) | `...rest` (Array legítimo) |
| **Parâmetros nomeados extras** | `**kwargs` (dicionário) | Desestruturação de opções: `{ a, b } = {}` |
| **Escopo de bloco** | Não (`if` e `for` não criam escopo novo) | Sim (`let` e `const` respeitam blocos `{}`) |
| **Closures e estado privado** | Suportado (`nonlocal`) | Suportado nativamente via escopo léxico |

O exemplo a seguir demonstra a diferença de escopo em laços de repetição:

```py title="Python: variável de loop vaza para o escopo externo"
for i in range(3):
    pass

print(i) # 2 (a variável i continua existindo no escopo da função/módulo!)
```

Em JavaScript, variáveis declaradas com `let` ou `const` ficam estritamente confinadas ao bloco do laço:

```js title="JavaScript: escopo de bloco com let"
for (let i = 0; i < 3; i++) {
  // i existe apenas aqui dentro
}

// console.log(i); // ReferenceError: i is not defined
```

## Classes e Orientação a Objetos

Em Python, a orientação a objetos expõe explicitamente o ponteiro da instância através do parâmetro `self` em todos os métodos de instância. Em JavaScript, classes utilizam a palavra-chave `class`, métodos recebem `this` implicitamente pelo contexto de execução e o método construtor se chama `constructor()`.

O exemplo a seguir compara a criação de uma classe com método e herança:

```py title="Python: classe e herança"
class Account:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount
        return self.balance

account = Account("Ana", 100)
account.deposit(50)
print(f"{account.owner}: R$ {account.balance}") # Ana: R$ 150
```

Em JavaScript, `this` substitui `self`, sem a necessidade de ser declarado na assinatura dos métodos:

```js title="JavaScript: classe e construtor"
class Account {
  constructor(owner, balance = 0) {
    this.owner = owner;
    this.balance = balance;
  }

  deposit(amount) {
    this.balance += amount;
    return this.balance;
  }
}

const account = new Account("Ana", 100);
account.deposit(50);
console.log(`${account.owner}: R$ ${account.balance}`); // Ana: R$ 150
```

## Módulos e Ecossistema

Ambos os ecossistemas utilizam importações para modularizar aplicações, mas a declaração de dependências e a estrutura de pacotes refletem suas ferramentas:

```py title="Python: importação e módulos"
# Importar módulo inteiro
import math
print(math.sqrt(16)) # 4.0

# Importar símbolos nomeados
from datetime import datetime
print(datetime.now())
```

Em JavaScript Moderno (ESM), usamos as palavras-chave `import` e `export`:

```js title="JavaScript: ESM (ECMAScript Modules)"
// Importar símbolos nomeados
import { readFile } from "node:fs/promises";

// Exportação nomeada e default

export default class Application {}
```

| Aspecto | Python | JavaScript |
| :--- | :--- | :--- |
| **Padrão oficial** | Módulos `.py` no `sys.path` | ECMAScript Modules (`import` / `export`) |
| **Repositório oficial** | PyPI (*Python Package Index*) | npm (*Node Package Manager Registry*) |
| **Ferramentas modernas** | `uv`, `pip`, `poetry` | `pnpm`, `npm`, `yarn` |
| **Arquivo de metadados** | `pyproject.toml` ou `requirements.txt` | `package.json` |

## Assincronismo e Concorrência

Em Python, o código síncrono é o padrão clássico. A biblioteca padrão disponibiliza `asyncio` para operações assíncronas baseadas em *coroutines* que exigem a inicialização explícita de um loop (`asyncio.run()`).

Em JavaScript, o modelo de execução em thread única baseia-se nativamente no **Event Loop**. Operações de entrada/saída (I/O, requisições HTTP e temporizadores) são não-bloqueantes por natureza, integrando Promises e a sintaxe `async/await` no núcleo da linguagem.

```py title="Python: assincronismo com asyncio"
import asyncio

async def fetch_user():
    await asyncio.sleep(0.1) # Simula I/O de rede
    return {"id": 1, "name": "Ana"}

async def main():
    user = await fetch_user()
    print(user)

asyncio.run(main())
```

Em JavaScript, chamadas assíncronas devolvem `Promise` e dispensam a criação manual de loop de eventos:

```js title="JavaScript: assincronismo nativo com async/await"
const fetchUser = async () => {
  // Simula I/O assíncrono
  await new Promise((resolve) => setTimeout(resolve, 100));
  return { id: 1, name: "Ana" };
};

const main = async () => {
  const user = await fetchUser();
  console.log(user);
};

main();
```

## Recursos Exclusivos de Cada Linguagem

As seções anteriores compararam construções que existem dos dois lados, com sintaxe diferente. Esta reúne o oposto: recursos que **não têm equivalente direto** na outra linguagem, e que por isso costumam ser o ponto de atrito de quem migra.

Conhecer essa lista evita dois erros comuns em direções opostas. O primeiro é procurar em JavaScript um recurso que só existe em Python, como o passo do fatiamento, e concluir que a linguagem é limitada quando na verdade a solução é outra. O segundo é escrever Python com hábitos de JavaScript, como confiar em coerção implícita, e receber `TypeError` em produção.

### Exclusivos do Python

A força do Python está na expressividade sintática: boa parte do que segue é açúcar de sintaxe que o interpretador reconhece, e não método de biblioteca. A última coluna diz o que fazer em JavaScript quando o recurso é necessário.

| Recurso | O que faz | Situação em JavaScript |
| :--- | :--- | :--- |
| **Fatiamento com passo** (`items[::2]`) | Recorta qualquer sequência com início, fim e passo. | Não existe: exige `filter()` por índice ou `toReversed()`. |
| **Atribuição em fatia** (`items[1:3] = [...]`) | Substitui uma faixa e pode alterar o comprimento. | Só com `splice()`, que muta e tem contrato diferente. |
| **Compreensões** (`[x for x in y if c]`) | Constrói listas, dicionários e conjuntos declarativamente. | Encadeamento `filter().map()`; não há forma literal. |
| **Sobrecarga de operadores** (`__add__`, `__eq__`) | Redefine `+`, `==` e `<` para tipos próprios. | Não existe: apenas `Symbol.toPrimitive` influencia coerção. |
| **Herança múltipla com MRO** | Uma classe herda de várias, com ordem de resolução definida. | A cadeia de protótipos é única; usa-se composição ou *mixins*. |
| **Decoradores** (`@cache`) | Sintaxe para envolver funções e classes. | Proposta em estágio 3: não roda sem transpilação. |
| **Argumentos nomeados** (`f(nome="Ana")`) | Parâmetros por nome, com obrigatoriedade via `*`. | Convenção com objeto desestruturado: `f({ nome })`. |
| **Comparação encadeada** (`1 < x < 10`) | Dois limites em uma única expressão relacional. | Exige `1 < x && x < 10`. |
| **`for...else` e `while...else`** | Bloco executado quando o laço termina sem `break`. | Não existe: exige uma variável de controle. |
| **Inteiros de precisão arbitrária** | `2 ** 200` continua sendo um `int` comum. | Requer o tipo separado `BigInt` e o sufixo `n`. |
| **Números complexos** (`3 + 4j`) | Tipo numérico nativo da linguagem. | Não existe em nenhuma forma nativa. |
| **`tuple` nativa** | Sequência imutável e *hashable*, usável como chave de `dict`. | `Object.freeze([...])` por convenção, sem *hash*. |

O trecho a seguir reúne quatro desses recursos em um exemplo executável:

```py title="Python: recursos sem equivalente direto em JavaScript"
# 1. Comparação encadeada
age = 25
print(1 < age < 100)  # True

# 2. Sobrecarga de operadores
class Point:
    def __init__(self, x):
        self.x = x

    def __add__(self, other):
        return Point(self.x + other.x)

    def __repr__(self):
        return f"Point({self.x})"

print(Point(1) + Point(2))  # Point(3)

# 3. Inteiro de precisão arbitrária, sem tipo especial
print(2 ** 200)  # 1606938044258990275541962092341162602522202993782792835301376

# 4. Argumentos nomeados obrigatórios
def register(*, name, role="viewer"):
    return f"{name}/{role}"

print(register(name="Ana"))  # Ana/viewer
```

### Exclusivos do JavaScript

Do lado do JavaScript, a maior parte dos recursos exclusivos vem de duas origens: o modelo de objetos por protótipos e a necessidade histórica de nunca interromper a página do usuário, que produziu a coerção implícita e o modelo assíncrono embutido na linguagem.

| Recurso | O que faz | Situação em Python |
| :--- | :--- | :--- |
| **Herança por protótipos** | Objetos delegam a outros objetos em tempo de execução. | Herança por classes, com MRO definido na declaração. |
| **`undefined` além de `null`** | Dois valores distintos para ausência de valor. | Apenas `None`. |
| **Coerção implícita** (`"5" * 2` é `10`) | Converte tipos automaticamente em operações mistas. | Tipagem forte: `"5" * 2` repete a string e `"5" + 2` lança `TypeError`. |
| **Valores *truthy* e *falsy*** | `""`, `0`, `NaN`, `null` e `undefined` são falsos. | Regra análoga, mas sem `undefined` e sem `NaN` como falso. |
| **`?.` e `??`** | Acesso seguro e coalescência que só reage a `null`/`undefined`. | Não há operador: usa-se `dict.get()`, `or` ou `try/except`. |
| **`Proxy` e `Reflect`** | Intercepta leitura, escrita, remoção e chamada de objetos. | `__getattr__` e `__setattr__` cobrem parte do caso. |
| **Símbolos e *well-known symbols*** | Chaves únicas que servem de gancho de protocolo. | Os métodos *dunder* cumprem papel equivalente. |
| **Template literals com tag** | A função recebe partes literais e interpoladas separadas. | *f-strings* não permitem interceptar a interpolação. |
| **Ligações vivas em módulos ES** | O `import` reflete reatribuições feitas no módulo de origem. | `from x import y` copia a referência no momento do import. |
| **Assincronismo na própria linguagem** | `Promise` e `async` fazem parte do núcleo, sobre um *event loop*. | Requer o módulo `asyncio` da biblioteca padrão. |
| ***Hoisting* e TDZ** | Declarações são elevadas; `let` e `const` ficam em zona morta. | Não existe: o nome só passa a existir após a atribuição. |
| **Execução nativa no navegador** | Única linguagem executada pelo cliente sem intermediários. | Só no navegador via WebAssembly, como no Pyodide. |

O exemplo abaixo demonstra quatro comportamentos que não se reproduzem em Python:

```js title="JavaScript: recursos sem equivalente direto em Python"
// 1. Coerção implícita muda o resultado conforme o operador
console.log("5" * 2); // 10   (coage para número)
console.log("5" + 2); // "52" (coage para string)

// 2. Dois valores distintos para ausência
let declared;
console.log(typeof declared, declared === null); // "undefined" false

// 3. Encadeamento opcional e coalescência nula
const config = {};
console.log(config?.server?.port); // undefined, sem lançar erro
console.log(config.retries ?? 3); // 3 (o zero seria preservado)

// 4. Template literal com tag recebe partes e valores separados
function inspect(parts, ...values) {
  return { partes: parts.raw, valores: values };
}

const user = "Ana";
console.log(inspect`Olá ${user}, você tem ${25} anos!`);
// { partes: [ 'Olá ', ', você tem ', ' anos!' ], valores: [ 'Ana', 25 ] }
```

<Aside type="note" title="A fronteira muda a cada edição da especificação">
  Nem toda diferença é permanente. O gerenciamento explícito de recursos, por exemplo, já deixou de ser exclusividade do Python: o `with` da linguagem tem hoje equivalente em JavaScript na declaração `using`, com `Symbol.dispose`, disponível no Node.js 24. Da mesma forma, `.at(-1)` aproximou os arrays da indexação negativa, e os *Iterator Helpers* do ES2025 trouxeram para JavaScript a avaliação preguiçosa que já existia nos geradores de Python.
</Aside>

<Aside type="caution" title="Dica de IA: O sotaque de Python que aparece no JavaScript gerado">
  Esta é a comparação com efeito mais direto na revisão de código gerado por IA. Modelos treinam nas duas linguagens e vazam construções de uma na outra: `len(lista)` no lugar de `lista.length`, `range(10)` em vez de `Array.from({ length: 10 }, (_, i) => i)`, `items[::-1]` no lugar de `toReversed()`, `//` como divisão inteira quando em JavaScript é comentário, e `is` no lugar de `===`. Em expressões regulares o vazamento é ainda mais comum, com `\A`, `\z` e *flags* embutidas `(?i)`, que não existem no motor do JavaScript. A maior parte quebra na primeira execução; a divisão inteira e os escapes de RegExp, não.

## Resumo e Boas Práticas

Esta seção sintetiza os principais pontos de atenção para evitar falsas equivalências ao alternar entre Python e JavaScript.

### Modelo Mental e Execução

- Reconheça o ambiente de destino: JavaScript foi concebido para o navegador e estendeu-se ao backend (Node.js); Python é nativo do sistema operacional, scripts e análise de dados.
- Lembre-se de que blocos em Python dependem estritamente da indentação, enquanto JavaScript requer chaves `{ ... }`.
- Python é fortemente tipado em runtime (rejeita operações incoerentes); JavaScript realiza coerções implícitas: utilize sempre o comparador estrito `===`.
- **Cuidado crítico com truthy/falsy**: em JavaScript, `[]` e `{}` são **truthy**. Sempre teste `.length === 0` para arrays e `Object.keys(obj).length === 0` para objetos.

### Tipos, Coerções e Coleções

- Para listas ordenadas, use `list` em Python (com *list comprehensions*) e `Array` em JavaScript (com `filter`, `map`, `reduce` e `toSorted`).
- Para obter elementos a partir do fim em JavaScript, utilize sempre o método nativo `.at(-1)`, evitando a sintaxe `arr[-1]`, que avalia silenciosamente para `undefined`.
- Em strings, lembre-se de que `len(s)` e `s.strip()` em Python equivalem a `s.length` e `s.trim()` em JavaScript.
- Para registros com propriedades fixas em JS, use objetos literais `{}`; para dicionários dinâmicos com chaves de tipos variados, prefira `Map`.
- Ao ordenar arrays numéricos em JavaScript, sempre passe uma função comparadora `arr.sort((a, b) => a - b)` para evitar ordenação alfabética textual.
- Reconheça que JavaScript não possui o tipo primitivo `tuple`: utilize arrays com desestruturação ou congelados via `Object.freeze()`.

### Funções, Módulos e Objetos

- Em Python, métodos de classe recebem `self` explicitamente na assinatura; em JavaScript, métodos acessam `this` implicitamente pelo contexto.
- Em JavaScript, prefira *Arrow Functions* para callbacks e métodos funcionais devido à sintaxe concisa e ao `this` léxico.
- Para gerenciar dependências e manifestos, adote `package.json` com `pnpm` no ecossistema JavaScript e `pyproject.toml` com `uv` no ecossistema Python.
- Em JavaScript, o assincronismo via *Event Loop* e Promises é nativo e ubíquo; em Python, o assincronismo via `asyncio` é adotado quando há concorrência intensiva de I/O.

  ```js title="transactions.js"
  }

  console.log(totals);
  // { alimentacao: 75, transporte: 20, lazer: 80 }
  ```
</details>

## Perguntas de revisão

### Modelo mental e tipagem

**1. Por que dizemos que Python possui tipagem forte enquanto JavaScript possui tipagem flexível/com coerções?**

<details>
  <summary>Possível resposta</summary>

  Ambas são dinâmicas (descobrem tipos em tempo de execução), mas Python recusa operações entre tipos incompatíveis (como somar string e número), lançando `TypeError`. JavaScript converte os tipos automaticamente (coerção implícita) para tentar concluir a operação.
</details>

**2. O que acontece ao avaliar `if ([])` em Python comparado a JavaScript?**

<details>
  <summary>Possível resposta</summary>

  Em Python, uma lista vazia `[]` é avaliada como `False` (todas as coleções vazias são *falsy*). Em JavaScript, todo e qualquer objeto ou array (mesmo vazio) é avaliado como `true` (*truthy*). Para testar array vazio em JS, deve-se checar `arr.length === 0`.
</details>

**3. Qual é a diferença entre os operadores `==` e `is` em Python e sua correspondência em JavaScript?**

<details>
  <summary>Possível resposta</summary>

  Em Python, `==` compara a equivalência dos valores e `is` compara se ambos apontam para o mesmo objeto na memória. Em JavaScript, adota-se `===` para comparar valor e tipo sem coerção implícita, e a comparação de objetos/arrays com `===` verifica a identidade de referência na memória.
</details>

### Estruturas de dados e métodos

**4. Como se compara a manipulação funcional de sequências entre Python e JavaScript?**

<details>
  <summary>Possível resposta</summary>

  Em Python, é idiomático utilizar *list comprehensions* para filtragem e mapeamento (`[fn(x) for x in lista if cond(x)]`). Em JavaScript, utiliza-se o encadeamento de métodos de alta ordem de `Array.prototype`, como `arr.filter().map()`.
</details>

**5. Qual a diferença entre usar um objeto literal `{}` e um `Map` em JavaScript ao comparar com um `dict` de Python?**

<details>
  <summary>Possível resposta</summary>

  Um objeto literal `{}` é ideal para registros estáticos com chaves string/symbol conhecidas. O `Map` é mais próximo do `dict` para dicionários dinâmicos, pois aceita chaves de qualquer tipo (números, objetos, booleanos) e preserva a ordem de inserção sem interferência de protótipos.
</details>

**6. Por que o método `.sort()` em JavaScript requer atenção especial ao lidar com números?**

<details>
  <summary>Possível resposta</summary>

  Porque, por padrão, o `.sort()` de JavaScript converte os elementos em strings e os ordena alfabeticamente pela tabela Unicode (fazendo `10` vir antes de `2`). Para ordenar números corretamente, é obrigatório fornecer uma função comparadora: `arr.sort((a, b) => a - b)`.
</details>

**7. Como se compara o acesso a elementos a partir do final da sequência em Python e JavaScript?**

<details>
  <summary>Possível resposta</summary>

  Em Python, utiliza-se a indexação negativa direta nos colchetes (`items[-1]`), e caso o índice extrapole os limites da lista, é lançada a exceção `IndexError`. Em JavaScript, a sintaxe de colchetes `items[-1]` tenta acessar a chave textual `"-1"` e devolve silenciosamente `undefined`. Para obter elementos a partir do fim com deslocamento relativo em JavaScript, utiliza-se o método nativo `items.at(-1)` (padronizado no ES2022) ou a expressão legada `items[items.length - 1]`.
</details>

### Orientação a objetos e assincronismo

**8. Como difere o uso de `self` em Python de `this` em JavaScript na definição de classes?**

<details>
  <summary>Possível resposta</summary>

  Em Python, `self` deve ser declarado explicitamente como o primeiro parâmetro de cada método de instância. Em JavaScript, `this` é uma palavra-chave implícita disponibilizada pelo contexto de execução e não é declarada na lista de parâmetros do método.
</details>

**9. Como funciona a execução assíncrona básica entre Python e JavaScript?**

<details>
  <summary>Possível resposta</summary>

  Em JavaScript, o runtime roda nativamente sobre um *Event Loop* não-bloqueante monothread, onde funções assíncronas retornam Promises prontas para `await`. Em Python, o código síncrono é o padrão clássico e a execução assíncrona requer o uso da biblioteca `asyncio` e a inicialização explícita do loop via `asyncio.run()`.
</details>
