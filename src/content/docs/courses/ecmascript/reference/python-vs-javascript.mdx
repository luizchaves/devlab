Esta aula compara **Python** e **JavaScript** para ajudar quem já estudou uma das linguagens
a transferir conceitos para a outra. As duas são dinâmicas, populares e multiparadigma, mas
nasceram em contextos diferentes e tomam decisões de sintaxe, execução e ecossistema bem
distintas.

JavaScript começou como linguagem do navegador e depois foi para o servidor com Node.js.
Python começou como linguagem de propósito geral no sistema operacional e ganhou força em
automação, dados, ciência, APIs e ensino.

## Objetivo

Comparar JavaScript e Python em modelo de execução, sintaxe, tipos, coleções, funções,
módulos, ecossistema e APIs nativas. Ao final, você deve conseguir traduzir estruturas
comuns entre as duas linguagens, evitar falsas equivalências, reconhecer métodos parecidos
em strings e listas/arrays e escolher a ferramenta adequada para cada tipo de tarefa.

## Panorama Geral

Python e JavaScript são linguagens de alto nível, com tipagem dinâmica e suporte a múltiplos
estilos de programação. A diferença principal está no ambiente padrão: JavaScript é nativo
do navegador; Python é nativo do terminal, do sistema operacional e de ambientes de dados.

A tabela resume as diferenças iniciais:

| Aspecto | Python | JavaScript |
| :--- | :--- | :--- |
| Origem | Linguagem de propósito geral | Linguagem de script para navegadores |
| Ambiente clássico | Terminal, scripts, servidores e dados | Navegador e, com Node.js, servidores |
| Delimitação de blocos | Indentação obrigatória | Chaves `{}` |
| Final de instrução | Quebra de linha | Ponto e vírgula opcional |
| Tipagem | Dinâmica e forte | Dinâmica, com coerções implícitas frequentes |
| Pacotes | PyPI, `pip`, `uv` | npm, `pnpm`, `yarn` |
| Formato de dados comum | Dicionários, listas, tuplas | Objetos, arrays, mapas |

<Aside type="note" title="Dinâmica não significa igual">
  As duas linguagens decidem tipos em runtime, mas JavaScript faz mais coerções implícitas.
  Python tende a recusar combinações incompatíveis com erro explícito.
</Aside>

## Execução e Ambiente

Python costuma executar arquivos `.py` com o interpretador CPython. JavaScript executa no
navegador, no Node.js ou em runtimes compatíveis. Em ambos os casos, existe uma etapa interna
de preparação antes da execução real, mas o fluxo de trabalho para o estudante é diferente.

O diagrama mostra os caminhos mais comuns:

<Mermaid title="Execução típica em Python e JavaScript">
{`
flowchart LR
  A["script.py"] --> B["CPython"]
  B --> C["saída no terminal"]

  D["script.js"] --> E["Node.js"]
  E --> F["saída no terminal"]

  G["app.js"] --> H["navegador"]
  H --> I["DOM, eventos e tela"]
`}
</Mermaid>

Em Python, o primeiro contato geralmente acontece no terminal:

```py title="hello.py"
name = "Ana"
print(f"Olá, {name}")
```

Em JavaScript, o mesmo exemplo pode aparecer no Node.js ou no console do navegador:

```js title="hello.js"
const name = "Ana";
console.log(`Olá, ${name}`);
```

<Aside type="tip" title="O ambiente muda a biblioteca disponível">
  `console.log()` existe em Node.js e no navegador, mas `document.querySelector()` só existe
  no navegador. Em Python, funções de arquivo, sistema e rede vêm da biblioteca padrão ou de
  pacotes instalados no ambiente.
</Aside>

## Sintaxe e Blocos

Python usa indentação como parte da sintaxe. JavaScript usa chaves para delimitar blocos e
costuma usar indentação como convenção de leitura.

O exemplo a seguir compara uma estrutura de decisão simples:

```py title="Python: bloco por indentação"
score = 8

if score >= 7:
    print("Aprovado")
else:
    print("Revisar conteúdo")
```

Em JavaScript, as chaves deixam o bloco explícito:

```js title="JavaScript: bloco por chaves"
const score = 8;

if (score >= 7) {
  console.log("Aprovado");
} else {
  console.log("Revisar conteúdo");
}
```

| Ideia | Python | JavaScript |
| :--- | :--- | :--- |
| Comentário de linha | `# texto` | `// texto` |
| String interpolada | `f"Olá, {name}"` | `` `Olá, ${name}` `` |
| Bloco condicional | `if score >= 7:` | `if (score >= 7) { ... }` |
| Valor nulo | `None` | `null` e `undefined` |
| Booleanos | `True`, `False` | `true`, `false` |
| E lógico | `and` | `&&` |
| Ou lógico | `or` | `\|\|` |
| Negação | `not` | `!` |

<Aside type="caution" title="Cuidado com tradução palavra por palavra">
  `None` parece `null`, mas JavaScript também tem `undefined`. `and` parece `&&`, mas
  expressões lógicas nas duas linguagens podem devolver operandos, não apenas booleanos.
</Aside>

## Tipos e Coerção

Python é dinâmico e forte: o tipo é decidido em runtime, mas operações incompatíveis tendem
a falhar em vez de converter silenciosamente. JavaScript também é dinâmico, mas possui várias
coerções automáticas.

O exemplo abaixo evidencia a diferença:

```py title="Python: conversão precisa ser explícita"
age = 20

# print("Idade: " + age)
# TypeError: só concatena string com string

print("Idade: " + str(age)) # Idade: 20
```

Em JavaScript, o operador `+` também concatena strings e pode converter números:

```js title="JavaScript: coerção implícita"
const age = 20;

console.log("Idade: " + age); // Idade: 20
console.log("5" - 2); // 3
console.log("5" + 2); // 52
```

<Aside type="caution" title="Coerção é uma fonte comum de bugs em JS">
  Em JavaScript, prefira `===`, conversões explícitas com `Number()` / `String()` e validações
  claras antes de comparar ou calcular valores vindos de entrada do usuário.
</Aside>

## Coleções e Objetos

As estruturas mais usadas têm equivalentes conceituais, mas não são idênticas. A maior
diferença para iniciantes é que o **objeto literal** de JavaScript parece um dicionário de
Python, mas também carrega regras de protótipo, métodos e acesso por ponto.

Esta tabela serve como mapa de tradução inicial:

| Conceito | Python | JavaScript |
| :--- | :--- | :--- |
| Lista ordenada mutável | `list` | `Array` |
| Registro chave-valor | `dict` | `Object` ou `Map` |
| Conjunto sem repetição | `set` | `Set` |
| Sequência imutável | `tuple` | Não há equivalente direto nativo |
| Ausência de valor | `None` | `null` / `undefined` |
| Iteração simples | `for item in items:` | `for (const item of items)` |

O exemplo compara filtragem e transformação de listas:

```py title="Python: list comprehension"
numbers = [1, 2, 3, 4, 5]
double_even = [number * 2 for number in numbers if number % 2 == 0]

print(double_even) # [4, 8]
```

Em JavaScript, a mesma intenção costuma combinar `filter()` e `map()`:

```js title="JavaScript: filter + map"
const numbers = [1, 2, 3, 4, 5];
const doubleEven = numbers
  .filter((number) => number % 2 === 0)
  .map((number) => number * 2);

console.log(doubleEven); // [4, 8]
```

<Aside type="tip" title="Map não é Object">
  Para chaves arbitrárias, preservação clara de inserção e operações próprias de mapa, use
  `Map` em JavaScript. Para registros simples com nomes de campos conhecidos, objeto literal
  costuma ser suficiente.
</Aside>

## Comparativo de APIs Nativas

Aprender a sintaxe geral é só metade da tradução entre linguagens. No dia a dia, a maior
parte do código chama métodos de strings, listas/arrays, dicionários/mapas e conjuntos.

As tabelas abaixo não tentam cobrir toda a biblioteca padrão. Elas funcionam como um mapa
prático: "se em Python eu usaria isto, o que costumo usar em JavaScript?".

### Strings: `str` vs `String`

Strings são imutáveis nas duas linguagens. Métodos de transformação devolvem uma nova string;
eles não alteram o texto original.

| Tarefa | Python `str` | JavaScript `String` |
| :--- | :--- | :--- |
| Tamanho | `len(text)` | `text.length` |
| Minúsculas | `text.lower()` | `text.toLowerCase()` |
| Maiúsculas | `text.upper()` | `text.toUpperCase()` |
| Remover espaços nas pontas | `text.strip()` | `text.trim()` |
| Começa com | `text.startswith("Dev")` | `text.startsWith("Dev")` |
| Termina com | `text.endswith(".js")` | `text.endsWith(".js")` |
| Contém trecho | `"lab" in text` | `text.includes("lab")` |
| Encontrar posição | `text.find("JS")` | `text.indexOf("JS")` |
| Substituir | `text.replace("JS", "JavaScript")` | `text.replace("JS", "JavaScript")` |
| Dividir | `text.split(",")` | `text.split(",")` |
| Juntar lista | `", ".join(items)` | `items.join(", ")` |
| Fatiar | `text[0:4]` | `text.slice(0, 4)` |

O exemplo abaixo mostra operações comuns lado a lado:

```py title="Python: API de str"
text = "  JavaScript,Python,TypeScript  "
items = [item.strip().lower() for item in text.split(",")]

print(items) # ['javascript', 'python', 'typescript']
print(" / ".join(items)) # javascript / python / typescript
```

Em JavaScript, a mesma cadeia usa métodos de `String` e `Array`:

```js title="JavaScript: API de String"
const text = "  JavaScript,Python,TypeScript  ";
const items = text
  .split(",")
  .map((item) => item.trim().toLowerCase());

console.log(items); // [ 'javascript', 'python', 'typescript' ]
console.log(items.join(" / ")); // javascript / python / typescript
```

<Aside type="caution" title="length não conta caracteres humanos perfeitamente">
  Em JavaScript, `string.length` conta unidades UTF-16, não necessariamente caracteres
  percebidos pelo usuário. Emojis e alguns caracteres acentuados podem exigir cuidado extra,
  como `Intl.Segmenter` ou bibliotecas específicas.
</Aside>

### Sequências Mutáveis: `list` vs `Array`

`list` em Python e `Array` em JavaScript representam sequências ordenadas e mutáveis. A
semelhança é forte, mas a API idiomática muda: Python usa muitas funções globais e métodos
mutadores; JavaScript usa muitos métodos de alta ordem no próprio array.

| Tarefa | Python `list` | JavaScript `Array` |
| :--- | :--- | :--- |
| Tamanho | `len(items)` | `items.length` |
| Adicionar no fim | `items.append(value)` | `items.push(value)` |
| Remover do fim | `items.pop()` | `items.pop()` |
| Adicionar vários | `items.extend(other)` | `items.push(...other)` ou `items.concat(other)` |
| Inserir em posição | `items.insert(index, value)` | `items.splice(index, 0, value)` |
| Remover por valor | `items.remove(value)` | `items.splice(items.indexOf(value), 1)` com cuidado |
| Fatiar | `items[1:3]` | `items.slice(1, 3)` |
| Mapear | `[fn(x) for x in items]` | `items.map(fn)` |
| Filtrar | `[x for x in items if test(x)]` | `items.filter(test)` |
| Reduzir | `functools.reduce(fn, items, initial)` | `items.reduce(fn, initial)` |
| Ordenar mutando | `items.sort()` | `items.sort(compareFn)` |
| Ordenar cópia | `sorted(items)` | `items.toSorted(compareFn)` |
| Verificar presença | `value in items` | `items.includes(value)` |

O exemplo a seguir compara um pipeline de dados com filtro, transformação e ordenação:

```py title="Python: list, sorted e comprehension"
scores = [7, 10, 4, 8]
approved = sorted([score + 1 for score in scores if score >= 7])

print(approved) # [8, 9, 11]
print(scores) # [7, 10, 4, 8]
```

Em JavaScript moderno, `toSorted()` preserva o array original:

```js title="JavaScript: Array, filter, map e toSorted"
const scores = [7, 10, 4, 8];
const approved = scores
  .filter((score) => score >= 7)
  .map((score) => score + 1)
  .toSorted((a, b) => a - b);

console.log(approved); // [8, 9, 11]
console.log(scores); // [7, 10, 4, 8]
```

<Aside type="caution" title="sort() em JavaScript ordena como texto por padrão">
  `array.sort()` converte valores para string se você não passar `compareFn`. Para números,
  use `array.sort((a, b) => a - b)` ou `array.toSorted((a, b) => a - b)`.
</Aside>

### Chave-Valor: `dict` vs `Object` e `Map`

O `dict` de Python é a estrutura padrão para chave-valor. Em JavaScript existem duas escolhas
comuns: objeto literal para registros com campos conhecidos e `Map` para mapa de chaves
arbitrárias.

| Tarefa | Python `dict` | JavaScript `Object` | JavaScript `Map` |
| :--- | :--- | :--- | :--- |
| Criar vazio | `{}` | `{}` | `new Map()` |
| Ler valor | `user["name"]` | `user.name` ou `user["name"]` | `map.get("name")` |
| Definir valor | `user["name"] = "Ana"` | `user.name = "Ana"` | `map.set("name", "Ana")` |
| Valor padrão | `user.get("age", 0)` | `user.age ?? 0` | `map.get("age") ?? 0` |
| Chaves | `user.keys()` | `Object.keys(user)` | `map.keys()` |
| Valores | `user.values()` | `Object.values(user)` | `map.values()` |
| Pares | `user.items()` | `Object.entries(user)` | `map.entries()` |
| Existe chave | `"name" in user` | `Object.hasOwn(user, "name")` | `map.has("name")` |
| Remover | `del user["name"]` | `delete user.name` | `map.delete("name")` |

O exemplo com objeto literal fica natural quando as propriedades fazem parte do modelo:

```js title="JavaScript: Object como registro"
const user = {
  name: "Ana",
  role: "student",
};

console.log(Object.keys(user)); // [ 'name', 'role' ]
console.log(user.name); // Ana
```

Quando as chaves são dinâmicas, `Map` deixa a intenção mais explícita:

```js title="JavaScript: Map como dicionário dinâmico"
const counters = new Map();

counters.set("javascript", 2);
counters.set("python", (counters.get("python") ?? 0) + 1);

console.log(counters.has("python")); // true
console.log([...counters.entries()]); // [ [ 'javascript', 2 ], [ 'python', 1 ] ]
```

<Aside type="tip" title="Objeto é ótimo para dados com forma conhecida">
  Se você está representando `user.name`, `user.email` e `user.role`, use objeto. Se está
  contando ocorrências por qualquer chave recebida em runtime, considere `Map`.
</Aside>

### Conjuntos: `set` vs `Set`

As duas linguagens têm conjuntos para guardar valores sem repetição. A ideia é parecida:
adicionar, testar presença, remover e combinar coleções.

| Tarefa | Python `set` | JavaScript `Set` |
| :--- | :--- | :--- |
| Criar | `set(items)` | `new Set(items)` |
| Tamanho | `len(tags)` | `tags.size` |
| Adicionar | `tags.add("js")` | `tags.add("js")` |
| Testar presença | `"js" in tags` | `tags.has("js")` |
| Remover | `tags.remove("js")` ou `tags.discard("js")` | `tags.delete("js")` |
| União | `a | b` ou `a.union(b)` | `new Set([...a, ...b])` |
| Interseção | `a & b` ou `a.intersection(b)` | filtrar valores presentes nos dois |
| Diferença | `a - b` ou `a.difference(b)` | filtrar valores ausentes no outro |

O exemplo abaixo mostra operações equivalentes com `Set`:

```js title="JavaScript: operações com Set"
const frontend = new Set(["html", "css", "javascript"]);
const backend = new Set(["javascript", "sql", "python"]);

const union = new Set([...frontend, ...backend]);
const intersection = new Set([...frontend].filter((item) => backend.has(item)));
const difference = new Set([...frontend].filter((item) => !backend.has(item)));

console.log([...union]); // [ 'html', 'css', 'javascript', 'sql', 'python' ]
console.log([...intersection]); // [ 'javascript' ]
console.log([...difference]); // [ 'html', 'css' ]
```

<Aside type="note" title="Nem toda API tem paridade perfeita">
  Python expõe operações de conjunto com operadores próprios (`|`, `&`, `-`). JavaScript
  tradicionalmente monta essas operações combinando `Set`, spread e métodos de `Array`.
</Aside>

## Funções e Escopo

Python e JavaScript tratam funções como valores: você pode guardar uma função em variável,
passar como argumento e retornar de outra função. A sintaxe, porém, muda bastante.

O exemplo abaixo define uma função nomeada em Python:

```py title="Python: função nomeada"
def apply_discount(price, percent=10):
    return price * (1 - percent / 100)

print(apply_discount(100)) # 90.0
```

Em JavaScript, funções podem ser declarações, expressões ou arrow functions:

```js title="JavaScript: arrow function"
const applyDiscount = (price, percent = 10) => {
  return price * (1 - percent / 100);
};

console.log(applyDiscount(100)); // 90
```

| Recurso | Python | JavaScript |
| :--- | :--- | :--- |
| Parâmetro padrão | `def fn(x=1):` | `function fn(x = 1)` |
| Vários argumentos posicionais | `*args` | `...args` |
| Argumentos nomeados extras | `**kwargs` | Objeto de opções |
| Função anônima curta | `lambda x: x * 2` | `(x) => x * 2` |
| Escopo de bloco | Não para `if`/`for` | Sim com `let` e `const` |

<Aside type="note" title="O escopo de bloco muda hábitos">
  Em JavaScript moderno, prefira `const` e `let`, que respeitam bloco. Em Python, uma variável
  criada dentro de `if` ou `for` continua existindo no escopo da função ou do módulo.
</Aside>

## Executando

Você pode comparar as duas linguagens executando dois arquivos que resolvem o mesmo problema:
receber uma lista de notas e calcular a média.

<Steps>

1. Crie um arquivo `average.py`:

   ```py title="average.py"
   grades = [8, 7.5, 9]
   average = sum(grades) / len(grades)

   print(f"Média: {average:.2f}")
   ```

2. Execute com Python:

   ```bash title="Terminal"
   python average.py
   ```

   ```txt title="Output"
   Média: 8.17
   ```

3. Crie um arquivo `average.js`:

   ```js title="average.js"
   const grades = [8, 7.5, 9];
   const total = grades.reduce((sum, grade) => sum + grade, 0);
   const average = total / grades.length;

   console.log(`Média: ${average.toFixed(2)}`);
   ```

4. Execute com Node.js:

   ```bash title="Terminal"
   node average.js
   ```

   ```txt title="Output"
   Média: 8.17
   ```

5. No navegador, cole apenas a versão JavaScript no console das DevTools. Python não roda
   nativamente no navegador sem uma camada adicional.

</Steps>

## Exercício

Traduza um pequeno programa de uma linguagem para a outra:

1. Comece com uma lista de cursos.
2. Cada curso deve ter `title` e `workload`.
3. Filtre apenas cursos com carga horária maior ou igual a 60.
4. Transforme o resultado em uma lista de títulos.
5. Escreva uma versão em Python.
6. Escreva uma versão em JavaScript.
7. Compare os nomes, delimitadores e métodos usados.

<details>
  <summary>Possível resposta</summary>

  ```py title="courses.py"
  courses = [
      {"title": "HTML", "workload": 40},
      {"title": "JavaScript", "workload": 80},
      {"title": "Python", "workload": 60},
  ]

  titles = [
      course["title"]
      for course in courses
      if course["workload"] >= 60
  ]

  print(titles) # ['JavaScript', 'Python']
  ```

  ```js title="courses.js"
  const courses = [
    { title: "HTML", workload: 40 },
    { title: "JavaScript", workload: 80 },
    { title: "Python", workload: 60 },
  ];

  const titles = courses
    .filter((course) => course.workload >= 60)
    .map((course) => course.title);

  console.log(titles); // [ 'JavaScript', 'Python' ]
  ```
</details>

## Desafio

Implemente a mesma lógica em Python e JavaScript: receber uma lista de vendas, agrupar o
total por categoria e imprimir o objeto/dicionário final.

<details>
  <summary>Possível resposta</summary>

  ```py title="sales.py"
  sales = [
      {"category": "book", "value": 40},
      {"category": "course", "value": 120},
      {"category": "book", "value": 35},
  ]

  totals = {}

  for sale in sales:
      category = sale["category"]
      totals[category] = totals.get(category, 0) + sale["value"]

  print(totals) # {'book': 75, 'course': 120}
  ```

  ```js title="sales.js"
  const sales = [
    { category: "book", value: 40 },
    { category: "course", value: 120 },
    { category: "book", value: 35 },
  ];

  const totals = {};

  for (const sale of sales) {
    totals[sale.category] = (totals[sale.category] ?? 0) + sale.value;
  }

  console.log(totals); // { book: 75, course: 120 }
  ```
</details>

## Perguntas de revisão

### Modelo mental

**1. Qual é a diferença mais importante entre o ambiente clássico de Python e o de JavaScript?**

<details>
  <summary>Possível resposta</summary>

  JavaScript é nativo do navegador e também roda no servidor com Node.js. Python é mais comum
  no terminal, em scripts, servidores, automação, dados e ferramentas de sistema.
</details>

**2. As duas linguagens têm tipagem dinâmica?**

<details>
  <summary>Possível resposta</summary>

  Sim. O tipo dos valores é conhecido em runtime. A diferença é que JavaScript faz mais
  coerções implícitas, enquanto Python tende a exigir conversões explícitas.
</details>

**3. Por que indentação é mais crítica em Python?**

<details>
  <summary>Possível resposta</summary>

  Porque a indentação delimita blocos de código. Em JavaScript, os blocos são delimitados
  por chaves, e a indentação é principalmente uma convenção de leitura.
</details>

### Tradução de conceitos

**4. Qual estrutura de JavaScript se aproxima de uma lista Python?**

<details>
  <summary>Possível resposta</summary>

  `Array`, porque representa uma sequência ordenada e mutável de valores.
</details>

**5. Um objeto JavaScript é exatamente igual a um dicionário Python?**

<details>
  <summary>Possível resposta</summary>

  Não. Objetos podem servir como registros chave-valor, mas têm protótipo e acesso por ponto.
  Para mapa de chaves arbitrárias, `Map` costuma ser uma comparação melhor.
</details>

**6. Qual é o equivalente direto de `None` em JavaScript?**

<details>
  <summary>Possível resposta</summary>

  Não há um único equivalente perfeito. `null` representa ausência intencional, enquanto
  `undefined` aparece quando um valor ainda não foi definido ou uma propriedade não existe.
</details>
