## Objetivo

Compreender como o JavaScript gerencia variáveis na memória, diferenciando declarações com `var`, `let` e `const`. Dominar as regras de escopo (global, função e bloco), o comportamento de *hoisting*, a Zona Morta Temporal (TDZ) e as convenções de boas práticas para criação de identificadores previsíveis.

## Variáveis e Declaração de Identificadores

Sem variáveis, o mesmo valor precisa ser repetido no código, dificultando a manutenção e ocultando a intenção do programa. Ao declarar uma variável, um valor recebe um nome simbólico e pode ser reutilizado.

O diagrama a seguir ilustra um modelo conceitual de memória, diferenciando valores
primitivos representados diretamente de objetos acessados por referência:

<Mermaid title="Modelo conceitual didático: primitivos, referências e objetos">
{`
flowchart LR
  subgraph Stack["Pilha (Stack)"]
    S1["price = 79.9<br>(Valor primitivo)"]
    S2["user = 0x00A4<br>(Endereço)"]
  end

    H1["0x00A4: { name: 'Ana' }"]
  end

  S2 -->|Ponteiro| H1
`}
</Mermaid>

Esse desenho é uma simplificação útil para visualizar valor e referência. A
especificação ECMAScript não obriga uma engine a armazenar primitivos na *stack* nem
objetos na *heap*; ela define o comportamento observável que o código precisa
respeitar.

O trecho a seguir traduz o diagrama para código executável: copiar um primitivo mantém
dois valores independentes, enquanto copiar um objeto compartilha a mesma estrutura:

```js title="Modelo conceitual: primitivos, referências e objetos"
let price = 79.9;
let copiedPrice = price;

copiedPrice = 99.9;

console.log(price); // 79.9
console.log(copiedPrice); // 99.9

const user = { name: "Ana" };
const sameUser = user;

sameUser.name = "Bia";

console.log(user.name); // "Bia"
console.log(sameUser.name); // "Bia"
```

### Por que variáveis existem?

Sem variáveis, o mesmo valor precisa ser repetido e o código perde intenção. Com uma
variável, o valor ganha nome e pode ser reutilizado.

```js title="Valor repetido"
console.log(79.9 * 0.9);
console.log(79.9 * 0.9 + 12);
```

Ao nomear os valores, o cálculo fica mais legível e cada parte passa a ter uma
responsabilidade clara.

```js title="Valor nomeado"
const price = 79.9;
const discountFactor = 0.9;
const shipping = 12;

const subtotal = price * discountFactor;
const total = subtotal + shipping;

console.log(subtotal); // 71.91
console.log(total); // 83.91
```

A diferença entre os dois trechos não está no resultado, mas na leitura. Quando cada
valor tem nome, o código explica melhor a intenção do cálculo.

<Aside type="tip" title="Nome é parte do código">
  Um bom nome reduz a necessidade de comentário. `total`, `price` e `shipping`
  explicam melhor o cálculo do que nomes como `x`, `y` e `z`.
</Aside>


### Identificadores

O nome da variável é chamado de identificador. Ele pode usar letras, dígitos,
`_` e `$`, mas não pode começar com dígito nem usar palavras reservadas como nome.

```js title="Identificadores válidos"
const _total = 10;
const $price = 19.9;
const fullName = "Fulano";

console.log(_total); // 10
console.log($price); // 19.9
console.log(fullName); // Fulano
```

Os exemplos abaixo estão comentados porque representam erros de sintaxe; se forem
descomentados, o arquivo deixa de executar.

```js title="Identificadores inválidos"
// SyntaxError: Invalid or unexpected token.
// const 2phase = "DW";

// SyntaxError: Identifier is a reserved word.
// const let = 10;

// O caractere - é operador de subtração, não parte do nome.
// const full-name = "Fulano";
```

Esses erros ajudam a separar problemas de sintaxe de problemas que só aparecem durante
a execução. O callout a seguir mostra como reconhecer cada caso.

<Aside type="note" title="Quando o erro acontece?">
  Nesta página aparecem erros de sintaxe, como `SyntaxError`, e erros em tempo de
  execução. Um `SyntaxError`, como em `const 2phase = "DW";`, impede o arquivo de
  ser interpretado. Já erros como `TypeError` e `RangeError` acontecem em tempo de
  execução: o código é sintaticamente válido, mas falha quando aquela linha roda. Em
  uma aplicação, um erro em tempo de execução pode interromper o fluxo atual se não
  for tratado com mecanismos como `try...catch`. Quando a execução parecer
  inconsistente ou incompleta, verifique sempre se o terminal ou o Console do
  navegador exibiu uma mensagem de erro ou *stack trace*. Normalmente eles indicam o
  tipo do erro, o arquivo, a linha e o caminho de chamadas que levou até a falha.

  ```js title="variables.js"
  const total = 1n + 1;
  console.log(total);
  ```

  ```txt title="Exemplo no console"
  TypeError: Cannot mix BigInt and other types
      at variables.js:1:17
  ```
</Aside>

### Convenções de Nomenclatura (Naming Conventions)

Para manter o código previsível, legível e organizado, o ecossistema JavaScript adota convenções de nomenclatura consolidadas para diferentes tipos de identificadores e arquivos.

A tabela a seguir apresenta os padrões de nomenclatura dominantes no desenvolvimento JavaScript moderno:

| Convenção | Padrão | Exemplo | Uso Recomendado |
| :--- | :--- | :--- | :--- |
| **`camelCase`** | primeira palavra em minúscula, subsequentes com inicial maiúscula | `userName`, `totalPrice`, `calculateTax()` | Variáveis comuns (`let`/`const`), parâmetros, propriedades de objetos e funções. |
| **`SCREAMING_SNAKE_CASE`** *(ou `UPPER_SNAKE_CASE`)* | todas as letras em maiúsculas separadas por underline `_` | `API_URL`, `MAX_ATTEMPTS`, `DEFAULT_TIMEOUT` | Constantes imutáveis de configuração global e "valores mágicos" conhecidos em tempo de código. |
| **`PascalCase`** | inicial de cada palavra em maiúscula | `UserProfile`, `OrderController`, `Button` | Classes, funções construtoras, interfaces/tipos e Componentes de UI (React, Vue, Svelte). |
| **`kebab-case`** | todas as letras minúsculas separadas por hífen `-` | `user-service.js`, `array-utils.js`, `syntax-cascade.mdx` | Nomes de arquivos de código, scripts, arquivos de estilo, pastas de módulos e rotas Web. |

Essa tabela não significa que todo `const` precise de caixa alta. A grafia também
depende de quando o valor é conhecido e do papel daquele nome no programa.

<Aside type="tip" title="Distinção Importante: `const` vs. `SCREAMING_SNAKE_CASE`">
  Nem toda declaração com a palavra-chave `const` deve ser grafada em `SCREAMING_SNAKE_CASE`!
  - Use **`SCREAMING_SNAKE_CASE`** exclusivamente para **valores fixos e imutáveis conhecidos antes da execução** (hardcoded), como `const MAX_RETRY_COUNT = 3;` ou `const API_BASE_URL = "https://api.exemplo.com";`.
  - Use **`camelCase`** para variáveis declaradas com `const` cujo valor é atribuído dinamicamente em **tempo de execução** (runtime), como `const userList = await fetchUsers();` ou `const currentElement = document.querySelector("#main");`.
</Aside>

Além do formato dos identificadores no código, vale padronizar também os nomes de
arquivos e pastas. Essa escolha evita diferenças sutis entre sistemas operacionais
e deixa imports mais previsíveis.

<Aside type="note" title="Por que usar `kebab-case` para arquivos?">
  No ecossistema JS/Node.js, prioriza-se **`kebab-case`** para arquivos e pastas porque diferentes sistemas operacionais (Windows, macOS e Linux) tratam letras maiúsculas e minúsculas (*case-sensitivity*) de formas distintas no sistema de arquivos. Nomes em `kebab-case` evitam bugs silenciosos de importação e de controle de versão no Git ao alterar maiúsculas/minúsculas.
</Aside>


<Aside type="tip" title="Dica de IA: Peça nomes alternativos antes de aceitar o primeiro">
  Nomear é a parte do código que o assistente resolve pior sozinho, porque o nome depende do domínio do projeto, e não da sintaxe. `data`, `result`, `item` e `temp` aparecem em código gerado com frequência muito maior do que em código revisado.

  **Prompt:** *"Sugira três nomes alternativos para cada variável e função deste trecho, considerando que o domínio é um sistema de matrícula acadêmica. Explique o que cada nome comunica e qual você escolheria."*
</Aside>

### Inicialização

Declarar é criar o nome. Inicializar é atribuir o primeiro valor.

```js title="Declaração sem inicialização"
let value;

console.log(value); // undefined
console.log(typeof value); // "undefined"

value = 100;
value += 50;

console.log(value); // 150
```

`const` precisa ser inicializada na declaração.

```js title="const precisa de valor inicial"
const defaultChoice = "const";
console.log(defaultChoice); // "const"

// SyntaxError: Missing initializer in const declaration.
// const missingValue;
```

### Declaração múltipla

JavaScript permite declarar mais de um identificador na mesma instrução, separando os
nomes por vírgula. Esse formato existe na linguagem, mas deve ser usado com cuidado:
quando cada variável tem um papel diferente, declarações separadas costumam deixar o
código mais fácil de ler, comentar e alterar.

O exemplo a seguir mostra a sintaxe válida e também o motivo para preferir uma linha
por intenção em código didático:

```js title="Declaração múltipla com vírgula"
let width = 320, height = 240;
const area = width * height;

console.log(area); // 76800

// Mais legível quando os valores têm papéis próprios:
let retryCount = 0;
let lastErrorMessage = "";
```

A vírgula pertence à instrução de declaração, não ao nome da variável. Por isso, cada
item pode ter inicialização própria, mas todos compartilham a mesma palavra-chave
inicial (`let`, `const` ou `var`).


## Palavras-Chave de Declaração: `var`, `let` e `const`

O ECMAScript oferece três palavras-chave para criar variáveis, cada uma com regras de escopo e reatribuição distintas:

| Palavra-Chave | Escopo | Reatribuição | Redeclaração no mesmo escopo | Hoisting |
| :--- | :--- | :--- | :--- | :--- |
| `var` | Função ou Global | Permitida | Permitida | Inicializada como `undefined` |
| `let` | Bloco | Permitida | Proibida (SyntaxError) | Não inicializada (TDZ) |
| `const` | Bloco | Proibida (TypeError) | Proibida (SyntaxError) | Não inicializada (TDZ) |

Leia a tabela por coluna. **Escopo** indica onde o nome pode ser acessado;
**reatribuição** indica se o mesmo identificador pode receber outro valor;
**redeclaração** indica se o mesmo nome pode ser declarado novamente no mesmo escopo;
e **hoisting** mostra o que acontece quando a engine conhece a declaração antes da
linha onde ela aparece no arquivo.

A linha de `var` concentra os comportamentos legados: escopo de função, redeclaração
permitida e inicialização automática como `undefined`. `let` e `const` são escolhas
modernas porque respeitam escopo de bloco e bloqueiam redeclaração acidental. A diferença
entre elas é a reassociação: `let` aceita trocar o valor do nome; `const` não aceita.

O exemplo a seguir transforma essa leitura da tabela em comportamento observável.
`let` e `var` aceitam uma nova atribuição para o mesmo nome; `const` bloqueia essa
reassociação porque o identificador já nasceu ligado a um valor.

```js title="Comportamento de reatribuição"
// const exige valor inicial e impede reassociação do identificador
const birthYear = 1995;
// birthYear = 1996; // TypeError: Assignment to constant variable.

// let permite alteração posterior do valor
let currentAge = 28;
currentAge = 29; // OK

// var permite reatribuição e redeclaração (Evitar em código moderno)
var userRole = "admin";
var userRole = "super-admin"; // Sem erro, substitui a declaração anterior
```

Esse bloqueio de `const` vale para trocar o valor associado ao nome. Ele não congela
automaticamente objetos e arrays, que continuam podendo sofrer mutação interna.

<Aside type="caution" title="`const` Protege a Variável, Não o Objeto Interno">
  A instrução `const` impede que o identificador seja reassociado a outro objeto ou valor na memória. No entanto, o conteúdo interno de objetos e arrays declarados com `const` **pode** ser modificado (mutação):

  ```js
  const user = { name: "Ana", age: 25 };
  user.age = 26; // Permitido! Mutação da propriedade interna.
  // user = { name: "Carlos" }; // Erro! Reatribuição do identificador.
  ```
</Aside>

### Panorama da declaração

Em JavaScript moderno, as declarações mais usadas são `const` e `let`. `var` ainda
aparece em códigos antigos, bibliotecas e materiais legados, mas deve ser evitado
como padrão em novos arquivos.

A tabela abaixo é uma versão operacional da comparação anterior. A coluna **Pode
reassociar?** responde se o identificador pode receber outro valor depois da
declaração; **Escopo principal** mostra onde o nome fica visível; e **Uso recomendado**
traduz a regra para uma decisão de escrita.

| Palavra-chave | Pode reassociar? | Escopo principal | Uso recomendado |
| -------------- | ---------------- | ---------------- | --------------- |
| `const` | Não | Bloco | Valor que não será trocado |
| `let` | Sim | Bloco | Valor que muda durante a execução |
| `var` | Sim | Função | Código legado |

Leia a tabela de cima para baixo. `const` deve ser a primeira tentativa porque reduz
mudanças acidentais no nome; `let` entra quando o algoritmo precisa atualizar aquele
identificador; `var` fica como vocabulário de leitura para código antigo. A escolha
prática se resume a começar pelo caso mais restritivo e relaxar a regra apenas quando
o código exigir mudança.

<Aside type="tip" title="Prefira const primeiro">
  Comece com `const`. Troque para `let` apenas quando o código precisar reassociar
  a variável. Esse hábito deixa claro quais valores mudam e quais permanecem
  estáveis.
</Aside>


### Redeclaração

`var` permite declarar novamente o mesmo nome no mesmo escopo. `let` e `const`
evitam isso.

```js title="Redeclaração com var"
var course = "DW";
var course = "Desenvolvimento Web";

console.log(course); // "Desenvolvimento Web"
```

Com `let` e `const`, a tentativa de repetir o mesmo nome no mesmo escopo é bloqueada
antes da execução.

```js title="Redeclaração bloqueada"
let semester = "2026.2";

// SyntaxError: Identifier 'semester' has already been declared.
// let semester = "2027.1";

let number = 10;

// SyntaxError: Identifier 'number' has already been declared.
// var number = 20;
```


<Aside type="caution" title="Dica de IA: Corrija o `var` que o assistente ainda sugere">
  Boa parte do JavaScript usado para treinar modelos foi escrita antes do ES6, e `var` continua aparecendo em código gerado, principalmente em laços `for`. O escopo de bloco elimina de uma vez a captura errada de variável em *closures* dentro de laços.

  **Prompt:** *"Reescreva este código sem `var`: use `const` por padrão e `let` apenas onde houver reassociação real. Aponte se alguma função criada dentro de laço muda de comportamento com a troca."*
</Aside>

## Reassociação e mutação

Reassociar é fazer a variável apontar para outro valor. `var` e `let` permitem
isso; `const` não permite.

```js title="Reassociação"
var declaredWithVar = 10;
let declaredWithLet = 20;
const declaredWithConst = 30;

declaredWithVar = 100;
declaredWithLet = 200;

console.log(declaredWithVar); // 100
console.log(declaredWithLet); // 200

// TypeError: Assignment to constant variable.
// declaredWithConst = 300;
```

`const` impede a troca da associação, mas não transforma objetos e arrays em valores
imutáveis. O conteúdo interno ainda pode mudar.

```js title="Mutação de array declarado com const"
const values = [];

values.push("A");
values.push("B");

console.log(values); // ["A", "B"]

// TypeError: Assignment to constant variable.
// values = [1, 2];
```

O mesmo vale para objetos: a variável continua apontando para o mesmo objeto, mas
uma propriedade interna pode ser modificada.

```js title="Mutação de objeto declarado com const"
const user = { name: "Alice" };

user.name = "Bob";

console.log(user); // { name: "Bob" }
```

O mesmo modelo fica mais visível quando duas variáveis apontam para o mesmo array. Mutar o
array por um nome afeta o objeto observado pelo outro; reassociar um dos nomes apenas troca
o destino daquele identificador.

O exemplo a seguir executa esse fluxo em duas fases: primeiro `alias` aponta para o
mesmo array de `values`; depois `alias = [9, 9]` cria uma nova associação apenas para
o identificador `alias`.

```js title="Referência compartilhada e reassociação"
const values = [1, 2, 3];
let alias = values;

alias.push(4);
console.log(values); // [1, 2, 3, 4]
console.log(values === alias); // true

alias = [9, 9];
console.log(values); // [1, 2, 3, 4]
console.log(alias); // [9, 9]
console.log(values === alias); // false
```

O diagrama abaixo sintetiza a execução do código. Antes da nova atribuição, os dois
identificadores chegam ao mesmo array; depois de `alias = [9, 9]`, apenas `alias`
passa a apontar para outra estrutura.

<Mermaid title="Identificadores são referências: antes e depois de alias = [9, 9]">
{`
flowchart TD
  subgraph antes["Antes de alias = [9, 9]"]
    values1(["values"]) --> array1["[1, 2, 3, 4]"]
    alias1(["alias"]) --> array1
  end

  subgraph depois["Depois de alias = [9, 9]"]
    values2(["values"]) --> array2["[1, 2, 3, 4]"]
    alias2(["alias"]) --> array3["[9, 9]"]
  end
`}
</Mermaid>

Depois de observar a mutação e a reassociação no código, a regra prática fica mais
direta: `const` protege o nome contra troca de destino, mas não torna a estrutura
apontada imutável.

<Aside type="caution" title="const não significa imutável">
  `const` protege a variável contra reassociação. Para trabalhar com objetos
  realmente imutáveis, é necessário adotar outras técnicas e padrões de código.
</Aside>


## Escopo Lexical e de Bloco

Escopo determina em quais partes do código um determinado identificador está visível e pode ser acessado. O JavaScript utiliza **Escopo Lexical**, o que significa que o acesso às variáveis é determinado pela posição onde o código foi escrito no arquivo.

O código a seguir cria três fronteiras: o escopo global, o escopo de função e um
bloco interno. Observe que a função consegue ler `globalVar`, o bloco consegue ler
`functionVar`, mas `blockVar` só existe dentro das chaves onde foi declarado.

```js title="Cadeia de busca em escopos aninhados"
const globalVar = "global";

function outerFunction() {
  const functionVar = "função";

  if (true) {
    const blockVar = "bloco";
    var legacyFunctionVar = "var fica na função";

    console.log(blockVar); // "bloco"
    console.log(functionVar); // "função"
    console.log(globalVar); // "global"
  }

  console.log(legacyFunctionVar); // "var fica na função"
  // console.log(blockVar); // ReferenceError: blockVar is not defined
}

outerFunction();
```

O diagrama sintetiza esse mesmo código como uma cadeia de busca (*Scope Chain*).
Quando um nome não está no bloco atual, a engine procura no escopo externo seguinte
até chegar ao global; se não encontrar, a leitura gera `ReferenceError`.

<Mermaid title="Fronteiras de Escopo e Cadeia de Busca (Scope Chain)">
{`
flowchart TD
  subgraph GlobalScope["Escopo Global (Nível Superior)"]
    G["globalVar (Acessível em qualquer ponto do código)"]

    subgraph FunctionScope["Escopo de Função (outerFunction)"]
      F["functionVar (Visível apenas dentro da função)"]

      subgraph BlockScope["Escopo de Bloco { if / for }"]
        B["blockVar (let / const: Restrito ao Bloco)"]
        L["var (vaza a fronteira do bloco para a Função!)"]
      end
    end
  end

  B -->|1. Procura no Bloco| F
  F -->|2. Procura na Função| G
  G -->|3. Não encontrado| ERR["ReferenceError: Not Defined"]
`}
</Mermaid>

### Escopo de Bloco (`let` e `const`)

Um bloco é delimitado por chaves `{ ... }` (como em instruções `if`, `for`, `while` ou blocos autônomos). Identificadores criados com `let` e `const` dentro de um bloco existem apenas naquele contexto.

```js title="Isolamento de bloco"
if (true) {
  const blockScoped = "Visível apenas dentro do bloco";
  var functionScoped = "Vaza para fora do bloco!";
  console.log(blockScoped); // "Visível apenas dentro do bloco"
}

// console.log(blockScoped); // ReferenceError: blockScoped is not defined
console.log(functionScoped); // "Vaza para fora do bloco!" (Comportamento do var)
```

### Escopo de Função e Global

Variáveis declaradas fora de qualquer função ou bloco pertencem ao escopo global. Variáveis declaradas com `var` dentro de uma função pertencem exclusivamente àquela função.

```js title="Escopo de Função"
function calculateTotal() {
  var internalTax = 0.15;
  return 100 * (1 + internalTax);
}

calculateTotal();
// console.log(internalTax); // ReferenceError: internalTax is not defined
```

### Panorama do escopo

Escopo define onde uma variável pode ser acessada. `let` e `const` respeitam escopo
de bloco, ou seja, o trecho entre `{` e `}`.

```js title="Escopo de bloco"
let semester = "2026.2";
console.log(semester); // "2026.2"

if (true) {
  let semester = "inside block";
  const period = "morning";

  console.log(semester); // "inside block"
  console.log(period); // "morning"
}

console.log(semester); // "2026.2"
```

`var` tem escopo de função. Por isso, uma variável declarada dentro de um bloco pode
continuar acessível fora dele quando está na mesma função. Fora da função, ela não
fica disponível.

```js title="Escopo de função com var"
function testBlockScope() {
  if (true) {
    var functionScoped = 1;
    let blockScoped = 2;

    console.log(blockScoped); // 2
  }

  console.log(functionScoped); // 1

  // ReferenceError: blockScoped is not defined.
  // console.log(blockScoped);
}

testBlockScope();

// ReferenceError: functionScoped is not defined.
// console.log(functionScoped);
```

O mesmo vale para `let` e `const`: variáveis declaradas dentro de uma função não
ficam disponíveis fora dela.

```js title="Escopo de função"
function greeting() {
  const message = "Hello";
  console.log(message); // "Hello"
}

greeting();

// ReferenceError: message is not defined.
// console.log(message);
```


### Escopo em laços

`let` cria uma nova associação por iteração em laços `for`. `var`, por ter escopo de
função, compartilha a mesma variável entre as iterações.

```js title="var e let em callbacks"
const callbacksWithVar = [];
const callbacksWithLet = [];

for (var i = 0; i < 3; i++) {
  callbacksWithVar.push(() => i);
}

for (let j = 0; j < 3; j++) {
  callbacksWithLet.push(() => j);
}

console.log(callbacksWithVar.map((callback) => callback())); // [3, 3, 3]
console.log(callbacksWithLet.map((callback) => callback())); // [0, 1, 2]
```


## Hoisting e a Zona Morta Temporal (TDZ)

*Hoisting* (Elevação) é o comportamento pelo qual a engine JavaScript processa
declarações de variáveis e funções antes de executar o código linha a linha.

### Hoisting com `var`

Declarações com `var` são elevadas ao topo de seu escopo e inicializadas com `undefined`.

```js title="Elevação de var"
console.log(userName); // undefined (Não lança erro de referência!)
var userName = "Beatriz";

// O código acima é interpretado pelo V8 como:
// var userName;
// console.log(userName);
// userName = "Beatriz";
```

### Hoisting com `let` e `const` (TDZ)

Variáveis declaradas com `let` e `const` também sofrem *hoisting*, mas **não são inicializadas**. A região do código entre o início do bloco e a linha da declaração é chamada de **Zona Morta Temporal** (*Temporal Dead Zone* - TDZ).

```js title="Acessando variável na TDZ"
// Início do escopo do bloco
// console.log(product); // ReferenceError: Cannot access 'product' before initialization (TDZ!)

let product = "Notebook"; // Fim da TDZ para 'product'
console.log(product); // "Notebook"
```

### Panorama do hoisting

Declarações são processadas antes da execução do código, comportamento chamado de
*hoisting*. Com `var`, a variável existe antes da linha de declaração, mas começa
como `undefined`.

```js title="Hoisting com var"
console.log(hoistedVar); // undefined

var hoistedVar = 10;

console.log(hoistedVar); // 10
```

Com `let` e `const`, acessar a variável antes da declaração gera erro por causa da
*Temporal Dead Zone*.

```js title="Temporal Dead Zone"
// ReferenceError: Cannot access 'tdzLet' before initialization.
// console.log(tdzLet);
// let tdzLet = 10;

// ReferenceError: Cannot access 'tdzConst' before initialization.
// console.log(tdzConst);
// const tdzConst = 10;
```

Na prática, o melhor uso de *hoisting* é evitar depender dele. Declare o nome antes
da primeira leitura para manter a ordem do arquivo parecida com a ordem da execução.

<Aside type="tip" title="Declare antes de usar">
  Mesmo conhecendo *hoisting*, escreva o código na ordem de leitura: declare a
  variável antes de acessar seu valor.
</Aside>


### Globais implícitas

Quando uma atribuição é feita sem declaração, JavaScript pode criar uma variável
global implícita em scripts não estritos. Esse comportamento é perigoso porque
espalha estado pelo programa.

O modo estrito (*strict mode*) é uma forma de pedir que a engine rejeite algumas
permissividades históricas da linguagem. Em um script clássico, ele é ativado com
a diretiva `"use strict"` no início do arquivo ou de uma função. Em ES modules, o
modo estrito já vem ativado automaticamente.

<Aside type="note" title="O que `use strict` muda?">
  A diretiva `"use strict"` faz o JavaScript tratar alguns comportamentos antigos
  como erro em vez de aceitar ou ignorar silenciosamente. Para este tópico, o efeito
  mais importante é impedir a criação acidental de variáveis globais por atribuição
  sem `const`, `let` ou `var`.

  Ela também torna mais visíveis alguns erros que poderiam passar despercebidos,
  como tentar escrever em propriedades não graváveis. A diretiva só vale como modo
  estrito quando aparece no início de um script ou de uma função, antes de outras
  instruções executáveis.
</Aside>

O exemplo abaixo mostra a diferença prática: sem modo estrito, a atribuição sem
declaração cria um nome em `globalThis`; com `"use strict"` ou dentro de um módulo,
a mesma linha passa a gerar `ReferenceError`.

```js title="Global implícita"
// Script clássico sem "use strict":
function createImplicitGlobal() {
  implicitTotal = 100;
  return implicitTotal;
}

console.log(createImplicitGlobal()); // 100
console.log(globalThis.implicitTotal); // 100
delete globalThis.implicitTotal;

// Com "use strict" ou dentro de ES modules:
// ReferenceError: implicitTotal is not defined.
```

O problema das globais implícitas é que elas fazem um nome escapar do local onde a
mudança parecia acontecer. O modo estrito ajuda a transformar esse vazamento
silencioso em erro explícito, o que facilita depuração e evita estado global
acidental.

<Aside type="caution" title="Sempre declare variáveis">
  Use `const`, `let` ou, ao ler código antigo, `var`. Não dependa de globais
  implícitas.
</Aside>


## Case sensitive

JavaScript diferencia letras maiúsculas e minúsculas. Portanto, `number`, `Number`
e `NUMBER` são nomes diferentes.

```js title="Case sensitive"
const number = 8;
const Number = 80;
const NUMBER = 800;

console.log(number); // 8
console.log(Number); // 80
console.log(NUMBER); // 800
```


## Boas práticas

A tabela final concentra escolhas que ajudam a reduzir surpresa em programas
pequenos e também em projetos maiores.

| Prática | Motivo |
| ------- | ------ |
| Prefira `const` | A maior parte dos nomes não precisa ser reassociada |
| Use `let` quando houver mudança | Deixa explícito que o valor varia com o tempo |
| Evite `var` em código novo | Reduz surpresas de escopo, redeclaração e *hoisting* |
| Declare sempre | Evita globais implícitas |
| Use nomes descritivos | Facilita leitura, revisão e depuração |
| Converta explicitamente quando necessário | Reduz resultados inesperados |

Este resumo mostra a regra mais comum em código moderno: `const` por padrão e `let`
quando o valor muda.

```js title="Resumo prático"
const defaultChoice = "const";
let changesOverTime = 0;

changesOverTime += 1;

console.log(defaultChoice); // "const"
console.log(changesOverTime); // 1
```

## Desafio

Crie um array `cart` com objetos de produto. O desafio deve mostrar a diferença
entre associação da variável, mutação de objeto e cálculo com nomes claros. Cada
produto deve ter `name`, `price` e `quantity`. Depois:

1. Adicione um novo produto com `push()`;
2. Altere o preço de um produto;
3. Calcule o total do carrinho;
4. Explique por que essas mudanças são possíveis mesmo quando `cart` foi declarado
   com `const`.

Uma resposta possível mantém `cart` associado ao mesmo array, mas altera o conteúdo
interno da estrutura.

<details>
  <summary>Possível resposta</summary>

  ```js title="cart.js"
  const cart = [
    {
      name: "Teclado",
      price: 129.9,
      quantity: 1,
    },
    {
      name: "Mouse",
      price: 59.9,
      quantity: 2,
    },
  ];

  cart.push({
    name: "Monitor",
    price: 899.9,
    quantity: 1,
  });

  cart[0].price = 119.9;

  const firstTotal = cart[0].price * cart[0].quantity;
  const secondTotal = cart[1].price * cart[1].quantity;
  const thirdTotal = cart[2].price * cart[2].quantity;
  const cartTotal = firstTotal + secondTotal + thirdTotal;

  console.log(cart);
  console.log(cartTotal); // 1139.6
  ```

  `cart` foi declarado com `const`, então a variável não pode receber outro array.
  Ainda assim, o array pode ser modificado com `push()` e os objetos dentro dele
  também podem ter propriedades alteradas. Isso é mutação, não reassociação da
  variável.
</details>


## Perguntas de revisão

### Variáveis e Escopo

**1. Qual é a diferença prática entre `let` e `const`?**

<details>
  <summary>Possível resposta</summary>

  `let` permite reassociar a variável a outro valor. `const` não permite reassociação, devendo ser usada para identificadores que não recebem novo valor.
</details>

**2. Quando faz sentido trocar `const` por `let`?**

<details>
  <summary>Possível resposta</summary>

  Quando o mesmo identificador precisa receber outro valor durante a execução, como um contador, acumulador ou estado que muda em um laço.
</details>

**3. Por que evitar `var` em código JS moderno?**

<details>
  <summary>Possível resposta</summary>

  Porque `var` possui escopo de função, permite redeclarações acidentais e é inicializada como `undefined` via hoisting, favorecendo bugs de escopo.
</details>

**4. O que acontece quando `var` é redeclarado no mesmo escopo?**

<details>
  <summary>Possível resposta</summary>

  A segunda declaração é aceita e pode sobrescrever o valor anterior, o que facilita erros acidentais em código maior.
</details>

**5. Por que `const` não torna um objeto imutável?**

<details>
  <summary>Possível resposta</summary>

  Porque `const` protege a associação da variável, não o conteúdo interno do objeto.
  Um array declarado com `const` ainda pode receber `push()`, e um objeto ainda pode
  ter propriedades alteradas.
</details>

**6. O que é a Zona Morta Temporal (TDZ)?**

<details>
  <summary>Possível resposta</summary>

  É o intervalo entre a entrada em um escopo e a inicialização de uma variável `let`
  ou `const`. Acessar o nome nesse intervalo gera `ReferenceError`.
</details>

**7. O que muda entre `var` e `let` dentro de um laço `for` com callbacks?**

<details>
  <summary>Possível resposta</summary>

  `var` compartilha a mesma variável entre as iterações, então callbacks podem ver o
  valor final do laço. `let` cria uma associação por iteração, preservando o valor
  correspondente a cada volta.
</details>

**8. Por que globais implícitas devem ser evitadas?**

<details>
  <summary>Possível resposta</summary>

  Porque elas criam estado fora do escopo esperado, podem sobrescrever nomes de
  outras partes do programa e deixam erros mais difíceis de encontrar.
</details>

**9. Por que `number`, `Number` e `NUMBER` são três identificadores diferentes?**

<details>
  <summary>Possível resposta</summary>

  Porque JavaScript é *case sensitive*. Letras maiúsculas e minúsculas fazem parte do
  nome do identificador.
</details>
