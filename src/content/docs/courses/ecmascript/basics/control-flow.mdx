Este tópico apresenta as estruturas de controle de fluxo em JavaScript, detalhando as estruturas de decisão (`if`, `else if`, `else`, `switch`), os laços de repetição (`while`, `do...while`, `for`), as instruções de interrupção (`break`, `continue`, `label`) e o aninhamento de laços para solução de problemas multidimensionais.

Materiais: [slides do tópico](../../../../slides/courses/ecmascript/basics/control-flow/) e
[mapa mental](../../../../mindmaps/courses/ecmascript/basics/control-flow/)

## Objetivo

Dominar o controle da ordem de execução de programas em JavaScript, da tomada de decisão condicional à automação de laços de repetição e interrupções de fluxo. Ao final do tópico, o leitor deve ser capaz de:

- Aplicar estruturas condicionais (`if`, `else if`, `else`) utilizando chaves `{}` para eliminar ambiguidades de escopo.
- Diagnosticar e prevenir armadilhas de condição, como atribuição acidental (`=`) e falsos positivos com valores *truthy* e *falsy*.
- Estruturar decisões com `switch`, compreendendo a comparação por igualdade estrita (`===`) e o controle deliberado de *fall-through*.
- Escolher a estrutura de repetição mais adequada (`while`, `do...while` ou `for`) conforme o momento da validação e a existência de contadores.
- Governar o fluxo interno de laços com `break`, `continue` e *labels*, prevenindo a ocorrência de laços infinitos.
- Construir laços aninhados para processar estruturas bidimensionais, tabelas e séries numéricas formatadas.

## Visão geral

A tabela abaixo funciona como mapa inicial. O uso correto depende menos de decorar
a sintaxe e mais de escolher a estrutura que deixa a intenção do código clara.

| Grupo | Statements | Uso comum |
| ----- | ---------- | --------- |
| Decisão simples | `if`, `else` | Executar um bloco ou outro |
| Decisão em cadeia | `if`, `else if`, `else` | Testar faixas, prioridades ou estados |
| Múltiplas opções | `switch`, `case`, `default` | Comparar um valor contra casos conhecidos |
| Repetição por condição | `while`, `do...while` | Repetir até uma condição mudar |
| Repetição por contador | `for` | Percorrer uma sequência controlada por índice |
| Controle interno | `break`, `continue` | Encerrar ou pular uma repetição |
| Controle aninhado | `label` | Interromper ou continuar laços externos em casos específicos |

## Decisão

Estruturas de decisão avaliam uma condição e escolhem qual bloco executar. Em
JavaScript, a condição não precisa ser literalmente `true` ou `false`; ela pode ser
um valor *truthy* ou *falsy*.

### if

O `if` executa o bloco apenas quando a condição é verdadeira ou *truthy*.

```js title="if"
const positiveNumber = 10;

if (positiveNumber > 0) {
  console.log("Positive number"); // "Positive number"
}
```

Use chaves para deixar claro quais linhas pertencem ao `if`. Sem chaves, apenas a
primeira instrução logo após o `if` fica condicionada.

```js title="if sem chaves"
const negativeNumber = -5;

if (negativeNumber > 0)
  console.log("Positive number");
console.log("End of verification"); // "End of verification"
```

No exemplo acima, `console.log("End of verification")` sempre executa, porque ele
não pertence ao corpo do `if`.

<Aside type="tip" title="Prefira chaves">
  JavaScript permite `if` sem chaves quando existe apenas uma instrução, mas chaves
  reduzem ambiguidade e evitam erro quando outra linha é adicionada depois.
</Aside>

### Condição e atribuição

Um erro comum é usar `=` quando a intenção era comparar. O operador `=` atribui
valor; `===` compara valor e tipo.

```js title="Atribuição dentro da condição"
let value = 0;

if (value = 10) {
  console.log("Entered", value); // "Entered" 10
}
```

O código entra no `if` porque `value = 10` atribui `10` e a própria expressão de
atribuição produz `10`, que é um valor *truthy*.

```js title="Comparação explícita"
let value = 0;

if (value === 10) {
  console.log("Entered", value);
} else {
  console.log("Different value"); // "Different value"
}
```

### Truthy e falsy

Valores como `0`, `""`, `null`, `undefined`, `NaN` e `false` são *falsy*. A maioria
dos outros valores é *truthy*, inclusive arrays e objetos vazios.

```js title="Array vazio é truthy"
const list = [];

if (list) {
  console.log("Empty array is truthy"); // "Empty array is truthy"
}
```

Para saber se um array tem itens, teste o tamanho.

```js title="Testando tamanho"
const list = [];

if (list.length) {
  console.log("Array has items");
} else {
  console.log("Array has no items"); // "Array has no items"
}
```

Já `Array.isArray()` responde outra pergunta: ele verifica se o valor é um array.
Isso é útil quando o dado pode vir de uma API, formulário, arquivo JSON ou função
externa. Depois de confirmar que é array, ainda pode ser necessário testar
`.length` para saber se existem itens.

```js title="Verificando se é array"
const list = [];
const maybeList = "not a list";

console.log(Array.isArray(list)); // true
console.log(Array.isArray(maybeList)); // false

if (Array.isArray(list) && list.length > 0) {
  console.log("Array has items");
} else {
  console.log("Value is not an array or array has no items");
}
```

### if, else if e else

O `else` define o caminho alternativo. O `else if` permite testar novas condições
quando as anteriores falham.

```js title="if e else"
const number = 0;

if (number > 0) {
  console.log("Positive number");
} else {
  console.log("Non-positive number"); // "Non-positive number"
}
```

Quando existem três ou mais possibilidades, a cadeia com `else if` pode separar os
casos.

```js title="if, else if e else"
const number = 0;

if (number > 0) {
  console.log("Positive number");
} else if (number < 0) {
  console.log("Negative number");
} else {
  console.log("Zero"); // "Zero"
}
```

O diagrama a seguir ilustra a avaliação sequencial de uma cadeia condicional, na qual o interpretador executa o primeiro bloco verdadeiro e ignora os testes subsequentes:

<Mermaid title="Fluxo de Decisão: if, else if e else">
{`
flowchart TD

  Cond1 -->|Sim| Block1["console.log('Positive number')"]
  Cond1 -->|Não| Cond2{"number < 0?"}
  Cond2 -->|Sim| Block2["console.log('Negative number')"]
  Cond2 -->|Não| Block3["console.log('Zero')"]
  Block1 --> EndNode(["Fim"])
  Block2 --> EndNode
  Block3 --> EndNode
`}
</Mermaid>

### Ordem das condições

A ordem dos testes importa. Em uma cadeia `if / else if`, o primeiro bloco que
passar interrompe o restante da cadeia.

```js title="Ordem que esconde um caso"
const grade = 95;

if (grade >= 60) {
  console.log("Approved"); // "Approved"
} else if (grade >= 90) {
  console.log("Approved with distinction");
} else {
  console.log("Failed");
}
```

Como `95 >= 60` já é verdadeiro, o teste `grade >= 90` nunca chega a executar. A
condição mais específica deve vir antes da mais geral.

```js title="Ordem mais específica primeiro"
const grade = 95;

if (grade >= 90) {
  console.log("Approved with distinction"); // "Approved with distinction"
} else if (grade >= 60) {
  console.log("Approved");
} else {
  console.log("Failed");
}
```

Quando duas mensagens são independentes, dois `if` separados podem fazer mais
sentido do que `else if`.

```js title="Condições independentes"
const grade = 95;

if (grade >= 60) console.log("Approved"); // "Approved"
if (grade >= 90) console.log("Approved with distinction"); // "Approved with distinction"
```

<Aside type="note" title="Cadeia ou testes independentes?">
  Use `else if` quando apenas um caminho deve executar. Use `if` separados quando
  várias condições podem ser verdadeiras ao mesmo tempo e cada uma deve produzir um
  efeito próprio.
</Aside>

### switch

O `switch` compara uma expressão com vários `case`. Ele é útil quando um mesmo valor
pode assumir opções conhecidas, como comandos, tipos ou operadores.

```js title="Calculadora com switch"
const number1 = 10;
const number2 = 20;
const operator = "+";
let result;

switch (operator) {
  case "+":
    result = number1 + number2;
    break;
  case "-":
    result = number1 - number2;
    break;
  case "*":
    result = number1 * number2;
    break;
  case "/":
    result = number1 / number2;
    break;
  default:
    result = "Invalid operator";
}

console.log(result); // 30
```

Cada `case` normalmente termina com `break`. Sem `break`, a execução continua para
os próximos casos.

O diagrama a seguir representa a seleção de casos e o desvio imediato promovido pela instrução `break`:

<Mermaid title="Mapeamento de Casos no switch com break">
{`
flowchart TD
  Expr(["Avalia operator"]) --> Case1{"operator === '+'?"}
  Case1 -->|Sim| Act1["result = n1 + n2<br>break"]
  Case1 -->|Não| Case2{"operator === '-'?"}
  Case2 -->|Sim| Act2["result = n1 - n2<br>break"]
  Case2 -->|Não| CaseMore["... outros casos ..."]
  CaseMore --> Def["default:<br>result = 'Invalid operator'"]
  Act1 --> OutNode(["Fim do switch"])
  Act2 --> OutNode
  Def --> OutNode
`}
</Mermaid>

### switch usa igualdade estrita

O `switch` compara os casos usando igualdade estrita, como `===`. Por isso, `1` e
`"1"` são casos diferentes.

```js title="switch e tipos"
const option = "1";

switch (option) {
  case 1:
    console.log("number one");
    break;
  case "1":
    console.log("string one"); // "string one"
    break;
  default:
    console.log("none");
}
```

### Fall-through

Quando um `case` não possui `break`, JavaScript continua executando os próximos
casos até encontrar um `break` ou o fim do `switch`. Esse comportamento é chamado
de *fall-through*.

```js title="Fall-through acidental"
const selectedOperator = "-";

switch (selectedOperator) {
  case "+":
    console.log("addition");
  case "-":
    console.log("subtraction"); // "subtraction"
  case "*":
    console.log("multiplication"); // "multiplication"
    break;
  default:
    console.log("invalid");
}
```

O *fall-through* também pode ser usado de forma intencional para agrupar casos que
devem executar o mesmo bloco.

```js title="Agrupando cases"
const day = "saturday";

switch (day) {
  case "saturday":
  case "sunday":
    console.log("weekend"); // "weekend"
    break;
  case "monday":
  case "tuesday":
  case "wednesday":
  case "thursday":
  case "friday":
    console.log("weekday");
    break;
  default:
    console.log("invalid day");
}
```

<Aside type="caution" title="Fall-through precisa parecer intencional">
  Quando um `case` não tiver `break` de propósito, deixe o agrupamento explícito ou
  comente a intenção. Caso contrário, a ausência de `break` costuma parecer erro.
</Aside>

### switch(true)

Também é possível usar `switch (true)` para avaliar condições em cada `case`. Isso
pode funcionar para faixas, mas `if / else if` costuma ser mais direto para esse
tipo de lógica.

```js title="switch(true)"
const positiveNumber = 10;

switch (true) {
  case positiveNumber > 0:
    console.log("Positive number"); // "Positive number"
    break;
  case positiveNumber < 0:
    console.log("Negative number");
    break;
  default:
    console.log("Zero");
}
```

## Repetição

Estruturas de repetição executam o mesmo bloco várias vezes. Toda repetição precisa
ter uma condição de parada clara; caso contrário, o programa pode ficar preso em um
laço infinito.

### while

O `while` testa a condição antes de executar o bloco. Se a condição já começar
falsa, o bloco não executa nenhuma vez.

```js title="while"
let count = 1;

while (count <= 5) {
  console.log(count); // 1, 2, 3, 4, 5
  count++;
}
```

Neste segundo exemplo, nada é exibido porque `count < 10` já é falso no início.

```js title="while sem execução"
let count = 10;

while (count < 10) {
  console.log(count);
  count++;
}
```

### do...while

O `do...while` executa o bloco primeiro e testa a condição depois. Por isso, o bloco
executa pelo menos uma vez.

```js title="do...while executa uma vez"
let count = 10;

do {
  console.log(count); // 10
  count++;
} while (count < 10);
```

Quando a condição continua verdadeira, ele segue repetindo.

```js title="do...while repetindo"
let count = 1;

do {
  console.log(count); // 1, 2, 3, 4, 5
  count++;
} while (count <= 5);
```

A diferença fundamental entre `while` e `do...while` reside no momento em que a condição é avaliada, definindo se o bloco pode ser ignorado ou se sempre executa ao menos uma vez:

<Mermaid title="Comparação de Laços: while vs do...while">
{`

    WBody --> WTest
    WTest -->|Não| WEnd(["Saída"])

  subgraph DOWHILE["Laço do...while (1 a N execuções)"]

    DTest -->|Sim| DBody
    DTest -->|Não| DEnd(["Saída"])
  end
`}
</Mermaid>

### for

O `for` concentra inicialização, condição e atualização no cabeçalho. Ele é comum
quando existe um contador ou um intervalo conhecido.

```js title="for"
for (let i = 1; i <= 5; i++) {
  console.log(i); // 1, 2, 3, 4, 5
}
```

O mesmo intervalo pode ser escrito com limites diferentes. `i <= 5` e `i < 6`
produzem a mesma sequência abaixo.

```js title="Limites equivalentes"
for (let i = 1; i <= 5; i++) {
  console.log(i); // 1, 2, 3, 4, 5
}

for (let i = 1; i < 6; i++) {
  console.log(i); // 1, 2, 3, 4, 5
}
```

O `for` também é útil para acumular resultados.

```js title="Somatório"
let total = 0;

for (let i = 1; i <= 10; i++) {
  total += i;
}

console.log(total); // 55
```

<Aside type="caution" title="Dica de IA: Confirme os limites do laço com as três entradas de sempre">
  Erros de contorno (*off-by-one*) são a falha mais comum em laços gerados por IA, e nenhuma delas aparece no exemplo de cinco elementos que acompanha a resposta: `<` trocado por `<=`, índice iniciando em `1` e a lista vazia que nunca foi considerada.

  **Prompt:** *"Execute mentalmente este laço com uma lista vazia, com um único elemento e com o índice do último item. Mostre a saída em cada caso e corrija se houver erro de contorno."*
</Aside>

### break e continue

`continue` pula para a próxima repetição. `break` encerra o laço.

```js title="break e continue"
for (let i = 1; i <= 5; i++) {
  if (i === 3) continue;
  if (i === 5) break;

  console.log(i); // 1, 2, 4
}
```

No exemplo, `3` é pulado por `continue`. Quando `i` chega a `5`, o `break` encerra
o laço antes do `console.log`.

O diagrama a seguir ilustra a mecânica de desvio de fluxo entre `continue` e `break`:

<Mermaid title="Desvio de Fluxo: break vs continue">
{`
flowchart TD
  Test{"Iteração ativa"} --> CondCheck{"Testa condição"}
  CondCheck -->|"fluxo normal"| Body["Executa o corpo restante"]
  Body --> NextIter["Próximo passo<br>incremento e condição"]
  CondCheck -->|continue| NextIter
  CondCheck -->|break| ExitLoop["Encerra o laço<br>e sai da estrutura"]
  NextIter --> Test
`}
</Mermaid>

<Aside type="tip" title="Laço infinito no terminal">
  Se um teste ficar preso em um laço infinito no terminal, interrompa com
  <kbd>Ctrl</kbd> + <kbd>C</kbd>. Depois verifique se a condição de parada muda em
  algum ponto do laço.
</Aside>

### Laços aninhados

Um laço pode ficar dentro de outro. Isso é útil para gerar combinações, percorrer
linhas e colunas ou montar séries.

```js title="Laços aninhados"
let output = "";

for (let ten = 0; ten <= 2; ten++) {
  for (let unit = 0; unit <= 2; unit++) {
    output += `${ten}${unit} `;
  }
}

console.log(output.trim()); // "00 01 02 10 11 12 20 21 22"
```

O laço externo controla a dezena; o laço interno controla a unidade. Para cada
valor de `ten`, o laço de `unit` executa completo.

### Labels

Labels dão nome a um statement. Em laços aninhados, eles permitem que `break` ou
`continue` atinjam um laço externo.

```js title="break com label"
outerBreak:
for (let i = 1; i <= 3; i++) {
  for (let j = 1; j <= 3; j++) {
    if (j === 2) break outerBreak;

    console.log(i, j); // 1 1
  }
}
```

Neste caso, `break outerBreak` encerra o laço externo inteiro, não apenas o laço de
`j`.

```js title="continue com label"
outerContinue:
for (let i = 1; i <= 3; i++) {
  for (let j = 1; j <= 3; j++) {
    if (j === 2) continue outerContinue;

    console.log(i, j); // 1 1, 2 1, 3 1
  }
}
```

Aqui, `continue outerContinue` pula para a próxima repetição do laço externo.

<Aside type="caution" title="Labels são raros">
  Labels existem na linguagem, mas aparecem pouco em código Web comum. Quando eles
  começarem a deixar o fluxo difícil de acompanhar, considere extrair uma função ou
  simplificar a lógica.
</Aside>

<Aside type="tip" title="Dica de IA: Peça a reescrita com retorno antecipado">
  Modelos tendem a devolver decisões em pirâmide, com `if` dentro de `if` dentro de `else`. Um segundo pedido costuma remover dois níveis de indentação sem alterar o comportamento.

  **Prompt:** *"Reescreva esta função com cláusulas de guarda: trate primeiro os casos inválidos com `return` antecipado, elimine os `else` e mantenha exatamente o mesmo resultado para todas as entradas."*
</Aside>

## Boas práticas

A tabela a seguir consolida as diretrizes essenciais para estruturar o fluxo de execução com clareza e previsibilidade:

| Prática | Motivo |
| ------- | ------ |
| Sempre utilize chaves `{}` | Previne bugs silenciosos ao adicionar novas instruções a blocos `if` ou laços |
| Utilize `===` em testes de condição | Impede atribuições acidentais com `=` e evita coerções imprevisíveis de tipo |
| Inspecione arrays com `Array.isArray()` e `.length` | Arrays vazios `[]` são *truthy*, exigindo validação explícita de itens |
| Ordene `else if` do específico para o geral | Condições mais amplas no topo capturam o fluxo precocemente e mascaram regras específicas |
| Finalize casos de `switch` com `break` | Evita *fall-through* inadvertido que executa múltiplos blocos por engano |
| Garanta atualização da variável de controle | Assegura que a condição de parada seja alcançada, prevenindo laços infinitos |

O exemplo a seguir reúne essas práticas em uma rotina defensiva de processamento de pedidos:

```js title="Resumo prático"
const orders = [
  { id: 1, items: 3, priority: "express" },
  { id: 2, items: 0, priority: "standard" },
];

// 1. Validação explícita de array e tamanho
if (Array.isArray(orders) && orders.length > 0) {
  for (let i = 0; i < orders.length; i++) {
    const order = orders[i];

    // 2. Chaves obrigatórias e interrupção limpa
    if (order.items === 0) {
      console.log(`Order ${order.id}: empty`);
      continue;
    }

    // 3. switch com igualdade estrita e break explícito
    let deliveryDays;
    switch (order.priority) {
      case "express":
        deliveryDays = 1;
        break;
      case "standard":
        deliveryDays = 3;
        break;
      default:
        deliveryDays = 5;
    }

    console.log(`Order ${order.id}: delivery in ${deliveryDays} days`);
  }
}
```

## Exercício

Os exercícios a seguir fixam a aplicação de estruturas de decisão em cadeia e laços aninhados com formatação controlada:

### Exercício 1: Classificação de nota

Crie um arquivo `grade-status.js`. Ele deve receber uma nota em uma variável `grade` e exibir a situação acadêmica do estudante:

1. `"Approved with distinction"` quando a nota for maior ou igual a `90`;
2. `"Approved"` quando a nota for maior ou igual a `60`;
3. `"Failed"` nos demais casos;
4. Teste a execução com os valores `95`, `75` e `40`.

A solução a seguir estrutura a cadeia condicional priorizando a regra mais restritiva no início:

<details>
  <summary>Possível resposta</summary>

  ```js title="grade-status.js"
  const grade = 95;

  if (grade >= 90) {
    console.log("Approved with distinction");
  } else if (grade >= 60) {
    console.log("Approved");
  } else {
    console.log("Failed");
  }
  ```

  A condição `grade >= 90` aparece antes de `grade >= 60` porque ela é mais
  específica. Se a ordem fosse invertida, uma nota `95` seria classificada apenas
  como `"Approved"`.
</details>

### Exercício 2: Séries numéricas com laços aninhados

Crie um arquivo `numeric-series.js` utilizando laços aninhados (`for`) para gerar uma série numérica de `00` a `99` formatada:

1. Imprima os números organizados em linhas contendo 10 elementos por dezena (de `00` a `09`, `10` a `19`, ..., `90` a `99`);
2. Separe os números da mesma linha por vírgula e espaço;
3. Inclua quebra de linha (`\n`) ao final de cada dezena;
4. O último elemento da série (`99`) não deve conter vírgula no final.

A saída esperada no console deve seguir este formato:

```txt title="Output Esperado"
00, 01, 02, 03, 04, 05, 06, 07, 08, 09,
```

  ```js title="numeric-series.js"
  let numbers = "";
  ```

## Desafio

Crie um arquivo `schedule-report.js` combinando `switch` e `for`:

1. Use `switch` para classificar uma variável `day` em `"weekend"`, `"weekday"` ou `"invalid day"`, agrupando sábado e domingo no mesmo caso;
2. Em seguida, utilize um laço `for` para gerar os números de `01` a `10`;
3. Pule o número `05` utilizando a instrução `continue`;
4. Encerre o laço ao atingir o número `09` utilizando a instrução `break`.

A solução a seguir integra a decisão múltipla com interrupções controladas de laço:

<details>
  <summary>Possível resposta</summary>

  ```js title="schedule-report.js"
  const day = "saturday";

  switch (day) {
    case "saturday":
    case "sunday":
      console.log("weekend");
      break;
    case "monday":
    case "tuesday":
    case "wednesday":
    case "thursday":
    case "friday":
      console.log("weekday");
      break;
    default:
      console.log("invalid day");
  }

  for (let i = 1; i <= 10; i++) {
    if (i === 5) continue;
    if (i === 9) break;

    console.log(String(i).padStart(2, "0"));
  }
  ```

  ```txt title="Output" frame="terminal"
  weekend
  01
  02
  03
  04
  06
  07
  08
  ```
</details>

## Perguntas de revisão

### Decisão

1. Qual é a diferença entre usar `if` com e sem chaves?

<details>
  <summary>Possível resposta</summary>

  Sem chaves, apenas a primeira instrução após o `if` pertence ao bloco
  condicional. Com chaves, todas as instruções dentro de `{}` pertencem ao `if`.
</details>

2. Por que `if (value = 10)` pode entrar no bloco mesmo quando a intenção era
   comparar?

<details>
  <summary>Possível resposta</summary>

  Porque `=` faz atribuição. A expressão atribui `10` a `value` e produz o próprio
  valor `10`, que é *truthy*. Para comparar valor e tipo, use `value === 10`.
</details>

3. Um array vazio é *truthy* ou *falsy*? Como testar se ele tem itens?

<details>
  <summary>Possível resposta</summary>

  Um array vazio é *truthy*. Para testar se ele tem itens, use `list.length` ou uma
  comparação explícita como `list.length > 0`.
</details>

4. Por que a ordem dos `else if` pode mudar o resultado?

<details>
  <summary>Possível resposta</summary>

  Porque a cadeia para no primeiro bloco verdadeiro. Condições mais específicas,
  como `grade >= 90`, devem vir antes de condições mais gerais, como `grade >= 60`.
</details>

5. Qual comparação o `switch` usa para comparar `case`?

<details>
  <summary>Possível resposta</summary>

  O `switch` usa igualdade estrita, equivalente a `===`. Por isso, `1` e `"1"` não
  são o mesmo caso.
</details>

6. O que é *fall-through* em `switch`?

<details>
  <summary>Possível resposta</summary>

  É a continuação da execução para os próximos `case` quando não existe `break`.
  Pode ser erro acidental ou uma técnica intencional para agrupar casos.
</details>

### Repetição

7. Qual é a diferença prática entre `while` e `do...while`?

<details>
  <summary>Possível resposta</summary>

  `while` testa a condição antes de executar o bloco. `do...while` executa o bloco
  primeiro e só depois testa a condição, então roda pelo menos uma vez.
</details>

8. Quais são as três partes comuns do cabeçalho de um `for`?

<details>
  <summary>Possível resposta</summary>

  Inicialização, condição e atualização. Exemplo: `for (let i = 0; i < 10; i++)`.
</details>

9. Qual é a diferença entre `break` e `continue`?

<details>
  <summary>Possível resposta</summary>

  `break` encerra o laço. `continue` pula o restante da repetição atual e segue
  para a próxima.
</details>

10. Quando um laço aninhado é útil?

<details>
  <summary>Possível resposta</summary>

  Quando o problema tem combinações ou dimensões, como linhas e colunas, dezenas e
  unidades, tabelas, matrizes ou pares de valores.
</details>

11. Para que servem labels com `break` ou `continue`?

<details>
  <summary>Possível resposta</summary>

  Servem para direcionar `break` ou `continue` a um statement nomeado, como um laço
  externo. São úteis em casos específicos, mas devem ser usados com cuidado.
</details>
