## Objetivo

Compreender como expressões e operadores compõem e transformam dados em JavaScript. Diferenciar expressões de *statements*, dominar as regras de precedência e associatividade na montagem da AST, utilizar operadores aritméticos, relacionais, de igualdade estrita, lógicos com avaliação em curto-circuito, coalescência nula e encadeamento opcional, aplicando parênteses explícitos para garantir clareza e previsibilidade de execução.

## Expressões e Statements

Uma expressão produz um valor. Esse valor pode ser exibido, atribuído a uma
variável, passado para uma função ou combinado com outra expressão.

```js title="Expressões"
console.log(1 + 1); // 2

let assignedValue;
console.log((assignedValue = 5)); // 5

let expressionCount = 0;
console.log(expressionCount++); // 0
console.log(expressionCount); // 1

console.log(18 >= 18 ? "adult" : "minor"); // "adult"
```

Um *statement* é uma instrução que organiza a execução do programa. Declarações,
`if`, `for`, `while`, `return` e blocos com `{}` são exemplos comuns. Nem todo
*statement* pode ser usado onde uma expressão é esperada.

```js title="Statement não é expressão"
// SyntaxError: Unexpected token 'if'.
// const result = if (true) { 1 } else { 2 };

// Uma declaração é um statement, não uma expressão.
// const total = const value = 5;
```

<Aside type="note" title="Expressão gera valor">
  A pergunta prática é: “isso produz um valor que posso usar aqui?”. `1 + 1`,
  `age >= 18`, `user.name` e `condition ? a : b` são expressões. Um `if`
  tradicional controla fluxo, mas não pode ser colocado diretamente no lado direito
  de uma atribuição. Essa separação muda entre linguagens: em Ruby, por exemplo,
  `if` pode produzir um valor e ser usado em uma atribuição. Neste tópico, a regra
  considerada é a de JavaScript.
</Aside>

### Ponto e vírgula e ASI

JavaScript possui ASI (*Automatic Semicolon Insertion*): em muitos casos, a engine
insere `;` automaticamente ao interpretar que uma instrução terminou. Por isso,
muitos códigos funcionam mesmo sem ponto e vírgula no fim da linha.

```js title="ASI em caso simples"
const subtotal = 10 + 5
console.log(subtotal) // 15
```

Isso não significa que `;` seja sempre opcional. Quando a próxima linha começa com
tokens que podem continuar a expressão anterior, como `(`, `[`, `/`, `+` ou `-`, o
código pode ser interpretado de forma diferente da intenção.

```js title="Quando o ponto e vírgula importa"
const total = 10
(function showTotal() {
  console.log(total)
})()
```

O código acima pode ser lido como uma tentativa de chamar `10` como função. O ponto
e vírgula separa claramente as duas instruções:

```js title="Separando instruções"
const total = 10;

(function showTotal() {
  console.log(total);
})();
```

O cabeçalho do `for` também ilustra um caso em que `;` é obrigatório: ele separa
inicialização, condição e atualização. Esses pontos e vírgulas não são inseridos por
ASI.

```js title="Ponto e vírgula no for"
for (let index = 0; index < 3; index++) {
  console.log(index);
}
```

<Aside type="caution" title="Quando usar ;">
  Mesmo em projetos que omitem ponto e vírgula por estilo, use `;` quando uma linha
  começar com `(`, `[`, `/`, `+` ou `-`, ou quando houver risco de a próxima linha
  continuar a expressão anterior. Formatadores como Prettier ajudam a manter essa
  escolha consistente.
</Aside>

### Objeto global

Algumas expressões dependem do ambiente em que o JavaScript está rodando. No
navegador existe `window`; no Node.js, `window` normalmente não existe. `globalThis`
é a forma padronizada de acessar o objeto global do ambiente atual.

```js title="Ambiente de execução"
console.log(typeof window); // "undefined", quando roda no Node.js
console.log(typeof globalThis); // "object"

// ReferenceError: window is not defined.
// console.log(window);
```

<Aside type="tip" title="Terminal e navegador podem divergir">
  Ao testar expressões, confirme onde o código está rodando. Um exemplo que usa
  `document`, `window` ou elementos HTML depende do navegador; um script executado
  com `node arquivo.js` não possui esses objetos por padrão.
</Aside>

## Precedência e Agrupamento

Quando uma expressão tem vários operadores, JavaScript precisa decidir o que será
calculado primeiro. Essa ordem é chamada de precedência.

| Conceito | Pergunta que responde | Exemplo |
| -------- | --------------------- | ------- |
| Precedência | Qual operador executa primeiro? | `20 - 10 * 2` |
| Agrupamento | Como forçar uma ordem? | `(20 - 10) * 2` |
| Associatividade | Em qual direção operadores iguais agrupam? | `20 - 10 - 5` |

A conversão de Fahrenheit para Celsius mostra por que parênteses não são apenas
detalhe visual. A fórmula correta é `(fahrenheit - 32) / 1.8`.

<math display="block" xmlns="http://www.w3.org/1998/Math/MathML">
  <mi>C</mi>
  <mo>=</mo>
  <mfrac>
    <mrow>
      <mi>F</mi>
      <mo>-</mo>
      <mn>32</mn>
    </mrow>
    <mn>1.8</mn>
  </mfrac>
</math>

Sem agrupamento, a divisão acontece antes da subtração:

```js title="Sem agrupamento"
const fahrenheit = 50;
const wrongCelsius = fahrenheit - 32 / 1.8;

console.log(wrongCelsius); // 32.22222222222222
```

Com parênteses, a subtração acontece primeiro:

```js title="Com agrupamento"
const fahrenheit = 50;
const celsius = (fahrenheit - 32) / 1.8;

console.log(celsius); // 10
```

Outros exemplos seguem a mesma regra: operadores de maior precedência são avaliados
antes, a menos que os parênteses indiquem outra ordem.

```js title="Precedência"
console.log(20 - 10 * 2); // 0
console.log((20 - 10) * 2); // 20

console.log(2 * 3 ** 2); // 18
console.log((2 * 3) ** 2); // 36

console.log(true || false && false); // true
console.log((true || false) && false); // false
```

O diagrama a seguir sintetiza como a presença dos parênteses altera a topologia da **Árvore de Sintaxe Abstrata (AST — *Abstract Syntax Tree*)** construída pela *engine* durante a análise sintática da expressão:

<Mermaid title="Árvore de Sintaxe Abstrata (AST): Precedência Padrão vs Agrupamento Explícito">
{`
flowchart TD
  subgraph SemParenteses["20 - 10 * 2 (Precedência Padrão)"]
    direction TB
    Sub1["Subtração (-)"]
    Left1["20"]
    Mult1["Multiplicação (*)"]
    MLeft1["10"]
    MRight1["2"]
    Sub1 --> Left1
    Sub1 --> Mult1
    Mult1 --> MLeft1
    Mult1 --> MRight1
  end

  subgraph ComParenteses["(20 - 10) * 2 (Agrupamento Forçado)"]
    direction TB
    Mult2["Multiplicação (*)"]
    Sub2["Subtração (-)"]
    SLeft2["20"]
    SRight2["10"]
    Right2["2"]
    Mult2 --> Sub2
    Mult2 --> Right2
    Sub2 --> SLeft2
    Sub2 --> SRight2
  end
`}
</Mermaid>

Internamente, a *engine* não avalia o código como texto plano, mas constrói uma árvore sintática (AST) na qual os nós inferiores são calculados primeiro (*bottom-up*) e propagados para a raiz. No primeiro cálculo, a multiplicação é o nó inferior resolvido primeiro, fornecendo seu produto (20) para a subtração final (20 - 20 = 0). No segundo cálculo, os parênteses alteram a topologia da AST e promovem a subtração a nó prioritário, calculando 10 antes da multiplicação final (10 * 2 = 20).

<Aside type="caution" title="Misturas proibidas">
  Alguns operadores não podem ser misturados sem parênteses. Por exemplo,
  `null ?? false || true` gera `SyntaxError`; escreva `(null ?? false) || true`
  quando quiser combinar `??` com `||` ou `&&`.
</Aside>

O trecho a seguir demonstra na prática o erro gerado pela ambiguidade entre coalescência nula e operadores lógicos, além da correção com parênteses:

```js title="Nullish coalescing com parênteses"
// SyntaxError: Unexpected token '||'.
// console.log(null ?? false || true);

console.log((null ?? false) || true); // true
```

Referência: [Operator precedence | MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Operator_precedence).

## Associatividade

Associatividade decide como operadores de mesma precedência são agrupados. A maioria
dos operadores aritméticos agrupa da esquerda para a direita; exponenciação agrupa
da direita para a esquerda.

```js title="Associatividade"
console.log(20 - 10 - 5); // 5, associatividade: →
console.log(2 ** 3 ** 2); // 512, associatividade: ←
```

Associatividade também afeta concatenação e coerção quando `+` mistura números e
strings.

```js title="Associatividade e coerção"
console.log(2 + 3 + "4"); // "54"
console.log("2" + 3 + 4); // "234"
```

No primeiro caso, `2 + 3` acontece antes e gera `5`; depois ocorre concatenação com
`"4"`. No segundo, a primeira operação já envolve string, então o restante segue
como concatenação.

### Aritméticos

Os operadores aritméticos (`+`, `-`, `*`, `/`, `%`, `**`) realizam cálculos numéricos e produzem, em geral, valores do tipo `number`. Isso vale inclusive para a divisão com `/`: JavaScript não separa divisão inteira de divisão decimal automaticamente. O operador `%` retorna o resto da divisão, não uma porcentagem.

```js title="Operadores aritméticos"
console.log(10 + 5); // 15
console.log(10 - 5); // 5
console.log(10 * 5); // 50
console.log(10 / 5); // 2
console.log(10 % 3); // 1
console.log(2 ** 3); // 8
```

JavaScript não possui um operador próprio de divisão inteira. A divisão com `/`
sempre produz um valor `number`; para descartar ou ajustar a parte decimal, use uma
função de arredondamento conforme a regra desejada.

```js title="Divisão inteira por arredondamento"
console.log(7 / 2); // 3.5
console.log(Math.trunc(7 / 2)); // 3
console.log(Math.floor(7 / 2)); // 3
console.log(Math.ceil(7 / 2)); // 4
console.log(Math.round(7 / 2)); // 4
```

Com números negativos, `Math.trunc()` e `Math.floor()` produzem resultados
diferentes.

```js title="Divisão com número negativo"
console.log(Math.trunc(-7 / 2)); // -3
console.log(Math.floor(-7 / 2)); // -4
```

O resto mantém o sinal do dividendo. Quando a ideia é normalizar índices, uma
expressão extra pode ser necessária.

```js title="Resto da divisão"
console.log(7 % 3); // 1
console.log(-7 % 3); // -1
console.log(7 % -3); // 1
console.log(7.5 % 2); // 1.5

const index = -7;
console.log(((index % 3) + 3) % 3); // 2
```

### Unários

Os operadores unários (`+`, `-`, `!`, `typeof`, `delete`) atuam sobre um único operando. Eles aparecem frequentemente em conversão numérica rápida, negação booleana, inspeção de tipo e remoção de propriedades.

```js title="Operadores unários"
console.log(+"5"); // 5
console.log(-"5"); // -5
console.log(!true); // false
console.log(!!"text"); // true
console.log(typeof "DW"); // "string"
console.log(typeof undeclaredName); // "undefined"
```

<Aside type="caution" title="Legibilidade importa">
  JavaScript permite sequências como `20 - + + +10 * 2`, mas esse tipo de expressão
  é difícil de ler. Em código de aula e produção, prefira conversões explícitas e
  parênteses quando a intenção não estiver óbvia.
</Aside>

```js title="Unários difíceis de ler"
// SyntaxError: Invalid left-hand side expression in prefix operation.
// console.log(20 - +++10 * 2);
// console.log(20 - ++10);

console.log(20 - + + +10 * 2); // 0
```

### Incremento e decremento

Os operadores de incremento (`++`) e decremento (`--`) alteram o valor de uma variável em uma unidade. A posição do operador (prefixo ou pós-fixo) define o valor retornado pela expressão:

```js title="Prefixo e pós-fixo"
let count = 0;

const postfix = count++;
console.log(postfix); // 0
console.log(count); // 1

const prefix = ++count;
console.log(prefix); // 2
console.log(count); // 2
```

O mesmo vale para decremento:

```js title="Decremento"
let decrement = 2;

const decrementPostfix = decrement--;
console.log(decrementPostfix); // 2
console.log(decrement); // 1

const decrementPrefix = --decrement;
console.log(decrementPrefix); // 0
console.log(decrement); // 0
```

### Relacionais

Os operadores relacionais (`<`, `<=`, `>`, `>=`, `in`, `instanceof`) comparam grandezas ou verificam pertinência, retornando sempre valores booleanos (`true` ou `false`). Quando tipos diferentes são comparados, JavaScript pode fazer coerção; quando duas strings são comparadas, a comparação é lexicográfica:

```js title="Comparações relacionais"
console.log(10 > 9); // true
console.log(10 >= 10); // true
console.log(9 <= 10); // true
console.log("10" > 9); // true
console.log("2" > "10"); // true
console.log("10" > "9"); // false
console.log("abc" < "abd"); // true
console.log("2" > 10); // false
```

`in` verifica se uma propriedade existe em um objeto ou índice existe em um array.
Para verificar se um valor aparece dentro de um array, `includes()` costuma ser mais
direto.

```js title="Operador in"
const person = { name: "Fulano", address: null };

console.log("name" in person); // true
console.log("age" in person); // false
console.log(3 in [1, 2, 3]); // false
console.log(0 in [1, 2, 3]); // true
console.log([1, 2, 3].includes(3)); // true
```

`instanceof` verifica se um objeto foi criado a partir de uma função construtora ou
classe na cadeia de protótipos.

```js title="instanceof"
console.log([] instanceof Array); // true
console.log([] instanceof Object); // true
console.log(new Date() instanceof Date); // true
console.log((() => {}) instanceof Function); // true
console.log("text" instanceof String); // false
console.log(42 instanceof Number); // false
```

### Igualdade

Os operadores de igualdade estrita (`===`, `!==`) e solta (`==`, `!=`) comparam valores em JavaScript. Use `===` e `!==` como padrão incondicional: eles comparam valor e tipo sem conversões implícitas. Já `==` e `!=` permitem coerção automática antes da comparação, o que pode esconder resultados inesperados:

```js title="Igualdade"
console.log(1 == 1); // true
console.log(1 === 1); // true
console.log(1 == "1"); // true
console.log(1 === "1"); // false
console.log(1 != "1"); // false
console.log(1 !== "1"); // true
```

A página [Equality comparisons and sameness | MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Equality_comparisons_and_sameness)
explica as diferenças entre igualdade solta, igualdade estrita e outras formas de
comparação usadas pela linguagem. A
[JavaScript Equality Table](https://dorey.github.io/JavaScript-Equality-Table/)
ajuda a visualizar casos curiosos de coerção com `==`; use-a como consulta para
entender o comportamento, não como motivo para escrever comparações ambíguas.

<Aside type="tip" title="Regra prática">
  Prefira `===` e `!==`. Use `==` apenas quando você souber exatamente qual coerção
  está sendo aplicada e por que ela é desejada.
</Aside>

<Aside type="note" title="Coerção: conversão implícita">
  Coerção é conversão implícita: JavaScript converte um valor automaticamente para
  executar uma operação. O mesmo operador pode ter comportamentos diferentes
  conforme os tipos envolvidos.

  ```js title="Coerção"
  console.log("5" + 9); // "59"
  console.log("5" - 3); // 2
  console.log(`total: ${42}`); // "total: 42"

  if ("text") {
    console.log("entered"); // "entered"
  }

  console.log(Number("5") + 9); // 14
  console.log(String(42)); // "42"
  ```

  Nem toda tentativa de combinar tipos termina em coerção bem-sucedida. Alguns
  casos lançam erro em tempo de execução.

  ```js title="Coerção que gera erro"
  // TypeError: Cannot mix BigInt and other types.
  // console.log(1n + 1);

  // TypeError: Cannot convert a Symbol value to a string.
  // console.log("id: " + Symbol("id"));
  ```
</Aside>

### Lógicos e coalescência nula

Os operadores lógicos (`&&`, `||`, `!`) e o operador de coalescência nula (`??`) combinam condições booleanas e selecionam valores em tempo de execução. Em JavaScript, eles não retornam apenas `true` ou `false`, mas devolvem diretamente um dos próprios operandos avaliados:

```js title="Operadores lógicos"
console.log(true && true); // true
console.log(true && false); // false
console.log(false || true); // true
console.log(false || false); // false
console.log(!false); // true

console.log("a" && "b"); // "b"
console.log("" || "default"); // "default"
console.log(0 && "x"); // 0
console.log(typeof (1 && 2)); // "number"
```

`||` trata qualquer valor *falsy* como ausência. `??` trata apenas `null` e
`undefined` como ausência.

```js title="|| e ??"
let value;
console.log(value || 10); // 10
console.log(value ?? 10); // 10

value = 0;
console.log(value || 10); // 10
console.log(value ?? 10); // 0
```

O diagrama a seguir detalha o fluxo de avaliação em curto-circuito dos operadores lógicos e do operador de coalescência nula:

<Mermaid title="Curto-Circuito: &&, || e ??">
{`
flowchart LR
  subgraph AND["A && B"]
    direction TB
    Q1{"A é falsy?"}
    Q1 -->|Sim| R1["Retorna A"]
    Q1 -->|Não| B1["Avalia B"]
  end

  subgraph OR["A || B"]
    direction TB
    Q2{"A é truthy?"}
    Q2 -->|Sim| R2["Retorna A"]
    Q2 -->|Não| B2["Avalia B"]
  end

  subgraph NULLISH["A ?? B"]
    direction TB
    Q3{"A é null / undefined?"}
    Q3 -->|Não| R3["Retorna A"]
    Q3 -->|Sim| B3["Avalia B"]
  end
`}
</Mermaid>

Esse mecanismo de avaliação condicional explica por que operadores lógicos podem ser usados com segurança para proteger chamadas de função ou para definir valores substitutos sem executar código desnecessário.

<Aside type="tip" title="Prefira ?? para valor padrão preservando 0">
  Se `0`, `""` ou `false` forem valores válidos, `??` costuma ser mais adequado que
  `||`, porque só substitui `null` e `undefined`.
</Aside>

### Bitwise

Os operadores bitwise (`&`, `|`, `^`, `~`, `<<`, `>>`, `>>>`) trabalham diretamente com a representação binária de 32 bits de números inteiros. Embora apareçam menos no desenvolvimento web convencional, são fundamentais em manipulação de *flags*, máscaras binárias, controle de permissões e cálculos de baixo nível.

Em uma operação bitwise, cada posição binária é comparada com a posição equivalente
do outro número. O resultado também é formado bit a bit. A conta fica mais clara na
vertical:

```txt title="5 & 3"
  0101
& 0011
------
  0001  // 1
```

A operação de disjunção (`|`) avalia as mesmas posições sob a regra do OU inclusivo:

```txt title="5 | 3"
  0101
| 0011
------
  0111  // 7
```

Já a disjunção exclusiva (`^`, XOR) preserva apenas as posições em que os bits comparados são diferentes:

```txt title="5 ^ 3"
  0101
^ 0011
------
  0110  // 6
```

O operador `&` mantém `1` apenas quando os dois bits são `1`. O operador `|` mantém
`1` quando ao menos um dos bits é `1`. O operador `^` mantém `1` quando os bits são
diferentes.

```js title="Bit a bit"
console.log(0b0101 & 0b0011); // 1  -> 0001
console.log(0b0101 | 0b0011); // 7  -> 0111
console.log(0b0101 ^ 0b0011); // 6  -> 0110
```

Deslocamentos movem os bits para a esquerda ou para a direita. Deslocar para a
esquerda costuma equivaler a multiplicar por potências de 2, dentro dos limites da
representação usada:

```js title="Deslocamento de bits"
console.log(0b0011 << 1); // 6  -> 0110
console.log(0b1100 >> 1); // 6  -> 0110
console.log(1 << 3); // 8  -> 1000
```

O bloco a seguir reúne os principais operadores bitwise da linguagem, incluindo a inversão unária com o operador til (`~`):

```js title="Operadores bitwise"
console.log(1 & 1); // 1
console.log(2 & 1); // 0
console.log(4 | 2); // 6
console.log(5 ^ 3); // 6
console.log(3 << 1); // 6
console.log(12 >> 1); // 6
console.log(1 << 3); // 8
console.log(~5); // -6
```

<Aside type="note" title="Não confunda lógico com bitwise">
  `&&` e `||` são operadores lógicos. `&` e `|` são operadores bitwise. Um caractere
  a menos muda completamente a operação. Além disso, `&&` e `||` fazem
  curto-circuito: dependendo do valor da esquerda, o lado direito nem é executado.
  Operadores bitwise como `&` e `|` avaliam os dois lados antes de operar bit a bit.
</Aside>

O exemplo abaixo usa uma função com `console.log` apenas para deixar visível quando
o lado direito da expressão é executado.

```js title="Curto-circuito"
function rightSide() {
  console.log("lado direito executado");
  return true;
}

console.log(false && rightSide()); // false
console.log(false & rightSide());  // "lado direito executado"
                                   // 0
```

No primeiro `console.log`, `rightSide()` não executa. No segundo, ela executa porque
`&` não faz curto-circuito; depois, os valores são convertidos para operação bitwise.

### Condicional ternário

O operador condicional ternário (`condicao ? exprSeVerdade : exprSeFalso`) escolhe entre dois valores com base em um teste lógico. Por ser uma expressão que produz valor, ele pode ser atribuído diretamente a uma variável ou passado como argumento:

```js title="Operador condicional"
const age = 18;
const ageStatus = age >= 18 ? "adult" : "minor";

console.log(ageStatus); // "adult"
```

Use ternário para escolhas curtas. Quando a lógica tiver muitos passos, `if` tende a
ser mais legível.

### Atribuição e atribuição lógica

Os operadores de atribuição direta (`=`), aritmética composta (`+=`, `-=`, `*=`, `/=`, `%=`, `**=`) e lógica (`||=`, `??=`, `&&=`) guardam ou atualizam valores em variáveis. As atribuições compostas combinam uma operação aritmética prévia com a atualização do identificador:

```js title="Atribuições compostas"
let total = 10;

total += 5;
console.log(total); // 15

total *= 2;
console.log(total); // 30
```

Quando `+` envolve string, ele concatena. Outros operadores aritméticos tendem a
converter o texto para número quando possível.

```js title="Atribuição e coerção"
let text = "10";
text += 5;
console.log(text); // "105"
console.log(typeof text); // "string"

let numericText = "10";
numericText -= 5;
console.log(numericText); // 5
```

Desestruturação também é uma forma de atribuição: ela extrai partes de arrays ou
objetos para nomes locais.

```js title="Desestruturação"
const [first, second] = [1, 2];
console.log(first); // 1
console.log(second); // 2

const { name, course } = { name: "Fulano", course: "DW" };
console.log(name); // "Fulano"
console.log(course); // "DW"
```

Operadores de atribuição lógica atualizam uma variável apenas quando uma condição
curta é satisfeita.

```js title="Atribuição lógica"
let a = 0;
let b = null;
let c = "text";

a ||= 10;
b ??= 20;
c &&= c.toUpperCase();

console.log(a, b, c); // 10 20 TEXT
```

### Encadeamento opcional

O operador de encadeamento opcional (*optional chaining*, `?.`) evita interrupções por exceção de tipo (`TypeError`) ao acessar propriedades ou chamar métodos de valores que podem ser `null` ou `undefined`:

```js title="Optional chaining"
const student = { name: "Fulano", address: null };

console.log(student.address?.city); // undefined
console.log(student.contact?.email); // undefined
console.log(student.save?.()); // undefined
console.log(student.address?.city ?? "not informed"); // "not informed"
```

Sem `?.`, o acesso tenta continuar mesmo quando `address` é `null`, gerando erro em
tempo de execução.

```js title="Acesso sem optional chaining"
// TypeError: Cannot read properties of null (reading 'city').
// console.log(student.address.city);
```

O diagrama a seguir ilustra o caminho de avaliação segura executado pelo operador:

<Mermaid title="Fluxo de Navegação Segura com Optional Chaining (?.)">
{`
flowchart TD
  Start["student?.address?.city"] --> CheckStudent{"student é null<br>ou undefined?"}
  CheckStudent -->|Sim| ReturnUndef1["Retorna undefined<br>(Sem erro)"]
  CheckStudent -->|Não| GetAddress["Acessa student.address"]
  GetAddress --> CheckAddress{"address é null<br>ou undefined?"}
  CheckAddress -->|Sim| ReturnUndef2["Retorna undefined<br>(Sem erro)"]
  CheckAddress -->|Não| GetCity["Lê propriedade city"]
  GetCity --> ReturnCity["Retorna valor de city"]
`}
</Mermaid>

Ao interromper a avaliação e retornar `undefined` imediatamente quando um elo intermediário é nulo ou indefinido, o encadeamento opcional impede que exceções de tipo interrompam o fluxo do programa.

### Outros operadores comuns

Alguns operadores aparecem continuamente no código cotidiano, mesmo quando não se assemelham aos operadores de cálculo tradicionais. Eles acessam membros (`.`, `[]`), chamam funções (`()`), criam instâncias (`new`), removem propriedades (`delete`), espalham valores (`...`) ou sequenciam expressões (`,`):

| Operador | Exemplo | Ideia principal |
| -------- | ------- | --------------- |
| `.` | `user.name` | Acessa propriedade por nome fixo |
| `[]` | `user["name"]`, `items[0]` | Acessa propriedade ou índice por expressão |
| `()` | `sum(2, 3)` | Chama uma função |
| `new` | `new Date()` | Cria objeto a partir de construtor ou classe |
| `delete` | `delete user.age` | Remove uma propriedade de objeto |
| `...` | `[0, ...numbers]` | Espalha valores em arrays, objetos ou argumentos |
| `,` | `(x += 1, x * 2)` | Avalia expressões em sequência e retorna a última |

O exemplo abaixo reúne alguns desses operadores em usos comuns. `delete` remove uma
propriedade do objeto, mas não deve ser confundido com “apagar uma variável”.

```js title="Outros operadores comuns"
const user = {
  name: "Ana",
  age: 20,
};

const numbers = [1, 2, 3];
const today = new Date();

console.log(user.name); // "Ana"
console.log(user["age"]); // 20
console.log(numbers[0]); // 1
console.log(today instanceof Date); // true

delete user.age;

console.log("age" in user); // false
console.log([0, ...numbers]); // [0, 1, 2, 3]

let x = 1;
const result = (x += 1, x * 2);

console.log(result); // 4
```

<Aside type="note" title="Spread depende do contexto">
  O operador `...` aparece em arrays, objetos, chamadas de função e parâmetros. A
  ideia geral é espalhar ou coletar valores, mas os detalhes ficam mais claros nas
  tópicos de funções, arrays e objetos.
</Aside>

<Aside type="caution" title="Operador vírgula é raro">
  O operador vírgula `,` avalia expressões da esquerda para a direita e retorna o
  valor da última. Ele existe na linguagem, mas costuma reduzir a legibilidade fora
  de casos específicos, como algumas expressões em `for`. Em código comum, prefira
  separar as operações em linhas diferentes. Em declarações como
  `const name = "Ana", age = 20;`, a vírgula separa declaradores de variável; isso
  é diferente do operador vírgula.
</Aside>

## Taxonomia Completa dos Operadores

A especificação ECMAScript organiza os operadores em categorias hierárquicas. A tabela a seguir serve como mapa de referência, ordenando os grupos da maior precedência (topo) para a menor precedência (base):

| Categoria de operador | Operadores | Finalidade e contexto |
| :--- | :--- | :--- |
| Expressões primárias | `this`, `function`, `class`, `yield`, `await`, `[]`, `{}`, `/regex/`, `()` | Literais fundamentais e palavras reservadas geradoras de valor |
| Acesso e instanciação | `obj.prop`, `obj["prop"]`, `new`, `super`, `...` | Acesso a membros, instanciação e espalhamento |
| Incremento e decremento | `++`, `--` | Alteração de valores numéricos em uma unidade |
| Operadores unários | `delete`, `void`, `typeof`, `+`, `-`, `~`, `!` | Operações sobre um único operando |
| Aritméticos | `**`, `*`, `/`, `%`, `+`, `-` | Cálculos matemáticos |
| Relacionais | `<`, `<=`, `>`, `>=`, `in`, `instanceof` | Comparações de grandeza, presença em objeto ou protótipo |
| Igualdade | `===`, `!==`, `==`, `!=` | Verificação de identidade estrita ou equivalência solta |
| Deslocamento de bits | `<<`, `>>`, `>>>` | Deslocamento binário de inteiros à esquerda ou à direita |
| Lógicos bit a bit | `&`, `^`, `\|` | Operações booleanas binárias posição a posição |
| Lógicos e coalescência | `&&`, `\|\|`, `??` | Conjunção, disjunção e seleção de valores por ausência |
| Condicional | `condicao ? a : b` | Escolha ternária baseada em valor de verdade |
| Atribuição | `=`, `+=`, `-=`, `*=`, `??=`, `\|\|=`, `&&=` | Atribuições diretas, aritméticas compostas e lógicas |
| Vírgula | `,` | Avaliação sequencial com descarte e retorno da última expressão |

A leitura desta taxonomia auxilia na tomada de decisão ao estruturar expressões complexas. Quando dois operadores disputam a ordem de cálculo, aquele situado em uma linha superior na tabela será executado prioritariamente pelo interpretador.

## Boas práticas

A tabela final concentra escolhas que ajudam a reduzir surpresas e bugs comuns ao trabalhar com expressões e operadores:

| Prática | Motivo |
| ------- | ------ |
| Prefira `===` e `!==` | Comparam valor e tipo sem conversões implícitas imprevisíveis |
| Use `??` para valores padrão | Preserva números válidos como `0`, strings vazias `""` e booleanos `false` |
| Proteja acessos dinâmicos com `?.` | Evita erros fatais de tipo (`TypeError`) ao ler propriedades ou invocar métodos |
| Explicite precedência com parênteses `()` | Torna o cálculo inequívoco e elimina dependência da memorização da tabela de precedência |
| Evite operadores unários empilhados | Expressões como `+ + +x` prejudicam a clareza; prefira funções explícitas como `Number()` |
| Reserve `||` para alternativas estritamente booleanas | Substitui qualquer valor *falsy*, sendo ideal apenas quando `0` e `""` forem inválidos |

Este resumo ilustra a aplicação conjunta dessas práticas em um fluxo de código defensivo e expressivo:

```js title="Resumo prático"
const user = {
  name: "Ana",
  preferences: {
    itemsPerPage: 0,
  },
};

// 1. Encadeamento opcional (?.) + Coalescência nula (??) preservando o zero
const limit = user?.preferences?.itemsPerPage ?? 10;

// 2. Comparação estrita (===) sem coerção implícita
const isCustom = limit !== 10;

// 3. Parênteses explícitos para prioridade de cálculo
const totalPages = Math.ceil((100 + 5) / (limit === 0 ? 10 : limit));

console.log(limit); // 0
console.log(isCustom); // true
console.log(totalPages); // 11
```

## Exercício

O exercício a seguir fixa o uso dos principais grupos de operadores da página em um script de cálculo financeiro:

1. Declare `unitPrice`, `quantity`, `discount` e `shipping`;
2. Calcule `subtotal`, `discountValue` e `total`;
3. Use parênteses para deixar a ordem do cálculo explícita;
4. Monte uma mensagem usando concatenação com `+`;
5. Use `total >= 100 ? "free shipping" : "paid shipping"`;
6. Teste a diferença entre `shipping || 10` e `shipping ?? 10` quando `shipping` for `0`;
7. Crie um objeto `order` e acesse propriedades com `.` e `[]`;
8. Use `delete` para remover uma propriedade temporária;
9. Exiba os resultados com `console.log`.

A solução a seguir reúne esses operadores em um script executável:

<details>
  <summary>Possível resposta</summary>

  ```js title="order.js"
  const unitPrice = 49.9;
  const quantity = 3;
  const discount = 0.1;
  const shipping = 0;

  const subtotal = unitPrice * quantity;
  const discountValue = subtotal * discount;
  const total = (subtotal - discountValue) + shipping;
  const message = "Total: R$ " + total;
  const shippingStatus = total >= 100 ? "free shipping" : "paid shipping";
  const order = {
    product: "Mouse",
    total,
    temporaryNote: "remove before save",
  };

  delete order.temporaryNote;

  console.log(subtotal); // 149.7
  console.log(discountValue); // 14.970000000000002
  console.log(total); // 134.73
  console.log(message); // "Total: R$ 134.73"
  console.log(shippingStatus); // "free shipping"
  console.log(shipping || 10); // 10
  console.log(shipping ?? 10); // 0
  console.log(order.product); // "Mouse"
  console.log(order["total"]); // 134.73
  console.log("temporaryNote" in order); // false
  ```

  O exemplo também revela a precisão decimal de `number`. Em uma aplicação real, o
  arredondamento deveria seguir a regra de negócio.
</details>

## Desafio

Crie um arquivo `student.js` que classifique a situação de um estudante combinando notas, faltas e dados de endereço:

1. Use `grade1`, `grade2`, `absences` e `student`;
2. Calcule a média com parênteses;
3. Use `?.` para acessar `student.address.city`;
4. Use `??` para exibir `"Cidade não informada"` quando a cidade estiver ausente;
5. Use `&&`, `||` e ternário para decidir se o estudante foi aprovado;
6. Inclua ao menos uma comparação com `===`.

Uma solução possível combina encadeamento opcional, coalescência nula e operador ternário de forma concisa:

<details>
  <summary>Possível resposta</summary>

  ```js title="student.js"
  const grade1 = 8;
  const grade2 = 6;
  const absences = 3;
  const student = {
    name: "Ana",
    address: null,
  };

  const average = (grade1 + grade2) / 2;
  const city = student.address?.city ?? "Cidade não informada";
  const hasMinimumGrade = average >= 7;
  const hasAcceptableAbsences = absences <= 5;
  const status = hasMinimumGrade && hasAcceptableAbsences ? "approved" : "failed";

  console.log(student.name); // "Ana"
  console.log(average); // 7
  console.log(city); // "Cidade não informada"
  console.log(status); // "approved"
  console.log(status === "approved"); // true
  ```

  `?.` evita erro ao acessar `city` quando `address` é `null`. `??` define o texto
  padrão apenas quando o valor à esquerda é `null` ou `undefined`.
</details>

## Perguntas de revisão

### Expressões

**1. Qual é a diferença entre expressão e statement?**

<details>
  <summary>Possível resposta</summary>

  Expressão produz um valor. Statement organiza a execução, como uma declaração,
  bloco, `if`, `for` ou `return`.
</details>

**2. Por que `(fahrenheit - 32) / 1.8` precisa de parênteses?**

<details>
  <summary>Possível resposta</summary>

  Porque divisão tem precedência maior que subtração. Sem parênteses, `32 / 1.8`
  seria calculado antes de subtrair de `fahrenheit`.
</details>

**3. O que é associatividade?**

<details>
  <summary>Possível resposta</summary>

  É a direção em que operadores de mesma precedência são agrupados. `20 - 10 - 5`
  agrupa da esquerda para a direita, enquanto `2 ** 3 ** 2` agrupa da direita para a
  esquerda.
</details>

### Operadores

**4. Por que preferir `===` a `==`?**

<details>
  <summary>Possível resposta</summary>

  Porque `===` compara valor e tipo sem coerção. `==` pode converter valores antes
  de comparar, gerando resultados menos previsíveis.
</details>

**5. Qual é a diferença entre `||` e `??` para valores padrão?**

<details>
  <summary>Possível resposta</summary>

  `||` substitui qualquer valor falsy, como `0`, `""` e `false`. `??` substitui
  apenas `null` e `undefined`.
</details>

**6. O que `student.address?.city` evita?**

<details>
  <summary>Possível resposta</summary>

  Evita um erro em tempo de execução quando `address` é `null` ou `undefined`.
  Nesses casos, a expressão retorna `undefined`.
</details>

**7. Por que `2 + 3 + "4"` e `"2" + 3 + 4` têm resultados diferentes?**

<details>
  <summary>Possível resposta</summary>

  Por causa da associatividade e da coerção. No primeiro caso, `2 + 3` vira `5` e
  depois concatena com `"4"`. No segundo, a string aparece logo no começo e as
  operações seguintes viram concatenação.
</details>

**8. Quando operadores bitwise costumam aparecer?**

<details>
  <summary>Possível resposta</summary>

  Em flags, máscaras, manipulação de bits, baixo nível e alguns cálculos
  específicos. Eles são diferentes dos operadores lógicos `&&` e `||`.
</details>

**9. Qual é a diferença entre `&&` e `&`?**

<details>
  <summary>Possível resposta</summary>

  `&&` é lógico e faz curto-circuito: o lado direito pode nem ser executado. `&` é
  bitwise, avalia os dois lados e opera bit a bit.
</details>

**10. Por que JavaScript não tem divisão inteira com `/`?**

<details>
  <summary>Possível resposta</summary>

  Porque `/` sempre produz um valor `number`. Para obter um resultado inteiro, é
  necessário aplicar uma estratégia como `Math.trunc()`, `Math.floor()`,
  `Math.ceil()` ou `Math.round()`.
</details>

**11. Para que servem `.`, `[]`, `()` e `new`?**

<details>
  <summary>Possível resposta</summary>

  `.` acessa propriedade por nome fixo, `[]` acessa propriedade ou índice por
  expressão, `()` chama uma função e `new` cria um objeto a partir de construtor ou
  classe.
</details>

**12. O que o operador `delete` remove?**

<details>
  <summary>Possível resposta</summary>

  `delete` remove uma propriedade de objeto. Ele não deve ser entendido como uma
  forma de apagar uma variável declarada com `const`, `let` ou `var`.
</details>
