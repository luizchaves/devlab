## Categorias de Tipos de Dados

No ECMAScript, as variáveis não possuem tipo fixo; os **valores** armazenados é que possuem tipo. A linguagem divide seus tipos de dados em duas categorias fundamentais: **Primitivos** e **Objetos (Tipos de Referência)**.

O diagrama a seguir ilustra a taxonomia completa dos tipos no JavaScript, destacando a separação entre primitivos e objetos:

A tabela a seguir apresenta a consolidação completa de todos os tipos de dados da linguagem, suas características e exemplos de representação:

| Categoria | Tipo (`typeof`) | Descrição | Exemplos de Literais |
| :--- | :--- | :--- | :--- |
| **Primitivo** | `undefined` | Ausência de valor atribuído por padrão | `undefined` |
| **Primitivo** | `null` | Ausência intencional de referência a objeto (*retorna 'object' no typeof*) | `null` |
| **Primitivo** | `boolean` | Valor lógico verdadeiro ou falso | `true`, `false` |
| **Primitivo** | `number` | Número em ponto flutuante IEEE 754 (64-bit) | `42`, `-15`, `3.14`, `314e-2`, `0b1111`, `0o17`, `0xf`, `15_000`, `NaN` |
| **Primitivo** | `bigint` | Inteiro com precisão arbitrária superior a 2⁵³ - 1 | `42n`, `9007199254740991n` |
| **Primitivo** | `string` | Sequência imutável de caracteres de texto (UTF-16) | `"DevLab"`, `'JS'`, `` `Olá ${name}` `` |
| **Primitivo** | `symbol` | Identificador único e imutável de propriedade | `Symbol("id")` |
| **Objeto** | `object` | Coleção de propriedades, estruturas de dados e datas | `{ id: 1 }`, `[1, 2, 3]`, `new Date()`, `/dw/i` |
| **Objeto** | `function` | Objeto invocável (*callable*) contendo bloco de código | `function sum(a, b) { ... }`, `() => {}` |

```js title="Valores primitivos"
console.log(undefined); // undefined
console.log(null); // null
console.log(true); // true
console.log(false); // false
console.log("Programacao para Web 2"); // Programacao para Web 2
console.log(`Hello, ${1 + 1}`); // Hello, 2
console.log(42); // 42
console.log(15_000); // 15000 (separador numérico)
console.log(0b1111); // 15 (binário: 0b)
console.log(0o17); // 15 (octal: 0o)
console.log(0xf); // 15 (hexadecimal: 0x)
console.log(42n); // 42n
console.log(Symbol("id")); // Symbol(id)
```

Já os objetos conseguem agrupar vários valores, comportamentos ou estruturas em uma
única representação.

```js title="Valores objeto"
console.log([]); // []
console.log([1, 2, 3]); // [1, 2, 3]
console.log([1, , 3]); // [1, <1 empty item>, 3]
console.log([1010, "Fulano", true, ["DW", "PW2"]]);
console.log({ id: 1010, name: "Fulano", active: true });
console.log(new Date("2026-08-12T00:00:00.000Z"));
console.log(/dw/i);
```

<Aside type="note" title="Objetos agrupam informação">
  Arrays, objetos, datas, expressões regulares e funções permitem representar
  estruturas mais ricas do que um único número, texto ou booleano.
</Aside>

## Imutabilidade dos Primitivos

Valores primitivos são imutáveis. Métodos chamados em uma string ou number retornam **novos** valores sem alterar a instância original.

```js title="Imutabilidade de primitivos"
let title = "javascript";
title.toUpperCase(); // Retorna "JAVASCRIPT"
console.log(title); // Continua "javascript" (imutable)

title = title.toUpperCase(); // Reatribuição do identificador para o novo valor
console.log(title); // "JAVASCRIPT"
```

## O Operador `typeof`

O operador unário `typeof` inspeciona e retorna uma string representando o tipo do operando atual.

```js title="Exemplos com typeof"
console.log(typeof 42); // "number"
console.log(typeof "DevLab"); // "string"
console.log(typeof true); // "boolean"
console.log(typeof undefined); // "undefined"
console.log(typeof Symbol()); // "symbol"
console.log(typeof 10n); // "bigint"
console.log(typeof {}); // "object"
console.log(typeof [1, 2]); // "object" (Arrays são objetos!)
console.log(typeof function() {}); // "function"
```

<Aside type="caution" title="A Armadilha Histórica: `typeof null === 'object'`">
  Na especificação inicial do JavaScript (1995), os valores eram representados por rótulos de tipo em memória de 32 bits. O rótulo para objetos era `000`. Como o ponteiro para `null` era um ponteiro nulo (`0x00`), o `typeof null` retornou `"object"`. Esse comportamento foi mantido no ECMAScript para preservar compatibilidade com a web antiga.

  ```js
  console.log(typeof null); // "object" (Erro histórico do JS!)
  ```
</Aside>

O operador `typeof` ajuda a observar o tipo de um valor em tempo de execução:

```js title="Inspecionando tipos"
console.log(typeof undefined); // "undefined"
console.log(typeof null); // "object"
console.log(typeof true); // "boolean"
console.log(typeof "Hello"); // "string"
console.log(typeof 42); // "number"
console.log(typeof 42n); // "bigint"
console.log(typeof Symbol("id")); // "symbol"
console.log(typeof []); // "object"
console.log(Array.isArray([])); // true
console.log(typeof {}); // "object"
console.log(typeof function () {}); // "function"
```

<Aside type="tip" title="Array precisa de teste próprio">
  Arrays retornam `"object"` com `typeof`. Para verificar se um valor é array, use
  `Array.isArray(value)`.
</Aside>

Referência: [`typeof` | MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/typeof).

<Aside type="caution" title="Dica de IA: Valide a checagem de tipo que veio pronta">
  Verificações de tipo geradas por IA costumam parar em `typeof value === "object"`, que é verdadeiro para `null`, para arrays e para datas. Executar a sugestão com os valores certos expõe em segundos a diferença entre uma checagem correta e uma que apenas parece correta.

</Aside>

## Tipagem Dinâmica e Tipagem Fraca (Weak Typing)

O sistema de tipos do JavaScript possui duas características fundamentais que moldam a escrita do código: **Tipagem Dinâmica** e **Tipagem Fraca** (*Loose/Weak Typing*).

**1. Tipagem Dinâmica (Dynamic Typing)**

Em JavaScript, **as variáveis não possuem tipos fixos associados**; os tipos pertencem aos **valores** atribuídos a elas. Por isso, a mesma variável pode armazenar um número em um momento e uma string no momento seguinte.

```js title="Reatribuição com tipos diferentes"
let data = 42;            // number
console.log(typeof data); // "number"

data = "DevLab";          // reatribuído para string
console.log(typeof data); // "string"
```

**2. Tipagem Fraca (Weak Typing)**

JavaScript possui **tipagem fraca**, o que significa que o motor da linguagem realiza **conversões automáticas de tipo (coerção implícita)** para tentar resolver operações entre tipos diferentes sem lançar erros de execução.

Em linguagens de **tipagem forte** (como Python ou Rust), misturar tipos incompatíveis gera um erro imediato (`TypeError`). Em JavaScript, a linguagem tenta converter silenciosamente os operandos:

| Operação | Resultado | Comportamento da Tipagem Fraca |
| :--- | :--- | :--- |
| `"5" + 2` | `"52"` | O operador `+` com string converte `2` para `"2"` e concatena. |
| `"5" - 2` | `3` | O operador `-` força conversão da string `"5"` para o número `5`. |
| `"5" * "2"` | `10` | O operador `*` converte ambas as strings para números. |
| `true + 1` | `2` | O booleano `true` é convertido para `1`. |
| `false * 10` | `0` | O booleano `false` é convertido para `0`. |

A tabela a seguir compara o comportamento da Tipagem Fraca em JavaScript com o comportamento em linguagens de Tipagem Forte:

| Característica | Tipagem Fraca (JavaScript) | Tipagem Forte (Python / Rust) |
| :--- | :--- | :--- |
| **Operação `"5" + 2`** | Retorna `"52"` (Converte `2` para string `"2"`) | Lança `TypeError` (Não concatena str com int automaticamente) |
| **Operação `"5" - 2`** | Retorna `3` (Converte `"5"` para número `5`) | Lança `TypeError` |
| **Execução** | Tenta converter silenciosamente em runtime | Lança exceção ou exige conversão explícita |

```js title="Exemplos de comportamento da tipagem fraca"
console.log("10" + 5);    // "105" (String)
console.log("10" - 5);    // 5     (Number)
console.log(true + true); // 2     (Number: 1 + 1)
console.log("10" == 10);  // true  (Coerção implícita na igualdade ampla)
```

<Aside type="caution" title="Perigos da Tipagem Fraca">
  A tipagem fraca pode causar bugs silenciosos onde um cálculo numérico produz concatenação de texto (ex: `"100" + 20` gerando `"10020"`). Para evitar esses problemas:
  - Utilize **coerção explícita** (`Number(val)`, `String(val)`).
  - Utilize sempre **igualdade estrita (`===`)** em vez de igualdade ampla (`==`).
</Aside>


## Coerção de Tipos (Implícita vs Explícita)

Coerção é o processo de conversão de um valor de um tipo de dado para outro. Essa conversão pode ocorrer de maneira explícita, quando o desenvolvedor solicita a transformação intencionalmente no código, ou de maneira implícita, quando o interpretador realiza a conversão automática para conseguir executar uma determinada operação.

### Conversão Explícita e Coerção Básica

A conversão explícita ocorre quando utilizamos funções conversoras nativas como `Number()`, `String()` e `Boolean()` sem o operador `new`. Esse padrão garante previsibilidade, deixando evidente a intenção de transformar o tipo de dado.

O código a seguir demonstra o uso dessas funções conversoras com diferentes tipos primitivos:

```js title="Exemplos de conversão explícita"
const input = "42";
const count = Number(input); // 42 (number)
const text = String(100);    // "100" (string)
const isValid = Boolean(1);  // true (boolean)

console.log(parseInt("42px")); // 42 (interpreta inteiros no início)
console.log(Number("42px"));   // NaN (conversão estrita falha)
console.log(Number(""));       // 0
```

Já a coerção implícita ocorre automaticamente quando o motor JavaScript encontra operadores aplicados a operandos de tipos divergentes:

```js title="Exemplos de coerção implícita básica"
console.log("5" + 2);   // "52" (operador + com string concatena texto)
console.log("5" - 2);   // 3 (operador - força conversão para number)
console.log("5" * "2"); // 10 (operador * força conversão numérica)
console.log(true + 1);  // 2 (true é convertido para 1)
console.log(false + 1); // 1 (false é convertido para 0)
```

Nem todas as tentativas de combinar tipos incompatíveis resultam em coerção automática. O JavaScript lança erros em operações com tipos que possuem restrições estritas de integridade, como `BigInt` e `Symbol`:

```js title="Coerções implícitas que lançam erro"
// TypeError: Cannot mix BigInt and other types.
// console.log(1n + 1);

// TypeError: Cannot convert a Symbol value to a string.
// console.log("id: " + Symbol("id"));

// RangeError: The number 1.5 cannot be converted to a BigInt.
// console.log(BigInt(1.5));
```

<Aside type="tip" title="Use Sempre Igualdade Estrita (`===`)">
  O operador de igualdade ampla (`==`) tenta realizar coerção implícita de tipos antes de comparar, gerando resultados contraintuitivos como `"0" == 0` (retorna `true`) e `"" == false` (retorna `true`). Sempre utilize a igualdade estrita (`===`) e a desigualdade estrita (`!==`), que comparam o tipo e o valor sem qualquer coerção.
</Aside>

O exemplo abaixo contrasta a comparação ampla, sujeita a coerção prévia, com a comparação estrita:

```js title="Comparação ampla (==) vs estrita (===)"
const big = 9007199254740991n;

// 1. Igualdade Ampla (==): Realiza coerção implícita antes de comparar
console.log(5 == "5");                 // true (converte "5" para 5)
console.log(big == 9007199254740991);  // true (compara valores ignorando o tipo)

// 2. Igualdade Estrita (===): Compara valor e tipo sem coerção
console.log(5 === "5");                // false (number vs string)
console.log(big === 9007199254740991); // false (bigint vs number)
```

### Comportamento de valueOf() e toString() nos Tipos de Dados

Para entender como a linguagem resolve conversões complexas, é necessário conhecer os dois métodos fundamentais de conversão definidos no protótipo base dos tipos de dados: `valueOf()` e `toString()`. O método `valueOf()` tem como objetivo fornecer a representação em valor primitivo (comumente numérico) do dado, enquanto `toString()` tem como objetivo gerar sua representação textual.

A tabela a seguir consolida o retorno padrão desses dois métodos nos principais tipos da linguagem:

| Tipo | Retorno de `valueOf()` | Retorno de `toString()` | Observações de Conversão |
| :--- | :--- | :--- | :--- |
| **`Number`** | Primitivo numérico (`42`) | String decimal ou na base informada (`"42"`, `"ff"`) | Aceita parâmetro opcional `radix` de 2 a 36. |
| **`Boolean`** | Primitivo booleano (`true` / `false`) | `"true"` ou `"false"` | Permite inspecionar o valor real de wrappers `new Boolean()`. |
| **`String`** | Primitiva textual (`"texto"`) | Primitiva textual (`"texto"`) | Comportamento idêntico em strings primitivas e wrappers. |
| **`Date`** | Timestamp numérico em milissegundos (`1767225600000`) | String legível no fuso local (`"Thu Jan 01 2026..."`) | `valueOf()` é idêntico a `date.getTime()`. |
| **`Array`** | O próprio array (`this`, objeto) | Elementos convertidos e unidos por vírgula (`"1,2,3"`) | Array vazio resulta em string vazia `""`. |
| **`Object`** | O próprio objeto (`this`, objeto) | Tag de tipo interna (`"[object Object]"`) | Pode ser sobrescrito com métodos próprios ou `Symbol.toStringTag`. |
| **`Function`** | A própria função (`this`) | Código-fonte da função em texto | Permite inspecionar a assinatura e corpo da função. |
| **`Symbol`** | O símbolo primitivo | String representativa (`"Symbol(id)"`) | Proíbe coerção implícita para string (exige chamada explícita). |
| **`null` / `undefined`** | *Lança TypeError* | *Lança TypeError* | Não possuem protótipo. Conversão exige `String(val)`. |

O exemplo a seguir demonstra o retorno direto desses dois métodos aplicados aos diferentes tipos nativos do JavaScript:

```js title="Métodos valueOf() e toString() nos tipos nativos"
// 1. Números e Booleanos
console.log((42).valueOf());               // 42
console.log((42).toString(16));            // "2a" (hexadecimal)
console.log(new Boolean(false).valueOf()); // false (desempacota o primitivo)
console.log(true.toString());              // "true"

// 2. Datas (Date)
const date = new Date("2026-01-01T00:00:00.000Z");
console.log(date.valueOf());               // 1767225600000 (timestamp em milissegundos)
console.log(date.valueOf() === date.getTime()); // true

// 3. Arrays e Objetos
const numbers = [10, 20, 30];
console.log(numbers.valueOf() === numbers); // true (retorna o próprio array)
console.log(numbers.toString());            // "10,20,30"
console.log([].toString());                 // "" (array vazio vira texto vazio)

const user = { name: "DevLab" };
console.log(user.valueOf() === user);       // true (retorna o próprio objeto)
console.log(user.toString());               // "[object Object]"

// 4. Funções
function sum(a, b) { return a + b; }
console.log(sum.toString()); // "function sum(a, b) { return a + b; }"

// 5. null e undefined
// null.toString(); // TypeError: Cannot read properties of null
console.log(String(null));      // "null" (conversão segura via função construtora)
console.log(String(undefined)); // "undefined"
```

### Mecanismo Interno: A Operação ToPrimitive e as Chamadas em Coerção

Quando uma operação em JavaScript envolve um objeto (como uma data, um array ou um objeto literal) e precisa de um valor primitivo para continuar, o motor executa internamente a operação abstrata `ToPrimitive(input, preferredType)`.

O algoritmo de conversão avalia o contexto da operação por meio de três dicas (*hints*):

1. **Contexto Numérico (`hint: "number"`)**: Acionado por operadores aritméticos matemáticos como subtração (`-`), multiplicação (`*`), divisão (`/`), unário `+` e comparações relacionais (`<`, `>`). O motor tenta primeiro invocar `obj.valueOf()`. Se o retorno for um valor primitivo, ele é utilizado no cálculo. Se retornar um objeto, o motor tenta invocar `obj.toString()` como plano de emergência. Se nenhum retornar primitivo, lança um `TypeError`.
2. **Contexto Textual (`hint: "string"`)**: Acionado por interpolação de texto com *template literals* (`` `${obj}` ``) e conversões com `String(obj)`. O motor tenta primeiro invocar `obj.toString()`. Se o retorno for um primitivo, ele é utilizado. Se retornar um objeto, tenta `obj.valueOf()`.
3. **Contexto Padrão (`hint: "default"`)**: Acionado pelo operador de adição binária (`obj + valor`) e pela igualdade ampla (`obj == valor`). Na maioria dos objetos, esse contexto comporta-se exatamente como o numérico, tentando `valueOf()` e depois `toString()`. A grande exceção da linguagem é o objeto `Date`, que trata o contexto padrão como textual, invocando `toString()` antes de `valueOf()`.

O exemplo a seguir ilustra a chamada implícita desses métodos na prática, demonstrando o cálculo com datas e a criação de objetos customizados que registram a execução de cada método:

```js title="Ordem de invocação de valueOf() e toString() em coerções"
// 1. Subtração de Datas utiliza valueOf() (hint "number")
const date1 = new Date("2026-01-01T00:00:00Z");
const date2 = new Date("2026-01-02T00:00:00Z");

// O operador '-' invoca date.valueOf() em ambos os operandos para obter milissegundos:
const diffMs = date2 - date1;
console.log(diffMs); // 86400000 (exatamente 24 horas em milissegundos)
console.log(diffMs === (date2.valueOf() - date1.valueOf())); // true

// 2. Objeto personalizado demonstrando a prioridade dos métodos
const item = {
  title: "Teclado",
  price: 250,

  valueOf() {
    console.log("[chamou valueOf]");
    return this.price;
  },

  toString() {
    console.log("[chamou toString]");
    return this.title;
  },
};

// Operações aritméticas acionam valueOf():
console.log(item * 2); 
// Log: [chamou valueOf] -> 500

console.log(item + 50); 
// Log: [chamou valueOf] -> 300

// Interpolação textual aciona toString():
console.log(`Produto: ${item}`); 
// Log: [chamou toString] -> "Produto: Teclado"

// 3. Por que somar objetos e arrays padrão resulta em texto?
// Como [1, 2].valueOf() retorna o próprio array (não primitivo),
// o motor recorre ao método toString() como segunda tentativa:
console.log([1, 2] + [3, 4]); // "1,23,4" (coerção de arrays via toString)
console.log({} + 5);          // "[object Object]5" (objeto puro recorre a toString)
```

O controle sobre a coerção para primitivo viabiliza padrões elegantes na modelagem de classes, como os *Value Objects*:

<Aside type="tip" title="Padrão Prático: Value Objects e Comparações Relacionais">
  Em arquiteturas de software, objetos de domínio como `Money` ou unidades de medida podem implementar `valueOf()` para expor seu valor primitivo subjacente (como centavos ou bytes). Isso permite somar e comparar instâncias diretamente com operadores nativos:

  ```js
  class Money {
    constructor(cents, currency = "BRL") {
      this.cents = cents;
      this.currency = currency;
    }

    valueOf() {
      return this.cents;
    }

    toString() {
      return `${this.currency} ${(this.cents / 100).toFixed(2)}`;
    }
  }

  const priceA = new Money(2500); // R$ 25,00
  const priceB = new Money(1500); // R$ 15,00

  console.log(priceA + priceB); // 4000 (soma direta aciona valueOf)
  console.log(priceA > priceB); // true (operadores relacionais acionam valueOf)
  console.log(`Total: ${new Money(priceA + priceB)}`); // "Total: BRL 40.00"
  ```

  No ECMAScript 2015 (ES6), o método `[Symbol.toPrimitive](hint)` foi adicionado para formalizar esse controle, recebendo diretamente a dica do contexto (`"number"`, `"string"` ou `"default"`). Caso `[Symbol.toPrimitive]` não seja definido, o motor recorre à dupla `valueOf()` e `toString()`.
</Aside>


<Aside type="tip" title="Dica de IA: Exija conversão explícita no lugar da coerção">
  Código gerado costuma se apoiar em coerção implícita porque ela é mais curta: `"5" * 2`, `if (valor)` e `valor + ""` resolvem em menos caracteres. O preço aparece quando a entrada muda de tipo e o resultado continua sem lançar erro.

  **Prompt:** *"Reescreva este trecho sem depender de coerção implícita: use `Number()`, `String()` e `Boolean()` de forma explícita e comparações com `===`. Aponte cada ponto em que o comportamento muda com entradas como `""`, `"0"`, `null` e `[]`."*
</Aside>

## `undefined` vs `null`

Ambos os valores representam ausência de dados, mas com intenções semânticas distintas:

- **`undefined`**: Significa que a variável foi declarada, mas ainda **não recebeu nenhum valor**, ou que uma função não retornou explicitamente nada. É o padrão do motor JavaScript.
- **`null`**: Significa a **ausência intencional** de um objeto ou valor. É atribuído programaticamente pelo desenvolvedor para indicar "sem valor".

```js title="Comparação entre undefined e null"
let unassigned;
console.log(unassigned); // undefined

const emptyUser = null; // Definido intencionalmente como vazio
console.log(emptyUser); // null

console.log(undefined == null); // true (Igualdade ampla)
console.log(undefined === null); // false (Tipos diferentes!)
```

Com `typeof` apresentado, fica mais fácil observar dois valores especiais de
ausência. `undefined` costuma indicar ausência de inicialização. `null` costuma ser
usado para representar ausência intencional de valor:

```js title="Ausência de valor"
let notInitialized;
const empty = null;

console.log(notInitialized); // undefined
console.log(typeof notInitialized); // "undefined"
console.log(empty); // null
console.log(typeof empty); // "object"
```

<Aside type="note" title="typeof null">
  `typeof null` retorna `"object"` por uma decisão antiga da linguagem. Apesar
  desse retorno, `null` é tratado como valor primitivo.
</Aside>

<Aside type="tip" title="undefined, null e memória">
  No modelo da linguagem, `undefined` e `null` são valores primitivos. Uma variável
  declarada com `let notInitialized;` existe como nome no escopo e seu valor inicial
  é `undefined`. Já `null` é um valor atribuído intencionalmente, muitas vezes para
  indicar que ali não há objeto ou resultado. Detalhes como quantidade de memória,
  representação interna e otimizações dependem da engine JavaScript, como V8,
  SpiderMonkey ou JavaScriptCore; para a programação do dia a dia, pense neles como
  valores especiais de ausência.
</Aside>


## Booleanos, Falsy e Truthy

Em contextos lógicos (como condicionais `if`), todos os valores em JavaScript são avaliados como **Truthy** (verdadeiro) ou **Falsy** (falso).

Existem exatamente **8 valores Falsy** no ECMAScript:
1. `false`
2. `0` (e `-0`)
3. `0n` (BigInt zero)
4. `""` (string vazia)
5. `null`
6. `undefined`
7. `NaN` (Not-a-Number)
8. `document.all` (em navegadores)

**Todos os demais valores são Truthy**, incluindo strings não-vazias (`"0"`, `"false"`), objetos vazios (`{}`), arrays vazios (`[]`) e qualquer número diferente de zero.

```js title="Testando Truthy e Falsy"
console.log(Boolean("")); // false (Falsy)
console.log(Boolean("0")); // true (Truthy! String não-vazia)
console.log(Boolean([])); // true (Truthy! Array é objeto)
console.log(Boolean({})); // true (Truthy! Objeto)
```

Quando JavaScript precisa avaliar um valor como condição, ele converte esse valor
para booleano. Alguns valores viram `false`; quase todo o restante vira `true`:

| Valor | Conversão |
| ----- | --------- |
| `false` | `false` |
| `0`, `-0`, `0n` | `false` |
| `""` | `false` |
| `null` | `false` |
| `undefined` | `false` |
| `NaN` | `false` |
| `[]`, `{}`, `"0"` | `true` |

A função `Boolean()` permite observar explicitamente como cada valor seria tratado
em uma condição:

```js title="Conversão booleana"
console.log(Boolean(false)); // false
console.log(Boolean(0)); // false
console.log(Boolean(0n)); // false
console.log(Boolean("")); // false
console.log(Boolean(null)); // false
console.log(Boolean(undefined)); // false
console.log(Boolean(NaN)); // false

console.log(Boolean([])); // true
console.log(Boolean({})); // true
```

<Aside type="caution" title="Array vazio é truthy">
  Um array vazio `[]` e um objeto vazio `{}` são convertidos para `true`. Isso é
  diferente de linguagens em que coleções vazias podem ser tratadas como falsas.
</Aside>

## Perguntas de revisão

**1. O que significa dizer que o tipo está no valor, não na variável?**

<details>
  <summary>Possível resposta</summary>

  Significa que variáveis em JS são dinamicamente tipadas e não possuem um tipo fixo. O tipo é uma propriedade do valor atribuído naquele momento.
</details>

**2. Por que `typeof null` retorna `"object"`?**

<details>
  <summary>Possível resposta</summary>

  Devido a uma limitação técnica histórica da primeira implementação do JS em 1995 na representação binária de ponteiros nulos.
</details>

**3. Quais valores são avaliados como Falsy em JavaScript?**

<details>
  <summary>Possível resposta</summary>

  `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined` e `NaN`. Valores como `[]`, `{}` e `"0"` são truthy.
</details>

**4. O que ocorre no comando `"10" + 5` vs `"10" - 5`?**

<details>
  <summary>Possível resposta</summary>

  No operador `+`, a presença de uma string força a concatenação (`"105"`). No operador `-`, ocorre coerção implícita da string para número, resultando em `5`.
</details>

**5. Por que `NaN === NaN` retorna `false` e qual a forma correta de testá-lo?**

<details>
  <summary>Possível resposta</summary>

  `NaN` representa um resultado numérico indefinido ou não-real e é o único valor no JS que não é igual a si mesmo. Para testá-lo de forma confiável, use `Number.isNaN(valor)` ou `Object.is(valor, NaN)`.
</details>
