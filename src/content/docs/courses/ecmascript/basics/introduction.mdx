Antes de manipular páginas no navegador ou construir servidores HTTP com Node.js, é fundamental entender o que é JavaScript e por que o termo **ECMAScript** aparece com tanta frequência. JavaScript não é apenas a linguagem da Web: ela é executada em navegadores, servidores, ferramentas de build e ambientes de automação.

## Objetivo

Compreender o ecossistema e a arquitetura da linguagem:

- Entender a origem do JavaScript e a padronização pelo **ECMAScript** (ECMA-262 / TC39).
- Diferenciar o núcleo teórico da linguagem das **Web APIs** (Navegador) e **Node.js APIs** (Servidor).
- Identificar os principais motores de execução (**V8**, **JavaScriptCore**, **SpiderMonkey**).
- Conhecer a diferença entre runtimes de servidor (**Node.js**, **Deno**, **Bun**).

## Por Que JavaScript Importa?

JavaScript se tornou a linguagem universal da Web por ser suportada nativamente por todos os navegadores modernos. Quando uma aplicação precisa reagir a interações do usuário, atualizar elementos da tela dinamicamente ou consumir dados via HTTP, o JavaScript é a ferramenta principal.

Com a criação do Node.js em 2009, a linguagem expandiu seu alcance para o backend, permitindo escrever servidores escaláveis, ferramentas de linha de comando (CLI) e scripts de automação utilizando o mesmo ecossistema.

<Aside type="note" title="Linguagem vs Ambiente">
  O **ECMAScript** define a sintaxe, tipos de dados e recursos fundamentais da linguagem. As **APIs do Ambiente** (como `document` no navegador ou `fs` no Node.js) são fornecidas pelo runtime onde o script é executado.
</Aside>

## Origem e a História dos Nomes

1. **Mocha** (Maio / 1995): Protótipo inicial desenvolvido por **Brendan Eich** na Netscape em apenas 10 dias.
2. **LiveScript** (Setembro / 1995): Primeiro nome comercial oficial no lançamento beta do Netscape Navigator 2.0.
3. **JavaScript** (Dezembro / 1995): Nome adotado em parceria de marketing com a Sun Microsystems para aproveitar o sucesso do Java.
4. **ECMAScript** (1996 - Presente): Nome oficial da especificação técnica internacional (**ECMA-262**) gerenciada pelo comitê **TC39**.

<Aside type="caution" title="Java vs JavaScript">
  Java e JavaScript são linguagens completamente distintas em sintaxe, execução e paradigma. Como diz o ditado popular no desenvolvimento: *"Java está para JavaScript assim como Carro está para Carpinteiro"*.
</Aside>

## Exemplo Prático Completo

O código abaixo demonstra um script compatível com o núcleo ECMAScript que executa tanto no navegador quanto no Node.js:

```javascript
// Função pura em ECMAScript (executa em qualquer ambiente JS)
function formatarSaudacao(nome, ambiente = "Geral") {
  const data = new Date().toLocaleDateString("pt-BR");
  return `[${data}] Olá, ${nome}! Executando no ambiente: ${ambiente}`;
}

const mensagem = formatarSaudacao("DevLab", "ECMAScript Core");
console.log(mensagem);
```

## Resumo e Boas Práticas

- **ECMAScript** é a norma padrão; **JavaScript** é a implementação comercial.
- Não confunda o núcleo da linguagem com as APIs específicas do navegador (`document`) ou do Node.js (`process`).
- Utilize runtimes modernos (Node.js 20+, Deno, Bun) para testar seus scripts de forma rápida no terminal.
