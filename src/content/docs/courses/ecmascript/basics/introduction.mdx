Antes de manipular páginas, consumir APIs ou construir servidores com Node.js, vale
entender o que é JavaScript e por que o termo **ECMAScript** aparece quando falamos
da linguagem. JavaScript não é apenas "a linguagem do navegador": hoje ela roda em
navegadores, servidores, ferramentas de build, aplicações desktop, automações e
ambientes de teste.

Nesta disciplina, JavaScript será usado nos dois lados da aplicação Web: no
navegador, para adicionar comportamento à interface, e no servidor, para construir
APIs HTTP com Node.js e Express.

## Objetivo

Entender a origem do JavaScript, diferenciar JavaScript de ECMAScript, reconhecer o
papel das Web APIs, identificar onde o código pode ser executado e preparar o
ambiente básico para escrever e testar scripts durante a disciplina.

## Por Que JavaScript Importa?

JavaScript se tornou uma das linguagens centrais da Web porque é suportada pelos
navegadores. Quando uma página precisa reagir a cliques, validar um formulário,
alterar elementos, buscar dados de uma API ou atualizar a tela sem recarregar tudo,
normalmente existe JavaScript envolvido.

Com Node.js, a linguagem também passou a ser usada fora do navegador. Isso permitiu
usar JavaScript para escrever servidores, ferramentas de linha de comando, scripts
de automação, testes, processos de build e aplicações completas.

<Aside type="note" title="JavaScript não substitui HTML nem CSS">
  HTML estrutura o conteúdo, CSS define a apresentação visual e JavaScript adiciona
  comportamento. Uma página Web bem construída combina essas três camadas, em vez
  de tentar resolver tudo com uma única tecnologia.
</Aside>

## Origem e a História dos Nomes

JavaScript foi criado em maio de 1995 por **Brendan Eich** enquanto trabalhava na **Netscape**. A linguagem foi desenvolvida em apenas 10 dias com o objetivo de adicionar comportamento dinâmico e interatividade às páginas do navegador Netscape Navigator.

### A Evolução dos Nomes da Linguagem

A linguagem passou por diversas mudanças de nome em um curto período antes de se consolidar mundialmente:

1. **Mocha** (Maio de 1995): Nome de código original do protótipo desenvolvido por Brendan Eich na Netscape.
2. **LiveScript** (Setembro de 1995): Primeiro nome comercial oficial utilizado no lançamento beta do Netscape Navigator 2.0.
3. **JavaScript** (Dezembro de 1995): Renomeada para **JavaScript** em uma estratégia de marketing conjunta entre a Netscape e a Sun Microsystems (cuja marca registrada "JavaScript" passou posteriormente para a **Oracle Corporation** após a aquisição da Sun em 2010). O objetivo era aproveitar o grande interesse do mercado pela marca Java na época.
4. **ECMAScript** (1996 - Presente): Com o surgimento de implementações concorrentes (como o JScript da Microsoft), a Netscape submeteu a linguagem para a **Ecma International** para padronização. Como o nome "Java" era uma marca registrada da Sun (e atualmente da Oracle), a especificação oficial e neutra foi batizada como **ECMAScript** (padrão **ECMA-262**).

| Nome | Ano | Contexto e Motivação |
| :--- | :--- | :--- |
| **Mocha** | Maio / 1995 | Nome interno do projeto durante o desenvolvimento do protótipo por Brendan Eich. |
| **LiveScript** | Setembro / 1995 | Nome da primeira versão lançada comercialmente no Netscape Navigator 2.0. |
| **JavaScript** | Dezembro / 1995 | Parceria de marketing com a Sun Microsystems (marca hoje pertencente à Oracle). |
| **ECMAScript** | 1996 - Presente | Especificação técnica oficial e padronizada pela Ecma International (ECMA-262). |

<Aside type="note" title="JavaScript vs Java">
  Apesar da semelhança no nome, **Java e JavaScript são linguagens completamente diferentes** em paradigma, regras de sintaxe, tipos e motores de execução. Uma analogia técnica popular diz que *"Java está para JavaScript assim como Carro está para Carpinteiro"*.
</Aside>

## JavaScript, ECMAScript e Web APIs

No uso diário, é comum dizer apenas "JavaScript". Tecnicamente, porém, uma página no
navegador mistura a linguagem ECMAScript com APIs fornecidas pelo ambiente.

| Termo | Papel | Exemplos |
| ----- | ----- | -------- |
| ECMAScript | Define a linguagem base | variáveis, funções, objetos, arrays, classes, módulos, promises |
| JavaScript | Nome comum da linguagem usada pelos desenvolvedores | código escrito em arquivos `.js` ou dentro de `<script>` |
| Web APIs | Recursos oferecidos pelo navegador | DOM, eventos, `fetch`, `localStorage`, timers, console |
| Node.js APIs | Recursos oferecidos pelo Node.js | sistema de arquivos, processos, servidor HTTP, módulos nativos |
| npm | Ecossistema de pacotes | Express, Vite, Prisma, Chart.js, bibliotecas de teste |

Por isso, `Array`, `Object`, `Promise` e `Map` pertencem à linguagem. Já
`document.querySelector`, `addEventListener`, `fetch` no navegador e `localStorage`
são recursos do ambiente Web.

<Aside type="note" title="O ambiente importa">
  Um código pode ser JavaScript válido e ainda assim não funcionar em todos os
  lugares. `document` existe no navegador, mas não existe em um script Node comum.
  Por outro lado, módulos como `node:fs` existem no Node.js, mas não no navegador.
</Aside>

## O Que a Linguagem Oferece?

ECMAScript define a base da linguagem que será usada nas próximas aulas. A tabela
abaixo mostra partes que aparecerão com frequência durante a disciplina.

| Área | Exemplos | Por que importa |
| ---- | -------- | --------------- |
| Valores e tipos | `number`, `string`, `boolean`, `undefined`, `null`, objetos | Representar dados da aplicação |
| Variáveis | `let`, `const` | Guardar valores e controlar escopo |
| Expressões e operadores | `+`, `===`, `&&`, `??`, `?.` | Calcular, comparar e compor valores |
| Controle de fluxo | `if`, `switch`, `for`, `while` | Decidir caminhos e repetir tarefas |
| Funções | declarações, arrow functions, callbacks | Organizar comportamento reutilizável |
| Objetos e arrays | literais, propriedades, métodos, iteração | Modelar entidades, listas e respostas de APIs |
| Módulos | `import`, `export` | Separar código em arquivos reutilizáveis |
| Assincronismo | `Promise`, `async`, `await` | Trabalhar com operações que demoram, como chamadas HTTP |

<Aside type="tip" title="A linguagem é pequena, o ecossistema é grande">
  Aprender JavaScript não significa memorizar todas as bibliotecas. Primeiro vem a
  linguagem: valores, funções, objetos, arrays, módulos e assincronismo. Depois fica
  mais fácil entender bibliotecas como Express, Vite, Prisma e Chart.js.
</Aside>

## Características Importantes

JavaScript é uma linguagem de alto nível, dinâmica e multiparadigma. Essas palavras
resumem decisões que afetam a forma de escrever e depurar código.

| Característica | Ideia principal | Exemplo prático |
| -------------- | --------------- | --------------- |
| Alto nível | Esconde muitos detalhes de memória e máquina | criar objetos e arrays sem alocar memória manualmente |
| Tipagem dinâmica | O tipo pertence ao valor, não à variável | uma variável pode receber número e depois string |
| Tipagem fraca | Algumas conversões podem ocorrer automaticamente | `'5' * 2` resulta em `10` |
| Multiparadigma | Aceita estilos diferentes de programação | funções, objetos, callbacks, classes e composição |
| Protótipos | Objetos podem herdar de outros objetos | métodos de arrays vêm de `Array.prototype` |
| ASI | O motor pode inserir ponto e vírgula em alguns casos | código sem `;` pode funcionar, mas exige cuidado |

```js title="Tipagem dinâmica"
let value = 10;
console.log(typeof value); // "number"

value = "10";
console.log(typeof value); // "string"
```

```js title="Conversão automática"
console.log("5" * 2); // 10
console.log("5" + 2); // "52"
```

Esses comportamentos não são "erros" da linguagem, mas exigem disciplina. Ao longo
da disciplina, vamos preferir comparações estritas (`===`), nomes claros e código
legível para reduzir surpresas.

## Comentários em JavaScript

Comentários são anotações inseridas no código que o motor de execução ignora totalmente. Eles servem para documentar intenções, explicar regras de negócio ou desativar temporariamente instruções durante o desenvolvimento.

JavaScript suporta três formatos de comentários:

### 1. Comentário de Linha Única (`//`)

Inicia com duas barras (`//`) e estende-se até o fim da linha. É ideal para notas curtas e diretas.

```js title="Comentário de linha única"
// Define a taxa de desconto para clientes VIP
const VIP_DISCOUNT = 0.15;

const total = 100; // Valor base da compra
```

### 2. Comentário de Múltiplas Linhas (`/* ... */`)

Inicia com `/*` e encerra em `*/`. É utilizado para explicações mais detalhadas ou para desativar blocos inteiros de código.

```js title="Comentário de bloco"
/*
  Cálculo de tributação para produtos importados.
  Considera a alíquota estadual (ICMS) e federal.
  Atualizado conforme a legislação vigente.
*/
function calculateTax(amount) {
  return amount * 0.20;
}
```

### 3. Comentários de Documentação JSDoc (`/** ... */`)

Iniciam com `/**` e encerram com `*/`. O **JSDoc** é o padrão oficial de documentação da comunidade JavaScript. Ele permite descrever parâmetros (`@param`), tipos e valores de retorno (`@returns`), fornecendo autocompletar e auxílio visual inteligente no editor de código (VS Code).

```js title="Documentação com JSDoc"
/**
 * Calcula o preço final aplicando desconto.
 *
 * @param {number} price - Preço original do produto.
 * @param {number} discount - Taxa de desconto de 0 a 1 (ex: 0.10 para 10%).
 * @returns {number} Valor final com o desconto aplicado.
 */
function applyDiscount(price, discount) {
  return price * (1 - discount);
}
```

<Aside type="tip" title="Boas Práticas de Comentários">
  - **Explique o PORQUÊ, não o O QUÊ**: Evite comentar o que o código já deixa óbvio (`let x = 10; // declara x como 10`). Explique o motivo ou o contexto por trás da decisão.
  - **Priorize Código Autoexplicativo**: Nomes claros para variáveis e funções reduzem drasticamente a necessidade de comentários informativos.
  - **Evite Código Morto**: Remova códigos velhos comentados antes de enviar o projeto para produção ou controle de versão (Git).
</Aside>

## Evolução da Linguagem

JavaScript continua evoluindo. O comitê TC39 organiza propostas de novas funcionalidades em estágios. Uma ideia começa imatura e precisa amadurecer até entrar oficialmente na especificação.

<Aside type="tip" title="Guia Completo de Versões do ECMAScript">
  Para uma visão aprofundada da evolução do JavaScript ano a ano, com exemplos práticos de código de todas as versões (do **ES6 / ES2015** até **ES2024 / ES2025**), consulte o nosso [Guia Completo de Versões do ECMAScript](../../evolution/tc39/).
</Aside>

| Estágio | Ideia geral |
| ------- | ----------- |
| Stage 0 | Ideia inicial, ainda muito experimental |
| Stage 1 | Proposta com problema e direção discutidos |
| Stage 2 | Rascunho mais concreto da solução |
| Stage 3 | Candidato próximo de finalização |
| Stage 4 | Recurso finalizado, pronto para entrar na especificação |

Para acompanhar a evolução da linguagem, os links mais úteis são:

- [TC39 Proposals](https://github.com/tc39/proposals), com propostas ativas;
- [Finished Proposals](https://github.com/tc39/proposals/blob/main/finished-proposals.md),
  com recursos que chegaram ao Stage 4;
- [ECMA-262](https://ecma-international.org/publications-and-standards/standards/ecma-262/),
  com a edição anual oficial da especificação;
- [ECMAScript draft](https://tc39.es/ecma262/), com o rascunho vivo da próxima
  edição.

Na tabela abaixo, "liberado" significa que o recurso entrou em uma edição anual do
ECMAScript. A disponibilidade em navegadores, Node.js, Deno ou Bun pode variar de
acordo com a versão do ambiente.

| Edição | Exemplos importantes | Por que marcou a linguagem |
| ------ | -------------------- | -------------------------- |
| ES2015 | `let`, `const`, arrow functions, classes, modules, promises | Modernizou a sintaxe e consolidou a base do JavaScript usado hoje |
| ES2017 | `async`/`await` | Tornou código assíncrono mais parecido com código sequencial |
| ES2020 | optional chaining (`?.`), nullish coalescing (`??`), `BigInt` | Reduziu verificações repetitivas de `null`/`undefined` e adicionou inteiros grandes |
| ES2021 | logical assignment (`&&=`, `\|\|=`, `??=`), `String.prototype.replaceAll()` | Melhorou atribuições condicionais e manipulação de strings |
| ES2022 | class fields, private fields (`#name`), top-level `await` | Fortaleceu a sintaxe de classes e simplificou módulos assíncronos |
| ES2023 | `Array.prototype.findLast()`, `findLastIndex()`, `toSorted()`, `toReversed()` | Adicionou métodos úteis para arrays, incluindo operações que não alteram o array original |
| ES2024 | `Object.groupBy()`, `Map.groupBy()`, `Promise.withResolvers()` | Trouxe APIs para agrupamento de dados e criação mais direta de promises |

<Aside type="caution" title="Nem toda novidade deve ser usada imediatamente">
  Uma feature pode aparecer em artigos, navegadores ou ferramentas antes de estar
  amplamente disponível. Em projetos reais, confira suporte no ambiente alvo,
  documentação e necessidade de transpilação antes de depender de recursos recentes.
</Aside>

## Navegador, Node.js e npm

Quando usamos JavaScript no navegador, o arquivo normalmente faz parte de uma página
Web. Quando usamos JavaScript no Node.js, o arquivo é executado como programa no
sistema operacional.

| Ambiente | Como executar | Uso comum |
| -------- | ------------- | --------- |
| Navegador | `<script>`, Console, DevTools | interagir com HTML, CSS, eventos, DOM e APIs Web |
| Node.js | `node arquivo.js` | criar scripts, servidores, APIs e automações |
| npm | `npm install`, `npm run`, `npx` | instalar pacotes e executar tarefas do projeto |

O `npm` será importante porque muitos projetos Web dependem de pacotes. Vite,
Bootstrap, Tailwind, Express, Prisma e várias ferramentas de teste ou build entram
no projeto por meio do ecossistema npm.

Mas o ecossistema JavaScript não depende apenas do `npm`. Existem outros gerenciadores
de pacotes, runtimes e registros de pacotes que podem aparecer em projetos modernos.
Eles não têm exatamente o mesmo papel, então vale separar o que cada um resolve.

| Ferramenta | Tipo | Uso comum |
| ---------- | ---- | --------- |
| [pnpm](https://pnpm.io/) | Gerenciador de pacotes | Alternativa ao npm com foco em velocidade, economia de disco e monorepos |
| [Yarn](https://yarnpkg.com/) | Gerenciador de pacotes | Alternativa ao npm com foco em projetos reproduzíveis e organização de dependências |
| [Bun](https://bun.com/) | Runtime e toolkit | Executar JavaScript/TypeScript, instalar pacotes, rodar testes e empacotar projetos |

## Exercício

Execute os três testes abaixo e observe onde cada um funciona:

1. No console do navegador:

   ```js
   console.log(document.title);
   ```

2. Em um arquivo `main.js` executado com Node.js:

   ```js
   console.log(process.version);
   ```

3. Nos dois ambientes:

   ```js
   const message = "JavaScript";
   console.log(message.toUpperCase());
   ```

Depois, responda: quais comandos pertencem à linguagem e quais dependem do ambiente
de execução?

## Perguntas de revisão

**1. Qual é a diferença entre JavaScript e ECMAScript?**

<details>
  <summary>Possível resposta</summary>

  ECMAScript é a especificação padronizada da linguagem. JavaScript é o nome comum
  da linguagem usada pelos desenvolvedores e implementada em navegadores, Node.js e
  outros ambientes.
</details>

**2. Por que JavaScript se tornou tão importante na Web?**

<details>
  <summary>Possível resposta</summary>

  Porque os navegadores passaram a executar JavaScript para adicionar comportamento
  às páginas, como responder a eventos, manipular o DOM, validar formulários e
  consumir APIs.
</details>

**3. O que são Web APIs?**

<details>
  <summary>Possível resposta</summary>

  São recursos fornecidos pelo navegador, como DOM, eventos, `fetch`, `localStorage`
  e timers. Elas são usadas por JavaScript, mas não fazem parte do núcleo da
  linguagem ECMAScript.
</details>

**4. Por que `document` funciona no navegador e não em um script Node comum?**

<details>
  <summary>Possível resposta</summary>

  Porque `document` é uma API do navegador para representar a página carregada. Em
  um script Node comum não existe uma página HTML sendo renderizada.
</details>

**5. Para que serve Node.js?**

<details>
  <summary>Possível resposta</summary>

  Node.js permite executar JavaScript fora do navegador, por exemplo para criar
  scripts, servidores HTTP, APIs, ferramentas de build e automações.
</details>

**6. Qual é o papel do npm?**

<details>
  <summary>Possível resposta</summary>

  npm é o ecossistema usado para instalar pacotes, gerenciar dependências e executar
  scripts do projeto, como comandos de desenvolvimento, build e testes.
</details>

**7. O que significa dizer que JavaScript tem tipagem dinâmica?**

<details>
  <summary>Possível resposta</summary>

  Significa que o tipo está associado ao valor em tempo de execução. Uma mesma
  variável pode receber valores de tipos diferentes ao longo do programa.
</details>

**8. Por que comparações estritas, como `===`, são preferíveis em muitos casos?**

<details>
  <summary>Possível resposta</summary>

  Porque evitam conversões automáticas inesperadas durante a comparação, tornando o
  comportamento do código mais previsível.
</details>

**9. O que o TC39 faz?**

<details>
  <summary>Possível resposta</summary>

  TC39 é o comitê responsável por evoluir a especificação ECMAScript, discutindo,
  avaliando e amadurecendo propostas de novas funcionalidades da linguagem.
</details>

**10. Por que a especificação ECMAScript não costuma ser o melhor material inicial para aprender a programar?**

<details>
  <summary>Possível resposta</summary>

  Porque ela é escrita para definir regras precisas de implementação da linguagem.
  Para aprender a escrever scripts, materiais como guias e referências da MDN são
  mais didáticos.
</details>
