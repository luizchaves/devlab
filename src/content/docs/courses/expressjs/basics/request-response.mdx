Uma requisição HTTP é mais do que caminho e corpo: ela traz cabeçalhos que dizem quem
chama, o que aceita receber e em que formato enviou os dados. Esta aula percorre `req` e
`res` além do trio `params`/`query`/`body`.

Materiais: [slides da aula](../../../../slides/courses/expressjs/basics/request-response/) e [mapa mental](../../../../mindmaps/courses/expressjs/basics/request-response/).

## Objetivo

Ao final você saberá ler cabeçalhos e metadados da requisição, escolher o formato da
resposta por negociação de conteúdo, usar corretamente cada método que encerra a resposta e
servir arquivos estáticos e downloads.

## Anatomia de uma mensagem HTTP

Requisição e resposta têm a mesma estrutura: uma linha inicial, cabeçalhos e um corpo
opcional. O Express expõe cada parte em uma propriedade diferente.

## Lendo a requisição

Além de `params`, `query` e `body`, o objeto `req` descreve o contexto da chamada:

| Propriedade         | Contém                                                            |
| ------------------- | ----------------------------------------------------------------- |
| `req.method`        | verbo HTTP em maiúsculas (`'GET'`)                                 |
| `req.path`          | caminho sem a query string (`'/tasks'`)                            |
| `req.originalUrl`   | caminho completo como chegou, com a query (`'/tasks?page=2'`)      |
| `req.baseUrl`       | prefixo sob o qual o router foi montado (`'/api'`)                 |
| `req.protocol`      | `'http'` ou `'https'`                                              |
| `req.hostname`      | host pedido pelo cliente                                           |
| `req.ip`            | endereço de origem                                                 |
| `req.headers`       | todos os cabeçalhos, com nomes em minúsculas                       |
| `req.get(nome)`     | um cabeçalho, sem se importar com maiúsculas/minúsculas            |
| `req.is(tipo)`      | testa o `Content-Type` recebido                                    |
| `req.accepts(tipo)` | testa o `Accept` enviado pelo cliente                              |

Na prática, esses membros aparecem em middlewares de log e de controle de acesso:

```js showLineNumbers {2,5}
export function logger(req, res, next) {
  const agent = req.get('user-agent') ?? 'desconhecido';

  res.on('finish', () => {
    console.log(`${req.method} ${req.originalUrl} ${res.statusCode} — ${agent}`);
  });

  next();
}
```

<Aside type="note" title="`res.on('finish')` em vez de logar antes">
  Logar antes do handler não sabe o status final. O evento `finish` dispara depois que a
  resposta foi escrita, então `res.statusCode` já reflete o que o cliente recebeu.
</Aside>

## Negociação de conteúdo

O cliente diz o que aceita no cabeçalho `Accept`; o servidor escolhe o formato. `res.format()`
faz a escolha e devolve `406 Not Acceptable` quando nenhuma opção serve:

```js title="Respondendo em vários formatos" showLineNumbers {3,7,11}
app.get('/tasks/:id', (req, res) => {
  const task = { id: 1, title: 'Estudar rotas do Express', done: true };

  res.format({
    'application/json': () => res.json(task),

    'text/html': () => res.send(`<h1>${task.title}</h1>`),

    'text/csv': () => {
      res.type('text/csv');
      res.send(`id,title,done\n${task.id},${task.title},${task.done}`);
    },
  });
});
```

<Aside type="caution" title="415 não é 400">
  `400 Bad Request` diz "o conteúdo está errado"; `415 Unsupported Media Type` diz "o
  formato não é aceito". Trocar um pelo outro faz o cliente procurar o erro no lugar errado.
</Aside>

## Escrevendo a resposta

Os métodos de `res` se dividem em dois grupos: os que **configuram** e devolvem o próprio
`res` (encadeáveis) e os que **encerram** o ciclo.

| Método                       | Grupo     | Efeito                                                    |
| ---------------------------- | --------- | --------------------------------------------------------- |
| `res.status(code)`           | configura | define o status                                            |
| `res.set(nome, valor)`       | configura | define um cabeçalho                                        |
| `res.type(mime)`             | configura | define o `Content-Type`                                    |
| `res.location(url)`          | configura | define o cabeçalho `Location`                              |
| `res.cookie(nome, valor)`    | configura | adiciona um `Set-Cookie`                                   |
| `res.json(dados)`            | encerra   | serializa em JSON e define o `Content-Type`                |
| `res.send(corpo)`            | encerra   | envia string, Buffer ou objeto, inferindo o tipo           |
| `res.sendStatus(code)`       | encerra   | status + o nome dele como corpo (`204`, `404`)             |
| `res.redirect(code, url)`    | encerra   | resposta `3xx` com `Location`                              |
| `res.sendFile(caminho)`      | encerra   | envia um arquivo do disco                                  |
| `res.download(caminho)`      | encerra   | envia com `Content-Disposition: attachment`                |
| `res.end()`                  | encerra   | fecha sem corpo                                            |

Encadear é o padrão mais comum, porque os métodos de configuração devolvem `res`:

```js title="Encadeamento" showLineNumbers
res
  .status(201)
  .set('Location', `/tasks/${task.id}`)
  .json(task);
```

<Aside type="danger" title="Só se responde uma vez">
  Chamar dois métodos que encerram na mesma requisição lança
  `ERR_HTTP_HEADERS_SENT`. A causa quase sempre é um `if` sem `return`:

  ```js del={3} ins={4}
  app.get('/tasks/:id', (req, res) => {
    if (!task) {
      res.status(404).json({ message: 'Não encontrada' });
      return res.status(404).json({ message: 'Não encontrada' });
    }

    res.json(task);
  });
  ```
</Aside>

## Redirecionamento

`res.redirect()` responde com um status `3xx` e o cabeçalho `Location`. O status escolhido
muda o comportamento do cliente:

| Status | Nome               | Uso                                                       |
| ------ | ------------------ | --------------------------------------------------------- |
| `301`  | Moved Permanently  | a URL mudou de vez — o navegador guarda em cache           |
| `302`  | Found              | desvio temporário (é o padrão de `res.redirect`)           |
| `303`  | See Other          | depois de um `POST`, mande o cliente buscar com `GET`      |
| `307`  | Temporary Redirect | como o `302`, mas preservando o método original            |

```js title="Redirecionamento após POST" showLineNumbers {4}
app.post('/tasks', (req, res) => {
  const task = createTask(req.body);

  res.redirect(303, `/tasks/${task.id}`);
});
```

## Arquivos estáticos e download

`express.static()` publica um diretório inteiro. É um middleware, então a ordem de registro
importa: o que ele encontra no disco é respondido antes de qualquer rota abaixo dele.

```js showLineNumbers {2,5}
// public/index.html passa a responder em GET /
app.use(express.static('public'));

// Sob um prefixo: public/logo.png -> GET /assets/logo.png
app.use('/assets', express.static('public'));
```

Para um arquivo específico, `res.sendFile()` envia inline e `res.download()` força o salvamento:

```js title="Envio de arquivos" showLineNumbers {2,7}
app.get('/relatorio', (req, res) => {
  res.sendFile('/caminho/absoluto/relatorio.pdf');
});

app.get('/relatorio/baixar', (req, res) => {
  // Define Content-Disposition: attachment; filename="relatorio-2026.pdf"
  res.download('/caminho/absoluto/relatorio.pdf', 'relatorio-2026.pdf');
});
```

<Aside type="caution" title="Nunca monte o caminho com dados do cliente">
  `res.sendFile(\`./uploads/${req.params.nome}\`)` permite `../../.env` e vaza qualquer
  arquivo do servidor. Valide o nome contra uma lista conhecida ou resolva o caminho e
  confirme que ele continua dentro do diretório permitido.
</Aside>

## Cabeçalhos de cache

Respostas de leitura ganham desempenho com dois cabeçalhos. O Express já envia `ETag`
automaticamente para `res.json()` e `res.send()`; `Cache-Control` é escolha da aplicação:

```js title="Cache de uma listagem pública" showLineNumbers {2}
app.get('/tags', (req, res) => {
  res.set('Cache-Control', 'public, max-age=300');

  res.json(tags);
});
```

Com o `ETag` guardado, o cliente reenvia `If-None-Match` e o Express responde `304 Not
Modified` sem corpo — a rede transporta apenas os cabeçalhos.

## Exercício

Escreva um middleware `responseTime` que:

1. registre o instante em que a requisição chegou;
2. no evento `finish`, calcule a duração;
3. escreva a duração no log junto com método, caminho e status.

Depois explique por que o cabeçalho `X-Response-Time` **não** pode ser definido dentro do
`finish`.

<details>
  <summary>Possível resposta</summary>

  ```js showLineNumbers
  export function responseTime(req, res, next) {
    const start = process.hrtime.bigint();

    res.on('finish', () => {
      const ms = Number(process.hrtime.bigint() - start) / 1e6;

      console.log(`${req.method} ${req.originalUrl} ${res.statusCode} — ${ms.toFixed(1)}ms`);
    });

    next();
  }
  ```

  O cabeçalho não pode ser definido no `finish` porque nesse ponto os cabeçalhos já foram
  enviados — `res.set()` ali lança `ERR_HTTP_HEADERS_SENT`. Para enviá-lo, seria preciso
  medir antes e interceptar `res.end`.
</details>

## Perguntas de revisão

### Requisição

1. **Qual a diferença entre `req.path` e `req.originalUrl`?**

   <details>
     <summary>Possível resposta</summary>

     `req.path` é só o caminho, já sem a query string e relativo ao ponto de montagem do
     router. `req.originalUrl` é a URL como chegou, com a query e com o prefixo — é a que se
     usa em logs.
   </details>

2. **Por que `req.get('Content-Type')` é melhor que `req.headers['Content-Type']`?**

   <details>
     <summary>Possível resposta</summary>

     Porque `req.headers` guarda os nomes em minúsculas: `req.headers['Content-Type']` é
     sempre `undefined`. `req.get()` ignora maiúsculas e minúsculas.
   </details>

### Resposta

3. **O que causa `ERR_HTTP_HEADERS_SENT`?**

   <details>
     <summary>Possível resposta</summary>

     Tentar responder duas vezes. O caso típico é um `if` de erro sem `return`, que responde
     e deixa o fluxo continuar até o `res.json()` final.
   </details>

4. **Quando usar `303` em vez de `302` em um redirecionamento?**

   <details>
     <summary>Possível resposta</summary>

     Depois de um `POST`, quando se quer que o cliente busque o recurso criado com `GET`. O
     `302` não garante a troca de método e pode reenviar o `POST` para a nova URL.
   </details>

5. **Por que `express.static()` precisa ser registrado antes das rotas de API?**

   <details>
     <summary>Possível resposta</summary>

     Porque é um middleware avaliado em ordem. Registrado depois, qualquer rota ou handler
     de 404 acima dele responderia primeiro — os arquivos nunca seriam servidos.
   </details>
