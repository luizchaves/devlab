## Rotas

| Método | Caminho      | Corpo             | Sucesso | Erros                     |
| ------ | ------------ | ----------------- | ------- | ------------------------- |
| GET    | `/users`     | —                 | `200`   | —                         |
| GET    | `/users/:id` | —                 | `200`   | `400`, `404`              |
| POST   | `/users`     | `{ name, email }` | `201`   | `400`, `409`, `415`       |
| PUT    | `/users/:id` | `{ name, email }` | `200`   | `400`, `404`, `415`       |
| DELETE | `/users/:id` | —                 | `204`   | `400`, `404`              |

## Exemplo

Nesta seção, testamos o comportamento do servidor TypeScript com verificação de tipo de mídia (`requireJson`) e respostas de erro estruturadas.

O middleware `requireJson` intercepta requisições `POST` sem o cabeçalho `Content-Type: application/json` antes de chegar ao controller, rejeitando-as com status `415 Unsupported Media Type`:

<details>
  <summary>Requisição .http correspondente</summary>

  ```http
  ### Testar erro de Content-Type incompativel (415)
  POST http://localhost:3000/users
  Content-Type: text/plain

  "corpo em texto puro"
  ```
</details>

<ApiRequest method="POST" path="/users" baseUrl="http://localhost:3000" description="Content-Type: text/plain" />

<ApiResponse status={415}>
{`
  {
    "error": {
      "status": 415,
      "message": "Content-Type precisa ser application/json"
    }
  }
`}
</ApiResponse>

Ao tentar cadastrar um usuário com e-mail já existente no banco (`ana@example.com`), o model lança um `HttpError` de conflito, retornando status `409 Conflict`:

<details>
  <summary>Requisição .http correspondente</summary>

  ```http
  ### Testar conflito de e-mail duplicado (409)
  POST http://localhost:3000/users
  Content-Type: application/json

  {
    "name": "Ana de novo",
    "email": "ana@example.com"
  }
  ```
</details>

<ApiRequest method="POST" path="/users" baseUrl="http://localhost:3000">
{`
  {
    "name": "Ana de novo",
    "email": "ana@example.com"
  }
`}
</ApiRequest>

<ApiResponse status={409}>
{`
  {
    "error": {
      "status": 409,
      "message": "E-mail ja cadastrado"
    }
  }
`}
</ApiResponse>

## Conceitos abordados

- Execução nativa de `.ts` pelo Node (*type stripping*)
- `tsconfig.json` com `noEmit`, `allowImportingTsExtensions` e `erasableSyntaxOnly`
- *Subpath imports* (`#`) declarados no `package.json`
- Tipagem de `Request`, `Response` e `NextFunction`
- Separação entre o tipo que **entra** (`UserInput`) e o que **sai** (`User`)
- `HttpError` e tratamento de erro centralizado

</Aside>
