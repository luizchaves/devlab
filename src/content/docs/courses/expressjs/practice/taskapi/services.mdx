Nível **Avançado** · Node.js · Express.js · TypeScript · Multer · Nodemailer · SSE

Quatro coisas que uma API faz além de responder JSON — e as quatro têm a mesma armadilha:
dado do cliente virando caminho de arquivo, comando de sistema ou endereço de destino.

## O que muda nesta etapa

| Recurso | Rota | Dependência |
| ------- | ---- | ----------- |
| Upload de avatar | `POST /auth/me/avatar` | Multer |
| Confirmação de e-mail | `GET /auth/verify` | Nodemailer |
| Tempo real | `GET /events` | nenhuma (SSE é HTTP) |

O `User` ganha `avatar`, `verifyToken` e `verifiedAt`.

<Aside type="danger" title="`mimetype` é declarado pelo cliente">
  O filtro barra o engano honesto, não o ataque: o `Content-Type` de cada parte é enviado
  pelo navegador e pode ser forjado. Para valer, é preciso ler os primeiros bytes do
  arquivo e conferir a assinatura — e nunca servir o diretório de uploads como conteúdo
  executável.
</Aside>

## E-mail: o cadastro não espera o SMTP

<SourceCode
  path="examples/courses/expressjs/projects/task-api-services/src/services/mail-service.ts"
  title="src/services/mail-service.ts"
  region="send"
/>

Um SMTP lento transformaria um cadastro de 50 ms numa espera de três segundos; um SMTP fora
do ar faria o cadastro **falhar**, quando o usuário já foi criado. O envio é disparado e
registrado no log, e a resposta HTTP não depende dele.

Em desenvolvimento não há credencial nenhuma: o `jsonTransport` serializa a mensagem em vez
de enviá-la, então o fluxo inteiro é exercitável sem mandar e-mail para ninguém.

## Tempo real: uma resposta que não termina

<Mermaid title="Ciclo de um evento no SSE">
{`
sequenceDiagram
  participant C as Cliente
  participant E as GET /events
  participant T as POST /tasks
  C->>E: EventSource, com token
  E-->>C: 200, Content-Type: text/event-stream
  Note over E,C: a resposta fica aberta
  C->>T: cria uma tarefa
  T->>E: publish(userId, 'task.created', task)
  E-->>C: event: task.created\\ndata: {…}
`}
</Mermaid>

O formato é texto puro, e a linha em branco no fim é o que encerra a mensagem — sem ela o
navegador continua esperando e nada é entregue:

recebe apenas os eventos das próprias tarefas. Autorização vale para SSE tanto quanto para

<Aside type="danger" title="A diferença é o shell">
  `exec('ping ' + host)` passa a string por um shell. Um host chamado

## Rotas novas

| Método | Caminho             | Descrição                                   |
| ------ | ------------------- | ------------------------------------------- |
| POST   | `/auth/me/avatar`   | Envia a imagem de perfil (`multipart`)      |
| GET    | `/auth/verify`      | Confirma o e-mail pelo token do link        |
| GET    | `/events`           | Fluxo SSE das tarefas do dono               |
| GET    | `/ping?host=`       | Mede latência até um host                   |
| GET    | `/uploads/:arquivo` | Serve a imagem enviada                      |

## Conceitos abordados

- `multipart/form-data` e por que o nome do arquivo é do servidor
- Limites de tamanho, de quantidade e de tipo no upload
- `express.static` no lugar de uma rota que monta caminho
- Envio de e-mail que não bloqueia a resposta, e o transporte de teste
- SSE: cabeçalhos, formato da mensagem e a linha em branco
- Assinatura por dono e a limpeza de conexões fechadas
- `execFile` contra `exec`, e a validação como segunda camada
