### US16 — Confirmar que o e-mail é meu · RF07

> **Como** cliente recém-cadastrado,
> **quero** receber um e-mail com um link de confirmação,
> **para** provar que o endereço que informei é meu.

```gherkin
Cenário: CA16.1 - O cadastro dispara, e não espera
  Quando envio POST /auth/signup com dados válidos
  Então recebo o status 201 sem esperar o SMTP
  E um e-mail de boas-vindas com o link de verificação é disparado

Cenário: CA16.2 - Em desenvolvimento nada é enviado
  Dado o ambiente sem SMTP_HOST
  Quando um cadastro acontece
  Então a mensagem aparece no log como mail_sent
  E nenhum destinatário real recebe nada

Cenário: CA16.3 - O link confirma o endereço
  Quando envio GET /auth/verify?token= com o token do link
  Então recebo o status 200 com "status" igual a "verified"
  E verifiedAt do usuário fica preenchido

Cenário: CA16.4 - Token inválido ou já usado
  Quando envio GET /auth/verify com um token desconhecido ou repetido
  Então recebo o status 400

Cenário: CA16.5 - O SMTP não derruba o cadastro
  Dado o SMTP fora do ar
  Quando envio POST /auth/signup com dados válidos
  Então recebo o status 201
  E a falha de envio vai para o log
```

### US17 — Ter uma foto de perfil · RF08

> **Como** cliente HTTP autenticado,
> **quero** enviar uma imagem de perfil,
> **para** que a minha conta seja reconhecível por quem consome a API.

```gherkin
Cenário: CA17.1 - Upload exige token
  Quando envio POST /auth/me/avatar sem Authorization
  Então recebo o status 401

Cenário: CA17.2 - Upload com sucesso
  Dado um token válido
  Quando envio um PNG de até 2 MB no campo "avatar"
  Então recebo o status 201
  E o corpo traz o caminho da imagem em "avatar"

Cenário: CA17.3 - Tipo fora da lista
  Quando envio um arquivo que não é PNG, JPEG nem WebP
  Então recebo o status 415
  E nada é gravado em disco

Cenário: CA17.4 - Tamanho acima do limite
  Quando envio um arquivo maior que 2 MB
  Então o upload é recusado antes de o arquivo ser gravado por inteiro

Cenário: CA17.5 - O nome é decisão do servidor
  Quando envio um arquivo chamado "../../etc/passwd.png"
  Então o arquivo no disco tem um nome UUID com a extensão do tipo
  E o nome original não é usado

Cenário: CA17.6 - Sem arquivo órfão
  Dado um usuário com avatar
  Quando ele envia um novo
  Então o arquivo anterior é apagado

Cenário: CA17.7 - A imagem é servida como estático
  Quando envio GET /uploads/{arquivo}
  Então recebo a imagem por express.static
  E não por uma rota que monta o caminho a partir da requisição
```

### US18 — Ser avisado no instante da mudança · RF09

> **Como** cliente HTTP autenticado,
> **quero** manter uma conexão aberta que receba as mudanças das minhas tarefas,
> **para** atualizar a tela sem consultar `/tasks` a cada segundo.

```gherkin
Cenário: CA18.1 - A resposta que não termina
  Quando envio GET /events com um token válido
  Então recebo o status 200 com Content-Type: text/event-stream
  E a resposta fica aberta

Cenário: CA18.2 - Cada mudança vira um evento
  Dado uma conexão aberta em /events
  Quando envio POST /tasks com o mesmo token
  Então recebo "event: task.created" com a tarefa em data
  E quando envio PUT /tasks/{id}
  Então recebo "event: task.updated"

Cenário: CA18.3 - Só os eventos do dono
  Dado Ana conectada em /events
  Quando Bruno cria uma tarefa
  Então nada chega à conexão da Ana

Cenário: CA18.4 - Conexão fechada sai do registro
  Quando o cliente fecha a conexão
  Então ele é removido do Map de clientes

Cenário: CA18.5 - Eventos exigem token
  Quando envio GET /events sem Authorization
  Então recebo o status 401
```

### US19 — Medir a latência até um host · RF10

> **Como** cliente HTTP autenticado,
> **quero** pedir à API que meça a latência até um host,
> **para** diagnosticar a rede a partir do servidor, e não da minha máquina.

```gherkin
Cenário: CA19.1 - Ping com sucesso
  Quando envio GET /ping?host=8.8.8.8 com um token válido
  Então recebo o status 200 com a latência medida

Cenário: CA19.2 - Injeção é recusada antes do comando
  Quando envio GET /ping?host=127.0.0.1;rm -rf /
  Então recebo o status 422
  E nenhum comando é executado

Cenário: CA19.3 - Nunca por um shell
  Quando abro src/services/ping-service.ts
  Então o comando é executado com execFile e argumentos em array
  E exec não aparece em lugar nenhum

Cenário: CA19.4 - Rota cara tem limite próprio
  Quando envio GET /ping sem token
  Então recebo o status 401
  E quando ultrapasso o limite da rota
  Então recebo o status 429

Cenário: CA19.5 - A extração é pura
  Quando testo a função que extrai a latência da saída do comando
  Então ela roda sem rede e sem processo filho
```

<Aside type="danger" title="`mimetype` é declarado pelo cliente">
  O filtro barra o engano honesto, não o ataque: o `Content-Type` de cada parte é enviado

## E-mail: o cadastro não espera o SMTP

<SourceCode
  path="examples/courses/expressjs/projects/task-api-services/src/services/mail-service.ts"
  title="src/services/mail-service.ts"

Um SMTP lento transformaria um cadastro de 50 ms numa espera de três segundos; um SMTP fora
do ar faria o cadastro **falhar**, quando o usuário já foi criado. O envio é disparado e
registrado no log, e a resposta HTTP não depende dele.

Em desenvolvimento não há credencial nenhuma: o `jsonTransport` serializa a mensagem em vez
de enviá-la, então o fluxo inteiro é exercitável sem mandar e-mail para ninguém.

## Tempo real: uma resposta que não termina

<Mermaid title="Ciclo de um evento no SSE">
{`
sequenceDiagram
  participant C as Cliente
  participant E as GET /events
  participant T as POST /tasks
  C->>E: EventSource, com token
  E-->>C: 200, Content-Type: text/event-stream
  Note over E,C: a resposta fica aberta
  C->>T: cria uma tarefa
  T->>E: publish(userId, 'task.created', task)
  E-->>C: event: task.created\\ndata: {…}
`}
</Mermaid>

O formato é texto puro, e a linha em branco no fim é o que encerra a mensagem — sem ela o
navegador continua esperando e nada é entregue:

## Conceitos abordados

- `multipart/form-data` e por que o nome do arquivo é do servidor
- Limites de tamanho, de quantidade e de tipo no upload
- `express.static` no lugar de uma rota que monta caminho
- Envio de e-mail que não bloqueia a resposta, e o transporte de teste
- SSE: cabeçalhos, formato da mensagem e a linha em branco
- Assinatura por dono e a limpeza de conexões fechadas
- `execFile` contra `exec`, e a validação como segunda camada
