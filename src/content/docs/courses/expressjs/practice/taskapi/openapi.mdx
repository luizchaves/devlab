## O que muda nesta etapa

Nenhuma rota de `/tasks` muda. O que entra é a publicação do contrato:

| Antes (etapa 5) | Agora (etapa 6) |
| --------------- | --------------- |
| O contrato existia só no `requests.http` | `src/docs/openapi.ts` |
| — | `GET /openapi.json`, o documento cru |
| — | `GET /docs`, o Swagger UI |

## O problema que isso resolve

Documentação escrita à mão descreve a API que existia no dia em que foi escrita. Quando a
regra muda no schema e ninguém lembra de atualizar o `.yaml`, o contrato publicado passa a
mentir — e o cliente que confiou nele quebra em produção.

<Mermaid title="Uma fonte, três consumidores">
{`
flowchart LR
  S["src/schemas/task.ts<br/>schema Zod"] --> V["validate<br/>recusa 422"]
  S --> J["z.toJSONSchema()"]
  J --> D["/openapi.json<br/>ferramentas"]
  J --> U["/docs<br/>Swagger UI"]
`}
</Mermaid>

Mudar `min(3)` para `min(5)` no schema muda, na mesma linha, o que a API recusa e o que a
documentação promete.

## O Zod converte sozinho

O Zod 4 gera JSON Schema sem biblioteca auxiliar. Como o OpenAPI 3.0 usa um dialeto
próprio, o alvo é informado na chamada:

<SourceCode
  path="examples/courses/express/projects/task-api-openapi/src/docs/openapi.ts"
  title="src/docs/openapi.ts"
  region="to-json-schema"
/>

Os schemas da etapa 5 declaram `body`, `params` e `query` como chaves de um objeto maior,
então `shapeOf` recorta a fonte que cada parte do documento precisa. O corpo do `POST`
vira o `requestBody`; a `query` vira a lista de `parameters`; o `params` vira o parâmetro
de caminho.

`/openapi.json` serve o documento cru, que Insomnia, Postman e geradores de client
consomem. `/docs` serve o Swagger UI, que é onde uma pessoa navega:

<Aside type="caution" title="`/docs` em produção é uma decisão, não um padrão">
  O Swagger UI expõe todos os endpoints, incluindo os administrativos. Numa API pública,
  ou você publica o contrato de propósito, ou protege `/docs` atrás de autenticação. O
  que não vale é deixá-lo aberto sem ter decidido.
</Aside>

## Rotas

| Método | Caminho          | O que serve                        |
| ------ | ---------------- | ---------------------------------- |
| GET    | `/docs`          | Swagger UI, para pessoas           |
| GET    | `/openapi.json`  | O documento cru, para ferramentas  |

As rotas de `/health` e `/tasks` são as mesmas da [etapa 5](../validation/).

## Conceitos abordados

- OpenAPI 3 como contrato da API
- `z.toJSONSchema()` com alvo `openapi-3.0`
- Uma fonte de verdade para validação e documentação
- Swagger UI servido pelo próprio Express
- Ordem de montagem do router de documentação
