## O que muda nesta etapa

É a etapa inicial, então tudo é novo. O que ela estabelece e que sobrevive até a etapa
12 são duas decisões: o recurso da API é a **tarefa** (`Task`), e a primeira rota é
`/health`.

## A rota que não depende do domínio

tarefa. É a rota mais simples possível que ainda é útil de verdade — toda API em

## Rotas

| Método | Caminho      | Sucesso | Erros   |
| ------ | ------------ | ------- | ------- |
| GET    | `/health`    | `200`   | —       |
| GET    | `/tasks`     | `200`   | —       |
| GET    | `/tasks/:id` | `200`   | `404`   |
| POST   | `/tasks`     | `201`   | `400`   |

## Testando

O `/health` responde imediatamente, sem tocar em nenhum dado da aplicação. O
`uptime` vem de `process.uptime()` e cresce a cada segundo que o processo fica no ar:

<ApiRequest method="GET" path="/health" baseUrl="http://localhost:3000" />

<ApiResponse status={200}>
{`
  {
    "status": "ok",
    "uptime": 12.480321
  }
`}
</ApiResponse>

A criação envia um JSON com o campo `title` e recebe de volta a tarefa já com `id` e
`done`, sob status `201 Created`:

<ApiRequest method="POST" path="/tasks" baseUrl="http://localhost:3000">
{`
  {
    "title": "Ler a documentação do Express"
  }
`}
</ApiRequest>

<ApiResponse status={201}>
{`
  {
    "id": 3,
    "title": "Ler a documentação do Express",
    "done": false
  }
`}
</ApiResponse>

Um `POST` sem `title` é recusado antes de chegar ao array, com `400 Bad Request` e uma
mensagem que diz qual campo falta:

<ApiRequest method="POST" path="/tasks" baseUrl="http://localhost:3000">
{`
  {}
`}
</ApiRequest>

<ApiResponse status={400}>
{`
  {
    "message": "O campo \\"title\\" e obrigatorio"
  }
`}
</ApiResponse>

## Conceitos abordados

- Criação do servidor com `express()` e `app.listen()`
- Rotas e métodos HTTP (`app.get`, `app.post`)
- Parâmetros de rota (`req.params`) e corpo JSON (`express.json()`, `req.body`)
- Status codes com `res.status()`
- O endpoint `/health` como contrato de operação
