## Objetivo

Trocar a camada de dados sem tocar nas demais camadas, comprovando na prática o valor
da separação feita em MVC.

## O que muda?

Só o model. O controller da etapa 7 e o da etapa 8 são **o mesmo arquivo** — é o que a
separação em camadas comprou lá atrás:

```ts title="src/models/task-model.ts" del={1,4-5} ins={2,7-11}
import { connect } from '#database/database.ts';
import { prisma } from '#database/prisma.ts';

const db = await connect();
const rows = await db.all('SELECT * FROM tasks WHERE done = ?', [0]);

const records = await prisma.task.findMany({
  where: { done: false },
  include: { tags: true },
  orderBy: { createdAt: 'desc' },
});
```

<Aside type="note" title="Sem try/catch em cada rota">
  No Express 5, o erro lançado dentro de uma função `async` chega sozinho ao
  `errorHandler`. Foi por isso que centralizamos o tratamento de erros lá atrás.
</Aside>

Duas escolhas ali merecem explicação. `update` lança `P2025` quando o id não existe — ao
contrário do `UPDATE` em SQL, que apenas afeta zero linhas —, então o `.catch(() => null)`
o converte no `undefined` que o controller já sabe traduzir em `404`. E `delete` também
lança; `deleteMany` não, porque devolve a contagem.

## Exercício

Implemente o CRUD completo de `Tag`, seguindo a mesma estrutura: `tag-model.ts`,
`tag-controller.ts` e `tag-router.ts`, montado em `/tags`. Ao remover uma tag que ainda
está associada a alguma tarefa, responda `409` em vez de apagá-la em silêncio.

## Desafio

Hoje o `409` de título repetido vem de uma consulta prévia no controller, o que deixa uma
janela entre a checagem e a escrita: duas requisições simultâneas passam pelas duas
checagens. Remova a consulta prévia e trate o erro de constraint `UNIQUE` no
`errorHandler`, respondendo `409 Conflict` com uma mensagem clara.

Dica: o erro tem `code === 'P2002'`.

<ApiResponse status={409}>
{`
  {
    "error": {
      "status": 409,
      "message": "Ja existe uma tarefa com esse titulo"
    }
  }
`}
</ApiResponse>
