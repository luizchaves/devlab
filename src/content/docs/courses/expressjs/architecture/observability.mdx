Log responde "o que aconteceu nesta requisição". Não responde "a API está mais lenta que
ontem?" nem "onde exatamente esses 3 segundos foram gastos?". Esta aula acrescenta os dois
sinais que faltam.

## Objetivo

Ao final você saberá distinguir logs, métricas e rastros, instrumentar uma API Express com o
SDK do OpenTelemetry, criar spans com atributos próprios, exportar por OTLP e correlacionar
um rastro com as linhas de log da mesma requisição.

## Monitoramento e observabilidade

Não são sinônimos, e a diferença é prática:

| Conceito         | Responde a                                     | Exemplo                                 |
| ---------------- | ---------------------------------------------- | --------------------------------------- |
| Monitoramento    | perguntas **previstas**                        | "a CPU passou de 80%?"                   |
| Observabilidade  | perguntas **não previstas**                    | "por que só os usuários do plano X estão lentos desde as 14h?" |

Observabilidade é a propriedade de conseguir entender o que o sistema está fazendo por
dentro **sem publicar código novo** para investigar. Ela se apoia em três sinais.

## Os três sinais

<Mermaid title="Logs, métricas e rastros: os três sinais da observabilidade">
{`
flowchart TD
  A["Uma requisição<br/>GET /investments"] --> B["Log<br/>evento discreto e detalhado"]
  A --> C["Métrica<br/>número agregado ao longo do tempo"]
  A --> D["Rastro (trace)<br/>o caminho e o tempo de cada etapa"]
  B --> E["'requestId 9f1c respondeu 500'"]
  C --> F["'p95 subiu de 120ms para 900ms'"]
  D --> G["'800ms foram na consulta ao banco'"]
`}
</Mermaid>

| Sinal    | Granularidade      | Custo de armazenamento | Responde                        |
| -------- | ------------------ | ---------------------- | ------------------------------- |
| Log      | um evento          | alto (texto por evento) | o que aconteceu **aqui**         |
| Métrica  | agregado por tempo | baixo (números)         | está pior que antes?             |
| Rastro   | uma requisição inteira | médio (amostrado)   | **onde** o tempo foi gasto       |

<Aside type="tip" title="Os três se complementam, não se substituem">
  A métrica avisa que algo piorou; o rastro mostra em qual etapa; o log explica o motivo
  daquela requisição específica. Ter só um dos três deixa uma parte da investigação cega.
</Aside>

## O que é o OpenTelemetry

O [OpenTelemetry](https://opentelemetry.io/) (OTel) é um padrão aberto — sob a CNCF — que
define **como** produzir e transportar os três sinais. Ele não é um servidor de
monitoramento: é a camada neutra entre a sua aplicação e a ferramenta que exibe os dados.

<Mermaid title="Papel do OpenTelemetry entre a aplicação e as ferramentas">
{`
flowchart TD
  A["API Express<br/>SDK do OpenTelemetry"] -->|"protocolo OTLP"| B["Collector<br/>recebe, processa, roteia"]
  B --> C["Jaeger / Tempo<br/>rastros"]
  B --> D["Prometheus / Mimir<br/>métricas"]
  B --> E["Loki / Elastic<br/>logs"]
  B --> F["SaaS<br/>Datadog, Honeycomb, Grafana Cloud"]
`}
</Mermaid>

O ganho é a ausência de amarração: trocar de ferramenta de visualização não exige tocar no
código instrumentado.

| Conceito OTel     | O que é                                                        |
| ----------------- | -------------------------------------------------------------- |
| **Trace**         | o percurso completo de uma requisição pelo sistema              |
| **Span**          | uma etapa do percurso, com início, fim e atributos              |
| **Trace ID**      | identificador do percurso, propagado entre serviços             |
| **Atributo**      | par chave-valor anexado ao span (`http.route`, `db.system`)     |
| **Instrumentação**| o código que cria spans — automática ou manual                  |
| **Exporter**      | quem envia os dados para fora do processo                       |
| **Collector**     | processo intermediário que recebe, filtra e roteia              |

## Instrumentação automática

A instrumentação automática cobre Express, HTTP, Prisma e o driver de banco sem nenhuma
alteração no código da aplicação:

<Steps>

1. Instale o SDK e as instrumentações:

   <PackageManagerTabs package="@opentelemetry/sdk-node @opentelemetry/auto-instrumentations-node @opentelemetry/exporter-trace-otlp-http" />

2. Crie o arquivo de inicialização — ele precisa rodar **antes** de qualquer outro import:

   ```ts title="src/telemetry.ts" showLineNumbers {5,9,13}
   import { NodeSDK } from '@opentelemetry/sdk-node';
   import { getNodeAutoInstrumentations } from '@opentelemetry/auto-instrumentations-node';
   import { OTLPTraceExporter } from '@opentelemetry/exporter-trace-otlp-http';

   const sdk = new NodeSDK({
     serviceName: 'investment-api',
     traceExporter: new OTLPTraceExporter({
       // Endpoint do Collector; em desenvolvimento, do Jaeger local.
       url: process.env.OTEL_EXPORTER_OTLP_ENDPOINT ?? 'http://localhost:4318/v1/traces',
     }),
     instrumentations: [getNodeAutoInstrumentations()],
   });

   sdk.start();
   ```

3. Carregue-o antes da aplicação:

   ```json title="package.json" {3}
   {
     "scripts": {
       "start": "node --import ./src/telemetry.ts src/server.ts"
     }
   }
   ```

4. Suba um Jaeger local para visualizar:

   ```bash title="Terminal"
   docker run -p 16686:16686 -p 4318:4318 jaegertracing/all-in-one
   ```

5. Faça algumas requisições e abra <code>http://localhost:16686</code>.

</Steps>

<Aside type="caution" title="A ordem de carregamento não é detalhe">
  As instrumentações funcionam substituindo módulos no momento da importação. Se `express` ou
  `pg` forem carregados antes do SDK, eles não são instrumentados e **nenhum span aparece** —
  sem erro nenhum. Por isso `--import`, e não um `import` no topo do `server.ts`.
</Aside>

O resultado é uma árvore de spans que mostra onde o tempo foi:

```txt title="Um trace de GET /investments"
GET /investments                                    412ms
├── middleware - authenticate                         2ms
├── middleware - jsonParser                           0ms
├── router - /investments                           408ms
│   ├── prisma:client:operation investment.findMany 385ms
│   │   └── prisma:engine:db_query SELECT …         381ms
│   └── prisma:client:operation category.findMany    18ms
└── response                                          1ms
```

A leitura é imediata: 381 ms dos 412 ms estão em uma única consulta.

## Spans manuais

A instrumentação automática cobre bordas — HTTP, banco, fila. O que ela não conhece é a
**sua** lógica. Um span manual dá nome a um trecho relevante:

```ts title="src/services/investment-service.ts" showLineNumbers {3,6,12,16}
import { trace, SpanStatusCode } from '@opentelemetry/api';

const tracer = trace.getTracer('investment-service');

export async function calcularRentabilidade(userId: string) {
  return tracer.startActiveSpan('calcular-rentabilidade', async (span) => {
    try {
      const investimentos = await Investment.findAllByUser(userId);

      // Atributos tornam o span filtrável: "só os que tinham mais de 100 itens".
      span.setAttribute('investimentos.total', investimentos.length);
      span.setAttribute('app.user_id', userId);

      return agregar(investimentos);
    } catch (error) {
      span.setStatus({ code: SpanStatusCode.ERROR, message: (error as Error).message });
      throw error;
    } finally {
      // Sem o end(), o span nunca é exportado.
      span.end();
    }
  });
}
```

<Aside type="danger" title="Nunca coloque dado sensível em atributo">
  Atributos de span vão para a ferramenta de observabilidade, com retenção e acesso próprios.
  Senha, token, CPF e e-mail completo não entram. Use identificadores, não conteúdo.
</Aside>

## Correlacionando rastro e log

O elo entre os dois sinais é o `traceId`. Incluí-lo em cada linha de log permite pular do
rastro lento para as linhas exatas daquela requisição:

```ts title="src/middlewares/logger.ts" showLineNumbers {1,5,11}
import { trace } from '@opentelemetry/api';

export function logger(req: Request, res: Response, next: NextFunction) {
  const start = process.hrtime.bigint();
  const span = trace.getActiveSpan();

  res.on('finish', () => {
    console.log(JSON.stringify({
      level: 'info',
      requestId: req.id,
      traceId: span?.spanContext().traceId,
      method: req.method,
      url: req.originalUrl,
      status: res.statusCode,
      durationMs: Number(process.hrtime.bigint() - start) / 1e6,
    }));
  });

  next();
}
```

O `traceId` também atravessa serviços: o cabeçalho `traceparent`, do padrão
[W3C Trace Context](https://www.w3.org/TR/trace-context/), é propagado automaticamente pelas
instrumentações de HTTP.

```http title="Propagação entre serviços"
GET /investments HTTP/1.1
traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01
             │  └── trace id ──────────────────┘ └── span pai ──┘ └ flags
             └ versão
```

## Métricas

Rastros mostram uma requisição; métricas mostram a tendência. Para uma API, o conjunto
mínimo é conhecido como **RED**:

| Métrica       | O que mede                       | Instrumento OTel   |
| ------------- | -------------------------------- | ------------------ |
| **R**ate      | requisições por segundo          | `Counter`          |
| **E**rrors    | proporção de respostas `5xx`     | `Counter` com atributo de status |
| **D**uration  | distribuição do tempo de resposta| `Histogram`        |

```ts title="src/telemetry-metrics.ts" showLineNumbers {3,5,11}
import { metrics } from '@opentelemetry/api';

const meter = metrics.getMeter('investment-api');

const duracao = meter.createHistogram('http.server.request.duration', {
  unit: 's',
  description: 'Duração das requisições HTTP',
});

export function metricsMiddleware(req: Request, res: Response, next: NextFunction) {
  const start = process.hrtime.bigint();

  res.on('finish', () => {
    duracao.record(Number(process.hrtime.bigint() - start) / 1e9, {
      // A rota, não a URL: /users/:id, e não /users/42.
      'http.route': req.route?.path ?? 'desconhecida',
      'http.request.method': req.method,
      'http.response.status_code': res.statusCode,
    });
  });

  next();
}
```

<Aside type="danger" title="Cardinalidade explode o custo">
  Usar `req.originalUrl` como atributo cria uma série temporal por **id**: `/users/1`,
  `/users/2`, `/users/3`… Milhares de séries derrubam o backend de métricas e a conta no
  fim do mês. Use sempre o padrão da rota (`req.route.path`), nunca a URL concreta.
</Aside>

Com o histograma, a pergunta que importa deixa de ser a média:

| Estatística | O que revela                                          |
| ----------- | ----------------------------------------------------- |
| Média       | pouco — uma requisição de 10 s se dilui em mil de 50 ms |
| p50         | a experiência típica                                   |
| p95 / p99   | a experiência dos piores casos — onde as reclamações moram |

## Amostragem

Exportar 100% dos rastros de uma API com tráfego alto custa caro. A amostragem decide o que
guardar:

<Tabs syncKey="sampling">
  <TabItem label="Por proporção">
    ```ts title="src/telemetry.ts" showLineNumbers {4}
    import { TraceIdRatioBasedSampler } from '@opentelemetry/sdk-trace-base';

    const sdk = new NodeSDK({
      sampler: new TraceIdRatioBasedSampler(0.1),   // guarda 10%
      // …
    });
    ```

    Simples e previsível. O problema: um erro raro tem 90% de chance de não ser guardado.
  </TabItem>

  <TabItem label="Por resultado">
    Decidida no Collector, depois de o rastro terminar (*tail sampling*): guarda 100% dos
    que tiveram erro ou passaram de 1 s, e uma amostra dos demais. Mais caro de operar, e o
    que se usa em produção séria.
  </TabItem>
</Tabs>

<Aside type="note" title="Em desenvolvimento, guarde tudo">
  Amostragem existe por causa de volume. Na sua máquina e em homologação, `AlwaysOnSampler` —
  o padrão — é o que você quer.
</Aside>

## Exercício

No projeto `express-auth`:

1. Instale o SDK e configure `src/telemetry.ts` com o exportador OTLP.
2. Suba o Jaeger em contêiner e faça login pela API.
3. Encontre o rastro do `POST /auth/signin` e identifique quanto tempo ficou em
   `hashPassword`.
4. Crie um span manual em torno de `verifyPassword` com o atributo `app.auth.result`.
5. Acrescente o `traceId` às linhas de log e localize, no Jaeger, o rastro de uma requisição
   a partir do log.

<details>
  <summary>Possível resposta</summary>

  ```ts title="src/controllers/auth-controller.ts" showLineNumbers {4,8}
  const tracer = trace.getTracer('auth');

  export function signIn(req: Request, res: Response) {
    return tracer.startActiveSpan('signin.verify-password', (span) => {
      try {
        const ok = verifyPassword(password, user.password);

        span.setAttribute('app.auth.result', ok ? 'success' : 'failure');

        // …
      } finally {
        span.end();
      }
    });
  }
  ```

  O rastro mostra que a maior parte do tempo do login está no Argon2 — e isso é

## Perguntas de revisão

### Sinais

1. **Qual a diferença entre monitoramento e observabilidade?**

   <details>
     <summary>Possível resposta</summary>

     Monitoramento responde a perguntas previstas — alertas configurados de antemão.
     Observabilidade é conseguir responder a perguntas **não previstas** sobre o
     comportamento interno, sem publicar código novo para investigar.
   </details>

2. **Por que log, métrica e rastro não se substituem?**

   <details>
     <summary>Possível resposta</summary>

     A métrica avisa que algo piorou, mas não diz onde; o rastro mostra em qual etapa o tempo
     foi gasto, mas não guarda detalhe de cada evento; o log explica a requisição específica,
     mas não revela tendência. Cada um cobre uma pergunta diferente.
   </details>

### OpenTelemetry

3. **Por que o SDK precisa ser carregado com `--import`, antes da aplicação?**

   <details>
     <summary>Possível resposta</summary>

     Porque as instrumentações substituem os módulos no momento da importação. Se `express`
     já tiver sido carregado, ele não é instrumentado — e nenhum span é gerado, sem nenhum
     erro visível.
   </details>

4. **O que liga um rastro às linhas de log da mesma requisição?**

   <details>
     <summary>Possível resposta</summary>

     O `traceId`, obtido de `trace.getActiveSpan()` e escrito em cada linha de log. Entre
     serviços, ele é propagado pelo cabeçalho `traceparent` do padrão W3C Trace Context.
   </details>

5. **Por que usar `req.route.path` e não `req.originalUrl` como atributo de métrica?**

   <details>
     <summary>Possível resposta</summary>

     Porque a URL concreta cria uma série temporal por id (`/users/1`, `/users/2`, …). Essa
     explosão de cardinalidade derruba o backend de métricas e multiplica o custo. O padrão
     da rota agrupa tudo em `/users/:id`.
   </details>
